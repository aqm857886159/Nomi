# fix: isolate test and walkthrough network traffic

Test and walkthrough fixtures previously replaced provider data while appFetch, hardenedFetch, and the prompt catalog could still reach public hosts. Test mode now rejects unregistered hosts at both shared main-process HTTP boundaries; registered fixture origins redirect to loopback. Production behavior is unchanged.

## 设计卡

- ★1 Creator friction: startup and project-open walks could trigger real model-list or raw GitHub requests.
- ★2 Scope: test and walkthrough network isolation only; no production paid-generation or canvas behavior.
- ★3 Reuse appFetch, hardenedFetch, Undici, and the existing Electron webRequest guard at shared boundaries.
- ★4 Verified transport-level rejection, fixture redirect, bundled prompt behavior, TypeScript, build, and contract gates.
- ★9 Full Card 25 rerun remains unverified because the smoke walk hit an existing Generate toolbar assertion.

## 系统改进

The class root was a missing shared test-mode destination invariant. `electron/testNetworkGuard.ts` is now called by `appFetch` and `hardenedFetch` before proxy, DNS, or fetch dispatch; prompt catalog test mode returns bundled content. The Chromium layer keeps the existing walkthrough guard. Contract: `docs/fixes/2026-10-07-tests-no-network.root-cause.json`.
