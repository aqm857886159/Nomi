# 全产品功能与性能测试系统设计卡

状态：已实现未推送；实现线 test_system；类别：测试基础设施。

1. 用户任务：维护者在每次功能变更时登记入口与动作，跑真实走查，导入量化回执，与同条件基线比较，追踪性能改善。真实任务包括已有多媒体项目编辑、编组整理、长对话与项目往返；素材仅在本机独立副本使用。主指标为输入到反馈/可交互、帧 p95/p99、长任务、CPU、RSS 与重复操作内存斜率。质量护栏为状态断言、完整样本、零外联、真实证据；来源为固定提交下的真实 Electron。测试系统的单测通过不代表产品全场景通过。
   1b. 连带面：命令行报告分别呈现 passed、failed、blocked、unverified。不新增产品界面。
2. Owner：已有 full-walk/catalog 是功能、旅程与点击目标来源；本目录只补动作级要求、性能合同、执行证据和变更覆盖门。既有 canvas runner 保留为指标采集源，不另建第二个画布执行器。
3. 复用：Node 标准库/node:test、已有 full-walk 与 canvas runner、git diff。清单从源码动态读取，禁止手抄快照被当作唯一事实。
4. 全状态：缺场景、缺证据、缺指标、样本不足、条件不一致、已知 gap 均使完整验收失败；未执行为 unverified；环境故障为 blocked；断言失败为 failed；仅全部要求满足才 passed。结构校验成功只证明清单可读。
5. 中断：测试计划是顺序执行清单；采集中断不能产生通过回执。CI 不自动执行付费脚本、不并行运行 GUI 性能测试。runner 原始产物由各已有执行器负责。
6. 外部数据：只接受相对路径与 SHA-256 证据，不打包用户素材、绝对路径、凭据。原始 trace 保留本地。不同模型等待与网络等待分别记录，无法归因则缺失，不抵扣 UI 延迟。
7. 预算：目标值先为 advisory；同条件回归比较同时超过相对 10% 和绝对噪声阈值才失败，缺失值直接失败。small/typical/heavy 严格为 image/video 4/2、24/24、160/160。禁止为过门自动抬高基线。
8. 真实条件：本线只验证 CPU 上的合同与门岗，不启动 Electron；真实执行与资源回执由协调线接入。Windows、实际供应商、真实 ComfyUI 和打包首启不能以 loopback 通过代替。
9. 验收/回滚：node --test tests/quality-system/\*.test.mjs；真实 repo 清单生成；缺失证据负对照必须红。集成 patch 只增加测试/文档/CI，不改生产源；回滚移除新门岗接线。合并前由协调线独立审查，尚未宣称 CI 部署生效。
