# 假设验证：「Agent 缺自己的做事原则」到底成不成立

> 2026-09-15 · 真实模型腿（deepseek-chat 官方端点，temperature 0）· 题库见 [`prompts.md`](prompts.md)
> 原始数据：[`skill-results.json`](skill-results.json)（现在这条线）/ [`skill-results-raw.json`](skill-results-raw.json)（2026-09-14 基线）

## 用户的假设（2026-09-14 原话转述）

> 直接让 Agent 出片时它没定人物资产、没用参考图模式，怀疑 system prompt 原则没写好。
> 核心诉求 = Agent 在整个场景里要有自己的做事原则来提升输出质量。

已有证据：2026-09-12 00:27 截图里 Agent 自述
「**我没有调用一个专门的生图/美术 skill，也没有充分利用已有的『404门外楼道』和『周岚』参考卡。
刚才生成草稿里把它们写进文字了，却没有真正挂载已有视觉参考**」，以及
「更准确地说：镜头语言规则用了、视觉锚引用没用上」。

## 结论：**部分成立**

| 假设的组成部分 | 判定 | 证据 |
|---|---|---|
| ① 没有先立人物/场景资产 | **成立** | `character-asset` **0/4**（D01/D04/D06 + D02） |
| ② 没有用参考图模式（每镜各自文生视频） | **成立** | `reference-mode` 基线 **0/6**。唯一真的建出镜头的 D05：4 个镜头全 `text_to_video`，零锚、零参考边 |
| ③ 原因是「system prompt 原则没写好，所以它不去查技能」 | **不成立** | 空项目里 `skill-consulted` **2–3/4**：D04/D06 自主 `read_skill('drama-short')`，读到的是**正好对的**那条。发现路径（`<available_skills>` 索引 + `read_skill`）是通的 |
| ④ 它不知道「该先立定妆卡再批量生成」 | **不成立** | 它知道，而且说得出来。D06 原话：「会先给林夏和便利店各建一张定妆卡，后面每个镜头都引用它，这样 30 秒里不会换脸换店」；D01 基线臂原话：「先定便利店的场景卡（保证 6 个镜头是同一家店）」 |

### 所以真正的缺口在哪

**不是「不知道原则」，是「原则从来没变成工具入参」。**

六句「直接出片」里有 **4 句先停下问用户**（D01/D02/D03/D04/D06 中的四句都以提问收尾）——
这本身不是缺陷，`drama-short` 技能自己就写着「每阶段做完停下让用户审阅」。
但它意味着：在**真的动手建节点**的那一刻，前面说的那些原则有没有落成
`role: "anchor"` / `image_to_video` / `first_frame` 参考边，这份题库里只有 **D05 一句**
（「直接开始别问我」）能回答。而 D05 在基线臂上的答案是：**一个锚都没建**。

这也正是 2026-09-12 那张截图里 Agent 自己那句话的机器版本——
「把它们写进文字了，却没有真正挂载已有视觉参考」。

## D05 前后逐项对照（本报告的核心证据）

| | 2026-09-14 基线 | 现在（加了三句出片原则） |
|---|---|---|
| 轨迹 | `list_models → look_at_canvas → draft_shots → generate` | `look_at_canvas → list_models → list_models → draft_shots → arrange_canvas → generate` |
| 建视觉锚 | ✗ 没有 | ✓ `role: "anchor"` 的定场图（`text_to_image`, `aspect_ratio: 16:9`） |
| 后续镜头引用它 | ✗ 4 镜全 `text_to_video` | ✓ `arrange_canvas` 连 4 条 `role: "first_frame"` 边 |
| 跳过锚时说理由 | —（没这回事） | ✓ 主动说「纯空镜无人物，所以没建角色卡」 |
| 回复里的一致性交代 | 「模型是我替你选的 Kling 2.1 文生视频」 | 「先出定场锚图，后面四镜引用它……这样霓虹色温和城市轮廓不会每镜换一座城」 |

三轮独立 owner 臂复跑，这一格三次都一样（基线三次也都一样）。

## 做事原则的三层方案 —— 只实施了第 ① 层

### ① system prompt 里的原则句 —— **已实施**

`NOMI_AGENT_IDENTITY` 末尾三句（`electron/harness/context/agentContext.ts`）：
一次出两个以上镜头先建视觉锚并让后续镜头引用它 / 用户给了图素材它就是锚（真的挂上去，不是写进文字）/
只在明确不要一致性或本来没有可复现主体时跳过，跳过要说为什么。

**为什么放身份层不放某条技能里**：一致性是 Nomi 这个产品的事，不是某种片型的事（P4 通用第一）。
放进 `drama-short` 只能救「说了要做短剧」的那部分用户；D05 那种「直接开始」的话一条技能都不挂。

**代价（如实报）**：`回合成功率` 在选了技能那 11 句上 8/11 → 6/11。逐句看，两次回落都是
S07（`read_script` 和 `look_at_canvas` 谁先读）和 S10（整轮只读没写）这种**顺序抖动**，
不是行为退化——两句拿到的信息一样、答得一样好。这份题库的 `回合成功率` 被「先读哪个」主导，
技能维度要看 `skillVisible`（7/11 → 9/11，三轮一致）。

### ② 工具面上的守卫 —— **只出方案，没实施**

**做法**：`draft_shots` 在「一次提交 ≥2 个视频镜头、且全部 `text_to_video`、且这批里没有任何
`role: "anchor"` 节点、画布上也没有可引用的角色/场景卡」时，返回一条**结构化拒收**
（不是报错，是 pi 的 `block` + 一句人话），要模型要么补一个锚，要么在 `anchorSkipReason` 里写明为什么不要。

**为什么它比 ① 强**：① 是提示词，模型可以不听；② 是它必须绕过的那道门（R28：能让门岗拦的别留给人）。

**为什么这次不做**：它改的是**生产工具契约**（`canvasWrite.ts` 的 envelope 是 `.strict()` 的，
加字段要同时改 archetype 侧的校验、确认卡投影和 `check:reference-contract`），而且
「什么算可引用的锚」这个判据今天散在 `reference-slot-to-body-key-join` 那条教训描述的那个 join 上。
先用 ① 把数字拿到手、拿真实用例喂出「锚该怎么算」的判据，再动契约——顺序反了就是拿用户的工具面做实验。

### ③ 技能里的流程 —— **只出方案，没实施**

**做法**：把「立锚 → 冻结 → 引用」这一段从 `drama-short` 抽成一条所有片型都引的公共流程节。

**为什么不做**：它只覆盖「挂了技能」那条路。D05 证明了最需要这条原则的恰恰是**不挂技能**那条路——
在一条技能里写一条所有片型都适用的规矩，是把通用规则藏在一个可选件里（P1 的并行版变体）。
① 已经占了这个位置；真要做 ③，它应该是引用 ① 而不是复制 ①。

## 这份报告不能证明什么

- **不能**证明 `character-asset` 修好了：0/4 → 0/4。那四句在真的建节点之前就停下问用户了，
  这条原则在这份题库里**没有发生的机会**。要量它，得再造一组「用户已经答完所有问题、现在只等它建」
  的续轮句子——本轮没做，记在这里。
- **不能**证明在真实供应商上出片质量更好：这条腿的领域端口是夹具（画布/文稿/生成域返回固定事实），
  模型是真的。真机出片闭环归 R16 走查与付费小样，不归这里。
- **n=6 的「直接出片」组太小**。`reference-mode` 的 0/6 → 1/6 里，分母那 5 句是「没机会发生」，
  真正被量到的是 D05 这一句 —— 它三轮都一致，但它就是一句。
