# 设计定稿 · 「用 AI 帮我接入」（模型设置页入口）

> 2026-09-11 · 状态：✅ 已交付 · 用户 2026-09-11 拍板「按默认」。画布七板成文于此；实施见
> [docs/plan/2026-09-11-ai-assisted-onboarding-entry.md](../plan/2026-09-11-ai-assisted-onboarding-entry.md)。
> 本文是这张卡的**形态真相源**：实现与它对不上，改的是实现。

## 一句话

用户想接新模型时人在「模型」这一屏，而这屏上没有任何地方告诉他「可以让你已经在用的 AI 助手替你接」，
更没告诉他**该跟它说什么**。这张卡只干一件事：把那份「跟助手说什么」交到他手上。

## 逐板决定

### §Before —— 摩擦

- 这一屏能给的最后一条路是「自定义 API / 中转站」：自己填 base URL、Key、模型 ID、再猜类型
  （`src/ui/onboarding/ModelSettingsHome.tsx` 的 `custom-api` 行）。
- 能干这件事的卡**已经存在**，但住在「自动化与权限 → AI 助手连接 → 管理连接」
  （`AutomationPermissionsSection.tsx:213` → `ConnectAssistantCard.tsx:1`），文案只说「建项目、出图」。
- **决定**：v1 补的不是「再造一张接入卡」（并行版），而是①把入口放到人在的这一屏，②补上缺的那半。

### §Main —— 卡的构图

一张卡，自上而下：图标 + 标题「用 AI 帮我接入」+ 一句话 + 一条 hint「需要一个能装 MCP 的 AI 助手」；
宿主分段（WorkBuddy / Codex / Claude Code / 其它）；一行连接状态（选到那三家时）；
主按钮「复制指引」；折叠行「看内容 · 任务提示词 · 技能文件」；末行「或：手动接入 →」。

- **只加了一个功能簇**（§1.5.2 常驻预算）。卡里只有一颗主动作「复制指引」——
  分段控件是它的参数，折叠行是证据，末行是出口，都不是第二个主动作。
- **「手动接入 →」不是第二个家**：它滚到本页已有的「自定义 API / 中转站」那一行并描一次边，不另开向导。
- **选那三家时，MCP 配置不用用户粘**——Nomi 已经能一键写进它们（`ConnectAssistantCard.tsx` 的 `installMcp`）。
  「复制指引」复制的是**任务提示词 + 技能文件**；只有选「其它」才把 MCP 配置片段也带上。
- **卡上没有、也不许有「一键接入 / 撤销接入」按钮**：那件事只有一个家（§1.5.2）。选到的那家没连上时，
  卡上出现一行「还没接入 Nomi · 去接入 →」（能点的只有动作词，见下面「实施偏差 · 文案」），点它跳去那个家。
- 空态（还没有任何连接）时这张卡仍在第一位——它渲染在搜索框正下方、所有连接区块之前。

**实施偏差 · 文案（记在这里，别当漂移）**：板上的折叠行写「看看会复制什么」（7 字）、未连上那行整行可点
且标签是「还没接入 Nomi」（5 字）——两条都撞上 2026-09-10 用户拍板的 §1.8「控件文字 ≤4 字」，
`check:controls` 即红。改法不是把话删短了事，而是按 §1.8 把**标签**和**说明**分开：
折叠行的标签收成「看内容」，它右边那半（「任务提示词 · 技能文件」）本来就是说明、继续照旧；
未连上那行的句子退回成纯状态文字，能点的只剩「去接入」三个字——整行可点会让一句话冒充按钮文案，
也让这一屏出现第二颗看起来像主动作的东西。**语义一个字没变，变的是谁是标签。**

**实施偏差 · 宿主数（同上）**：板上写「那三家由 Nomi 一键写入」，真实是**五家**
（`ASSISTANT_CLIENT_ORDER` 含 Cursor / Pi）。四分段的形态不变；「其它」那段多一行
**从真实客户端表 derive** 的指路，点名剩下那几家也能一键接入。手列宿主名会在加客户端时漏，故 derive。

### §Copied —— 复制之后

按钮变「已复制 ✓」（降成描边样式，不再是主动作，这一屏仍然只有一个主动作），下面出现三步小示意：
① 粘到助手里 → ② 说要接哪个 → ③ 在 Nomi 里贴 Key，末尾一句
「Key 只经过这一页，不进 AI 的上下文，助手全程看不到它」。

- **三步图只在复制之后出现**——不复制的人不用先读一段教程（D1 effect-first）。
- 第 3 步那句是**真事实**不是安慰话：凭据走 `integration.open_credentials` 弹的 Nomi 本机安全页
  （`electron/capabilityCore/dispatcher.ts:741`），MCP 参数里永远没有 key（`mcpIntegrationTools.ts` 文件头）。
- 切换宿主 = 换了要复制的东西，「已复制」立刻失效（否则那颗勾在说谎）。

### §SkillFile —— 复制的到底是什么

展开「看内容」看到三块：

1. **任务提示词** —— 粘到助手对话框里的那句话，尖括号处换成要接的东西。
2. **`nomi-add-model/SKILL.md`** —— 同一份，任何宿主都能装。
   - frontmatter **只有标准键**（`name` / `description` / `compatibility` / `metadata`），
     用的是 Agent Skills 通行格式（<https://agentskills.io/specification>），不是自造的 `skill.json`
     （R31：外部也要读的格式必须对齐标准，不另起平行文件）。这也正是「同一份任何宿主都能装」成立的原因。
   - 正文六个 action 逐条对着真实工具契约写（`electron/capabilityCore/mcpIntegrationTools.ts:11-15,55-64`）：
     「不得传 key」「空 proposal 探 /models」「authHeader 给名不给值」「`compileRequest` → `adapterDraft`」都在那份 schema 里。
   - **实施偏差**：板上假设宿主一定装得下技能。Codex 官方文档（<https://learn.chatgpt.com/docs/extend/mcp?surface=cli>）
     没有 Agent Skills 这一格，所以提示词改成「有技能目录就存进去，没有就直接照它做」——原文本身就是说明书。
3. **MCP 配置片段** —— 只在选「其它」时出现。command / args **逐台机器不同**，由 Nomi 当场从
   `McpInfo.server` 生成（形状与主进程 `mcpConfig.jsonSnippet` 一致，也是 `.mcp.json` 的事实标准形状）。
   这一份不带客户端签名，但接入全程照样走得完（`dispatcher.ts:725-790` 里只有 `integration.manage.*` 要签名身份）。

### §Progress —— 进行中

活儿在另一个窗口里干。用户回到 Nomi 只想知道两件事：**到哪一步了**、**要不要我做点什么**。

五步（名字是用户语言，右边灰字是**真实 stage 名**，排错时对得上日志）：

| 步 | 真实 stage |
|---|---|
| 建立接入会话 | `draft` |
| 你贴 Key | `needs_credential` |
| 找模型、挑模型 | `needs_input` → `discovering` → `needs_selection` |
| 试跑一次验证 | `needs_spend_confirmation` → `awaiting_human_confirmation` → `human_confirmed` → `certifying` |
| 出现在上面的「已接入」里 | `committing` → `completed` |

- **失败不复用「进行中」的壳**：标题直说结果（「没有接进来」），给出事前停在哪一步 + 原始错误码 + 一句人话。
  **不吞掉已保存的 Key**。`partial` 与 `failed` 同档——模型没进列表，不许显示一颗绿勾。
- 「要花钱先弹确认」沿用现有的付费确认卡，不新造。
- 完成后进度收起，卡退回默认样子——模型此刻已经在上面的「已接入」里了。

### §V2 —— 不推荐（Agent 面板加号里的入口）

画出来是为了**能把它否掉**：① 那个「+」的家是「往这次对话里加东西」，接模型是设置动作；
② 面板里的宿主就是 Nomi 自己的 Agent，它本来就能直接调 `nomi_integration`，所以那是**另一个功能**；
③ 两条路 = 两套心智，出问题时说不清走的是哪条。**结论：不做**；真要满足这个诉求应单独立项。

### §Checkpoints —— 卡点表

| 四问 | v1 的答案 | 证据 / 缺口 |
|---|---|---|
| ① 怎么知道有这功能 | 卡常驻在「模型」页搜索框正下方——想接模型的人一定会到这一屏 | 首次出现给一次 accent 描边，看过即消（`nomi:assisted-onboarding-seen:v1`），不做常驻高亮 |
| ② 动手前知不知道要付出什么 | 不额外花钱，但需要**一个能装 MCP 的 AI 助手**——这句 hint 就在卡上 | 真花钱的只有最后「试跑一次」，由现有付费确认卡当场弹 |
| ③ 空了 / 错了看到什么 | 一个助手都没接过：卡照常可用（复制指引本来就不要求先连上）。接的过程炸了：换失败态，直说「没有接进来」+ 原始错误码，Key 不丢 | 见 §Progress 下半 |
| ④ 凭什么信结果对 | 模型**出现在「已接入」里**，而且是真跑通一次才出现的——不是「助手说接好了」 | `start` → `certifying` → `completed` 是唯一路径（`integrationContract.ts:4`）；跳过 `start` 就没有 `completed` |

这条路 4 步：选宿主 → 复制 → 粘上去说一句 → 在 Nomi 里贴 Key。
**砍不掉的是「贴 Key」**——它是安全边界（Key 不许过模型上下文），结构上省不了。

## 删除清单 —— 我没放上去的

| 没放 | 为什么 | 他要它时怎么找到 |
|---|---|---|
| 各宿主的教程长文与截图 | 一张卡会涨成一页说明书；宿主界面一改就过期，我们维护不动（D1） | 「看内容」里就是可直接用的原文 |
| 卡里的 Key 输入框 | Key 只有一条合法路径（Nomi 本机安全弹页）。再放一个 = 开第二条凭据路径 | 第 3 步会自动弹那一页 |
| 「一键接入 MCP」按钮 | 它已经存在于「自动化与权限 → AI 助手连接」。再放一颗就是同一功能两个家（§1.5.2） | 选到那家未连上时卡上出现「还没接入 Nomi · 去接入 →」 |
| 模型类型 / 参数 / 价格的预填表单 | 那正是我们请 Agent 去干的活。让用户先填一遍 = 换个地方累（D1） | Agent 在 `propose` 时自己判定；判错了在模型详情页改类型 |
| 实时日志流 | 用户只想知道「到哪一步了」。日志是排错才要的，平时是噪音 | 五步右边的灰字就是真实 stage 名，够对日志 |
| **「重试」/「取消这次接入」按钮**（板上有，实施删） | 渲染层桥上没有 cancel / retry 这条路——那是 MCP 侧的 action。画上去就是一颗按不动的按钮（控件契约 C1，`check:controls` 抓的正是这族） | 失败态里直说「Key 已保存，回到助手里让它重试即可」 |
| 「查看完整报错」（板上有，实施删） | 同上：渲染层拿到的只有 `blockingReason.code`，没有完整报错可展开 | 错误码原样显示在失败态里；完整日志在诊断包（通用设置 → 隐私与诊断） |

## 验收（UI 交付定义）

设计实验室 `settings` 屏：光色四格 `assisted-01-idle` / `assisted-02-not-connected` /
`assisted-03-progress` / `assisted-04-failed`，暗色两格 `assisted-05-idle-dark` /
`assisted-06-failed-dark`——暗色只取默认与失败：需要在暗色下重判一次的颜色决定
（accent 主按钮 + success 勾、danger 底 + 原始错误码）都在这两格里，其余两格的配色是它们的子集。
基线只录这六格。R13 走查：`tests/ux/assisted-onboarding-entry.walk.mjs`。
