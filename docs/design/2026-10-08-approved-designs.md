## ① 列表视图

- 起因（用户 10-08）：分镜和画布「都放冗余」；画布生成对新手麻烦，LibTV 有能总览、也能直接生成的视图。拍板：分镜 / 画布是**同一份镜头、两个视图**；生成页加「画布 | 列表」切换；删画布里的分镜表节点；创作页「分镜方案」点进来 = 列表筛到那份分镜。
- 列表内容：分镜镜头按镜号在最前（锚条 + 接上一镜），其余按画布分组，再是未分组。点卡 = 右侧检查器，就是画布节点的生成框（改模型 / 参数只在这里）。
- **批量条不做**——用户原话：「批量条我们以前不是讨论过没必要做 类似编组那个事吗」「就是因为节点的模型创建的时候是选好的 没必要选模型吧」（呼应 10-06：「生成几个 以及 生成选择的模式删掉了 那些就放入编组之后的生成全部按钮就好」）。所以：卡片没有勾选框；每个分区（分镜 / 画布分组）表头一个「生成整组」（与画布编组同一个按钮）→ 付费确认框逐项勾（没生成的默认勾、已生成的不勾、生成中的锁住）；未分组不出这个按钮。
- **补画后已拍板（10-08 晚，画布 H 板）**：各种节点在列表里的样子——生成类大卡（视频首帧 + 时长、声音波形、文本前几行），导演台 / 剪辑 / 3D / 全景 / 画板 / 输出 / Agent 产物是小卡（点了回画布），末尾「未被引用的素材」条，每个节点恰好出现一次；列表只替换中间画布那块，顶栏 / 左栏 / 右侧 Agent / 时间轴不动。
- **镜头编号只留分镜里的号**（用户 10-08）：画布、列表、Agent、时间轴一个镜头一个叫法「镜 03」（多份分镜时「分镜名 · 镜 03」），去掉画布上全局「镜头 N」。
- #1107（分镜表「确认前不建节点」）里的分镜表批量参数条随分镜表节点一起删除，不随 0.24 发出。

## ② 自动引用

- 用户原话（10-08）：「如果是 ai 设计方案 那其实直接引用应该就可以」「如果是画布里面的可能不能直接引用 可能出错 比如设计一个 @ 下面置灰 然后点击可以选择……另外可以多设计一种 就是引用 一个是 agent 一个是画布节点 点击之后可以点选画布里面的东西」。
- 拍板：AI 写的方案里唯一对得上的直接绑，对得上多个就退回建议并由 Agent 一句话说明；手写提示词识别到的词显示灰色虚线（只表示建议），点开出候选（同名 / 别名 / 最近用过），选了才变正式引用；@ 菜单分「Agent（方案定好的视觉锚）/ 画布节点（在画布上点选）」。匹配规则分镜和画布共用一份。

## ③ 画布拉环与空节点

- 起因（用户 10-08，看 LibTV）：「左边是添加上下文 右边是引用该节点输出……这方面我们还很少」。
- 拍板：拉环只在**能用的一侧**出现（收不了输入的上传素材没有左环，没有可引用产物的剪辑卡没有右环；文本卡左环收文字和图（10-09 用户拍板：按「这一侧能用才出现」，文本节点获得输入后有左环）；改掉 09-21「所有种类两边都有」）；左「+」=「给它加输入」（按本卡能收什么列，含「从素材库添加」「在画布上点选」），右「+」=「用这个节点生成」；点一下「+」就出菜单；空节点用 2–3 个「试试」任务替换那句操作说明，点了只搭结构、不生成不花钱；空画布一排任务卡。
- 样张线实测的两个现有 bug：纯点击「+」什么都不出；左「+」拖到空白处按「本卡当源」判（视频卡左侧图片 / 文字被置灰，文本卡能连出无意义的边）。类根因：「这张卡收不收输入」没有唯一 owner——实现时加在节点种类定义上，拉环、菜单和建边校验都读它。
- 「在画布上点选」模式由这条实现线建成共享能力，自动引用复用同一个。

## ④ 应用内更新提醒

- 起因（用户 10-08）：「我们的应用内更新提醒设计 以及 说明为什么更新 带来什么用户体验」。核心权衡：修好的问题要尽快到用户手里，又不打断正在跑的生成、不催人。
- 拍板：热修版（版本号第三位变）除顶栏胶囊外在项目库出一次性横幅（只在受影响平台出，文字写「修好了什么」）；Windows 点「下载更新」= 同意，后台下、下次退出时自动装（走退出唯一 owner），有任务在跑不让重启打断；Mac 维持官网下载 + 弹窗三步引导（暂不签名）；更新后第一次打开出一次「已更新到 x」卡。
- 样张线查出的现有 bug（实现时一并修）：项目库页没挂更新提醒；发版说明经 GitHub feed 到应用里被剥成平文本；英文按钮写成 "Reinstall"；「完成后再更新」的提示没有任何东西真的在等；下载失败点重试要点两次；0.23.0 发版说明缺英文段（要加发版说明门岗：必须有英文段与中英标题句）。

## ①续 分镜与画布：同一份镜头（用户 10-08 夜再拍板，覆盖上面“创作页分镜方案点进来 = 列表筛到那份分镜”）

- 分镜和画布是**同一份镜头的两个视图**，共用一套组件和同一份数据：一个镜头一条记录、三阶段（草稿只在方案里 → 确认生成或“放到画布”后才落画布 → 已生成）；删掉“节点覆写 → 分镜行采纳 / 丢弃”那层，两本账（分镜方案与 Agent 画布草稿）合一；想在画布上试别的就复制成变体，不动原镜。
- 一个文稿可有多份方案，复制只复制文字草稿；**分镜方案留在创作页**（整条片子的设计：时长、策略、视觉锚条、接上一镜、草稿 + 已落画布的镜头）；生成页的列表只显示已落画布的节点、与画布一一对应；预览选一份方案当片子顺序。两边共用镜头卡片 / 大详情 / “生成整组”确认框，旧分镜表编辑器换成这套组件后删掉。
- 画布里自动建的分镜表节点删掉，换成互相跳转（分镜行“在画布里看”、画布节点镜号角标点回分镜）；“拆参考片”来源的表保留（那是参考资料分析）。分镜版式用等高网格 + 右侧检查器，加顶部视觉锚条、卡上锚标签（未定妆显示“等定妆”），相邻卡可选“接上一镜”（上一镜尾帧当首帧）。
- 类根因（用户觉得“冗余”的真东西）：同一镜存了三份（方案、Run、节点覆写）和两条生成路径——双扣与镜头认领问题都是它的后果，不是界面放两处。第一步（小）：版式 + 锚条 + 接上一镜 + 删画布分镜表 + 互相跳转；第二步（结构，碰花钱路径）：账本合一、删覆写层，要 9 格设计卡和独立验收，排在当前修复之后。
- 自动引用的方向补充：AI 写的方案里的指代直接绑；用户在画布里手写的提示词不直接绑，先置灰为建议，选了才算。

## ⑤ 文本节点（用户 10-08 夜，三题都按推荐）

- 定位：画布上的**文字中间产物**（提示词、描述、风格说明），不做第二个文稿编辑器；剧本归创作页（剧本放两处会让 Agent 和分镜方案读不到）。
- 先做两步：第 1 步 Agent 能读写正文，拼进下游的文字用“引用：文本名”小签摆出来（执行器和小签读同一个投影，文字不许偷偷拼进下游——违反“说的 = 摆的”）；第 2 步左环能接图 / 视频 / 文本，加工框预设：扩写成提示词、看图写描述、翻译、拆成多条，保留续写 / 改写 / 重写，模型默认跟随 Agent、不强制先选。
- 第 3 步“拆成多条 → 每条建节点扇出”等编组“生成全部 + 确认框”落地后再做，避免多一条批量花钱路径。“写脚本”从文本节点拿掉，不放跳转链接。空文本节点的“试试”最终是：扩写成提示词 · 看图写描述 · 拆成多条（第 2 步上线前过渡为：拿它生图 · 拿它生视频）。

## ⑥ 外部 Agent 在没打开的项目里生成：先落节点再花钱（用户 10-09）

- 钱花了结果必须看得见（以前 Nomi 没开时照样扣钱，结果永远不上画布）。**Nomi 没开**：经 MCP 冷启的是隐藏主窗口，主进程经 `nomi:production-deep-link` 让它打开目标项目，落地后再派发。
- **用户可见窗口正开着别的项目，或走旧的进程内 stdio 路**：拒绝、不派发，回给 Agent 的话写“需要在 Nomi 里打开项目 X”；绝不切换用户正在看的项目。
- 主进程直接把节点写进没打开的项目文件（3–5 天工作量）：另立独立卡，暂不做。

## ⑦ 生命周期三项结构改法（用户 10-08 批准，全文见 `docs/audit/2026-10-08-architecture-review.md`）

- A 生命周期唯一 owner：启动 / 开项目 / 退出 / 更新由一个 owner 分阶段管，各子系统登记“必需 / 可选”、每阶段总时限，可选的失败只降级；静态守卫禁止 owner 以外拦退出。B 落盘格式登记：每种落盘文件声明版本与旧 / 坏读法（迁移 / 隔离 / 默认值但告诉用户），不再静默清空。C Mac 生命周期端到端走查进 CI。
- 新功能接入启动 / 退出 / 落盘时按 A / B 的登记方式接，不再各自 `app.on`、各自 `JSON.parse`。
