任务卡：出海投放的人，在「不知道这条素材该怎么拍」的那一刻，找到几条同类目正在跑量的片子，挑一条带回项目。挑完就走。

v1 · 只有一件事 ← 默认推荐

一个输入框 + 一列带规模证据的卡片 + 点一下加入。三个控件。 入口不是第 8 个按钮——是现有「贴链接」那颗的升级（🔗 已点亮）： 贴链接 = 我已经知道要哪条；输关键词 = 我还不知道要哪条。同一个家，常驻控件数仍是 7。

为什么这三样必须留：
· 输入框＝「找」的唯一入口
· 规模角标（♥点赞 + 放量标）＝「跑量」的证据。去掉它这条线就退化成普通搜索，也就没有存在理由了

刻意少得让人不安的地方：没有筛选、没有排序、没有 tab、没有详情面板。第一眼会觉得「就这？」——这是预期内的，要什么再往上加。

v2.5 · 从 v3 捞回三个真核心维度 ← 修正后的推荐

按「用户挑素材时脑子里在判断什么」捞，不按「API 给了什么」捞。只有三个判断是必答的： 同市场吗（地区）· 同目标吗（卖货/推 App/拉流量）· 真跑量还是噪声（规模角标，已在 v1）。 代价：+1 行 chip，面板高 +30px。行业/表现分位/时长/语言/Spark/创意标签仍全部不加。

地区默认跟随他的投放地区（可 derive，不用问）——是一颗已选中的 chip，不是要他填的下拉。

广告目标是这次真正捞回来的那个。实测一次「skincare」搜索的 20 条里： 产品销售 9 / 转化 6 / 流量 3 / 触达 2 —— 四种目标混排。做电商的人看到「拉流量」和「触达」的素材是纯浪费， 因为拍法根本不同（卖货演产品使用，推 App 演界面操作）。

⚠️ API 的枚举有 7 种（流量/应用安装/转化/视频浏览/触达/潜在客户/产品销售）。 这里刻意收成 3 颗——按「用户的问题」分组，不按 API 的枚举分。让用户学平台的 7 分类法 = 让他学我们的格式。

时间窗不做成常驻筛选器：默认近 30 天，只在结果为空时才冒出一颗「放宽到半年」。

v3 · 全都要（对照组 —— 不过这道闸会画成的样子）

把研究里拿到的能力全铺出来：7 个筛选器 + 广告/自然流量 tab + 花费档 + 评论分享 + 落地页 + 逐秒 highlight 曲线。 这不是推荐项，是让「全都要」的代价可见——面板高度翻倍，第一屏只剩 2 条结果，而任务卡那件事一步都没变快。

卡点表逼出来的三个改动（前三件产物一个都发现不了）

前三件产物管构图（一屏上有多少东西）；卡点表管路径（用户走一条路会卡在哪）。 把这条路真的走一遍，抓到三个问题——其中第一个是我上一轮的减法自己造出来的。

① 发现：🔗 这个入口是断的（自己造的坑）

这功能的价值在「我还不知道要哪条」，但 IconLink 说的是「我已经有链接了」—— 没有链接的人永远不会点它。上一轮为了「一功能一个家」把它塞进 🔗：构图赢了，路径断了。 修法用「就近」手法（代价 0，不是收纳）：素材库空态的主 CTA 直接是它，而且输入框就地内嵌、不弹层——顺便砍掉一步。

实测修正：不是「中文不可用」，是平台没选（用户指出）

初稿写「中文关键词基本不可用」。这个结论是错的，错在我自己的方法——我拿中文去查了 TikTok 广告库，那是英文市场的库。 补测同一个词 护肤精华：

平台 / 端点条数相关性
抖音 douyin/search/fetch_video_search_v176/7（86%） —— 中文在中文平台完全可用
TikTok 广告库 tiktok/ads/search_ads196/19（32%），混入泰语 / 印尼语
TikTok 自然流量 tiktok/app/v3/fetch_video_search_result0—

真正的结论：平台不是一个筛选器，是任务卡的一部分 —— 它由「用户在做哪件事」决定，不该让用户选。

用户在做什么该查哪关键词语言有没有「跑量证据」
TikTok 出海投放（= 本设计的任务卡）TikTok 广告库英文（所以自动转译更该做）✅ CTR / 花费档 / 表现分位
国内做抖音内容抖音中文原生可用❌ 只有点赞/播放，没有广告表现面

这条修正带出一个结构性事实：这条产品线的核心价值（「按曝光排序的跑量素材」）是 TikTok 特有的——它来自 TikTok Creative Center，抖音侧没有对偶数据。 → v2.5 保持 TikTok-only，但不假装自己是通用的「找参考」：任务卡写死「TikTok 出海投放」，界面上说明白查的是什么库。 「做抖音内容」是另一张任务卡，要做得单独立项。

必答题：这条路能不能少一步？

原设计 10 步：打开素材库 → 看见 🔗 → 点它 →（查 key，没配则去设置再回来）→ 弹输入框 → 输关键词 → 回车 → 看结果 → 点一张 → 落进素材库。

砍掉的步骤怎么砍的
「弹输入框」这一层空态里就地内嵌输入框，看到即可用，少一次弹层开合
「用户自己想英文关键词」中文自动转译 + 回显。他本来得先知道「这个库是英文的」才能用对——那是让用户学我们的实现细节
砍不掉：配 key（外部依赖，只能前移不能消除，已前移到点击那一刻就检查）

10 步 → 8 步。

为什么角标从「CTR 前 N%」换成「♥点赞 + 放量」（实测推翻了初稿）

2026-09-07 用真 key 拉了 20 条 skincare / US / 近半年 的真实广告，按花费档分组：

花费档 cost条数CTR 均值点赞均值读法
2（花得最多）90.16%8374真被放量了；受众放宽后 CTR 自然摊薄
180.51%1372中间档
0（几乎没花钱）30.64%7CTR 最高，但只有 7 个赞 —— 小样本噪声

结论：CTR 和投放规模是反的。 初稿 v1 的「CTR 前 1%」角标会把一条 CTR 0.87% / 点赞 1 的噪声素材 当爆款推给用户 —— 那正是这条产品线最不该犯的错。 用户原始诉求那句是「按曝光量排好序」，曝光量对应的是 cost（花费档）与点赞量，不是 CTR。 所以角标改成 ♥点赞量（规模） + 「放量」标（cost 高时才出）；CTR 降级进详情，不上卡片正面。

⚠️ 顺带三条实测契约修正（文档都写错了）：limit 上限是 20 不是文档说的 50（传 30/50 都 422）· cost 实际出现 0 值，不是文档说的 1–5 · like 是整数枚举 1–5（传 "top_1" 直接 422）。

诚实标注（不许在实现时悄悄糊掉）

点状态
「贴链接」那颗按钮语义要扩（链接 + 关键词两用）⚠️ 这是改现有控件的语义，不是加新控件。文案/aria-label 要一起改，且要过 check:icon-semantics（同一动作只能一个图标）
CTR 角标写「前 1%」⚠️ 实调 get_ad_percentile 只回 ctr_percentile 一个数（如 0.99）。「前 1%」是我按 0.99 反推的展示口径，未与 TikHub 核对语义方向——接线前必须确认它是「超过 99% 的同行」还是别的
