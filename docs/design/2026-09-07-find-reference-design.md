## 闸② 新面 → 三件产物

### 产物 1 · 任务卡

> **出海投放的人，在「不知道这条素材该怎么拍」的那一刻，找到几条同类目正在跑量的片子，挑一条带回项目。挑完就走。**

⚠️ 这张卡**只描述「找」这一个时刻**。「拆一条已有素材看它为什么行」是另一个时刻 → 另一张任务卡、另一次判层级。合成一张就会开始堆。

### 产物 2 · 三版减法梯度

| 版本 | 内容 | 判断 |
|---|---|---|
| v1 只有一件事 | 一个输入框 + 一列带规模角标的卡片 + 点一下加入。**三个控件** | 🟡 基准线 |
| **v2.5 捞回三个真核心维度** | v1 + 地区 chip + **广告目标 3 颗 chip**（卖货 / 推 App / 拉流量） | ✅ **推荐**（2026-09-07 用户提出「v2 好像还要再往上加一点点」后修正） |
| v3 全都要 | 7 个筛选器 + 广告/自然流量/热榜 3 个 tab + 花费档 + 评论分享 + 落地页 + 逐秒曲线 | ❌ 对照组 |

### 从 v3 捞回来的判断（按「用户脑子里在判断什么」分，不按「API 给了什么」分）

用户挑素材时只有三个判断是必答的：

| 判断 | 维度 | 为什么核心 | 处置 |
|---|---|---|---|
| 同市场吗 | **地区** | 美区跑的和东南亚跑的完全两回事 | ✅ 一颗已选中 chip，默认跟随投放地区（可 derive，不用问） |
| 同目标吗 | **广告目标** | 实测一次 `skincare` 搜索的 20 条里：产品销售 9 / 转化 6 / 流量 3 / 触达 2——**四种混排**。做电商的看到「拉流量」「触达」素材是纯浪费，因为**拍法根本不同**（卖货演产品使用，推 App 演界面操作） | ✅ **3 颗 chip**。API 枚举有 7 种，刻意收成 3 颗——按用户的问题分组，不按 API 枚举分（让用户学平台的 7 分类法 = 让他学我们的格式） |
| 真跑量还是噪声 | **规模（点赞 + 花费档）** | 见下节：**CTR 会骗人** | ✅ 已在卡片角标（v1 就有，但语义被修正了） |

不捞的，以及理由：**行业**（关键词已覆盖，且它是一张数字 ID 表 = 让用户学分类法）·**表现分位**（列表已按表现排序 + 角标已显示，作为筛选器纯冗余）·**时长/语言/Spark Ads/创意标签**（长尾；语言基本被地区蕴含）·**落地页/评论/分享**（复盘用不是挑素材用）·**逐秒曲线**（属于「拆」的时刻）·**三个 tab**（自然流量侧没有花费/CTR 数据，混排 = 一半卡片有角标一半没有 = 两套心智）。

**时间窗单独处理**：它不做成常驻筛选器，但必须存在——「正在跑量」的「正在」就是它，且实测筛太细会返回 0 条。做法：默认近 30 天并在结果区标一行小字；**只在结果为空时**才冒出一颗「放宽到半年」。

### ⚠️ 实测推翻了初稿的角标设计：CTR 不是「跑量」

2026-09-07 用真 key 拉 20 条 `skincare / US / 近半年`，按花费档 `cost` 分组：

| `cost` | 条数 | CTR 均值 | 点赞均值 | 读法 |
|---|---|---|---|---|
| 2（花得最多） | 9 | 0.16% | **8374** | 真被放量了；受众放宽后 CTR 自然摊薄 |
| 1 | 8 | 0.51% | 1372 | 中间档 |
| 0（几乎没花钱） | 3 | **0.64%** | **7** | CTR 最高但只有 7 个赞 —— **小样本噪声** |

**CTR 和投放规模是反的。** 初稿的「CTR 前 1%」角标会把一条 `CTR 0.87% / 点赞 1` 的噪声当爆款推给用户——这正是这条产品线最不该犯的错。用户原始诉求那句是「**按曝光量**排好序」，曝光量对应 `cost` 与点赞量，**不是 CTR**。

→ 角标改为 **♥点赞量（规模）+「放量」标（`cost` 高时才出）**；CTR 降级进详情，不上卡片正面。

**v1 三样为什么必须留**（对着任务卡逐项判）：
- **输入框** = 「找」的唯一入口
- **CTR 角标** = 「跑量」的证据。**去掉它这条线就退化成普通搜索**，也就没有存在理由了
- **点卡片加入** = 任务卡里的「带回项目」，即出口

**v3 的真实代价**（样张里画出来了，不是嘴上说）：10 颗筛选 chip 里 **9 颗他第一次进来时不知道自己要什么**；三个 tab 是**两套心智混排**（广告 vs 自然流量，UX 体检尺子 pattern 2）；逐秒曲线在「找」的时刻**没有解释力**（还没看过片，曲线是天书）；结果从 3 条掉到 2 条，而任务卡那件事**一步没少**。

### 产物 3 · 删除清单

| 我没放上去的 | 为什么 | 用户要它时怎么找到 |
|---|---|---|
| 行业 / 广告目标 / 表现分位 / 时长 / 语言 / Spark Ads / 创意标签 | 第一次进来不知道自己要筛什么，**先看见东西才有得筛** | 结果区顶部「筛选 ▾」，L3 |
| 落地页 / 花费档 / 评论数 / 分享数 | 投放复盘用，不是「挑一条带回去」用 | 卡片展开详情，L3 |
| 逐秒 highlight 曲线 | 属于「拆」的时刻，是另一张任务卡 | 拆解卡上，与分镜表镜号对齐 |
| 自然流量搜索（非广告） | 两个源混排 = 两套心智 | v2 之后再评估 |
| Top Contents 热榜 / 热门话题 | 那是「逛」，与「挑完就走」冲突 | 暂不做 |
| 「搜索」按钮 | 回车即搜；多一颗按钮不多一分能力（快捷键不算入口，算加速器） | 回车 |

### 产物 4 · 卡点表（把这条路真的走一遍）

**这条路现在 10 步**：打开素材库 → 看见 🔗 → 点它 → （查 key，没配则去设置再回来）→ 弹输入框 → 输关键词 → 回车 → 看结果 → 点一张 → 落进素材库。

| # | 用户看到什么 | 会卡在哪 | 我们做什么 | 证据 |
|---|---|---|---|---|
| **① 发现** | 工具栏上一个**纯图标** 🔗（无文字，只有 hover 的 `title`） | 🔴 **致命，而且是我自己造的**。这功能的价值在「**我还不知道要哪条**」，但 `IconLink` 说的是「**我已经有链接了**」。没有链接的人**永远不会点它**。上一轮为了「一功能一个家」把它塞进 🔗——**构图赢了，路径断了** | ① 素材库**空态主 CTA 直接是「找参考素材」**（空态是天然教学位，且素材库空时正是最需要它的时刻）；② 🔗 加上文字标签 | 现状：`AssetLibraryToolbar.tsx:123-127`（纯图标 + `title`）· 空态组件已有：`DesignEmptyState`（A3 已收口） |
| **② 代价前置** | 点开就能用 | 🟡 两笔代价：**要配 TikHub key**（已处理好）；**每搜一次要花钱**（$0.001/次，比贴链接的「一次一条」大） | key 检查**照抄现成范例**（先查 key 再弹输入框，不让他输完才发现）；花费**不弹确认**（$0.001 弹窗 = 灾难性摩擦），改为面板内一行极小诚实说明 | 范例：`pasteShareLinkImport.ts:57-68`（注释「少一步空跑」）· 定价见 `../research/2026-09-07-tiktok-creative-intelligence.md` |
| **③ 空态与失败** | 结果列表 | 🔴 **实测撞到两个**：(a) `keyword+period=30+like=1` → `total_count=0`，用户会以为坏了；(b) 中文关键词在 TikTok 广告库相关性只有 32%——**因为那是英文市场的库**（见下节修正） | (a) 空结果文案走三段式 + 给动作「放宽到半年」；(b) 平台固定 TikTok ⇒ **中文自动转英文再搜，并回显「已按 skincare serum 搜索」可改** | 现成规范：`pasteShareLinkImport.ts` 的 `ERROR_KIND_KEY` 九种错误 → 三段式 |
| **④ 结果可信与退路** | 卡片角标 | 🔴 初稿角标写「CTR 前 1%」——**实测 CTR 与投放规模反相关**，会把噪声当爆款推给用户 | 已修：角标改 ♥点赞 + 放量标。退路：素材库已有删除 | 实测见本文上节；删除：`AssetLibraryToolbar.tsx:143-148` |

**必答题 · 能不能砍掉一步？**
✅ **能砍两步**：
- **砍掉「弹输入框」这一层**——空态里**就地内嵌输入框**，看到即可用（少一次弹层开合）。
- **砍掉「用户自己想英文关键词」**——中文自动转译（见 ③b）。他本来得先知道「这个库是英文的」才能用对，那是**让用户学我们的实现细节**。

砍不掉的是「配 key」（外部依赖，只能前移不能消除，已前移）。
→ **10 步 → 8 步。**

### ⚠️ 实测修正：不是「中文不可用」，是**平台没选**（用户 2026-09-07 指出）

初稿写「中文关键词基本不可用」。**这个结论是错的，而且错在我自己的方法**：我拿中文去查了 **TikTok 广告库**——那是英文市场的库。补测同一个词 `护肤精华`：

| 平台 / 端点 | 结果 | 相关性 |
|---|---|---|
| **抖音** `douyin/search/fetch_video_search_v1` | 7 条 | **6/7（86%）** — 中文在中文平台完全可用 |
| TikTok **广告库** `tiktok/ads/search_ads` | 19 条 | 6/19（32%），混入泰语/印尼语 |
| TikTok **自然流量** `tiktok/app/v3/fetch_video_search_result` | **0 条** | — |

**真正的结论**：**平台不是一个筛选器，是任务卡的一部分**——它由「用户在做哪件事」决定，不该让用户选：

| 用户在做什么 | 该查哪 | 关键词语言 | 有没有「跑量证据」 |
|---|---|---|---|
| **TikTok 出海投放**（= 本设计的任务卡） | TikTok 广告库 | **英文**（所以自动转译更该做，不是不该做） | ✅ CTR / 花费档 / 表现分位 |
| 国内做抖音内容 | 抖音 | 中文原生可用 | ❌ **只有点赞/播放，没有广告表现面** |

**这条修正带出一个结构性事实**：这条产品线的核心价值（「按曝光排序的跑量素材 + 为什么能传开」）**是 TikTok 特有的**——它来自 TikTok Creative Center。抖音侧没有对偶数据（见 `../research/2026-09-07-tiktok-creative-intelligence.md` §2.2）。

→ **v2.5 保持 TikTok-only，但不假装自己是通用的「找参考」**：任务卡里写死「TikTok 出海投放」，界面上说明白查的是什么库。
→ 自动转译**保留且理由更强**：平台固定是 TikTok ⇒ 英文永远是对的查询语言，用户不该需要知道这件事。
→ 「做抖音内容」是**另一张任务卡**，要做得单独立项——它的价值主张完全不同（没有跑量证据这一层）。

## 它住哪 —— 「找参考」不是新按钮，是「贴链接」的升级

- 现在的「贴链接」= **我已经知道要哪一条**
- 「找参考」= **我还不知道要哪一条**

两者是同一个目的（把外部素材弄进来）的两个前置状态 → **一功能一个家**（§1.5.2 硬规则 1）：入口仍是 `IconLink` 那一颗，点开后输入框同时接受**分享链接**和**关键词**，按内容形状分流。**常驻控件数不变，仍是 7。**

## 诚实标注（实现时不许悄悄糊掉）

| 点 | 状态 |
|---|---|
