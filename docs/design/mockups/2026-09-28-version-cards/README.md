## 来源

用户原话：

- 09-27～28：「我们在一个地方一直生产，会出现几版……把几版设计一个展开的逻辑：点击然后直接展开所有的生产，它可以覆盖目前现有的功能……icon 也调整一下。」
- 09-27～28：「优化那个几版右边一个小窗口，可以看、下载什么的——可以直接类似一个打开/收起节点，直接把所有版本展开收起成为卡片那样的设计，更方便简洁，现在操作有点复杂了。同时那个『设为主图』得留下。可能我的设计也有遗漏，你思考一下。」
- 09-28（看过 v1 展开态后改向）：「是不是可以原地展开：比如右侧有一个 icon，点展开，就原地铺开几个节点，然后我也可以处理其他的。」

改向经过：v1 按协调方向画成「节点旁一个浮动托盘 + 其余节点压暗 + 点空白 / Esc 收起 + 同时只开一个」（存档：[`shots/v1-floating-panel-rejected-dark-zh.png`](shots/v1-floating-panel-rejected-dark-zh.png)）。用户看后改成 v2：

1. 去掉浮层外框和整画布压暗；版本就是画布上的**一排节点卡**，卡片上方的小标签写「第 N 版」，主图带「主图」标；和原节点相邻成组，分组提示要克制。
2. 铺开是**持久的**：点空白、按 Esc、去操作别的节点都不收；只有再点那个图标才收。**可以同时铺开多个**。
3. 入口是节点**右侧**的「图标 + 数字」（替换原来「N 版」胶囊的位置），铺开后同一位置变成收起图标。
4. 右边放不下就往左；**绝不挪别的节点、不动视口**；会盖住邻居时给方案（进「疑问」），样张做推荐方案。
5. 12 版：先铺 8 张 +「+N」，点开铺其余（换不换行由设计定，写理由）。

保留不变：收起态（节点显示主图 + 背后叠卡边缘）、旧小窗 8 件事的去处、设为主图的提示 + 撤销 + 下游 N 个、删除改撤销、「+N」、中英 / 亮暗。

## 任务卡

**反复出图的创作者，在挑版本的那一刻：把几版铺开、定一张主图、删掉废片；铺开的可以留着对照，接着去处理别的节点。**

## 样张里能做的

- 点节点右侧的层叠图标：版本在原地铺成一排卡片；只有再点同一个图标才收。
- 悬停版本卡：上方出「设为主图 / 下载 / 删除」（制作镜头多一个「重拍这镜」）；点卡片本身是大图预览（← → 翻版本），不改主图。
- 同时铺开两个，再去点、去拖第三个节点：两排都在；被盖住的节点一点就浮到最上面，它的标题也回来。
- 「场景 · 雨巷」设主图：提示「下游 3 个节点下次生成会用它」+ 撤销，3 条下游连线和节点同时亮一下。
- 删除：不弹框，提示里撤销（Ctrl / ⌘ + Z 也行）；删主图时提示写明「第 N 版成为主图」和下游个数。
- 「角色 · 林雾」12 版：先铺 8 张 +「+4」，点开在下面换行成第二排。
- 「镜头 5 · 街角回望」贴右边：往左铺。
- 视频卡：悬停就播、拖底边进度条、聚焦后 ← → 一次 1 秒。
- 拖版本卡＝拖整组；按住 Alt 拖到空白处＝复制成独立素材卡。
- 拖空白处平移、左下角缩放：卡片跟着节点走，视口只在你自己拖的时候动。

## 你可能漏的

### 方向里写了，这里讲清它解决什么

1. **原地铺开、一直留着、可以同时开好几个。** 旧小窗是临时浮层，一点别处就关，挑版本时没法顺手去改别的节点。现在铺开是画布上的一种摆放状态，跟编组折叠一样由你开关。
2. **绝不挪别的节点、不动视口。** 铺开只在原节点旁加卡片；右边放不下往左。位置不够时卡片会盖到邻居上（怎么盖见疑问 1），但不会把邻居推走，也不会自己平移画布（09-25 拍板）。实测：铺开 / 收起 / 往左铺前后，视口和所有节点坐标都不变（交互核对第 6、11 条）。
3. **先铺 8 张 +「+N」；点开后换行成第二排。** 12 版一排两千多像素。为什么点开后换行、不接着往右：第一排已经是屏幕上看得到的宽度，往右加只会伸出屏外，而程序不许替你挪画布；往下换行留在同一宽度里（样张实测 835 × 326 屏幕像素，全在画布内），读序仍是从新到旧。
4. **设为主图后，提示里写明下游几个节点。** 换主图会改掉下游节点拿到的输入，现在悄悄发生；画布上也没有「参考已变」标记（只有分镜表有，`src/workbench/creation/storyboard/exec/storyboardRowStatus.ts:77`；上游版本戳在 `src/workbench/generationCanvas/runner/refSnapshotStamp.ts:4-9`）。提示写「**下次生成**会用它」，免得被读成下游会自动重跑、自动花钱——它不会。
5. **删除不弹框，提示里撤销。** 但现在删除会当场删掉盘上的文件（`src/workbench/assets/deleteAssetResult.ts:117-122`，先改元数据、保存项目、再 `workspace.deleteFiles`）。要能撤销，实现时得把真删文件推迟到提示消失以后（提示期间只从版本里拿掉）。这是数据层改动，不只是换 UI；还要想清提示期间关掉 App 时文件怎么办。

### 我另外发现的

6. **分组只靠一条细线。** 去掉外框后版本卡和节点长得一样，会被当成「多出来 5 个节点」。样张用一条 1.5px 细线：从展开图标下方往下，再拐到卡片底下（像托盘的底边）。它住在节点下面一层，碰到别的节点就被挡住，不划过别人的画面。
7. **被压住的标题先藏起来（我补的规则）。** 版本卡盖在邻居上时，邻居的标题文字会从卡片标签的空隙里漏出来，和「第 N 版」拼成一行（改之前的截图里「第 9 版 ✓主图 镜头 2 · 视频 推镜进入咖啡馆」连成一串）。规则：按层级（选中节点 > 选中的版本组 > 版本组 > 普通节点），谁在下面、标签又被压到，谁的标签先藏；点中它浮上来就恢复。实现是节点和版本卡矩形求交，全在画布坐标里。
8. **铺开着也要能接着生成。** 现在展开版本时，节点自己的工具条、生成浮框、拖进时间轴把手都会被卸掉（`src/workbench/generationCanvas/nodes/BaseGenerationNode.tsx:197`、`:222`、`:295`）——那是给临时小窗用的。铺开变持久后必须去掉这条限制，否则铺着就没法生成下一版。
9. **版本卡没有连线把手。** 长得像节点但不是节点：不能连线、不能单独跑生成。去掉左右把手就是在视觉上说「这不是完整节点」。要拿某一版当下游参考：Alt 拖出一张独立素材卡再连。
10. **拖版本卡＝拖整组。** 卡片属于节点，拖它就是拖节点（和它的版本一起走）；Alt 拖＝复制出来（设计软件里「Alt 拖复制」同一个手势）。现状小窗里不按 Alt 的拖动什么也不做（`NodeResultStack.tsx:200-209`）。
11. **铺开状态要存进项目（我的默认）。** 和编组折叠一样按节点记住（编组的 `collapsed` 在 `model/generationCanvasTypes.ts:213`，随画布快照的 `groups` 一起存盘，同文件 `:270`），关掉项目再打开还铺着；否则「持久」只持续到切页。
12. **「同节点大小」很占地方。** 80% 缩放、1:1 节点宽 240：同尺寸 5 张一排 1011 屏幕像素、有 2 张伸出 1310 宽的画布；开着 Agent 面板时画布可见宽只有约 810（before 截图实量 60→870）。铺开又是常驻的：实测同一排的邻居只露出 5%～16%（紧凑：20%～100%）。见疑问 1、2。
13. **「第 N 版」编号会漂。** 现在编号是列表下标（`NodeResultStack.tsx:517` 的 `index + 1`），列表又是最新在前（`store/nodeRunOutcome.ts:24-41` 的 `mergeResultHistory`）：每出一版新的，所有旧版号 +1；删一版，后面的都 −1。提示里说「已删除第 3 版」时，卡片上的「第 3 版」可能已经是另一张。样张改成号跟着版本走（1＝最早），删了留空号；最新一张紧挨节点，「+N」收的是最早的几版。实现要给结果存一个持久序号。
14. **删主图会自动顶一个新主图。** 删掉当前版本时，剩下最新的一版自动成为主图（`model/nodeResultLifecycle.ts:77-81`），下游也跟着换。样张的删除提示写明「第 N 版成为主图」+ 下游个数。
15. **层叠图标撞车。** `IconStack2` 在画布上已经是「编组」（`components/CollapsedGroupCard.tsx:78`、`components/GroupFrameHeader.tsx:218`），`IconBoxMultiple` 是「镜头」类型图标（`nodes/renderRegistry.tsx:55`）。样张用 Tabler 的 `IconVersions`（名字就叫版本：一张卡后叠两张），收起用已登记的 `IconArrowsDiagonalMinimize2`（§6 里的「原地收拢」）。实现时 `IconVersions` 要进 `src/vendor/tablerIcons.ts` 并在设计系统 §6 登记一行。
16. **「重拍这镜」是整镜动作，而且花钱。** 调用时只带镜头号、不带版本（`NodeResultStack.tsx:392` → `reworkProductionShot(projectId, runId, shotId)`）；放进每张卡的悬停条会被读成「按这一版重拍」，挨着下载也容易误点。见疑问 3。
17. **新生成的版本自动变主图。** 每次生成完，新结果直接顶成主图（`mergeResultHistory` + `result` 覆盖），下游一样悄悄换。这是现状，样张照画（重拍出的新版会自动带「主图」）；要不要改归下一刀。
18. **视频节点也叫「主图」。** 按用户原话只留一个词（「设为主图」4 字，合 §1.8）；中文里「主图视频」本来就常用。英文统一 Primary / Make primary（2 词）。
19. **预览里暂不放「设为主图」。** 照「一功能一个家」只住悬停条；放大看完想当场定是个真需求，要加得在 §1.5 登记例外。
20. **竞品证据是空白。** LibTV 做的是画布级全局「历史记录」（`docs/product/2026-09-07-libtv-full-feature-by-feature-comparison.md:51`），节点级版本怎么摆我们没调研过（`docs/research/competitive/2026-09-25/libtv-design-notes.md:142` 列为持续观察）。这版是自家推导，不是竞品还原。

## 疑问（3 条，都带推荐；样张里都能切换对比）

### 1. 铺开的卡片盖住邻居节点时怎么办？

- **推荐：盖在上面。** 被盖住的邻居露出来的部分照样能点，点中它就浮到最上面；它的标题被压住时先藏起来（见上面第 7 条）。「点中就浮上来」就是画布现在的行为：选中节点被 Nomi 自己的样式抬到 `z-index: 5`（`src/workbench/generationCanvas/reactFlow/generationCanvasReactFlow.css:34-36`），React Flow 内核的 `elevateNodesOnSelect` 是关着的（`reactFlow/GenerationCanvasReactFlowViewport.tsx:209`）。
- ⚠️ 仓库里对「选中要不要提层」有两份说法：上面那条 CSS 在提；`docs/engineering/framework-boundaries.json:1058-1062` 给关掉内核提层写的理由却是「选中不该改层」。推荐方案依赖 CSS 现在的行为，拍板时请顺手把那条理由改成「由 Nomi 自己的样式提到 5，不用内核的提层（内核会越过框 / 折叠卡的分层）」。
- 为什么：不许挪人、不许动视口，挤的地方只能叠。「卡片自动收紧到空隙里」在挤的画布上不成立：样张里「镜头 1」右边到「镜头 2」的空隙只有 120（画布单位），扣掉图标位后一张紧凑卡（宽 120）都放不下，等于没铺开。
- 要和疑问 2 一起定：同节点大小时，同一排的邻居只露出 5%～16%（实测），「点露出的部分」几乎点不到；紧凑时露 20%～100%。
- 另一种（样张开关「不选中时垫下面」）：你去处理别的节点，铺开的就沉到邻居下面，邻居永远完整；代价是回来找版本时有的被挡住，要先点一下它的节点。
- 截图：[`03-two-open-operating-third-dark-zh.png`](shots/03-two-open-operating-third-dark-zh.png)（推荐）、[`13-cover-under-when-not-selected-dark-zh.png`](shots/13-cover-under-when-not-selected-dark-zh.png)（另一种）。

### 2. 版本卡默认多大？

- **推荐：紧凑**（节点的一半宽、一半高）。
- 为什么：铺开现在是常驻的，卡片会长期占着画布。80% 缩放下同节点大小 5 张一排约 1010 屏幕像素、把同一排邻居盖得只剩 5%～16%；紧凑面积是四分之一，5 张约 520，邻居露 20%～100%。看细节交给点开预览。
- 代价：卡片小，比细节要多点一下。样张默认仍按最初方向用「同节点大小」，右上角切换。
- 截图：[`02-expanded-in-place-dark-zh.png`](shots/02-expanded-in-place-dark-zh.png) / [`02b-expanded-compact-dark-zh.png`](shots/02b-expanded-compact-dark-zh.png)，同节点大小的代价：[`02c-node-size-covers-and-overflows-dark-zh.png`](shots/02c-node-size-covers-and-overflows-dark-zh.png)。

### 3. 「重拍这镜」放哪？

- **推荐：整排只放一张「重拍这镜」卡**，放在新版本会出现的位置（紧挨节点）；点它后那张卡变成「排队中 / 生成中」，出片后就是新的一版。
- 为什么：重拍是整镜动作、要花钱；放进每张卡的悬停条既重复 N 次，又像「按这一版重拍」，还挨着下载。
- 代价：和协调方向不同；排里多一张卡。样张默认按方向画在悬停条里，开关「排头一张」切换。
- 截图：[`09-production-rerun-bar-dark-zh.png`](shots/09-production-rerun-bar-dark-zh.png)（方向）、[`09b-production-rerun-slot-dark-zh.png`](shots/09b-production-rerun-slot-dark-zh.png)（推荐）、[`09d-production-rerun-landed-dark-zh.png`](shots/09d-production-rerun-landed-dark-zh.png)（出片落地）。

## 关键取舍（为什么这么放）

- **版本卡＝画布上的节点卡，不是面板。** 同样的圆角、描边、阴影、上方标签行（「第 N 版」用和「镜头 N」同款的小标签），跟着画布平移缩放。区别只有三处：没有连线把手、主图用标签不用蓝框（蓝框在画布上是「选中」）、悬停出动作条。
- **图标位置照旧（节点右侧、原「N 版」胶囊处）。** 铺开后它正好夹在节点和第一张卡之间，像一个铰链；收起图标只能在这里，用户不用找。
- **最新一张紧挨节点，「+N」收最早的。** 新生成的最常被看；挤不下时藏起来的是最旧的。往左铺时顺序镜像，最新的仍紧挨节点。
- **点卡片＝预览，不改主图。** 旧小窗「点一行就换主图」是误触源头；换主图会改下游，必须是一次明确的点击。
- **动作条浮在卡片上方、反向缩放。** 和节点浮动工具条同一套外壳（`FloatingToolbarShell`：边框 + 纸色 + 中阴影，按钮 32px，图标 16 / 1.6），缩到多小都看得清；不压画面（§1.5.3「动作不许压在内容上」）。
- **分组细线 + 遮挡规则。** 没有面板时靠一条细线成组；叠在邻居上时靠「被压住的标签先藏」保证读得清。两条都不新增常驻控件。
- **不压暗、不聚焦模式。** 铺开不打断工作，别的节点保持原样可操作。
