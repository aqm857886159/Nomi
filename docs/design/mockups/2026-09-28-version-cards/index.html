    • 方向里写了，这里说清它解决什么
    • 原地铺开、一直留着、可以同时开好几个旧小窗是临时浮层，一点别处就关，挑版本时没法顺手去改别的节点。现在铺开是画布上的一种摆放状态，跟编组折叠一样由你开关：点空白、按 Esc、去操作别的节点都不收，只有再点那个图标才收。
    • 绝不挪别的节点、不动视口铺开只在原节点旁边加卡片；右边放不下往左。位置不够时卡片会盖到邻居上（怎么盖见疑问 1），但不会把邻居推走，也不会自己平移画布（09-25 拍板）。
    • 先铺 8 张，更早的收成「+N」；点开后换行成第二排12 版一排要两千多像素宽。为什么点开后换行、不接着往右：第一排已经是屏幕上看得到的宽度，往右加只会伸出屏外，而程序不许替你挪画布；往下换行留在同一宽度里，读序仍是从新到旧。
    • 设为主图后，提示里写明下游几个节点换主图会改掉下游节点拿到的输入，现在悄悄发生；画布上也没有「参考已变」标记（只有分镜表有，storyboardRowStatus.ts:77）。提示写「下次生成会用它」，免得被读成下游会自动重跑、自动花钱——它不会。
    • 删除不弹框，提示里撤销每删一张少点一次确认。但现在删除会当场删掉盘上的文件（deleteAssetResult.ts:117-122）；要能撤销，实现时得把真删文件推迟到提示消失以后。这是数据层的改动，不只是换个界面。
    • 我另外发现的
    • 分组只靠一条细线去掉外框以后，版本卡和节点长得一样，容易被当成「多出来 5 个节点」。样张用一条 1.5px 的细线，从展开图标下方拐到卡片底下，像托盘的底边；它住在节点下面一层，碰到别的节点就被挡住，不会划过别人的画面。
    • 被压住的标题先藏起来（我补的）版本卡盖在邻居上时，邻居的标题文字会从卡片标签的空隙里漏出来，和「第 N 版」拼成一行，读起来像出错了。样张的规则：谁在下面、标题又被压到，谁的标题先藏；点中它浮上来就恢复。实现时拿节点和版本卡的矩形求交就行（都在画布坐标里）。
    • 铺开着也要能接着生成现在展开版本时，节点自己的工具条、生成浮框、拖进时间轴把手都会被卸掉（BaseGenerationNode.tsx:197,222,295）——那是给临时小窗用的。铺开变成持久状态后必须去掉这条限制，否则铺着就没法生成下一版。
    • 版本卡没有连线把手长得像节点但不是节点：不能连线、不能单独跑生成。去掉左右把手，就是在视觉上说「这不是完整节点」。要拿某一版当下游参考：Alt 拖出一张独立素材卡再连。
    • 拖版本卡＝拖整组卡片属于节点，拖它就是拖节点（和它的版本一起走）；Alt 拖＝复制出来，和设计软件里「Alt 拖复制」同一个手势。
    • 铺开状态要存进项目和编组折叠一样按节点记住（我的默认）：关掉项目再打开还铺着。否则「持久」只持续到切页。
    • 「同节点大小」很占地方80% 缩放下 1:1 节点宽 240：同尺寸 5 张一排约 1010 屏幕像素；开着 Agent 面板时画布可见宽只有约 810（before 截图实量）。铺开又是常驻的，同尺寸会把同一排的邻居盖得只剩 5%～16%。「紧凑」（半宽半高）面积只有四分之一，5 张约 520，邻居露 20%～100%。见疑问 2。
    • 「第 N 版」编号会漂现在的编号是列表下标（NodeResultStack.tsx:517），列表又是最新在前（nodeRunOutcome.ts:24-41）：每出一版新的，所有旧版号 +1；删一版，后面的都 −1。样张改成号跟着版本走（1＝最早），删了留空号；最新一张紧挨节点，「+N」收的是最早的几版。
    • 删主图会自动顶一个新主图删掉当前版本时，剩下最新的一版自动成为主图（nodeResultLifecycle.ts:77-81），下游也跟着换。样张的删除提示写明「第 N 版成为主图」和下游个数。
    • 层叠图标撞车IconStack2 在画布上已经是「编组」（CollapsedGroupCard.tsx:78、GroupFrameHeader.tsx:218），拿来当版本图标会被读成一个组。样张用 Tabler 的 IconVersions（名字就叫版本），收起用已登记的 IconArrowsDiagonalMinimize2（原地收拢）；实现时要进 src/vendor/tablerIcons.ts 并在设计系统 §6 登记。
    • 「重拍这镜」是整镜动作，而且花钱它只带镜头号、不带版本（NodeResultStack.tsx:392）；放进每张卡的悬停条，会被读成「按这一版重拍」，挨着下载也容易误点。见疑问 3。
    • 新生成的版本自动变主图每次生成完，新结果直接顶成主图（nodeRunOutcome.ts:24-41），下游一样悄悄换。这是现状，样张照画（重拍出的新版会自动带「主图」），要不要改归下一刀。
    • 视频节点也叫「主图」按用户原话只留一个词；中文里「主图视频」本来就常用。英文统一 Primary。
    • 预览里暂不放「设为主图」照「一功能一个家」，设主图只住悬停条。放大看完想当场定，是个真需求；要加得在 §1.5 登记例外。
    • 竞品证据是空白LibTV 做的是画布级全局「历史记录」（libtv-full-feature-by-feature-comparison.md:51），节点级版本怎么摆我们没调研过（libtv-design-notes.md:142 列为持续观察）。卡片解剖借 AI Elements Artifact（头＝标题＋动作，内容是纯媒体不被盖）和 Beautiful UI Selection Actions（动作条浮在目标上方）。
    • In the direction — what each one solves
    • Lay out in place, stay open, several at onceThe old window was a transient overlay that closed on any outside click, so you couldn’t touch another node while choosing. Now “laid out” is a canvas state you switch, like collapsing a group: clicking empty canvas, pressing Esc or working on other nodes never folds it; only the icon does.
    • Never move other nodes or the viewportCards are added beside the node, flipping left when the right side has no room. When space runs out they overlap neighbours (how, see question 1) but never push them away, and the app never pans for you (decided 09-25).
    • First 8, older ones fold into “+N”; expanding wraps to a second rowTwelve versions in one row is over 2,000 px. Why wrap instead of continuing right: the first row is already as wide as what’s on screen; adding to the right only runs off screen, and the app may not pan. Wrapping keeps the same width, and reading order is still newest to oldest.
    • The primary notice names downstream nodesSwitching the primary changes what downstream nodes receive, silently today, and the canvas has no “reference changed” marker (only the storyboard table has one, storyboardRowStatus.ts:77). “Will use it next time they generate” keeps it from reading as an automatic, paid re-run, which it isn’t.
    • Delete without a dialog, Undo in the noticeOne click less per delete. But delete currently removes the file on disk immediately (deleteAssetResult.ts:117-122); to undo, the real deletion has to wait until the notice expires. That’s a data-layer change, not a UI swap.
    • What I found on top
    • Grouping by one thin lineWithout a frame, version cards look like nodes and read as “five new nodes”. A single 1.5 px line runs from under the expand icon and turns under the cards, like the lip of a tray. It sits one layer below nodes, so it disappears behind any node it crosses instead of striking through its image.
    • Covered titles hide (my addition)When cards cover a neighbour, its title leaks through the gaps between card labels and merges with “Version N” into one line that looks broken. The rule: whoever is underneath and has its label covered hides that label; it returns when the node is clicked and comes to the top. Implementation is a rectangle intersection between nodes and version cards, all in canvas coordinates.
    • Laid-out nodes must still generateToday, opening versions unmounts the node’s toolbar, composer and timeline handle (BaseGenerationNode.tsx:197,222,295), which made sense for a transient window. With a persistent layout that rule has to go, or you can’t generate the next version while versions are out.
    • Version cards have no connection handlesThey look like nodes but aren’t: no links, no separate generation. Dropping the side handles says so visually. To use a version downstream, Alt-drag it out as an asset card and connect that.
    • Dragging a version card drags the groupThe card belongs to the node, so dragging it moves the node with its versions; Alt-drag copies it out, the same gesture as Alt-drag-to-duplicate in design tools.
    • The laid-out state should be saved in the projectRemembered per node like group collapse (my default), so it survives closing and reopening; otherwise “persistent” only lasts until you switch pages.
    • “Node size” takes a lot of roomAt 80% zoom a 1:1 node is 240 wide: five node-size cards take about 1,010 screen px, while the canvas is about 810 px wide with the Agent panel open (measured on the before screenshot). Since rows now stay open, node-size cards leave same-row neighbours only 5–16% visible. Compact (half width, half height) is a quarter of the area: about 520 px for five, neighbours 20–100% visible. See question 2.
    • “Version N” numbers driftToday the number is the list index (NodeResultStack.tsx:517) and the list is newest-first (nodeRunOutcome.ts:24-41): every new version bumps older numbers by one, every delete shifts them back. The mockup ties numbers to versions (1 = oldest, gaps stay after deletes); the newest sits next to the node and “+N” holds the oldest.
    • Deleting the primary silently promotes anotherThe newest remaining version becomes primary (nodeResultLifecycle.ts:77-81) and downstream follows. The delete notice now says which version became primary and how many downstream nodes are affected.
    • Stack icon collisionIconStack2 already means “group” on the canvas (CollapsedGroupCard.tsx:78, GroupFrameHeader.tsx:218). The mockup uses Tabler’s IconVersions, and folds with the registered IconArrowsDiagonalMinimize2; both need src/vendor/tablerIcons.ts and a §6 entry.
    • “Re-film shot” acts on the whole shot and costs moneyIt carries the shot, not a version (NodeResultStack.tsx:392). On every card’s hover bar it reads as “re-film from this version”, one slip away from Download. See question 3.
    • New versions become primary automaticallyEach finished generation replaces the primary (nodeRunOutcome.ts:24-41), so downstream changes quietly there too. That’s today’s behaviour and the mockup follows it; changing it belongs to a later cut.
    • Video nodes also say “Primary”One word, as the user put it; in Chinese “主图视频” is already common usage.
    • No “Make primary” inside the preview (yet)Per “one home per action”, it lives on the hover bar only. Deciding right after a close look is a real need; adding it means registering an exception in §1.5.
    • No competitor evidenceLibTV has a canvas-wide history list (libtv-full-feature-by-feature-comparison.md:51); how anyone lays out per-node versions was never researched (libtv-design-notes.md:142). Card anatomy borrows AI Elements Artifact (header = title + actions, media never covered) and Beautiful UI Selection Actions (action bar floats above the target).
