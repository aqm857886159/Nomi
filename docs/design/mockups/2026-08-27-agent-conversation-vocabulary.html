同排按钮四条规则
1 · 同一排的动作按钮 等宽均分（flex:1），主次只用颜色分：深底=主，描边=次。层级不靠尺寸。
2 · 一排最多 3 个；再多 → 主按钮 + 「更多」收起。
3 · 文字链 不与按钮同排 —— 要么单独一行，要么升级成按钮。
4 · 选项 chip 例外：按内容定宽（它是内容不是动作），但同组高/圆角/字号必须一致。
派生纪律：文案要为布局让步 —— 三等分时「换个模型重试」会挤，写「换模型重试」。实现时长文案撑破行 = 设计错误，不是内容问题。

输入区 · 技能、提示词与快捷输入（默认不要求用户配置）
1 · 默认自动匹配技能。用户直接描述任务即可；只有想锁定完整工作流时，才打开「技能」。
2 · 技能先看结果。悬停或键盘聚焦显示 16:9 图片/静音视频，同时列出输入、产物、步骤与能力依赖；无媒体时显示结构化说明，不造假封面。
3 · 提示词独立。提示词只改变本轮回答侧重，不调用工具；选择后以可移除引用显示，并能看到完整正文，不再藏进技能名称。
4 · 四条入口只有一套语义。拖入=添加文件，@=引用现场或对象，/=快速调用技能，按钮=可发现入口；最后都进入同一份发送快照。
5 · 一次只固定一个技能和一个提示词。多技能编排由 Agent 在计划里解释；缺少浏览器、模型或素材权限时，在选择前直接显示。
6 · Connector 不做常驻按钮。浏览器、图库、音乐库等由 Agent 调用、@ 引用或技能依赖进入；生成参数继续在计划卡确认。

MiniMax Design：右侧 Agent、中间流程画布、左侧 Skill/资产，以及 3D/剪辑专项 Agent，证明“对话连续 + 专业子界面”可共存；Nomi 保留层级，但不把模型、Skill、自动模式平铺成一排。
TapNow：作品可以打开“只读创作过程”并克隆项目，说明工作流应以真实节点和产物展示；因此 Nomi 的技能选择先看演示、输入和产物，再决定是否调用。
YouMind：官方 Skill 广场按图片、视频、写作等产物分类，并明确步骤、输入和默认模型；因此 Skill 名称只是次级信息，用户先按结果发现技能。
小云雀：长剧本、角色生命周期、统一风格与多集连续生成属于项目状态；因此不能把每次聊天当成孤立的一次生成。
AI SDK Elements：Conversation、Attachments、Confirmation、Context、Plan、Queue、Reasoning、Sources、Task、Tool 与 Artifact 是按状态出现的反馈组件，不应全部常驻；Nomi 复用已有 18 种反馈，只补滚动回底、来源与输入快捷层。
Pi Agent Extensions：/sessions、/workflow、文件浏览、结构化提问、上下文仪表、旁路提问与后台通知证明命令可加速复杂 Agent；Nomi 用 / 调技能、@ 引用、药丸承载后台状态，但不复制终端式界面。
