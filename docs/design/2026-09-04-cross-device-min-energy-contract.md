# 跨设备继续编辑：界面契约

这份契约先于生产代码。视觉验收不再使用独立 HTML；必须启动真实 Nomi，使用 `SettingsDialog`、`ProjectLocationSection` 和真实 token 截图。最新真实 Settings 页面和 `SettingsDialog.tsx` 是唯一底稿。

## 用户任务

用户只想把项目从电脑 A 带到电脑 B 继续编辑。最短路径是：选择一个项目文件夹 → 用已有同步工具双向同步 → 在另一台电脑打开项目。

## 信息层级

- L1：新项目默认位置；自动另存生成物不再占用此页面的设置空间。
- L2：更改、打开文件夹、检查目录。
- L3：同步工具说明和“Nomi 不上传项目”放入短提示/信息提示，不占主视觉。
- 不新增同步中心、顶部入口或第三方账号配置。
- 自动另存生成物的设置入口从“文件与保存”移除；生成物仍保留现有内部存储与手动下载能力。

## 文案规则

- 主状态使用用户结果，不用产品术语；推荐 `可在另一台电脑继续编辑`，异常用 `需要重新检查`、`素材未同步`。
- 说明最多一行：`VerySync / 坚果云：双向同步此文件夹`。
- 不使用“同步成功”“已完成同步”等 Nomi 无法证明的说法。
- “Nomi 不上传项目”只出现一次；默认收进信息提示，避免重复解释。
- 每个异常只给一个主动作：`检查目录`或`重新检查`。
- 不假设用户认识 VerySync/坚果云；主界面统一称为`同步工具`，品牌名只放在“查看步骤”里作为例子。

## 不熟悉同步工具时

- 默认只显示一行：`用同步工具同步上面的文件夹`，旁边提供`查看 3 步`；展开后才显示三个编号步骤。
- 展开后只说明三步：安装一个同步工具 → 添加上面的项目文件夹 → 等待工具显示传输完成，再在另一台电脑打开 Nomi。
- 提供`复制路径`和`打开文件夹`，不要求用户手写路径或理解 Nomi 内部文件格式。
- Nomi 不自动安装、登录或配置第三方同步工具；不检测“同步成功”，只检查本地目录和项目完整性。
- `VerySync` / `坚果云`入口只打开各自官方页面；链接需在实现前按官方文档核验，不在 Nomi 内嵌登录或安装流程。

## 视觉和组件规则

- 使用 SettingsDialog 现有外壳、`DesignButton`、`rounded-nomi-sm`、`border-nomi-line`、`bg-nomi-ink-05` 和既有文字 token；浅色/深色跟随应用主题。
- 路径是主信息；“更改…”和“打开文件夹”属于 L2 次操作，使用紧凑的 `h-8` / `text-caption` 级别，不做大块按钮。
- 不在样张中自定义红绿颜色。状态色沿用真实组件 token；如果现有 success 色过重，应在共享状态组件层统一调淡，而不是在本功能单独改色。
- 保持真实页面已有分隔线和区块顺序，不在项目位置区块内部叠加横线。
- 路径、主按钮、次按钮保持同一行；响应式窄屏才换行。
- 排版分成两个语义区：`新项目默认位置`只负责路径和本地目录操作；`换电脑继续`只负责同步提示和可继续编辑状态。两区之间只使用 Settings 现有的一条分隔线，不叠加卡片。
- 状态通过真实项目夹具触发，正式页面只显示真实状态，不显示样张测试控件。

## 必须证明

1. 新用户 3 秒内找到项目位置和换电脑动作。
2. 设置完成后可以关闭电脑 A，在电脑 B 找到并打开项目。
3. 外部更新、素材未同步、目录失效均能给出唯一下一步。
4. 中文/英文和浅色/深色仍使用同一组件与 token。

## 视觉验收方式

1. 从最新分支启动真实 Nomi。
2. 打开设置 → 文件与保存，保持自动另存区域不变。
3. 对真实页面截图，逐项核对字号、按钮、间距、分隔线、主题和状态文案。
4. 不接受独立 HTML 与真实页面之间的“近似相同”。
