## D1 · 工作方式轴：掰回 3 档 vs 保留 4 档自主强度 【方向 · 必须拍板】

- **现状**：过渡版把工作方式做成 4 档「自主强度」`ask / guided(引导) / balanced(平衡) / auto(策略自动)`（截图 03），且**契约级**（`PROJECT_AGENT_WORK_MODES`），并把审批语义折进工作方式文案（「平衡=批准后自动填默认」「策略自动=高风险仍停」）。同时**丢了 `编辑选中`** 这一档（全仓不存在「只对冻结选区提修改」）。
- **建议**：**掰回 #194 §14.1 的 3 档 `Ask / 编辑选中 / Agent`**（这轴管「agent 能碰什么」），把「自主强度/问多少」并入**批准策略轴**（§14.2 的 3 档 `逐步确认/自动批准安全动作/完全允许`）。两轴正交、改工作方式不隐式扩大批准。
- **理由**：§14 是用户 **2026-08-27 亲自裁定**过的两根正交轴——4 档把「能碰什么」和「问多少」揉成一根、且丢了「只改冻结选区」这档最贴 J1「选中图片框 crop 改光线」的用法。cutover 不该单方改掉用户裁过的轴。
- **反选项**：若用户认为「4 档自主强度」更好用 → 需明确批准它**替代** §14、并同步改 `nomi-agent-interaction.md` §14（不留两套心智）。二选一，不并存。

## D2 · 结果卡区落地节奏：过渡期先互斥 vs 直接上双区并存

- **现状**：③合流终局已由用户 2026-09-01 拍板（右槽=Agent 工作区双区），但双区外壳（结果卡区）**尚未落地**；拆解 v1 现在按「就近面板」实施、与 AI 栏互斥抢槽（视图 06/07）。
- **建议**：**过渡期先走互斥**（屏 C：拆解开→Agent 收顶栏角标 / Agent 开→拆解收节点浮条），**双区外壳就绪后自然并存**（屏 D：拆解卡进结果卡区 + 会话流并存、互斥消失）。
- **理由**：拆解卡订阅**工件状态**（`videoUrl/nodeId` 维度的 `DeconstructVideoResult`）不绑面板 open 布尔，两阶段都不返工（`right-slot-opinion.md` 结果卡契约 + R-C-7）。先互斥不阻塞拆解 v1 交付；等 M 线交互 epic 落双区外壳时拆解卡平移进去即可。
- **风险提示**：若用户希望**跳过互斥、直接上双区**，则拆解 v1 需等这个 epic 的双区外壳先落地（拉长拆解交付）——不推荐（拆解 v1 引擎已九成熟，不该被 epic 卡住）。

## D3 · composer 附件触发：保留独立 📎 vs 并进「执行方式」

- **现状**：过渡版底栏 7 控件顶满 L1 ≤5 预算；收簇后（§7）@/技能归位到**输入框 @ token**（v3：上下文架已删）、工作方式+审批合成「执行方式」一簇，底栏剩 5 簇（📎附件 · ⚡执行方式 · 🤖模型 · ✏️提示词 · ↑发送）。
- **建议**：**保留 📎 附件独立触发**（收簇后 5 簇已在预算内，无需再收）。
- **理由**：附件是高频输入动作，并进「执行方式」反而多一次点击（§1.5.4 反例：为凑数把中频/高频控件收进 ▾ = 净负收益）。「≤5」是观察指标不是硬门，5 簇不超预算。
- **反选项**：若用户坚持底栏更瘦（如移动端 320px 极窄）→ 附件可降级进「+ 更多」，但仅在窄栏断点生效、桌面端保持独立。

## D4 · 付费富卡「本会话不再提示」：agent 对话档是否给这个开关

- **现状**：`SpendConfirmDialog` 的**用户直发档**有「本会话不再提示」开关（light 变体）；#194 §10 把付费确认拆成两宿主（用户直发→可选静默 / agent 受理→每次必确认 / 外部 MCP→倒计时）。
- **建议**：**agent 受理档不给「本会话不再提示」**（每次必确认），仅**用户直发档**保留该开关。**v3 样张已按此画**（agent 档卡上无开关也无倒计时——倒计时属外部 MCP 档）；反选只需回补一个勾选框。
- **理由**：agent 自动规划时的静默扣费风险高于用户亲手点生成——诚实优先（#194 §1③）。用户亲手点=他清楚在花钱；agent 自主跑=更该每次停一下。两宿主语义已在 §10 分开，这条是把「不再提示」的边界画在「谁发起」上。
- **反选项**：若用户要 agent 档也能静默（重度自动化流）→ 可给，但绑到批准策略的「完全允许（本项目）」档 + 预算护栏（超预算仍问，R-M-4），不做成付费卡上的独立勾选。

## D5 · 开闸删旧范围：一次删净 vs 渐进

- **现状**：过渡版（4 档工作方式契约 + 右槽互斥标志 `generationAiCollapsed`↔`videoDeconstructionCollapsed` 互翻 + resident 里未接护城河卡的转录路径）仍活着。
- **建议**：**开闸同 commit 删净**过渡版的 4 档工作方式契约 + 互斥抢槽逻辑（最终版右槽双区并存、互斥标志作废），拆解 handoff 靠工件状态键平移。
- **理由**：留着两套工作方式/两套右槽逻辑 = 并行版，违反 P1「加新必删旧、无并行版、无 fallback」。拆解卡订阅工件状态不绑面板布尔，平移不需渐进保留旧路径（C9 答案）。
- **风险提示**：删净是「开闸实现时」的动作，不在本设计包（纯设计零代码）。此条是**预先声明删旧范围**，让实现班知道最终版不与过渡版并存。
