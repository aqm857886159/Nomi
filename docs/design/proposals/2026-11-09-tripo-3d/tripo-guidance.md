# Tripo 使用与推广引导

日期：2026-11-09。用户已确定 Tripo 方向；本文是产品设计合同草案，尚未实施或取得界面拍板。复用[交互设计](interaction.md)与[API 合同](api-contract.md)，不新增账户、钱包、广告后台或另一套模型设置。

## 用户要完成什么

创作者已有一张道具参考图，希望把它变成能检查背面、放进场景、跨机位复用的资产。第一次使用卡在开户和凭据，生成后卡在判断质量和怎么放进镜头。引导分别解决这些问题，再提供可选的 Tripo 学习入口。

不把观看推广、重新注册或购买 Studio 设为生成前置条件。已有 Tripo API 账户的人直接连接；API 余额不足时只引导核对 API 余额。Studio 的积分和 API 积分分开，不能用一个含糊的“开通会员”按钮替代两种购买。[官方权益说明](https://www.tripo3d.ai/help/api-plugins/tripo-studiotripo-api)

## 三处入口，一个主任务

| 位置与触发 | 主动作 | 可选引导 | 目的地和约束 |
|---|---|---|---|
| 现有供应商连接页：首次选 Tripo、缺凭据 | 连接 API 账户，保存后返回原草稿 | 尚无 API 账户时提供官方开户/凭据帮助；另有折叠的 Studio 介绍 | 主动作去官方开发者平台；账户专属分享链接目前指向 Studio，不能拿来冒充 API 开户或充值入口 |
| 3D 节点/素材详情：真实产物成功落盘 | 检查模型、引用为素材、放入导演台 | 来源字段显示 Tripo 与实际模型版本，次级“了解 Tripo” | 复用现有来源/帮助位置；示意或导入资产不能冒称 Tripo 生成；不盖在预览上、不插成功弹窗 |
| 现有帮助/教程入口：用户主动学习 | 从参考图到同一道具的两个机位 | 展示真实输入、完整结果、失败局限和 Tripo 使用入口 | 产品操作指引优先；介绍 Studio 时才提供适用且披露的分享入口；不强迫离开未保存任务 |

“了解 Tripo”先解释网页 Studio 与 API 的区别，再让用户选择适合自己的目的地。只需 API 的人直接进入 API 路径；不把 Studio 一次性体验额度写成持续 API 权益。分享链接和适用范围由私有合作记录管理，实施时在既有供应商链接定义处维护，不散落到节点、Agent 和文案中。

## 引导如何验收

建议先按既有计划做 5 人形成性走查，再用 10 名真实创作者检验完整使用；这些是计划，当前没有用户成绩。

| 结果 | 量具与分母 | 通过/停止条件 |
|---|---|---|
| 能继续原任务 | 观察首次连接者从选模型、连接到返回相同草稿；记录耗时中位数、P90及放弃原因 | 不丢输入；已有账户不必重注册；连接与首次成功时间先取基线，不虚设已达标数字 |
| 真正完成创作 | 10 人各一次完整任务；落盘、离线重开、进入导演台、两机位引用同一资产的任务回执 | 沿用商业试点建议 ≥8/10 完成；单独记录上游失败和操作困难，不能把看见预览当完成 |
| 理解购买 | 购买前请参与者说出将买 API 额度还是 Studio，以及能在哪用；记录误解人数/观察人数 | 0 人因文案买错产品；发现一次误导就暂停对应推广入口并改稿 |
| 主动愿意了解 | 有权限时记录匿名聚合的入口展示→主动打开帮助/分享；按连接、结果、教程位置分别计数 | 点击率只诊断入口，不作为创作成功或收入证明；不上传素材、密钥、项目名或跨账户身份 |
| 产生实际收入 | 私有渠道按平台的归因订单、撤销、核准、付款分别对账 | 点击不等于购买，pending 不等于到账；未确认的 API 计佣预算为零 |

首期先交付连接解释与结果来源；教程用经过许可的真实案例后再发布。对照试验只调整可选说明的位置或措辞，保留同一主任务与披露。若主任务完成率下降、买错产品或支持负担超过新增价值，移除该位置的推广，正常 API 使用继续可用。

## 下一阶段的实施约束

不为本设计执行申请、对外联系、付费调用或真实推广。进入实现前：取得适用内嵌授权；核准桌面推广位置与目标页面；完成 Claude Design 画布、用户样张拍板及生产组件清单。分享链接只在供应商允许的方法下验证，不用自购、自邀或假注册制造转化。模型版本、上传引用、任务恢复和本地资产闭环继续按原 API 合同验收。
