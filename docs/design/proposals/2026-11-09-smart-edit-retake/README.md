# 智能编辑与视频局部重拍：功能方案

调研开始：2026-11-09 · 范围修订：2026-11-10（用户明确只用 APIMart） · 基线：`origin/main@7ca679e15e9bb1bd4cb789c43d2d2e0beba92f76`

**状态：研究与推荐方案，待产品评审；没有实施、模型实测或用户测试。** 本文中的默认值是本轮建议，不能当成用户已拍板。官方能力、源码事实与推断见 [research.md](research.md)。

**供应商范围：仅 APIMart。** 不接入其他供应商，不以别家官网能力推导 APIMart 能力。以下模型名均指 APIMart 提供的接口；本地切片、遮罩和合成复用 Nomi 的现有能力。

[TapNow / LibTV真实功能走查](tapnow-libtv-real.md)记录实际选区、意见、视频分段与一次标注保存；[交互决定](interaction.md)说明如何用于Nomi。产品界面只作操作参考，不扩展生成供应商；两家均未提交AI生成。

## 1. 要给创作者的结果

图片已经大致满意，只想把手、衣服、道具或一段字改对；视频前后已经满意，只想重做中间的一小段。两者共用一个习惯：**指出哪里 → 说怎么改 → 原位看新版本 → 对比或退回**。不让创作者手动找原参考图、搬文件或剪接结果。

推荐先做图片智能编辑，再让它成为视频关键帧修改的共用能力。视频第一轮聚焦**单条视频的一个连续时段**，并提供完整接回后的结果；不能只交一个孤立的新片段，就宣称局部重拍完成。

默认场景：分镜图片修改人物/物件，AI 生成视频修改动作或瑕疵。商品素材纳入反例；有对白素材用于验证原声保留，但首轮不承诺自动改台词或口型。

### 已定边界，继续沿用

- 修改已有素材默认回原节点版本栈；新生成的完整版本自动成为主图。对比、回到第 N 版都在素材本身发生。只有明确说“用这些做新的”才建新节点。
- 参考原节点的下游不自动重跑。已经剪进时间轴的素材不因主图变化而全部替换。
- Agent 只放引用、必要请示和回执；完整预览、选区与编辑器留在素材工作区。
- 沿用现有生成权限和 Run/任务身份，不因新功能再增加一层通用批准。普通评论不自动触发生成，明确按“生成修改”才是执行意图。
- 保留 Q-8：图片局部意见默认“当前成品图＋原参考”微调；原参考可见、可移除。没有兼容能力/参考槽不足时，既有一般迭代仍按原参考重来并说明；新的区域编辑不可静默变成整图重生，提供显式“按原参考重新生成”的切换，草稿如实写出改法。

以上来自 [select-to-iterate 已定规则](../../../plan/2026-10-21-select-to-iterate.md) 与 [设计系统 §1.0](../../nomi-design-system.md)。

## 2. 三条路线与推荐

| 路线 | 创作者会经历什么 | 收益与代价 | 判断 |
|---|---|---|---|
| 沿现有评论方向补齐 | 图上框选/标记、就地写意见；视频条上选时段；复用生成与版本 | 习惯连续、工作区不增一套；需补区域/时段的真实请求合同 | **推荐** |
| 新建完整图片/视频编辑器 | 打开独立编辑页，图层、遮罩、时间轴和参数集中配置 | 专业能力多，界面和维护成本高，创作者要多学一套 | 首轮不做 |
| 只在聊天里描述，删除区域工具 | 发图后说“把左边改掉”“改 2–4 秒” | 实现少，但指代含糊、难修正，仍要来回解释 | 不能完成用户需求 |

核心取舍：**先让人准确表达修改意图，再按模型实际能力执行；圈得出来不等于模型能严格锁住圈外。**

## 3. 图片智能编辑

### 3.1 入口与布局

图片快捷浮条的现有“改图”菜单加入“智能编辑”；全局评论、已有意见的“圈一下”、大图预览的编辑入口都打开**同一份图片编辑会话**。不在底栏、节点和聊天里各存一份标注。普通评论仍可只讨论。

进入后保留图片原位置；小图空间不足时在现有画布内大图预览中编辑。内容区是原图与标注，旁侧/底侧只放当前意见和“生成修改”。窄窗改底部输入，不在画面上铺长文字。顶部始终能认出“镜头 03 · 第 2 版”。

第一轮单图一次只执行一条修改意见；同一意图可包含多个不相连区域，例如两只鞋一起改色。不做多条冲突意见的自动合并。用户自然语言提出“全图暖一点”时允许不选区，发送前明确对象是整图。

### 3.2 默认怎么圈

**首轮推荐默认“框选”，另有细线“标记”；不再默认自由套索。** 拖出可调整的矩形，松手即可写意见；框只说明“改这里”，不承诺圈外像素锁定。编号放边缘，不遮挡脸或字。这是本轮真实走查后的设计判断，尚未证明比其他手势更省力。

| 动作 | 建议反馈 | 防止的摩擦 |
|---|---|---|
| 拖一个框 | 实时轮廓和浅色填充；松开后输入就绪，边/角可调整 | 不要求刷满，也不用猜开放路径如何闭合 |
| 用细线指示对象或多个位置 | 保留原始笔迹，与同一句意见绑定；不自动闭合成精确范围 | 一根线不悄悄变成半张图的遮罩 |
| 单点/极短笔迹 | 位置评论；可补框或文字，不启动语义识别 | 不把定位冒充对象识别或像素范围 |
| 需要补细节（后续） | “涂抹范围”，圆形笔头，增加/减去；显示笔头大小 | 精细mask不纳入首轮，不让每次修改先刷满 |
| 撤销、清除、平移 | 撤销回退本次标记；空格临时平移；清除范围不清文字，退出保留草稿 | 不用重写意见，画布移动不误画线 |

[真实走查](tapnow-libtv-real.md)中，LibTV点选依赖“识别中…”再给对象名，TapNow重绘用画笔/框选；没有足够依据把自由套索定为最佳默认。首轮避免增加语义分割等待和自由路径闭合规则；细线笔头只用于指示，圆笔头不意味着选区必须为圆形。笔头初值和默认工具仍须用真实素材做原型任务比较，不直接照抄竞品的3、4或30。

可访问替代：框选提供可编辑的范围值和键盘微调；不能画线的人仍可描述整图或框选修改。读屏播报目标版本、范围类型和当前动作；颜色之外保留编号与轮廓。标注采用设计 token，强对比外描边适配亮/暗素材，不加调色盘。

键盘按焦点归属：意见输入框里的空格/撤销保持文字编辑语义；媒体区域聚焦才平移/撤笔迹，沿用既有shortcut/modal owner，不能全局截获。

### 3.3 一次完整流程

1. 打开“智能编辑”，看到当前版本；已有评论的文字直接带入。
2. 框住需要改的东西，或用细线标记；松开后输入框就绪，预览中始终能看清范围和意见的对应。
3. 写“把这只杯子换成红色，人物和背景保持原样”；系统默认带上该版本的原参考，可移除，也可拖入一张目标杯子的参考图。参考重复只留一份，丢失则明示。
4. 下方显示“按标注修改，圈外也可能变化”。模型、实际提示词、来源与输入可展开核对，不能用不可见提示词改写用户指令。后续精细模式另显示“限定范围重绘”，不纳入首轮。
5. 点“生成修改”。执行前核对原图、版本、标注和参考资源已落盘可读，按现有权限提交一次。
6. 原图保持可看，编辑草稿保留；真实阶段显示“准备素材 / 生成中 / 正在保存”，不编造百分比。
7. 有效结果落原节点新版本并成为主图，仍停在同一张图；按住对比原版或拖分隔线；不满意可“回到第 2 版”或带原标注继续改。

### 3.4 发给 AI 的是什么

一份不可变请求冻结：项目、节点、**结果身份/版本**、提交前主图身份、原图资源及尺寸/方向、归一化标注路径/选区、用户意见、实际发送提示词、原参考/额外参考及角色、执行模型与输入能力、Run/任务身份。不能提交时再去读“此刻主图”，把用户圈的 v2 偷换成 v3。

正常完成仍自动主图。执行期间用户换了主图、另一次任务已落新版本、删除目标或停止采用，则保留结果在原任务并提示“有新结果待处理”，用户明确采用后才走统一版本owner；不抢走后来正在看的版本。历史版编辑区分“基于v2改”和“提交前主图是v5”，回退默认回到提交前v5，不把来源版与回退版混成一个号。

| 执行能力 | 实际输入 | 产品承诺 |
|---|---|---|
| APIMart 原生标注引导（首轮推荐） | 干净原图 + 同尺寸透明标注 PNG + 意见＋原参考 | “按标注修改”；圈外可能变化 |
| APIMart 原生遮罩重绘（后续精细模式） | 干净原图 + 同尺寸透明遮罩 + 意见＋原参考 | “限定范围重绘”；严格程度仍需实测 |
| APIMart 普通参考图改图 | 既有一般迭代按Q-8；未验证的标注图不能伪装原生区域能力 | 无标注能力时显式切到原参考重生，不能偷偷丢选区 |

优先验证原生标注路线。APIMart GPT Image 2.6 官方已说明 `markup_url` 是独立透明层，禁止与 `mask_url` 同传；Nomi 现有档案尚未声明这两项。**不借 headless 字段绕过“界面所见即实际输入”的保护**，要在模型输入合同、生成框与发送校验一起接通。

原图不烧入圈线；可读的合成标注预览是派生显示，不替代干净原图。局部裁图只作模型明确支持的补充上下文，保留坐标变换，不拿低分辨率截图代替原图。

**首轮只交“按标注修改”，允许圈外细微变化并明示；精细涂抹、原生遮罩和严格合成是后续切片，不阻塞首轮。** 后续只有严格模式才做本地合成：结果尺寸/坐标对齐通过后，选区外直接取原图像素；羽化边缘算作明确显示的编辑范围。用解码后的无损图验证圈外像素，而非 JPEG 文件字节。若新物体需要伸出选区，先让用户扩大范围，不能硬剪掉后当成功。APIMart的模型遮罩本身不保证圈外逐像素一致。

## 4. 视频局部重拍

### 4.1 创作者界面

视频节点现有片段条进入区间编辑后，提供并列动作“剪出片段 / 重拍此段”。前者仍产新片段，后者产完整新版本，避免相同选区下动词混淆。大图视频预览进入同一会话；不另外搭一套小时间轴。

选区显示左右手柄、起止时间和持续时间。默认循环选区，结果出来后默认循环“入点前 → 新段 → 出点后”，也可播放全片。不预先假定 2 秒最适合所有视频；已有时段选择直接沿用，没有则让用户明确选取。

每段意见与选区结构化绑定，调整范围不丢意见；清除选区要明确连带清除意见或保留为待重新选区的草稿，不能变成全片指令。未选部分默认沿用原素材，不让用户逐段设置“保持不变”。两端手柄改入出点，中部继续保留现有seek语义，不改成移动整段；拖动时暂停并预览对应边界，起止时间可输入/键盘微调。结果接缝循环暂建议前后各1秒、触到源片首尾则缩短，待真实任务检验；旧/新切换保持播放位置。上述决定的资料和限制见interaction.md。

第一轮节点入口修改单源视频；时间轴上下文菜单“重拍此段”定位到同一源素材会话并携带片段实例身份。首轮仅自动回填**单一源、正向、1×速度且无时间重映射**的片段；其他片段一步“打开源视频重拍”，原时间轴保留，不灰成死路。未来再接多片段/变速映射。

### 4.2 一次完整流程：2–4 秒

1. 选中视频，拖选 2–4 秒；看/听这段确认范围。
2. 写“抬手更自然，别改变人和镜头”。只写意图，系统读取当前版本的生成记录，用户不用找原图。
3. 自动准备原视频、原提示词/模型参数、仍可访问的原参考图，以及边界与选中帧。来源区列出实际使用项；导入视频显示“导入素材”，不编造生成记录。
4. 生成前显示**实际替换范围**、上下文窗口、原音轨策略与APIMart执行模型；选区不受支持时给“调整范围”或“选择支持的APIMart模型”，保留当前草稿。
5. 按现有权限生成。若需要先改关键帧，自动接入同一个图片智能编辑能力；用户可直接在关键帧上框选/标记并描述。关键帧确认留在素材工作区，Agent 只指向它。
6. 完整结果在临时产物中完成技术检查后落原节点新版本；主图自动更新，用户立即看到接缝循环预览。自动落主图不代表接缝质量已通过。
7. 不满意可回到上一版或再次重拍。若从时间轴发起，点一次“替换当前片段”才回填发起的那个实例；一次撤销可退回。

关键帧编辑是可选的控制手段，**不是每次强迫用户先走一轮改图**。首轮视频编辑先做一次视频模型调用；用户主动改关键帧时才增加一次图片生成，执行前展开两步计划，各有独立provider task_id/attempt，共同属于一个父Run。不能把“一次重拍”藏成未知多次生成，也不能把多个APIMart任务压成一个task_id。

### 4.3 底层执行路线

**推荐先验证 APIMart Seedance 2.5 的“视频编辑＋本地回填”。** 不依赖未在APIMart文档发现的“任意时段range”字段。

| APIMart能力 | 实际执行 | 边界与首轮安排 |
|---|---|---|
| Seedance 2.5 video edit | `video_urls`给编辑窗口；显式 `omni_reference_task_type=edit`、`size=adaptive`、`duration=-1`；编辑后取目标区间接回 | 官方编辑源片要求4–30秒；不是发送`duration:2`。Nomi已有参考模式但未声明这套edit合同；首轮技术试验主路线 |
| Gemini Omni 1.2 Flash edit | 一条≤15秒源视频，显式edit；文档说忽略duration、保持源时长 | 用于后续验证短源视频等条件；最低可编辑时长/小数时长保持能力未证实；仅16:9/9:16。不作为首轮静默替代 |
| APIMart 首尾帧生成 | 用边界图重新生成，再精确回填 | 后续自由动作重拍路线；时长/参考组合须按APIMart模式验证，不作为首轮兜底 |

例：12秒原片只改2–4秒。为满足Seedance编辑至少4秒的输入，系统准备原片1–5秒作为**4秒编辑窗口**；API结果仍需核对为4秒；取结果本地1–3秒，回填原片2–4秒，原片0–2和4–12直接来自原素材。选区不足4秒时系统补足上下文，不扩大替换范围。靠近片头/尾则向另一侧补足；原片总长不足4秒，该路线不可用，保留草稿并提供另一项经验证的APIMart能力或调整素材。

额外上下文是输入，不代表用户授权改它；**生成窗口 ≠ 替换窗口**。模型输出动作节奏不一定与源片同时间对应，局部裁取的连续性必须用真实结果验证。不能只因官方写“保持时长”就认定接回自然。

每个计划只选定一条已验证路线，失败不偷偷改策略。现有 Nomi 剪辑按0.1秒归一化，首轮UI按此精度表达；2.3–3.7不改成2–4。未来若要帧级选区，再补帧/PTS映射与量具，不能宣称现有控件已经帧级。没有任何通过试验的适配能力时不提交，提供可执行的APIMart模型选择或回到源素材。

### 4.4 参考图和首尾衔接

- 优先使用**当前结果版本**的生成来源快照，而不是当前节点已改过的提示词和连线；原参考默认保留并可见、可移除，用户新指令优先。模型模式不接的参考不能偷偷发入或丢掉后假装原条件未变。
- 原参考图取冻结的结果身份；缺失就列出缺失项。身份关键参考不可读时给一步重新关联；已有视频仍可走不依赖该参考的能力，明确告知条件变化。
- 截取入点前最后保留帧、出点后第一保留帧作接缝依据。首轮APIMart视频编辑不假设有关键帧定位参数；这些帧用于对比与可选改图，只有该模式明确支持的参考才进入请求。
- 改动作与保留边界姿态可能冲突，例如从“坐着”改成“站起离开”但只给半秒。执行前给扩大范围/缩小动作的明确建议，不能用不可能的首尾帧要求包装成功。
- 边界帧只能控制外观与部分姿态，不能保证速度、加速度、运镜和光照连续。自动检查可提示跳变，最终必须看/听完整接回后的结果；首轮不许用自动溶解掩盖失败。

### 4.5 时间、音轨与回填

请求冻结源视频版本/哈希、媒体时间基、目标起止、生成窗口、窗口内时间映射、生成来源、音轨策略与计划能力；时间轴发起另带片段实例和时间轴 revision。VFR 保留 PTS，不把帧号简单除以一个平均 fps。

本地回填输出时长与原片一致，选区外使用原片解码帧；统一编码时可能重编码，不承诺任意边界都能 stream-copy 无损。检查分辨率、方向、宽高比、时基、色彩和 HDR；首轮无法保留的规格显示明确能力限制，不能悄悄降成 SDR。APIMart编辑窗口通过现有上传机制获得可读取URL；上传大小和模型大小限制都要过，不因为模型接受200MB就假设上传接口也接受。原声留本地回填，不能假设APIMart返回原音轨。

生成片段过短、黑帧、无法解码或不满足替换映射，保留产物供查看并标为未完成，不覆盖当前版本。过长只在计划明确映射后裁切；不静默拉速、补定格或改全片时长。需要调速才能成立时回到计划。

默认保留原视频音轨和独立配音/音乐；生成音轨不自动替换。若动作改变导致音效不匹配，预览时标明并供检查；台词/口型修改另列后续能力。没有音轨的输入仍能完成。输出原声无损复制是否可用由容器/编码决定，不用“保留原声”承诺字节不变。

时间轴回填仅替换发起实例中对应的源引用，保留入出点、位置、变换、音量、淡入淡出和其他音轨；源素材完整版本与 timeline clip 不混用相同秒数。revision 变更则保留新版本，提供“重新定位当前片段”，不能回填到用户后来剪过的别处。多个引用实例不联动替换。

## 5. 两项能力的共同状态

| 状态 | 素材工作区 | Agent/任务中心 | 下一步 |
|---|---|---|---|
| 草稿/无范围 | 原素材可看，意见和选区可编辑 | 如从评论来，保留意见引用 | 选择范围或明确整图 |
| 准备中 | 显示准备实际输入；可退出 | 同一个 Run 的真实阶段 | 可取消，草稿保留 |
| 排队/生成中 | 原版本仍在，不锁全项目 | 同一任务身份和进度来源 | 去做别的；不重复提交 |
| 合成/保存中 | “正在接回原视频 / 正在保存” | 阶段继续，不另开第二个付费任务 | 本地失败只重试处理 |
| 成功 | 完整新版本主图＋对比/回退 | “已生成第 3 版”＋定位引用 | 看图或看完整接缝 |
| 部分成功 | 已生成但未接回；原主图保留 | 准确写“片段已生成，接回失败” | 从已保存产物重试合成 |
| 失败 | 范围与意见保留、具体原因 | 同一失败记录 | 改输入或显式重试 |
| 取消中/已停止 | 不假装上游已取消；原版保留 | 显示实际任务状态；晚到产物不自动采用 | 查看结果/重新发起 |
| 过期/冲突 | 目标版本或片段变更提示，旧标注不迁到新图 | 指向原身份，不猜新目标 | 继续编辑原版或重新标注 |
| 能力不可用 | 说明缺哪项输入/模型能力 | 同一句原因＋定位 | 选择支持模型；草稿跟随 |

中英关键文案：智能编辑 / Smart edit；框选 / Box selection；标记 / Mark；涂抹范围 / Paint selection；按标注修改 / Edit with markup；限定范围重绘 / Edit selected area；生成修改 / Generate edit；重拍此段 / Retake range；正在接回原视频 / Assembling full video；替换当前片段 / Replace this timeline clip；回到第 2 版 / Return to version 2。

## 6. 打断、存量与数据归属

| 时机 | 停止 | 关编辑面板 | 断网 | 重启 | 连点 |
|---|---|---|---|---|---|
| 提交前 | 保存草稿，无任务 | 保存草稿 | 保留本地输入 | 恢复草稿 | 不能创建重复计划 |
| 提交中/回执未知 | 记录停止意图，不能宣称APIMart未执行 | 保留提交记录 | 有task_id才可查询；无task_id保持待确认，不自动重发 | 恢复已存提交记录；缺task_id需人工关联 | 本机按intent抑制连点，不承诺上游恰好一次 |
| 已提交/生成中 | 有上游取消能力才请求；其他记停止采用 | 不取消远端任务 | 恢复查询 | 任务中心接回 | 不生成第二单 |
| 本地合成/保存 | 中止临时输出，保留已生成片段 | 持久任务可继续 | 本地输入齐全可继续 | 检查点续接，不重生 | 同一产物只落一次 |
| 已落版本 | 按回退而非停止处理 | 留在版本历史 | 本地可读 | 版本与引用恢复 | 幂等，不多一版 |

费用归现有 Spend/Run 回执，以APIMart实际状态为准；取消不等于退款，回执未知不等于没提交。当前APIMart适配器声明无上游submit幂等/取消能力，无task_id时对账为indeterminate：提供关联已知任务号/已有产物，或明确旧请求可能已执行后由用户显式重新生成，不能靠GET凭空找回丢失的任务号。只重试本地合成不触发新的生成授权；显式重新生成才创建新attempt。产品文案不编造“不扣费”等承诺。

唯一归属：标注与时段意图属于项目内的媒体反馈/编辑请求；生成计划/attempt 属于 Run；结果/版本号属于 `nodeResultLifecycle`；时间轴实例与撤销属于时间轴。UI 和 Agent 只投影同一请求，不建立另一套任务中心。此处是拟议归属，实施前还须核对概念登记并登记新增 owner。

升级不破坏旧项目：无标注/来源记录的旧素材保持现有打开、剪辑、生成能力。新字段可选；缺来源不编造。旧版对新字段的忽略/保存行为仍待真实旧数据验证，不能先承诺降级保存不丢新增记录。原素材和已成功产物不得删除；临时文件按既有资源引用与清理机制回收。

## 7. 全部入口与复用范围

两类真实短视频：相机运动的人物镜头、静物/商品镜头；另加对白片检验原声。分别验证2–4整秒和2.3–3.7非整秒；技术检查与人眼接缝评价分开。固定范围两端的替换映射、总时长、非选区内容来源、音轨同步与不重复提交；生成质量差不能用容器正确代替通过。
