# TapNow / LibTV：真实功能走查

日期：2026-11-10。通过 Chrome 中的真实产品界面操作，使用公开案例/站内示例中的现成图片、视频；不是仅阅读帮助页。生成接口方案仍然**只用 APIMart**，下文不推导竞品后端或接入其模型。

证据分三类：**实操**=实际点击、输入并观察反馈；**界面显示**=看见但没有跑到限制或结果；**未验证**=没有执行。截图保留在本次 CUA 工具记录，未导出成本目录的截图文件。

## 2. 图片：两家都把“画上去”和“让 AI 改”分开

### TapNow

| 实操步骤 | 真实反馈 | 边界 |
|---|---|---|
| 选真实图片 → 浮条“重绘” | 图上浮动工具含画笔、框选、橡皮擦；大小初始显示30；图下有“描述你想改变什么…”、参考、模型与生成按钮 | 初开时三个工具的可访问选中状态均为false；不能声称“默认画笔已选中” |
| 明确选择画笔，在墙面刷一笔 | 白色粗笔迹；只有笔迹而没有意见时，生成不可用 | 没有验证这条笔迹在请求中是mask还是markup |
| 输入“把标出的墙面改为深蓝色，人物和其他画面保持原样。” | 生成按钮可用 | 停在提交前，未验证输出是否改对、圈外是否变化 |
| 关闭重绘，再打开同一张图 | 此次意见、笔迹消失；撤销及生成不可用 | 只说明此次关闭/重开行为；不能泛化成所有导航或重启都会丢草稿 |
| 图片浮条更多 → “标注” | 独立工具：默认画笔、框选、橡皮擦、文字、红色、线宽4、撤销/重做、保存；没有修改意见或AI生成按钮 | 与重绘不是同一动作 |
| 画红线 → “保存” | “正在保存…”后提示“标注已保存”；出现独立 `Annotated Image` 节点和来源连线；原图保留，Agent输入区自动出现该标注图的引用 | **实际走完一次保存**，但没验证其是否保留可编辑矢量历史、如何再交给AI |

### LibTV

| 实操步骤 | 真实反馈 | 边界 |
|---|---|---|
| 选图片 → 浮条“元素编辑” | 默认“点选”，另有框选、画笔、撤销；提示“标记你想要修改的对象” | 默认来自实际界面，不据此认定最适合Nomi |
| 点人物手部附近 | 先“识别中…”，再出现对象名“手”，可“修改、移动” | 只测这个对象；没有识别准确率或等待时间统计 |
| 修改 → 输入“将衣袖改成深蓝色，保持人物与背景不变” → 添加 | 形成“编辑内容 1处”，对象缩略图、名称和意见一起出现，可编辑/删除；有取消、生成与预计点数 | **意图绑定对象的提交前流程已实操**；识别出的“手”和意见里的“衣袖”仍需用户核对，不把识别名当理解正确的证明 |
| 换画笔，默认大小3，在衣服上画线 | 白笔迹与包围框，出现“选区”和“修改”；没有意见时生成不可用 | 未验证自由路径自动闭合、遮罩边界或像素精度 |
| 退出 → 图片浮条“标注” | 独立工具：默认红色画笔、线宽4、矩形、文字、颜色、撤销/重做、“保存标注” | 没点保存，不推断它的结果落点 |

**观察结论：**“标注成一张图”“表达给AI的局部修改意见”“限定模型可改的像素”必须分别命名。TapNow实际保存标注会新建素材；LibTV元素编辑会先形成对象＋意见条目。二者都不足以证明圈外像素被锁定。

## 3. 视频：同叫重拍，操作对象不同

### TapNow：沿全片安排分段机位

使用案例中的真实7.1秒视频，打开浮条“视频重拍”：

1. 初始覆盖全片的一段 `0.0–7.1s`，界面选中“固定 / 正面 / 特写”。有播放、在此处剪切、重置整段、关闭。
2. 播放头定位2.0秒并剪切，再定位4.0秒并剪切，得到 `0–2 / 2–4 / 4–7.1` 三段。**2秒中段可在界面中独立表达。**
3. 新切出的段继承“固定”。手动把前、后段各设“保持不变”，中段设“固定 / 侧前方 / 中景”。
4. 来回选段，确认首段仍选中“保持不变”，显示“该时间段保持原视频，不调整视角与景别”；中段仍为侧前方/中景，配置按段保留。

另有“切换、平滑移动”、可拖动机位球、正面/侧前方/侧后方/背面/俯视/仰视、特写/中景/全景/远景，以及补充要求。**没有点生成视频**，因此这里只证明能编排分段机位，不证明模型只生成2秒、其他段像素不变、原声保留或最终无缝。它不是通用动作修复的完整证据。

### LibTV：选片段，把时间引用插进提示词

使用内置15.1秒源视频：

| 实操 | 真实反馈 | 对证据的限制 |
|---|---|---|
| 视频浮条“片段重拍” | 创建相连的新重拍节点，带播放器、胶片条和 `0/5个片段`；源视频自动引用 | 5是界面显示上限，本次没有填满5再尝试第6段 |
| 在胶片条拖选 | 蓝色范围、左右手柄、5.0s标记；输入区自动含 `[视频1]` 与 `[00:01–00:07]` 时间引用 | 输入区整秒显示和范围小数时长并存，不反推底层精度 |
| 当前 Seedance 2.5 / 720P 下缩短范围 | 最短观察到4.1s；时间引用显示 `[00:01–00:06]` | **仅此配置的实测界面限制**，不推广到全部模型，更不当成APIMart限制 |
| 在后面空白处再选一段 | `2/5`，新时间引用追加到同一个输入区；在其后另写修改文字 | 没看到独立的逐段意见表单 |
| 再点不足长度的尾段 | 提示“剩余片段不足4.1秒” | 没有提交请求 |
| 选第二段并删除 | `2/5→1/5`，第二个时间引用消失；其后的修改文字仍留在总提示词中，接在第一段内容后 | 已观察到文字与引用可能脱开；未生成，不能判定后端如何解释或认定生成bug |
| 在原位置重新添加第二段 | `2/5`，时间引用追加到末尾，旧文字没有自动重新绑定 | 没测全局撤销；不能声称无法恢复 |

原示例已有源视频/结果连线，但不是本次生成结果。本次未验证新结果的全片拼接、音轨、接缝、对比、采用或回退。

## 4. 给Nomi的取舍（建议，尚未用户测试）

| 真实发现 | 采用/不采用 | 对本方案的具体影响 |
|---|---|---|
| LibTV对象＋意见条目，TapNow标注与重绘分开 | 采用语义分离，不复制两套编辑数据 | 普通评论不等于生成；“生成修改”才执行；标注路径和意见属于一个版本会话 |
| LibTV默认点选要等识别；TapNow用刷选，不存在已验证的默认自由套索先例 | 首轮默认**可调框选**，另给细线标记；点选先作为位置评论 | 替换旧建议“默认自由套索”。框选省去闭合判断；细线用于指示，均不承诺mask；是否更省力仍待原型任务比较 |
| TapNow此次退出重绘后草稿未恢复 | 保留范围＋文字＋源版本的草稿 | 关闭/重开不能逼用户重画、重写；切主图时不可把旧标记贴到新版 |
| TapNow分段后需手动把前后设不变 | 不复制这个步骤 | Nomi只选择要改的一段，未选部分默认沿用原素材；不是让用户逐段声明不改 |
| LibTV范围删除后文字保留在公共输入中 | 意见结构化绑定选区 | 首轮一段一条意见；调整范围保留绑定，删除选区时连带处理意见，不能悄悄变成全片指令 |
| TapNow可设2秒段；LibTV当前配置最短4.1秒 | 分开用户替换范围与模型输入窗口 | Nomi允许表达2–4秒，按APIMart真实约束扩输入上下文；不得偷扩实际替换范围 |
| 两家本轮都未走生成结果 | 不照着示例宣布闭环 | APIMart实测、完整接回、原声与接缝检查仍是独立验收门槛 |

未做：竞品AI生成与付费结果验证、用户访谈、Nomi新功能原型/高保真拍板；这些不能用本次真实界面走查代替。
