## ① 背后逻辑：解决哪个真实摩擦

**用户原话（一字不改）**：

> 表格框架必须保留，是为了批量生成和冗余观察，一行一镜。只有顶部的锚（角色图/场景图/道具，被下面反复引用的东西）需要展开/收起两态：收起时排成一条紧凑参考条，方便下面镜头引用。每一镜生成前是编辑态（选模型、选提示词、加参考），生成后结果回到同一行；视频要能播放、图片按比例显示。模型、模式、时长、比例、状态、操作这些不要变成列，放进提示词框，提示词框下面选参数，就像图片节点那样。不同模型的参考模式不一样、能参考的数量和种类不一样，参考槽要按模型能力出。下面的镜头引用上面的锚，也能 @ 引用任何已有素材。生成好之后要能自动被引用去做下一步生成。旧分镜表的功能一个都不能少，这是它的升级版；体验要和画布里的图片/视频节点一致。兜底方案：把图片节点/视频节点的参数框整个抄过来放行里，生成物在第一列。设计必须基于现在真实页面的排版做，不许全变。

**这解决的是哪个真实摩擦（大白话）**：

用户在分镜表里同时要做两件性质完全不同的事——**「扫一眼全片、批量处理」**（冗余观察：这一场有几镜、哪几镜还没生成、哪几镜缺参考）和**「一镜一镜精细调」**（编辑态：选模型、写提示词、挑参考、调参数）。现在这版表格把第二件事的控件（模型/模式/时长/画幅/状态/操作）摊成一排排的胶囊挤在行上沿，行一多就成了一条控件河，反而看不清「谁做完了、谁没做」——这正是表格本该负责的第一件事。

v6 的核心动作是**把这两件事的视觉预算分开**：批量观察继续靠表格骨架（行、场分组、画面格、状态色）；精细调参数的控件全部收进提示词框下方的「底栏」，和画布里生成节点的参数区**长一个样**——用户已经在画布上学会了这套手感，不需要在表格里重新学一遍。

**他要权衡的那个核心东西（一句话点破）**：这么做每行会比现在高出约 30px（底栏占了原来省下的空间），换来的是「模型/模式/参数」不再和「这镜做完没有」抢视觉带宽——**批量观察越干净，单行操作就得多留一点高度**，这是本设计唯一的正面取舍，不是缺陷。

**升级点（相对旧分镜表）**：旧版分镜表只是"剧本 → 落画布 → 在画布上生成"的中间产物，选完模型就得导出去画布才能点生成；这版的升级是**在表格里原地生成**，不用再导一次。旧版的其余功能一个不少（对账见 §5）。

## ② 信息架构

### 2.1 表壳（编辑器外壳，`StoryboardPlanEditor` 的视觉不变）

自上而下五段，与现役 `StoryboardPlanEditor.tsx:276` 的 `grid-template-rows: auto auto auto minmax(0,1fr) auto` 完全一致，**这层壳不变**：

1. **标题栏**（48px）：图标 + 方案名（可改）+ 镜数/场数/总时长 pill + 右侧「从原稿重新拆分镜」「放弃方案」。
2. **提示行**：「AI 草拟，随便改 · 先生成参考卡锁住长相，再生成镜头 · 每次生成前确认花费」。
3. **全部镜头批量条**（sticky，`bg-nomi-ink-05`）：类型/模型/画幅/时长四个 `NomiSelect size=xs` + 「改这里 = N 个镜头一起改」提示。**时长不进批量**（图片镜没有统一时长语义），批量条改的是**整片**，与逐镜设置是不同作用域，位置排在锚区和分镜表之前（§1.5.3：不同作用域视觉可分）。
4. **滚动主体**：锚区 → 分镜表（场分组 + 行）。
5. **footer**（sticky）：左「返回原稿」+ 进度文案 + 「选中 N 镜 · 交给 Agent 改」；右「将跑 N 镜」提示 + 主按钮「生成未生成的 N 镜」。

### 2.2 锚区两态（`跨镜头要一致的`）

**存在的理由**：角色/场景/道具/风格这些资产被下面**多个**镜头反复引用；锚区不是"分镜表的第一段"，是"下面所有镜头共享的参考池"。

**两态**（用户原话："只有顶部的锚需要展开/收起两态"）：

| 态 | 形态 | 高度 |
|---|---|---|
| **收起（合并态）** | 一条紧凑参考条：每张锚 = 40px 缩略 + 名字 + 「被 N 镜引用」/生成状态一行小字，`border:1px solid #e3e1de; border-radius:10px` 胶囊；一行排不下自动换行 | 48px/行（`.mini` 40×40 + padding） |
| **展开** | 和下面镜头行**完全同一套解剖**（画面格 / 参考列 / 提示词框 + 底栏），在这里直接生成参考图；文字锚（如"全片风格"）没有画面格，只有一个提示词框，因为它**不生成图，只是写进每一镜的提示词** | 与镜头行等高（≈132–144px/行） |

- **不是「少了」或「不用了」，只是收起来排在那里**——收起态依然是锚的完整表示，不是摘要视图。
- **「全部展开 / 全部收起」** 在小节标题行右侧，一次性切换全部锚的态（不支持逐张展开——逐张展开的交互复杂度不值得，用户没有提这个需求）。
- 收起态点一张锚 = 反查过滤（现役已有：`StoryboardPlanEditor.tsx:385-398`，只看引用它的镜）。
- 锚的生成态（空/生成中/失败/已生成/已锁/文字）见 §3 状态表。

### 2.3 行骨架（分镜行 = 锚展开行，同一套解剖）

**这是 v6 与 v5（当前实现）最大的结构性差异**，改动只在这一处：

| | v5（当前实现，`StoryboardShotRow.tsx:182`） | v6（本合同） |
|---|---|---|
| 行 grid | `14px 84px 136px minmax(0,1fr)` | **`14px 136px 200px minmax(0,1fr)`** |
| 画面格列 | 固定 84px 列宽，格子本身写死 76×132（竖版专用，无横版实现，见 brief §C3-1） | **固定 136px 列宽，媒体框按比例缩放**（9:16 用 76×135，16:9 用 136×77，1:1 用 108×108——同一列宽内混排仍左对齐、仍整齐） |
| 参考列 | 136px，槽形态随 mode 变但没有固定行为约束 | **固定 200px、单行、最多 3 格、不换行**（规则见 §4） |
| 模型/模式/参数位置 | 行上沿一排 `NomiSelect size=xs` 胶囊（`StoryboardShotRow.tsx:317`），与提示词框分离 | **搬进提示词框下方的底栏**（`.composer .bar`），和画布节点参数框同一手感 |
| 动作浮条 | 半透明浮层 **压在**画面格上（hover 才现，见 token-sheet §11「悬停动作浮条」） | **移到画面格下方**，不压图（`.acts` 一行常驻小图标按钮；解决 brief §E4 点名的 §1.5.3 违规——半透明按钮压在缩略图上是已知反例，不是本合同引入的新债） |

行内三块的阅读顺序不变（沿用 v5 已拍板顺序，`2026-09-01-storyboard-table-image-first.intent.mjs` 的既有意图）：**画面格（要生成的）→ 参考列（拿来参考的）→ 提示词块（怎么描述）**。

**提示词块内部结构（`.composer`，即"和图片节点一样"）**：

```
┌───────────────────────────────────────────┐
│ 远景，雨后天台，@林薇 独自站在栏杆边，霓虹反光，缓推   │  ← 提示词文本（TipTap，@ 挂 mention chip）
├───────────────────────────────────────────┤
│ [模型▾] [模式▾] [画幅▾] [时长▾] [清晰度▾]  [N优化] [生成] │  ← 底栏：NomiSelect xs 胶囊 + 生成按钮
└───────────────────────────────────────────┘
```

- 底栏胶囊顺序：**类型不再作为逐镜选项**（类型由批量条统一整片声明，逐镜只能换模型/模式，与用户口述"模型、模式、时长、比例、状态、操作这些不要变成列"一致——它们不是列，是底栏里的胶囊，视觉上属于提示词块，不属于表格列）。
- 图片镜的底栏没有「模式」以外的时长控件，改显示「停留」时长（时间轴停留语义，v5 已有此语义改变，见 C1-15，v6 保留）。
- 已生成/已锁定的镜，底栏用一枚 `tag g`/`tag n`（"已生成 · 已作为 镜 03 首帧" / "已锁定 · 不进批量"）替换「生成」按钮位置，不额外加行。
- 台词/转场行在提示词框**下方**、composer 外部一行小字 + ▾ 展开钮（现役已有，`StoryboardShotRowExpand.tsx`，v6 不动这块）。

### 2.4 画面格比例规则

- **列宽固定 136px**（不随内容变化，这样批量竖向扫视时左边缘永远对齐）。
- **媒体框按 mode 的 `aspect_ratio` 缩放**，高度以行内容自然高度（≈132–144px）为基准反算宽度，宽度不超过 136px：
  - 9:16 → 约 76×135（贴近竖屏项目主画幅，用户 2026-09-02 已拍板过"图是主角"原则，参见 v5 intent 契约）
  - 16:9 → 约 136×77（占满列宽，高度让出）
  - 1:1 → 约 108×108
  - **横版首次有真实表达**（v5 唯一没做的 `.row.land` 缺口，见 brief §C3-1，v6 用"列宽不变、媒体框变"解决，而不是 v5 样张原方案"整行列宽切换成 176px"——切换列宽会让混合画幅的行失去左右对齐，是 09-05 讨论中明确否决的取舍，见 canvas.json 注解 a-main 末段）。
- **未生成态**（虚线框、常�驻「生成」按钮）用批量条声明的整片默认画幅撑出占位尺寸；一旦该镜单独换了画幅，占位框跟着换。
- **动作条在图下方**，横向一排小图标按钮（重生成/变体/锁定/放大/用作…），不悬浮、不压图，常驻可见（不是 hover 才出——媒体框下方本来就是空白区，不需要用悬浮遮挡内容来省这点空间）。

## ④ 参考列规则 + 槽矩阵

### 4.1 参考列的两条硬规则（2026-09-05 用户提问后追加拍板，逐字保留）

> ① 一个槽一个格，不是一张图一个格——首帧/尾帧/图片/视频/音频各一格；能放多张的槽画成叠放格+计数角标（12/30），点开是浮层网格，在里面加删排序；锚名照旧在提示词里以 @ 出现。
> ② 参考列固定单行、最多三格、200px、永不换行——所有已声明模式的槽数 ≤ 3，左中永远对齐。

**这两条规则解决的问题**：v5 的参考区曾经"一张图一个格"（`StoryboardShotRow.tsx:274-279` 逐张渲染 tile），槽一多（如 Seedance `omni` 的 30 图）行高会被参考区撑爆；v6 改成**槽是格的单位，不是素材是格的单位**——一个 `image_ref` 槽不管里面装了 1 张还是 30 张，在参考列里永远只占**一个格**（叠放显示 + 计数角标），行高因此稳定。第②条规则保证了参考列本身也不会因为模型换了就撑爆整行——已知六种真实档案里最多同时出现的具名槽数是 3（`first_frame`+`last_frame`+`image_ref`，或 `image_ref`+`video_ref`+`audio_ref`），200px 单行三格是**按已知真实数据定的上限，不是拍脑袋**。

### 4.2 每种槽形态的画法

| 槽状态 | 画法 |
|---|---|
| 不吃参考（`slots: []`，如 t2v） | 一行灰字「此模型不吃参考」，`@` 仍可引用锚写进提示词 |
| 具名槽 · 必填未填（`min≥1` 且为空） | 虚线**红**框 tile，caption 红字「首帧」/「尾帧」 |
| 具名槽 · 可选未填（`min=0`） | 虚线灰框 tile，caption 灰字 |
| 具名槽 · 已填 1 张 | 单张缩略图 tile，caption 是引用来源（锚名/镜号） |
| 数组槽 · 已填 ≥2 张 | **叠放格**（手抓扑克，见 §2.6）+ 右下角 `N/max` 计数角标；`max` 缺省时角标只显 `N`（不显示分母——不能拦一个供应商没公布上限的东西） |
| `characterIndexed` 的数组槽 | 叠放格最上面那张左上角加 `①` 编号（对应 prompt 里的 `character1`），点开浮层里可拖拽调整顺序 |
| 通用 `@` 加槽 | 虚线灰框 + `+` 图标 + 右下角 `已用/上限` 角标（如 `0/10`）；无上限时只显 `+` 无角标 |

**derive 规则（对实现方的硬约束，不是建议）**：
- 只画**当前选中 mode** 声明的槽（`ArchetypeMode.slots`），换 mode 参考列整个重画，不保留上一个 mode 的槽形态。
- `min ≥ 1` → 红「必填」；`min = 0` → 灰「可选」——**必填判定只看 `min`，`ArchetypeReferenceSlot` 类型上没有 `required` 字段**（brief §D1 已核实,不要凭空发明这个字段）。
- `characterIndexed` 才给编号，其余槽不编号（`requiresAnyOf` 依赖只在提交时校验，不在参考列拦，见 brief §D1：容量在放入时拦，依赖只在运行时拦）。
- `max` 缺省 = 供应商没公布上限，UI 必须能画一个"无上限"的槽，不能编造一个假上限。

### 4.3 六种真实档案矩阵（`SlotMatrix.html` 的数据来源，file:line 见 brief §D3/§D5）

| 模型 · mode | file:line | 声明的槽 | 参考列画法 |
|---|---|---|---|
| Seedance 2.5 · 文生视频 | `seedance25.ts:100` | `slots: []` | 「此模式不吃参考」灰字 |
| Seedance 2.5 · 首帧 | `seedance25.ts:110` | `first_frame` 1–1 | 1 个红「必填」格 |
| Seedance 2.5 · 首尾帧 | `seedance25.ts:119` | `first_frame` 1–1 + `last_frame` 1–1 | 2 个红「必填」格 |
| Seedance 2.5 · 全能参考 | `seedance25.ts:138` | `image_ref` 0–30（`characterIndexed`）+ `video_ref` 0–10 + `audio_ref` 0–10 | 3 个格：图片(叠放+①②③)/视频/音频，各自 `0/30` `0/10` `0/10` |
| Veo 3.1 · 帧 | `veo31.ts:53` | `first_frame` **1–1** + `last_frame` **0–1** | 2 格：首帧红必填、尾帧灰可选（**同一 mode 内必填度不同**，v5 实现表达不了这个区别，是本合同要修的缺口之一，见 §5） |

**必须吸收的散布度**（来自 brief §D5，逐条落实到本合同的画法规则里）：槽数量跨度 0→3；单槽上限跨度 1→30 且可能整个缺省；同一 mode 可以同时出现图/视频/音频；必填度在同一 mode 内可以不同（Veo 帧）；只有 `characterIndexed` 的槽在乎顺序。

## ⑧ 不做项

| 不做的东西 | 为什么 |
|---|---|
| **方向 B**（参考槽塞进提示词框头部，横向 chip） | 参考跟提示词挤在同一个框里，横向少一列换来的是"哪几镜缺参考"这个批量观察能力变弱；多槽模型（全能参考 3 种×上限）在一行芯片里会挤爆。与"批量生成和冗余观察"这条最高优先级摩擦冲突（见 §1）。 |
| **方向 C**（兜底：整块照搬节点参数框放进行里） | 用户自己提出的兜底方案，评估后没有必要——代价是分段条+说明+槽+提示词+底栏五层堆叠，单行高度 ≈220px，一屏只能看 3 镜，"冗余观察"几乎失效，模式切换还会占掉提示词的位置。方向 A 已经吸收了"和图片/视频节点一致"这条要求（底栏形态相同），不需要照搬整个节点面板。 |
| **HyperFrames / 完整 Excel 式表格** | 用户口述从未提出要做电子表格意义上的"任意单元格可编辑、可拖拽公式"，分镜表的表格骨架服务于"一行一镜"的批量观察，不是通用数据表格产品；引入完整表格能力（虚拟滚动、列排序、单元格级选区）远超本次摩擦的范围，也不在 D2 讲的"solo 团队扛得动的护城河"上。 |
| **横版列宽切换方案**（v5 样张原 `.row.land` 176px 整行切换） | 09-05 讨论中明确否决：切换列宽会让混合画幅的行左右不对齐，表格失去"扫一列看全片"的价值；改用"列宽固定 136，媒体框按比例缩放"实现同样的横版表达（见 §2.4）。 |
| **逐张展开锚**（只展开一张锚，其余保持收起） | 用户只要求"全部展开/全部收起"这一种交互；逐张展开会引入"哪些张是展开的"这个额外状态，复杂度不值得。 |
| **参考列的"接受什么媒体类型"提示文案** | 槽上没有这个字段（brief §D1 已核实，类型由 `kind` 推导），设计不应该在参考列里编造一个不存在的提示文案，实现阶段从 `kind` derive 即可，不需要额外的 UI 元素承载它。 |

### 9.2 真机走查项（R13/R16，实现阶段必须补的端到端旅程）

按真实用户任务而非功能点验收，建议至少覆盖：
