## 1. 需求本体：引用胶囊要在输入框**内部**

### 1.1 现状的问题（用户 2026-09-03 亲自指出）

现在胶囊排成框**外**独立一行，`AutoGrowTextarea` 在另一个盒子里——**两个盒子**。

后果：**胶囊的生命周期是模糊的**。发完消息它该消失还是留着？用户看不出来。

### 1.2 要什么

胶囊与正在输入的文字**同处一个边框内** = 它们是同一条消息，一起发、一起清空。
这与 `AttachmentRail` 的语义一致（附件本来就跟消息走）。

### 1.3 落到重做规格上，建议新增的锚点

| 锚点 | 是什么 |
|---|---|
| `data-agent-composer-references` | 胶囊容器，**在 `-prompt` 的同一个边框内** |
| `data-agent-composer-reference` | 单个胶囊（带 icon + 标签 + `×`） |

### 1.4 三条约束（都有理由，别当装饰）

1. **`maxHeight` 只约束文字区**，不含胶囊 —— 否则胶囊多了会把输入区挤没。
2. **胶囊 > 3 个折叠成「第 3 镜 +2」**，点开展全部 —— 现状是 `max-h-14 overflow-y-auto`，
   进框后滚动条很难看。
3. **附件轨（AttachmentRail）留在框外** —— 它带缩略图、比文字胶囊高得多，进框会挤满输入区；
   语义也不同：附件是「我传了个文件」（持久物），引用是「我指的是这个」（消息的一部分）。

## 2. 分镜表这边会往里塞哪些胶囊（供重做设计 icon 与状态）

用户在分镜表上**点选**后自动产生引用，无需再点 AI 图标（选中本身已表达意图）。
三种粒度，**各自 icon 不同**（不用颜色区分——暗色模式下颜色不稳，icon 是语义的）：

| 引用源 | 胶囊文案 | 建议 icon | 语义 |
|---|---|---|---|
| 整行 | `第 3 镜` | `layout-rows` | 关于这一镜的一切 |
| 画面格 | `第 3 镜 · 画面` | `photo` | 关于**已生成的产物**（「这张脸糊了」讲的是图，不是镜头设定） |
| 提示词文字选区 | `第 3 镜 · 选中` | `text-caption` | 只动选中那几个字 |

**每个胶囊必须能单独取消（`×`）** —— §1.6 C2「作用域跟选中走」，不能只靠点别处消。

## 3. 状态：本需求牵动的 composer 状态

重做要定 icon 和状态，这里列出分镜表会触发的：

- **有引用 / 无引用** —— 有引用时 composer 的占位文案应当变（「继续告诉 Nomi 要改什么…」
  在有引用时是错的，此刻用户要说的是「对这几个东西做什么」）
- **引用已失效** —— 用户引用了第 3 镜后把它删了。引用不该静默消失
  （现有 `validatePlan` 对失效锚引用的做法是**标红而不是静默擦掉用户的镜头**，同一原则）
- **引用来自另一个页面** —— 在分镜页引用了某镜，切到生成页再发送，引用还成立吗？
  **这条我们没有答案**，交给重做定。
