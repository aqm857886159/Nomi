## 0. v1 被打回，和它错在哪

用户原话（2026-09-10 20:30）：

> 「太丑了，和我们的不一样。你没有用我们下面那种一行的模式：**上边是提示词，下边是那些参数组件**，
> 然后只是你需要用卡，下面再加一些东西。**四段视频你都没给我提示词。**
> 要和画布里一样的真实体验：提示词，下面控件，能选；生成就生成，不生成就擦掉。
> 后面还有卡就左右翻；批量的话看完也有批量生成按钮。」

v1 错在**取件取错了**。它从画布节点上摘走了「参数条」这半件，把它上面那半件——**提示词**——留在了画布上。
于是一张要确认「花 ¥1.20 生成 4 段视频」的卡上，四段视频要拍什么，一个字都没有；
用户此刻要判断的第一件事根本不在卡上。
参数条还被摆成竖排（`layout="stacked"`），一行拆成两行，长得和画布上那条也不是一个东西。

v2 的做法只有一句话：**整件 `NodeGenerationComposer` 进来**（新增 `host="panel"` 档）。
卡壳只负责它上下那一圈——槽头 / 翻页器 / 价格行 / 动作。卡体里一个像素都不是卡自己画的。

## 0.1 v3 · 用户 2026-09-10 21:20 反馈

用户看过 v2 之后（大意）：

> 「卡整体没问题，主要是**排版**：参数摆得不齐、还上下两行。卡里**不需要优化/运镜/更多**
> ——都写完了还优化啥。**模型和参数在前，缩成一行。加键盘左右翻页。**」

再加上同一天拍板的通用按钮规则：**一屏一个主动作 · 否定动作用 × · 批量不是第二颗文字按钮**。

**v2 错在哪**：它把整件 composer 请进来了，却**把画布上那一整排控件也照单请了进来**——
锁、更多、运镜、优化、×N、模型、参数，七件。画布上那一排有 880px 可用，面板里只有 350px，
七件排不下就换行（v2 给底栏开了 `flex-wrap` 兜底）。用户看到的因此不是「一行控件」，
而是**两行长短不齐的控件**——他说的「摆得不齐」指的就是这个。

但换行只是症状。根因是**取件的时候没有问「这一刻他要做什么」**：卡上的提示词是 Nomi
**已经写完**的，这一刻的活是「看一眼、要不要改一个字、按下去」。在这个语境里，
「更多（提示词库）」是重新起草、「运镜」是重新导演、「优化」是**再花一次模型钱去改一句已经写好的话**——
最后这件尤其错：在一张**正在确认花钱**的卡上摆第二颗花钱的钮，等于结账时递上另一张账单。
删掉这三件之后，剩下的恰好就是用户点名的那三件、按他给的顺序：

```
[模型 ▾] [参数 ▾] [×N ▾]      ← 恒一行，不换行
```

所以 v3 不是「把 flex-wrap 关掉」（那只会把七件挤成一条缝），而是**把不属于这一刻的四件拿走**，
剩下三件自然就是一行（R2 根因不修症状）。

三处改动，逐条对应他的三句话：

| 他说的 | v3 做了什么 | 在哪看 |
|---|---|---|
| 「参数摆得不齐、还上下两行」「模型和参数在前，缩成一行」 | 底栏只剩 `[模型][参数][×N]`，`flex-nowrap` **显式禁止换行**；展开的参数面板搬到底栏**下面**的落点，不再挤进那一排 | `-collapsed` / `-panel-open` |
| 「卡里不需要优化/运镜/更多」 | `host="panel"` 不渲染 更多 / 效果推荐行 / 运镜 / 优化 / 锁 / 圆形生成钮 | §2.1 表 |
| 「加键盘左右翻页」 | 卡聚焦时 ← → 翻页；翻页器后面印两个箭头当提示（不占地方，也不写成一句说明） | `-collapsed` 那一行 `‹ 1/4 › ←→` |
| 按钮规则：批量不是第二颗文字按钮 | 「全部生成 ¥1.20」那颗次按钮**删掉**，改成翻页器旁的范围切换 `逐镜 \| 全部`，主按钮自己改口成「生成 4 镜 ¥1.20」 | `-all` |
| 按钮规则：否定动作用 × | 「不要」换成动作行右端一颗 ×（文案变成它的无障碍名与 tooltip，没有消失） | 每一张 |
| 按钮规则：一屏一个主动作 | 动作行现在只剩**一颗**填色按钮 | 每一张 |

**顺带搬的一件：翻页器从槽头搬到了动作行上方那一行。** 两条理由，都是结构性的：
① 它现在决定主按钮上印的**那个数**（逐镜印这一页的价、全部印合计）——改一个数的控件必须和那个数在一处，
否则用户按下去之前得在卡的两端来回对；② 范围切换必须紧挨翻页器（用户原话），
而 390px 的槽头已经排满了（icon + 标题 + 「付费 · Nomi 选的」），再塞一个切换就会挤出视口。
2026-09-09「行尾附属信息紧跟内容、不许 `ml-auto` 贴右缘」那条规则照常守：这一行三件都在内容流里紧跟彼此。

## 1. 任务卡

**这解决的真实摩擦**：Nomi 说「要花 ¥1.20 生成 4 段视频」。用户想确认的从来不只是价钱，
而是**这四段到底拍什么、用什么模型、多长、什么画质**——任何一项都可能是他真正想动的那个。
今天这张卡上：提示词没有，参数是四枚不能点的灰 chip，唯一的出口是一颗「换模型」。
想改一句台词或把 3 秒改成 5 秒？只能拒掉这张卡、回去打字重说一遍，再看一次报价。
**一次决定被拆成三个来回，其中两个是我们自己造出来的。**

而「上面提示词、下面参数、点了能选」这件事，Nomi 里早就有一份做好了的：
用户在画布上选中一个镜头时弹出的那张生成框（`NodeGenerationComposer`）。
它已经有 `PromptEditor`（含 @ 引用素材）、有从模型档案长出来的画质/时长/比例/声效、
有模型下拉与供应商标注、有 ×N。**卡不该再造一个，卡该把它请进来。**

**用户要权衡的那个核心东西**：一张卡上装多少。
装到「整件生成框 + 逐镜翻页」，这一刻的决定就完整了，代价是卡高 367px（4 镜时仍是 367px，翻页不叠高）；
装少了，就还是今天这个三来回。本方案选前者，并用两件事把高度按住：
参数收进一枚摘要 pill（节点那条条当初的解法）、多镜**翻页而不是竖着摞**。

## 2. 增量 1 · 付费卡 v2 的构造

```
┌───────────────────────────────────────────────┐
│ ⚡ 生成 4 镜的视频        付费 · Nomi 选的      │  ← 卡壳：槽头
├───────────────────────────────────────────────┤
│                                               │
│   ［ NodeGenerationComposer host="panel" ］    │  ← 卡体：整件生成框
│     生成方式  文生视频 / 图生视频               │     （参考区 / 模式栏）
│     雨夜街口，霓虹映在积水里，女孩撑伞…          │     （提示词 · 真 PromptEditor）
│     ◎ Kling 3.0 ▾   std · 3 · 16:9 ▾   1 张 ▾ │     （参数条 · 真 InlineParameterBar，恒一行）
│                                               │
├───────────────────────────────────────────────┤
│ 4 镜 × 3s · 标准画质 · ¥0.10/秒  合计 ¥1.20     │  ← 卡壳：价格算式行
│ ‹ 1/4 ›  ←→   [ 逐镜 | 全部 ]                  │  ← 卡壳：翻页 + 范围
│ [✓ 生成 ¥0.30]                             ×  │  ← 卡壳：动作（一颗主动作 + 一颗 ×）
└───────────────────────────────────────────────┘
```

卡壳（`V4Intervention` 的 spend kind）只加四样东西，**提示词与参数条之间一样都不加**：

| # | 卡壳加的 | 为什么 |
|---|---|---|
| ① | 槽头一行：`生成 N 镜的视频` + `付费` + `Nomi 选的` | 「付费」是这张卡的性质；「Nomi 选的」说的是**模型不是你挑的**。后者**从当前 meta 现算**——用户一改模型它就消失，不会留在卡上变成一句假话 |
| ② | 翻页器 `‹ 1/4 ›` + 键盘提示 `←→` + 范围切换 `逐镜 \| 全部`（动作行上方那一行） | 一镜一张卡；范围决定主按钮印哪个数，所以它们和那颗按钮在一起（v3 从槽头搬下来，理由见 §0.1）。只有一镜时整行不渲染 |
| ③ | 价格算式行 `4 镜 × 3s · 标准画质 · ¥0.10/秒　合计 ¥1.20` | 形态 9 / B-02 的「逐项单价 + 加粗合计」。随参数**原地刷新**，卡不重开、不跳转 |
| ④ | 动作：一颗主按钮 `生成 ¥0.30`（切到全部 = `生成 4 镜 ¥1.20`）+ 一颗 `×` | 见 §3 |

标题里**不印金额**：金额随参数变，两个地方印同一个数就一定有一个先漂。
标题只说要做什么，钱归价格行（账）与按钮（承诺）。

### 2.1 `NodeGenerationComposer` 在卡宿主里差在哪（props 差异）

新增的是**一个** prop：`host?: 'canvas' | 'panel'`，默认 `canvas`。
刻意不做成一堆 `hideXxx` 开关——宿主只有两种、两种各自成套；散成开关之后，
第三个调用者一定会挑出一套没人验证过的组合。用户说的「用 props 隐藏、不复制组件」在这里的
落法就是它：**面板里那张卡和画布上那张是同一个组件的同一份代码**，只是 `host` 不同。

| 件 | `canvas`（画布，默认） | `panel`（付费卡） | 理由 |
|---|---|---|---|
| 外层定位 | `absolute` + `useComposerViewportPlacement` 反缩放浮在节点下沿 | 普通内容流（`w-full`），由介入槽定位 | 卡不是浮层 |
| 卡壳 | `border` + `rounded-nomi` + `shadow-nomi-md` + `p-3` | **全脱掉**（`p-0`，无边框无投影） | 外面已经有一张卡，再描一层就是框中框，而里外说的是同一张卡 |
| 高度/宽度钳制 | `maxHeight/maxWidth/minWidth` 按视口算 | 不钳制，跟着面板宽（390）与内容 | 面板宽由面板定，卡不该跟视口谈判 |
| 参考区滚动上限 | `referenceMaxHeight` | 不设上限 | 同上 |
| 锁徽标 `NodeLockBadge` | 有 | **不渲染** | 锁是画布上的概念（锁住这个节点不被改）。卡上那是一份**还没落到画布上的草稿**，没有可锁的东西 |
| 「更多 ▾」`effects.more` + 效果推荐行 `effects.recommendations` | 有 | **不渲染**（v3 新增） | 提示词是 Nomi **已经写完**的。这一刻的活是「看一眼、改一个字、按下去」，不是重新起草 |
| 运镜 `NodeCameraMoveControl` | 有 | **不渲染**（v3 新增） | 同上：运镜已经写在那句提示词里了 |
| 提示词优化 `NodePromptOptimizer` | 有 | **不渲染**（v3 新增） | 同上，且它要**再花一次模型钱**——在一张正在确认花钱的卡上摆第二颗花钱的钮是错的 |
| 生成钮（右下角圆形 `↑`） | 有 | **不渲染**，由卡壳的主按钮接替 | 见 §3 「为什么生成钮不留在参数条里」 |
| 参数浮层 | portal 到 body，打开时定位一次不跟随 | **就地展开**（`panelMode="inline"`）+ 下拉浮层落在卡内（`portalTarget`） | 画布上节点卡不滚动，静止定位反而省事；面板里的卡随转录滚动，body 上的静止浮层会**留在原地**脱离卡 |
| 展开的参数面板落在哪 | —（是 portal 浮层） | 底栏**下面**那个落点（`inlinePanelSlot`，v3 新增） | 面板是整幅的（`w-full`）；留在底栏那一排里它就会变成那排的兄弟去抢宽度，把「模型/参数/×N」挤成两行（v2 的病灶） |
| 底栏排布 | 恒单行（卡宽内容驱动，最宽 880） | **恒单行**（`flex-nowrap`，v3 改） | 面板里可用宽 350，一行只放得下三件——所以那儿**只渲三件**。v2 用 `flex-wrap` 兜底，代价是两行长短不齐（用户：「摆得不齐」）。排不下不是靠换行解决的，是靠别往这一排塞第四件解决的 |

**其余全部一模一样**：提示词编辑器（含 @ 引用）、模式栏、模型下拉（同一份目录、同一套供应商 chip）、
参数面板（同一份档案算出的画质/时长/比例/声效）、×N。

改到的 props（都是可选，画布一个都不传 = 画布形态零变化）：

| props | 在哪 | 干什么 |
|---|---|---|
| `host?: 'canvas' \| 'panel'` | `NodeGenerationComposer` | 上面整张表。**唯一**决定「这张 composer 挂在哪」的开关 |
| `inlinePanelTarget?: RefObject` | `NodeParameterControls` | 给了就把参数面板换成就地展开、**下拉浮层**落进这个容器（传的是整张卡） |
| `inlinePanelSlot?: RefObject` | `NodeParameterControls` → `InlineParameterBar`（v3 新增） | **面板本体**落在哪（传的是底栏下面那个空 div）。和上一条是两件事：一个管浮层的 portal 根，一个管面板的位置 |

- `InlineParameterBar` v2 那条「横排允许换行」**已删除**（P1）：面板既然搬出了那一排，
  就没有什么要给它让位了，留着只会让底栏在别的调用点上悄悄变两行。
- `InlineParameterBar` 的 `modelBadge`（v1 加的「Nomi 选的」徽标）**已删除**：v2 把这句话放回槽头（§2 ①），
  同一件事不留两份实现（P1）。

### 2.2 与画布节点体验逐项对照

用户那句「要和画布里一样的真实体验」拆成四条，逐条对：

| 用户说的 | 画布上 | 付费卡上 | 一致？ |
|---|---|---|---|
| **提示词** | `PromptEditor`（TipTap），可编辑、可 @ 引用素材、可从提示词库追加 | **同一个组件、同一个实例路径**。打字直接写回 `useGenerationCanvasStore` | ✅ 同一件 |
| **下面控件，能选** | 模型芯片下拉（带供应商 chip）+ 摘要 pill 弹参数面板（画质/时长/比例/声效）+ 运镜 + 优化 + ×N | **同一条 `InlineParameterBar`**，同一份档案算出的控件，改完真回写 meta | ⚠️ **同一件、少三件**：模型 / 参数 / ×N 一模一样；运镜 / 优化 / 更多不进卡（v3，理由见 §0.1） |
| **生成就生成** | 右下角圆形 `↑`，点了直接跑 | 卡壳主按钮 `✓ 生成 ¥0.30`，点了直接跑这一镜 | ⚠️ **位置不同、动作相同**（理由见 §3） |
| **不生成就擦掉** | 画布上删节点 | 动作行右端一颗 `×`，丢弃这份草稿 | ✅ 同一个动作，且和「生成」在同一行 |

## 3. 翻页与批量的规则

**一镜一张卡。** 4 镜 = 同一张卡翻 4 页，不是 4 张卡竖着摞。
摞的代价不是好不好看：4 个提示词框会把转录顶到几屏之外，而用户此刻只做一件事——逐条看过去。
翻页把「同一件事的第 N 项」压在同一个位置上，眼睛不用重新找（对照 `-page2` 与 `-collapsed` 两张图：
除了内容，一个像素都没动）。

| 规则 | 内容 |
|---|---|
| 翻页器位置 | **动作行上方那一行**（v3 从槽头搬下来，理由见 §0.1），仍在内容流里紧跟彼此、**不用 `ml-auto` 顶到右缘**（2026-09-09 用户拍板的通用规则；`check:tokens` 对 `src/workbench/ai/` 是硬零） |
| 键盘 | **卡聚焦时 ← → 翻页**（2026-09-10 用户要求）。焦点落在提示词编辑器/输入框里时不接管——那儿的左右键是移动光标。翻页器后面印两个箭头 `←→` 当提示：它不是说明文字，是「这里有快捷键」的最短形式 |
| 循环 | 首尾相接（第 4 页按 `›` 回第 1 页）。4 项的清单不值得给两颗禁用的箭头 |
| 每镜独立 | 提示词、模型、画质、时长、比例、声效——每一镜各存各的（就是各自那个节点的 `prompt`/`meta`）。翻页只换内容不换位置 |
| **范围切换** `逐镜 \| 全部` | 紧挨翻页器的一枚极小分段控件（现役 `NomiSegmented`，`density="compact"`）。它不是第二个决定，是同一个决定（生成）的**范围** |
| 主按钮 = 一颗，标签跟着范围走 | 逐镜档 `生成 ¥0.30`（当前这一页的报价，翻页会变）；全部档 `生成 4 镜 ¥1.20`（合计）。**动作行上永远只有一颗填色按钮** |
| `×` = 丢弃这份草稿 | 动作行最右端一颗 ×（现役关闭按钮原子，同 `V4Queue` 行尾那颗）。文案「不要」没消失——它是这颗 × 的无障碍名与 tooltip。单镜卡上它也在 |
| 单镜卡 | 不出翻页行（既没有页可翻，也没有「全部」可言），其余一模一样（`-single` 那张图） |
| 报不出价时 | 范围切换**不渲染**：没有合计可印，「全部」就没有能落到按钮上的数（`-price-unknown` 那张图：只剩翻页器与 `←→`） |

**为什么生成钮不留在参数条右端**（选了「隐藏 composer 的生成钮、由卡壳给主按钮」这一档）：
画布上那颗 `↑` 是那张卡上唯一的出口，放右下角没问题。介入槽里不是——
「生成」和「不要」是同一个决定的两面（做 / 不做），必须并排放在同一处。
把「生成」留在参数条里、「不要」压在底栏，等于把一个决定拆成两个家（§1.5 一功能一个家），
而且用户改完参数抬眼看到的第一颗钮会是「生成」，「不要」反而要往下找——这在**花钱**的卡上是错的默认。
另一档（「composer 的生成钮就是主按钮，标签变成『生成 ¥1.20』」）在单镜卡上也成立，
但一到多镜就要在参数条里放「生成本镜」、底栏放「全部生成」，同一个动词出现在两处，反而更糊。

**为什么「全部」是切换、不是第二颗按钮**（v3）：两颗一样重的文字按钮（`生成 ¥0.30` / `全部生成 ¥1.20`）
在花钱的卡上要求用户在**按下去的那一刻**同时决定两件事——做不做、做几个。
切换把它拆成先后两步：先选范围（切完主按钮当场把数改了，你看得见自己选了什么），再按那一颗。
这也正是 2026-09-10 拍板的按钮规则要的：一屏一个主动作，批量是范围不是第二个按钮。

**价格算式什么时候不成立**：逐镜参数可以各不相同，所以「4 镜 × 3s · ¥0.10/秒」这句**只有整齐时才是真的**。
一旦有一镜被改长了，算式退成 `4 镜 · 逐镜不同`，具体数字交给下面那个「逐镜 · 4 镜」折叠口
（`-repriced` 那张图：第 1 镜改成 5s → 合计 ¥1.20→¥1.40，主按钮同步变 ¥0.50）。
整齐时**不出**折叠口——那时每一行都是同一个数，摊开等于把同一句话抄 4 遍。

## 5. 增量 2 · 「全自动」档

沿定稿三个词「每步问 / 自动改 / 全自动」，不新造档、不新造词。只补两件：

**(a) 切档二次确认**（`v4-auto-mode-confirm.png` / `-dark.png`）
一句话：「之后可撤销的改动 Nomi 直接做，不再逐步问你。**付费和不可逆的操作仍然每次问。**」
**它不是新组件**——就是介入槽的可撤销档（换档本身可撤销），所以没有「不再问 →」、没有 badge、没有范围行。

v2 改动：**标题左边那颗 ✓ 删掉**（`InterventionData.hideIcon`）。
那是 `approval-reversible` 档统一的「可撤销」记号，而这张卡的标题是一句**问句**（「切到全自动？」）——
问句前面顶着一个 ✓ 读起来像「已经切好了」，记号和它要说的事正好相反。

**(b) 开启后的常驻提醒**（`v4-auto-mode-reminder.png` / `-dark.png`）
一条 h-6 的微字横条压在 composer 上沿：`● 全自动　付费和不可逆仍会问　[回到自动改]　×`。

v2 改动：**右端加 `×`，点了本会话不再显示**。
为什么允许叉：这条是**提醒**，不是开关。提醒的价值在「你可能忘了」，
看过一次就不会忘的人被它常年占掉一行（用户原话：可以叉掉，一直放占空间）。
叉掉只影响这一会话的这一条横幅，**档位一动不动**——改档的家仍是 composer 底栏那颗钮。

它为什么该存在：三档里只有「全自动」会让 Nomi 在**没人看着**的时候连着做改动。
另外两档每一步都会在介入槽里现身，用户不可能忘了自己开着什么；全自动恰恰相反——
它的特征就是「什么都不问」，于是「我现在开着什么」在界面上没有任何痕迹。
composer 底栏那颗档位钮不算：三档长得一模一样，读它等于每次都要低头确认一遍。
只在 `project` 档渲染，别的档一行都没有。不画闪电/机器人 icon（定稿 ⑧ 禁用那一族），
一颗 6px 的点 + warning-soft 底就够被眼睛抓到。

   确认时把改过的提示词与参数一起回给宿主。
3. 报价：`quoteShot` 换成真报价来源；报不出价时**必须**走 `unavailable` 那条路，不许兜底成 0。
4. 录基线：`agent-panel-v4` 整屏仍登记在 `calibration.json` 的 `pendingApprovalScreens` 里，
   拍板后连同整屏一起录，并删掉那条登记。

## 11. 为什么本轮**没有**录视觉基线

`agent-panel-v4` 整屏在 `tests/ux/design-lab/calibration.json` 的 `pendingApprovalScreens` 名单上：
这屏的基线本来就在等用户拍板。给还没被看过的格子录基线，等于替用户点头把「今天碰巧长这样」
钉成「应该长这样」——那比红更糟（同 `docs/lessons/design-lab-update-rewrites-every-baseline.md`）。
所以本轮产出的是**给人看的截图**，不是基线。
