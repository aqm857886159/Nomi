# Nomi 体验清晰度与可发现性设计

## 用户目标

用户不应该因为画布滚轮、暗色叠加层、假模型名称或隐藏在三种模式后的系统提示词而迷路。创作入口应该从“选一个内部模式”变成“描述目标，再选择一个可解释、可自定义的工作方式”。

## 已确认的根因

1. 生成节点里的提示词编辑器没有在滚轮边界阻断事件，事件冒泡到画布后继续平移画布。
2. 提示词卡、全屏媒体预览共用低对比度 `nomi-overlay-chip`，暗色图片上文字和关闭按钮不满足可读性。
3. “转视频”直接复用图片提示词；这不是同一意图的提示词，入口会制造错误预期。
4. 故事拆镜入口暴露“图片分镜 / 视频分镜 / 图片+视频分镜”三个内部术语，用户必须先理解实现方式。
5. 创作区把内置系统提示词伪装成模式下拉框；素材规划是有价值的能力，却被放在大量选项中。
6. APIMart 内置目录仍种入 `deepseek-v4-pro`，而官方当前文档列出的 DeepSeek 变体是 V3/V3.1 系列；旧键还会同时污染创作区和画布助手。

## 设计决策

- 拆镜入口只保留一个“拆成镜头”行动，默认按图片镜头规划；每个镜头在计划编辑器中单独选择图片或视频。用户仍可通过自然语言表达视频意图，但不必先学习三个模式。
- 移除画布上的“转视频”按钮。等视频提示词有独立编辑体验后再恢复；当前入口只会把错误的图片提示词搬过去。
- 创作区不再显示七项内部模式下拉。保留内部 mode id 作为兼容层，将“工作方式”统一交给技能库：内置素材规划作为置顶工作方式，卡片显示用途、启用按钮和系统提示词预览；用户技能继续支持自定义系统提示词。
- APIMart 内置默认模型改为官方目录中存在的 `deepseek-v3.1-250821`，并迁移/停用旧 `deepseek-v4-pro` 内置记录。迁移只针对 APIMart 的精确旧键，避免误删用户自定义供应商模型。
- 所有暗色叠加控件统一使用强叠加 token、细边框和阴影，保持 token-only，不写新的 hex/任意颜色。

## 不在本次小步中冒险的范围

剪辑节点是独立的产品能力，涉及画布节点 schema、时间轴资产来源、裁剪状态和导出 IPC；本次先建立可运行的设计契约与最小节点入口，完整导出链路按单独计划推进，不能用一个假按钮冒充完成。

## 验收标准

- 提示词编辑器滚动到边界时，画布 viewport 的滚动位置不变。
- 暗色主题下提示词类型角标、预览标题和关闭按钮在深/浅媒体上都可辨认，键盘焦点清晰。
- 画布图片节点不再出现“转视频”按钮。
- 故事拆镜卡只有一个主行动和一句白话说明，计划编辑器仍能逐镜头选媒体类型。
- 创作区没有内部模式下拉；素材规划可从工作方式/技能入口一眼找到，并能查看系统提示词。
- 创作区与生成画布的模型选择器都不再显示 `deepseek-v4-pro`；默认 APIMart 条目为 `deepseek-v3.1-250821`。
- 现有行为测试、类型检查、构建和真实浏览器走查通过。
