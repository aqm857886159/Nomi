## 2. 根因判断

Nomi 现在不缺通用宣传素材，缺的是三个控制面：

1. **搜索承接不足**：sitemap 只有 4 个页面，英文只有首页，无法覆盖人物一致性、ComfyUI 工作流、MCP 视频制作等具体需求。
2. **发布和归因断层**：成片、竖版、海报、截图和双语稿已经制作，但部分成片仍在 ChatCut / 旧机器，且没有按假设发布或统一记录复盘窗口。
3. **证据单元不足**：功能截图不能替代“最终成片 + 真实账单 + 可复现工程”。旗舰发布必须等三件套齐全。

公开定位统一为：

- 中文：`Nomi，开源、本地优先的 AI 视频工作台`
- 英文：`Nomi Video — Open-source, local-first AI video workbench`
- 核心差异：多镜头视觉连续性、可带走的工作流、包含失败重试的真实成本、Agent 可操作但关键节点由人确认。

英文渠道统一使用 `Nomi Video`，降低与其他 Nomi 品牌的搜索混淆。官网中文主张“把 AI 视频的成本打下来”继续保留。

## 4. 两条执行线

### A. 国内周更

P0 渠道：B站、知乎、即刻、官网 SEO。公众号与微信群负责承接。小红书、抖音作为 P1 短内容验证渠道。

每周只讲一个真实问题：

1. 同一角色跨 8-10 个镜头如何不漂移
2. 一条片实际花费多少，失败重试花在哪里
3. ComfyUI 普通 Save 工作流如何导入、查缺件并进入时间线
4. Codex / Claude Code 如何通过 MCP 推进初稿，以及四个人工门禁

### B. 英文搜索与集中发布

先建立 `/en/` 搜索承接和英文 quickstart，再用一个完整旗舰工程拆成文章、YouTube、GitHub Discussion、X、HN 和适配社区的 Reddit 技术复盘。

英文 P0 需求簇：

- open source / local AI video editor
- ComfyUI video workflow editor
- consistent character AI video / storyboard
- agentic / MCP video editor
- AI video workflow software

Show HN 不做零散试水。只有真实工程、最终 MP4、失败过程、成本账单和复现材料都可访问时才发布一次。

## 6. 发射门槛

国内常规内容至少具备：

- 一个可独立成立的结果或明确产品证据
- 素材与宣称逐项可核验
- 单一 CTA 和对应 UTM
- 按平台要求标记 AI 生成内容

旗舰案例和英文集中发布必须同时具备：

- 最终成片
- 真实账单，包含失败和重试，不只报成功调用
- 可复现材料：提示词、模型、版本、关键设置和可下载工程
- 安装信任说明：官方来源、源码、安全边界；签名完成前明确披露未签名状态

不得写无来源行业百分比、虚构搜索量、客户、节省比例或平台成绩。MCP 工具数量不在渠道稿手写，发布时以目录和契约测试为准。

## 7. 指标与复盘

| 层级 | 指标 | 窗口 | 下一步规则 |
|---|---|---|---|
| 发现 | 展示、搜索 impressions、视频 CTR | 短视频 48-72 小时；长文 7 天；SEO 28 天 | 展示低则改标题、封面或搜索意图，不先改产品 |
| 兴趣 | 30 秒留存、完读、收藏、有效评论 | 48 小时 / 7 天 | 进入率高但留存低，重剪前 15 秒和证据顺序 |
| 意图 | 官网点击、GitHub unique、release 页面访问 | 7 天 | 内容有互动但无点击，收紧 CTA 和链接位置 |
| 转化 | 安装包下载增量、stars、forks、issues | 7 天 / 28 天 | 克隆高下载低，优先解决签名与安装信任 |
| 学习 | 安装阻塞、工作流问题、真实项目咨询 | 每周 | 只把重复出现且能复现的问题进入产品 backlog |

每周只保留“发布前 7 天 vs 发布后 7 天”的同口径比较，并记录同期 release 等干扰事件。不要把累计值直接归因给单篇内容。

## 8. 停止清单

- 不买量，直到搜索承接、安装信任和归因链路可用。
- 不把功能清单当内容主题，不在没有作品时发截图合集。
- 不跨平台复制同一首句和正文；每个平台改写原生开头。
- 不批量向 Reddit、GitHub Issues 或群聊投放重复推广。
- 不在没有真实对装测试时发布竞品对比。
- 不为了 SEO 生成批量薄页、doorway 页面或关键词堆砌。
