## §2 结构结论

**结论 1：9 份里有 3 份（B 类）不是 `scripts` 这一层的病。** 它们的根因在产品代码，脚本只是修复时顺手加的检测器或走查客户端。原因是模块键按路径取：`scripts/check-x.mjs` 只有两段，只能取到 `scripts` 这一级，于是 295 个互不相干的脚本共用一个桶。这和 09-15 那份评审指出的「`src/workbench` 键太粗」是同一个问题（[`2026-09-15-numeric-contract-structure.md`](2026-09-15-numeric-contract-structure.md) §3），也在发版后欠账清单上。

**结论 2：剩下的里面确实有一种共同的结构病——门岗量的是替身，不是事实。** A 类 4 份加 A′ 类 1 份，形状完全一样：

- 门岗想守的事实是：文案都国际化了 / 同类入口都扫过了 / 改动质量过关 / 每一层都查过现成件；
- 门岗实际量的是：有没有汉字 / 字段填没填 / 在墙钟内跑没跑完 / 带出处的条目够不够 3 条；
- 替身和事实之间有一条**不付出事实就能满足替身的路**，而且这条路在高负载下正好是最省力的那条。

现有规则 R17 要求「加规则必须先验它会红」，但**只要求证明违规会红，没要求证明「伪装合规」也会红**。这 5 份合同全都通过了「违规会红」的验证，出问题的全是后一种。

## §3 本轮已经照这条结论做的事

2026-09-17 的分层表门岗在测试里专门写了「伪装合规」的用例，不只测违规：

- 把合格的表放进代码块当样例 → 红（这一条顺带挖出了旧判据的洞：节抽取不跳过围栏代码块）；
- 自报豁免，但代码 diff 显示在长新模块 / 加运行时依赖 → 红；
- 「查过：无」不带链接 → 红；豁免类别写「架构」→ 红。

测试文件：`scripts/prior-art-layers.node-test.mjs`。
