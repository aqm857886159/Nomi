# 结构评审：`src/workbench` 的「布局不变量」为什么反复被改坏

状态：单一评审者视角，不代表多位独立审批者。触发方式不是排期，是门岗——
`check:symptom-cluster` 在 `docs/fixes/2026-09-15-generation-shell-bottom-band.root-cause.json`
落盘时报出模块键 `src/workbench` 在 2026-09-09 到 09-15 的 7 天里已有 71 份根因合同。

71 这个数字本身是一周大合并潮（Agent 面板 v4 接线、画布性能、分镜与审批重做）的体量，
**不是一个结构缺口能解释的**；本文只回答这一份合同所在的那条结构：
**「哪一块占哪一格、谁被谁顶上去、谁不许压住谁」这一族不变量，在这个模块里由谁持有。**

范围：`src/workbench/generation/GenerationWorkspace.tsx`（生成面外壳网格）、
`src/workbench/preview/PreviewWorkspace.tsx`（剪辑面停靠列）、
`src/workbench/timeline/TimelinePanel.tsx`（面板内的行模板）、
`src/workbench/AssistantPane.tsx`（助手面板的停靠态 / 浮层态两种几何）。

## 1. 同一类的几份合同（都在这 7 天的窗口里）

| 合同 | 它说的类根因 | 不变量写在哪 |
|---|---|---|
| `2026-09-09-node-label-outside` | 没有一层拥有「媒体外侧的常驻信息 + 工具条让位」 | 节点外壳的类名 |
| `2026-09-09-process-feedback-overlay-collision` | 状态与镜号没有各自的常驻空间归属 | 卡片外壳的类名 |
| `2026-09-10-creation-columns` | 共同宿主处没有一份「工作区框」规格 | 三个工作区各自的类名 |
| `2026-09-10-timeline-toolbar-overlay` | 面板内的常驻控件必须占一行真实布局 | 面板的行模板（类名） |
| `2026-09-15-generation-shell-bottom-band`（本轮） | 外壳三件的容器关系没有拥有层，改错不会红 | 外壳的网格模板与三处落位（类名） |

五份的共同形状很具体：**这一族不变量的唯一实现是一串 Tailwind 类名，而类名不进任何判据。**
它同时具备三个让缺陷长寿的性质：① 编译器看不见（类名是字符串）；
② 单测看不见（没有渲染、更没有几何）；③ 走查大多只断「元素在不在」，不断「它在哪一格」。
于是每一次「顺手调一下布局」都是一次无保护的改动，而后果要等真机截图才看得出来。

本轮的证据尤其干净：`d2bb622c1` 改的那一行同时留下一段解释性注释，
而**同一晚落地的走查注释写的是相反的事实**（`tests/ux/timeline-toolbar-row.walk.mjs:266`
至今写着「生成画布的时间轴是 col-span-full，宽度不随助手面板变」）。
两份注释互相矛盾地共存了 5 天，期间 CI 全绿——这不是谁不小心，这是缺一道判据。

## 2. 缺口在哪一层

不在「某个面写错了」这一层，而在**没有一层把「容器关系」当成状态**。
对比同模块已经做对的地方：
- 助手面板的**宽度**有拥有层（`src/workbench/assistantWidthBounds.ts`：上下限与窄窗钳制都是派生函数，四个面共用），所以宽度从没出过这一类事故；
- 时间轴面板的**高度下限**在 09-10 被抽成派生量（`timelinePanelBounds.ts`），此后也没再出事；
- 而**容器关系**（行列跨越、落位顺序、覆盖是否完整）一直没有对应的定义处：它只存在于 JSX 的类名里。

所以缺口是「派生量已经有 owner，拓扑关系还没有」。

## 3. 本轮修法与它的适用边界

本轮没有引入新机制（P1/R20：不为这件事造一层布局框架）。做的是把拓扑关系变成**可判定的两头**：
- 结构测试断「源码里写的是哪几个类名与落位顺序」（`generationWorkspaceLayout.structure.test.ts`）；
- 走查断「真实矩形关系」——横贯、被顶上去、三块并集覆盖工作区、宽度不随面板开关变
  （`tests/ux/layout-timeline-panel-span.walk.mjs`，带两个阳性对照）。

两头一起才够：结构测试单独存在会在一次正当的视觉重构后假红；走查单独存在跑得慢、只在受影响路径触发。
两条都已实测会红（把 `col-span-full` 改回单列：结构测试报缺类名，走查报
「底部带没有横贯工作区（timeline.w=798 section.w=1220）」）。

**适用边界（诚实标注）**：这套做法只覆盖了生成面这一处拓扑。上表另四份合同各自的面仍然只有类名，
没有几何判据。要把这一族收干净，需要的不是再写四份同样的测试，而是先回答一个产品问题——
三个工作区的外壳是不是同一份框（`T-DS-01` 三栏统一那条，用户 09-14 明确说「等 T-DS-01」）。
在那个问题拍板之前，逐面补几何判据是**症状修法**：它拦得住回归，但不会减少要维护的拓扑份数。
本文把这一点记下来，作为 T-DS-01 的一条输入，而不是在本轮偷偷扩大范围。

## 4. 建议（不在本轮做）

1. `T-DS-01`（三栏统一）落地时，把「外壳框」做成一个有定义处的东西（哪些行列、哪块占哪格），三个面从它派生；那时上表五份合同的类根因才真正消掉。
2. 助手面板的**浮层态几何**（`AssistantPane.tsx` 收起时 `absolute inset-0`，定位祖先是整个工作区）值得单独看一眼：它让浮起来的输入条锚在工作区底部中央，压住底部带的轨道，也压住画布底部那颗时间轴胶囊——本轮合同的 `residual_risks` 已登记，归属方是「画布底部停靠区」这个概念，不是本轮改的三处。
