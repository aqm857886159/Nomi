## 为什么要这张表

四列表按我们自己列的能力清单走，只覆盖已经想到的那些。这张表把参考实现**完整拆开逐层摆在旁边**，
照的是另一格：**压根没想到还有这一层**——没人会给自己不知道存在的东西列一行。

**目标不是一致。** 桌面创作、审批花钱、产物是画布/分镜/时间轴，这些领域约束本来就要求我们不同。
目标是**每一处不同都是看过它的做法之后有理由地不同**。

## 参考实现逐层对照

> 层可裁剪（不是每个框架都有全部九层），但只能从这九层里选：
> 工具 / 转录渲染 / 会话 / 上下文 / 模型与花费 / 控制流 / 扩展 API / 观测与测试 / 安全。
> 裁掉哪层要在下面「裁剪说明」里写清为什么，并同步写进登记表的 `referenceConformance.layers`。
>
> 判定只有三档：
> - `一致` —— 我们就是照它那样做的。
> - `有意不同(理由)` —— **理由必须是领域约束**（桌面本地优先 / 花钱要用户审批 / 产物是画布·分镜·时间轴 …）。
>   「我们这样更简单」「当时就这么写的」「风格不一样」是偏好，不是理由，写上去等同于判 `没想到`。
> - `没想到` —— 看完才发现有这一层。**这一档进前置门**：最后一列填的那个阶段开工前必须补上。

## 自检（交之前逐条问自己）

- [ ] 每一格「它怎么做」都有 `file:line` 或示例 URL —— 没有出处的格子等于没查。
- [ ] 全是 `一致`？说明抄了它，没在想我们的领域约束。全是 `有意不同`？说明根本没看。两种都退回。
- [ ] 每条 `有意不同` 的理由都是领域约束，不是偏好。念一遍：这句话换个框架还成立吗？成立 = 它是偏好。
