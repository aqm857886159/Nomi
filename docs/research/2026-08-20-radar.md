# Nomi 论文雷达（2026-08-20）

本轮最该动的两件事：

1. 把“实体/状态参考库 + 每镜引用”做成不可丢字段；没有持久化视觉锚，跨镜一致性只能靠 prompt 运气。
2. 把“生成 → 结构化审片 → 针对性重试”做成默认闭环，并把提示词验证从测试纯核接到 storyboard 与 batch 生产路径。

## 🟢 可落地

### ViMax：Agentic Video Generation

- 日期：2026-06-02；论文：[arXiv:2606.07649](https://arxiv.org/abs/2606.07649)；代码：[HKUDS/ViMax](https://github.com/HKUDS/ViMax)。
- 洞察：把 script → scene → character bank → shot brief → `ff_desc/lf_desc/motion_desc` → reference selector → 首帧图 → I2V → 拼接拆成可审计阶段；参考图选择和 best-of-k 不是附属功能，而是跨镜一致性的主路径。
- 落到 Nomi：`StoryboardPlan` 保留 `ffDesc/lfDesc/variationType/camIdx`，落画布时写入节点元数据；批次 driver 按实体锚和首尾帧依赖排序，禁止在转换器里静默丢字段。

### SCMAPR：Self-Correcting Multi-Agent Prompt Refinement

- 日期：2026-04-07；论文：[arXiv:2604.05489](https://arxiv.org/abs/2604.05489)；代码：[HiThink-Research/SCMAPR](https://github.com/HiThink-Research/SCMAPR)。
- 洞察：先做场景路由，再生成场景策略、改写 prompt，最后把原始意图拆成原子并做语义蕴含校验；发现缺失/矛盾才定向重写，而不是无限“润色”。
- 落到 Nomi：让 `checkShotLanguage` 负责原子级静态门（污染词、角色名、镜头字段），优化器只接收校验报告生成修复稿；修复稿再次过同一纯核。

### EntityBench / EntityMem

- 日期：2026-05-14；论文：[arXiv:2605.15199](https://arxiv.org/abs/2605.15199)；代码：[EntityBench](https://github.com/Catherine-R-He/EntityBench)。
- 洞察：先建立“已验证的每实体视觉记忆”，再做跨镜生成；评测把镜内质量、prompt 遵从、跨镜一致性拆开，并在实体外观不合格时不计入跨镜分数。
- 落到 Nomi：把角色/场景/道具锚从一次性的 reference sheet 升级成带状态版本的资产记忆；QA 先过实体 fidelity gate，再统计 continuity，避免“看不清也算 0 分”污染均分。

## 🟡 架构教训

### FilmWorld：Dynamic Cinematic World Modeling

- 日期：2026-07-21；论文：[arXiv:2607.19038](https://arxiv.org/abs/2607.19038)。
- 教训：生成前要把人物、地点、道具离散成可传播的世界状态；生成后要做 state-anchored verification → diagnostic → corrective → select 的闭环。单纯增加分镜字段，不能替代状态记忆和审片反馈。
- 对 Nomi 的决策：`variationType` 与 `camIdx` 不能只是描述字段，必须成为生成/审片路由键；每镜应继承“永久身份锚 + 当前状态 checkpoint”，而不是只继承一段长 prompt。

### MuSS：Multi-Shot Subject-to-Video Benchmark

- 日期：2026-04-26；论文：[arXiv:2604.23789](https://arxiv.org/abs/2604.23789)。
- 教训：只看全局“像不像电影”会掩盖 copy-paste、主体缺失和跨镜逻辑错误；局部镜头准确性与全局叙事连贯性要分两层评估，并额外惩罚静态贴纸式输出。
- 对 Nomi 的决策：审片结果至少分为 `shot fidelity`、`entity continuity`、`action/physics`、`narrative continuity`；不能用一个总分掩盖某一轴未判定或未执行。

## 🔵 对标基准

### VBench-2.0

- 论文：[arXiv:2503.21755](https://arxiv.org/abs/2503.21755)。
- 接法：把 human fidelity、controllability、physics、commonsense 作为 Nomi 的模型/流程对比维度；不替代产品级审片，但可用于供应商切换和 prompt 版本回归。

### VABench

- 日期：CVPR 2026；论文/页面：[VABench](https://openaccess.thecvf.com/content/CVPR2026/html/Hua_VABench_A_Comprehensive_Benchmark_for_Audio-Video_Generation_CVPR_2026_paper.html)。
- 接法：当 Nomi 进入原生音画生成时，增加 speech quality、audio-video alignment、lip-sync、desync、visual/audio QA 五类指标；音画不能只靠人眼抽帧验收。

### MSVBench

- 论文：[arXiv:2602.23969](https://arxiv.org/abs/2602.23969)。
- 接法：作为多镜叙事回归集，按镜头数量、角色重现间隔、场景切换难度分层；每次改动至少跑短片、跨场景、长间隔重现三组。

## 本轮筛掉的噪音

筛掉只优化底模或需要重新训练大模型、但无法直接进入 Nomi 编排层的工作；也未把社区 prompt 经验当作模型能力证据。

## 上轮 vs 本轮 diff

- 新增重点：EntityBench 的“持久实体记忆 + fidelity gate”直接对应 Nomi 的锚卡冻结和判分口径；SCMAPR 直接对应 W4 的提示词静态校验接线。
- 方向升级：Seedance 2.5 已支持单次最多 30 张图、10 段视频、10 段音频和 30 秒生成，但这扩大的是参考通道，不会自动替 Nomi 完成资产职责、状态传播和 QA 闭环。
