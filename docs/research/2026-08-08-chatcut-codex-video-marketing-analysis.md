# ChatCut × Codex 宣传视频拆解

日期：2026-08-08
来源：`https://x.com/chatcutapp/status/2075203997359898712`
目标：学习其视频营销结构，为 Nomi 宣传片和“视频拆解”产品能力提供可验证依据。

## 结论

这条视频最值得学习的不是某种滤镜，而是“强主张 → 真实使用情境 → 界面证据 → 现实结果 → 单一 CTA”的证据链。画面在咖啡店实拍与 Codex/ChatCut 实机界面之间反复切换：界面证明工具做了什么，实拍证明它为什么对真实创作有价值。

Nomi 应沿用这种证据结构，但不能照搬咖啡店、演员、文案或具体镜头。Nomi 的实机证据应换成本地项目目录、设置中的 API/本地模型、真实 Skill/MCP 执行记录、生成画布、时间轴初稿和本地导出文件。AI 生成镜头只负责难以实拍的情绪转场，不能替代产品证据。

## 帖子与传播数据

帖子主张：

- “Codex is now a full video editor!”
- ChatCut 插件把非线性编辑能力带进 Codex。
- 已付费 Codex 用户无需额外订阅。
- 一分钟开始使用。
- 单一 CTA：让 Codex 读取 `chatcut.io/codex`。

抓取时页面显示约 186.5 万次浏览、3177 个喜欢、4192 个书签、369 次转发和 103 条回复。数据是抓取时快照，不应在后续宣传中当作恒定事实。

## 真实解析证据

使用 EcCut 本地管线解析 65.024 秒、720×720、24 fps 的 H.264/AAC 视频。分析产物位于 EcCut 工作目录 `pipeline/work/tasks/20260808-chatcut-codex/`，未复制进 Nomi 仓库。

| 指标 | 结果 |
|---|---:|
| 物理镜头 | 38 |
| 平均镜头时长 | 约 1.71 秒 |
| ASR | 0 句 / 0 词 |
| OCR | 90 行，去重后 77 条 |
| 营销段落 | 4 |
| 模型调用 | 11 次，0 次重试 |
| 输入 / 输出 tokens | 137621 / 9850 |
| 计算成本 | 约 ¥0.354 |
| 总耗时 | 201.42 秒 |

ASR 为零说明视频不依赖可识别口播推进。它主要靠音乐、花字、产品界面和画面动作讲故事，因此静音浏览也能理解主线。

## 四段结构

| 时间 | 角色 | 用户看到 | 营销作用 |
|---|---|---|---|
| 0–12 秒 | Hook | 进入咖啡店、打开电脑、点 Codex、导入项目 | 先建立真实工作情境，再让产品出现 |
| 12–28 秒 | 问题与思路 | Codex 文本分析、咖啡制作、时间轴 | 证明 Agent 理解素材和剪辑问题 |
| 28–48 秒 | Solution | 剪辑指令、动效、BGM、SFX、时间轴与实拍结果交叉 | 逐项展示“做了什么”，但不做功能清单口播 |
| 48–65 秒 | Trust / CTA | 导出完成、顾客体验、ChatCut × Codex 品牌页 | 用完成结果收束，最后才给品牌和定位 |

人工核验关键帧后，约有 20 个真人/咖啡店实拍镜头、17 个电脑界面/时间轴镜头和 1 个品牌收尾镜头。没有足够证据证明其中存在 AI 生成画面，因此不能把它描述成“AI 生成 + 实拍”；更准确的说法是“实拍 + 实机界面 + Agent 完成的剪辑结果”。

## 可迁移方法

1. 第一秒做品类重定义，不先介绍团队或背景。
2. 产品界面与现实结果成对出现，避免连续十几秒录屏。
3. 每个界面镜头只证明一件事，OCR 可读时间通常在 1–3 秒。
4. 快节奏集中在中段，最后一个品牌镜头保留约 6.8 秒，给 CTA 足够识别时间。
5. 把价格和上手阻力压到最低：已有订阅免费、一分钟安装、一个 CTA。
6. 不靠旁白也能理解，因此适合 X、LinkedIn 等默认静音场景。

## 不应照搬

- 不复制咖啡店、演员、产品包装、具体英文指令和镜头构图。
- 不把“任何 API”说成“所有 API 都已原生适配”；准确表述是支持兼容端点和本地 ComfyUI，并允许扩展供应商适配。
- 不说“全部本地生成”。准确表述是项目、密钥和编排状态本地保存；实际推理由用户选择的本地或外部模型完成。
- 不把“Agent 可发起流程”说成“Agent 可绕过用户授权花费或发布”。

## 对 Nomi 宣传片的直接启发

建议一分钟结构：

- 0–4 秒：品类重定义，“你的 Codex，现在能导演一条片。”
- 4–14 秒：本地桌面与项目目录，证明本地优先。
- 14–26 秒：在设置中切换兼容 API / 本地 ComfyUI，证明模型可替换。
- 26–40 秒：Codex 或 Claude 经 MCP 发起草稿，Nomi 展示真实 Skill、制作摘要和支出确认。
- 40–52 秒：分镜节点、生成结果、时间轴初稿交叉剪辑。
- 52–60 秒：本地导出文件 + 开源仓库 + 单一 CTA。

镜头语言采用约 55% Nomi 实机录屏、30% 本地工作情境实拍、15% AI 生成转场。任何产品主张出现时，画面必须同时给出对应真实证据。

## 解析过程暴露的产品问题

- EcCut 的镜头切分和 OCR 阶段在完成前长时间无输出，用户会误以为卡死。
- OpenCV 与 PyAV 在当前 macOS 环境加载了两套 `libavdevice`，运行时给出类冲突警告；本次成功，但应视为稳定性风险。
- OCR 能抓到大量界面文字，但英文小字存在黏连和误识别，结果必须保留原帧证据并允许人工改。
- 模型曾尝试改写 OCR 文本，管线的确定性契约已拒绝并修复这些变更；Nomi 必须显示“原始证据”和“模型解释”的边界。
- 总耗时 201 秒，若只显示 spinner 会形成明显黑盒；阶段、真实耗时、是否使用外部推理和预计成本都应可见。
