## 🟡 架构教训

### GroundShot — 训练无关的多镜实体记忆 + 镜头调度（**前轮已列**，本轮补机制细节）

- **证据**：[arXiv:2606.20799](https://arxiv.org/abs/2606.20799) · 2026-06-18（v3 2026-07-20），[官方 HTML](https://arxiv.org/html/2606.20799v1)。自述 **training-free、model-agnostic**，无需额外训练或改模型——正是 Nomi 的接入姿势（P4 解耦）。**两个会话独立搜索都未找到官方代码仓或项目页**（只有论文与 awesome-list 收录）。
- **核心洞察**：观众判断一致性，是拿角色**每次后续出场跟它第一次清晰出场比**。机制四步：① 从**已接受**的镜头在线建实体级视觉记忆；② 按「这一镜作为后续实体参考的预期价值」排生成顺序（**不是**剧本线性顺序）；③ 实体 ground 出来并**验证可靠后才入库**；④ 每镜生成前检索最合适的参考。配套诊断基准 GroundBench。
- **落到哪**（路径已核实）：排镜顺序 → [dependencyWaves.ts](src/workbench/generationCanvas/runner/dependencyWaves.ts)（现有生成波次）与 [storyboardPlan.ts](src/workbench/generationCanvas/agent/storyboardPlan.ts)；实体参考检索 → [referenceSlots.ts](src/workbench/generationCanvas/runner/referenceSlots.ts) + [referenceAncestors.ts](src/workbench/generationCanvas/runner/referenceAncestors.ts) + [generationReferenceResolver.ts](src/workbench/generationCanvas/runner/generationReferenceResolver.ts) + [relayFrameResolver.ts](src/workbench/generationCanvas/runner/relayFrameResolver.ts)。
- **差在哪**：Nomi 现在的中继是**结构依赖驱动**（上游节点→下游槽）、排镜是叙事线性；GroundShot 多一层「按参考价值主动调度 + 入库前验证」的语义。这条**不碰 provider 内部**，正好落在已有的 agent/记忆层。
- **限制**：无仓 = 不能接代码、不能宣称复现；GroundBench 指标细节论文摘要未给全，接 eval 前需读正文核实。

### UnityShots — 双记忆 + 边界门控（**本轮唯一真新增**）

- **证据**：[arXiv:2606.21661](https://arxiv.org/abs/2606.21661) · 2026-06-19，[项目页](https://jackailab.github.io/Projects/UnityShots)。**不是黑盒可套**——在 LTX-2.3 上重训，靠 speaker token + 离散 cut-type 先验专门训练。
- **机制**：长期记忆槽锚在**开场镜**、短期记忆槽存紧邻的**上一镜尾帧**，由「边界条件门」在每个切点用视觉切镜概率 + 节拍信号更新。报告在 200 条多文化多镜序列（6 大族裔区 / 10+ 语言）上领先全部开源基线，多镜轴追平最强闭源。
- **对 Nomi 的意思**（只借设计、不接模型）：Nomi 的 relay 已有「上一段尾帧接下一段首帧」（`relayFrameResolver.ts`）——UnityShots 说**别只传尾帧**，应同时保留一个「开场锚点」长期记忆，并在**切点**（而非固定间隔）由切镜信号触发更新。[detectShotCuts.ts](electron/video/detectShotCuts.ts) 已有切镜检测，正好供这个「边界门」用。
- **限制**：需重训 LTX-2.3 + 多卡，solo 本地产品接不了。

### DirectorBench + KathaTrace 双证：瓶颈在**镜间**与**规划**（前轮已列 · 本轮补量化）

- **DirectorBench**（[arXiv:2605.30090](https://arxiv.org/abs/2605.30090) · 2026-05-28 · repo + HF 公开）把 ViMax 一字不差描述成 "open-source decompose-stitch pipeline whose base LLM produces a script, then a storyboard, then a first-frame image per shot, then runs per-shot text-to-video, and finally composes background music and voiceover post-hoc"——**这就是 Nomi 的流水线原型**。四系统排名 Kling Canvas Agent > Dreamina Creation Agent > MovieAgent > **ViMax（最差）**；ViMax temporal coherence **0.18**，跨工作流 transition 均分 **0.256**，inter-unit 质量普遍远弱于单帧质量。
- **KathaTrace**（[arXiv:2607.01312](https://arxiv.org/abs/2607.01312) · 2026-07-01 · [项目页](https://jamunasmurthy.github.io/kathatrace/)，代码释出待核实）定义 "semantic trajectory collapse"——画面各自都连贯，但镜间的因果/情绪/后果链断了。关键实验：**渲染器固定、只改规划器，坍缩指标降 11.2 分；只改渲染器仅降 4.1 分**。
- **影响 Nomi 哪个决策**：**别再把「加 provider / 提单镜画质」当主路**。两篇独立证据同向：差异化投入应压在**镜间**（转场 + 实体中继）和**规划质量**（[workbenchStore.ts](src/workbench/workbenchStore.ts) 的 storyboard 编排、`storyboardPlan.ts`）上，不是广度（呼应 D2「广度是敌人」）。评测也要显式测「镜间因果/情绪是否存活」，不能只测「每镜好不好看」。

## 🔵 对标基准

### EntityBench — 跨镜实体一致的专用卷（**本轮升级为「已实查可执行」**）

- **证据**：[arXiv:2605.15199](https://arxiv.org/abs/2605.15199) · 2026-05-14；官方仓 [Catherine-R-He/EntityBench](https://github.com/Catherine-R-He/EntityBench)（12 stars / 5 commits，08-28 已记链接）。**本轮新增的是可执行性实查**：`eval/evaluate_benchmark.py`（单卡）、`run_eval_distributed.py`（多卡）、`compare_methods.py`，example 脚本 `examples/run_eval_example.sh`；按 `<results_dir>/<episode_id>/<scene>_<shot>.mp4` 目录约定即可对**任意生成器输出**打分。
- **测什么**：140 集 / **2491 镜**，easy/medium/hard 三档，单集最多 50 镜、最多 13 个跨镜角色 / 8 个跨镜地点、复现间隔跨 48 镜。三层度量：intra-shot 画质（6 个 VBench 类指标）、intra-shot prompt 对齐（实体在场/逐实体保真/动作保真）、**inter-shot 实体一致（核心）**——DINOv2 embedding 相似度 + GroundingDINO 定位 + 多模态 LLM 逐实体比对，共 51 个指标。
- **怎么接**：把「首次清晰出场做锚、后续每次比锚」搬进 `evals/journeys/`（扩 `j4-reference.mjs`），**embedding 相似度这条离线指标先做，不接生产模型**；再从其 recurrence-gap 分层借一组最小真实任务（角色/道具/地点间隔 1/8/24 镜后再现），接 [shotVerifyOrchestrate.ts](electron/capabilityCore/shotVerifyOrchestrate.ts) 时先加 fidelity gate（实体没按 prompt 出现就不算「像不像」）。
- **接入边界（本轮实查补充）**：依赖 `groundingdino-py + vbench + pyiqa`，且需 **Azure OpenAI endpoint + Gemini API keys**（round-robin）——**不是零成本**；先跑最小子集验证能对 Nomi 输出打分，别整包当默认门岗。

### 两把现成的跨镜尺子：KathaTrace 的 STG + DirectorBench 的 checkpoint 骨架

- **STG（Semantic Trajectory Gap）** = 「只给文字的可恢复度 − 只给图像的可恢复度」，量化「意思在可视化过程中丢了多少」；配 KathaBench-25K（5,000 叙事 / 20,000 转场 / 28,712 可恢复性问题）。Nomi 现在的验收偏「每镜首帧对不对」（[shotVerifyRunner.ts](src/workbench/generationCanvas/agent/shotVerifyRunner.ts) / `shotVerifyOrchestrate.ts`），**测不到「镜间意思断没断」**。接法：在 `evals/journeys/` 定义「转场可恢复度」验收槽作**跨镜维度**，先在 2–3 条多镜任务取基线，**只借指标形式、不引 KathaBench 数据集**。限制：需要一个 VLM 打分器，接前要定清用哪个模型、成本多少。
- **DirectorBench 的 5 维（Script & Narrative / Visual / Audio / Cross-Modal / Stability）+ 40 checkpoint + 9 sub-metric** 可作内部诊断报告骨架，其中 transition sub-metric 直接对应 Nomi 时间轴 shot→shot 链。**只作诊断层，不作单一自动放行条件**（守 P3：全绿≠完成，仍需真实任务走查）。

## 本周建议的最小验证（都先产证据，不接依赖、不加入口）

### A. 跨镜身份评测任务（第一优先）

- 在 `evals/journeys/` 加一条「一名角色跨 6 镜 + 一次镜间转场」的离线任务，扩 `j4-reference.mjs`；度量借 EntityBench 的「首次出场做锚、后续比锚」，embedding 相似度离线算。
- 先取基线，量清当前 reference-relay 掉在哪，再谈要不要引入新机制。

### B. GroundShot 式「按参考价值排镜 + 已接受实体记忆」原型

- 落 `referenceSlots.ts`（复用已验证实体裁片）+ `dependencyWaves.ts` / `storyboardPlan.ts`（按实体覆盖度重排生成顺序），**不接 GroundShot 代码（无仓）**。
- 3–5 条多镜多角色真实任务，对比「线性顺序 + 首帧参考」vs「按参考价值排序 + 已接受实体记忆」的身份保持 / 漂移 / 成本；失败样例也留。
- 通过条件：跨镜身份改善不以排镜成本成倍或动作僵化为代价。

### C.（次优先）STG 转场可恢复度接进跨镜验收维度

- 在 `evals/journeys/` 加「转场可恢复度(STG)」验收槽，喂 `shotVerifyOrchestrate.ts` 作跨镜维度（区别于现有单镜首帧维度）；先在 2–3 条多镜任务取基线。

- 三项都先产证据再决定架构 / 门岗，不与项目级统一 Agent/MCP/Skill 的单一能力合同争第二套状态源。
