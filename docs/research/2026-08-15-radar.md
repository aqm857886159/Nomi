# Nomi Research Radar — 2026-08-15

> 本轮按 8 个固定方向分别查询 arXiv，并对命中项回到论文全文、官方项目页和官方代码仓核验。时间窗为 2026-02-15 至 2026-08-15；只保留会改变 Nomi 落地、架构或评测决策的条目。

## 一句话结论

今天最值得拿走的不是“再接一个视频模型”，而是两段现有闭环的升级：**用可验证的 DSG/CMQ 问题替代笼统 VLM 打分来驱动黑盒 I2V 重试**，以及**把运镜评测从“一镜一个动作标签”升级为“镜内分段 + 多动作并存”**。

**本轮最该动的 1-2 件事**：

1. 在现有 `shotVerify` / 自我改进闭环上做一个小规模“诊断 → 改 prompt → 重生成 → 涨才收”的 I2V lane：每镜把提示词编译成不超过 20 个 DSG/CMQ 是非题，重试最多 2 次；只有模型档案明确暴露 `seed` / `cfg` 时才搜索这些参数，不给所有供应商硬加参数。
2. 先把 CamChoreo 的“时间区间 + 复合运镜”标签接进 `evals/journeys/j6-camera-move.mjs`，补上“推近后甩镜”“横移同时摇镜”等用例；**暂不扩 3D 渲染器**，先量出当前 `customMove` 退化路径的真实失败率再决定产品范围。

## 🟢 可落地

### Beyond Trial-and-Error — Agentic Optimization for Image-to-Video Adherence

- [arXiv:2608.12290](https://arxiv.org/abs/2608.12290) · 2026-08-12 · Google Cloud / Google DeepMind
- **一句话洞察**：面对黑盒 I2V，先让 mLLM 把输入编译成 Davidsonian Scene Graph（主体、动作、客体、地点、属性）和 Common Mistake Questions（肢体、闪变、无故说话、该动不动等），据此迭代 prompt；再用质量指标选择 seed / CFG。人评中优化结果相对 baseline 的偏好胜率最高达 69%。
- **Nomi 落点**：扩展 `src/workbench/generationCanvas/agent/shotVerify.ts` 与 `shotVerifyJudge.ts`，让 verify 输出“可回答的是非题 + 失败类型”，并把失败项送入 `shotVerifyStore.ts` 的修复消息；在 `electron/productionRun/productionRunDriverOps.ts` 复用 `maxAttemptsPerJob` 和样片门，做最多 2 次的候选生成，评分落到 `evals/lib/vbenchRubric.mjs`，仅保留相对当前 adopted 产物确实上涨的候选。它应并入历轮 TARA 的“类型化修复 + accept-or-revert”主线，不另造第二套 loop。
- **成熟度 / 热度**：论文刚发布，全文未给公开代码仓或项目页；但方法只依赖黑盒生成 API + mLLM，且附录公开了 DSG/CMQ 提示模板。可落的是机制，不是可直接复制的代码。论文也明确承认多轮生成成本高、现有 mLLM 对细微运动理解仍弱，所以 Nomi 必须设额度上限和保守回滚。

## 🟡 架构教训

### Context-Matched Distillation — Teacher Causality for Autoregressive Video Distillation

- [arXiv:2608.13391](https://arxiv.org/abs/2608.13391) · [官方项目页](https://hmrishavbandy.github.io/cmd-site/) · 2026-08-13
- **一句话洞察**：如果“裁判”看到了生成当时不可能看到的未来帧/未来控制，得到的监督会系统性偏离真实 rollout；论文用 causal teacher、prefix scoring 和 prefix corruption 把评测上下文与学生实际拥有的前缀对齐。
- **影响 Nomi 的决策**：Nomi 虽不训练视频模型，但同样有 decompose-stitch 的因果边界。`shotVerifyRunner.ts`、`dependencyWaves.ts` 与 production run 的逐镜验证，必须区分“生成当时可用证据”和“全片完成后的复盘证据”：前者才能驱动在线修复，后者只能做离线质量报告。否则会出现 eval 认为某镜“本可避免”，实际当时根本没有后续实体状态可用的假诊断。
- **成熟度 / 热度**：有官方项目页，摘要未承诺开源代码；核心实现需要训练 causal teacher，不适合 Nomi 直接采用。价值是把“无未来信息泄漏”固化成 eval 数据契约。

### ContextMaster — Interactive Multi-Shot Video Creation via Fixed-Budget Sparse Context Routing

- [arXiv:2608.04956](https://arxiv.org/abs/2608.04956) · [官方项目页](https://guoxu1233.github.io/ContextMaster/) · 2026-08-05 · 清华 / 南大 / 快手 Kling / HKUST
- **一句话洞察**：生成、跟随参考、编辑已有视频不应是三套割裂上下文；论文把 reference、history、source、target 做成 role-aware context，并用固定预算稀疏路由读取不断增长的镜头历史，强制约束通过 ConstraintSink 常驻。
- **影响 Nomi 的决策**：`electron/ai/agentChatV2.ts` 的长项目上下文应明确分成“必须始终可见的当前镜约束”和“可检索的历史证据”，而不是随项目增长把所有分镜、参考与旧结果平铺进同一消息。生成 / 参考 / 编辑三类动作继续共用同一套 project evidence 与 provenance，模型适配层只决定怎么消费。
- **成熟度 / 热度**：官方页展示了 T2MV、R2MV、V2MV 和组合工作流，论文声称单卡 16 FPS；但项目页的“GitHub”按钮仍回链项目页本身，未找到真实代码仓。现阶段只作架构依据，不列为可集成依赖。

### Vorch-Streamer — Extending Human Audio-Visual Generation to Real-Time Long-Form Streaming

- [arXiv:2608.05663](https://arxiv.org/abs/2608.05663) · [官方项目页](https://vorch-project.github.io/Vorch-Streamer-project/) · 2026-08-06
- **一句话洞察**：长音视频不能把整段台词当作一个全局条件交给短上下文生成器；论文用 25 Hz 的 speech-planning token 指明“当前块该说到哪里”，再配合 bounded context 与 self-forcing 控制长程漂移。
- **影响 Nomi 的决策**：音频节点与视频镜头之间应持久化“台词片段 / 说话人 / 时间区间 / 已消费进度”，并随 shot provenance 传递；不要只存一段 TTS 文件 URL 后靠最终合成猜对齐。这个状态未来应成为 `electron/audioTaskRunner.ts` 与时间轴插入层之间的显式契约。
- **成熟度 / 热度**：官方页给出 22.8B 模型、27.12 FPS、Sync-C / WER / identity 对比，但代码明确标为 Coming soon，且需要重训练大型模型；Nomi 只吸收状态设计，不追模型实现。

## 🔵 对标基准

### CamChoreo / CamDistill — Temporally Grounded Compositional Camera Motion Understanding

- [arXiv:2608.10932](https://arxiv.org/abs/2608.10932) · [项目页](https://ddz16.github.io/cammotion.github.io/) · [代码](https://github.com/ddz16/CamDistill) · 2026-08-11
- **一句话洞察**：真实单镜运镜会在镜内变化，且近半标注区间同时包含多个运动；整段只贴一个 `pan` / `dolly` 标签会丢掉时间边界和组合关系。CamChoreo 给出 4,229 个真实镜头、20 个带方向的标签和区间级多标签协议。
- **接入 eval**：在 `evals/journeys/j6-camera-move.mjs` 增加三组评分：区间边界、区间内多标签集合、方向正确性；测试当前 `electron/ai/canvasTools.ts` 的 `customMove` 对复合/连续运镜是否完整保留，而不是先改动其刻意限定的 `SINGLE dominant move` 精确渲染契约。评测稳定后，再决定 `cameraMoveSchedule.ts` 是否值得支持多段轨迹。
- **成熟度 / 热度**：官方数据集、训练/评测代码和 4B/8B 权重均已发布；GitHub 于 2026-08-14 仍有提交，Apache-2.0，当前 1 star。可复现性强，但传播尚早，优先借 taxonomy 与 eval，不引入 4B/8B 模型到产品运行时。

### AcoustiTrace — When Plausible Sound Violates Physics

- [arXiv:2608.02035](https://arxiv.org/abs/2608.02035) · 2026-08-03
- **一句话洞察**：音效“听起来合理、时间也大致同步”仍可能违反画面里的声学过程；基准按声源生成、传播环境、接收三个阶段拆成 8 个可诊断维度，而不是只给一个 A/V alignment 总分。
- **接入 eval**：`evals/lib/vbenchRubric.mjs` 目前的视频维度只有对齐、主体一致、运动平滑、时序稳定和动态程度，没有音频。不要把音频硬塞进现有帧采样评分；新增独立 audio-video rubric，至少记录 `event onset`、`source match`、`environment/reverb`、`distance/occlusion` 与 `lip-sync`，最终由 `scripts/eval-review-images.mjs` 的后继媒体评测入口汇总为分维结果。
- **成熟度 / 热度**：论文提供完整任务定义与数据构成，arXiv 摘要未给代码或项目页；先接指标契约和小型固定 smoke 集，不宣称复现官方 benchmark。
