# Nomi 论文雷达 · 2026-08-08（增量）

> 检索窗与方法：按固定 8 方向查询近 6 个月 arXiv，重点核对 2026-08-07 之后的新稿；论文事实回到 arXiv 原文，代码成熟度回到官方项目页与 GitHub。只保留会改变 Nomi 行动、架构或 eval 的条目。

## 一句话总结

本轮 **🟢 1 / 🟡 1 / 🔵 0**。最值得立刻吸收的不是新生成模型，而是 VideoArgus 的“**每个真实任务先冻结 rubric，再按可见证据逐项评估**”；这应直接进入本次 Run/权限/可观察性真实任务测试。ContextMaster 继续证明跨镜上下文需要角色化、稀疏路由，但它属于模型内部方案，不能被包装成 Nomi 可直接接入的能力。

**本轮最该动的两件事：**

1. 本次 `evals/` 新增的真实用户任务，为每条场景保存固定 rubric、失败模式与证据计划；评价器只消费截图、事件、账本和产物，不凭单一总分放行。
2. Run/Artifact 合同保留“约束属于哪个阶段/镜头/实体”的显式归属，避免把全局品牌约束、当前镜头动作和历史产物堆成无边界上下文；暂不引入模型内部 memory 或 attention 依赖。

## 🟢 可落地

### VideoArgus：按实例冻结 rubric，再用工具证据逐项判生成与编辑结果

- **链接 / 日期**：[arXiv 2608.05485](https://arxiv.org/abs/2608.05485)，v1 **2026-08-06**；[官方项目与代码](https://github.com/zzzmyyzeng/VideoArgus)。截至 2026-08-08，仓库 2 stars、当日仍有 push，属于很新但尚未被广泛复现的实现。
- **一句话洞察**：同一个输入的候选结果共享一份 output-blind rubric；rubric 先写清判据、失败模式和取证计划，再由 VLM QA 与视觉工具产出逐项证据和诊断报告，避免 judge 看完结果后临时改尺子。
- **落到 Nomi**：扩展 `evals/lib/judge.mjs` 与本次新增的 Run 真实任务 fixtures。每个场景固化 `criteria / hardFailures / evidenceSources`，证据来自 Run event、Approval ledger、素材缩略图、技术检查和真实 UI 截图；同一场景的不同实现版本复用同一 rubric。
- **诚实边界**：不直接引入整套仓库和重模型；先复用评测合同与证据链。2 stars 不能证明工业成熟，必须在 Nomi 自己的任务上验证。

## 🟡 架构教训

### ContextMaster：长流程上下文要按角色和约束路由，不能把所有历史平铺给模型

- **链接 / 日期**：[arXiv 2608.04956](https://arxiv.org/abs/2608.04956)，v1 **2026-08-05**；论文给出[项目页](https://guoxu1233.github.io/ContextMaster/)，本轮未在 arXiv 或项目页发现公开 GitHub 仓库。
- **一句话洞察**：它把生成、参考遵循和编辑的上下文按角色表达，并用固定预算稀疏路由读取不断增长的历史，同时让任务约束保持可见。
- **影响 Nomi 哪个决策**：Run 事件是审计事实，不应整段灌入每次生成 prompt；阶段 driver 应只装载当前镜头需要的品牌约束、实体参考、已批准方向和上游产物。落点是 `electron/skills/playbookOrchestrator.ts` 的阶段输入合同，以及 storyboard 的 anchor/shot 明确归属。
- **诚实边界**：论文收益主要来自模型训练和推理内部机制。Nomi 只能借鉴“角色化上下文与固定预算”的编排原则，不能声称获得其速度或一致性指标。

## 🔵 对标基准

本轮没有比 2026-08-07 已收录的 EntityBench / MSAVBench 更适合立刻接入的新独立 benchmark。VideoArgus 同时发布 1,026 个输入实例，但本轮先归入“可落地”的 rubric/evidence 方法，不重复计数。

## 上轮 vs 本轮 diff

- **新增**：VideoArgus（🟢）、ContextMaster（🟡）。
- **主线变化**：08-07 的“实体级、分组 rubric”不变；本轮把它进一步收紧为“每个任务先冻结 rubric，再按证据执行”，可直接用于当前体验改造验收。

- **筛掉约 30 篇噪音**：机器人 world model、虚拟试衣、纯训练组件、搜索误命中的理解任务，以及没有公开实现且越过 provider 边界的模型内部方法。
