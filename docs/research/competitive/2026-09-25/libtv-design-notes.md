这份文档回答的是“用户如何完成一次创作，以及每个中间状态怎样告诉用户发生了什么”。它把已看到的页面行为和推断分开。页面、截图和文本证据以 `E-*` 或文件名回查；没有成功生成图片，所以生成质量、供应商失败、超时、积分返还仍然未验证。

## 1. 产品核心判断

LibTV 的核心不是单个模型入口，而是把“自然语言意图—可编辑画布—节点状态—资产/角色复用—Agent 辅助”放进同一个生产对象。公开 Plugin 页面承诺 Agent 可以调用全模型、管理多资产和编排多场景；CLI 指南进一步把项目、画布、上传、节点、连接、进度、失败定位、重试和结果 URL 写成一条链。真实画布把这条链落在节点上：提示词、模型、参数、费用、确认、取消和后续对话都能回到同一个图片节点。

因此，LibTV 的设计单位更接近“可再次运行的创作节点”，而不是一次性聊天回答。用户可以先只建节点、再改参数、再确认运行；取消也不会丢掉节点。这个闭环是本轮最值得带回 Nomi 的机制。

## 2. 入口与信息架构

### 2.1 公开入口如何建立预期

首页同时展示“新建画布创作”、脚本/图片/视频/音频/智能剪辑能力、最近项目、TV Show 和近期上新。导航还把 Agent、3D-BOX、项目、资产、插件与扩展、社区、版本更新、积分超市和会员放在同一层。它传递的不是“这里有很多模型”，而是“这里有从创意到成片的不同工作入口”。

Plugin 页面使用三步安装指令（添加 marketplace、添加 `libtv`、授权 LibTV 账号），再用具体工作流示例说明结果仍回到 LibTV。Blender 页则只承担一个清晰承诺：在 Blender 内完成白模视频，一键导出到 LibTV 成片。CLI 指南面向觉得画布沉重的用户，说明适用任务、登录、Access Key、积分、团队/个人空间和失败处理。三个入口分别服务发现、接入和替代操作方式，没有把所有说明塞进画布。

### 2.2 画布外壳

观察到的画布外壳包含：

- 顶部：项目名、积分余额、工作流/故事板切换、发布与分享、积分超市。
- 左侧：添加节点、移动、素材库、角色造型室、生成历史、快捷键、教程。
- 中央：可平移、缩放、吸附、隐藏连线、小地图和整理画布的无限画布。
- 右侧：画布/资产双标签、节点搜索、评级筛选、展示设置、节点列表和定位。
- 节点内部：提示词编辑、参考/标记/风格槽、模型、比例/画质/分辨率/数量、预设、AutoLink、费用和生成按钮。
- 故事板：文本/图片/视频分栏、对话记录、待确认/已询问等状态，以及“全能创作/手动生成”两种继续方式。

这种布局把“空间组织”和“单节点生产”分开。左侧功能是可发现的工具箱，右侧是结果索引，节点本身保留真正影响产出的参数。

## 3. 一次图片生成的状态机

证据矩阵的机器可读版本见 `libtv-state-matrix.json`；下面是面向产品和设计评审的简化版。

| 状态 | 触发条件 | 用户看到的反馈 | 下一步 | 证据/状态 |
|---|---|---|---|---|
| 空画布 | 首页新建画布 | `TV Director`、0 节点、图片/视频/音频/剧本/智能剪辑入口 | 选择一个节点类型 | `01-new-canvas-*`，observed |
| 图片节点已创建 | 选择图片生成 | 节点名、尝试入口、提示词占位、参考/标记/风格、模型和参数 | 输入提示词或上传参考 | `02-image-node-*`，observed |
| 空提示词 | 提示词为空 | 提交按钮 disabled；没有额外错误文案 | 输入文本/参考 | `11-empty-prompt-*`，observed |
| 可提交 | 输入文字提示词 | 文案留在节点中，生成按钮可用，费用显示为 15 | 点击生成 | `03-image-prompt-*`，observed |
| 待确认 | 点击生成后进入故事板/Agent | “1 个图片提示词已预备”“预计消耗 15 积分”“点击查看提示词”；有自动确认、取消、确认生成 | 查看提示词、确认或取消 | `17-storyboard-confirmation-*`，observed |
| 第一次取消 | 点待确认的取消 | Agent 改问“是否运行图片节点…”，提供“暂不运行”；节点仍未生成 | 暂不运行或继续 | `18-generation-cancelled-*`，observed |
| 取消完成 | 点暂不运行 | “好的，已取消本次运行，图片节点保持未生成状态。需要时告诉我，我再帮你运行或调整参数。” | 稍后运行、调整参数 | `19-generation-dont-run-*`，observed |
| 余额不足 | 6 积分余额尝试 15 积分生成 | 供应站提示积分不足，给升级会员/充值入口，并展示积分规则、套餐和退款/返还 FAQ | 充值、升级或退出 | `08-insufficient-credits.png`，observed |
| 运行中 | 确认后（本轮未能进入） | 画布/故事板应保留节点和取消入口；此前 DOM 曾出现“生成中/取消 ESC” | 等待或取消 | `05-image-started-*`，partial |
| 成功 | 服务返回图片（本轮无余额，未进入） | 图片结果回到节点/历史，应该可以继续引用或接下游节点 | 继续编辑、复用、导出 | unverified |
| 失败 | 服务错误/超时（本轮未进入） | 供应商错误、重试、积分返还等行为未取得实证 | 重试、改参数或取消 | unverified |

关键设计是“确认”和“取消”有两个层次。第一个取消停止自动运行，第二个“暂不运行”让 Agent 给出最终确认；最终文本还告诉用户节点没有被删除，降低误操作焦虑。它把可逆性写进反馈，而不是让用户自己猜。

## 4. 状态与信任设计

### 4.1 费用在动作前可见

节点内直接显示 15，确认对话再次显示预计消耗 15，余额在顶栏显示 6。余额不足后，供应站解释免费用户每日赠送 20 积分、云存储 3GB、会员积分周期和积分消耗/返还/退款规则。用户至少有三次机会知道成本：节点、确认、供应站。这个重复是必要的，因为生成是有成本的不可逆动作。

### 4.2 结果是否存在有明确证据

取消完成的文案明确写“保持未生成状态”；生成历史还显示图片/视频/音频计数和“没有更多了”。即使本轮没有成功图片，系统仍能告诉用户“没有结果”与“没有更多历史”是两个不同事实。

### 4.3 Agent 是过程解释器

Agent 侧边栏不替代画布，而是解释节点为什么等待、需要什么确认、下一步能做什么。可见状态包括“待确认后生成”“已询问”“思考中”，并给出全能创作与手动生成两个出口。公开 CLI 文档中，Agent 还承诺查询进度、定位失败节点、重试并返回项目 URL/视频/过程摘要；这些是产品声明，未在本轮成功生成上验证。

## 5. 资产、角色和历史

素材库侧栏把风格库、特效库、创建风格/特效节点和工具箱放在一起；它不是单纯文件浏览器，而是能把资产转化成可连接的节点。角色造型室分“我的角色库/官方角色库”，提供性别、年龄段、文化区域过滤、搜索、多选、列表/宫格切换和创建新角色。它说明 LibTV 把角色当成可复用生产资产，而不是每次提示词里重新描述。

生成历史支持全部画布/本画布、图片/视频/音频、评级过滤、时间倒序和批量操作。历史的主键不是一个文件夹，而是“生成记录”；这与画布节点、角色库和资产库互相连接，形成复用网络。

## 6. 教程与快捷键如何降低学习成本

教程入口给出使用教程、联系客服、联系销售和公众号，按用户意图分流。快捷键面板把高频动作按“创作、生成、缩放、触控板/鼠标、键盘、其他”分组：生成 Enter、新建节点 Tab、复制节点和连线 D、连线 L、撤销 Z、重做 Shift+Z、搜索 F、整理画布 Option+Shift+F。它没有要求用户先读长文档，用户在操作时才需要快捷键。

这是一种“渐进发现”设计：空画布先给动作入口；熟练用户再通过快捷键提高速度；遇到问题才进入教程/客服/销售。Nomi 可以复用这个层级，而不是把所有快捷键和说明常驻在主界面。

## 7. 公开生态的接入逻辑

| 入口 | 面向用户 | 承诺 | 本轮证据 | 未验证 |
|---|---|---|---|---|
| Plugin | Codex/Agent 用户 | 安装插件、授权账号、全模型/多资产/多场景编排，结果回到 LibTV | Plugin 页面截图和文本 | 授权后首个真实产物 |
| CLI | 习惯命令行或觉得画布重的用户 | 创建项目/画布、上传、搭节点、查进度、定位失败、重试、返回 URL | 飞书 CLI 指南 | 真实登录、Access Key、命令结果 |
| Blender | 3D/白模用户 | Blender 内白模视频，一键导出到 LibTV 成片 | Blender 页面截图和文本 | 插件安装、导出回流 |
| Agent 对话 | 画布用户 | 解释待确认、取消、继续运行或调整参数 | 真实故事板/对话截图 | 成功/失败/重试完整闭环 |

共同结构是“外部入口负责接入，LibTV 画布负责承接结果”。这比单独做一个聊天窗口更有价值，因为用户最终需要继续编辑，而不是只拿到一段回复。

## 8. 对 Nomi 的设计启示

### 直接适用

1. **节点是可复用任务，而非提交表单。** 每次生成都应留下可再次运行的输入、参数、成本和状态；取消只撤销本次运行，不删除节点。
2. **把成本和不可逆性放到动作前。** 生成按钮、确认对话、余额不足三个层次分别承担预估、确认和补救，用户不必在结果后才发现扣费。
3. **用 Agent 解释状态，画布保留编辑权。** Agent 可以问确认、显示进度、解释失败；真正的提示词/参考/模型/参数仍在节点中可见。

### 值得试验

1. 在 Nomi 现有画布上做“待确认→取消→最终取消”最小实验。成功指标：用户能复述“没生成、节点还在、可以稍后再跑”，且不需要离开当前画布。
2. 在真实生成任务上对比“单次提交”与“节点内费用+确认对话”。指标：误触发率、取消后继续修改率、用户对扣费的预期准确率。
3. 让素材/角色库的条目能一键变成可连接节点，再与当前参考槽对账；不增加第二套资产状态。

### 持续观察

- 成功图片回到节点后的预览、版本、复用和导出。
- 失败/超时/积分返还，以及取消发生在排队、运行和完成前的差异。
- 故事板与工作流模式之间切换时，当前节点和对话是否保持一致。
- Plugin/CLI/Blender 的安装、授权、更新和解绑。

### 暂不采用

- 不为了复制“全模型调用”而增加第二套供应商选择器；先把 Nomi 的通用模型档案和真实能力边界做清楚。
- 不把公开营销页面当成运行证据；本轮 LibTV 的成功生成、失败重试和视频链路仍需真实额度或官方可复现样例。

## 9. 研究边界与成本收据

- 真实浏览器输入：完成首页→画布→节点→提示词→确认→取消→最终取消，以及教程、快捷键、历史、素材库、角色库、故事板切换。
- 截图/文本：已保存 01–20 的关键帧与 DOM 文本，另有 `libtv-state-matrix.json` 和 SHA-256。
- 录屏：没有安全隔离的浏览器窗口录屏；以截图序列和动作日志保存，录制验收为 `partial`。
- 真实生成：余额 6，单次估算 15；没有购买。观察到的充值/会员入口的最小可见方案远高于单次测试所需成本，因此按“最小且必要成本”停止。
- 未验证：真实成功图片、供应商失败、队列/超时、积分返还、视频/音频成片、插件/CLI/Blender 首次接入。

下一次 LibTV 补测应只做三件事：取得可控的最小生成额度并记录完整成功/失败/返还状态；在同一项目完成一条图片到视频的可编辑回流；隔离一个浏览器窗口录制完整操作并亲自回看。完成这三项后，才可把本轮从 `partial` 改为 LibTV 子课题的 `completed`。
