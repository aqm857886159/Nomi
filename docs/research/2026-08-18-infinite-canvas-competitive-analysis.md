## 0. 数据可信度（先说这个，因为第一轮全错过）

**第一轮作废。** 用子 agent 自由抓取，产出的数据存在严重串库：中间文件按「第几个视频」命名
（`cmt1.json`/`sub_v1.txt`/`v1_comments_p3.json`），任何重试/错位都会让 A 视频的评论挂到 B 视频
名下且无人察觉；评论翻页参数失效时返回同一页，agent 看不出来，抓了 5% 就自报「已抓全」
（13 个分页文件全是 2248 字节 = 同一页抓了 13 遍）。

**根因**：把正确性寄托在模型自觉上，而不是结构上。

**第二轮的结构保证**（`/tmp/dx_fetch.py`，产物 `/tmp/dx2/{BV}.json`）：

| 闸 | 做法 | 拦住什么 |
|---|---|---|
| 身份闸① | 每视频先取 `x/web-interface/view?bvid=`，断言返回 bvid == 请求 bvid | 请求错视频 |
| 身份闸② | aid/cid **只从该次校验过的响应取**，绝不跨视频复用 | 串库（第一轮真凶） |
| 身份闸③ | 每条评论回带 `oid` 必须 == 本视频 aid，不符剔除并记 ERROR | 评论错位 |
| 污染闸 | 字幕时间轴末尾必须落在视频时长内 | 别的视频的字幕 |
| 诚实闸 | 覆盖率写成 `拿到N/官方M` + 是否触顶，**无「已抓全」字段** | 自我欺骗 |
| 产物 | 一律 `{BV}.json` 按 BV key | 错位不可能悄悄发生 |

**校验器自身也修过一次**：最初用「字幕含不含技术词」判污染，把 GTA5 春节那期真字幕误判为
suspect（人家本来就只有「恭喜发财」）。**判据必须是硬事实（时间轴越界），不能是软推测。**

**最终数据**：60/60 视频，评论顶楼 8844 + 楼中楼 10546 = **19390 条**（官方计数 22598，覆盖 86%），
弹幕 1433 条，字幕 60/60 全部通过污染校验，**零身份错配、零抓取失败**。
原始数据：`docs/research/data/2026-08-18-daxiong-bilibili-raw.tar.gz`，
信号明细：`docs/research/data/2026-08-18-infinite-canvas-raw-signals.md`。

## 3. 他做对的三件事（代码级）

### ① protocol 一等抽象 —— 直击「接了模型改不了 URL」

```python
# main.py:317
SUPPORTED_PROVIDER_PROTOCOLS = {"openai", "apimart", "gemini", "gemini-cli",
                                "volcengine", "runninghub", "jimeng", "codex"}
```

用户流程：**填 Token → 验证 → 拉取模型 → 勾选想用的 → 保存**。
路由齐备：`/api/providers`、`/providers/fetch-models`、`/providers/test-connection`、
`/providers/probe-async`。

> 这正对上 Nomi 微信群那条「接了阶跃星辰但改不了 API URL，翻半天找不到地方」，
> 也对上你提过的「他拉取很多模型，要有个地方选哪个不选哪个」。

### ② 素材库全局化 + `@` 引用 —— 不连线也能喂参考图

`data/asset_library.json` 结构：`libraries → categories(角色/场景/工作流) → items`，带 `dir` 映射到磁盘目录。
交互：`smart-canvas.js:14496` `if(/@$/.test(before)) showMentionPicker();`

教程原话：「素材库是**全局的**，不只属于某一个画布」「在智能画布中输入 `@` 选择素材库里的图片，
**不需要手动连线**，也能把图片作为参考输入」。

### ③ 循环节点 —— 批量的最小心智模型

「上游输入一个基础提示词，下方写多个变化项，**循环节点每运行一次就自动切换到第几个变化项**」。
智能画布里更进一步：「把循环节点拖到目标卡片附近，**会自动连接**」。

他播放量最高的视频（10.8万）整期在讲这个（批量生成卖点图）。

### ④ 附带：导入工作流后有内置测试区

「上传工作流 JSON → 识别参数 → **勾选要暴露的输入** → 调整顺序 → 内置测试区上传测试图 →
**运行测试** → 确认没问题再保存」。**Nomi 没有这个「保存前先跑一次」的闭环。**

## 4. 他踩的坑（Nomi 已走得更远）

### ① 硬编码模型清单 —— 每出新模型发一版

提交历史：`add Seedream 5.0 Pro&4.7 model` ×3、`Add 'seedance2.0mini' to video models list`、
`Add more video models to JIMENG_DEFAULT_VIDEO_MODELS`。

### ② 模型类型靠关键词猜 —— issue #190

社区自己诊断得很清楚：分类规则匹配 `veo/sora/video/i2v/t2v/seedance/kling`，
`MiniMax-H3` 不含任一关键词 → 落入默认 `chat_models` → 在模型选择器里显示为 LLM。
他的修法停在「再加几条关键词规则」。

**Nomi 对同一个病的诊断深一层**（`docs/plan/2026-08-11-model-kind-misguess.md`）：
猜错后模型不是报错而是**从下拉里消失**（三层过滤逐层拦掉：`modelCatalogCache.ts:116` →
`catalogTaskResolve.ts:144` → `types.ts:415`），且落库后**全 App 没有任何地方能改 kind**，
于是「猜错 = 永久错且不可发现」；同时设置页只看 `enabled && hasApiKey` 就显示绿色「已连接」
（`settingsAutomationView.ts:40`）—— **在撒谎**。

### ③ ComfyUI 只吃 API 格式

教程原话：「在 ComfyUI 中点击**导出 API 格式**工作流」。代码侧 `main.py:18242` 判
`class_type` + `inputs` 结构 = API 格式。

**Nomi 现状相同**，但 Nomi 已发现更大的缺口（`docs/feedback/2026-08-01-comfyui-demand-audit.md`）：
ComfyUI 自带 **493 个官方模板全是 UI 格式**，网上分享的也绝大多数是 UI 格式；且实测
「手写转换器只对 2/14，**用 ComfyUI 自己的前端转换 14/14 结构全对**」。

> **这是整个赛道的空白区 —— 他没做，Nomi 已经知道怎么做。**

## 6. 三方会师：一个判断

**需求侧**（N4/N6）：用户反复喊角色一致性，并具体提出「名字↔参考图自动绑定」。
**竞品侧**：他用「素材库 + `@` 引用」接这个需求 —— 是**交互层**的解法。
**学术侧**（今日雷达，已验证 arXiv 真实）：
- **EntityBench**（arXiv:2605.15199, 2026-05-14）：140 集 / 2491 镜头基准，核心发现
  **跨镜实体一致性随复现距离急剧衰减**；解法 EntityMem = **生成前建持久实体记忆库**（架构层）。
- **DirectorBench**（arXiv:2605.30090, 2026-05-28）：实测**转场质量均分仅 0.256**，
  最好的工作流也才 0.356 —— 是所有维度里最差的。

**三条独立证据落在同一点上。** 这不是「又一个可加的功能」，是这个赛道当前的真命门，
而 Nomi 的定位本来就压在这里。

## 7. 迭代方案（按「解决哪个真实摩擦」排，不按功能列）

### 优先级判断依据

用户决策逻辑 D1（从真实摩擦出发）+ D2（从结构约束出发，solo、广度是敌人）：
**凡是「他做了但只是交互糖」的，抄；凡是「他和所有人都没做、且 Nomi 有结构优势」的，做成招牌。**

### P0 — 把「接了模型用不了」彻底了结（他领先，Nomi 有欠账）

**摩擦**：用户接入模型后，模型从下拉里**消失**，全 App 无处可改，设置页还显示绿色「已连接」。
**为什么现在做**：这是 Nomi 自己 issue #4/#8/#9/#19/#23/#42/#62 同源主诉，
且竞品在这条上是完整闭环（填 Token → 验证 → 拉取 → **勾选** → 保存），差距是明确的。
**做什么**：按已拍板的 `2026-08-11-model-kind-misguess.md` 五屏样张做完 —— kind 落库后可改 +
改 kind 时同步重建调用通道（`draftShapeForKind` 那层，光改 kind 是假修）+ 设置页显示能力摘要
而非假绿灯。
**用户体验**：接完模型立刻能在对应节点看到它；万一分类错了，自己一个下拉就能改回来。

### P1 — 命名实体绑定：把 N6 做成 Nomi 的招牌（三方会师点）

**摩擦**（用户原话）：多张参考图喂进去，模型分不清谁是谁 → 张冠李戴；
用户想要的是「图片命名孙权/刘备/曹操，提示词写名字就自动对上」。
**为什么是 Nomi 做而不是抄他**：他的 `@` 引用是**交互糖**（把图塞进提示词），
解决不了跨镜衰减；EntityBench 指出真解法是**持久实体记忆库**，
而 Nomi 已经有项目库 + 画布 + 导演台三层结构可以挂载这个记忆。
**做什么**：项目级「角色档案」= 名字 + 若干参考图 + 生效范围；提示词里写名字即自动解析为该角色的
参考图集合；跨镜头复用同一档案。现有 `generationReferenceResolver.ts` 从「按连线解析」扩展为
「按连线 **或** 按命名实体解析」。
**用户体验**：建一次角色，全片所有镜头都认得他；第 20 个镜头的他还是第 1 个镜头的他。
**配套**：按 EntityBench 三支柱给 `evals/lib/vbenchRubric.mjs` 补「跨镜实体连续性」维度 ——
否则做完了也不知道有没有变好。

### P2 — ComfyUI UI 格式 + 官方 493 模板（赛道空白区）

**摩擦**：用户手上的工作流绝大多数是 UI 格式（ComfyUI 默认保存/分享就是这个），
导进来连不上；而装了 ComfyUI 就自带 493 个官方模板，里面有「Storyboard To Video」
「LTX 图生视频」「参考图控一致性」这些正好是 Nomi 主线的场景，现在一个都没露出。
**为什么现在做**：竞品和所有人都只吃 API 格式，Nomi 已实测出可行路径
（用 ComfyUI 自己的前端转换 14/14 全对）。这是**结构上对手抄不动**的差异化（D2）。
**用户体验**：从 ComfyUI 随手存的工作流直接拖进来就能用；打开就有一排官方模板可选。

### P3 — 抄他两个轻量交互（低成本高回报）

1. **导入工作流后的「保存前先跑一次」测试区** —— 他有，Nomi 没有。Nomi 的缺件对账更强，
   但缺「跑通了我才敢存」这个确定感。
2. **循环节点式批量心智** —— 「一个基础提示词 + 一列变化项」比配置面板轻得多，
   且拖到目标附近自动吸附连接。

### 不做（明确砍掉，D4）

- **不做一键整合包/自带 Python 那套** —— Nomi 是 Electron 应用，安装包本身就是答案，
  这是结构性领先，不需要跟进他的形态。
- **不做 LoRA 训练 / 数据集制作** —— 他的另一半内容在这里，但那是「广度」，
  对 solo 是敌人（D2），且与 Nomi 主线（成片）无关。
- **不追模型横评** —— 他大量视频是模型测评，那是内容生意不是产品能力。
