# Nomi 论文雷达（2026-08-24）

本轮最该动的两件事：

1. 把“实体状态记忆 + 生成前 fidelity gate”落成 Nomi 现有角色/场景/道具卡与 storyboard 编译合同；这比继续堆更长的 prompt 更能解决跨镜漂移。
2. 把镜间连续性拆成“背景/空间关系”和“角色/道具状态”两条可审计轴，先在 6 镜回归集上量化，不把整片质量压成一个 VLM 总分。

## 🟢 可落地

### EntityBench：持久化实体记忆 + 三柱评测

- 论文：[arXiv:2605.15199](https://arxiv.org/abs/2605.15199)（2026-05-14）；代码与数据：[GitHub](https://github.com/Catherine-R-He/EntityBench)（本次检查为 12 stars，公开 140 episodes / 2,491 shots）。
- 洞察：跨镜一致性会随着实体再次出现的间隔明显下降；“先把每个实体的已验证参考存进 memory bank，再生成”比只依赖长 prompt 更稳。评测把镜内质量、prompt 遵从、跨镜实体一致性拆开，并在一致性计分前先过实体 fidelity gate。
- 落点：接到 `src/workbench/creation/storyboard/` 的 anchor/state 合同和 `electron/capabilityCore/shotVerify*`；先做轻量 `entityId + assetVersion + stateId + allowedChanges`，再把 fidelity gate 结果写入 shot 生成记录。无需引入论文模型或训练。

## 🟡 架构教训

### InfinityStory：背景一致性与多主体转场必须分开建模

- 论文：[arXiv:2603.03646](https://arxiv.org/abs/2603.03646)（2026-03-04）。
- 洞察：长叙事不只是角色脸一致，还要维持背景、空间关系和多主体进出画面的转场；论文把 world consistency 与 character-aware transition 作为不同模块，报告 VBench 背景一致性 88.94、主体一致性 82.11（这些是论文内部实验值，不等于 Nomi 现状）。
- 对 Nomi 的决策：`ff/lf/motion` 之外，shot checkpoint 还应记录“空间拓扑/在场主体/交接动作”。下一镜不能只重新引用角色卡；要明确继承上一镜尾状态，或明确声明这是新场景。

### Gloria：多参考图的职责要结构化，而不是把图堆进输入槽

- 论文：[arXiv:2603.29931](https://arxiv.org/abs/2603.29931)（2026-03-31）。
- 洞察：内容锚点需要区分多张参考的相对位置和职责，避免多参考冲突与 copy-paste；论文通过 compact anchor set 与位置编码保持跨视角身份。
- 对 Nomi 的决策：继续沿用“角色卡锁身份、场景卡锁空间、上一镜尾帧锁状态”的职责分离；不要因为供应商支持更多参考图，就把一组无标签的图片直接塞进通用 `references`。

## 🔵 对标基准

- EntityBench 的 140 episodes / 2,491 shots 与 easy/medium/hard 分层，可缩成 Nomi 的首个 6 镜内部回归集：角色重现、道具状态、场景重返、换装、多人进出、长间隔复现。
- 评测维度先固定为：`entity_fidelity`、`prompt_alignment`、`background_continuity`、`shot_transition`；每一项记录观察证据与修复动作，不用单一“好不好看”分数替代。

## 本轮筛掉的噪音

8 个固定方向均做了定向检索。相机轨迹、唇形同步、局部编辑和 prompt 优化本轮没有发现同时满足“近 6 个月 + 可直接接入 Nomi 的 vendor/API 层 + 有可复现实现”的新增条目；较老的 VPO、RAPO++、VABench 沿用既有结论，不重复收录。

## 上轮 vs 本轮 diff

- 新增：EntityBench 的公开代码/数据可直接作为 Nomi 评测设计参照；InfinityStory 把背景连续性和多主体转场拆成独立问题；Gloria 强化了多参考职责与锚点位置的观点。
- 不变：Nomi 的首要工程顺序仍是“字段不丢 → 状态可继承 → 校验真接线 → 再扩模型能力”。
