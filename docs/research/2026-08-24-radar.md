# Nomi 论文雷达：2026-08-24

一句话：Video Agent 的通用价值不在“让一个 Agent 替用户点完所有按钮”，而在于把叙事拆解、实体记忆、镜头执行和质量反馈接成可暂停、可回滚、可验证的长流程。

本轮最该动的两件事：

1. 把 ProductionRun 的单镜头 owner 继续向“实体记忆 + 多镜头计划”扩展，但保持每一步可人工确认、可回滚；
2. 为 Video Agent 建立跨镜实体一致性、镜头顺序/转场、prompt 对齐和可见交付四类评测，而不是只看最终视频总分。

## 🟢 可落地

### EntityBench：长距离跨镜实体一致性

- 日期：2026-05-14
- 来源：[论文](https://arxiv.org/abs/2605.15199)、[代码与数据](https://github.com/Catherine-R-He/EntityBench/)
- 洞察：实体跨镜重复出现时，随着间隔增加，一致性明显下降；显式 per-entity memory 对角色 fidelity 和 presence 最有效。
- 落到 Nomi：Video Agent 不能只保留一段长 prompt；应把角色、道具、场景变成可验证的实体记忆，并在每个 Shot 的 contract 中记录引用的实体版本。落点是现有 ProductionRun/Asset/ExecutionContract 的多镜头扩展，不是新建第二套 Canvas 状态。

### VideoMemory：记忆应在镜头前检索、镜头后更新

- 日期：2026-01-07
- 来源：[论文](https://arxiv.org/abs/2601.03655)
- 洞察：结构化脚本先由 planner 拆成镜头，生成前检索实体表示，生成后更新 memory bank，才能支撑远距离再出现。
- 落到 Nomi：把“参考素材选择”做成 Agent 的可解释动作：它要告诉用户“本镜头引用了哪些角色/场景/道具版本”，生成后再由质量检查决定是否更新实体记忆。不能让 Agent 静默覆盖全局资产。

## 🟡 架构教训

### InfinityStory：长叙事的瓶颈是场景转场和多主体关系

- 日期：2026-03-04
- 来源：[论文](https://arxiv.org/abs/2603.03646)
- 洞察：长片不是把很多独立短片串起来；背景一致性、主体出入场和 shot-to-shot transition 是独立问题。
- 影响 Nomi：P4 不能只做“批量 submit N 个镜头”。需要 transition intent、前后镜证据和可回滚的 adopt gate；Timeline 只能是项目事实的投影，不应变成 Agent 的第二真相。

### TempAct：planner 和 executor 是不同职责

- 日期：2026-06-26
- 来源：[论文](https://arxiv.org/abs/2606.28016)
- 洞察：全局计划与分段执行的反馈目标不同；单一 prompt 或盲目按步切 prompt 会导致延迟响应、语义混合和错误传播。
- 影响 Nomi：Video Agent 应拆成“意图/镜头规划”和“Runtime 执行”两层。Planner 可以提出候选和风险，executor 只执行冻结合同；不能让 LLM 在 provider 已接受后继续改合同。

## 🔵 对标基准

### TOC-Bench：时间对象一致性

- 日期：2026-05-11
- 来源：[论文](https://arxiv.org/abs/2605.09904)
- 怎么接：为多镜头任务增加 object identity、状态变化、遮挡后再出现、事件顺序和 hallucination-aware verification 维度；把每个维度映射到“通过/失败/下一步建议”。

### TC-Bench：时间组合性

- 日期：2024-06-12（基准仍适合做机制级回归）
- 来源：[论文](https://arxiv.org/abs/2406.08656)
- 怎么接：用首态→终态、对象关系和动作顺序测试模式选择与 prompt rewrite，验证 Agent 是否真的理解“先做什么、再发生什么”，而不是只生成一段看起来像的运动。
