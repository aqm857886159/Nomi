# Nomi Research Radar — 2026-08-12

## 一句话结论

本轮最强信号：**FilmBench（2607.24241）把电影语言拆成 35 个可量化子维度并开源评测算子**，是现成考卷直接接入 Nomi eval；以及 **CoTriSyGen 的闭环「违规检测→即时重生成」**，给 Nomi 的镜间闭环补上了对称的证据。GroundShot / ViMax / CausalCine 等上轮已录入，本轮标状态不重复正文。

**本轮最该动的 1-2 件事**：
1. 把 FilmOps 接进 `evals/` 评测链路：用它的「多镜衔接」与「动态美学」算子给 Nomi 生成管线打分——现成开源代码 + 人工验证 Spearman ρ=0.95，比现有 VLM judge 鲁棒。
2. 在 `shotVerifyRunner.ts` 的镜后校验里加「语义违规 → 当镜重生成 + 下一镜 prompt 改写」的闭环：CoTriSyGen 在 StoryBench 上实测有效，机制直接可迁；目前 Nomi 只有校验，没有自动修复回路。

## 🟢 可落地

### FilmBench + FilmOps — 电影级生成质量评测套件

- [arXiv:2607.24241](https://arxiv.org/abs/2607.24241) · 2026-07-29
- **方法**：由北京电影学院与弘景影视联合开发，1,169 条 prompt 反向工程自获奖影片（其中 1,056 条为多镜）。评测体系三层：3 轴 × 12 组件 × 35 个 T2V 子指标（含 3 个 R2V 专属）；同时评测了 9 个 T2V 模型和 7 个 R2V 模型。核心算子套件 **FilmOps 已开源**（含训练权重 + 推理脚本）。
- **火度**：院校 + 行业联合、公开评测多个 SOTA 模型、人工验证 Spearman ρ=0.95/0.96——benchmark 公信力高，近期有持续社区关注。
- **Nomi 落点**：`evals/verify-shot-smoke.mjs` 目前跑冒烟验证；可把 FilmOps 的「多镜衔接连贯性」与「动态美学」两个算子直接插进 `shotVerifyJudge.ts` 的质量门，替代现有 ad-hoc VLM 评分——既有可解释维度（不再是黑盒分数）又有人工锚点背书（防 08-11 雷达 V2V-Bench 揭示的 VLM 抱团跑偏）。**开源代码可核实，优先级高**。

### GroupVideo — 多角色同帧身份定制视频

- [arXiv:2607.21027](https://arxiv.org/abs/2607.21027) · 2026-07-23
- **方法**：基于 Video DiT，用「多模态身份对齐（视觉+语义）+ ID 定位模块（bounding box + mask 正则化）」实现多角色同时出镜且各自保持独立身份，配套构建了 20,000 条多身份视频数据集。
- **Nomi 落点**：目前 Nomi 的 `referenceSlots.ts` + `generationReferenceResolver.ts` 支持把参考图注入生成参数，但只处理单角色场景。GroupVideo 的「ID 定位 + 空间 mask 分区」机制是多角色参考注入的方法论参考——设计卡片里"群像镜头"场景可参考此思路。因需专用训练数据（非 training-free），**落点为设计参考而非代码直接复用**；注意这一点。

## 🟡 架构教训

### CoTriSyGen — 闭环三元协同长视频生成

- [arXiv:2606.16184](https://arxiv.org/abs/2606.16184) · 2026-06-15
- **洞察**：把多镜生成定义为「计划意图 + 持久记忆 + 生成视觉」三元闭环：每镜生成后检测语义违规（角色、道具、场景），违规则在镜内重生成、同时改写后续镜头 prompt；以实体为中心的记忆追踪跨镜状态。在 StoryBench 上超过前向 baseline。
- **对 Nomi 的影响**：`shotVerifyRunner.ts` 现在跑 VLM 校验，但结果只用于「报警/标记」，**没有自动回路**触发重生成或改写后续 prompt。CoTriSyGen 的「违规→即时修复→下镜改写」三步形成完整闭环——这正是 08-11 雷达「接力锚定」原则在校验层的对称实现，两条证据线现在汇合。

### QWERTY — Training-Free 运镜控制（ECCV 2026）

- [arXiv:2607.01869](https://arxiv.org/abs/2607.01869) · 2026-07-02 · ECCV 2026
- **洞察**：通过在 3D attention 机制上「翻转查询的帧不变语义子空间」实现运镜控制，不需要任何微调——效果对标有监督方法。用户只需提供光流或 object warping 路径。
- **对 Nomi 的影响**：`useScene3DTrajectoryEditing.ts` 目前管理相机轨迹的 3D 交互，但生成侧还依赖模型自身支持运镜参数（如 Seedance cameramovements 字段）。QWERTY 的 training-free 机制若有开源代码，可作为「不支持原生运镜参数的模型」的通用 wrapper——**现代 ImageToVideo DiT 通用，符合 P4 解耦原则**。待核实：代码是否公开（arxiv 页面未给出 GitHub 链接；ECCV 2026 论文通常会在 camera-ready 后开源）。

### Camera Artist — 多 Agent 电影化语言注入

- [arXiv:2604.09195](https://arxiv.org/abs/2604.09195) · 2026-04-10
- **洞察**：引入专门的「摄影分镜 Agent」执行两件事：① 递归 storyboard 生成（确保相邻镜连续性）；② 电影语言注入（产出景别/运镜等电影描述符）。在叙事连贯性、动态表现力、感知影片质量上超过 baseline。
- **对 Nomi 的影响**：`runStoryboardPlanner.ts` 里的镜头规划当前产出「动作描述」，但缺少电影语言标注（镜别/机位/运动）。Camera Artist 的「电影语言 → prompt 注入」路径说明这层标注可由 LLM Agent 自动完成，不需要用户手工填写——与 VERTIGO（08-09 之前雷达）组成同一条线：**自动电影语言化是下一步**。

## 🔵 对标基准

### EntityBench — 实体一致性跨镜基准（已有代码）

- [arXiv:2605.15199](https://arxiv.org/abs/2605.15199) · 2026-05-14 · [GitHub](https://github.com/Catherine-R-He/EntityBench/)
- **本轮新增**：GitHub 仓库已确认可访问（CC-BY-SA 4.0），配套 EntityMem baseline 在最难 tier（50 镜 / 13 角色 / 48 镜复现间隔）上 Cohen's d=+2.33 领先。**上轮已列入 🔵，本轮确认代码可直接取用**。
- **接入 eval**：`shotVerifyJudge.ts` 的角色一致性评分可用 EntityBench 的分层 rubric（easy/medium/hard 按复现间隔分级）替代现有单一 VLM prompt；将「最难 tier」跑通作为 Nomi 的 spike 测试。

### DirectorBench — 长视频工作流诊断基准

- [arXiv:2605.30090](https://arxiv.org/abs/2605.30090) · 2026-05-28
- **本轮补充数据**：转场质量跨 4 个工作流平均仅 0.256，最优 0.356——这是整个行业在「转场」上的得分上限参考，Nomi 目前未量化此指标。
- **接入 eval**：「转场质量 0-1 分」可作为 Nomi eval 体系里的新维度，沿用 DirectorBench 的评测逻辑（无需完整跑其全套）；把「0.356」作为当前行业 SOTA 基准线写进 `evals/` 注释。
