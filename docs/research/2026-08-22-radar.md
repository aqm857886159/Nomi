# Nomi 研究雷达 · 2026-08-22

本轮最该动的两件事：

1. 把多镜生成的“实体记忆 + 镜间承接”从 Prompt 习惯升级为 `PromptSpec/AssetRegistry/ExecutionSnapshot` 的硬合同。
2. 把视频验收从“文件存在”升级为时间定位的视觉、音频和编辑质量证据。

## 🟢 可落地

- [EntityBench](https://arxiv.org/abs/2605.15199)（2026-05-14）：长距离多镜实体一致性会随递归距离快速下降，显式 per-entity memory 最有效。落地：`AssetRegistry` 增加 identity/scene/prop state snapshot；每个 shot job 固化引用版本，不只传一段角色描述。
- [VEBench](https://arxiv.org/abs/2605.03276)（2026-05-05）：把真实视频编辑拆成编辑理解和操作推理，并提供时间标注 QA。落地：为 `EditorCommand` 增加 affected range/semantic intent，J5 用时间区间级对抗测试，不只检查 MP4 存在。
- [VABench](https://openaccess.thecvf.com/content/CVPR2026/html/Hua_VABench_A_Comprehensive_Benchmark_for_Audio-Video_Generation_CVPR_2026_paper.html)（2026-06）：同时评估文本-视频、文本-音频、音画同步、唇形一致性。落地：音频 Skill 与视频 Skill 分开，`audioPolicy` 在 Preflight 明示 native/separate/none，并用 waveform/同步检查验收。

## 🟡 架构教训

- [InfinityStory](https://arxiv.org/abs/2603.03646)（2026-03-04）和 [ShotStream](https://arxiv.org/abs/2603.25746)（2026-03-26）：全局上下文记忆与局部镜头缓存是不同层；连续镜头不能只靠把上一条 prompt 拼进下一条。影响：Nomi 将 `global identity/style memory` 与 `local previous-tail/first-frame` 分开建模。
- [Prompt-Adapter Context Routing](https://arxiv.org/abs/2607.06481)（2026-07-07）：按叙事依赖路由实体、地点、动作和风格 prompt，而不是每镜全量复制。影响：`PromptSpec` 按 reference role/shot dependency 选择字段，降低上下文污染和成本。

## 🔵 对标基准

- [LongVQUBench](https://arxiv.org/abs/2607.01086)（2026-07-01）：长视频质量理解基准。接入：抽帧 contact sheet + 时间区间问题，测试 VLM 是否能定位中后段连续性/字幕/转场问题。
- [Spotlight](https://spotlight-video.github.io/)（2026）：时间定位的生成视频错误分类与标注。接入：QA finding 必须带 `startFrame/endFrame/category/evidenceFrame`，重试只针对受影响片段。
- [MEDit-Bench](https://www.alphaxiv.org/abs/2607.25300)（2026-07-28）：消息驱动剪辑评测显示同一原片不同编辑指令会产生不同切点。接入：J5/J6 记录 instruction→EditCommand→timeline diff，评估区间 F1/任务遵从，而非只看视觉质量。

本轮未纳入的论文/摘要：缺少可复现代码、只提升单镜画质、或与 Nomi 运行时无直接映射的工作。
