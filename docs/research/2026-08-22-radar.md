# Nomi 论文雷达 · 2026-08-22

本轮最该动的两件事：把跨镜实体一致性从“审片时凭感觉”收敛成可量化门槛；把已有的 Prompt Optimizer 继续演成“检索 → 改写 → 多候选排序”的闭环。前者直接对应 Nomi 当前的 shotVerify / agentic production，后者能在不重训视频模型的前提下改善用户输入糙导致的成片波动。

## 🟢 可落地

### Retrieval, Refinement, and Ranking for Text-to-Video Generation via Prompt Optimization and Test-Time Scaling

- 论文：[arXiv:2603.01509](https://arxiv.org/abs/2603.01509) · 日期：2026-03-02
- 洞察：3R 用 RAG 找 modifier，再改写 prompt，并用多候选与时序一致性策略提升 T2V；核心价值是可跨模型、无需训练基础模型。
- 落地：接到 `src/workbench/generationCanvas/nodes/NodePromptOptimizer.tsx` 及现有 prompt 库，先做“召回相关镜头语言/动作词 → 生成 2–3 个候选 → 用户或轻量判分选一个”的最小闭环；不要先引入论文里的训练环节。

## 🟡 架构教训

### Gloria: Consistent Character Video Generation via Content Anchors

- 论文：[arXiv:2603.29931](https://arxiv.org/abs/2603.29931) · 项目页：[Gloria](https://yyvhang.github.io/Gloria_Page/) · 日期：2026-03-31
- 洞察：角色一致性不是不断堆最近一帧，而是用全局、视角、表情等结构化 anchor 覆盖角色的视觉空间；多参考图还要解决复制粘贴和参考冲突。
- 教训：Nomi 的定妆卡/anchor bible 应继续保留“静态身份锚”和“镜头动态锚”的分层，生成每镜前先明确取哪类锚；不要把所有参考图混成一个无语义图片数组。对应 `src/workbench/generationCanvas/model/anchorBibleKeys.ts` 与 MCP 的冻结门。

### InfinityStory: Unlimited Video Generation with World Consistency and Character-Aware Shot Transitions

- 论文：[arXiv:2603.03646](https://arxiv.org/abs/2603.03646) · 日期：2026-03-04
- 洞察：长叙事的难点同时在背景连续、多主体进出场和镜间过渡，不能只优化单镜质量；跨镜状态需要被显式保留。
- 教训：production playbook 需要把“镜头结束状态 → 下一镜输入”当作一等数据，而不是只把视频文件串起来。现有 `electron/productionRun/` 与 `shotVerify` 应优先记录可复核的尾帧/实体状态。

## 🔵 对标基准

### EntityBench: Towards Entity-Consistent Long-Range Multi-Shot Video Generation

- 论文：[arXiv:2605.15199](https://arxiv.org/abs/2605.15199) · 代码：[EntityBench](https://github.com/Catherine-R-He/EntityBench) · 日期：2026-05-14
- 洞察：它把单镜质量、prompt 对齐、跨镜实体一致性拆开评估，并覆盖最长 50 镜、实体重现间隔最长 48 镜；一致性会随 recurrence distance 明显下降。
- 接法：把 Nomi 的 `electron/capabilityCore/shotVerifyCore.ts` / `src/workbench/generationCanvas/agent/shotVerify.ts` 结果拆成“镜内质量、指令对齐、跨镜角色/道具/场景一致性”三列，先用小型 Nomi 任务集复现指标口径，再考虑接入公开 benchmark。

## 本轮筛掉

筛掉 4 篇：过时的通用 T2V benchmark、需要大规模重训且没有可复用实现的模型论文、与 Nomi 当前痛点无直接关系的音频/编辑论文。

## 上轮 vs 本轮 diff

- 新出现：跨镜实体一致性已经有更明确的 benchmark 口径；prompt 优化开始从单次改写走向检索与 test-time 排序。
- 持续有效：Nomi 当前的“定妆锚 → 分镜 → 逐镜生成 → 审片”链路方向是对的，下一步重点是把实体状态和评测结果结构化，而不是再堆一个独立生成入口。
