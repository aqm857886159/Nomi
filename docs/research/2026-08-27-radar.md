# Nomi 论文雷达 · 2026-08-27

本轮没有达到“本周可直接接入”的新论文。最该动的仍是两件事：把跨镜角色/场景锚点做成可追踪实体记忆；给多镜真实任务补“隔很久再次出现”的一致性评测，而不是只看相邻镜头。

## 🟢 可落地

本轮 0 篇。检索到的近期方法要么需要训练专用视频模型，要么尚未发现可直接复用的官方实现，不冒充可接能力。

## 🟡 架构教训

### Gloria: Consistent Character Video Generation via Content Anchors

- [arXiv:2603.29931](https://arxiv.org/abs/2603.29931) · 2026-03-31；CVPR 2026 论文与项目页已公开，本轮未发现官方代码仓。
- 教训：单张角色参考图不够；方法把全局、视角和表情锚点分开，并显式处理多参考互相冲突与复制粘贴伪影。
- 影响 Nomi：角色设定卡应保存“锚点角色 + 锚点用途”，参考槽需要稳定身份和角色说明，不能只传一个无语义顺序的 URL 数组。落点优先核对 `src/workbench/generationCanvas/model/parameterReferenceIdentity.ts` 与角色/场景设定卡投影。

### InfinityStory: Unlimited Video Generation with World Consistency and Character-Aware Shot Transitions

- [arXiv:2603.03646](https://arxiv.org/abs/2603.03646) · 2026-03-04；本轮未确认作者官方代码，搜索到的同名第三方仓不能当实现依据。
- 教训：背景世界状态、角色身份和镜间出入画是同一条连续性问题；只保存人物脸部参考会让场景关系在跨镜时漂移。
- 影响 Nomi：生产 Run 的跨镜状态应同时携带 entity / location / transition boundary，避免把世界一致性降成每镜独立 prompt。

## 🔵 对标基准

### EntityBench: Towards Entity-Consistent Long-Range Multi-Shot Video Generation

- [arXiv:2605.15199](https://arxiv.org/abs/2605.15199) · 2026-05-14；论文声明[官方代码与数据](https://github.com/Catherine-R-He/EntityBench/)已公开。
- 接法：从其 recurrence gap 分层借一组最小真实任务，覆盖角色、道具、地点在间隔 1 / 8 / 24 镜后再次出现；接入现有 `electron/capabilityCore/shotVerifyOrchestrate.ts` 时先加 fidelity gate，实体没按 prompt 出现就不计算“长得像不像”。

### EduVQA: Benchmarking AI-Generated Video Quality Assessment for Education

- [arXiv:2603.03066](https://arxiv.org/abs/2603.03066) · 2026-03-03；论文写明代码将公开，但本轮未找到可验证的官方代码仓。
- 接法：只借其“空间质量 / 时间质量 / 词级与句级 prompt 对齐分开计分”的结构，不采用教育领域数据；作为现有宽泛总分的解释性补充，未开源前不进入自动门岗。

## 上轮 vs 本轮

- 新增：Gloria 的多锚点角色表示值得写入角色参考契约设计；明确标成架构教训，不声称可直接接入。
- 延续：EntityBench 仍是跨镜实体一致性最贴 Nomi 的可执行基准。
- 降级：没有把搜索命中的旧 benchmark 或未找到官方实现的项目列成“可落地”。本轮筛掉 11 条过期、同名误命中或纯模型画质增量噪音。
