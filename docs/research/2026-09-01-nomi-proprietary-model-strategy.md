# Nomi 专有模型与用户数据战略底稿

日期：2026-09-01  
状态：研究稿，供产品方向确认；不代表已经开启遥测、收集用户内容、训练模型或对外承诺。  
证据标记：**观察** = 一手资料或当前代码可核对；**推断** = 根据观察做出的判断；**建议** = Nomi 的待确认方案。

## 一句话结论

Nomi **可以**和用户商量，建立一个“自愿贡献、默认不出机”的数据飞轮；但现在不应该把目标写成“训练一个更大的 Nomi 通用大模型”。更有胜算的目标是：训练一组懂 Nomi 的窄任务模型——能把自然语言变成可编辑的生产合同，知道哪个模型/供应商真的可用，能诊断并修复失败，能判断跨镜连续性和成本质量，并且始终服从 Nomi 的确认、预算和隐私边界。

这条路线既能保留“本地优先”的信任，又能把真实使用产生的高价值反馈变成护城河。原始对话和原始素材不是第一优先级；**用户改了什么、接受了什么、为什么失败、修复是否成功、最终是否完成作品**，才是最值钱的数据。

## 1. 先把三个问题分开

### 1.1 Nomi 现在是什么

**观察：** 当前 Agent 已经是 pi SDK `0.84.3`，而不是旧方案里的 `runAgentChatV2`；对话仍分为 `creation` 和 `generation` 两个 area，历史分别持久化。对话消息保存在每个项目的 `.nomi/conversations.json`，最多保留 30 个 thread、每个 thread 200 条消息（`electron/conversations/conversationsStore.ts:3-28`）。

**观察：** Nomi 已有本地事件日志，按项目写入 `.nomi/events/log-<seg>.jsonl`；事件最大约 4KB，超大字段截断，写入前做密钥/鉴权信息脱敏，而且日志是旁路观察，I/O 失败不打断产品（`electron/events/eventLogRepository.ts:1-9,18-36`）。

**观察：** Agent 轨迹目前只记录 prompt 头、工具提议及参数、工具结果头、最终文本头、哈希、usage 和 finish reason；增量文本不入日志（`electron/events/agentChatTrace.ts:8-9,33-53,55-116`）。这是一份本地评估轨迹，不是可直接远传的训练集。

**观察：** Agent 请求本身可以包含 prompt、历史、项目、system prompt、模型/供应商、温度和附件；附件可能是图片、PDF 或抽取后的文档文本（`electron/harness/agentChatContracts.ts:15-38`；`electron/ai/agentUserContent.ts:49-99`）。因此“Agent 对话”实际可能包含故事 IP、未公开素材、第三方个人信息、商业秘密、肖像/声音和版权内容。

**观察：** 匿名图传是另一条数据流。当前设置明确提示：公共临时托管可能“任何人可访问”、有有效期和网络失败风险；未配置 KIE 时会在回退前询问（`src/i18n/locales/settings.ts:196-218`；`electron/settings/automationPolicyContract.ts:22-45`）。

**推断：** “为了让模型能读取素材而上传”不等于“允许 Nomi 把素材用于训练”。这两个同意必须拆开；公共图床的同意更不可能自动推导出训练许可。

### 1.2 我们想解决的到底是什么

| 目标 | 真正需要的数据 | 是否值得现在做 |
|---|---|---|
| 让 Agent 更会理解意图 | 输入摘要、结构化计划、用户采纳/修改差异 | 值得，先做文本/结构化任务 |
| 让模型接入少出错 | 供应商、模型、能力声明、参数、错误码、修复动作、最终结果 | 最值得，和当前痛点直接相连 |
| 让上传失败更少 | 文件类型/大小/目标供应商/网络阶段/错误类别/回退选择 | 值得，先收结构化错误，不收素材本身 |
| 让跨镜一致性更好 | 参考图、镜头关系、用户选择/拒绝、连续性评分 | 值得，但素材应晚于文本 pilot，单独同意 |
| 训练一个通用聊天底模 | 大规模、合法、稳定、去重后的通用语料和巨量算力 | 现阶段不值得 |

### 1.3 目标不是“拥有一个模型文件”

**推断：** Nomi 的专有智能应当是一个可替换的系统，而不是一个孤立的 checkpoint：

`Nomi 状态与工具合同 → 任务模型 → 评估/反馈 → 版本化发布`

模型只是其中一环。真正难抄的是 Nomi 的生产合同、供应商能力账本、可恢复执行、成本/质量反馈和连续性评估集。

## 2. 行业证据：谁真正靠什么赢

### 2.1 Cursor：任务层、harness、评估和环境 RL

**观察：** Cursor 的 Composer 公开技术报告描述了两阶段路线：以 Kimi K2.5 等开源基座做继续预训练，再在贴近真实 Cursor 的工具环境中做大规模强化学习；训练和评估都使用同一类生产工具/harness，CursorBench 来自真实工程请求和人工整理的最优解。报告还描述了跨区域异步 RL、数十万沙盒环境和专用低精度基础设施。[Composer 2 技术报告](https://cursor.com/blog/composer-2-technical-report)

**观察：** Cursor 的早期 Composer 文章明确说，模型被训练为使用读写文件、终端和语义搜索等工具，并奖励高效工具调用、并行化、证据化沟通和真实测试结果。[Composer 文章](https://prod.cursor.com/blog/composer)

**观察：** Cursor 的隐私政策把 Privacy Mode 与训练数据明确分开：开启时客户数据不用于 Cursor 训练；关闭时，代码库、prompt、编辑动作和代码片段才可能用于改进和训练。[Cursor Data Use](https://cursor.com/data-use)

**推断：** Cursor 的可积累资产不是“所有用户原始聊天”，而是“问题 → 工具行动 → 可验证结果”的轨迹，以及围绕轨迹建立的评估和奖励机制。它也证明了：真实用户数据飞轮必须服从隐私选择，不是默认权利。

### 2.2 LiblibAI / LibTV：聚合、工作流、Agent 分发

**观察：** LiblibAI 的公开 2.0 材料把产品描述为多模态平台，将模型训练、图像、视频、灵感和 AI 应用打通，并聚合多家模型；没有公开证据表明它靠自训通用视频底模作为主要优势。[LiblibAI 2.0](https://www.liblib.art/teaching/532c1bc80ae84530ac235ba8324a5d9c)

**观察：** LibTV 的官方 Skill/OpenAPI 资料强调“人类创作者 + Agent”双入口：自然语言请求由后端选择模型、编排工作流并返回结果，同时支持多个外部模型。[LibTV Skill](https://raw.githubusercontent.com/libtv-labs/libtv-skills/main/skills/libtv-skill/SKILL.md)

**推断：** 对 Nomi 真正有参考价值的是“自然语言 → 工作流 → 结果回写”和模型分发，不是复制一个没有边界的模型大厅。LibTV 是否训练自有视频底模、训练集规模和 ROI，公开材料无法证实，不能当事实写。

### 2.3 其他可借鉴点

- Runway 的 Gen-4 把跨镜角色/物体/地点一致性做成模型与交互能力，并强调不需要用户为每个角色重新 fine-tune；这支持 Nomi 把“视觉锚点 + 连续性判断”做成通用任务层，而不是要求每个用户训练个人模型。[Runway Gen-4](https://runway.com/research/introducing-runway-gen-4)
- Replit 公开的路线是平台上下文定制、较小模型和智能路由来降低成本与供应商依赖；这比从零训练通用底模更接近 Nomi 的资源约束。[Replit LLM training](https://replit.com/blog/llm-training)、[Intelligent model routing](https://replit.com/blog/intelligent-model-routing)
- ComfyUI 的耐久性来自可保存的 JSON 工作流、插件/模型可替换和本地离线执行；这与 Nomi 的“生产合同 + 可恢复执行”方向相容。[ComfyUI README](https://raw.githubusercontent.com/comfyanonymous/ComfyUI/master/README.md)

## 3. Nomi 应该收集什么：按价值而不是按“越多越好”

### 3.1 S 级：结果和改动信号

这些数据最接近“什么真的有用”，而且可以在不收原文/原素材的情况下收集：

1. **提议合同 → 用户动作**：接受、拒绝、编辑了哪些字段、编辑前后差异。
2. **模型/供应商 → 结果**：能力、模式、参数桶、成功/失败、重试次数、延迟桶、成本桶。
3. **错误 → 修复**：错误阶段、稳定错误码、候选修复、修复后是否成功；例如空 `size`、不支持的输入模态、公共图床超时、模型能力声明不匹配。
4. **生产闭环**：是否完成分镜、生成、QA、组装、导出；返工发生在哪个阶段；用户最后采用哪一版。
5. **连续性判断**：用户是否认为人物、场景、道具、风格在镜头间保持一致；可先用低/中/高或接受/拒绝标签，不要求上传视频。

这些可以形成偏好对、分类样本、排序样本和 repair 样本。它们比单纯聊天文本更容易脱敏、更容易评估，也更接近 Nomi 的产品差异。

### 3.2 A 级：低敏技术遥测

可选字段：应用版本、OS 家族、locale、能力/功能名、错误类别、成功率、次数、时长/成本区间、粗粒度模型/供应商类别、随机轮换安装 ID。不要收绝对路径、密钥、URL 查询参数、完整 prompt、完整输出或原始素材。

### 3.3 B 级：对话样本

对话文本包含最丰富的语义，也包含最大的隐私、版权和商业秘密风险。若将来收集，应当：

- 只允许用户主动选择“一条消息/一个样本”，不自动上传整段历史；
- 默认文本，不带附件；
- 先在本机展示脱敏预览，用户可编辑后再发送；
- 单独选择用途：“改进 Nomi 体验”与“训练未来模型”不能合并；
- 记录样本级撤回和删除凭证；
- 经过人工或规则审核后才进训练集。

### 3.4 C 级：图片、视频、音频和文档

先排除出最小 pilot。素材可能包含脸、声音、生物特征、EXIF/地理位置、未公开作品、商业秘密和第三方版权。即使用户有上传权，也不一定有把其中所有人的信息拿来训练的权利。任何素材贡献都必须是一次一意的、目的明确的、带目标区域和保存期限的单独流程。

## 4. Nomi 的专有模型应该训练什么

| 模型/能力 | 输入 | 输出 | 为什么是 Nomi 的差异 | 第一版形态 |
|---|---|---|---|---|
| Intent → Production Contract | 自然语言 + 当前项目状态 | `StoryboardPlan` / `EditPlan` / 约束字段 | 把模糊表达变成可编辑、可回滚的制作对象 | 结构化生成 + schema 校验 |
| Provider Capability Router | 任务、能力、模型目录、历史结果 | 供应商/模型/模式/参数建议 | 不猜模型；依据已认证能力和成本选择 | 分类器/排序器 + 规则护栏 |
| Failure Diagnosis & Repair | 错误码、阶段、请求摘要、环境 | 根因分类、修复动作、是否需人确认 | 直接解决“模型接入容易出问题” | 小模型分类 + 检索/模板 |
| Prompt/Recipe Compiler | 镜头意图、视觉锚点、目标模型声明 | 模型无关语义 + 供应商适配参数 | 让一次创作意图跨模型稳定迁移 | 结构化编译器，先不训练 |
| Continuity Judge | 参考图、镜头摘要、生成结果的视觉特征 | 一致性标签/差异原因 | 对视频创作最贴近真实价值 | 视觉语言模型打分 + 人工校准 |
| Cost/Quality Selector | 目标质量、预算、延迟、历史结果 | 推荐路线、置信度、预计成本 | 把“能生成”变成“可控地完成作品” | bandit/排序模型，后置训练 |
| Approval/Recovery Policy | 提议、预算、风险、用户偏好 | 自动继续/回到 Nomi 确认/回滚 | 保持可逆、可审计，而不是盲目自动化 | 规则状态机，模型只做建议 |

**关键判断：** 最先训练的不是“会聊天的 Nomi”，而是“会做 Nomi 这套生产工作、且知道何时不能自作主张的模型”。

## 5. 模型大小、训练阶段和模态路线

以下数字是**规划启发式，不是行业保证**，真正选型必须用 Nomi 自己的评估集和许可审查验证。

### 阶段 0：先做数据闭环，不训练（现在）

- 建立任务词典和 gold set：接入诊断、合同生成、失败修复、连续性判断。
- 用规则、schema、检索、现有 API 模型做 baseline。
- 只记录本地结构化结果和用户动作；不上传对话/素材。
- 目标不是模型分数，而是先证明我们能定义“成功”。

### 阶段 1：小任务模型（有稳定的结构化数据后）

- 路由、错误分类、字段抽取、排序：约 0.5–3B 或更小的 encoder/classifier。
- 结构化计划/修复建议：约 3–8B 的开源指令模型，优先量化部署。
- 先 SFT/蒸馏，再考虑偏好优化；用 LoRA/QLoRA，不做全量预训练。
- Hugging Face PEFT 文档说明 LoRA 冻结基座、只训练低秩矩阵；QLoRA 论文展示了在 4-bit 量化基座上做低内存微调的路线。[PEFT LoRA](https://huggingface.co/docs/peft/main/conceptual_guides/lora)、[LoRA 论文](https://arxiv.org/abs/2106.09685)、[QLoRA 论文](https://arxiv.org/abs/2305.14314)

### 阶段 2：任务级多模态模型（数据和标注都成熟后）

- 先做图像理解/连续性判分，不直接训练视频生成底模。
- 可评估当前开放权重多模态家族的 4–14B 档位；例如 Gemma 3 官方资料列出 1B/4B/12B/27B 多个尺寸和图像输入，但最终候选必须按许可、中文能力、端侧显存和实际 Nomi 评测决定。[Gemma 3 model card](https://ai.google.dev/gemma/docs/core/model_card_3)
- 音频先做转写、音画对齐和错误分类，不把声音/人脸原始数据纳入默认训练。

### 阶段 3：从零训练/继续预训练（暂缓）

只有在同时满足以下条件时才重新评估：

1. 有数百万级以上、来源和许可可追溯的领域语料，而不是几千段私人对话；
2. 有持续可验证的任务收益，且小模型/适配器已经证明需求；
3. 有专职训练、评测、数据治理和安全团队；
4. 有长期算力预算、分布式训练和发布运维能力；
5. 能处理用户撤回、数据删除、版权争议和模型泄露风险。

Cursor 自己也把大规模继续预训练与环境 RL 放在成熟的任务 harness、评估集和基础设施之后；Meta 的 Llama 3 公开规模则是数百 B 参数、万亿级 token 和极高训练 FLOPs。它们说明从零做通用底模是另一种资本密集型业务，不是 Nomi 当前的自然下一步。[Cursor Composer 2](https://cursor.com/blog/composer-2-technical-report)、[Llama 3](https://ai.meta.com/research/publications/the-llama-3-herd-of-models/)

## 6. 数据契约：用户如何“同意”才算真的同意

### 6.1 四个独立开关

不要用一个“帮助改进 Nomi”的总开关打包所有数据：

1. 使用统计：粗粒度次数、成功率、版本。
2. 错误/崩溃报告：结构化错误、堆栈指纹、性能桶。
3. 反馈轨迹：接受/拒绝/编辑差异、错误到修复结果。
4. 对话/素材贡献：高风险，逐样本、逐用途、逐区域、逐期限同意。

“接受使用条款”不等于“允许训练模型”；“允许上传到临时图床”不等于“允许训练”；“允许改进产品”也不等于“允许发布数据集”。

### 6.2 本机先处理，再决定是否出网

建议形成一个明确的 `ContributionEnvelope`，与现有 `.nomi/events` 分离：

```text
consentId / consentVersion / purpose / dataTier / region
taskKind / capability / providerClass / modelClass
eventOutcome / errorCode / repairAction / editDiff
latencyBucket / costBucket / sampleHash / retentionUntil
```

本机预处理必须做：密钥、Bearer、鉴权 query、绝对路径、URL、邮箱/手机号/地址/证件号、EXIF、过长 prompt/output 的移除或替换；用户看到脱敏预览后才能发送。现有 `redactDeep` 主要处理密钥和鉴权形态，不能被误称为“已经匿名化”（`electron/events/redact.ts:1-42`）。哈希和伪名是降低风险，不是让数据自动脱离个人信息法律范围。

### 6.3 权利、保存和删除

建议 pilot 默认值（需法律意见确认）：

- 结构化元数据：原始明细 30 天，聚合后删除；
- 性能/错误轨迹：14–30 天；
- 用户主动贡献的文本样本：最多 90 天，隔离存储；
- 素材：不进最小 pilot；未来如有明确同意，处理完成后尽快删除，目标不超过 24 小时；
- 撤回后停止后续发送，并在 30 天内删除既有可选数据；
- 同意凭证、删除审计和必要的影响评估记录单独保存，不与训练内容混放。

中国《个人信息保护法》要求知情、自愿、明确同意，目的/种类变化需重新同意，撤回应便捷，保存期限应为实现目的所必要的最短期限，并要求提供访问、更正、删除等路径。[中国个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

欧盟 EDPB 对 AI 模型的意见强调，要判断模型是否真正匿名、合法利益能否成立，以及非法处理的数据会对模型带来什么后果；英国 ICO 还特别提醒，训练、微调和部署阶段都要考虑知情、删除、异议和模型泄露风险。[EDPB AI models](https://www.edpb.europa.eu/news/edpb-opinion-on-ai-models-gdpr-principles-support-responsible-ai_en)、[ICO AI rights](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/artificial-intelligence/guidance-on-ai-and-data-protection/how-do-we-ensure-individual-rights-in-our-ai-systems/?search=minimisation)

### 6.4 区域、未成年人和版权

- 中国来源的原始对话/素材，默认存储在中国境内；跨境前需审查 PIPL 第 38–41 条路径、单独同意、影响评估和接收方合同。不要因为“没有姓名”就视为不受限制。[CAC 跨境规则](https://www.cac.gov.cn/2024-03/22/c_1712776611775634.htm)
- 最小 pilot 建议是邀请制、成年人、低敏任务；不要用一个“18+”勾选框假装解决未成年人、肖像、声音和第三方内容问题。欧盟、美国和中国的年龄阈值与监护要求不同，需按目标市场分别处理。
- 用户只能授权其有权授权的内容；提示词、角色设定、参考图、视频和声音可能包含第三方版权/人格权/商业秘密。训练许可应和隐私同意分开，且需要律师确认派生模型、撤回和再训练义务。

你提到的“18+2”含义我不擅自解释。如果你指的是“18+ 年龄门槛”，建议按上面的未成年人政策单独设计；如果指的是别的业务分组，需在定稿前补充定义。

## 7. 最小可行 pilot：先验证“数据能不能让产品变好”

**建议方案：20–50 名邀请制成人测试者，默认不收对话/素材。** 这是方案，不是立即执行授权。

### Pilot A：零内容遥测

- 默认关闭；只收用户主动发送的结构化错误/崩溃报告和低敏计数。
- 不持久化 IP、绝对路径、完整 prompt、输出、附件或供应商密钥。
- 运行真实任务：模型接入、参考上传、分镜到生成、失败恢复、导出。
- 每次记录用户是否成功、在哪里失败、修复是否有效。

### Pilot B：单条文本反馈

只有 Pilot A 能稳定完成删除和区域隔离后，才加入：

- 用户主动点击“贡献这一条”；
- 本机显示脱敏预览并允许修改；
- 仅文本，不含附件；
- 独立选择“改进体验”或“训练未来任务模型”；
- 90 天内删除原文，保留不可逆聚合指标；
- 人工抽检、数据血缘登记、样本级撤回。

### 成功门槛

先不看“模型有多大”，看五件事：

1. 接入成功率和首次成功时间是否改善；
2. 上传失败是否能被正确分类并给出有效修复；
3. 用户编辑距离、拒绝率、返工次数是否下降；
4. 预算/延迟/质量选择是否更稳定；
5. 删除、撤回、导出、审计演练是否能拿出证据。

## 8. 我建议现在确认的决策

### 推荐决策

选 **B：同意驱动的结构化数据 + 任务模型路线**：

1. 保留 Nomi 的“默认本地、无账号、无遥测”主承诺；如未来开启自愿贡献，必须改成“默认不收集，可单独选择贡献”，并在文案和设置中明确例外。

## 9. 还不能宣称的事情

- 不能说“我们会用所有用户对话训练 Nomi”；当前没有这样的授权、数据管线或法律结论。
- 不能说“脱敏/哈希后就是匿名”；伪名化仍可能是个人信息，模型也有记忆、反演和成员推断风险。[NIST Differential Privacy](https://csrc.nist.gov/pubs/sp/800/226/final)
- 不能说“Cursor/LibTV 已经证明用户数据训练一定成功”；公开资料只支持它们在特定任务、harness 和隐私设置下的做法，规模、ROI 和未公开训练集未知。
- 不能把匿名图传、供应商请求、错误遥测和模型训练写成一条模糊的“数据使用”。每条出网路径都要有目的、接收方、期限和开关。

## 11. 底座优先：公开的都用，Nomi 只做缺口

你补充的原则我赞成，而且它应该成为整个项目的 build-vs-buy 闸门：**公开标准/成熟实现优先；Nomi 只写连接层、语义层、评估集和真正独有的策略。**“公开”不等于“随便拿来训练”：每一项仍要过许可证、商用范围、区域、隐私和安全审查。

### 11.1 分阶段复用地图

| 阶段 | 优先复用的公开底座 | Nomi 真正要做的部分 | 明确不做 |
|---|---|---|---|
| 协议与 Agent | MCP 协议、JSON Schema、现有 pi SDK 和 Nomi 的工具合同 | 把 Nomi 的项目/画布/时间轴语义映射成稳定合同，做权限、确认、回滚 | 不再造一套 Agent 协议或第二套工具 schema |
| 事件与可观测 | 现有 `NomiEvent`；需要跨系统时再投影到 OpenTelemetry 语义 | 同意、数据分级、样本血缘和删除墓碑 | 不把本地事件日志直接改成云端训练库 |
| 媒体与制作 | FFmpeg/ffprobe、现有本地解码、ComfyUI 工作流 JSON | 视觉锚点、`StoryboardPlan`/`EditPlan`、ProductionRun 的生产语义 | 不写自有编解码器、时间轴渲染器或第二个画布内核 |
| 数据格式与质量 | JSONL、Arrow/Parquet、JSON Schema；数据版本工具按需要选 | `ContributionEnvelope` 白名单、数据血缘、许可/同意状态、去重和质量门 | 不发明私有训练数据格式或不可删除的黑箱仓 |
| 脱敏与隐私 | 现有密钥脱敏；可评估 Presidio 等成熟 PII 检测；NIST 差分隐私方法 | 本机预览、区域路由、样本级撤回、删除传播和风险分级 | 不把哈希、普通“去标识化”宣传成匿名；不先做联邦学习炫技 |
| 标注与反馈 | 需要人工标注时优先本地 Label Studio/Argilla 等公开工具 | Nomi 的任务标签、错误分类、连续性 rubric 和标注协议 | 不把原始项目素材默认交给第三方标注 SaaS |
| 训练/后训练 | Transformers、PEFT/LoRA、TRL、Accelerate；QLoRA；必要时再用 FSDP/DeepSpeed | 任务数据配方、拒答/安全约束、版本门、回归集 | 不自写优化器、分布式训练框架或 tokenizer |
| 评测 | 公开的语言/Agent 评测工具；VBench、T2V-CompBench；ffmpeg/ffprobe | `NomiBench`：真实接入、上传、分镜、恢复、成本、连续性和导出任务 | 不只用一个 LLM judge 或一个 CLIP 分数宣称“视频质量提升” |
| 本地/云推理 | 按平台评估 llama.cpp/MLX 等端侧运行时，服务端再评估 vLLM/SGLang 等 | 模型目录、能力认证、量化档位、供应商回退、隐私模式 | 不把现有供应商路由重写成模型专用分支 |

这张表里的工具是**候选底座**，不是现在就引入的依赖。真正动手时要逐项查当前官方文档、许可证和版本；只在 NomiBench 或安全/性能门槛证明有必要时引入。

### 11.2 哪些才是 Nomi 的独有层

Nomi 的专有部分应集中在五层：

1. **创作语义层**：视觉锚点、镜头关系、`StoryboardPlan`、`EditPlan`、时间轴/导出约束。
2. **供应商真实能力账本**：模型到底支持什么输入、参数和模式，何时通过认证，何时降级；不是凭模型名字猜能力。
3. **人机共同决策层**：方向、支出、不可逆操作和粗剪采用必须回到 Nomi，由状态机和回执保护。
4. **结果型数据与评测集**：用户修改差异、错误到修复、生产闭环、连续性和成本质量的任务样本。
5. **贡献治理层**：本机最小化、用途分层、同意/撤回、区域、保留期限、血缘和删除传播。

这些层即使底座模型从 Qwen、Gemma、Mistral 或其他公开权重换成下一代模型，也仍然成立；这才是“模型可替换、Nomi 不可替换”的结构。

### 11.3 复用顺序

每个新能力按以下顺序过一次，不满足前一条就不进入下一条：

1. **标准协议能否表达？** 能，就直接采用标准语义（例如 MCP/JSON Schema）。
2. **成熟开源实现能否覆盖？** 能，就包适配器，不复制实现。
3. **现有 Nomi 领域对象能否承载？** 能，就扩展单一 owner，不另建平行状态。
4. **只剩真正缺口时才自研。** 缺口必须能写成一个可测的任务和回归集，例如“从供应商错误 envelope 预测可行修复”。
5. **模型训练是最后一层。** 如果规则、检索、编译器或路由已经解决，就不为“看起来像 AI”再训练一个模型。

因此，Nomi 的第一批“专有模型”很可能只是小型 router、repair classifier、合同编译器和连续性 judge 的适配器；它们组合起来的行为比一个孤立的大模型更有价值。
