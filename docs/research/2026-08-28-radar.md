# Nomi 论文雷达 · 2026-08-28

一句话：本轮最值得 Nomi 立即吸收的不是新生成模型，而是两套**验收形状**——EntityBench 用「实体记忆 + 跨镜复现距离」测长期一致性，PersonaShot 把人物叙事连续性拆成物理状态、情绪和电影语法；它们都说明只看单镜画质会系统性漏掉真正的成片问题。

本轮最该动的两件事：

1. 在真实任务评测里增加「角色/物体/地点跨镜复现」案例，并记录实体间隔，而不是只验证连续相邻镜头。
2. 把跨镜验收从单一相似度拆为外观、物理状态、情绪轨迹和镜头关系四组证据，先以人工/VLM rubric 落地，再决定是否引入专用评估器。

> 检索窗口：2026-02-28 至 2026-08-28；对 8 个固定方向逐项检索，只保留能映射到 Nomi 当前模块或评测体系的结果。

## 🟢 可落地

### EntityBench：用显式实体记忆对抗长距离跨镜遗忘

- **链接 / 日期**：[arXiv 2605.15199](https://arxiv.org/abs/2605.15199)，2026-05-14；[官方代码与数据](https://github.com/Catherine-R-He/EntityBench/)。
- **火度 / 成熟度**：论文同时公开代码和数据；140 个 episode、2,491 个镜头，覆盖最多 50 镜、13 个角色、8 个地点和 22 个物体。属于能直接借鉴评测协议的成熟 benchmark，而非只给概念。
- **洞察**：现有方法的实体一致性会随着「上次出现到再次出现之间隔了多少镜」快速下降；显式、按实体维护并经过验证的视觉参考，比只把最近一镜继续传下去更稳。
- **落到 Nomi**：在现有真实用户任务/生成走查中新增 recurrence-gap 维度：同一角色在第 1、5、20 镜重新出现，分别检查 presence、appearance fidelity 和 prompt alignment。生产侧复用项目的角色/场景资产与引用绑定，评测侧不要只比较相邻镜。具体接点需结合统一 Agent 迁移后的最终 eval 入口复核，暂不硬塞进仍在迁移的 runtime。

## 🟡 架构教训

### Gloria：多参考不是越多越好，必须有角色中心的锚点语义

- **链接 / 日期**：[arXiv 2603.29931](https://arxiv.org/abs/2603.29931)，2026-03-31；[CVPR 2026 项目页](https://yyvhang.github.io/Gloria_Page/)；[CVPR 论文](https://openaccess.thecvf.com/content/CVPR2026/papers/Yang_Gloria_Consistent_Character_Video_Generation_via_Content_Anchors_CVPR_2026_paper.pdf)。
- **火度 / 成熟度**：CVPR 2026，项目页与 benchmark 已公开；未发现可直接嵌入 Nomi 的完整推理代码，因此不列为本月实现项。
- **洞察**：把任意历史帧当 memory 会混入无关场景并引发多参考冲突；更稳的做法是角色中心的结构化锚点（整体、视角、表情），并保留锚点之间的身份区别，避免复制粘贴。
- **影响 Nomi 哪个决策**：Nomi 的多图输入契约应继续坚持**显式角色/用途绑定**，不能回退到 `images[]` 按位置猜 `firstFrame` 或角色身份。新模型即使只暴露一个图片数组，也应由模型档案把 Nomi 的稳定角色语义翻译到供应商字段，而不是让供应商字段反向污染产品语义。

## 🔵 对标基准

### PersonaShot：把人物跨镜连续性从「像不像」扩成叙事状态是否接得上

- **链接 / 日期**：[arXiv 2608.16717](https://arxiv.org/abs/2608.16717)，2026-08-17。
- **火度 / 成熟度**：发布仅 11 天，约 1,000 个多镜片段、16 个指标；本轮未找到公开代码，当前适合借 rubric，不适合宣称已可一键复现。
- **洞察**：高画质视频仍经常在切镜后重置人物姿态/物理状态、突然改变情绪，或破坏视线和镜头关系。benchmark 分别看镜内状态、跨镜转移和整段轨迹，并用视觉、时间、关系证据匹配不同指标。
- **怎么接进 Nomi eval**：给真实任务测试增加四列证据：①角色外观；②动作/道具/位置状态；③情绪连续性；④镜头关系与视线。每列记录镜号和失败截图，避免一个总分掩盖具体断点。等官方 evaluator 代码公开后，再评估是否替换人工/VLM rubric。

### MSVBench：用层级剧本和参考图评估整段，而非把镜头分数简单求和

- **链接 / 日期**：[arXiv 2602.23969](https://arxiv.org/abs/2602.23969)，2026-02-27（窗口边界）；[ACL 2026 Findings 官方代码](https://github.com/HITsz-TMG/MSVBench)，本轮检索时 8 stars。
- **洞察**：其数据把全局故事、场景和镜头条件分层，评估组合 LMM 的高层叙事判断与专用模型的细粒度感知；论文报告与人类排序相关系数 94.4%。这给 Nomi 的真实任务测试一个清晰对照：验收物应是「层级意图 + 成片」，不是孤立节点输出。
- **怎么接进 Nomi eval**：先抽取少量公开故事为离线对标样本，映射到 Nomi 的剧本→分镜→生成→时间轴闭环，保留每层意图作为验收证据。完整 GPU 指标栈依赖较重，不直接并入 CI；CI 只保留结构和小样本断言，周期审计再跑完整评测。

## 上轮（08-26）vs 本轮（08-28）diff

- **新出现**：PersonaShot 把人物连续性扩展到情绪与电影语法，补上此前 EntityBench 偏实体外观的盲区。
- **继续加固**：08-26 的「首尾帧/转场不能只看单点」结论，本轮被 PersonaShot 的跨镜状态转移和 EntityBench 的长距离复现再次证明。
- **没有升级为落地项**：本轮在 prompt 优化、唇形同步、局部编辑和相机轨迹方向没有检索到同时满足“近 6 月、与 Nomi 当前痛点直接相关、可复现”的新结果；不为凑数收录。
- **本轮筛掉**：旧论文、自动驾驶相机轨迹、单人 talking-head、只提高单镜画质、没有可映射到 Nomi 使用闭环的条目共 9 篇。
