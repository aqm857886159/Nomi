# 资源库样张与素材库用户旅程复审

日期：2026-08-30
范围：只读走查 `docs/prototypes/library-discovery.html`（A 方案，素材库）与当前 `AssetLibraryPanel` 实现。
角色：真实创作者；目标是“从另一个项目找到一张参考图，并把它带到当前画布”。

## 最短任务走查

预期路径：打开素材库 → 搜素材文件名 → 用一个分类缩小结果 → 认出真实缩略图 → 查看/预览 → 导入当前项目。

### 1. 素材卡仍然说得太多，主动作被稀释

- **问题**：原型卡片同时展示文件名、大小/时间、标签、收藏、导入、更多操作；面板还有说明段落、全部/最近/收藏、排序、分类、类型。360px 左右的侧栏会让用户先读 UI，而不是认素材。
- **证据**：原型 `docs/prototypes/library-discovery.html:138` 的工具区和 `:135` 的卡片模板；实际紧凑卡片只渲染媒体、类型角标和文件名，没有描述/按钮行（`src/workbench/assets/AssetLibraryPanelParts.tsx:313-353`）。
- **建议**：素材库收敛为“看图、认出、拿走”：保留媒体、文件名、一个很轻的类型线索；保留“全部素材/项目素材”范围（这是跨项目所必需）；分类只保留一个紧凑入口。删除卡片上的描述、标签、收藏、排序和逐卡导入按钮，低频动作放到选中后的统一操作或更多菜单。
- **验收**：A 方案侧栏中，用户无需阅读段落即可识别素材；每张卡的可见文字不超过文件名+类型；从搜索结果到导入只有一个明确主动作。

### 2. 原型把“分类”和“类型”拆成两个入口，和真实代码语义不一致

- **问题**：原型同时显示“分类（人物/场景/声音/片头）”和“类型（图像/视频/音频）”，用户会以为 Nomi 已经有稳定的语义分类体系。真实代码的“分类”按钮实际是媒体类型多选，选项只有图片/视频/音频。
- **证据**：原型 `docs/prototypes/library-discovery.html:138`；`AssetLibraryPanel` 的筛选入口和菜单在 `src/workbench/assets/AssetLibraryPanel.tsx:568-600`、`src/workbench/assets/AssetLibraryPanelParts.tsx:1-93`，选项定义在 `src/workbench/assets/assetLibraryPanelFilters.ts:3-13`。
- **建议**：V1 只保留一个“类型/分类”入口，显示图片、视频、音频及数量；不要在没有索引合同前添加“人物/场景”等 AI 或手工语义分类。项目内已有文件夹，只在“项目素材”范围内生效（`AssetLibraryPanel.tsx:201-211`），不要暗示它是跨项目全局分类。
- **验收**：打开筛选只需一次点击；选项与真实数据字段一致；筛选后结果数、空态和清除动作同步变化；跨项目范围不会出现不存在的语义分类。

### 3. 搜索占位文案承诺了不存在的字段

- **问题**：原型提示“搜索素材、描述或标签”，但实际素材过滤只匹配文件名。用户输入项目描述或标签时会得到空结果，属于假 affordance。
- **证据**：原型 `docs/prototypes/library-discovery.html:138`；实际过滤 `src/workbench/assets/assetTypes.ts:90-98` 只对 `asset.name` 做大小写不敏感匹配，面板调用为 `filterAssets(sourceFilteredAssets, { query })`（`AssetLibraryPanel.tsx:169-171`）。
- **建议**：第一阶段把占位统一为“搜索素材名”，先保证跨项目文件名可命中；若未来要搜来源项目/文件夹，再先扩展 `AssetRef`/索引字段和测试，不要只改文案。
- **验收**：用上一项目的真实文件名搜索，在“全部素材”范围能命中；输入未实现字段不会被 UI 宣传为可搜；搜索结果计数和清空入口正确。

### 4. 跨项目能找到，但来源线索不能占用卡片文字

- **问题**：`useAllProjectAssets` 已遍历所有项目并合并资产，但紧凑卡片通常只显示文件名；不同项目同名素材无法快速区分。直接加一行“来自某项目”又会重回文字堆叠。
- **证据**：跨项目枚举和稳定排序在 `src/workbench/assets/useAllProjectAssets.ts:89-140`；`AssetRef.origin` 带 `projectId` 但紧凑卡片只渲染文件名/类型（`AssetLibraryPanelParts.tsx:333-350`）。
- **建议**：卡片保持无额外长文；只有同名或详情确认时，在中央预览/详情中显示来源项目，或使用可悬停的短来源标记。跨项目动作必须与“预览”分开，导入时才建立当前项目归属。
- **验收**：同名素材可在中央详情中区分源项目；侧栏仍保持一眼看图；导入后素材出现在当前项目，源文件不被移动或改写。

### 5. 真实比例方向正确，但生产两种密度要避免回退成方块裁切

- **问题**：原型 A 已演示竖图、横视频、音频条和 4:3 图片的不同高度；但生产 `AssetGridCell` 的非 compact 分支仍是 `aspect-square`，`AssetThumb` 的图片是 `object-cover`，在全宽资源页可能裁切真实构图。
- **证据**：原型 `.asset-grid` 使用卡片自身 `aspect-ratio`（`docs/prototypes/library-discovery.html:44,57`）；生产紧凑分支图片使用 `h-auto w-full object-contain`、视频/音频有各自高度（`AssetLibraryPanelParts.tsx:333-347`），非紧凑分支则固定正方形（`:355-377`），通用图片缩略图为 `object-cover`（`src/workbench/assets/AssetTile.tsx:138-148`）。
- **建议**：素材库默认使用 compact 的自然比例瀑布流；全宽/独立库也按媒体元数据保留比例，视频使用首帧 poster，音频使用固定波形条。不要用统一正方形作为素材库的默认视觉。
- **验收**：用竖图、16:9 视频、长图和音频截图对比，主体不被裁切；调整面板宽度后比例仍稳定；视频首帧可辨识。

### 6. 中央详情是对的，但必须和现有预览/导入语义对齐

- **问题**：原型点击卡片打开中央详情，这个方向比右侧抽屉更不挤压画布；但它把“查看详情”和“导入当前项目”同时放入一个对话框，且点击卡片上的主按钮会绕过详情。原型 toast 又写“加入导入队列 · 确认后写入”，页面没有后续确认，动作时机不清楚。
- **证据**：原型 `docs/prototypes/library-discovery.html:142,160`；生产当前根据上下文区分动作：画布“全部素材”单击是预览、项目素材单击是选择（`src/workbench/assets/assetLibraryUsage.ts:22-28`），媒体预览通过 body portal 居中 lightbox（`src/workbench/assets/AssetPreviewDialog.tsx:32-40`），双击与 Esc 关闭分别在 `AssetLibraryPanelParts.tsx:269-272`、`AssetPreviewDialog.tsx:20-30`。
- **建议**：保留居中预览/详情，不引入右侧常驻栏；不要在第一阶段改变现有上下文动作合同。素材卡的唯一主路径应明确为“预览”或“导入到当前项目”之一；若导入是立即写入，就直接说“导入到当前项目”并给成功反馈；若需要确认，就真实提供确认步骤，不能只在 toast 里暗示。
- **验收**：点击媒体得到中央预览，遮罩、关闭按钮和 Esc 都可退出；导入动作只出现一次且反馈与实际持久化一致；不会出现“看似导入、实际仍在队列”的歧义。

## 结论与实现前置条件

素材库的产品表达应收敛为：**真实媒体网格 + 文件名搜索 + 一个类型分类 + 全部/项目范围**。详情放中央只承担确认，不承担第二套资源管理。现有跨项目枚举、拖拽和安全写入路径继续复用；原型需要删掉未落地的描述/标签搜索、语义分类、逐卡导入和过多文字后，才能作为生产实现的可信交互合同。

本审查只读完成，未修改生产代码；原型和方案的修改由主任务统一合并。
