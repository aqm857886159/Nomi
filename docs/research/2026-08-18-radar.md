# Nomi Research Radar — 2026-08-18

> 本轮按 8 个固定方向分别查询 arXiv，时间窗为 2026-02-18 至 2026-08-18；只保留会改变 Nomi 落地、架构或评测决策的条目。所有论断来自本次实搜，给 arxiv 链接。

## 一句话结论

本轮最强信号来自两端：**跨镜身份一致性已有高质量 benchmark（EntityBench）可直接接进 eval**，以及 **DirectorBench 实测证实「转场质量」是所有 decompose-stitch 流水线的最差维度（均分只有 0.256）**——这两件事加起来明确了 Nomi 下一步补强的优先级。

**本轮最该动的 1-2 件事**：

1. **把 EntityBench 的「三支柱评估框架」接进 Nomi eval 体系**：EntityBench (arXiv:2605.15199) 提供了 140 个剧集、2,491 个镜头的实体调度基准，区分「场景内质量 / prompt 对齐 / 跨镜一致性」三维——而 Nomi 当前 `evals/lib/vbenchRubric.mjs` 缺少跨镜实体连续性这一维度。可在 `evals/journeys/` 新增 `j7-entity-consistency.mjs`，对 Nomi 生成的多镜序列测角色保真度（用 EntityBench 的 Cohen's d 保真度门控逻辑）。

2. **用 DirectorBench 的 5 维诊断框架给 Nomi 当前流水线打一次分**：DirectorBench (arXiv:2605.30090) 测了 4 种 decompose-stitch 流水线，转场质量（transition quality）均分仅 0.256，是最差维度。Nomi 的镜间转场目前靠 `relayFrameResolver.ts` 做帧接力，没有对 script / visual / audio / cross-modal / stability 做联合评估——这 5 维框架可以直接作为 Nomi 的 eval 诊断契约模板。

## 🟢 可落地

### EntityBench — Towards Entity-Consistent Long-Range Multi-Shot Video Generation

- [arXiv:2605.15199](https://arxiv.org/abs/2605.15199) · [项目页](https://catherine-r-he.github.io/EntityBench/) · 2026-05-14 · 有 GitHub 代码
- **一句话洞察**：140 个剧集、2491 个镜头的跨镜实体一致性基准，提出「三支柱评估框架」（场景内质量 / prompt 对齐 / 跨镜一致性），用保真度门控机制（Cohen's d）分离「某镜生成好看」和「跨镜还是同一个角色」这两件事——当前所有主流方法在跨镜一致性上都显著退化。
- **Nomi 落点**：`evals/journeys/` 新增 `j7-entity-consistency.mjs`，从 Nomi 生成的多镜序列中抽取人脸/主体参考帧，用 `evals/lib/vbenchRubric.mjs` 的相邻帧比较扩展为跨镜比较；三支柱中「跨镜一致性」维度可作为 production run 后的自动质检维度，驱动 `generationNodeExecutor.ts` 的重试判断。
- **成熟度/热度**：有官方代码 + 项目页，数据和指标已公开，机制仅需 VLM + 相似度计算，无需重训模型，适合 Nomi 直接接。

## 🟡 架构教训

### DirectorBench — Diagnosing Long-Form Video Generation with Personalized Multi-Agent Evaluation

- [arXiv:2605.30090](https://arxiv.org/abs/2605.30090) · 2026-05-28
- **一句话洞察**：测了 4 种长片生成流水线的 5 维表现（script / visual / audio / cross-modal / stability），含 80 条结构化元数据 + 7 种用户画像 + 40 个检查点；关键发现：**转场质量均分只有 0.256**，是最低维度，而整体得分掩盖了流水线特定的失败模式。
- **影响 Nomi 的决策**：Nomi 的 `relayFrameResolver.ts` 做帧接力转场，当前没有任何针对镜间转场质量的评测维度。DirectorBench 的 5 维框架明确了 Nomi eval 的缺口：audio 维度、cross-modal（视听对齐）维度和 stability（上下文稳定性）维度均未覆盖。不必照搬 40 个检查点，但应先量出当前 Nomi 的转场在 visual / stability 两维的真实失败率，再决定 `relayFrameResolver.ts` 是否需要引入语义一致性约束。
- **成熟度/热度**：摘要未给代码仓，但 5 维评测协议已完整发布在论文中，可作为 Nomi eval 契约的参考框架。

### Camera Artist — A Multi-Agent Framework for Cinematic Language Storytelling Video Generation

- [arXiv:2604.09195](https://arxiv.org/abs/2604.09195) · 2026-04-10
- **一句话洞察**：把故事板生成拆成「Director Agent（脚本 → 场景 → 镜头层级扩展）」+ 「Cinematography Shot Agent（递归故事板生成 + 电影语言注入）」两层，关键发现是递归故事板生成可以在级联误差出现时提供局部修正点，而不是等全片生成完才发现前期决策错误。
- **影响 Nomi 的决策**：Nomi 的拆镜头规划（`extractShotCutsToNodes.ts`）目前是一次性生成，后续生成节点无法反馈「本镜结果与上镜参考的实际偏差」来修正后续镜头的 prompt。Camera Artist 的递归故事板机制提示：**在 `dependencyWaves.ts` 的波次执行中，每波完成后应把视觉结果摘要（或关键帧描述）送回 storyboard 上下文，让后续波次的 prompt 可以参考实际生成结果而不是原始计划**——这是防止跨镜级联漂移的结构性方案。未找到公开代码仓。

### One Sentence, One Drama — Personalized Short-Form Drama Generation via Multi-Agent Systems

- [arXiv:2605.22144](https://arxiv.org/abs/2605.22144) · 2026-05-21
- **一句话洞察**：三模块系统（多 agent 辩论驱动剧本生成 / 3D 空间基础保角色跨镜一致性 / 多阶段审查循环错误修正）从一句话自动生成完整短剧；关键设计是「审查循环」在脚本、视觉、视频生成三个阶段分别做错误检测和有针对性修正，而非最终一次检查。
- **影响 Nomi 的决策**：Nomi 当前的 `recoverTaskActions.ts` 只在任务失败时触发修复，没有在「脚本生成完 / 首帧生成完」等中间节点做主动质量门控。该论文的「分阶段审查」结构教训：**应在 `generationRunController.ts` 的关键中间节点（如拆镜头结束、首帧图生成结束）加入主动验证点，而不是等视频生成完才发现前期问题**。未找到公开代码仓。

### ViMax — Agentic Video Generation

- [arXiv:2606.07649](https://arxiv.org/abs/2606.07649) · 2026-06-02（v2: 2026-07-21）
- **一句话洞察**：完整 decompose-stitch 开源流水线：叙事引擎（RAG 增强）→ 依赖感知视觉一致性追踪（角色 + 环境状态）→ VLM 引导 agent（监控叙事连贯与视觉保真）。被 DirectorBench 直接点名比较，是目前最接近 Nomi 架构的公开对标实现。
- **影响 Nomi 的决策**：ViMax 的「依赖感知视觉一致性追踪」提示 Nomi 的 `generationReferenceResolver.ts` 应显式维护「已生成实体的视觉状态表」（角色外观、场景布局），而不是仅靠 reference slot 把参考图传给每镜。这个「实体状态表」是 Camera Artist 递归故事板教训的具体实现形式。未找到公开代码仓，未开源。

## 🔵 对标基准

### DirectorBench 5 维评测协议（同上，双档）

- [arXiv:2605.30090](https://arxiv.org/abs/2605.30090) · 2026-05-28
- **接入 eval**：5 维框架（script / visual / audio / cross-modal / stability）可作为 Nomi 端到端 eval 的诊断契约：在 `evals/lib/vbenchRubric.mjs` 对应增设 5 维评分维度，优先补 visual（帧质量 + 转场连贯性）和 stability（跨镜上下文稳定性），audio / cross-modal 参考上轮 AcoustiTrace 的 rubric 扩展方向。baseline 对比：Nomi 当前流水线 vs 0.256 的行业转场均分——量出自己在哪里。

### ShotPlan — Cinematic Video Generation with Learnable Planning Token

- [arXiv:2607.17675](https://arxiv.org/abs/2607.17675) · [项目页已知存在] · 2026-07-20
- **接入 eval**：ShotPlan 提出用可学习规划 token（配合分数阶时间 RoPE）显式控制镜间转场时间戳——其评测方法（如转场时间误差、转场类型分类准确率）可作为 Nomi `relayFrameResolver.ts` 的评测参考维度：**量出当前抽帧接力在转场时间点对齐上的真实误差**，再决定是否需要更显式的转场控制机制。需要训练，不适合直接集成，但 benchmark 协议可借。

## 上轮 vs 本轮 diff

- **新增**：EntityBench（🟢 跨镜实体一致性 benchmark，可接 eval）、DirectorBench（🟡🔵 5 维诊断框架 + 转场均分 0.256 行业基线）、Camera Artist（🟡 递归故事板防级联漂移）、One Sentence One Drama（🟡 分阶段审查循环）、ViMax（🟡 decompose-stitch 行业对标）、ShotPlan（🔵 转场时间戳控制 benchmark 协议）。
- **延续不重复**：上轮「Beyond Trial-and-Error / DSG-CMQ 结构化重试」、「CamChoreo 复合运镜 eval」结论未过期；本轮 DirectorBench 的 visual 维度是 CamChoreo 的上层诊断，两者互补。
- **筛掉的噪音**：LaVieID（arxiv:2508.07603，2025-08-11，超出 6 个月窗口）、SpeakerVid-5M（2025-07，超窗口）、Gloria（有项目页但需重训大模型，成熟度不足，降到待观察）、QWERTY camera control（训练自由但仅针对 I2V DiT backbone，与 Nomi 黑盒供应商架构不兼容）、VideoPainter/AdaFlow（需专用训练，inpaint 方向无比历轮更适合黑盒架构的新方案）。
- **检索分诊**：8/8 个固定方向均完成定向查询 + 关键论文 WebFetch 深挖，初筛约 50+ 条结果；去重后筛掉约 40 篇噪音、重复项或超出时间窗的工作。正文收 **1 篇可落地、4 篇架构教训、2 篇对标基准**。
