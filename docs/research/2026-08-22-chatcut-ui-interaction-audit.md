# ChatCut 编辑器页面与交互实测审计

> 日期：2026-08-22（Asia/Shanghai）
> 方法：登录态 Chrome/CDP + Playwright 真实页面点击、菜单展开、布局切换、时间线选取、截图；再与 ChatCut 官方 Agent Plugin/Skill 文档对账。
> 范围：编辑器主壳、剪辑区 Agent、时间线、素材/资源库、工作区预设、技能/风格/音色市场、项目库、账户/积分、导出、检查器、真实 Agent 对话。
> 安全边界：没有提交生成、没有购买/升级、没有导出、没有应用素材/风格、没有删除项目。

## 先给结论

ChatCut 的默认编辑器把 Agent 作为剪辑工作区的一等公民：左侧是持久在线 Agent，中间是素材/预览，底部是全宽时间线。Agent 不是独立的“创作首页”，而是直接绑定当前项目、当前时间线和当前素材。

它用工作区预设解决“Agent 占空间”和“剪辑需要专注”的矛盾：默认/竖屏预览保留 Agent，NLE/逐字稿编辑则把 Agent 隐藏，用户仍可以切回 AI 面板。这个取舍比把 Agent 永久塞进另一个页面更合理，也验证了 Nomi 的剪辑区必须有 Agent，但不应强制每种编辑模式都显示同样宽度的 Agent。

## 1. 实测环境与证据边界

- 实测入口：`https://app.chatcut.io/zh/editor/9cf8560b-7cd2-4b26-8a3b-bfe9f194f017`，另检查了一个已有较长 Agent 对话的真实项目。
- 浏览器视口：CSS 1920×936。
- 观察到的原项目：`DJI口播精剪_20260807`；另一个项目含 `8月22日.mov` 的口播剪辑对话。
- 截图证据暂存在本机 `/tmp/chatcut-*.png`，包括主编辑器、四种布局、项目库、素材库、资源库、市场、导出、检查器和真实 Agent 对话。

### 需要透明记录的一次意外

项目库的 `新建项目` 是“一点即创建”，没有二次确认或名称表单。我在验证该入口时实际创建了一个空项目：`Content Tan Alpaca`。没有上传、生成、扣费、导出或删除任何内容；没有擅自删除它。这个行为本身是产品风险：新建项目属于可见的持久化变化，至少应有撤销/确认/创建后引导。

## 2. 页面壳层：Agent 已经在剪辑区里

### 默认编辑器布局

| 区域 | 实测内容 | 交互意义 |
|---|---|---|
| 顶部 | 项目入口、桌面端、项目名/协作者、撤销/重做、版本、工作区、导出、升级、积分 | 项目级动作固定在壳层，不藏进聊天 |
| 左侧 | AI Agent、快捷创作卡、对话流、输入框 | Agent 能读取并修改当前项目，且一直可见 |
| 中部 | `我的素材`、`资源库`、`剪口播` 标签；预览区 | 同一个工作区切换“资产/资源/逐字稿/预览” |
| 底部 | 全宽时间线、轨道、播放头、工具、缩放、字幕、画幅比例 | 时间线不是 Agent 的附件，而是共同工作面 |

左侧 Agent 首屏快捷意图卡实测包括：`口播剪辑`、`MG动画`、`Seedance 2.5`、`音色克隆`、`拼贴 B-roll`、`产品 / App 宣传`、`AI 短片`、`讲解视频`、`更多`。这比让用户先学习 prompt 格式更低摩擦。

### Agent 输入区

默认 placeholder 是“告诉 AI 要做哪些修改 - @ 引用素材”。输入区同时提供：

- `Agent / 视频生成`模式切换；
- 生成模型、音色、设计风格、技能等上下文选择器；
- 附件/素材引用；
- Agent 设置（思考模式、MG 质量、自动允许生成）；
- 发送按钮。

关键判断：这些不是独立设置页，而是当前请求的可见上下文。用户在发请求前就能看到“会用哪个模型/声音/风格/技能”，而不是让 Agent 在后台悄悄换配置。

## 3. 真实点击得到的交互状态

### 3.1 Agent 与视频生成是两个模式，不是两个页面

点击 `Agent 代理` 后，菜单只有两项：`Agent 代理`、`视频生成`。

切到 `视频生成` 后，输入 placeholder 变为“描述你希望 Seedance 2.5 生成的视频...”，并出现首帧/尾帧、模型和视频设置。实测模型菜单有 Seedance 2.5、Seedance 2.0、Seedance 2.0 Fast、Seedance 2.0 mini、Kling 3.0、Gemini Omni。

视频设置菜单实测包含：

- 输入模式：首尾帧、全能参考、编辑视频、延长视频；
- 画幅：16:9、4:3、1:1、3:4、9:16、21:9；
- 分辨率：480p、720p、1080p；
- 时长：5s；
- 输出：MP4、MOV。

这说明生成是编辑器内的一个“任务模式”，但它没有把生成结果自动当成时间线片段；官方 `video-gen` Skill 也明确一调用一任务、完成后再由用户审阅，不自动落时间线。[官方 video-gen Skill](https://raw.githubusercontent.com/ChatCut-Inc/agent-plugin/main/codex/skills/video-gen/SKILL.md)

### 3.2 Agent 设置与上下文选择器

- Agent 设置：思考模式 `速度 / 均衡 / 高质量`；MG 质量；`自动允许生成`。
- 音色：精选音色、我的音色、克隆音色；能看到性别/年龄/气质等简短标签。
- 设计风格：无、精选预设、我的风格、新建设计风格。
- 技能：说明“选择一个技能，让 AI 根据技能的指导流程进行工作”，并提供“浏览全部 Skill / 我的技能 / 把这次剪辑流程保存为技能”。

这里最值得 Nomi 借的是“上下文 chip + 可展开细节”，不是把所有参数做成复杂表单。

### 3.3 工作区预设

点击 `工作区` 实测菜单分为 `面板` 与 `布局预设`：

- 面板：AI、我的素材、检查器、资源库、剪口播、时间线；
- 布局：默认、逐字稿编辑、NLE、竖屏预览。

真实截图观察：

1. **默认**：左 Agent + 中素材/预览 + 底部时间线。
2. **竖屏预览**：保留 Agent，右侧给窄的竖屏预览，适合短视频。
3. **NLE**：隐藏 Agent，左侧资产 bins，中间预览，底部密集时间线，给熟练剪辑者最大时间线空间。
4. **逐字稿编辑**：以大段 transcript 为主，预览在右，时间线在底；适合先按文字改 A-roll。

产品结论：Agent 应常驻于剪辑工作区能力模型，但允许“聚焦预设”隐藏它；隐藏不是把 Agent 路由到别的页面，而是可随时召回的面板状态。

### 3.4 时间线与检查器

时间线工具实测：新建时间线、选择/修剪/刀片模式、分割、吸附、录制旁白、录制设置、播放、缩放、适配视图、画幅比例、字幕开关、字幕样式、全屏。

选择时间线片段后打开 `检查器`，实测有：

- 视频：缩放、位置、旋转、对齐、不透明度、淡入淡出、圆角、裁剪、速度；
- 音频：音量 dB、淡入淡出、人声隔离；
- 效果：已应用效果列表。

这条路径证明 Agent 的正确职责不是直接代替检查器，而是：读取当前选区 → 提议变化 → 用户确认/应用 → 检查器和时间线显示结果。

## 4. 素材、资源和创作市场

### 我的素材

我的素材页有搜索、上传、新文件夹、列表/网格、排序、过滤。过滤项实测能按：全部、时间线、视频、音频、MG 动画、图片、效果、LUT。选择素材后，右侧可看预览，底部仍保留时间线，Agent 也仍在左侧。

### 资源库

资源库的一级类别实测：MG 动画、音效、转场、特效、缩放、LUT、Audio Effect。MG 子类包括数据可视化、信息图表、下三分之一字幕、引用卡片、社交界面、人物叠加、文字特效、标题卡片等。加载后能看到如 `Hand-Drawn Stack Chart`、`Timeline Progress Bar`、`Product Specs Panel` 等可复用卡片。

资源库的交互重点是“先浏览/筛选，再应用”，而不是让 Agent 每次从零写效果。ChatCut 的 `shader-gen` 规则也采用 catalog-first：已有效果优先，新效果先生成资产、验证后再提议落轴。

### 创作市场

`更多` 打开“创作市场”，有三个 tab：`Skill 市场`、`设计风格`、`音色库`。

- Skill 卡片有 `使用` 和 `在其他 AI agent 中使用`。
- “在其他 AI agent 中使用”会显示 ChatCut 插件安装/复制口令，明确支持 Codex、Claude Code、WorkBuddy。
- 设计风格卡片有 `基于此风格定制`、`在其他 AI agent 中使用`、`应用`。
- 音色库提供大量带性别/年龄/气质标签的音色，并有 `使用`。

官方 Plugin 仓库进一步确认：外部 Agent 可以导入素材、改时间线、创建 MG、生成资产、转录、加字幕、导出和验证可见结果；认证通过 ChatCut 的 MCP endpoint 完成。[ChatCut Agent Plugin](https://github.com/ChatCut-Inc/agent-plugin)

需要注意一个架构边界：官方 `create-motion-graphics` 文档明确说它是 ACP/本地 CLI 的直接 JSX 编辑路径，不是内置 ChatCut Agent 的路径；内置 Agent 使用另一套 `motion-graphic-gen`/`submit_motion_graphic`。因此“页面里看到的 Agent”“外部 Codex/Claude 插件”“底层素材/时间线工具”不是同一个权限面，Nomi 不能把外部 Skill 正文直接当成内置 Agent 的执行器。

## 5. 真实 Agent 对话：从意图到可恢复状态

在另一个已有项目中，我没有发送新消息，而是读取了页面已有的真实对话。用户请求是：加载 talking-head guide，把口播素材逐步做成片，并一起决定口播清理、B-roll、MG、音乐、字幕。

页面实际展示的 Agent 行为顺序：

1. 声明会加载 talking-head guide，并先检查素材。
2. 报告素材已在项目中：约 8 分 22 秒、竖屏、带原声、尚无文字稿。
3. 用按钮让用户选择发布平台：用户点 `抖音竖屏`。
4. 再让用户选择时长：用户点 `保留完整内容`。
5. 把画布设为竖屏并把整段口播放入时间线；页面显示“更新了一条时间线，调整了一个片段”。
6. 在继续处理前，先询问口播清理力度；用户点 `标准清理：去呃额、明显重复和过长停顿`。
7. 读取脚本失败后，Agent 显示 `Retrying script read with refreshCache`，并说明正在重试。
8. 随后没有假装成功：它说明文字稿未生成、素材登记信息缺少可读的原始文件副本；建议重新添加原始 `8月22日.mov` 或提供本机路径。
9. 用户点击 `重新添加了` 后，Agent 再次检查项目，发现仍是不可读副本，再次给出明确下一步，而不是无限转圈或扣费。

这条对话是最重要的交互证据：

- Agent 不是只回答问题，而是和编辑器状态同步；
- 高杠杆选择用可点击选项降低输入成本；
- 每个上游阶段完成后才进入下游；
- 失败状态必须有原因、证据和下一步；
- “检查了项目”“更新了一条时间线”等事件卡让用户知道 Agent 真做了什么。

官方 `talking-head-guide` 文档与这条实测对得上：A-roll 的最终语音时间线应先稳定，之后 MG、B-roll、音乐、字幕都绑定这条时间线；每个主要步骤通常要单独确认。[官方 talking-head guide](https://raw.githubusercontent.com/ChatCut-Inc/agent-plugin/main/codex/skills/talking-head-guide/SKILL.md)

## 6. 导出、资产准备和风险提示

点击 `导出` 只读查看了完整对话框，分为：视频、音频、MG 动画、字幕、XML。

- 视频：MP4/H.264、480/720/1080p、24/25/30/50/60fps；页面明确提示云端导出可能有问题，并警告一个 MG 使用了无法识别的字体，会静默回退到 Arial。
- 音频：单独导出 MP3，忽略视频轨道。
- 字幕：转录未完成时明确禁止导出，要求等待字幕轨道完成。
- MG：ProRes 4444，逐元素独立 `.mov`，保留透明通道。
- XML：Premiere Pro/达芬奇；可以打包素材，并明确 ChatCut 生成的配音、音乐、音效与本地已有素材的区别。

官方 `export` Skill 也要求导出前确认当前时间线、范围、分辨率、编码和格式；排队/运行中的 render 不能宣称已交付，并要报告 XML/字幕等不支持或丢弃的元素。[官方 export Skill](https://raw.githubusercontent.com/ChatCut-Inc/agent-plugin/main/codex/skills/export/SKILL.md)

## 7. 对 Nomi 的直接建议

### 建议的剪辑区结构

```text
┌──────────────┬──────────────────────────────┬──────────────┐
│ 素材/文字稿   │ 预览                          │ Agent        │
│ 可折叠        │                               │ 常驻可收起    │
├──────────────┴──────────────────────────────┴──────────────┤
│ 全宽时间线 + 选区/播放头/字幕/音频/检查器                    │
└─────────────────────────────────────────────────────────────┘
```

具体行为：

1. **默认**：Agent 常驻，宽度可拖拽/收起；发送时冻结当前选区、播放头、编辑器 revision。
2. **聚焦**：NLE/逐字稿模式可以隐藏 Agent，但顶部保留明确召回入口/快捷键；不另开第二套聊天状态。
3. **互斥协调**：Agent、任务中心、模型/设置面板共用一个右侧 dock 管理器，避免互相遮盖、重复审批。
4. **选区优先**：Agent 说“改这一段”时绑定选中的 clip/文字稿范围；播放头只作观察上下文，不能让提案在用户移动播放头后漂移。
5. **提案而非暗改**：读取是自动的；时间线写入先给 diff/预览，再通过一次 apply gate；生成资产和落时间线分开。
6. **状态可见**：每个操作显示 `检查项目 → 计划 → 等待确认 → 运行 → 已更新/需要处理`，失败必须有原因和下一步。

### Nomi 不应照搬的地方

- 不要照搬一键 `新建项目` 无确认。
- 不要让“自动允许生成”绕过费用/安全/模型能力 gate。
- 不要把资源卡/Skill 正文提到的工具名当成权限；权限必须来自阶段合同。
- 不要在字幕未就绪、字体不支持、媒体不可读时显示“完成”。
- 不要让生成模型负责精确节拍；音乐生成后由时间线处理 trim/loop/fade/ducking。[官方 music Skill](https://raw.githubusercontent.com/ChatCut-Inc/agent-plugin/main/codex/skills/music/SKILL.md)

## 8. 已验证与未验证

### 已验证

- 编辑器默认壳层与 Agent/时间线共存。
- Agent/视频生成模式切换及模型/时长/画幅/分辨率菜单。
- Agent 设置、音色、设计风格、Skill 选择器。
- 默认/NLE/逐字稿/竖屏四种工作区预设。
- 项目库网格/列表/排序、素材过滤、资源库分类和加载。
- Skill/风格/音色市场及外部 Agent 安装入口。
- 账户、积分记录、主题、语言、快捷键、升级价格页（仅观察）。
- 检查器、字幕样式、画幅比例和导出多格式入口。
- 真实项目中 Agent 的确认、时间线更新、失败重试和可恢复提示。

### 本轮没有触发，不能声称已验证

- 真实视频/图片/MG/音乐生成质量和实际扣费。
- 真正的购买、升级、导出下载、分享链接发布。
- 删除项目、恢复项目、多人协作冲突。
- 移动端/桌面客户端与不同浏览器的全部布局。
- 每一种 Skill 的完整执行链和供应商差异。

## 最终判断

用户说“剪辑区域也得放 Agent”是对的，而且 ChatCut 的实测已经给出答案：Agent 应该就在编辑器里，和素材、预览、时间线共享上下文；但它不是永远占满屏的聊天栏，而是一个可收起、可按工作区预设隐藏、又能随时召回的编辑器 dock。Nomi 的第一版应先把这个“同一项目、同一选区、同一时间线、同一提案状态”的闭环做对，再扩充更多 Skill 和生成入口。
