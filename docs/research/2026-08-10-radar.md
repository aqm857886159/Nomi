# Nomi Research Radar — 2026-08-10

## 一句话结论

近期最值得 Nomi 动的不是再堆一个生成模型，而是把跨镜实体记忆与可量化的镜间一致性接进现有 decompose-stitch 管线；同时把生成失败的可观测性做成产品能力。

## 🟢 可落地

### EntityBench — Towards Entity-Consistent Long-Range Multi-Shot Video Generation

- [arXiv:2605.15199](https://arxiv.org/abs/2605.15199) · 2026-05-14
- 洞察：跨镜实体一致性会随递归距离快速衰减，显式的 per-entity memory 明显提升角色保真度。
- 落点：在 `character_ref` / 设定卡数据结构中给每个角色、物件、地点保留可追踪的 memory 摘要，并由 storyboard 生成器按镜头显式注入；先做只读 schema 与 prompt 组装，不改供应商适配层。

### Retrieval, Refinement, and Ranking for Text-to-Video Generation via Prompt Optimization and Test-Time Scaling

- [arXiv:2603.01509](https://arxiv.org/abs/2603.01509) · 2026-03-02
- 洞察：生成质量对 prompt 结构极敏感，检索、重写、排序的闭环比一次性改写更稳。
- 落点：放到 prompt 优化节点，先记录候选 prompt、反馈信号和最终选择，形成可回放的最小 test-time ranking；待核实当前 prompt 节点文件名。

## 🟡 架构教训

### InfinityStory — Unlimited Video Generation with World Consistency and Character-Aware Shot Transitions

- [arXiv:2603.03646](https://arxiv.org/abs/2603.03646) · 2026-03-04
- 洞察：长叙事的核心不是单镜画质，而是背景、人物、空间关系与 shot transition 同时连续；每次接力都可能放大漂移。
- 对 Nomi 的影响：时间轴应保留 shot-to-shot 的证据与失败边界（参考帧、实体摘要、转场意图），不要只存最终视频 URL，否则无法定位是规划、首帧还是 t2v 接力造成的漂移。

### Soap2Soap — Long Cinematic Video Remaking via Multi-Agent Collaboration

- [arXiv:2605.17423](https://arxiv.org/abs/2605.17423) · 2026-05-20
- 洞察：多 agent 协作需要持久的语义骨架（结构化 screenplay）和动态分配的视觉锚点，不能让每个 agent 各自重述上下文。
- 对 Nomi 的影响：把 screenplay/storyboard 作为单一事实源，节点只引用版本化片段；审批、重试和替换都必须留下同一条上下文链。

## 🔵 对标基准

### MuSS — A Large-Scale Dataset and Cinematic Narrative Benchmark for Multi-Shot Subject-to-Video Generation

- [arXiv:2604.23789](https://arxiv.org/abs/2604.23789) · 2026-04-26
- 洞察：先保证局部 shot caption 准确，再评估全局叙事连贯，能拆开级联误差。
- 接入 eval：为 Nomi 每次生成保存 shot-level caption、实体标签和 scene-level 叙事摘要，分别算局部文本对齐、实体/场景一致性与全局连贯性。

### MSVBench — Towards Human-Level Evaluation of Multi-Shot Video Generation

- [arXiv:2602.23969](https://arxiv.org/abs/2602.23969) · 2026-02-27
- 洞察：多镜评测需要层级脚本与参考图，单镜 VBench 分数无法代表成片可用性。
- 接入 eval：把 scene、shot、subject 三层 rubric 固化到评测记录，先人工抽样建立基线，再逐步接入自动 VLM 评分。

## 上轮 vs 本轮 diff

- 新增：EntityBench 的实体记忆落点、MuSS/MSVBench 的分层评测建议，以及 prompt ranking 闭环。
- 延续：审批边界、阶段/镜头/实体 ownership、失败证据可见性仍是架构优先级。
- 本轮筛掉：其余检索结果未同时满足“近 6 个月、与 Nomi 痛点直接相关、可复现或可接入”的门槛。
