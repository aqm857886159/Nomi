# Nomi 论文雷达（2026-08-25）

一句话：昨天 EntityBench 只**诊断**了「跨镜实体漂移」，今天出现的 **GroundShot** 给了同一问题的**训练无关、模型无关的运行时配方**（在线实体记忆 + 按「谁会被后面引用」排生成顺序 + 生成后 grounding 校验才入库）——这正好是 Nomi 已有 `shotVerify` + storyboard anchor 两块能拼出来的东西，不用引模型、不用训练。

本轮最该动的两件事：

1. **把 GroundShot 的「实体记忆 + 排序 + 入库前校验」三步接到 Nomi 现有 `shotVerify` 管线上**：不是新造系统，是把 `gatherShotVerifyInputs → shotVerifyJudge` 的判定结果**回写成一个 per-entity 参考库**（entityId + 已验证首帧/canonical 引用），下一镜生成前从库里取参考——把「校验」从只读打分升成「攒可复用锚点」。这比继续堆更长 prompt 更能治漂移。
2. **把 storyboard 的镜生成顺序从「顺序」改成「依赖拓扑序」**：先生成「会被后面反复引用的实体首次清晰亮相」的那些镜，再生成引用它们的镜。落在 `StoryboardPlanEditor`/anchor 编译层，是一个纯调度改动，零额度可先在 6 镜回归集验。

## 🟢 可落地

### GroundShot：训练无关、模型无关的多镜一致性运行时配方

- 论文：[arXiv:2606.20799](https://arxiv.org/abs/2606.20799)（2026-06-18）。自带 GroundBench（实体级一致性诊断集）。**未见公开代码仓**（只有 arxiv HTML/PDF），但方法描述足够细可直接复刻，不依赖其模型。
- 洞察：观众判一致性的方式是「拿每个实体的后续出现去比它第一次清晰亮相」——所以别对整段视频求一致，要**对每个实体**维护记忆。四步：① 解析剧本抽出复现的角色/物体/地点、标出每镜的实体集；② 按「预测的参考来源镜」建依赖图、拓扑排序成生成顺序（先产被引用的，再产引用者）；③ 在线实体视觉记忆，存 canonical 参考 + 一致的补充参考；④ 每镜生成前取参考、选 t2v 还是 ref2v、生成后 **grounding 校验实体证据、可靠才入库**。
- 落点（已核实文件）：Nomi 已有半套零件。`src/workbench/generationCanvas/agent/shotVerify.ts` / `shotVerifyJudge.ts` / `gatherShotVerifyInputs.ts` = 现成的「生成后校验」（对应第④步的验证），今天只是**只读打分**；改成把通过校验的镜的实体首帧写进一个轻量 `entityRef` 库（`entityId + assetVersion + verifiedFrameRef`）。生成顺序落 `src/workbench/creation/storyboard/StoryboardPlanEditor.tsx` + anchor 卡（`StoryboardAnchorCard.tsx`）：把「每镜实体集 → 依赖图 → 拓扑序」编进 storyboard 编译合同。全程无需引论文模型或训练。

### CANVAS：把「视觉连续性」当成显式规划对象（agentic，用现成模型）

- 论文：[arXiv:2604.13452](https://arxiv.org/abs/2604.13452)（2026-04-15）。多 agent 框架，**用现成生成模型不重训**；未见公开代码。
- 洞察：与 GroundShot 互补——GroundShot 管「生成时取哪张参考」，CANVAS 管「规划时就把连续性写死」：显式规划 ① 角色连续、② 持久背景锚点、③ 位置感知的场景规划，三条连续性在**分镜阶段**就锁，而不是生成后补救。
- 落点：Nomi 的 storyboard 已有 anchor 卡（`StoryboardAnchorCard.tsx`）和 action 卡（`StoryboardActionCard.tsx`）——CANVAS 的「持久背景锚点 + 位置感知」正好补进 anchor 合同：每镜除引角色卡外，显式声明「继承上一镜的背景锚点/在场位置」或「这是新场景、锚点重置」。这是把昨天 InfinityStory 的「背景/转场要单独建模」教训**落成 storyboard 字段**的具体接法。

### PhyPrompt：纯 prompt 层、零样本跨模型的 prompt 改写器（P4 教科书样本）

- 论文：[arXiv:2603.03505](https://arxiv.org/abs/2603.03505)（2026-03-03）。**零样本跨异构 t2v 生成器**（在 Lavie / VideoCrafter2 / CogVideoX-5B 上均提升，最高 +16.8%）；未见公开代码。
- 洞察：**纯 prompt 层工作、不碰目标模型内部**——这正是 Nomi P4「与供应商/模型解耦」要的形状：一个改写器，输出保留用户原意但补齐（此文是物理常识）的 prompt，喂给任意后端。PhyPrompt 补的是物理，Nomi 可复用同一「RL/规则改写 + 跨模型零样本」骨架去补**镜头语言/一致性锚点描述**。
- 落点：`src/workbench/promptLibrary/`（现成的 prompt 库/AI 优化节点的家）。先不做 RL，先做规则版改写器：用户糙输入 → 结构化补全（主体锚点/机位/光线/连续性提示）→ 与后端解耦地发出去。把「改写器与模型解耦」定成 promptLibrary 的架构不变量。

## 🟡 架构教训

### VERTIGO：相机轨迹要靠「渲染预览 + VLM 打分」的导演在环闭环，而不是一把生成

- 论文：[arXiv:2604.02467](https://arxiv.org/abs/2604.02467)（2026-04-02）。**需要后训练**（基于视觉偏好的 DPO），非训练无关；未见公开代码。
- 洞察：VERTIGO 用实时引擎（Unity）把生成的相机运动渲成 2D 预览、再用 VLM 给预览打分，形成「导演-摄影」反馈回路；把「角色出画率」从 38% 压到近 0%。关键教训不是那个模型，是那个**闭环形状**：相机轨迹是「生成→渲染预览→打分→修」的迭代，不是文本一把出。
- 对 Nomi 的决策：Nomi 已有 3D 站位/导演台（`src/workbench/generationCanvas/nodes/scene3d/stagingBuilder.ts` + `stagingVocab.ts` + `StagingCaptureHost.tsx`）——这本身就是「渲染预览」那一环。可把「站位/机位预览截图 → VLM 判『主体是否出画/构图是否成立』→ 提示修正」接成一个可选校验回路（复用 shotVerify 的 VLM 通路），把「出画率」当成一个可量化的站位质量指标。不必上 DPO 训练，先要那个**评-修闭环**。

### Talker-T2AV：口型/音视频是「联合生成」在走，拼接式 lipsync 会被联合模型甩开

- 论文：[arXiv:2604.23586](https://arxiv.org/abs/2604.23586)（2026-04-26）。单一模型（共享 backbone + 模态专用解码器）**联合**产音频与口型视频，不是流水线；未见公开代码。
- 对 Nomi 的决策：确认昨天标过的 lipsync gap **仍是 gap**，且方向在变——SOTA 正从「先出画再贴 lipsync」转向「音视频联合生成」。Nomi 走 decompose-stitch + vendor 解耦，短期不追联合模型；但当接入带 lipsync 的供应商时，别把它当「后期贴一层」的可选滤镜，要把「这段是否需要 talking / 口型」作为**镜级声明**从 storyboard 一路带下去（谁在说话、说什么），供应商能力到位时才对得上。诚实标：Nomi 现无联合 lipsync，涉及口型的镜先明标跳过或降级。

## 🔵 对标基准

### DirectorBench：直接就是「我们这张卷」——checkpoint 级诊断而非一个总分

- 论文：[arXiv:2605.30090](https://arxiv.org/abs/2605.30090)（2026-05-28）。80 条结构化 metadata + 7 个用户画像 + 40 条 checkpoint 判据，跨 5 维：**剧本 / 视觉 / 音频 / 跨模态 / 稳定性**；覆盖 4 条长片工作流 + 6 个基座 LLM，14 名标注员做人评校准。未见公开 leaderboard/代码 URL（待核实）。
- 为什么是我们的卷：它**明确按 checkpoint 定位瓶颈、拒绝聚合成单一分**——这正是昨天定的 Nomi 评测纪律（别把整片压成一个 VLM 总分）。它的「稳定性」维度对应 Nomi 的跨镜一致性，「跨模态」对应音画对齐。
- 接法：把 DirectorBench 的 **5 维 × checkpoint** 结构当 Nomi eval 骨架，落 `evals/datasets/` + `evals/journeys/`。先只实现与 Nomi 阶段对齐的子集：script / visual / stability 三维，每维记「观察证据 + 修复动作」，跨模态/音频维等音频链成熟再开。用 `evals/verify-shot-smoke.mjs` 那套跑法，零额度可先跑结构。

### KathaTrace：给「镜间转场瓶颈」一把真尺子——转场**意义**能不能被复原（STG）

- 论文：[arXiv:2607.01312](https://arxiv.org/abs/2607.01312)（2026-07-01）。提出 **Semantic Trajectory Gap (STG)** 指标 + KathaBench-25K（5,000 叙事 / 20,000 转场 / 28,712 评测问题，分 text-only / image-only / text+image 三种证据条件）；未见公开代码 URL（待核实）。
- 为什么补 EntityBench 的空：EntityBench/帧级只测「实体/画面一致」；KathaTrace 测的是**语义轨迹坍缩**——分镜张张看着连贯、但「这一镜为什么接下一镜」的转场意义丢了。它测的正是 DirectorBench 指认、Nomi 时间轴 shot→shot 链的**中心瓶颈**。
- 接法：把 STG 的思路做成 Nomi eval 的一维 `shot_transition_meaning`：给一对相邻镜，问「只看图能不能推出叙事如何推进」——能不能复原 = 转场是否有意义。落 `evals/` 与 DirectorBench 骨架并列，作为「background_continuity」之外的第二条转场轴（昨天已把 `shot_transition` 列进维度，这里给它一个**可操作的判法**）。

## 本轮筛掉的噪音

8 个方向均做了定向检索。筛掉：AlcheMinT / OneStory / BachVid（多镜一致但结论与昨天 EntityBench 系重叠，不重复收）；MSVBench / MSAVBench / MTAVG-Bench（多镜/音视频 benchmark，但当前偏音频链、与 Nomi 阶段错位，等音频成熟再看）；VPO / RAPO++ / Prompt-A-Video（prompt 优化老条目，沿用既有结论，PhyPrompt 的「零样本跨模型」增量才收）；DiffuEraser / SkyReels-V4 / FlowEdit 系（视频编辑/inpaint，需接入具体模型且与 Nomi 当前主路不咬合）。

## 上轮 vs 本轮 diff（对照 2026-08-24）

- **新增**：
  - GroundShot（2606）= EntityBench 诊断问题的**运行时解**，训练无关/模型无关，可直接复刻接 shotVerify——本轮头条。
  - CANVAS（2604）把连续性提前到**分镜规划**锁，补 InfinityStory「背景/转场单独建模」的落地字段。
  - PhyPrompt（2603）= P4 解耦的 prompt 改写器样本（纯 prompt 层、零样本跨模型）。
  - DirectorBench（2605）+ KathaTrace（2607）两把新尺子：前者 checkpoint 级诊断骨架，后者给「镜间转场意义」一个可操作判法（STG）。
- **升级**：昨天「把镜间连续性拆成背景/状态两轴、别压成单一 VLM 总分」——今天被 DirectorBench（拒聚合分）和 KathaTrace（转场语义单列）双双印证，可从「原则」进到「有现成 checkpoint/指标可抄」。
- **不变**：Nomi 工程顺序仍是「字段不丢 → 状态可继承 → 校验真接线（今天升级为：校验结果回写成实体记忆）→ 再扩模型能力」。lipsync 仍是明标的 gap。
