Research brief / 2026-08-29

OpenMontage
像写软件一样制作视频

把 brief、调研、剧本、场景计划、素材、旁白、音乐和渲染，变成可检查、可回滚、可追溯的 Agent 工作流。下面说明它真正解决了什么，以及哪些边界适合 Nomi 借鉴。

一句话结论OpenMontage 最有价值的不是一套渲染器，而是把创作中间产物和人工闸门做成一等公民。Nomi 应借它的 artifact / checkpoint / provenance 思路，继续保留自己的 TimelineState、EditPlan 与 Adoption 真相源。

Positioning

Agent-native 的视频制作系统

OpenMontage 由 Agent harness 驱动，兼容 Claude Code、Codex、OpenCode 等工作方式，同时提供 OpenMontage Studio。它的产品假设是：人用自然语言描述目标，Agent 把目标拆成文件化的中间产物，人在人机闸门处确认，再进入昂贵的生成和渲染。

项目不是“点按钮自动出片”的黑盒。每一步都留下 brief、research、script、scene plan、素材来源、成本和渲染检查结果，方便局部重做与审计。

The Gate 的意义：付费生成前先把成本显示出来并等待批准。它把“模型能不能调用”改成“这一步是否值得花钱”，也让拒绝成为一种正常的项目状态，而不是异常。

Artifact 是状态

中间文件不是日志附件，而是下一阶段的输入。场景卡可以单独重做，避免一次小修改触发整条管线。

Scene card 是反馈单元

反馈可以落在某一场景：换素材、改镜头、改旁白或调整节奏。Agent 获得了明确的局部上下文。

Provenance 是交付物

素材来源、许可证、模型和生成参数都应可回看。视频“看起来对”不等于项目“可交付”。

Adopt

建议吸收

  • 把 brief、调研、计划、渲染诊断纳入 artifact 目录。
  • 在生成前显示镜头级和总成本，并记录批准事件。
  • 补 provenance、来源和许可证检查。
  • 把渲染后 ffprobe / 抽帧验证做成可复用 gate。
Keep out

不要直接复制

  • 不要把 OpenMontage 的 Python runtime 接进 Electron 主流程。
  • 不要把完整 edit_decisions 大 schema 塞进 Nomi 的时间线领域模型。
  • 不要让外部 store 绕过 Nomi 的 Adoption、revision 和 Undo。
兼容 #223：OpenMontage 的 artifact/checkpoint 思路与 Project Agent Host 的冻结 target、revision、content hash 是同一类“先锁定再写入”纪律；但本次创作区选区修复解决的是失焦后的视觉反馈，两者不应混成一套状态源。

协议与 Nomi 当前政策

工程判断不等于法律意见

OpenMontage：AGPL-3.0

AGPL 允许运行、研究、修改和再分发，但对“向他人提供修改后的程序”有更强的源代码提供义务；网络交互场景也不能简单当作只在本机运行。合并 OpenMontage 代码或形成基于它的派生服务前，应保留版权与许可证通知，提供对应源代码，并逐项审计依赖。

“参考架构”与“复制代码”是两件事：前者通常不触发代码许可义务，后者必须按实际复制范围、链接方式和分发方式做合规判断。

Nomi：AGPL-only，不要求 CLA

Nomi 当前 package.json 标记为 AGPL-3.0-only，项目只发布这一种开源版本，不要求贡献者签署 CLA。个人使用、内部使用和普通 fork 可按 AGPL 使用；修改后分发或提供网络服务时，应按 AGPL 提供对应源代码和许可证说明。团队可以收费提供合规的定制开发、集成、部署、培训和持续迭代，但不承诺隐瞒对应源代码的闭源 Nomi 版本。

行为通常要关注什么工程建议
只读 OpenMontage 的公开文档没有代码复制保留来源链接与核验日期
复制代码或 schema版权、NOTICE、对应源代码、网络交互条款在依赖清单和发行审计中登记，不用“只复制几行”规避
Nomi 接受外部贡献贡献者是否有权提交、来源与依赖许可证是否清楚不需要签 CLA；按 AGPL-3.0-only 接受贡献并保留必要的版权、许可证和来源说明
Nomi 为什么不再要求 CLA

旧版仓库曾用 CLA 为“AGPL 开源 + 商业授权”双轨准备贡献授权，但现行决策是只发布 AGPL-3.0-only。继续要求签字只会增加贡献摩擦，并不是 AGPL 的要求，因此已移除 CLA 机器人和签名账本；CLA.md 仅保留为旧链接的说明页。

边界声明：这里是基于仓库文件和官方页面的工程调研，不构成法律意见。具体分发、网络服务、静态/动态链接、商标和第三方依赖组合，应让熟悉适用法域的律师复核。
