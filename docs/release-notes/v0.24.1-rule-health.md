## 三、没拦住的

按上一版“条目主问题 + 已有结构拦截”的统计口径，本批没有整条缺拦截证据的项目；这不等于没有未拦住的形状。以下缺口不另增账本条数，也不另计一次“已解决”：

- **账本未结 2 条**：模型清单修复提交 `68219ce0c` 已随 #1423 合入，但条目仍 candidate / pending、completionCommits 为空；就绪夹具修复 `b04323a5e` 已随 #1378 合入，仍 reviewed、无 fixedInPr / completionCommits。代码保护可计档，不能替协调翻账或声称已获真实验收。模型清单的真实外部 AI 选型仍未验。
- **项目与安装升级**：位置合同仍列出默认目录回扫在部分读取路径制造临时身份、媒体解析在锁内重读、启动对账仍会写登记；Windows ACL、真实权限/杀毒、断电等未全覆盖。旧版卸载器在用户尚未先升级时仍会整目录删除。出处：组 1 两份位置/安装器合同 residual_risks；不能因新安装器有保护就说旧卸载器安全。
- **接入与协议**：能力声明从另一个进程更新后，已经打开的渲染界面会继续用旧清单/参数；旧目录不自动获得准确参数控件。视频字节路径 UI 取消接线与超长下载的渲染期限仍有缺口，旧行里的默认猜测路径和显式声明无法区分。出处：组 4 能力/协议合同 residual_risks；协议合同关于恢复再次下单的历史描述，已有后续 #1401，应以当前恢复合同为准，不重复当成新缺陷。
- **取回与重发**：恢复合同仍列出旧版已写成 provider_task_failed 的记录无法区分、无 Run 老记录/试跑在模型停用时的失败归类、观察者与前台同时下载可能多一份相同素材；试跑合同仍列出手改有效 JSON 等非真实写手形状可能堵住人工出口、旧单没有持久身份无法重建。出处：组 5 两份恢复/试跑合同。
- **生成卡死验收不能读旧合同就下结论**：`docs/evidence/2026-11-02-generation-lock-exit/verification.json` 的 paidRun4 已是 passed（提交 `8116ea8e6`，分镜/画布/列表/重启四段）；paidRun2 为 partial，paidRun3 因测试错误假设失败，均保留。paidRun4 的 Windows、打包版、真实文本模型、英文付费、实扣及独立复验仍未验证，并明记“批量确认缺托管告知，参考图请求早于托管同意”。因此不能把合同中较早的“真付费待跑”当当前状态，也不能把这次真图通过当全面验收。
- **坐标尺**：删主体后相机仍指向旧对象、只移动相机而未带主体、无可测量项时退静止仍未拦全。出处：组 6 合同 residual_risks。
- **反馈、参考和清理**：旧版已排队报告不会重新过新投影；接收端无幂等键仍可重复送达，原 Windows 卡住现场不可还原。非 Run 的试跑/辅助入口不记录链接拒绝，探测不确定时仍可发送原链；模型地区/防盗链拒绝可能先失败一笔。无 expiresAt 对象不删，清理超预算须跨小时。出处：组 7 各合同。雷达合同所说的“版本健康判停被称为没查成”已由 #1412、`scripts/daily-radar-session.node-test.mjs` 修复，不当现存缺口。
- **性能与发布**：弱 Windows 显卡、深色组底缺块量具仍有限；发布遥测只分 major.minor，无法比较 0.24.1 与 0.24.0，Agent 回合和真实安装完成无遥测，手动下载不受分批比例约束。`docs/release-process.md` 的 Windows 真装矩阵和同输入真模型前后对比仍标“待接线”；本次没有核到其 RC 收据，不能据此批准晋级。
