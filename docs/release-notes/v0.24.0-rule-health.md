# v0.24.0 规则体检

晋级前的体检记录（`docs/release-process.md` §5）。范围：v0.23.2 到 main 之间新增、或改成 fixed 的逃逸账本条目，共 119 条。写法实事求是：拦住了就写拦在哪一档，没拦住就写没拦住，账本没结的账也照实记。

档位按强弱：删掉 > 结构上做不出来 > 门岗自动拦 > 文字规则。

篇幅较长，只想看结论读「总览」「三」「四」「五」；「二」是逐组明细，每条账本条目恰好出现在一组的「条目」行里。

## 一、范围与口径

- **取法**：`git diff --name-status v0.23.2 origin/main -- tests/ux/full-walk/escapeLedger/`，117 条新增、2 条修改（`REC-20261007-receipt-upgrade-quarantine` 由 candidate 改成 fixed；`FB-20261007-quit-teardown-orphaned-lane` 的修复 PR 由 0.23.x 上的 #1067 换成 main 上的 #1104）。v0.23.2 的发布分支只带了这 2 条，其余都是 main 上新长出来的，对 0.24 来说就是整本账。按登记日期分：10-18（v0.23.2）之前登记的 104 条，之后登记的 15 条（其中 12 条已 fixed）。`USER-20261016-video-result-not-retrieved` 的 0.23.x 面已在 `docs/release-notes/v0.23.2-rule-health.md` 写过，这里只补 main 上的完整面。
- **状态**：fixed 75 条，reviewed 7 条，candidate 37 条。`check:escape-ledger` 对 fixed 强制要有根因合同、类检查和 PR 号，75 条都有。
- **分档口径**（每条取最强的一档，依据是它的根因合同和挂在条目上的类检查）：
  - 删掉：造成这一类的实现、说法或入口本身没有了，不需要再有守卫来守它不回来；
  - 结构上做不出来：唯一 owner、类型或签名，绕开它写不出来，或写了就被挂在 owner 上的类检查当场红；
  - 门岗自动拦：由普查、矩阵、静态扫描或计数门守着，owner 本身不强制；
  - 文字规则：只有规则文字。
  - 逐组的「条目」行里，已结账和「代码已拦、账本未翻」的条目后面标了计档：〔删〕删掉、〔结〕结构上做不出来、〔门〕门岗自动拦。
- **这次没做的**：没有重跑任何测试或门岗。核对的是：条目引用的类检查文件、合同里的类回归测试和 owner 文件是否真实存在（共 8 条的旁证路径已不存在，见「账本结账的缺口」）；另抽查了 5 个结构测试的内容（`electron/quitLifecycleGuard.test.ts`、`src/workbench/timeline/timelineGesture.structure.test.ts`、`src/workbench/generationCanvas/reactFlow/canvasLayerOrder.test.ts`、`src/workbench/common/richTextActions.structure.test.ts`、`src/design/outsidePress.structure.test.ts`）。档位按合同自述和这些抽查定。「结构」这一档牢不牢，取决于挂在 owner 上的那道普查认得出多少种写法，识别盲区写在各组「没拦住的」里。「没拦住的」里引用的合同自述残余，是合同写成时的口径，这次没有逐条复核是否已被后来的改动补上。
- **没结账的 44 条**按证据分四类：代码里已拦住、账本没翻 fixed（14）；只拦住一部分（5）；疑已被别的改动覆盖但没有对证（12，是推断，不算拦住）；没有任何拦截证据（13）。后两类合起来 25 条，都算「没拦住」。
