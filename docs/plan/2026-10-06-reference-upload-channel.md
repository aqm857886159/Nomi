## 根因（一句话）

| 反馈 | 直接原因 | 类根因 |
|---|---|---|
| NF-0928-0004 | Agnes 没有声明自己的参考图收法，`resolveAssetIngestionWithFallback` 按「目标 → 别家已接入 → relay → 匿名图床」排队，于是借了 APIMart 的上传接口、用的是用户在 APIMart 的账户；那一家 402，失败面只有一句 `api.apimart.ai: HTTP 402`，提示还说「走了免费图床」 | 收法只能按**供应商**声明一种，而同一家不同端点收法不同（Agnes 图片端点收 Data URI，视频端点只收公网 URL），于是整家都没声明、一律借别家；借来的通道失败时没人说那是哪一家的账户 |
| NF-0928-0001 | 「模型不存在」的英文措辞表要求 `does not exist`，自建渠道说的是 `Model not exist.` | 同一句话的非母语变体没进表（表本身要求出现 model 一词，不放宽到别的名词） |

## 要拍板（不在本 PR 里决定）

制作流程路径（`productionReferenceUrls`，Agent 付费卡）为了请求可封存，参考必须是 http(s) 地址，不收 Data URI，所以 Agnes 走制作流程时仍会借别家通道。两个方向：A 允许制作流程封存内联参考（按内容哈希封存，请求体变大）；B 保持现状，只靠本 PR 的点名失败面。推荐 A（参考图只给用户选的那一家，隐私与「别家余额」问题一起没了），代价是封存体积与制作流程改动面，排在收敛那条线之后。

## 方向检查（RW）

触发：`assetLocalization.ts` 第 4 刀、`runtime.ts` 第 6 刀、`classifyError.ts` 第 15 刀、概念「生成错误怎么说成人话」第 17 刀、`generationCommon.ts#observability` 第 17 刀。

### 0. 一句话根因
参考图「该怎么送」被声明在错的粒度（供应商）上，于是缺声明时的兜底（借别家）成了常态路径；错误文案又预设了兜底的某一种（图床）。

### 1. 归类表
| 提交 / bug | 直接原因 | 类 |
|---|---|---|
| 08-20 HTTP 413 | 只取第一条通道 | 通道排队 |
| NF-0928-0004（本次） | 端点收法没处声明，借别家 | 声明粒度 |
| NF-0928-0001（本次） | 措辞表漏变体 | 关键词表覆盖 |
| classifyError 其余刀（#1022 断线、#1047 未发出） | 新的失败类别接进分类器 | 不同类别，按码接入，与本类无关 |

### 2. 为什么会一直出现
供应商级声明只能写一种收法，凡是一家多端点收法不同，都会落到借用；而借用的失败属于另一家账户，文案按「图床」写死。铁律 ⑫：用户点「生成」以为只碰 Agnes，实际动了 APIMart 账户。

### 3. 不改结构会冒出什么
| 预测 | 怎么验证 |
|---|---|
| 另一家多端点供应商（如图片收 Data URI、视频只收 URL）同样借别家 | 内置种子里改图端点没有自己收法、供应商级也没有的清单（`rg assetIngestion electron/catalog`） |
| 借用通道 401 / 403 被说成图床连不上 | 本 PR 的失败行点名测试 |

### 4. 靶子独立性
报障文字逐字来自反馈附件；Agnes 收法以官方文档为准，不以我们的测试为准。

### 5. P0
上传本身不自写（复用既有策略）；「哪个端点收什么」是供应商事实的声明，属领域目录里的「模型接入」。

### 6. 推荐
本 PR：端点级声明 + 借用点名 + 文案去预设（补在正确的粒度）。后续：上面「要拍板」的 A。

### 7. 用户要权衡的核心
借用别家通道让「没有自己上传口的模型」也能用本机参考图，代价是图片经过另一家、失败可能来自另一家的账户；本 PR 让能直达的端点直达，不能的照旧借、但说清借了谁。
