## 重载前必须补齐的原有边界

| 状态 | 现有机制与缺口 | 原边界要求 |
| --- | --- | --- |
| 未发送文字、技能、附件、引用 | `workbenchStore.ts` 的草稿字段；项目 payload 未涵盖完整待发送状态。 | 恢复同一项目及原草稿，不自动发送，不丢附件/技能；不得用清空草稿来通过。 |
| 文稿、旧分镜、画布 prompt | `useProjectWindowLifecycle.ts` 等待 `persistActiveWorkbenchProjectNow`。 | 保留保存失败拒绝；等待实际编辑缓冲写入和落盘回执，不能只等定时器。 |
| Run 分镜编辑 | `useStoryboardRunHost.ts` 自有 session/flush，项目保存不会自动等待全部 session。 | 使用原保存队列，全部相关 dirty session 成功才允许离开；冲突保留本地输入。 |
| 未批准付款修改 | `spendCardDraft.ts` 按项目、Run、操作、报价和版本保存 localStorage 草稿。 | 读取校验与存储失败须可见；恢复不批准、不回写画布，不绑定新版无关请求。 |
| 运行任务与目标 | `electron/main.ts` 销毁旧窗口；`textStreamIpc.ts` 在 sender 销毁时 abort，renderer runner 的待执行批次依赖原进程。 | 本次不承诺跨重载续跑。活跃、待提交或结果未知时不允许重载；检查到销毁期间也不能再接入新任务。重开固定原项目/方案/节点。 |

现有 `hardReloadWindow` 是发出 IPC 后即返回的接口，不是保存、恢复、任务接管成功的回执。它不能独自承担上述保证。项目 save 返回 null 不能当保存成功；当前活动 Run/方案与节点选区不全在项目存档中，恢复位置也需原导航边界补齐。项目切换后台继续的现有证据不适用于窗口销毁。

## 推荐与执行界限

推荐评估 B 的空闲窗口版本：用户明确触发；原各状态 owner 完成保存并确认；保存失败、目标变化、仍有运行或结果未知任务时保持原窗口；重开只恢复状态，不重放提交。禁止自动刷新和循环刷新。持续资源损坏给出诊断，不承诺刷新可修复文件。

这仍是待验证的策略调整，尚未授权为新的 T7 放行标准。若实现要求把任务迁到另一套执行 owner、增加通用上下文系统或模块加载框架，停止该路线，不扩大成 T3。上游稳定运行时修复保持独立兼容性验证，不仓促换大版本或维护分叉。

架构检查唯一 owner；产品检查显式恢复及运行任务保护；设计只处理原错误区的真实动作说明；前端检查草稿/依赖/事件生命周期；后端检查保存回执与零重放；用户验收检查实际内容、目标和可编辑结果。独立反方源码审查记录 `/tmp/nomi-pr828-reload-feasibility.md`，不是运行证据。

## 必须保留的验收

1. 入口、必要共享依赖分别失败并解除；持续缺失也单独测。语法/执行错误独立分类，不盲重试副作用。
2. 两宿主通过原界面恢复后实际输入/点击；比对聊天、技能附件、文稿、两类分镜、节点、付款草稿及精确目标。
3. 保存失败与任务仍运行时窗口不销毁；明确操作连续点击也只允许一次恢复。恢复前后请求账本无新增批准或供应商提交。
4. 原红测保留；改变局部恢复为窗口重载时另记批准依据与新行为，不删断言制造旧标准通过。
5. 开发服务器、构建文件、最终安装包、真实供应商和 Windows 分别记录。当前未完成以上新路线验收，不更新 PR 为可合入。
