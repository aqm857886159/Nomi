## ★1 用户怎么用
打开应用 → 使用或不操作 → 关主窗 → 保存确认 → 空闲时 PID 消失；有未完工作时保持原关闭行为 → activate / 再启动 / 深链 / 通知叫回真正主窗。真实任务为：空库空闲关闭、辅助窗仍在时召回、真实本地导出中关闭并召回。主指标：空闲关闭退出成功比例 1/1；质量：各入口主窗恢复比例 1/1；护栏：忙或未知不自动退出比例 1/1。量具为 `tests/ux/desktop-window-lifecycle.walk.mjs`（zh/en）与下列行为单测；修前基线需实测，不预填。打包 Finder / Dock、Windows、卡死不在本刀承诺内。

### ★1b 连带界面
两个系统通知保持原文与深链目标，只改恢复的窗口身份；截图与凭据入口保持原窗口及项目租约，只共享显示操作；无新增文字。

### ★1c 老用户
不改项目 / 模型 / 设置，不需要数据迁移；旧数据与回退兼容。唯一变化：Mac 确知主、渲染两端全空闲，保存成功后关主窗真的退出；生成、导出和未知状态不新增策略。

## ★2 谁说了算
主窗身份归 `appWindowRegistry.getMainWindow`；恢复归 `mainWindowPresence`；生产工作归 `backgroundLaunch.hasInFlightProductionWork`；未派发队列沿用 `updateBusyGate` 单例及已有 report-busy 通道；退出归 `quitTeardown.requestQuit`；保存归 `windowCloseConfirmation`。只有原 busyGate 一份报告 Map，迁到既有工作 owner，更新读同一个实例。机器门图修前：ensureMainWindow 3 门 / 5 处，getMainWindow 6 门 / 8 处，hasInFlightProductionWork 2 门 / 2 处；核包装一跳包括维护重建、深链和两通知。

## ★4 全状态
空闲：保存成功后退出；加载：缺渲染报告保活；成功：主窗显示并聚焦；失败：记恢复失败、后续可重试；部分成功：工作或读取未知保活；取消中：不推断为空闲；过期：销毁窗口不能作主窗；能力不可用：沿原日志与原生无响应确认，不新增界面。中英文无文案变更。
