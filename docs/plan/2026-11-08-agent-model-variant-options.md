# 模型详情里的变体参数

- ★1 创作者要求 Fast、4K、无音频，只起草。实际 V4 Flash 读了 Seedance 通用 t2v 的 4K，把它用在 Fast，第一次 draft_shots 被拒。量具是只允许文字费的 P06、已有 modelSpecParity.class 的全型号对照和产物参数。合格条件是 Fast 详情只能把 480p／720p 列为合法清晰度，标准档仍可选 4K；无媒体请求。存量草稿及自建无档案条目不迁移。
- ★2 变体参数的合法范围归现有 specializeArchetypeForVariant；说明书只投影它的结果。应用内与 MCP 共享详情。薄名单不增加参数。
- ★3 历史上 modelSpecProjection 已把两个端的模型说明合为一份。只改提示词无法告诉模型实际范围，删掉变体会失去 Fast；沿用同一档案取值，比从准入错误反推参数更早。
- ★4 未点名变体时按 resolveArchetypeVariant 的目录身份判默认。点名变体时读它对当前模式的参数修订。顶层模式反映未点名时的实际默认档；其它变体的未改参数继承模式，移除的参数显式为空。
- ★9 P06 的 Fast 4K 拒收原文与详情对照；测试 Fast、标准档和 Mini；逐型号比较模式、变体与同一档案特化结果，覆盖移除与新增参数。薄名单不带详情；同一模型名的不同供应商仍隔离。真实模型修后同句只起草，记录工具调用、实落参数、是否有媒体提交。

APIMart 官方文档分别列出标准档的 4K 和 Fast 的 480p、720p；因此修订的是 Nomi 的说明投影，无须改变这两个档位的准入。 [Seedance 2.0 官方说明](https://docs.apimart.ai/en/api-reference/videos/seedance-2-0/generation.md)


## 修前修后实测

Mac 开发构建，真实 Electron Agent，APIMart DeepSeek V4 Flash。测量的是用户输入、工具返回、供应商实际收到的文字请求，以及项目内 Run 的镜头参数。问卡由测试驱动回答；两遍都向模型发送同一条 P06。实际扣款金额未知。

| 输入 | 工具结果 | 项目内结果 |
|---|---|---|
| 窗台橘猫，5 秒，只起草 | look_at_canvas 和 draft_shots 均一次成功。3 次文字请求，0 次媒体请求 | 一张角色锚、一镜视频草稿，该镜头的 duration 为 5 |
| P06 修前，Fast、无音频、4K、仅起草 | 8 次文字请求；Fast+4K 拒收一次，再起草成功 | Fast 720p，3 镜。对两次问卡，评测器均答“你定就好，按最稳妥的来” |
| P06 修后，同句 | 9 次文字请求；Fast+4K 仍拒收一次。之后问卡明确给出 Fast 720p 和标准版 4K，评测器选择后者 | Standard 4K、无音频，4 镜，0 次媒体请求 |

修前、修后都查了 Seedance 的具体型号（带 vendor 与 modelId），不止看薄名单。从真实文字请求经脱敏的网络账本中核了两份工具正文的相同位置。修前 t2v.resolution.options 列 480p/720p/1080p/4k，fast 与 standard 条目只列标识。修后 t2v.resolution.options 只列 480p/720p，standard.parameterOverridesByMode.t2v.resolution 明列 1080p/4k。详情默认变体是 fast。修复让模型有正确的约束可读；上述单次对照没有观察到第一次参数拒收减少。最终的标准档选择来自评测器，不能当作用户偏好。

已有 39 题的旧基线有 31 道可判，P06、P30 同错均达三次。它们是不同时间、不同目录条件下的结果。另用受控模型重放已登记的宿主请求上限反例，设 5 时仍观察到 11 次模型请求、10 个立即结果、0 个落盘镜头。这个现象归回合预算；P06 的两次当前样本都没有撞到这类连续循环。
