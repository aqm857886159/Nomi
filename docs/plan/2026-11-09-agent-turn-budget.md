# Agent 回合止损真的生效——被叫停的工具再被发一次，这一轮就结束

> 设计卡（9 格全填：长跑 / 可打断——一回合几十次模型请求、这一刀就是「什么时候打断这一轮」；不碰付费生成路径，但空转的每一次都是一次付费的模型请求）。
> 来源：用户 11-07「经常出现什么参数不对 重试等问题」；免费复现：工具一直被拒时，上限 5 的回合发出 11 次请求，生产缺省没有上限、只要模型不听就一直空转。
> 方向检查：`docs/engineering/direction-checks/2026-11-09-agent-lane-retry-loop.md`（独立复盘 + 用户 11-09 拍板「按推荐改」，并补「但更多的还是我们说的 要把这个地方根源解决」）。
> 不做：生产默认总步数上限（09-18 用户删掉的 24 不恢复）；放宽止损去照顾「第 4 次才写对」（那笔账算在根因修复上，见 ★9）；首次参数写错的根因修复（另一条线，本卡只交「为什么模型会一直写错」的证据）。

## ★0 先查别人

| 出处 | 它怎么做 | 对我们哪个决定的影响 |
|---|---|---|
| Vercel AI SDK Loop Control https://ai-sdk.dev/docs/agents/loop-control （2026-11-09 读） | 停止由**循环层**的 `stopWhen` 按每步结果判断（`isStepCount` 只是其中一种条件，可自定义）；`prepareStep` 管每步配置 | **改了**停止的位置：从工具钩子（`before_tool`，立即结果到不了）挪到循环层的请求入口，一处判所有结果；**确认了**不照搬默认步数 |
| OpenAI Agents SDK `max_turns` → `MaxTurnsExceeded` https://openai.github.io/openai-agents-python/running_agents/ （2026-11-09 读） | 只有全局轮数上限，到了抛异常，由应用决定怎么收尾；「同一工具反复失败」框架不管 | **确认了**全局上限只当实验旋钮（宿主 `limits.maxModelRequests`），生产缺省不设；「同一工具连败」这类领域止损要我们自己判 |
| Claude Agent SDK `maxTurns` → `error_max_turns` https://code.claude.com/docs/en/agent-sdk/typescript （2026-11-09 读） | 同样是全局轮数上限，缺省 `undefined` = 不设；到了以 `error_max_turns` 子类型的结果消息结束这次查询 | **确认了**收掉一轮时已成功的内容保留、运行状态明确结束，不回滚已做的 |
| pi-agent-core 0.85.1 `requestAbort`（`dist/harness/agent-harness.d.ts`、`runtime/lane.js`） | 持久化 cancel_requested、驱动闸置 aborting（下一次 `streamSimple` 之前就拒），交回还没被消费的 steer / followUp；`abort()` 还要等 drive 收尾 | **改了**终止手段：用现成原语，不自造取消循环；钩子里只 await `requestAbort`，不 await `abort()`（会等自己）；交回的用户输入由宿主排回队里 |

出口：pi-agent-core `requestAbort`（`runtime/lane.js`）· 取消后把没被消费的用户插话交回调用方、会话照常可续 · 改变了我们的出口：被收掉的这一轮之后，用户再说一句话（新 prompt / 插话被吃进去）就清零，工具重新可用；那一刻排着的话原样排回队里（看得见、能撤回、随下一句话一起发），不丢。

## ★1 用户怎么用

当我让 Agent 起草镜头、它的参数一直写不对时，我想它**有限地自己纠正几次，然后明确停下、保住已经做成的**，以便我不用盯着它空转、也不会白付一串模型请求的钱。

1. 我说「起草 3 个镜头」；Agent 调 `draft_shots`。
2. 参数错了：拒收正文点名出错字段和该填什么（保留，上一刀的成果）。
3. 同一个工具自上次成功以来第 3 次失败：正文末尾加一句「别再发它；再发一次这一轮就立刻结束；换条路，或用 `ask_user` 问我」——换一个错字段**也算在内**。
4. 模型照做：换路或问我，回合照常继续。
5. 模型不听又发了它：这一次不执行，这一轮**在下一次模型请求之前**结束；面板那一行说「这一轮先停在这里，这一步没有执行。你回一句话，它就能接着做。」
6. 我回一句话：清零，工具重新可用；停点那一刻我排着的话也一起发过去。

不做什么：不设生产默认总上限；不在钩子里 await 等自己收尾的 abort；不改参数校验 / 字段诊断 / 审批。
已知坑：①每次错一个不同字段、正在往对的方向改、第 4 次才写对的，会在第 4 次被停（代价，见 ★9 与方向检查末节）；②被收掉的一轮在 trace 里记成 `cancelled`，和用户按停止一样（残余）；③未知工具名第 3 次失败时没有「停」那句话（pi 的未知工具结果不经过我们的正文），第 4 次照样收掉。

真实任务：
- 用户 11-07 那一类：`draft_shots` 连撞参数（1080P / 4k、`duration` 写在镜头上、`parameters.aspectRatio`）——假模型端点按同样的错写序列回放，修前修后各一次。
- 正常长任务：30 步全成功的回合（09-18 用户删上限时要保的那件事）。
- 参数评测里「第 4 次才写对」的三道题：真模型重跑（协调跑，见 ★9）。

指标：
- 主指标：工具一直失败的回合里，停点之后多发的模型请求数（目标 0；修前 = 脚本剩多少就发多少）。量具：`electron/agentLane/laneToolInputBoundary.test.ts` 的假模型请求计数。
- 护栏：全成功回合被停的比例（目标 0%）。量具：同文件「30 步全成功 → 31 次请求」+ `tests/agent-runtime/lane-resilience.test.mts`「缺省不设上限」。
- 质量：参数评测三道「第 4 次才写对」的题在 3 次以内写对的比例（目标 3/3）。量具：参数评测走查（真模型，未验证：本线不跑真模型）。

### ★1b 连带界面

- Agent 面板失败行（`tool_retry_stopped` 那句）：旧文案「同一处连着填错了 3 次，这一轮不再重试，它会直接问你。」/「It got the same field wrong 3 times … will ask you instead.」是错的（这一轮已经没有下一次请求，它不会再问你）。改为：zh「同一步连着失败 3 次后它还在重试，这一轮先停在这里，这一步没有执行。你回一句话，它就能接着做。」；en「It kept retrying a step that had failed 3 times in a row, so this turn stopped here and the step did not run. Reply and it can carry on.」。只改词条文字，不改布局；截图见 ★9。
- 模型读的正文：第 3 次失败那句改成数「自上次成功以来连败几次」并说清再发的后果；停点那句不再承诺「现在总结」。
- 运行状态：这一轮结束后面板不再显示在跑；已成功的工具结果都在。

### ★1c 老用户

升级后：已有会话转录不重写，旧的失败行照旧显示（码不变，只是那句话换了）。计数是内存态、每条 lane 新建，升级不带旧状态。宿主上限只有实验脚本传，生产装配不传，行为不变。退回上一版：转录格式没变，照常打开。

## ★2 谁说了算

- 「这一轮该不该停」唯一 owner：`laneTurnBudget.mts` 的 `before_request` 钩子（按 runId 记请求数和 `turn.over`）；宿主只装配，执行手段只有 pi `requestAbort` 一处（`door-map requestAbort`：1 扇写门）。
- 「这个工具连败几次」唯一 owner：`laneRepeatedFailure.mts`（按工具名一份，`door-map createLaneRepeatedFailureTracker`：1 扇写门，宿主创建）；写入只经入参边界的 `settle`（入参拒收 + 宿主 `after_tool`）和宿主 `tool_end`（只记未注册的工具名）。
- 「宣布到此结束」：入参边界拿到 `turn.end()`，只能宣布、不能自己停；停只在请求入口发生。
- 修前：预算在 `before_request` 计、`before_tool` 判（两处，后者被立即结果绕过）+ 墙按「码 + 字段」分桶；修后判断只剩请求入口一处，计数只认工具。
- 清零点：用户消息被这一轮实际吃进去（`message_end`，role=user）；答卡 / 改口两处照旧；排队那一刻不再清零。

## ★3 一致与复用

- 以前定过什么：09-18 用户「不要给什么次数限制」——删的是默认 24 次总上限（`91e3ec137`），本卡不恢复；11-07 定了「同错 3 次就停、转 ask_user」——保留阈值 3 和转问用户，改的是「同错」的口径（复盘：换错字段不能再绕过）和「停」的执行（复盘：运行时真的停）。
- 三条路（见方向检查第 6 节）：沿原方向补钩子（不选：绕不过立即结果）/ **接 pi 的取消原语**（选）/ 删掉自写熔断（不选：用户得盯空转）。
- 复用：pi `requestAbort`、`lane.steer / followUp`（排回交回的输入）、既有入参边界与拒收格式器；不新增 fallback。
- 同提交删：`before_tool` 里的预算判断和「State your conclusion … now」措辞；`laneWallKey` 与按「码 + 字段路径」分桶；墙立着时只回不执行的立即结果、回合继续的那条路径；`note()` 的 body 参数；排队时清零。
- 残余：surface / 访问 / 审批拒绝不进计数（它们不是「模型写错」，且审批有自己的出口）。

## ★4 全状态

- 空：没有工具调用的回合不受影响（`lane-resilience`「阳性对照 · never calls a tool」）。
- 加载 / 进行中：失败 1、2 次照旧显示拒收行；第 3 次行文末带「停」那句（模型读）。
- 成功：每步都成功的回合不计数、不被停，30 步 31 次请求。
- 失败（停点）：那一行「这一轮先停在这里，这一步没有执行。你回一句话，它就能接着做。」；面板不再显示在跑。
- 部分成功：停点之前做成的草稿留着；同一批里排在停点之后的调用不执行、各有一条结果。
- 取消中：用户手动停止与宿主收掉走同一个 pi 原语；宿主收掉时没有在跑的工具（停点在两次请求之间），不会留半截。
- 过期：老会话里旧的 `tool_retry_stopped` 行用新文案显示。
- 能力不可用：不涉及（这一刀不碰模型 / 供应商可用性）。

## 5 中途表

| 时刻 | 发生什么 | 用户看到 |

| 停点那一次调用 | 入参边界 `turn.end()`，这一次不执行 | 一条失败行 |

## 6 外部数据与失败

- 模型请求：停点之后不再发，所以不会多付一次。
- `requestAbort` 返回失败（lane 已关闭等）：不排回、照常结束；交回的输入排回失败只记日志（`lane-turn-requeue-failed`），不抛给用户。
- 未知工具名：pi 自己给立即结果，宿主在 `tool_end` 里记「未知工具」一份计数。

## 真实场景复现

- 用户那次：11-07 反馈「经常出现什么参数不对 重试等问题」，Agent 起草时参数一直被拒、一直重试。
- 我怎么走：同一条真 lane（pi + 入参边界 + 契约 + 准入），假模型按同样的错写序列逐字回放；数一回合实发的模型请求、执行了几次、最后状态。
- 差在哪：模型是脚本，不会「读懂」拒收后改口——它只测「模型不听时运行时停不停」；真模型会不会照「停」那句转路，要真模型重跑（协调跑）。
- 修前：上限 5 的回合 10 个错调用发 11 次请求；生产缺省同样 11 次（脚本有多长就发多长）；换错字段熔断一次不跳。
- 修后：同样的序列都在第 4 次请求后结束，0 次多发；30 步全成功 31 次请求不被停。
