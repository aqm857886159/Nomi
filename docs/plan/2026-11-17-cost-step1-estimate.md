## ★1 用户怎么用

当我在画布节点上准备点生成时，我想在发送键上直接看到这次大概花多少积分、改了参数数字跟着变，以便点之前心里有数；算不出来的时候不骗我。

步骤：①选模型、调参数 → ②发送键上出现硬币图标 + 积分数（约数）→ ③改时长 / 分辨率 / 张数，数字跟着变 → ④鼠标停在键上：一句话说明这是按 APIMart 公开价估的、出完按 APIMart 实际扣费记 → ⑤点发送，照原来的流程走。

不做（明确归别的步骤）：余额、缺额、「去充值」（第三步）；单位切换（第二步）；设置里的账户卡（第三步）；搜型号（第四步）；批量和助手确认处的积分数（已由 11-15 的确认条拆分接管）；生成之后的实扣来源详情。
已知坑：旧 PR 把「读账户余额」和「显示约价」写在同一个钩子里，余额过期后画面不回退的毛病就出在那一段——第一步**不接账户**，那一段不摘。

真实任务（供应商和价目都指到本机回环的假服务，不连真供应商、不花钱）：
1. 文生视频型号，5 秒 720P：键上出现硬币 + 积分数；悬停一句说明含积分数和美元约数。
2. 把时长改成 10 秒、再改分辨率：数字各变一次，等于假价目里对应规格的价；中途不闪 0、不闪旧数。
3. 份数（协调 11-17 改）：主分支上 APIMart 的出图 / 出视频型号没有数量参数，界面上没有「×N」这个操作，真窗口走不了——这一条由单测守（单价 × 份数，含份数为 2 的用例），真窗口记 unverified。乘法代码保留，以后加数量参数时价格不会少算。
4. 一个价目里没有的型号 / 带参考图而价目没写附加费的：键上只有箭头，不印数、不印 0；悬停「暂时估不出这次用量」。
5. 假价目服务回 500 或超时：同任务 4，发送照常可点。
6. 只看价格、不点发送：假服务收到的生成请求 0、花钱授权 0。

指标与量具：
- 显示的数 = 假价目里那一格的价 × 份数，逐项相等 · 量具：走查脚本读键上的数和假服务的价目对账。
- 没有公开价时印出数字的次数 = 0 · 量具：同一脚本读未知各态的键面文字。
- 只看价格产生的生成请求 / 花钱授权 = 0 · 量具：假服务请求记录 + 主进程授权计数。
- 参数改动到新数字出现的耗时 · 量具：`tests/perf/scenarios/` 新登记的场景（见 ★7）。

## ★2 谁说了算

- 请求长什么样：主干现有的请求构造（`buildCatalogTaskRequest`），约价只读它的结果，不另拼一份。
- 价格：主进程里的公开价读取（`vendorPricePreview`），界面只拿结果；公开价 GET 不带凭据。
- 显示成什么字：一个格式化函数（积分数、美元约数），发送键只管画。
- 约价不是许可：能不能发、要不要确认，仍归原来的发送流程；约价这条链上没有任何一处能创建任务或授权。
- 链（准备线读过原文）：请求构造 → 约价钩子 → IPC → 请求投影成询价 → 读公开价 → 格式化 → 发送键。门数由实现线用 `node scripts/door-map.mjs` 重数。

## ★4 全状态

- 空（没选型号 / 没有 APIMart 连接）：只有箭头。
- 加载（算价中）：新价 300 毫秒内回来，键上从旧数直接换成新数，中间不闪；超过 300 毫秒没回来，收成只有箭头，回来再显示。不加转圈，不闪 0。
- 成功（有价）：硬币 + 数字。
- 失败（价目读不到）：只有箭头，悬停「暂时估不出这次用量」。
- 部分成功（多份里只有单价）：单价 × 份数；份数未知按未知。
- 取消中 / 生成中：照现有忙态，键上不显示新的约价。
- 过期（参数变了、旧响应后到）：只采用和当前参数对得上的那一次响应。
- 能力不可用（非 APIMart、自定义模板、价目没写附加费）：未知。
- 禁用（不能发送）+ 有价：键是禁用样子，数字仍可读。
- 最大值：最长数字按价目里真实的上界画一张（实现线从假价目里取最贵规格 × 最大份数，写下是多少）；英文；最窄的节点宽度；暗色。

## 6 外部数据与失败

- 公开价目接口：字段名、单位以旧 PR 里验过的回放为准；返回形状不认识、缺规格、非 2xx、超时 → 一律未知，不猜、不补 0。
- 价目请求的地址：不写死主域名。不开代理的国内创作者主域名连不上，应用会自动换到官方备用地址（现有的备用地址机制，生成 / 轮询 / 上传都走它）；价目请求也经同一处改写，不在约价这条链上另写一份域名（协调 2026-11-17 补，用户同日提醒「接口地址要注意更新」）。
- 价格是公开折后价，会员实扣可能更低：悬停句只说「按公开价估」「按实际扣费记」，不说「将扣」。

## ★7 性能

- 新增的操作：改一个参数 → 键上数字更新。最坏规模：画布上 40 个节点各开着底栏、连续改 10 次参数。
- 预算：改参数到新数字出现 ≤ 200 毫秒（含防抖）；改参数这一下的界面响应不许比没有约价时更慢（同机交替量主分支 / 本分支各 5 次，中位数差在量具噪声内）。
