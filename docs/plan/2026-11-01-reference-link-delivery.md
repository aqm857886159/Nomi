# 参考素材的临时链接失效后，改用本机文件（设计卡）

改动名：参考素材发给模型前先确认临时链接还活着。类别：[花钱][长跑]。实现线和验收线分开，验收线编号见 PR 正文。

方向检查：`docs/engineering/direction-checks/2026-11-01-reference-link-delivery.md`。

## ★0 先查别人

1. 一家媒体生成托管服务的数据保留文档 · API 产出的文件默认一小时后删除，要求用户自己存副本 · **确认了**「本机文件才算数，不按固定寿命信任链接」，也说明 48 小时不是普遍事实。
2. 一家模型聚合服务的错误码文档 · 服务器下载不了输入 URL 时返回 422，错误有稳定的 `type`（`file_download_error`），标明不可原样重试，并要求不要解析人话字段 · **改了**：判据先看上游错误码再看文字；**确认了**不自动原样重发。
3. 一家模型 API 的开发者论坛（`invalid_image_url`，「Timeout while downloading」） · 同一张图浏览器打得开，API 仍会拉取失败，而且时好时坏；建议下载后直接发字节 · **改了**：本机试探通过不算数，必须有「模型拒绝后这条连接改走上传」这条回路。
4. [对象存储预签名链接文档](https://docs.aws.eu/AmazonS3/latest/userguide/using-presigned-url.html) 和 [pulp #9595](https://pulp.plan.io/issues/9595) · 预签名链接只对签名时的方法有效，GET 签名的链接用 HEAD 会得到 403；有效期在请求到达时判定 · **改了**：试探用 GET 加 Range，不用 HEAD；**确认了**一次试探只说明当下有效。

5. 一家云厂商模型平台的错误码文档、一家模型 API 的开发者论坛原帖 · 逐字列出模型下载不了输入时的原话和错误码 · **改了**（第 4 轮）：判据换成原话表。查证时还发现之前当成真实原话的 6 条说法查不到出处，全部不登记。

没找到把 Range GET 当正式有效性探测的权威出处，这是我们的工程判断；误判的代价已按下面的方向压低：判错成「活着」最多模型拒绝一次，判错成「失效」只是多一次上传。

## ★1 用户怎么用

当我引用一张刚生成的图或视频做参考、点生成时，我想它照常出结果，不用管那条临时链接过没过期。

1. 生成一张图。
2. 过一段时间，在下一个节点把它当参考。
3. 点生成，确认花钱卡（如果有）。
4. Nomi 在「提交中」试一下这条链接。
5. 还活着就发这条链接；明确失效就上传本机文件，发新链接。
6. 出结果。

不做什么：不加按钮、设置和提示；不自动重发付费请求；不让用户或 Agent 填链接寿命；不改 48 小时窗口（超过 48 小时的图照旧上传，不试探）；不处理本机没有文件的公网链接，只把错误说清楚。

已知坑：本机打得开不等于模型拉得到；`resolveLocalAsset` 里的第二处捷径会把判死的链接再发一次；探针失败不能当失效（本机网络不通时模型可能拉得到）；内网和回环地址的链接（自建服务）被出站策略拒绝时要和今天一样照发；做片返工发的是上一次批准冻住的链接，不经过决定点；试探和上传期间点停止，今天就拦不住提交。

真实任务：
- 接中转的创作者，生成图一小时后引用（链接已失效）。
- 分镜批量 26 镜，共用 3 张角色图。
- 老用户升级后，引用升级前刚生成的图。

指标和量具：
- 主指标：链接明确失效时，发出去的是可用的新链接，POST 仍只有一次。量具：`electron/catalog/referenceLinkDelivery.matrix.test.ts`。基线：主线全错（发死链接）；目标：全对。
- 质量指标：链接活着或判断不了时，请求和主线逐字相同。量具：同一矩阵，加 `electron/catalog/upgradeKeepsWorkingModels.test.ts`（断言不改）。
- 护栏指标：一个请求增加的等待不随参考张数累加；同一张图在批量里只试一次；试探不调用模型。量具：perf 场景 `reference-link-probe`，加矩阵里的并发和去重行。

## ★1c 老用户

升级那一刻：项目、素材、`.meta`、目录、设置都不动，没有迁移，目录版本不变。

三条路：
- 什么都不做：链接活着，请求和升级前一字不差，多一次试探。
- 试探失败：明确失效的转上传，这和升级前超过 48 小时的图走同一条路；判断不了的和今天一样照发。传不了时在发请求之前停，今天这种请求发出去也是失败。
- 模型拒绝：记下这条连接，之后走上传。

退回旧版本：多出来的 `reference-link-refusals.json` 没人读，行为回到今天，不影响打开。

Preview / RC 首次启动：这份记录和连接一起带过去（`electron/settings/sideBySideInstallSeed.ts`），不带的话要再被模型拒一次才知道。

证据：`upgrade-path` 用 `tests/fixtures/old-user-data/` 里由 0.24.0 真实函数落盘的素材和 `.meta`（`assets/v0.24.0-generated`）跑矩阵。

## ★2 谁说了算

- 「这次发链接还是传文件」：唯一决定点 `electron/catalog/assetLocalization.ts#localizeAssetsForVendor`（新概念 `asset.reference-link-trust`）。删掉 `resolveLocalAsset` 里的捷径。
- 试探：`electron/assets/providerMediaFetch.ts#probeProviderLink`，这个文件本来就是「从供应商取东西」线路和超时的 owner。
- 「这条连接的模型拉不到临时链接」：`electron/catalog/referenceLinkRefusals.ts`，一份小配置文件，只有 Run 写入，只有 `assetLocalizationOptions` 读。
- 「这句失败是不是模型拉不到参考」：`electron/shared/assets/referenceFetchRefusal.ts`，不依赖 electron，主进程和渲染层共用这一份，不再各写一份。
- 做片返工：沿用上一次批准冻住的链接表（`authorizedReferenceUrls`）之前，先问同一条规则。这条连接拒绝过，或冻住的链接明确失效，就重新走 `resolveProductionReferenceUrls`；否则沿用，不重传。

同一份事实只存一份。没有靠「东西不见了」猜意图。

## ★3 一致与复用

- 上传：现有通道链，不新增通道。失效链接的走法和超过 48 小时的图完全相同。
- 网络：`hardenedFetch`（出站策略、跳转逐跳检查、不带 Key、`throwOnNon2xx:false`）。服务器忽略 Range 时会超过字节上限并抛错，读抛错上的诊断（状态码和类型），不算失败。
- 配置文件：`configFileStore` 和 `getSettingsRoot`，和 `automationPolicySettings` 同一写法。
- 错误卡：现有 `NodeErrorReport` 和 `reportFor`，不改卡片结构。传不了时用现有的 `asset-upload-failed`。

## ★4 全状态

| 状态 | 用户看到什么 | 请求 |
|---|---|---|
| 没有临时链接，或超过 48 小时 | 和今天一样 | 上传，不试探 |
| 试探中 | 「提交中」 | 还没发 |
| 链接活着 | 「提交中 → 生成中」，无提示 | 和今天逐字相同 |
| 判断不了（超时、断网、5xx、429、416、出站策略拒绝） | 同上 | 和今天逐字相同 |
| 明确失效（其余 4xx，或 2xx 返回网页、JSON、文本） | 同上，多等一次上传，无提示 | 新链接 |
| 明确失效且上传全失败 | 现有卡「参考图没能送到服务商」 | 不发 |
| 明确失效且只剩公共托管，未同意 | 现有的公共托管确认或拒绝文案 | 不发 |
| 模型拒绝（提交被拒或任务失败） | 新错误卡，主按钮「重试」 | 已发一次，不重发 |
| 重试 | 「提交中 → 生成中」 | 这条连接改走上传，不再试探；做片返工同样换新链接 |
| 试探或上传时点停止 | 和今天「提交中」点停止一样，节点回可生成，结果由观察者收进项目 | 照发，和今天一样拦不住；做片入口 Run 已失效时不发 |

新错误卡文案：

- 中文标题：模型取不到参考图
- 中文说明：模型那边取不到这张参考图的链接，可能已过期或被拦。点「重试」时，Nomi 会尽量改用你电脑上的原图上传后再发。还是不行就换个模型；这张图本机没有原文件的话，换一张或重新生成。
- 英文标题：The model could not fetch a reference image
- 英文说明：The model could not fetch this reference image's link. It may have expired or been blocked. When you retry, Nomi tries to upload the original file from your computer and send that instead. If it still fails, switch models. If the image has no local file, replace it or generate it again.
- 动作：主按钮重试，次动作换模型（上传过模型还拒绝时，这是唯一的出口）。不提扣费（`narrate.ts` 现有规矩）。

能力不可用：本机没有文件的公网链接，下一步是换图或重新生成，卡片说明里已写。

## 6 外部数据与失败

- 临时链接：来源是服务商返回。认 2xx 的开头字节和类型；Range 被忽略时截断读取；跳转逐跳走出站策略。规范：[RFC 9110 Range](https://www.rfc-editor.org/rfc/rfc9110#name-range-requests)。偏差：不解析 `Content-Range`，因为只问活不活。
- 模型的失败说法：一张原话表，上游错误码加服务商真实说过的整句，逐字比对，不用正则；没有出处的不登记，没说是输入的不收；不按服务商写分支。认不出的和今天一样落「认不出原因」，发送前的试探还在。中文说法查不到原话，表里没有。
- 未知失败不甩锅给用户的 Key。

## ★7 性能

- 新增操作：点生成时的一次试探。不新增界面操作，不占主线程：试探是主进程异步网络请求。
- 最坏规模：一个请求 14 张新参考图；批量 26 镜共 30 张不同的图。
- 预算：一个请求增加的等待 ≤ 最慢那一次试探，不随张数累加；单次上限 4 秒；批量里同一链接只发一个 GET；活着或判断不了的结果记 5 分钟，失效的记到进程结束；下载量每条约 1KB。
- 场景：`reference-link-probe`（`tests/perf/reference-link-probe-bench.mjs`，真函数加本地假服务，固定延迟 200ms，主指标是超出一次往返的毫秒数，预算 100ms）。基线由协调在安静窗口写。
- 真实链接实测（协调 11-01，同一条链接 10 次）：约 1.2 秒，其中加密握手约 0.8 秒；走不走代理差不多。样本只有一条。

## ★9 验收与回滚

验收线核下面每一条，反例由实现线做过并还原，验收线再挑两条自己做。

矩阵（`electron/catalog/referenceLinkDelivery.matrix.test.ts`，真 `localizeAssetsForVendor`、真试探函数、本地 HTTP 假服务，上传函数注入，`NOMI_TEST_NETWORK_GUARD=1`，不出网）：

- 链接状态：206 图、200 图且忽略 Range 并返回大文件、200 octet-stream、跳转到 200、跳转到 403 → 前三个和跳转到 200 发原链接，跳转到 403 转上传；401、403、404、410、400 → 转上传；200 HTML、200 JSON、200 纯文本 → 转上传；429、408、416、500、503、连接被拒、挂起到超时、出站策略拒绝 → 发原链接。
- 上传：自家通道成功；第一条失败第二条成功；全失败 → 抛现有错误且 POST 0 次；没有通道 → 抛现有错误且 POST 0 次；只剩匿名通道且同意为 allow、ask、deny 各一行。
- 媒体：图片、视频、音频。
- 入口：`runtime.ts` 普通生成、`customCallDispatch.ts` 自定义调用、`productionReferenceUrls.ts` 做片流程，各一组失效链接，都断言发出的是新链接。
- 做片返工：这条连接拒绝过，或冻住的链接明确失效 → 发新链接，POST 1 次，请求封存校验不拒发；冻住的链接活着或判断不了 → 和今天逐字相同，不重传。
- 不试探的情况：超过 48 小时（GET 0 次，直接上传）；没有 `originalUrl`；`ageMs` 未知要试探；ComfyUI 目标；内联 data。
- 模型拒绝：提交 4xx（两个引擎）和轮询失败（两个引擎）各一行 → POST 仍 1 次、没有自动重发；同一连接下一次发上传后的链接且不试探；兄弟连接和别的连接不受影响；清内存后读文件仍生效；文件缺失或损坏时当作没有记录；做片引擎的任务失败，错误卡能看到上游原话，`errorCode` 不变。
- 并发和去重：一个请求 5 张图，耗时约等于一次试探；26 个请求共用一张图，GET 1 次；5 分钟后再试；试探中点停止和今天「提交中」一样（POST 1 次，结果落账）；做片入口 Run 失效，POST 0 次。
- 老用户：0.24.0 真实落盘的素材走活着、失效两行；`upgradeKeepsWorkingModels` 断言不改且全过。

账本（`electron/productionRun/referenceLinkDispatchLedger.test.ts`，真提交出口、真账本、本机回环）：试探和上传不算付费派发。带查询串的活链接、上传成功或失败，只要模型一笔没收到，就是「没发出去」，可以直接重试；上传失败给「参考图没能送到服务商」那张卡。模型收下后连接断了，仍是结果未知，重试被拒。

拒绝记录（`electron/catalog/referenceLinkRefusals.test.ts`）：30 天后失效，到期后再被拒就重新记；时间读不出来或者在未来，都当作没有记录。

判据（`electron/shared/assets/referenceFetchRefusal.test.ts`）：表里每条原话和错误码都有一行为真（含 `An input media URL could not be fetched (403/404/410).` 的四种形式、错误码被带进文字）；假例一条不删，再加上通用规则认错过的句子、没说是输入的真话、查不到出处的说法，都为假；把卡死过的文字喂进来只是一次字符串比对；源码里有正则判句子就红。
