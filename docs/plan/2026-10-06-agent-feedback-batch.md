## 每条的根因（一句话）

| 条目 | 用户看到 | 直接原因 | 类根因 |
|---|---|---|---|
| NF-1001-0001 | 「这件事在当前页面做不了。」然后 Agent 停了 | 用户不在创作页，模型按「这个」去读文稿**选区**（`read_script` 的说明书叫它「用户说这个 / 这里就用 selection」）；创作页编辑器没挂，基线端口没有选区，回 `capability_unsupported` | 「文稿没有位置（选区 / 光标）」和泛泛的「做不了」共用一个码，用户那句和模型那句都给不出下一步；说明书把 selection 说成任何页面都可用 |
| NF-1001-0002 | 「这一步的结果没对上账，先别按已完成算。」 | 轨迹只有 `failed: true`，没有码，**直接原因无法从反馈确证**。代码里能产出它的写路径中，唯一与「写一份长剧本」相符、且不需要用户操作的一条：执行器另有 15 秒缺省超时，而 lane 给写工具的预算是 60 秒——渲染端落盘超过 15 秒时，写已开始，执行器掐断并报「结果未确认」，文稿里其实已经写进去了 | 「一次能力执行能等多久」有两个主人（动词声明 30/60 秒 vs 执行器 15 秒），内层更短的那个把慢但成功的写判成未知；失败话术叫模型「去核对回执」，模型没有任何读回执的工具 |
| NF-1001-0003 | 「Stream ended without finish_reason」英文原文 | pi-ai 的 openai-completions 在流没给 finish_reason 就结束时抛这句（中转站半路掐断）。#1022 之后它被归到「连不上服务商」 | 看门狗 / pi 自己写的几句话和服务商原话混在一起，交给关键词去猜 |
| NF-1001-0004 | 「Nomi model idle timeout after 120000ms」英文原文 | 看门狗在 pi 推 `start`（**收到响应头**）时就开 120 秒空闲表；推理模型在 chat completions 上思考时不流任何东西，于是长思考被当卡死掐断，pi 再把整份上下文重发三次 | 看门狗的相位边界放错：「连上了、还在想」和「出字出到一半断了」被当成一件事。比 pi 自己的传输层空闲默认值（300 秒、按字节计、连保活注释都算）紧得多 |
| NF-0928-0003 | 一回合输入几十万 token，撞上下文窗口 | 同一个用户回合里反复读整份剧本：每读一次，之后**每一次**请求都多带一份旧副本；pi 的阈值压缩确实触发了，但切不进当前回合，摘要请求白发 | 读工具的结果是可变资源的快照，旧快照被新快照取代后仍随每次请求重发；回合内没有人负责「只带最新那一份」 |

### 0. 一句话根因

Agent 失败的「事实」在产生它的那一层没有被说清：看门狗 / pi / 文稿端口 / 执行器各自只留下一串字或一个泛码，下游（面板、模型提示、轨迹）只能按字去猜，猜一次漏一句，于是每来一种新失败就补一刀文案。

### 1. 归类表

| 提交 / bug | 直接原因 | 类 |
|---|---|---|
| #1022 断线归网络、已重试退场 | 嗅探表抄漏 | 猜原文 |
| NF-1001-0003 / NF-1001-0004（本次） | 看门狗与 pi 的英文被当服务商原话猜 | 猜原文 |
| NF-1001-0001（本次） | 「没有位置」与「做不了」共用一个码 | 产生处没把事实说全 |
| NF-1001-0002（本次） | 两个超时主人；失败话术给了做不到的下一步 | 同一预算两份定义 |
| NF-0928-0003（本次） | 回合内旧快照无人取舍 | 上下文组装缺一个主人 |
| lane 目录 14 天其余刀（面板身份、流式重画） | 渲染性能与身份，不是失败文字 | 不同概念，与本类无关 |

### 2. 为什么会一直出现

错误在跨层时被压成字符串（`errorMessage`）或泛码，信息在产生处就丢了；下游每一处都得重新判断「这是什么」，而它们判断的依据（关键词、码）比产生处知道的少。铁律 ⑫（点了 = 以为的）：用户看到「连不上服务商」以为网络坏了，实际是模型在想。

### 3. 不改结构的话，接下来会冒出什么

| 预测 | 怎么验证 |
|---|---|
| 下一个 pi 升级改了某句英文，面板退回原文 | `laneAssistantFault.test.ts` 读依赖源码钉字面量，升级当场红 |
| 新加一个读动词（如读素材库全量）在回合内反复读又撑爆 | 判据从声明派生，`laneSupersededReads.test.ts` 第三条遍历全目录 |
| 新写路径再设一个比声明短的超时 | `rg "timeoutMs:" electron/capabilityCore` 出现新常量 |

### 4. 靶子独立性

报障原文逐字来自应用内反馈附件；NF-0928-0003 的尺子是请求体里的汉字数（不是 pi 的 chars/4 估算，它对中文低估 3–4 倍），改前改后同一条回环测试量；看门狗用可控时钟，不靠真等。

### 5. P0：是我们独有的吗

不是。可重试 / 溢出判定接 pi 现成函数，思考预算对齐 pi 默认值；我们只保留「映射成本地化人话」和「哪个读动词是哪份快照」（领域：文稿 / 画布 / 时间轴）。

### 6. 对比与推荐

| 选项 | 做什么 | 代价 | 推荐 |
|---|---|---|---|
| 补 | 再给关键词表加几句英文 | 小 | 否，下一句还漏 |
| 在产生处给事实（本 PR） | 看门狗 / pi 那几类在投影认成 `fault`；文稿缺位置单独一个码；超时一个主人；回合内只带最新快照 | 中 | 是 |
| 重写 | 把 pi 的错误通道整体换成结构化错误对象 | 大，要改上游 | 否，等 pi 自己出结构化错误 |

### 7. 用户要权衡的核心

思考预算放到 300 秒：真卡死的中转要等 5 分钟才报错（用户随时可以按停止），换来长思考模型不再被半路掐断、不再白花三倍 token。
