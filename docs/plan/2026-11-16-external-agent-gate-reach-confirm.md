## ★0 先查别人

- [Kubernetes · Server-Side Apply（managedFields）](https://kubernetes.io/docs/reference/using-api/server-side-apply/) · 每个字段记「谁管」，另一个管理者要改别人管的字段时默认冲突、点名字段，除非显式抢管 · **确认了**修②：内置连接的地址 / 认证 / 素材上传方式归内置种子管，交卡的人不许静默改；不同就拒、点名是哪个字段，下一步给出（照抄连接的值 / 换一个连接名）。
- [VS Code · `lm.selectChatModels` / `lm.onDidChangeChatModels`](https://code.visualstudio.com/api/references/vscode-api#lm) · 扩展每次用模型时现选，不缓存启动时的列表；列表变了发事件 · **确认了**修①：门、预览、起草每次调用时读现在的表（按目录版本号缓存），不在宿主启动时拍快照；**否决了**另做一套「变了就通知刷新」——要动的调用方 ≥5 处，按版本号现读就够、每次 0.6ms。
- [LobeChat · 模型列表环境变量](https://app.unpkg.com/@lobehub/chat@1.94.4/files/docs/self-hosting/advanced/model-list.mdx) · 内置模型列表 + 用户 `-模型名` 去掉、`+模型名` 加上，内置的那份永远可以重新拿回来 · **确认了**修④：整家删 = 一条「这家删了」记录，不逐模型记；用户重新存这家的密钥 = 把这条记录摘掉，内置模型回来，单删过的那几个照旧不回。
- 出口：[Kubernetes SSA · 冲突处理](https://kubernetes.io/docs/reference/using-api/server-side-apply/#conflicts) · 冲突时给出三条路：放弃这个字段、改成和现值一致、显式抢管 · **确认了**修②新增的两种拒绝都带下一步：地址 / 认证不同 → 照连接的值抄、或者换一个连接名另开一个连接；卡里写了内置目录已有的模型 → 把这几个从卡里去掉（Nomi 已按内置档案在跑它们）。门的「你删了这家」回复下一步是「重新存这家的密钥」（设置页或 `nomi_model_setup action=set_key`）。修①删掉一道快照，不新增拦截。

## ★1 用户怎么用

当创作者让外部 Agent（Claude / Codex 经 MCP）给一个模型交接入卡、试跑出了片之后，我想让它接着走正式生成、到确认这一步停下等我批，以便不用重启 Nomi、不用懂「供应商行」是什么。

1. 外部 Agent `nomi_model_setup` 交卡（模型挂在内置 APIMart 连接上）→ 2. 试跑出片 → 3. `nomi_create_draft` → `nomi_preview` → `nomi_gate_request` → 门回 `confirm`，等创作者在 Nomi 里确认。
今天（主干）第 3 步两句话失败：预览说「Unknown model」（宿主启动时拍下的模型表里没有新卡的模型）；修了表之后门又说 `configured_provider`（卡把内置 APIMart 行的素材上传方式改了，整条内置连接被判成「不是内置的了」，内置图片模型也一起没就绪）。

- 不做什么：确认卡 / 确认条 / 小卡的样子和文案一个字不改；试跑确认方式、「批一次管一段」、全自动设置不动；画布生成请求体、模型档案内容、别家种子不动；用户在设置页把内置连接地址改成代码不认识的域名，行为同今天（报告里描述）。
- 真实任务：用户那次的原路径（外部 Agent 交卡 → 试跑 → 正式生成），用 0.24.0 真代码生成的三种旧盘形状重放；另加整家删 APIMart 再存密钥。
- 指标：主指标 = 用户原路径走到门回 `confirm` 的形状数 / 全部形状数（量具：`externalAgentGateReachConfirm.test.ts` 的 it.each，三种旧盘 + 新装）；护栏 = 每次过门读模型表的耗时（量具：`tests/perf/gate-live-catalog-bench.mjs` 的 `perGateCatalogReadMs`）、内置图片模型同一条连接上仍然走到确认（同一测试）。

### ★1b 连带界面
不适用：不加、不改任何界面元素和文案。变的只有 MCP 工具回给外部 Agent 的话：交卡被拒时的 `code` / `rejections` / `nextAction`，删整家内置连接的 `userSees`，门在「这家被你删了」时的事实与下一步。

### ★1c 老用户
升级就好，不要用户做事。启动对账（`seedBuiltins.ts#restoreBuiltinOwnedFields`）把卡写进内置连接的字段还原：素材上传方式回到种子；内置目录里有的模型上卡写的适配器 / 声明投影 / 参数 / 卡专属映射去掉，回到内置档案。地址和认证字段**不碰**——设置页的接入向导也会写它们，分不出是谁写的；用户在设置页改过的地址保留（测试钉了：APIMart 备用域名仍就绪；不认识的中转域名同今天不就绪）。
四种 0.24.0 旧盘（`tests/fixtures/old-user-data/builtin-connection/`，用 0.24.0 真代码生成）：只存了内置密钥没交卡（对照）/ 交卡挂了一个非内置模型 / 交卡挂的模型后来进了内置目录（flux-3-video）→ 升级后三种都就绪、内置图片模型与卡模型都走到确认、后进内置目录的那个回到内置档案；整家删过 → 升级后仍是删掉的，存一次密钥整家回来。
整家删的旧盘判据：0.24.x 整家删是逐模型记的，而之后内置目录又加了模型，「每个内置模型都在删除记录里」在真旧盘上不成立；改为「这家有删除记录、盘上一个内置模型都没有」= 整家删，只换算一次（字段 `suppressedBuiltinVendors` 一旦写过就不再换算）。

## ★2 谁说了算

- 「现在有哪些模型」：唯一来源是盘上的模型目录；两个宿主（应用内 MCP、独立 stdio 进程）都只经 `createLiveGenerationRuntime().registry` 读，按 `catalogRevisionToken()`（目录文件内容不变就是同一个对象）缓存，版本变了就重建。宿主里不再存启动快照。
- 「一次工具调用读哪一版」：生成工具入口 `registry.pinForCall` 取一版（`AsyncLocalStorage`），这次调用里起草 / 预览 / 过门的 resolve、snapshot 和宿主读就绪（`readBootstrap`）都读这一版；调用结束就放开，调用里起的后台活之后读现在的目录。生成工具的依赖只剩这一个目录来源（删了可选的 `createDraftScope`，类型上就做不出「起草一版、门另一版」）。**这个 1 靠什么保持（2026-11-21 按今天主分支核过）**：「只有一个来源」靠类型；「这一个来源是活的」类型不保证——`pinForCall` 在依赖类型里是可选的，宿主递一份启动时拍的表仍然编得过，靠第 11 条真窗口走查和第 1 条单测在使用结果那一步守；第 7 条查宿主源码写法的测试只算提示，不算保证。方向检查 `docs/engineering/direction-checks/2026-11-16-external-agent-host.md` 第 1 段；生产调用方 2 处、不改盘上格式，所以并进本 PR。
- 「内置连接的地址 / 认证 / 素材上传方式」：内置种子 + 设置页。交卡只能往内置连接上加非内置的模型（`declaredProviderRegistration.ts#builtinConnectionMismatches`）。
- 「这家内置连接被用户整家删了」：目录里 `suppressedBuiltinVendors` 一条；只有存这家密钥（`applyApiKeyUpsert`，设置页和 `set_key` 共用）能摘掉。

## ★3 一致与复用

- 复用现有的删除记录机制（`suppressedBuiltinModels`）和种子对账（`applyBuiltinSeeds`），新增一种盘上形状（家级记录），不另起存储。
- 拒绝码复用现有词表：`credential_origin_mismatch`、`route_conflict`；门的下一步在封闭词表 `GENERATION_PROBLEM_NEXT_LIST` 里加一项 `save_provider_key_again`。
- 设置页存密钥与 `set_key` 走同一个 `applyApiKeyUpsert`，摘记录只写一处。

## ★4 全状态

| 状态 | 外部 Agent / 创作者看到什么 |
|---|---|
| 交卡成功（内置连接 + 非内置模型） | 同今天；连接名仍是内置的名字 |
| 交卡被拒：地址 / 认证不同 | `credential_origin_mismatch`，逐字段点名（如 `provider.authHeader`），什么都没写；下一步：照连接的值抄，或换连接名另开 |
| 交卡被拒：卡里有内置目录已有的模型 | `route_conflict`，点名模型；下一步：从卡里去掉，Nomi 已按内置档案跑 |
| 交卡被拒：内置行不存在 | 下一步：先在 Nomi 设置页存这家的密钥 |
| 过门：卡刚交、没重启 | `confirm`，等创作者确认（确认卡不变） |
| 过门：整家删了、没存密钥 | 不认识这个模型；事实「用户在 Nomi 里删了这家」，下一步「重新存这家的密钥」 |
| 删整家内置连接 | 「已删，含保存的密钥，重启也不回来；重新存这家的密钥就连同内置模型回来」 |
| 存回密钥 | 内置模型回来，单删过的不回 |
| 能力不可用：目录读不到 | 同今天（门按目录为空处理，回现有的未就绪原因） |
| 空 / 加载 / 部分成功 / 取消中 / 过期 | 不适用：都是同步的目录读写，没有中间态；过期 = 目录版本变了，下一次调用自动读新的 |

## 6 外部数据与失败

- 外部来源：外部 Agent 交的接入卡（用户输入）、0.24.x 旧盘目录。卡的规范是接入卡契约（不改）；偏差：内置连接上卡的地址 / 认证 / 素材上传方式不再生效，改成拒绝或忽略。旧盘按 0.24.0 真代码生成的形状验。

## ★7 性能

- ①新增操作：无新交互；变的是每次预览 / 过门 / 起草读模型表（原来读宿主启动快照）。
- ②最坏规模：一次 40 个镜头的草稿（全部内置图片模型），连续预览 + 过门 40 次；目录版本中途变一次。
- ③预算：每次过门读目录 ≤5ms（主指标 `perGateCatalogReadMs`，命中缓存）；目录变了之后的重建约 100ms，只发生在版本变的那一次。

## ★9 验收与回滚

验收清单（实现线按它自验，验收线只核它）：

1. 用户原路径（交卡挂内置 APIMart → 起草 → 预览 → 过门）不重启走到 `confirm`；主干上同一测试红（「Unknown model」/ `configured_provider`）。
2. 同一连接上的内置图片模型过门走到 `confirm`。
3. 三种 0.24.0 旧盘（只存密钥 / 交卡非内置模型 / 交卡模型后进内置目录）升级后：素材上传方式等于种子、连接就绪、内置图片模型与卡模型都走到确认、内置模型上没有卡写的适配器。
4. 设置页改过的地址保留：APIMart 备用域名仍就绪；不认识的中转域名同今天不就绪。
5. 交卡：地址同、认证方式不同 → 拒，点名 `provider.authHeader` 不点 `provider.baseUrl`，连接行一字节不变；卡里有内置模型 → 拒，点名每个模型。
6. 整家删 → 重启不回来、门说删了 / 存密钥就回；存回密钥 → 全回、单删的那个不回、再重启一样；整家删旧盘 → 换算成家级记录，存密钥全回、过门确认。
7. 两个宿主源码里没有 `createDraftScope().registry` 快照，都传 `registry: liveGenerationRuntime.registry`（静态测试钉）。
8. 确认卡 / 确认条 / 小卡没有任何文件改动。
9. perf 场景 `perGateCatalogReadMs` ≤5ms。
10. 一次工具调用只读一版目录：调用中途目录变了，调用里的模型表和就绪不变、多镜每镜同一版；下一次调用读新版；调用里起的后台活过后读现在的。
11. （第 7 条只算提示：它查的是源码里有没有那一行，不是结果。）真 Electron 两个宿主（应用内 HTTP、stdio）都先起来再交卡，不重启：起草 → 预览认得 → 过门在窗口弹确认卡，点取消，不发生成请求（`tests/ux/mcp-declared-model-gate.e2e.mjs`）。
