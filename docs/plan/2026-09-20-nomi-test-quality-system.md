## 0. 一页决策摘要

选用“**增强现有测试链**”，不采用“从零建测试平台”或“所有回归都让 AI 临场操作”。

第一阶段先交付四个可核验结果：

1. **可信绿灯：**区分能力评测与回归放行；明确跳过、缺资源、重试通过和实际通过；发布必测项未执行不能放行。
2. **核心真实入口回归：**从原页面与确认入口覆盖付款、方案目标、保存、Undo、输入恢复、pi 历史与完整 T7，而不是只测底层函数。
3. **异常可重放：**供应商/模型响应由隔离服务控制；在真实异步边界重放迟到、重复、断连及中断，不依靠随机 sleep。
4. **一页证据报告：**显示本次变更影响、必测覆盖、首次结果、异常原因、平台/模型/包身份，以及少量需要用户判断的体验片段。

第二阶段扩充媒体、模型接入、MCP、安装/升级/导出等覆盖，再做高风险模块的属性测试、变异测试和 AI 探索。**测试基础设施完成、产品缺陷修复完成、候选包可以发布是三个独立结论。**

不承诺“测完后所有用户永远零 bug”。应承诺：在明确范围内每个高风险行为有约束、有测试、有失败证据；任何未验证项都不会被隐藏在绿色总数里。

### 0.1 这次决定与核心取舍

用户本轮要求：把原方案与讨论建议合入一个 PR，能够逐步做、不一次做大，并明确通用性、扩展和测试系统构建原则。本 PR 交付文档与待办接线；没有批准在本 PR 实施测试平台或产品改造。

核心取舍是：**先保护一个真实用户行为，再从第二个真实复用点提炼共用能力。**严格保留付款、数据和证据边界；可以减少一批交付的行为数量，不能为求“小步”降低单个行为的验证质量。

| 推进方式 | 用户先得到什么 | 维护代价 | 本轮决定 |
|---|---|---|---|
| 先铺完全部基础设施，再补旅途 | 较晚才有可见保护 | 容易预建用不上的抽象 | 不采用 |
| 每个 bug 各写一套脚本 | 局部保护出现快 | 启动、隔离、报告和判据分叉 | 不采用 |
| 原体系内做小切片，同时提炼真实共用点 | 一条条减少人工复查，结果随时可看 | 每批都要核对复用与维护成本 | **采用** |

### 0.2 第一批就要看见收益

先修可信汇总，再用一个历史问题把真实页面、受控服务、最终状态和报告接通。首选 QA-05：A 项目批准生成 → 暂缓响应 → 切 B → 释放响应 → 结果仍落 A，B 不串写；同时验证原目标变化后应拒绝未提交部分的反向情形。WP0 若发现该链尚不适合起步，可按证据换为关闭付款卡或保存重开，记录原因，QA-05 仍保留在后续范围。

**最简一页报告从 WP1 开始，随每个切片更新。**最初可以是原报告目录中的文本/Markdown 与原机器结果的视图：计划、首次结果、失败用户后果、最短证据链接、未验证项、构建身份。不要等到 WP7 才报告，也不先造网页仪表盘。

### 0.3 每个实现 PR 的边界

- 只解决一个可描述的测试行为/共用边界，列出输入、允许副作用、禁止副作用、验收案例与实际变更文件。
- 必须有可观察的增量价值：抓住一种旧错误、修正一种误判、减少一种人工重复操作，或解锁下一条明确回归。不要以新增框架层数/测试数量作为成果。
- 基础设施改动与生产修复分开审阅；发现阻塞主链的产品 bug，交最小复现与关联修复 PR。红证可以收货，不能叫产品通过。
- 回滚只撤销本批新增接线/代码；历史证据不覆盖，已知失败不删除。严格判定发生故障时保留阻塞，不回退为宽松绿灯。
- 交付后记录下一步和具体阻塞，不自动接着执行整个路线、合并或发布。已有用户单独授权的范围照常执行。

## 2. 方案选择与现成能力复用

| 方案 | 收益 | 代价/风险 | 裁决 |
|---|---|---|---|
| 增强现有测试链 | 可复用现有入口、证据、锁和版本纪律，较少迁移 | 要逐个修正既有判据和薄弱接线 | **采用** |
| 全部交给 AI 自主测试与自动修复 | 适合探索新路径、生成初稿 | 随机、费用、可能修改期望或跳过坏功能 | 只作为受约束探索工具 |
| 新建完整测试平台/引入大型服务 | 集中管理可能便利 | 第二套身份/报告/权限、迁移维护成本 | 本阶段不采用 |

### 2.1 复用表

| 能力 | 复用入口 | 本次动作 |
|---|---|---|
| 单测/集成 | Vitest、现有 `*.test.ts`、agent-runtime 测试 | 补真实边界测试与正负对照，不另建 runner |
| 桌面交互 | `tests/ux/_launchApp.mjs` 及现有旅途 | 核对后扩展隔离、证据与事件控制，不复制启动器 |
| 旅途 | `evals/journeys/index.mjs`、`evals/lib/journeyRunner.mjs` | 保留现有 ID 和连续会话；补案例元数据及最终状态断言 |
| 评分 | `evals/lib/grading.mjs`、`scripts/eval-journey.mjs` | 区分能力与回归；保存首次失败、完整分母与证据 |
| 选择 | `scripts/eval-journey-selection.mjs` | 保留空选择拒绝；新增必测完整性与请求 ID 校验 |

| 上下文/消息 | 安装版本 pi 的 Session/Branch、watch、压缩与队列 | 用真实 SDK 测试；测试模型不能替代运行引擎 |
| 操作序列/竞态 | 已声明的 fast-check | 优先在受控 Promise/领域边界试点 |
| 测试有效性 | Stryker＋Vitest，或隔离定向历史变异 | 先固定版本兼容探针；不作为全仓前置 |

Playwright 的 Electron 支持仍是实验性；原生对话框不能由普通浏览器拦截直接覆盖。Stryker Vitest runner 不支持 Browser Mode。fast-check scheduler 只能控制被纳入调度的异步工作；它不是 OS/网络全局调度器。[W1][W5][W6]

### 2.2 测试系统构建原则

**目标是让新行为容易接入、旧行为持续被保护，并让维护成本可承受。通用性以真实复用验证，不以抽象层数衡量。**以下是既有测试体系的增量约束，不要求另建一套框架，也不修改产品架构。

| 原则 | 具体约束 | 扩展时怎样判断做对了 |
|---|---|---|
| 机制共用，业务判据归领域 | 计划/身份/隔离/受控时序/证据/汇总可共享；付款许可、目标归属、保存与 Stop 的期望由对应模块定义 | 通用评分器不按供应商名称或某个 UI 写分支；不用生产算法算 expected |
| 一个语义只有一个 owner | 案例沿用原注册表；严格 verdict 由一个判定入口生成，CLI/CI/报告消费同一结果 | 新增案例不复制 runner/评分器/风险分类器；历史 ID 可映射、不可悄悄重用 |
| 先实例，后共性 | 首条回归直接使用已有机制；第二个真实消费者出现后再决定抽薄适配 | 提炼时用两个确有差异的消费者证明复用，保留差异；不预建插件平台、场景 DSL 或万能 base class |
| 按能力扩展 | 平台/宿主/模型以能力和已批准范围决定适用案例；协议差异进边界适配器 | 不能到处写 vendor 名分支，也不能把“不支持”伪装成默认成功；能力声明本身有合同验证 |
| 深度验证放在最早共享边界 | 大量组合/错误分类用 L1/L2；L3 保留每个关键用户入口与跨层接线 | 不把所有纯函数边界展开成昂贵 UI 旅途；也不因 L2 已绿而跳过 UI/IPC 接线 |
| 替身只控制外部条件 | 原授权、runner、持久化真实运行；UI helper 表达点击/输入等真实动作 | 不直接铸成功收据/节点，不复制生产状态机；替身的请求账本独立于产品结果 |
| 可重放，少依赖时间猜测 | 有界条件等待、明确事件屏障、seed/时序记录；资源释放可观察 | 相同反例能重放；没有随机 sleep、等待更久碰运气或为测试插入生产 await |
| 证据与判定可演进 | 扩展原结果 schema，记录格式和判定策略版本；旧报告只读展示 | 缺必需新字段不能补默认 PASS；未知版本、损坏与不兼容证据阻塞对应严格汇总 |
| 安全是运行条件 | worker 独占资源、无真实凭据继承、出站约束、费用预留、所有权清理 | 增加并发/新适配前验证隔离；no-live 不成立就停依赖它的测试，不能先跑后补 |
| 正反成对，证明测试有用 | 每条关键禁止行为配合法成功路径；历史变异与独立期望检验断言 | “全部拦住”不能通过；恢复旧错后应出现对应业务失败，而非任意启动错误 |
| 维护成本可见 | 从首批记录耗时、环境失败、不稳定、定位和维护投入 | 扩面前能说清新增收益与成本；测试噪声有 owner，不把不稳定永久隔离 |
| 测试随产品有序退出 | 废弃入口/重复 helper 有 owner、来源与替代覆盖；旧格式读能力按使用需要保留 | 行为确实退役才删对应测试；失败或维护麻烦不是删必测的依据 |

### 2.3 扩展边界：加什么，放哪里

| 新需求 | 默认扩展位置 | 必须补的验证 | 不应顺手扩大的部分 |
|---|---|---|---|
| 新业务行为 | 原 case 登记＋领域断言＋风险映射 | 真实入口/结果、正反例、所需证据 | 不修改通用评分语义来适配当前失败 |
| 同协议新模型/供应商 | 现有模型档案及测试夹具参数 | 能力声明、请求合同、授权后的 live 格 | 不为每个模型复制 UI/旅途/runner |
| 新供应商协议或故障类型 | 现有边界适配与替身场景 | 协议对照样例、故障恢复；真实协议兼容另验 | 不把供应商特例放进所有案例或全局 verdict |
| 新宿主或平台 | 原启动适配/能力声明/环境矩阵 | 共享合同＋该宿主的入口/生命周期/原生差异 | 不继承另一 OS、源码构建或测试包的通过证据 |
| 新证据字段或报告视图 | 原证据采集与报告 schema | 新旧固定样例、缺字段/损坏/未知版本反例 | 不造另一份存储和放行数据库，不反写旧结果 |
| 新执行器或 AI 探索工具 | 先证明现有工具缺口，再做单模块兼容试点 | 输入/输出合同、成本、可撤销接线和普通回归产物 | 不把工具选型变成启动前置或产品重构 |

共享 helper 只拥有单一职责。若必须加入大量互相影响的布尔参数才能容纳第二个消费者，先检查是不是把不同业务判据错抽到一起。小量明确重复可暂留业务案例，不能因此复制授权/安全算法；确认同一语义后再收敛到原 owner。

**报告升级约束：**先让现有消费者识别版本与缺失字段，再启用新生产者；未知版本不能按最新版本猜读。旧证据保留原始内容，迁移/派生视图写清来源。若采用短期双版本读取，它是同一读入口的明确兼容行为，不是长期双套报告真相源；以实际消费者迁移情况决定退役时间。策略变更需正反例，不能重新解释旧失败为当前通过。

**通用化不等于统一业务后果。**例如“取消生成”和“取消导出”可共用隔离与请求记录，但领域身份、允许的恢复、最终产物检查仍各自明确。新模型也不能仅靠继承共同 case 就自动获得生成质量认证。

## 4. 测试层次与证据标签

| 层次 | 真实部分 | 可替换部分 | 可声称的结论 |
|---|---|---|---|
| L1 契约/纯函数 | 实际 parser、范围、错误投影、序列化 | 独立输入数据 | 某一契约或算法符合断言 |
| L2 集成/属性 | 实际领域服务、存储/授权接线；明确标注替换边界 | 供应商响应、受控时钟/故障端口 | 模块组合与指定异常成立 |
| L3 真实 Electron＋loopback | 原页面、preload、IPC、原 runner、实际磁盘 | 外部模型/媒体服务的隔离响应 | 用户真实入口到产品结果链正确，不是真实供应商 |
| L4 真实 Agent/供应商 | 实际 pi＋获准 LLM；必要时真实媒体接口 | 只有明确披露的其他依赖 | 指定模型/供应商/样本的实际结果 |
| L5 候选包/平台 | 最终待交付二进制、资源与适用 OS | 可分为 loopback 和 live 两种子档 | 该包在该平台、该流程验证过 |

L3 与 L5 可以使用真实媒体夹具；真实媒体不意味着真实付费生成。真实 Electron 不意味着所有 OS 事件都是真实发生。每份报告分列 `appMode`、`modelMode`、`providerMode`、`osEventMode`，不压缩成一个含糊的“real=true”。

模型 stub 只替换已批准的模型协议端点；原 pi/工具调度仍实际运行。不得直接构造产品 store、付款收据、lease 或“成功节点”来替代被测动作。原生文件对话框返回值 stub 可用于导入之后的功能链，但原生对话框本身另有平台测试。[W1]

## 6. 可信通过判定与指标

### 6.1 先纠正现有含义

保留 `passAtK` 作为能力指标：在预先固定的 k 次独立 trial 中至少成功一次。保留 `passAllK` 和 `passRate`；它们是本次样本描述，不自动等于真实用户成功概率。[G2][G3][W7]

**回归放行不使用“只要成功一次”。**确定性关键回归要求计划内所有 trial 的首次执行通过，所有必需断言成立，证据齐备。诊断重跑成功保留为 flaky 信号，不能抹去首次失败。

随机模型的“独立 trial”与“同一次失败后重试”是两个轴。不得在模型任务失败后不断追加试验直到出现一条成功；不能用 pass@k 的 k 代替产品自身重试次数。样本量和模型比较计划须在开始前冻结。

### 6.2 执行与放行分离

沿用原 runner 状态，增加薄归一化输出，不修改产品状态词表。每个计划项至少显示首次结果、全部 attempt、终态、失败原因与证据身份。

| 结果 | 展示 | 严格必测放行 |
|---|---|---|
| 首次及计划内各 trial 均成功，证据完整 | 通过 | 可以计入 |
| 首次失败、同 trial 重试成功 | 重试通过/不稳定 | 不当干净通过；调查或按明确非关键隔离规则处理 |
| 产品或安全断言失败 | 失败 | 阻断 |
| 缺授权、平台、模型目录、基础设施 | 未验证/阻塞 | 阻断对应已承诺范围，不能算通过 |
| 取消、超时、报告缺失或损坏 | 未完成 | 阻断对应必测范围 |
| 启动前已明确不适用 | 不适用 | 不计入本次必测分母，但必须说明原因 |
| 可选探索失败 | 探索发现 | 不自动冒充必测失败；一旦证实是候选包 P0/P1，则另形成发布阻断 |

故障注入测试中的“预期拒绝”可以是通过；注入的超时不是当然的 infra 失败。例：提交回执被丢弃后，产品诚实保持 unknown 且不重提，是成功满足安全断言。

### 6.3 计划集合不得在运行后缩小

运行前保存计划：caseId × 环境 × trial 数。运行后必须解释每一个计划项。所请求 ID 有任意未知项即拒绝请求，不允许“一个合法＋一个拼错”静默只跑合法项。

已存在的空选择拒绝继续使用。还要分别处理：

- 明确 docs-only 且风险策略证明不涉及任何功能验证：质量策略可返回“不需要功能 lane”，不能伪造一个 0/0 成功旅途。
- 已选中必测旅途但全因缺资源跳过：返回阻塞，不得 exit 0 宣称回归成功。
- 一个分片成功，另一个没有上传报告：整体不完整。
- 旧构建报告、重复 case 或同一个 trial 被多次累计：证据无效。
- 仅部分能力在此次发布范围内：范围须在运行前按产品决定冻结，不许看见失败后临时删平台/模型。

### 6.4 汇总公式与发布规则

```text
执行完整率 = 已执行的计划内 trial 数 / 计划内必须执行的 trial 数
首次成功率 = 首次成功的 trial 数 / 实际启动的 trial 数
不稳定率   = 首次失败后重跑成功的 trial 数 / 实际启动的 trial 数
```

同时展示缺失数与环境阻塞数，不能只显示成功率。`FAIL` 优先于 `BLOCKED`；没有已知失败但缺证据时是 `BLOCKED`；只有计划完整、首次成功、安全约束满足才是 `PASS`。这种测试 verdict 仅是进入人工合入/发布决策的证据，不执行 merge/release。

真实模型的质量统计应与固定基线使用相同任务、夹具、模型参数和预定试验数，展示每任务差异与样本数。试点不编造“98%可靠”等阈值。关键任务逐例通过；非关键主观质量只作为对照报告，成为门禁前由产品负责人批准量表及阈值。

## 7. 隔离与故障注入：真实产品，受控外部世界

### 7.1 最小隔离单元

每个 worker 独占：测试根目录、userData、项目副本、临时目录、端口、模型配置、日志目录和子进程组。沿用现有 `_launchApp`/isoApp 的已验证能力；清理只删除由本次运行创建并带所有权标记的目录，校验真实路径与符号链接，拒绝用户目录和旧证据 profile。

历史 profile 续接不得运行会清空目录的初始化。新试验与恢复既有试验是显式不同模式，不能用默认 reset 猜测。

**仅 browser route 拦截不足以保证零外网。**Electron main、Node fetch、原生二进制和子进程也可能请求网络。no-live 档应在隔离运行环境限制出站，仅允许本次 loopback 端点；关闭真实凭据继承，验证所有应用/子进程请求。依赖安装和运行测试阶段分开。没有覆盖主进程/子进程的证据，不称“已证明零供应商调用”。[W1][W10]

### 7.2 受控服务复用原则

复用现有 loopback 供应商/模型服务。新增场景是数据配置，不新增测试专用生产执行路径。替身维护自己的请求/响应账本，用来检验真实产品输出；不要直接写 Nomi 的成功状态。

| 场景 | 注入边界 | 必要断言 |
|---|---|---|
| 读取慢于页面切换 | 原请求发出后暂存响应，切目标再释放 | 目标不串写，原编辑不被抹掉 |
| 提交已被服务接收但响应丢失 | 服务持久记录接收，然后断连 | 不盲重提；unknown 与恢复查询正确 |
| 重复回调、乱序进度 | 相同任务的重复/旧序号响应 | 单结果、不回退到旧状态；不重复收费 |
| 401/403、429/5xx、缺任务、损坏存储 | 协议/存储明确失败 | 分类正确，不把所有异常都解释成不存在 |
| 半幅图、损坏视频、伪 PNG | 完整网络返回但真实解码失败 | 不显示为可用成功产物；保留错误与重试边界 |
| 写入失败/只读/空间不足 | 隔离存储或已公开存储端口 | 已保存承诺不被虚构；原数据/备份不损坏 |
| 保存或提交中进程退出 | 确认实际阶段后终止本次隔离进程 | 新进程恢复；未决外部结果不重付 |
| 压缩/停止期间迟到 ACK | 真实 pi 准入及公开异步边界 | 旧输入不复活、不清新草稿、不误停新任务 |

可以用无副作用观测点暂停测试，但不得把新 await、sleep 或测试状态分支插入生产逻辑后，将由此创造的时序当成原有竞态。

### 7.3 关于“没有副作用”的证据

不能点击关闭后立即读一次计数为 0 就宣布安全。应同时验证本次请求已结束、没有待执行提交/outbox 项，释放所有受控迟到响应，再关闭和重开检查。全应用有其他既存合法任务时，只断言本次 request/approval 关联的提交为零，而非禁止所有后台工作。

不能宣称无限未来永不提交；可证明的是规定生命周期与故障阶段内，产品状态/授权与外部请求账本一致，并由宿主安全约束持续限制执行。

### 7.4 数据对照

标准起点为两个项目，每项目两篇文稿、每篇两个方案；为跨文稿/方案场景使用其中至少两篇各两方案。每个对象使用明显不同的内容和稳定 ID。并列保存：规范化作者内容、引用身份、画布结构/覆写、结果/历史、执行授权/次数。

真实旧项目必须是获准只读来源的副本；合成旧格式明确标合成。比较原件哈希，禁止测试中隐式升级原件。为了构造“损坏文件”而动真实用户文件不在授权内。

## 8. 属性、序列与变异测试

### 8.1 从四个小模型开始

| 模型 | 动作 | 检查点 |
|---|---|---|
| 付款与批次 | present、修改、关卡、批准、返回/丢失回执、继续下一批 | INV-01/02/04/11 |
| 编辑与保存 | 编辑、保存、切目标、冲突、删除、重开 | INV-03/05/06/10 |
| 输入与历史 | 发消息、排队、停止、继续、重发、压缩、分页 | INV-07/08 |
| 参数条 | 单选、多选、历史开关、拖动中断、尺寸变化 | INV-09 |

测试模型只写最少预期事实，禁止调用生产 reducer/同一个生成函数计算 expected 值，以免实现和判据一起错。随机序列必须来自合法用户/协议动作，不随意构造生产接口不可能产生的中间状态。

使用 fast-check 保存 seed、path、版本、原完整命令序列及缩减后的反例；缩减过程也在 no-live 环境，不对真实付费任务反复尝试。先覆盖明确危险顺序，再用随机生成发现遗漏。起始建议为每模型固定回归种子＋100 条有界序列，每条最多30个命令；这是可评审的试点预算，不是完整性或工时承诺。[W5]

### 8.2 组合覆盖

语言/主题/窗口尺寸/节点类型可采用两两组合减小数量；付款阶段/目标变化/回执顺序等必须保留明确的三因素或更高阶场景。报告实际覆盖了哪些组合，不写“全组合通过”。长操作序列不能用两两参数覆盖替代。[W9]

### 8.3 变异测试试点

先在范围解析、任务领域、评分器和保存冲突等纯/集成模块中使用 Stryker。验证实际安装 Vitest 版本；Browser Mode/原生 Electron 不在该 runner 的直接覆盖能力内。别为使用工具升级整个应用依赖。[W6]

保留一组有用户意义的定向变异：忽略 shotIds；把所有错误当 not-found；去掉目标比较；将关闭接回删除；将 Shift+Z 当 Undo；压缩后重新从运行快照显示全部历史；缺资源后输出成功。变异只在隔离源码副本，确认现有测试会失败，不提交错误版本。

不要求全仓统一高分。每个存活变异需裁定等价、未覆盖或错误判据；工具原始分类保留，业务评审中超时不直接作为关键行为变异已被有效检出的证明。关键定向变异必须被抓住，普通变异分数只是辅助信号。共享依赖、快照、配置和工具升级时失效增量缓存，不能仅靠变异文件没变就复用结果。[W6]

## 9. 完整 T7、视觉、键盘与原生事件

**完整 T7 是第一阶段产品回归范围，不再被自动放到后续。**必须复用原参数条和两宿主，不为测试替换成实验室简化页面。[U1，第24行]

### 9.1 交互断言顺序

1. 从真实节点点击进入，检查选中目标与单选/多选语义。
2. 检查面板计算后的可见性、边界位置、滚动可达性，不仅查 DOM 数量。
3. 用正常点击/键盘进行实际编辑，读到输入值和规范化保存内容；不以 `force:true` 绕开遮挡。
4. 检查非目标节点坐标、prompt、模型、参考没有被这次按键修改。
5. 历史打开/关闭、切面、失焦、取消、尺寸归零再恢复后重复上述操作。
6. 对付款卡重复同类操作；未确认的卡内编辑不得提前写画布或提交媒体。

定位优先可访问名称/角色、稳定业务 ID，确需 testid 时复用原测试约定；不依赖长层级 CSS 路径。截图要包含整块真实外壳及目标区域；不能只裁出一个看起来正常的控件。[W2]

### 9.2 逐项故障注入

| 故障 | 怎么验证 | 不可替代的证据 |
|---|---|---|
| 参数条 chunk 首次失败 | 在实际资源加载边界拒绝该资源，进入局部错误，再恢复并点击重试 | 实际加载失败与恢复请求、原页面可操作、未整窗重载 |
| 零尺寸/隐藏恢复 | 真实切换原工作区或改变窗口尺寸后恢复 | 面板恢复后实际输入/点击，不用手改 visible 类 |
| 拖动中断 | 实际按下移动后分别释放/取消/失焦/切面 | 原节点/舞台、该手势结束、晚事件不改新舞台 |
| Portal 键盘串域 | 打开原参数选择/数值面板，按方向键/Enter/Escape | 参数按预期变化，所有无关节点坐标不变 |
| 付款卡引用上传迟到 | 上传等待中切 A 卡→B 卡→A 卡，释放旧响应 | 旧访问回调不能写进新访问或画布 |

源构建可拦 chunk 网络请求；安装包可能使用本地协议和不同资源边界。需按实际启动方式设计故障方法，不能把关闭整网或人工抛 React 错误当成完全等价证据。失败不能被注入时标明该项缺验证，并继续其他不受阻场景。

### 9.3 视觉与性能

复用原样张/设计基线、zh/en、明暗模式、最小支持窗口及典型窗口。冻结测试时间/字体/缩放与合法动画条件，防止机器差异噪声；不能关闭本次正在验收的加载/等待动画来让截图稳定。

截图差异先判定产品变化或渲染噪声，再决定更新。AI 不可自动接受全套基线；已明确延期的左右栏整体布局不重新要求本 PR 重画，但记录其实际可操作性限制。

性能沿用现有预算与同环境基线，观察输入延迟、主进程阻塞、长会话内存/监听器/队列增长。进度广播次数下降不等于 FPS 改善。指标波动先归因，不能抬预算掩盖回归。

可访问性先检查核心控件名称、键盘可达、焦点、Escape 与可读对比；可选引入 axe，但自动扫描无法覆盖所有无障碍或“好不好用”的判断。[W12]

### 9.4 平台真实性

macOS arm64、macOS x64、Windows x64 按实际发行范围列矩阵。Linux CI 是有价值的运行证据，但不替代 Windows/macOS 原生行为。真实 OS 失焦、原生文件选择/取消、剪贴板、权限提示、显示缩放、安装和更新分别登记。

使用测试主机/VM需说明其局限；页面合成 blur 只算受控事件；进程 kill 只能模拟进程崩溃，不能宣称覆盖断电、设备缓存和所有文件系统故障。没有相应权限/设备时保留 BLOCKED，而不是把全量 T7 改名成 partial 后放行。不得为自动化临时削弱正式包的安全 fuse、sandbox 或凭据保护。若正式包不能使用调试启动方式，采用获准原生驱动，或分别报告可观测测试构建和正式包人工/原生冒烟，不能把修改过的包冒充原发行产物。

## 10. Agent、技能、MCP 与真实模型评测

### 10.1 两条链分别验

**产品链：**正确工具参数进入后，原工具执行/保存/授权/恢复是否正确。用确定性端点验证，可进常规 PR。

**Agent 链：**真实 pi＋获准真实 LLM 在自然语言、技能、附件、长会话和失败反馈下，是否正确理解、选择工具并完成目标。真实模型输出不稳定，需要预定试验数、固定数据、可检验终态。[W7]

不得为了“固定工具轨迹”误判合法替代方案。只固定必须的偏序，例如审批先于提交、全文完整读取先于宣称已读全文；不要求模型逐字复现某一条理想轨迹。

### 10.2 三类判据

| 判据 | 对 Nomi 的例子 | 是否可由模型独占裁决 |
|---|---|---|
| 硬性正确性 | 三个成片镜头、参考另计、正确目标、有效任务身份、保存内容、付款范围 | 否，程序验证 |
| 可观察体验 | 入口能找到、错误含恢复路径、是否无反馈、需要几次额外操作 | 程序/录屏/人或 AI评议结合 |
| 主观质量 | 分镜连贯、人物/场景一致、表达符合任务 | 可模型辅助，定期人工校准，不替代付款安全判据 |

模型评委看任务和脱敏输出，不看“作者说已通过”的总结；对材料不足允许 unknown。用一组已标注的正例、明确坏例和边界例校准，尤其检查严重错误被误判通过的比例。评委模型/提示词变更是评测器变更，旧分数不能直接同比。

### 10.3 真实模型样本与费用

首轮真实模型评测建议从已存在的稳定任务集小规模开始，每个已批准任务预定3个独立 trial。三次成功只是该样本通过，不宣称99%可靠。失败后禁止不断追加 k；真实付费生成的失败不得由测试框架自动重开一次业务。

| 资源档 | 外部调用 | 默认授权 |
|---|---|---|
| no-live | LLM和媒体均为隔离替身 | 可以用于计划内自动化；仍核对计算/存储配额 |
| live-LLM | 真实 LLM/视觉评委，媒体替身 | **需单独授权与预算** |
| live-media | 指定真实供应商出图/视频/语音 | **需单独授权，冻结模型/对象/次数/金额策略** |

本次研究请求没有提供真实费用预算，默认 no-live。已知单价与未知单价分别处理；预算按并行 worker 共享的原子预留计数，不能每个 worker 都认为自己还有全部额度。超时/unknown 不释放成“可再花一次”，先查询任务与账单事实。账户余额恢复不是新的测试授权。

测试中的合成价目用于 no-live 正负对照，必须标记 synthetic；真实目录价未知保持 unknown，不伪造价格来跨过付费保护。

### 10.4 外部 MCP/技能

从实际注册工具清单生成协议覆盖，不猜“九工具”的名字；从现行获准模型清单决定“哪些四家”，缺失材料只阻塞对应 live 子项。协议列出/调用成功与真实外部宿主完成产物分开记录。[W11]

工具/技能输出、文稿和外部页面都按不可信测试数据处理。加入恶意文本要求改判据、泄漏密钥、跳过付款、调用未准入工具的负向案例。不得为了测试 A2 外部出片而自动启用原来关闭的权限；预期关闭要验证拒绝正确，启用路径另需产品授权。

### 10.5 防止评测过拟合

保留固定回归集，同时轮换不改变需求含义的文稿/人物/素材/表达方式。重要任务留少量未用于修提示词的复核样本，防止只对“林岚、33张、固定三镜”等示例特判。每个问题最终以通用 ID、角色类型和数量断言表达，而不是把用户当时的文案写死在产品逻辑里。

## 11. AI 测试工作的权限和收货方式

AI 适合探索、生成案例和协助归因；固定脚本承担长期回归。按实际能力使用 Playwright Test Agents；它们的网页 seed 不能未经适配当成 Electron seed。先用原 `_launchApp` 启动的窗口证明一条真实操作可被探索和生成。[W8]

| 角色 | 可以做什么 | 不可以做什么 |
|---|---|---|
| 探索者 | 按用户任务操作测试应用，收集难找入口、死路、错误反馈 | 自行给付款授权，读用户真实项目或修改产品需求 |
| 测试实现者 | 使用真实定位器，生成独立可复现测试，提交小范围修订 | mock 掉被测边界；把当前错误行为写成期望 |
| 失败分析者 | 判断产品/夹具/测量/环境问题，提交带证据的修改建议 | 删关键断言、任意抬超时、强制点击绕遮挡 |
| 评审者 | 复核需求、入口、证据和边界，与实现者职责分离 | 用“所有测试绿”代替体验或安全判断 |

官方 healer 可能在认为功能损坏时输出 skipped 测试；Nomi 中这只能是缺陷线索，不能获得发布放行权。[W8]

关键案例的预期变更需要独立复核：产品行为改变由用户或既有产品决定授权；测试 oracle 错误可由非原作者复核后修正，不必把每个定位器调整交给用户。记录旧失败、错判原因、新断言与对照；不能无声降低期望。

没有独立模型/工程师资源时，报告“同作者自评，外部复核缺失”，不伪称多代理独立通过。不为获得不同模型的名字而绕过凭据或预算。

## 12. CI 执行、提速与证据绑定

### 12.1 复用现有风险分档

`validation-policy.mjs` 决定要跑哪些 lane，案例登记决定这些 lane 里必须包含哪些用户行为。两者是选择层级，不是两个竞争分类器。[G5]

| 变化范围 | 至少触发的验证 |
|---|---|
| 付款、任务身份、原 runner/确认入口 | INV-01/02/03/04/11；相关QA-01～QA-08与集成/真实入口 |
| 文稿/方案/保存/绑定 | QA-09～QA-15、受影响旧项目/重开；不遗漏异步目标 |
| pi/消息/技能/队列 | QA-16～QA-21、真实 SDK 与入参/终态检查 |
| 参数条/Portal/手势/共享写入 | QA-22～QA-27，两宿主及原生边界适用项 |
| 诊断/附件/引用/媒体 | QA-26/28及QA-31～QA-38适用项 |
| 打包、依赖、preload/IPC、工具面 | 对应功能＋包内 smoke、QA-39；旧版本读取受影响则QA-29/30 |
| 测试启动器、选择器、评分器、报告、workflow | 测试测试系统的 GA 集＋受影响功能验证，不可只跑新脚本单测 |
| 单纯文档且策略可证明 | 文档与必要静态校验；明确没有功能放行结论 |
| 不可确定影响范围 | 原 fail-closed 全量策略；记录原因，不能静默 focused |

共享文件、动态注册、IPC、生成代码、删除/重命名不能只依赖文件名相似度选择测试。保留一组零费用跨域 smoke，防路径映射遗漏。现有“同文件匹配”不足的地方加最少映射和选择器回归，不写全仓依赖建模平台。

### 12.2 运行节奏

开发时跑定点与邻接；PR 运行被选中的真实入口；定期CI扩展更多种子、长会话和变异；候选包验证完整已承诺范围。这里是实施建议，不是本次已经创建定时任务。

可取消被新提交替代的 no-live PR 测试，标记 cancelled/superseded；不要取消已开始的真实付费任务并立即另开重复 trial，也不要把上一 merge 的证据取消成缺失。复用 workflow 现有分组规则，变更时保留对应测试。[G6]

不能为了速度让多个进程共用 profile/项目，不能杀其他 worktree 的测试或绕锁。先确认外层聚合命令是否已经持锁，避免重复包装自锁。只有在真实资源隔离并验证之后才提高并发。

### 12.3 首次失败与不稳定测试

确定性关键案例默认不重试以掩盖失败；可选一次明确的诊断重跑，仍保存首次失败。非关键 flaky 隔离必须有负责人、具体原因、到期点与替代覆盖，并显示风险；不能隔离付款、丢数据或已确认核心流程错误后继续称全部通过。

预期网络波动与产品错误分离，不用正则把所有 timeout 都归 infra。产品无结束反馈、错误重试、UI卡住，即使起因是供应商故障，也可能是产品行为失败。

### 12.4 包与合并

PR head、实际测试的合成 merge tree、合入后的 commit、候选包不是同一身份。复用原 build stamp 与 exact-SHA CI 收据。纯文档变化可凭影响证明复用相同产品/测试树证据；生产或测量代码变化必须使受影响证据失效。

来源依赖精确：锁文件、Electron/Node、平台架构、构建配置、native binaries、模型/目录与夹具版本。签名、公证、安装、升级和回滚分开列证据。旧格式不兼容时，不能为了回滚直接用旧版本写入新格式数据；使用明确支持的恢复路径和备份。

本方案不自动 merge、push main、发布、推送更新或执行回滚。准备好证据以后，由用户作合入和发布决定。

## 13. 安全、隐私与费用治理

### 13.1 CI 信任边界

公共 PR 代码、附件、生成测试和 workflow 产物都不自动可信。无密钥 PR 环境执行功能测试；持凭据的 LLM/媒体/签名 job 只在获准的可信提交上运行。不能在 `pull_request_target` 的高权限上下文 checkout 并执行未经信任的 PR 代码，也不能通过 `workflow_run` 下载 artifact 后执行其中脚本来绕过隔离。[W10]

自托管机器不得默认读取开发者 home、项目原件、SSH 私钥和日常凭据。测试脚本和子进程使用最小权限和短生命周期环境。测试系统自己若能拿真实密钥并按外部文本任意执行，自动化会扩大事故面，而非降低事故面。

### 13.2 证据的两种版本

**本地私有证据：**必要原始日志和内部关联，只在获准隔离目录保留。

**可提交/可分享证据：**测试夹具、脱敏摘要、相对路径、产物hash、断言结果和明确的数据来源。trace/HAR/截图可能含正文、token、URL参数和本机路径，上传前必须检查，不因为文件叫 redacted 就默认安全。

优先合成或获准的固定素材，不默认使用用户真实文稿。无法完全脱敏的原始记录留本地；分享的是充分可复现的最小片段。哈希不是匿名化保证，短文本/可枚举身份的 hash 不应作为默认隐私方案。读取/打包证据需限制路径、大小、符号链接与压缩包解包范围。

### 13.3 预算与重试

LLM、视觉评委、媒体、云runner分别记录。默认所有 live 预算为0；授权后限定目的、候选构建、模型/供应商、次数和金额策略。unknown 费用保持 unknown，并列已预留/已提交/已确认，不能计成0或认为已经退款。

并行任务统一预留；达到上限后停止新增付费请求，允许对已提交任务做获准恢复。重放服务结果是免费夹具验证，重新请求供应商是另一笔操作，不得混称。

| 编号 | 反例或检查 | 必须得出的结果 |

## 18. 交付、维护与一页报告

### 18.1 每个提交/PR需交什么

准确的生产/测试/工具/文档改动范围；每个新增抽象复用或新增理由；需求→案例→入口→断言映射；红绿测试实际命令和退出码；首失败与重试；app/模型/供应商/OS真实性；源码/测试/包/夹具身份；费用及unknown；未验证项及原因。

不强制为每个微小变化生成另一份长报告。复用原根因合同、报告目录与PR模板；机器索引自动生成，主文只写重要结论和例外。已有代码经确认可用就复用，不因缺新文档重复实现。

### 18.2 建议的一页质量报告（格式，不是本次结果）

```text
范围：本候选承诺的项目/平台/模型/用户行为
构建：源码tree、测试tree、实际安装包hash、依赖/夹具版本
本次变化：影响哪些用户体验，明确哪些没改
必测覆盖：计划数 / 实际执行 / 首次通过 / 不稳定 / 失败 / 阻塞
安全：误删、串写、错误付费、泄漏、未知重提的证据
体验：参数条/错误反馈/窄窗/键盘的关键前后片段
失败：具体用户后果、最小复现入口、真实根因状态
外部费用：LLM/视觉/媒体分别列已知与unknown
平台：Linux、macOS、Windows及source/packaged分别列
结论：测试设施交付状态；产品修复状态；候选发布建议
需用户决定：只有真正的产品取舍、范围豁免或live费用许可
```

不让用户审阅几千行日志。其主要工作应是判断入口是否好找、反馈能否理解、生成质量是否合用，以及明确延期/发布范围；工程实现者负责功能、安全和证据真实性。

### 18.3 运营指标，不造完成比例

跟踪：用户发现但现有回归漏掉的缺陷、从反馈到可复现用例的进展、核心场景首次成功/不稳定率、缺失平台格、测试运行资源、人工重复操作次数、真实费用。按候选范围和运行环境分层，不能合成一个“代码质量90分”。

先测现状，再比较改进。若没有用户使用遥测，不能给出全量用户故障率；可以统计获准反馈和内部测试数据，但注明样本偏差。用户反馈默认本地留存、主动导出，未经批准不新增遥测。

### 18.4 缺陷闭环

反馈 → 保留原证据 → 在副本/合成数据复现 → 写能抓住旧错的案例 → 最小修复 → 邻接及真实入口回归 → 合入后按对应tree复验 → 固定案例维护。

因产品决定淘汰旧入口，可以退役不适用测试；必须引用决定、列出替代行为覆盖，不允许因为它红了就说“旧测试过时”。历史未归因事件维持未归因，后续绿灯不改写原事实。

### 18.5 测试系统自己的运行与维护成本

从 T-QA-21 起记录已有数据能支持的基线；缺数据写未采集，不为填表引入遥测平台。报告首屏只列本批明显变化，细节留原运行结果。成本统计与质量 verdict 分离。

| 观察项 | 最小记录方法 | 用于什么决定 |
|---|---|---|
| 反馈速度 | 同 lane 的排队、运行、取证时间及机器条件；足够样本后再给中位数/分位数 | 是否缩小 PR 必跑组合、移到定期任务或改分片，不能漏掉风险必测 |
| 噪声 | 原首次结果、诊断重跑结果；人工确认产品/测试/环境原因，保留未归因 | 修不稳定根因；不把所有 timeout 记环境错误 |
| 定位成本 | 从首次失败到得到最小可重放步骤的耗时及缺少的证据 | 优先改善哪类日志/trace，不默认采集全部私人内容 |
| 维护投入 | 本批新增/修改的共用助手、重复实现、修夹具时间及负责模块 | 判断抽象是否真正减少维护；没有第二消费者就不扩框架 |

## 21. 方案级判定参考与本次实际自检

### 21.1 验证范围

以下纯函数用来把§6的严格判定规则变成可运行反例。它**没有接入Nomi，没有读取或修改产品状态，也不替代可信证据采集器**。`evidenceComplete`与`fingerprint`必须由原证据/身份校验链生成，不得相信被测Agent自报；生产集成还需GA-11～GA-20及实际CLI/CI验收。

必测计划已在运行前排除经批准的不适用项，key包含case/environment/trial。可选探索与已证实的当前关键缺陷另行传递；已知关键失败不能被可选项过滤隐藏。函数只返回判定，实际CLI需输出逐项原因、分母和全部原始attempt。

### 21.2 参考模块 `verdict-reference.mjs`

```js
/**
 * 方案级严格判定参考；不是Nomi产品实现，也不是可信证据收集器。
 * key已经包含case/environment/trial；attempt从0开始，仅表示诊断重跑。
 * @param {{fingerprint:string, requiredKeys:string[]}} plan
 * @param {Array<{key:string, attempt:number, fingerprint:string,
 *   status:'passed'|'failed'|'blocked'|'skipped'|'cancelled',
 *   assertions:number, evidenceComplete:boolean}>} rows
 * @param {boolean} knownCriticalFailure 已核实的当前候选关键缺陷
 * @returns {'PASS'|'FAIL'|'BLOCKED'}
 */
export function strictVerdict(plan, rows, knownCriticalFailure = false) {
  if (knownCriticalFailure === true) return 'FAIL';
  if (knownCriticalFailure !== false) return 'BLOCKED';
  if (!plan || typeof plan.fingerprint !== 'string' || !plan.fingerprint.trim()
      || !Array.isArray(plan.requiredKeys) || !plan.requiredKeys.length
      || plan.requiredKeys.some(k => typeof k !== 'string' || !k.trim())
      || new Set(plan.requiredKeys).size !== plan.requiredKeys.length
      || !Array.isArray(rows)) return 'BLOCKED';
  const required = new Set(plan.requiredKeys);
  const allowed = new Set(['passed', 'failed', 'blocked', 'skipped', 'cancelled']);
  if (rows.some(r => !r || !required.has(r.key)
      || r.fingerprint !== plan.fingerprint || !allowed.has(r.status)
      || !Number.isSafeInteger(r.attempt) || r.attempt < 0
      || !Number.isSafeInteger(r.assertions) || r.assertions < 0
      || typeof r.evidenceComplete !== 'boolean')) return 'BLOCKED';
  // 具有当前身份的已观察失败，不能被其他格尚未完成掩盖。
  if (rows.some(r => r.status === 'failed')) return 'FAIL';
  for (const key of required) {
    const attempts = rows.filter(r => r.key === key).sort((a, b) => a.attempt - b.attempt);
    if (!attempts.length || attempts.some((r, i) => r.attempt !== i)) return 'BLOCKED';
    if (attempts.some(r => r.status !== 'passed' || r.assertions === 0
        || !r.evidenceComplete)) return 'BLOCKED';
  }
  return 'PASS';
}
```
