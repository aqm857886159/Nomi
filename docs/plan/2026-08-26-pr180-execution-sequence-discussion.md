## 2. 对原方案的调整

| 原安排或本轮需澄清的问题 | 建议调整 | 理由 |
|---|---|---|
| B4 默认自建，pi 仅借源码 | 已确认先验证受控 AgentSession，再接回现有产品；Nomi 专属控制层保留 | 业务控制权和通用框架复用可以分离；不是只改一个 loop import |
| B4 完成后才做 B5 | B5 设计可并行，相关交互在其实现前确认；运行层不等完整样张 | 运行层先满足最小归属/取消/结果合同，不能把全产品设计新增成其前置 |
| 换芯后是否仍保留两个页面助手 | 阶段 2 的 R2-U1 必交项目级会话/任务/宿主统一；area 旧键只作迁移过渡 | 统一运行库不等于统一 Agent，不能把共享历史与任务连续性当可选美化 |
| 把 Part 6 当全串行清单 | Agent 接线与 E2 交付缺口分开推进，再在真实任务里汇合 | 分镜时长和音频导出不依赖 pi，也不依赖整套 Agent 主栏完成 |
| 多空间究竟串联到什么程度 | 将原有选择性采纳原则落实为合同：身份、任务状态、来源连续，内容变化按影响范围选择 | 改脚本不能静默重生成、换素材或覆盖已剪好的片段 |
| 第一条小说 Pack 与通用产品的关系 | 保留原 Pack 候选，但先用短脚本验证通用跨空间闭环 | 本轮核心是多空间交互，不据一条反馈把 Nomi 改成小说专用工具 |
| SDK7 spike 是排定的一步 | 后置为有明确收益时再开，不与 pi 同时做两次运行时迁移 | 缩小选型与回归面；没有证据时维持现有可用运行时 |

三种排法的取舍：

| 排法 | 用户何时获得价值 | 代价 |
|---|---|---|
| 先把 B4 全写完，再设计交互 | 较晚 | 容易把错误的共同编辑规则固化进框架 |
| 先重画三空间，再补执行层 | 很快看到外观 | 确认、恢复、回写可能只是展示，之后返工 |
| **规则前置、两个实现方向并行、按闭环汇合（推荐）** | 每阶段有真实可用的增量 | 需要明确接口与阶段闸门，但不必一次建完平台 |

### 阶段 1：运行层可先推进，交互设计和粗剪基础并行

三个工作包可以并行。当前推荐优先 1B 的 R0→R1：验证 pi 后接回现有产品；不等 1A 完整样张，也不同时大改三套系统。

**1A — 交互合同和关键样张（B5 设计前置）。**

先只回答六件会影响架构的事：

1. 用户发送指令时绑定哪个项目、段落/镜头/片段；之后换页、换选区不改变已发送任务。
2. 人在输入或拖动时，Agent 不抢焦点；当前选区可以建议下一次目标，不能静默重绑已编辑的指令草稿。
3. Agent 工作期间，人改了同一目标怎么办：旧提案不得覆盖；保留结果，允许基于最新内容重算或放弃。
4. 改上游脚本影响哪些已生成/已采纳内容：只提示实际关联的对象，由人选择要不要更新。
5. 停止任务、撤销作品修改、重试生成分别是什么意思：停止不等于撤销，也不保证远端已提交任务能取消。
6. 重开项目如何继续：恢复当前任务与待处理结果；普通导航不必强迫用户重走创作→生成→剪辑。

样张只覆盖选段拆镜、生成中手改、候选采纳、剪辑计划审阅、停止/重开五个关键状态，必须基于真实 Nomi 外壳与设计系统；不新增第四个工作台，也不先重画全部 B5。

**出口：** owner 确认交互规则和关键样张，供新增交互实现使用；不是 1B 运行层验证/旧 UI 换芯的前置。文档、镜头、素材、clip 的关联与版本前提有最小合同。先声明首次流程所需步骤/停点/恢复语义，供后续 L6 封装，不先造通用流程编辑器。

另可并行做 Track C 的客户端 elicitation 能力探针；它只核实现役客户端的确认路径，不必等完整 Pack、E2 或 B5，也不提前宣传外部全流程已可用。

## 4. 谁验证什么

| 验证 | 证明什么 | 不能冒充什么 |
|---|---|---|
| 契约/故障注入测试 | 审批、目标版本、幂等、取消、恢复和 Undo 的安全性 | 不能证明用户理解交互 |
| 真机走查与音视频检查 | 实际构建、实际入口能完成作品；输出没有丢音/错时长 | 静态 `check:walkthroughs` 和旧截图不能替代 |
| owner 看样张 | 产品方向与设计取舍获认可 | owner 不是目标用户样本 |
| 目标用户试用 | 新手是否找得到下一步、能否接管和继续修改 | Agent 模拟角色审查不是用户研究 |

建议第一轮以 5 名目标新手做形成性试用：不给口头指路，完成首次作品、一次中途修改、关闭后继续三项任务；记录完成率、求助点、重复描述/上传次数和返工。人数是建议，不是统计显著性结论；招募与联系不在本轮授权内。

安全硬门：人工修改被静默覆盖 = 0；拒绝审批后付费提交 = 0；重复提交 = 0。自动化验证覆盖本期明确支持的场景，不宣称已解决任意语义冲突。

本稿已做 CTO、设计、PM、前端、后端、用户任务代理六视角的桌面审查，主要修订是缩小阶段 2、提前外部确认不可达的安全边界、区分内外闭环。它不是目标用户试用证据。
