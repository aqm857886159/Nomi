### 0. 一句话根因

画板组件把「组件卸载时清理资源」和「用户关掉画板」当成了同一件事：`InlineWhiteboard.tsx:231` 的 effect 什么都没开，cleanup 却去关业务会话。只要组件被卸载再挂上（开发模式的 StrictMode 演练，或者生产里任何一次真卸载），画板就被关掉。

### 2. 为什么这一类会一直出现

- React 的规矩：effect 的 cleanup 只撤销 setup 做过的事；用户分不出「effect 跑一次」（生产）和「setup→cleanup→setup」（开发）的区别。出处：https://react.dev/learn/synchronizing-with-effects 「How to handle the Effect firing twice in development?」，10-29 实抓。
- 我们把业务动作（关会话）挂在 cleanup 上，违反了这条规矩，于是：
  - 开发模式每次都自关；
  - 生产里节点一旦真卸载也会关。画布开了 `onlyRenderVisibleElements`（`GenerationCanvasReactFlowViewport.tsx:258`），节点移出视口就卸载。
- 门岗为什么没拦住：
  - 画板走查只跑生产构建，还把「点两下才开」当正常；
  - 单测把 `closeWhiteboard` mock 成空函数；
  - 没有一条测试在 StrictMode 下真挂编辑器。
- 铁律：落在 ⑫「点了 = 以为的」。点「打开画板」，预期打开，实际一闪就关。

### 5. P0：我们独有吗

不独有。生命周期规矩是 React 官方的：cleanup 只撤销 setup，业务状态放在外部 store，用显式事件开关。`whiteboardSession.ts` 本来就是外部会话 store，方向和标准一致，不用自己发明。
