## §1 用例卡格式

`cases.json` 是用例登记真源；本文同 id 的卡是人读版本，证据在未来运行报告里，不能把登记状态当运行结果。每卡固定以下字段，先读摩擦再读任务：

| 字段 | 内容与约束 |
|---|---|
| `id` / `title` / `dimension` | 唯一编号、标题；维度为 core / tools / mcp / skill / research / material / long-running |
| `friction` | 用户此刻卡在哪里；每张卡第一段 |
| `user_quote` | 一句话任务输入；来自用户原话时原样保留，其余是明确标注的验收任务句，不伪称用户说过 |
| `expected_experience` | 用户看到的结果、打断次数上限、目标分钟数；均为待验证目标，不是实测承诺 |
| `capabilities` | 工具 / MCP / skill / 沙箱脚本 / 浏览器 / 生成模型 / 剪辑 / 导出中的一组 |
| `status` | 只允许 `runnable-now`、`needs-stage-4`、`capability-gap` |
| `status_reason` | 现状证据及前置条件；Goal 用 `needs-stage-4`，此字段再明确 `goal-v1`，不发明第四种状态 |
| `gaps` | 无缺口用 `[]`；gap 卡每项含 `id`、`missing`、`layer`、`disposition`（固定“先记录不做”），逐项对应 §4 |
| `evidence` | 截图、产物与数字；不能只以聊天里“完成了”作为成功证据 |
| `r30` | `applicable` 或 `not-applicable`；适用时必须记录下述两个数字，不适用原因写在 evidence |
| `budget_cny` | 单次用例总硬上限（人民币）；付费用例 **≤¥5**，零额度用例为 0，所有重试/审片/宿主模型成本都算在内 |
| `emotion_log` | 每步逐秒记录“不舒服”，字段和报告规则见 §5；无摩擦也明确写“无” |

状态解释：`runnable-now` 仅指基线已有可达能力，**不等于已跑通**；`needs-stage-4` 指底座已有但新 lane 的用户入口未切换；`capability-gap` 指完整任务还缺一段能力。阶段 4 合并不会自动消掉 gap。`electron/agentLane/laneIpc.ts:9` 明确影子期不注册，本轮不得手动打开新 lane。

R30 沿用主线口径：工具一次写对率 = 回合内第一次工具调用非错数 / 首调数；回合成功率 = 同时有收尾文字且领域终态符合预期的回合数 / 尝试回合数。报告写 `n/d` 和百分比，分清工具选择、schema、参数绑定、输出处理、端到端失败；拒绝、取消另记原因，不删除失败样本。分母为 0 写 N/A，不能写 100%。C0 一次旅程不能冒充主线的 5 任务 × 3 次评测，沿用其 ≥90% 真实 canvas 首调门和既有成功率基线，不降低标准。

### 执行人、构建和准备

- **谁跑**：一位执行者扮演独立视频创作者，一位验收者完整看片并核对截图（可异步验收，不要求两人同时操作）。执行前在报告填姓名/角色、日期、操作系统、架构、Nomi 版本、构建提交 SHA、安装包 SHA256、使用的 Agent 模型与 MiniMax H3 档案 id。没有构建身份不开始。
- **在哪个构建**：当前打包版可做 C0 基线；阶段 4 切换 PR 的**真实候选打包版**必须在合并前再跑一次。候选版可以在它自己的任务分支注册新 lane，但本轮不做，也不在旧构建注入测试开关伪造。阶段 4 合后按 §5 跑维度用例。
- **隔离**：只建空白验收项目 `G1-C0-<日期>-<构建短SHA>`；通过已有 `_launchApp.mjs:82` 的隔离环境约定设独立 user-data/settings/projects/capability 目录，使用候选包可执行文件启动；人工原生启动也必须保持隔离。不读取、复制或覆盖真实项目库。自动化沿用 Playwright-over-Electron、`_assert.mjs`、`screenshotSettled` 和带 `provenBy` 的 `expectAbsent`，不新造 launcher/断言框架。
- **准备素材**：一份专为验收写的完整短剧本、两张自有角色/场景参考图；明确横屏 16:9、成片 60–120 秒、人物/地点/结局，约 8–12 镜。建议题材“创作者赶在日落前把一次街头观察剪成短片”：到达→发现细节→拍摄→整理→完成。先固定每镜动作和叙事作用，再核对总时长；禁止纯色板、预制成片或人工预填终态冒充闭环。输入文件和授权说明随报告保存，不含私人素材。
- **密钥**：由执行者在隔离设置的安全输入入口配置；报告只写供应商/模型和已配置布尔，不截图密钥输入、不输出鉴权头。未配置时停止并记录环境阻塞，不把费用记 0 后继续。
- **钱怎么算**：本次 **总上限 ¥5**，包括 Agent 文本推理、MiniMax H3、图片/声音/审片及失败重试；本轮文档交付实际为 ¥0。开跑前按当前报价和每镜时长做逐项估算，并预留所有在途请求上界。建议分配 Agent ≤¥1、H3 ≤¥3.5、其他与重试 ≤¥0.5；这是封顶分配，不是供应商报价。价格未知或完整 60–120 秒方案估价 >¥5 就不提交，报告 `blocked-budget`；不能降低时长、改模型、重复镜头凑时长或悄悄超支来拿通过。退回预算/用例可行性决策，C0 保持未通过。没有新的明确授权不得提额。

### 逐步操作与观察

所有截图用 `C0-<构建短SHA>-<步骤>.png`，保存原始尺寸。每步开始/结束记时间；看见稳定状态再截图，固定 sleep 不是完成信号。表中分钟是 45 分钟目标的分配，不是超时后自动通过；超时如实判定并保留在途任务证据。

| 步骤 / 目标耗时 | 执行者做什么 | 截什么、核什么 | 什么算“不舒服”或未通过 |
|---|---|---|---|
| 00 准备 / 3 分钟 | 启动候选包、核对版本和空项目；确认报价、预算与安全配置 | 版本/空项目、输入文件清单、报价时间与逐项上界；不拍密钥 | 版本不明、跑到真库、价格未知；直接阻塞，不能试着花钱 |
| 01 剧本 / 4 分钟 | 从创作区输入完整剧本和上述约束；请 Agent 整理为可拍内容 | 文稿全貌与 Agent 收尾，原文和结果文件 | 要用户手写工具 JSON；反复追问已给的画幅/主角；擅改结局 |
| 02 分镜 / 5 分钟 | 用现有“拆成镜头”或 Agent 分镜入口，审阅镜头顺序、动作、时长和参考 | 分镜表、每镜时长合计 60–120 秒、与剧本对应关系、审批卡 | 表只在聊天里不可继续制作；遗漏关键剧情；时长算不清；术语逼用户猜 |
| 03 画布 / 3 分钟 | 批准分镜落画布；核对镜头数/顺序/参考线、H3 模型与当前参数 | 画布全貌+一个镜头局部、节点与分镜对应、预算确认 | 要逐镜重新输入剧本；参考连错；创建重复卡；看不出将花多少钱 |
| 04 生成 / 15 分钟 | 在真实付费确认后提交；观察任务进度；出现错误先记证据，不盲重试 | 提交前报价/确认、任务进度、成功与失败卡、脱敏 job/run id、真实账单 | 无反馈空转、错误不知怎么恢复、同镜重复扣费；Agent 说成功但无素材。人眼检查动作/身份/连续性，不能拿供应商 success 当质量通过 |
| 05 时间轴 / 5 分钟 | 将选中产物按叙事放入时间轴；播放首尾及每处切点；只作必要剪辑 | 全轨时间轴+切点，片段与资产引用、总时长/音轨、局部修改回执 | 黑段、丢镜、顺序错、长空等、音画不符；必须手动从下载目录找回素材；时间轴和画布看着是两套结果 |
| 06 导出 / 5 分钟 | 在 Nomi 导出 MP4 至隔离输出目录；等真实完成后从外部播放器打开 | 导出设置/进度/完成、文件名/大小/hash、播放器首中尾帧；用已有 ffprobe 检查时长、视频流尺寸与预期音轨 | UI 报完成却无文件；不可解码/截断；时长非 60–120 秒；故事需要声音却被静默省略 |
| 07 完整看片 / 5 分钟 | 验收者从头到尾播放，逐镜核对剧本；重开项目检查产物仍可找到 | MP4 原件、逐镜判定、重开截图、两项 R30 数字、费用与情绪日志 | “机器全绿”但故事不成立、动作不对/切点难受；未披露降级；未解决的体验问题。任何一项都不能宣称 C0 完成 |

| G-SEARCH | Agent 可用的浏览器/搜索与视频来源、日期追溯；未合的找参考 PR 不作为已有能力 | Agent 工具接入 / 外部检索 | R1 | 阶段 4 后另行评估；先记录不做 |
| G-VISION | 让 Agent 获得可核对时间码的画面/声音拆解；已有外部审片与 asset.read 元数据不覆盖全链 | 媒体理解契约 / Agent 工具接入 | R2 | 阶段 4 后结合现有审片能力评估；先记录不做 |
| G-SCREEN | 平面录屏提深度的可用性尚未验明；若需求是点击聚焦，还缺光标跟踪/自动缩放 | 素材加工 / 交互意图澄清 | D2 | 核心出片稳后按真实输入评估；先记录不做 |

R1/R2 的缺口同时阻塞研究→复刻**整链**；R3 独立任务可用人工核实输入，不能据此消账。T4 和 S1–S3 属“底座已有、等接线”，不假造 capability-gap。Goal 的前置另由 L1/L2 与原调研管理，避免复制一份实现 backlog。

## §5 运行顺序与门

1. **本轮只设计与登记**。先校验注册表和文档，不启动 Nomi、不读真实库、不调用生成/评测模型；模型雷达、论文雷达不在本次明确限定范围内，不扩任务。
2. **C0 先跑**。保留阶段 4 切换合并前候选打包版的 C0 硬门，失败/阻塞时套件不能宣称通过。当前旧通路 C0 只给基线证据，不给新通路放行。
3. **阶段 4 合后跑维度用例**。按注册表顺序先 `runnable-now`：T1→T2→T3→M1（两个宿主独立）→M2→M3→R3→D1。M2 可用空配置隔离子环境，M3 复用本次 run；D1 不点生成。再核对 T4/S1/S2/S3 的前置是否实际满足，满足才逐条验；不自动批量把状态改成可跑。L1/L2 还要 goal-v1；R1/R2/D2 先记缺口不实跑其完整任务。
4. **每条写情绪摩擦日志**。格式沿用[现有教训](../lessons/experiential-qa-emotion-log.md)：`时间点 | 步骤/动作 | 预期 | 实际 | 情绪（心慌/看不懂/吓一跳/想骂人/无） | 等待秒数 | 打断原因与累计次数 | 截图/产物 | 问题归属 | 处理与复走证据`。每卡至少有开始、关键转折、收尾三处记录；不能只勾“体验正常”。
5. **区分缺能力与已有能力的故障**。本轮预先登记的 capability-gap 不要求立刻实现；未来 runnable 用例里冒出的 bug、体验/UI/UX/设计/产品感问题，按 R16 修完并复走才算该条完成。不能把失败卡改名 gap 来绕过 C0；本轮若只发现文档事实偏差，就修文档，不扩到生产代码。
6. **收货按构建、用例、尝试分开**。未来报告每条写 pass / fail / blocked / not-run（是报告结果，不是注册表 status）；附失败数和原因，不平均掩盖一个宿主/版本的失败。未跑维度保留 not-run；只有 C0 完成可说“核心验收通过”，不得说所有维度已覆盖。能力 gap 清零也不是本轮完成条件。

## §6 官方 use case eval 形态

### 先查别人

本节官方页面均于 2026-09-08 在线读取正文；只借评测组织方式，不引入 SDK、服务、包或新的外部格式。此 JSON 是仓内用例登记，不冒充 Agent Skills/MCP 等外部协议。

- **Claude Code**：[Best practices](https://code.claude.com/docs/en/best-practices) 的 “Give Claude a way to verify its work” 让任务带可执行检查、截图对照和可读证据；要求看真实运行结果，不能只信完成声明。我们借“任务句+验收证据+实际 UI”，不把编码任务的 build 通过等同于视频好看，也不在 Nomi 复制 Claude Code 的命令/Goal 机制。
- **Codex**：[Testing Agent Skills Systematically with Evals](https://developers.openai.com/blog/eval-skills) 给小型任务集、显式调用/隐式匹配/不应触发三类提示词，采集 `codex exec --json` 轨迹，再做确定性检查和可选 rubric 判分，并观察反复执行与 token 开销。我们借 S1–S3 的正负触发对照、任务输入和可追溯结果，不运行文章中的 Codex 模型评测，不另造 CSV/评分服务。
- **OpenAI**：[Evaluate agent workflows](https://platform.openai.com/docs/guides/agent-evals) 区分排查行为的 trace grading、积累失败案例的数据集、用于回归的 eval runs；trace 记录模型/工具/交接过程，评分要能定位失败步骤。我们借 R30 两个数字、失败归段和按构建保存证据，不上传真实项目/密钥，不要求接入托管平台才能验收。
- **Anthropic**：[Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) 区分 task、trial、transcript、outcome、grader；“说订好了”不等于环境里有订单，倡导从真实失败开始建立小套件，并结合确定性检查、模型判断和人工判断。我们借“说导出完成”必须对应真实 MP4、尝试与终态分开，以及情绪日志；不把通用 benchmark 分数或模型自评单独当质量门。
- **仓库里已有**：`tests/ux/_assert.mjs`（阳性基线+不存在断言）、`tests/ux/production-mcp-journey.e2e.mjs:1`（外部生产旅程）、`tests/ux/video-depth-real-task.walk.mjs:1`（真实素材深度链）、`tests/ux/agent-runtime-production.walk.mjs:73`（分镜工具）已是近邻；继续用它们。官方 Skills 导入规范见 [Agent Skills specification](https://agentskills.io/specification)，本轮只登记已有标准 zip/SKILL.md 的验收，不改格式。
