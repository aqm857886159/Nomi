### 0. 一句话根因

Agent 工具入参被拒有三个校验点（pi 的形状校验、契约 parse、准入层），各说各的话；其中 pi 的形状校验失败走「立即结果」，**跳过 `before_tool` / `after_tool` 两个钩子**——熔断、失败信封、面板三样都挂在那两个钩子上，所以最常见的那一种失败它们一样都看不见。缺的是「一个入参失败边界」，不是哪一句文案。

### 2. 为什么这一类会一直出现

每次修的都是「这一个校验点的这一句话」，而失败的**路**有三条、其中一条（pi 立即结果）在我们所有机制的视野之外。补丁于是落在离边界越来越远的地方（投影层补例子、渲染层正则散文），下一种新工具、新字段一来，它走的还是 pi 的默认正文、计数还是 0。表示层上也没有「一条入参问题」这个东西：每处各自拼字符串，面板只能拿到 `path / expected / receivedType` 三格。

三条体验铁律：⑩ ⑫ 不适用（不是意图↔草稿参数、不是点击预期）；⑪「能选到」部分相关——这一刀让「这一层能填哪些字段」从**模型可见 schema 本身**取，不另抄清单。逃逸账本另记一条（候选），结账挂类检查：25 个真实被拒样本逐条过真实 lane，断言都出字段路径 + 合法值或近似键。

### 3. 不改结构的话，接下来会冒出什么

| 预测 | 怎么验证 |
|---|---|
| 新加一个工具，模型多填一个键，拿到的仍是 `must not have additional properties`，不说哪个键 | 特征测试：样本过真实 lane，读发给模型的请求体 |
| 同一个形状错连发 6 次，熔断计数恒为 0，一次都不拦 | 特征测试：同错 ×6，第 4 次起应是拦截正文 |
| 面板对形状错只显示「参数不合法」，不说哪个字段 | 视图模型测试：无信封的失败结果 zh/en 文案 |

### 4. 靶子独立性检查

- 25 个样本来自另一条线的探针（真实模型、真实被拒入参），不是这条线写的；本线只拿它当输入。
- 真实模型的前后对比由协调会话的评测脚本跑，本线只写命令。
- 没有「修对了反而掉分」的先例；风险点是走查脚本按 `Validation failed for tool` 数被拒次数——新正文首行保留这个头。

### 5. P0：这些是我们独有的吗？现成方案有哪些

- **校验本身**：不自写，用 pi 的 `validateToolArguments`（同一把尺子），结构化错误用 TypeBox 的 `Compile().Errors()`，契约那层用 Zod 的 issues。
- **拦截点**：用 pi 官方的 `prepareArguments` 钩子（校验之前、同步），不改依赖源码。
- **文案格式化**：现成的 `zod-validation-error`、`better-ajv-errors` 各管一种来源，不给「这一层能填的字段 + 最接近的键」，也不分「给模型的（可带它自己刚发的短值）/ 给面板的（不带收到的值，用户文稿可能在参数里）」两份。自写的只有这一个格式化函数，理由是后一条隐私边界；修复的思路是「复用 + 一个格式器」，不新增机制。
- Vercel AI SDK 的 `experimental_repairToolCall` 是另一条路（自动改参数），任务书明令不做「静默改键」。

### 6. 三条路对比表 + 推荐

| 选项 | 做什么 | 代价 | 风险 | 推荐 |
|---|---|---|---|---|
| 沿原方向修 | 再在投影层补一句、给 pi 的正文再加一个正则 | 小 | 下一个工具 / 字段照旧；熔断仍看不见立即结果 | 否 |
| 换一种做法 | 一个入参边界：包 pi 官方 `prepareArguments`，用 pi 自己的校验判、TypeBox / Zod 结构化错误收成一份清单、一个函数写正文、同一个计数器；面板信封按入参重推 | 中：新增一个边界文件 + 一个零依赖清单文件；删掉 `laneArgumentFailure`、桌面端口的 parse 包装、「应长这样」补丁、到不了的「第 5 次终止」 | 正文变长（多了合法值与例子，封顶 8 条 / 600 字的例子）；`perf` 场景守 | **是** |
| 删掉 | 去掉契约 parse 那第二道校验，只留 pi 一道 | 小 | 契约里的跨字段约束（如「图生视频必须有图」）pi 的 schema 表达不了，删了就让坏参数进执行 | 否 |

### 7. 用户要权衡的核心

失败正文变长一点（多出合法值和一个对的例子），换模型第二次就填对、第三次还错就停下来问人，而不是让它自己重试六遍。
