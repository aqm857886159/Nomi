## 先查别人

（10-09 开源调研的结论，整理进本方案；截帧 / 剪辑 / 拆片三件都按这一节的结论走。）

- 依赖里已有：`package.json` 已有 `@ffmpeg-installer/ffmpeg` 与 ffprobe；主进程抽帧 `electron/video/extractVideoFrame.ts`（经 `electron/video/videoIpc.ts:13` 暴露）的实现类型已允许任意 `number` 时间点、带缓存与 PNG 输出——截「当前帧」只差入口，不需要新依赖。
- 仓库里已有：截帧落图片节点 `src/workbench/generationCanvas/nodes/extractVideoFrameToNode.ts`（原先只有首 / 尾两值）；剪辑时间轴 `ClipNodeTimeline` 与统一手势入口 `src/workbench/timeline/timelineGesture.ts`（#1145 / #1149），剪辑面板复用它们而不是引入第二条时间轴。
- 生态里已有（浏览器端媒体处理）：[ffmpeg.wasm](https://github.com/ffmpegwasm/ffmpeg.wasm) 能在渲染层截帧 / 剪切，但约 30MB 级 wasm、worker / CSP 约束与 FFmpeg 外部许可证条件都重复了已有的本机 FFmpeg 能力 → 不接；[Mediabunny](https://github.com/Vanilagy/mediabunny)（MPL-2.0，WebCodecs 读写）适合以后做浏览器侧预览缩略，本片不需要。
- 生态里已有（时间轴组件）：[react-timeline-editor](https://github.com/xzdarcy/react-timeline-editor)（MIT）是另一套数据模型与拖拽 / 吸附，接进来即第二条时间轴；[Remotion Timeline](https://www.remotion.dev/docs/timeline) 是付费可定制层时间轴 → 都不接，复用自有 `ClipNodeTimeline`（「剪辑」领域概念的一部分）。
- 生态里已有（节点图表达媒体变换）：[ComfyUI `nodes_video.py`](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy_extras/nodes_video.py) 内置 VideoSlice / VideoTrim 等节点，印证「截帧 / 剪辑结果是一张新节点、原视频不动」的节点图做法。
- 自媒体（TikHub）：未查——截帧 / 剪辑是常规动作，交互已由用户 10-10 按样张拍板。
- 结论：媒体处理全部走已有本机 FFmpeg；时间轴与手势复用自有实现；不新增依赖。

## 样张怎么搭的（为什么这些格子可信）

- 浮条：`FloatingToolbarShell` / `ToolbarActionMenu` / `ToolbarButton` / `NodeDepthActionButton` 全是生产件；新的只有「哪几颗钮、什么顺序」。节点卡是骨架外壳（类名与现役逐字相同）里放一个**真 `<video>`**，所以播放头、时间码是真的。
- 剪辑面板：入点 / 出点手柄、拖动手感、时间尺、播放头是生产 `ClipNodeTimeline` 本体（一条视频放成一个片段，片段两边就是入点 / 出点）。「拖动入点中」那格对真手柄发真实的 pointerdown / pointermove（不发 pointerup），不是画的。确认 / 取消用生产 `DecisionBar`（确认在右）。
- 按镜头拆：面板是生产 `NodeShotCutPanel` 本体（实验室替它开了一个假项目、一条假的检测桥）；新增的「拆成：图片｜视频片段」用生产 `NomiSegmented`，样张里挂进底栏，接线时就是面板里一行 JSX。
- 结果格：现役 `GenerationCanvas`（真 React Flow、真连线、真编组框、真错误卡、真处理中遮罩）+ 夹具节点；成组落位用生产 `shotCutNodePositions`。
- 不是生产本体的地方（诚实标出）：①卡片外壳是骨架；②读数行（入点 / 出点 / 保留）靠观察时间轴片段元素上的 `data-start-frame` 实时跟，接线时给时间轴加一个可选 `onResizePreview` 回调（约 5 行）替掉观察；③剪辑中的顶条借深度提取同一个 `GeneratingOverlay`，接线时把 `isVideoDepthProgressPhase` 放宽成「本地处理阶段」；④预览中那格视频冻在 11.5 秒、界面显示「播放中」（截图要确定性）。

## 九格

- ★1 用户怎么用：当我在画布上有一段视频，我想从里面取一帧或一段，以便拿去当首尾帧 / 参考 / 接力，而不必离开画布。步骤：选中视频卡 → 浮条「截帧▾」选当前帧（先在卡里把播放头停到想要的画面，菜单里显示它的时间码）/ 首帧 / 尾帧 → 旁边出一张图片卡并连线；或点「剪辑」→ 贴着卡弹出面板 → 拖入点 / 出点 → 点播放预览保留的那一段 → 点「确认」→ 旁边出一张新视频卡（顶上一条进度 + 取消）；或「拆解▾ → 按镜头拆」→ 面板里选「拆成：视频片段」→ 点「拆成 N 段视频」→ 一组连好的视频卡。真实任务：①取视频第 7 秒的画面当下一镜首帧；②把 24 秒长镜头剪成 6–18 秒；③把五个镜头的成片拆成五段分别二次生成。不做：全局时间轴剪辑、多段合并、智能剪辑（竞品有，我们不做）、花钱。已知坑：原视频不动，所以磁盘上多一份文件（项目缓存区）；N 个切点切出 N+1 段，所以选「视频片段」时面板按段显示（含 0:00 起的第一段，每格写起止区间），标题、主按钮、结果卡数都是同一个 N+1（样张 5）；图片模式不变。主指标：点「截帧 / 剪辑」后 60 秒内拿到新卡；护栏：原视频被改动 = 0。证据：待实现线补真实任务脚本。
- ★2 谁说了算：结果卡是节点，归画布 store（`generationCanvasStore`）；落位 / 连线 / 编组沿用 `extractVideoFrameToNode` 与 `extractShotCutsToNodes`（一份）；ffmpeg 抽帧归 `electron/video/extractVideoFrame.ts`（`which` 已经支持任意秒数，当前帧不需要新 IPC）；剪辑要新增一个主进程动作（裁一段落成项目素材），放在同目录，复用 `electron/export/` 的 ffmpeg 路径解析、进度解析（`ffmpegProgress`）和取消（`ffmpegRunner` 杀子进程）。事实只存一份：新卡的来源 = 一条普通的画布边，不另记「派生自」字段。意图走显式事件（点了哪个钮），不猜。证据：实现线跑 `node scripts/door-map.mjs extractVideoFrameToNode`。
- ★3 一致与复用：见「样张怎么搭的」。同类控件一个组件：三选一菜单、二选一分段、确认 / 取消都是现成件。颜色全 token，实验室文件里没有写死色值。
- ★4 全状态：截帧——空 / 加载（<1 秒，不做加载态）/ 成功（新图片卡）/ 失败（新卡变错误卡：顶上一行原因，原视频不动，格 11）；剪辑——刚打开（入点出点在两头，读数 = 全长）/ 拖动入点中（读数高亮入点、预览画面跟着入点、手柄旁是生产的「−6.0s · 18.2s」标签）/ 预览中（只播保留段，按钮变暂停）/ 确认后处理中（新卡先用入点那一帧占位，顶条「剪辑中 · 62% [取消]」，格 7）/ 成功（格 6）/ 失败（格 12）/ **取消中**：点取消 = 杀 ffmpeg、删掉那张新卡，和深度提取一致（「取消 = 当没发生过」）；能力不可用：ffmpeg 找不到时新卡直接出错误卡，原因写「找不到 ffmpeg」，下一步 = 重试（桌面端内置 ffmpeg，正常不会发生）；拆成视频片段——切点检测中 / 一镜到底（没有切点时「拆成视频片段」灰掉并说原因，改走「均匀抽帧」只对图片有意义，所以一镜到底时二选一不出现）/ 成功（一组卡 + 编组框 + 来源线）。zh / en、亮 / 暗、画布 50% 全有格。文案不谈钱。失败卡沿用现役错误卡，**已知别扭**：现役错误卡的按钮里有「换个模型」，对本地处理没意义（深度提取失败现在也是这样），建议另开一刀把本地处理的失败归一类、只留「重试」；本样张不新造卡。
- 5 中途表：见下表。
- 6 外部数据与失败：外部来源 = 用户的视频文件（可能是 HEVC / 变帧率 / 无音轨 / 仅 https 链接）。`which` 秒数超出时长 → 主进程夹到末尾前 0.1 秒（`resolveSeekSeconds` 已有同类处理，实现线补测）；HEVC 在 Chromium 播不了 → 剪辑面板预览走现有 `useVideoPlaybackHeal` 自愈；ffmpeg 失败一律带 stderr 末尾 300 字进错误卡的「技术详情」，不甩锅给用户的 key。
- 7 性能预算：截帧 = 一次 ffmpeg 抽帧（现有路径，本机单帧亚秒级）；剪辑 = 重编码。**本机实测（Windows，20 线程，合成 1080p 30fps 素材）**：60 秒片段 libx264 veryfast crf18 重编码 5.9 秒（约 10 倍速）；同一段整段流拷贝 0.24 秒（但只能切在关键帧上，不帧精确）。真实素材（高码率 / 4K / HEVC）与低配机器会慢几倍到十几倍，**unverified，待真机量**。设计：默认重编码保帧精确；任务在主进程跑、不占渲染线程，进度由 `out_time` 解析；一次只跑 2 个剪辑任务（与现有 filmstrip 并发闸同口径）。长视频（> 10 分钟）剪辑需要几分钟，因此必须能中途取消、关面板后继续在新卡上跑（面板只负责设入点出点，确认后即收起，进度全在新卡上）。
- 8 真实条件：Windows ✓（本机离屏 Chromium 真渲染，中英 / 亮暗各 14 格）；最小窗口 unverified；真规模 unverified；干净安装不适用；真付费不适用；键盘：面板内 Esc 关闭、Tab 走控件沿用现有控件行为，**手柄的键盘微调（←→ 一帧）样张没画**，实现线要补；真素材 + 真 ffmpeg 全链路 unverified（样张用夹具视频）。
- ★9 验收与回滚：验收（另一条线）：按 ★1 三条真实任务在真窗口走一遍，核对 14 格（命令 `node tests/ux/design-lab-video-node-next.walk.mjs`）；硬门：原视频文件与节点在三条路径后字节不变；取消后无残留卡无残留临时文件；英文界面无截断。回滚：实现 PR 整个 revert，样张屏留着不影响（`calibration.json` 登记在，基线待拍板后才录）。独立验收报告：待协调会话派线（不得与实现线相同）。
