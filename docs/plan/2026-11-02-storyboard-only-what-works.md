## ★1 用户怎么用

Brief：创作者拆完镜头后，每镜管自己的提示词、模型和参数；整页只生成剩余，选中用来交给 Agent 或删除。新手通过每镜模型菜单换类型，老手勾几镜用自然语言修改。

真实任务：①拆完镜头逐镜换模型 → 参数跟随新模型 → 单镜生成；②整片改 9:16 → 单独覆盖不变 → 生成请求与画面一致；③勾三镜交给 Agent → 面板打开且输入聚焦 → 说要改什么；④生成剩余 → 确认卡去掉两张 → 请求少两次。每步用“预期 → 实际 → 证据”记录。

主指标：有用控件归位比例 100%，量具 `tests/ux/storyboard-only-what-works.test.mjs`。质量：跨类型模型与供应商正确比例 100%，量具行为单测及真实编辑器浏览器测试；护栏：去掉镜头请求比例 0%，量具批量执行测试与走查。当前基线来自指定提交，目标见 ★9；真实模型仅由验收协调运行，当前 unverified。

### ★1b 连带界面

模型菜单保留现成默认模型及供应商选择；参数面板从新模型档案 derive；首帧提示词关闭后保留但不参与执行。Agent 仍用既有引用芯片，不新增聊天编辑器。确认卡和失败面沿用依赖分支成果，不改样子和行为。

### ★1c 老用户

`plan.aspectRatio`、逐镜模型和参数、`meta.frozen`、`shot.sceneId` 不迁移，旧项目照常打开；跳过从未持久化。用 `tests/fixtures/old-user-data/` 与 `tests/ux/core-a-old-project.packaged.mjs` 核对；未跑即标未验证，不以合成夹具替代。图片+视频切图片模型会按现有类型切换语义移除首帧，报告明示。

发布说明草稿：中文“分镜配置回到每一镜；整片画幅在分镜标题旁，多镜修改请选中后交给 Agent。”英文“Configure each shot in its own row. Film aspect is beside the storyboard heading; select shots and ask Agent for changes across shots.”

## ★3 一致与复用 / 方向检查

### 0. 一句话根因

旧的整片配置、多选配置和每镜配置同时存在，把创作决定复制到三个作用域；旧合同测试保住了冗余入口，却没有保住“点了后的真实结果”。

### 1. 归类表

| 症状 | 直接原因 | 类 |
| --- | --- | --- |
| 重复配置 | 批量条、浮条、行分别写参数 | 同一决定多入口 |
| 交给 Agent 没反馈 | 只写引用，不打开面板 | 动作反馈断链 |
| 首帧开关可能丢模型 | 类型切换函数清模型参数 | 开关与类型耦合 |

### 2. 结构缺口与体验铁律

⑩模型和供应商必须一起写；⑪每镜参数继续从档案 derive，删除的批量入口从可达检查移除，其它入口不减弱；⑫交给 Agent 必须有引用、打开与焦点三种可见结果。

### 3. 可验证预测

若只藏批量条，实验室与旧调用仍保留入口；若关闭首帧时删对象，提示词丢失；若只换模型 key，跨类型请求仍可能按旧类型执行。分别由引用全表、开关保留行为测试、跨类型请求测试核对。

### 4. 靶子独立性

实现线自测，不冒充独立验收；旧三入口、批量模型测试依据新的拍板更新；独立验收由另一条线按 ★9 完成。

### 5. P0 领域与复用

镜头模型、画幅、按镜请求属于本项目领域；控件继续用现有 NomiSelect、InlineParameterBar、Mantine、既有批量卡；不新增 npm 包。

### 6. 三条路

| 路线 | 代价和风险 | 结论 |
| --- | --- | --- |
| 沿原方向补 | 继续同步三个作用域，测试固化冗余 | 不选 |
| 换批量模式 | 增加解释和控制 | 不选 |
| 删除重复入口 | 多镜改动需对 Agent 说一句；保住每镜控制与确认卡去除 | 按已批准方向执行 |

### 7. 核心取舍

用一次自然语言表达换掉长期占屏且无效的整片与选中配置。

热点：`StoryboardShotRow.tsx` 近14天 3 个 fix，目录 6 个 fix；本次为已授权删除方向，按指定任务边界推进。特征测试先锁模型身份、画幅覆盖、批量去除和旧数据；不改变锁定、移场、生成失败面或确认卡。

## ★4 全状态
