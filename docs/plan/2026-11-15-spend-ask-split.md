# 设计卡：付费确认拆开——镜头在对话里竖着排，输入框上只留一条确认

> 四类（花钱确认的样子 + 界面重排）。用户 2026-11-15 在探索稿第 ⑤ ⑥ 块上定了方向：「按竖排做没有问题」，并要求每一行点了能到那个节点。
> 这一刀只做界面这一半；「落的和原本要的不一样」怎么带过来是另一刀（Agent 只说想要什么那张卡的 2b），这里只给它留好位置。

## ★0 先查别人

| 出处（2026-11-15 协调自己打开看的） | 它怎么做 | 对哪个决定的影响 |
|---|---|---|
| LibTV 助手（真发了一句做图，停在确认上；截图在仓库外，指纹 26271d47dce1…、22f5ff90ad55…、1e0ab3a597d8…） | 对话里只有一行「图片节点已创建」，点开是带节点名的小标签；确认占输入框的位置：一句问话 + 预计消耗 + 「查看提示词」+「本对话自动确认」+ 取消 / 确认生成；点「查看提示词」选中画布节点并在画布顶上给「1/1 取消 确认生成」 | 确认只放问话和按钮、镜头在别处指，方向一致。不一样的地方和原因：它印积分；我们的预估花费按 11-07 模型面板那块板印积分，下一刀做，这一刀留位置；它的指向是纯文字标签，我们带小缩略图（生成后同一行变成结果）；它的自动确认开关在确认条上，我们的在输入框模式菜单里（紧挨着，不重复放） |

- 出口：不涉及：这一刀不改任何出口——确认条「取消」、行尾「不生成 ×」/「恢复」、节点上的 ↑ 都照旧，镜头留在画布上；只换了镜头住在哪儿（LibTV 同样是取消后节点留着、可在节点上单独再生成，2026-11-15 截图）。

## ★1 用户怎么用

当 Agent 起草了一批镜头、要我确认花钱时，我想一眼看清「要生成几段、什么参数」，想细看哪一镜就点它去画布，以便镜头再多、说明再多，确认也不把对话挤没。

1. 我说「把文稿拆成 12 个镜头」。
2. 对话里 Agent 那句话下面出现这一批镜头，一行一个：小缩略图 + 镜号 + 标题；露前 4 个，下面一行「还有 8 个镜头」。
3. 输入框上方一条确认：一行共同参数 + 「取消」「生成 12 段」。
4. 我点第 3 行 → 画布定位到那个节点并闪一下；窄窗口时对话收成小球，画布底部有「回到对话」。
5. 我把鼠标停在第 5 行，点行尾的 × → 这一镜退出这次出价，主按钮变「生成 11 段」，那一行变灰写「已去掉，不生成」，行尾是「恢复」。
6. 我点「生成 11 段」→ 确认条变成「正在发出 k/11 段」+ 取消；每一行自己显示到哪了。
7. 发完确认条收走；那组镜头下面多一行「✓ 已发出 11 段」。出了结果的行缩略图换成画面。
8. 哪一镜没发出去，原因写在它自己那一行；确认条留着原因和下一步按钮。

量具：★9 的清单在设计实验室和真窗口里逐条走；确认条高度用 `getBoundingClientRect` 量（3 镜和 12 镜必须相等）。

不做什么：不在确认条或行里改参数；不做完整预览；不印合计金额（逐镜价格折叠照旧，不在这一刀动）；不动全自动；不做「落的和原本要的不一样」的数据（另一刀）。
已知坑：付费卡以前只画过 3 镜（实验室夹具类型就是 1|2|3）；格子形态的「不生成 ×」是挂在缩略图角上的，行形态要重新给它找位置。

### ★1b 连带界面

- 面板收起时小球上的待确认计数：不变。
- 窄窗口点指向 → 对话收成小球：收起后确认条也不见了（今天的卡也是这样），不在这一刀改。
- 画布节点上的「已去掉，不生成」「等你确认」：不变。
- 外部 MCP / 时间轴 / 任务中心：不涉及。

### ★1c 老用户

没有存盘数据变化。旧对话里的「已发出 N 段」回执是按节点和 Run 现读现画的，升级后自动换成一行一个的样子；旧卡账本键照旧只停读不清盘。

## ★2 谁说了算

- 「这一次出价里有哪几镜、各自到哪了」：宿主推来的那一次出价 + 画布节点，唯一投影 `agentPanelSpendCard.ts`（纯函数）。不新增第二份。
- 「一镜在聊天里长什么样」：`NodePointer` / `NodePointerGroup`。行形态已有，这一刀给它加「超过 N 个折起」和「行尾挂宿主小动作」，不另写一个列表组件。
- 「对话里某次生成的那一组」：`GenerationReceiptPointers`，从「发完才出现」改成「出价时就出现，一组用到底」。
- 允许读：面板外壳、设计实验室。不许：确认条自己再读一遍节点去画镜头。

## ★3 一致与复用

- 以前定过、还算数：10-22「聊天里只放三样；请示不顺带改参数；多个对象用一组指向」；10-23 指向元素 P1 小卡 + P2 行内 / 列表行，付费卡一张卡一颗「生成」；10-25 数量只写在主按钮上；11-14 极简（每行都一样的事只说一次）；11-07 模型面板板（ModelSurfaces）`cost.batch-card`「批量 / Agent 花钱确认卡沿用，单位换成积分」。
- 核过前提后改掉的旧决定：10-08「界面不谈钱」（付费卡板 D5「合计行不印金额」、设计系统「钱只印一处」里「不印金额」那半句）。当时的理由：都走中转站，扣没扣钱、扣多少 Nomi 不知道，印数就是替用户断言。现在不成立：价目已经在目录里（画布批量确认条已经在印预估），用户 2026-11-15 原话「当时我们不谈钱，是因为我们没有深度适配 APIMart……有些东西变化的话，其实应该是去改决策的」，同日批了新说法「可以印预估、不断言实扣、算不出不写 0」。还成立的一半照旧：不断言实际扣了多少、不说免费、算不出不写 0。这一刀只留位置。
- 这一刀改掉的已批条目：付费卡板 `card.title`（标题问话，删：按钮已经说了）、`card.pointers`（搬到对话里）、`card.pointer.exclude`（× 从缩略图角搬到行尾）、`card.summary`（只留共同项，逐镜不同的回到各行）、`card.done`（不再另画一组，原组下面加一行）；指向元素板的组指向在对话里默认用列表行、超 4 个折起。
- 三条路：沿原样只限高（镜头多时仍然又图又字，说明还得另起一行）；拆开（选这条，理由见 ★0）；不在聊天里确认、去画布上点（和 10-22「必要请示放聊天」相反）。

## ★4 全状态

| 状态 | 对话里那组镜头 | 确认条 |
|---|---|---|
| 等确认（1 镜） | 一行 | 共同参数 + 取消 / 生成（左侧留给预估花费，这一刀空着） |
| 等确认（多镜） | ≤4 行全露；更多折成「还有 N 个镜头」 | 共同参数 + 取消 / 生成 N 段（左侧留给预估花费，这一刀空着） |
| 逐镜参数不同 | 不同的那一项写在各行第二行 | 只写共同项 |
| 去掉一镜 | 那一行变灰「已去掉，不生成」+ 恢复 | 数字跟着减 |
| 全去掉 | 全灰 | 现行「没有可生成的」那一态，文案不改 |
| 发出中 | 各行自己的状态 | 「正在发出 k/N 段」+ 取消 |
| 发完 | 组下面一行「✓ 已发出 N 段」（都出结果后「已生成」） | 收走 |
| 某镜没发出去 / 参数被拒 | 那一行红色第二行写原因 | 原因一行 + 现行的两颗按钮 |
| 画布接走了一部分 | 那几行显示节点自己的状态 | 「生成剩下 N 段」 |
| 节点被删 | 行显示「已删除」，不可点 | 数字跟着减 |
| 读不到待决 | 不画组 | 现行那张缺卡，不改 |
| 刹车说明 | 不变 | 说明一行 + 按钮 |
| 取消中 | 行状态照节点 | 现行写法 |

## 5 中途表

发出中点取消：已发出的照常生成，没发的留在组里可再发；面板收起再打开、切对话再回来：组和确认条按同一份出价重画，不丢「去掉」的选择（现行行为，回归）。

## 6 外部数据与失败

不接新的外部数据。失败原因文案沿用 `spendCardFailure`。

## ★7 性能

新增的操作：展开「还有 N 个镜头」；悬停某一行（画布节点同亮）。最坏规模：一次出价 40 镜（宿主上限：`electron/shared/agentCapabilities/generationPlanSchemas.ts` 里出价镜头 `.max(40)`）、画布 200 个有图节点。预算：仓库默认「操作到可见反馈 ≤100ms」，两下取慢的那一下。

场景 `tests/perf/scenarios/spend-rows-expand-hover-40.json`（量具 `tests/perf/canvas-scale-bench.mjs` 的工作台场景 `spend-rows-expand-hover-40`：每次采样先按「取消」收掉上一份、从画布 store 删掉上一份那 40 个节点（「取消」不删节点，不删的话节点越积越多、适应视图缩到远景、节点外壳不挂），再让 Agent 出一份新的 40 镜出价（面板收成小球时仍挂在 DOM 里，收起再打开不会让那一组回到折起），新那一组是折起的；点「还有 36 个镜头」到 40 行全画出来，再停到最后一行到画布节点亮）。实现线只量不写基线（`--measure-only`），登记为待测，基线由协调或验收线写。数字：见下一行。
- 实现线 `--measure-only`（提交 acffa83df + 本场景修正，darwin arm64 M5 / 24GB，5 次 + 1 次预热）：中位数 38.9ms / p95 43.4ms / 预算 100ms，长任务 0 次；慢的那一下是悬停到节点亮，点开 40 行比它快。

## ★9 验收与回滚（动手前写全）

1. 3 镜和 12 镜的确认条高度相等（量具：`getBoundingClientRect`）。反例：把镜头塞回确认条 → 红。
2. 12 镜默认只露 4 行 + 「还有 8 个镜头」；点了全露。反例：把折起阈值改成无穷 → 红。
3. 每一行真点一次：画布选中的就是那一行的节点（读选中节点 id 对比）。反例：把行的点击处理拿掉 → 红。
4. 行尾 × 去掉一镜：主按钮数字减 1、节点显示「已去掉，不生成」；点「恢复」回来。反例：× 不改出价 → 红。
5. 发完后对话里同一次生成只有一组镜头（按 `data-operation-id` 数 = 1），组下有回执行。反例：恢复旧的「发完另画一组」→ 红。
6. 确认条里没有指向元素（确认条内 `data-node-pointer` 数 = 0）。反例同 1。
7. 逐镜参数不同：确认条不出现「×2 · ×1」这种拆写，不同项在各行第二行。反例：恢复旧摘要拆写 → 红。
8. 某镜没发出去：原因出现在那一行，也出现在确认条；「再试一次」只重发那一镜。
9. 中英文、明暗、宽 390（真面板默认宽 V4_PANEL_WIDTH，和同槽反问卡同宽；原写 392，产品里没有这个宽）和窄 320 各一张实验室截图，自己逐张看过；窄 320 英文标题不折成两行、不顶出面板。
10. 铁律矩阵 `tests/experience-laws` 全绿；`pnpm run check:board-parity`、`pnpm run check:design-lab` 绿。
