## ★1 用户怎么用

当我框了一组节点点「生成这一组」、在分镜页点批量生成、或让助手「把这几镜出了」时，我想让每个入口对同样的节点给出同样的结论——谁会被生成、默认勾哪些、谁先谁后——以便我花的每一份钱都是我看见并同意的，锁住的不被重做，已经付过钱、能免费找回的不被再付一次。

步骤：①选范围（框组 / 勾镜头 / 对助手点名）→ ②入口把节点事实和动作意图交给共用主人 → ③主人回一份规划：候选行（勾 / 不勾 / 灰着 + 原因）、实际成员、依赖先后 → ④确认处照这份规划画（样子不变）→ ⑤确认后按我勾的再问一次主人，得到执行计划 → ⑥派发；中途有节点被别处占用或入队前被剔掉，再问一次主人，依赖重算。

不做：不改确认条 / 确认卡的样子和花费数字；不改账本写口、授权、停下、失败传染、任务中心的职责；不碰模型能不能用（只消费）；不改差异 1 的默认取值。
已知坑：画布节点和分镜草稿不是同一种数据（分镜确认前不落节点），所以主人吃的是中立的「事实 + 稳定 ID」，不吃画布节点本身；一个镜头可能是首帧 + 镜头两个付费任务。

真实任务（同一组事实，样本来源：本线按现有测试夹具形状在仓库里新建的对拍测试；不是合成的新形状，节点状态都是现有代码会产生的）：
1. 画布组生成：框 8 个节点（2 个没生成、1 个失败、1 个已生成、1 个锁住、1 个可找回、1 个生成中、1 个 idle 但有结果）点「生成这一组」。
2. 单节点带未生成上游：镜头 B 参考角色卡 A，A 没出图，在 B 上点 ↑：确认条列 A、B 两项，A 先 B 后。
3. 分镜批量：同一组镜头绑在分镜方案上，点「生成未生成的 N 镜」。
4. Nomi 里的助手点名几镜：助手起草方案后 `generate` 点名其中 4 镜，付费卡 → 交给画布。
5. 外部助手点名几镜：外部宿主走付费门点名同样 4 镜 → 交给画布。

指标（目标 → 信号 → 指标）：
- 一致：五个入口对同一组事实的成员、默认勾选、先后，除意图表里写明的格子外逐项相同 · 指标：对拍测试里不一致项 / 总项 = 0 · 量具：新增 `src/workbench/generationCanvas/runner/generationScopeEntries.test.ts`（走真实入口：`runGroupGenerate`、`startGenerationFromComposer`、`runStoryboardBatch`、`presentGenerationPlan` / `resolveGateScope` + `handOverShotsOp`）。修前基线：差异 1/2/3 三处不一致（准备线静态推演，本线实现前先用这个测试跑出修前数字）。
- 护钱：锁住的、可找回的进入执行计划的比例 = 0（所有入口）· 量具：同一对拍测试 + 反例表。
- 不悄悄改范围：被规则剔掉的项在付钱前出现在确认处（灰着带原因）的比例 = 100% · 量具：对拍测试读确认处行；真窗口走查读回（`canvas-group-generate` / `storyboard-batch` 或现有最接近的走查）。
- 收口：自己算成员或先后的生产文件数 1（主人）+ 1（事实适配）· 量具：`node scripts/door-map.mjs` 前后对比 + 扩展后的 `check:batch-machines` 扫描。

## ★3 一致与复用

- 以前定过：2026-10-08 C10「没生成的默认勾、已生成的默认不勾（可勾上重生成）、生成中的锁住」（`docs/design/2026-10-08-approved-designs.md`，仍算数，原样进意图表）；2026-10-27 不点名只重摆最近一张卡（仍算数，主人原样）；2026-09-06 可找回不进批量（分镜已做，这次扩到所有入口）；分镜「锁 = 满意了别动，不进批量」（`storyboardRowActions.ts:322`，扩到所有批量入口）；2026-06-14 单发自动备齐未生成上游（保留为「单发」意图）；W2 冻结门（未冻结参考卡的下游拦下，保留）。
- 三条路：沿渲染层 `dependencyWaves` 扩（主进程要反依赖渲染层，或逼分镜确认前落节点，不选）；扩现有共用主人（选这条）；删入口内整段统一走组生成（会丢分镜确认前不落节点、首帧 + 镜头两任务、出价账「最近一张卡」语义；只作为本方案的调用方减法）。
- 复用：现有的拓扑算法原样搬家（不重写、不引库——依赖图规模几十个节点，Kahn 分层几十行，引图库换不来任何东西）；现有状态词；现有锁开关与免费找回。

## ★4 全状态

- 空：一个能勾的都没有 → 现有「这一组没有能生成的」提示（不变）。
- 加载：规划是同步纯函数，不出加载态。
- 成功：确认处照规划画，确认后照勾的跑。
- 失败：上游没结果 / 未冻结参考卡 / 成环 → 现有拦下文案（不变）。
- 部分成功：现有失败汇总 + 「重试失败的 N 个」（不变，改问主人排）。
- 取消中：现有（确认前取消零花费）。
- 过期：卡开着时节点被别处开始生成 / 被锁 / 变可找回 → 确认后再问主人，那一项不进，跑完的汇总里按现有「跳过」说。
- 能力不可用：不适用——范围规划不需要模型或外部资源；模型能不能用由另一条线的共用判据管，这里只消费。
- 最大值：一组 40 镜（每镜 3 张参考、依赖链 6 层）的确认卡行数 = 现有行为，不改；最长文字：行名沿用现有截断。

## 已定（协调 2026-11-17 回话）

1. 单发点在锁住的节点本身：照常允许，行为和今天一样。锁只管批量形状的入口（组生成、分镜批量、重试失败、交接、单发自动补进来的上游）。理由：锁防的是「机器顺手把它带上」，不是防人自己点这一个。意图表里写成一格 `lockedTarget`（单发 = 允许，其余 = 拦下），带一条测试。
2. 组生成确认卡上锁住 / 可找回的行：灰着、不可勾、用现有状态词（已锁定 / 可找回），不加新字、不改布局。这是花钱确认处的样子变化，推送前交中英真窗口截图（卡上同时有可勾、已锁定、可找回三种行）+ 修前同状态对照图，由协调问用户。
3. 助手点名了锁住的镜头：加一个原因码 `node_locked`，中文「这一镜已锁定，先在节点上解锁」，英文同义。它同时是回给助手的工具结果里的受控原因（公开码 + 这句话），助手能据此改口；先找已有的准入指引（`electron/shared/admissionRejectionHints.ts` 一类）作为它的家，不另开第二处；进文案登记门岗。
4. 不知道 1 复现出来就改：参考卡成员按参考列里实际摆着的，不再按 `anchorIds`。复现不出来不改，写明。
5. 旧漏洞「可找回的参考卡会被列进分镜批量卡再付一次钱」单独一条修前红的测试；PR 正文「真实场景复现」照实写由读代码发现、真窗口复现与否。
