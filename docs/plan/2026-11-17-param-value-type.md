## ★0 先查别人

- JSON Schema 按类型的关键字（https://json-schema.org/understanding-json-schema/reference/type ，复盘线亲自打开）· `type: number` 只认数字 42，字符串 "42" 不通过；标准只负责声明和校验，任何一步都不自动转换 · **确认了**：内部值和报文值各自要有明确的类型，不能指望下拉控件或 JSON Schema 替业务把值规整好。所以规整必须由我们自己在一个门口做一次。
- Zod 的 coerce（https://zod.dev/api?id=coercion ，复盘线亲自打开）· 在 `schema.parse` 那一处把 unknown 变成目标类型，数字转换沿用 Number 的语义 · **确认了**：值门用已经装好的 Zod（`^3.25.76`）。门口先把空串、null、布尔值和非规范文本排除掉，剩下的再转成数字。不对全部参数盲目 Number，也不引入 v4 才有的 codec。
- 仓库里的先例：`electron/shared/videoCapabilities/geminiOmni11.ts` 把时长声明成数字，`electron/catalog/kieGeminiOmni11.ts` 记下了真实供应商要的是字符串，只在出口那一步 toString · **确认了**：门里用数字，出口按供应商契约编码。我们这次在已有的唯一出口里做编码，并且照档案声明的报文值来编（理由见 ★3），不去改供应商存盘的 paramMap。
- typescript-eslint 的 `no-unnecessary-type-conversion`（https://typescript-eslint.io/rules/no-unnecessary-type-conversion/ ，本线亲自打开）· 拦「值已经是目标类型还去转」的 `Number(x)`、`+x`、`String(x)` 等，原文 "This rule requires type information to run" · 对守的影响：它要类型化 lint，仓库没开；而且我们门里读出来的参数袋是 `unknown`，它不认为转换多余，拦不住。仓库现有的 ESLint 守全是内置 `no-restricted-syntax` / `no-restricted-imports` 加选择器，选择器只认语法形状，认不出「这个变量来自参数袋」。所以这次写一条用 ESLint 标准规则接口的小规则（见 ★3、★9.15），这是仓库里第一条这样的规则。
- 出口：Ajv 的类型转换规则（https://ajv.js.org/coercion.html ，复盘线和本线都亲自打开过）· 默认关着（`coerceTypes` 为 false）；只在调用校验器、输入类型对不上时尝试转换，转不成就校验失败（原文 "otherwise the validation fails"）；多类型时按顺序试，oneOf 会在每个子 schema 里各转一次，而且不回退 · 确认了我们的出口：转换只放在一个边界，不给每个下游开，也不给全部 schema 开。门认不出的值（非规范数字串、空串、文字）原样交给现有政策，也就是「值摆不成原样就取最近、付费前写明」，或者照旧拒收并说明原因；不自动当成 0，也不自动当成默认值。这次不新增、不扩大、不挪动任何会挡住人的保护。外部助手送来的 `"12"` 在准入之前先规整，所以只会多接住原来被误拒的值，不会多拦。助手写入时「两个时长」的拒收（`writeVerbs.ts:137`）这次不动。

## ★1 用户怎么用

当我在分镜行、画布节点上点了一个时长，或者让助手按我的意思填时长时，我想要行上显示的、节点上存的、约价算的、最后发给供应商的都是同一个秒数，以便点 12 就真拿到 12 秒的片子，也只为 12 秒付钱。

步骤：
1. 选模型；
2. 打开参数面板，或者用节点底栏；
3. 点时长，或者告诉助手「这镜 12 秒」；
4. 关面板；
5. 看行上显示和约价；
6. 点生成；
7. 供应商收到这个模型契约要求的写法（RunningHub 收字符串 `"12"`，APIMart 的 Seedance 收数字 12）。

不做：
- 不改参数面板、节点底栏、分镜行、模型菜单的样子和文案；
- 不改约价的样子；
- 不改「换模型之后旧时长怎么处理」，那件事另有记录；
- 不评判助手怎么起草；
- 不改「值摆不成原样就取最近、付费前写明」这条裁决；
- 不批量重写用户资料。

已知坑：
- 声明不在内置档案里的控件，包括旧目录配置、ComfyUI、用户目录里的 `parameterControls`，主进程看不到它们的声明，所以这次保持原样，不做规整。它们今天的行为也不变，见 ★1c。
- 用户的中转草稿如果写了 `"5s"` 这种非规范档位，这一档不规整，照今天的样子处理，见格 6。

## ★2 谁说了算

概念：参数值的内部类型，以及它和供应商报文写法之间的换算。唯一的家是新文件 `electron/shared/videoCapabilities/paramValue.ts`，主进程和渲染层共用，纯函数。

三个门，各一处：

1. **声明门**（档案进门时规整）：放在档案唯一入口 `electron/shared/modelArchetypes/entry.ts` 里，产出 `scopedArchetype` 和 `narrowToVariant` 结果的那一处。
   - 规则：一个下拉控件的选项如果全是规范数字串（`String(Number(s)) === s`），选项值和默认值都换成数字，每个选项同时记住它声明的报文值。
   - 文字、混型、非规范写法一律不动。
   - `catalogFacts.headlessDefaultsOf`、`everyBuiltInArchetype` 这两处直接读 `MODEL_ARCHETYPES` 的，实现时改成同样经过声明门，或者证明它们只读报文默认值、不需要规整。
2. **值门**（外来值进门时规整）：`admitParamValue(control, raw)`，用 Zod 实现。
   - 有限数字直接通过；规范数字串转成数字；其余原样交给政策处理，不当 0、不当默认。
   - 调用方：
     - `resolveModelParams`，全部政策都先过门；
     - 准入：`executionContract.ts` 现在先检查类型，再用 `Object.is` 严格比对枚举，所以必须在它之前规整；
     - 分镜改时长：按控件的角色认时长，不认字面上的 `'duration'`；
     - 分镜方案读入：两个字段打架的处理；
     - 「从参数里读秒数」的唯一取值函数 `paramSeconds(bag)`：取代外部助手的估时 `shotDurationSeconds` 和推荐目标 `videoRecommendationInput`、助手起草 / 改镜头时读时长、导演预演读时长、生成列表的时长读取。
   - 不改：助手写入时「两个时长」的比对（`writeVerbs.ts:137`）。它是写入边界，今天 `"12"` 和 5 不会被它拒，修后也不拒；这种镜头读入时按用户定的规则保留 5。不扩大任何会挡人的检查。
3. **出口编码**：`encodeParamsForWire(controls, params)`，放在 `electron/catalog/taskParams.ts` 的 `applyHeadlessParamDefaults` 里，对「创作者自己的参数」（`owned`）编码，**在补供应商操作默认值（`applyWireDefaults`）之前**。
   - 这是两套引擎、所有路由共同经过的一处：`runtime.ts` 和 `apimartGenerationProvider.ts` 都调它，后面接唯一一次 `applyParamMap`。
   - 每个已声明的控件按它声明的报文值写回去。可以重复跑，不改供应商存盘的 paramMap。
   - 放在补默认之前，是因为 Agnes 2.5 这类操作的默认参数本来就是供应商写法（`"5"`）；先编码再补默认，补进来的值一个字节都不动。
   - 编码按什么认控件：和声明门用同一个入口函数认档案（`resolveModelArchetype`，按模型名也认），不看请求里有没有方式记录。方式已知，就用这个方式的控件；方式不知道（无界面请求、按模型名认出的中转草稿），就看这个键在全部方式里的声明，各方式写法一致才编码，不一致就原样放行。内置目录里数字类下拉 24 个「档案 × 键」，跨方式写法不一致的是 0 个；实现时连同数字型控件再普查一遍。
   - 这样，凡是渲染层认得出档案、把值规整成内部类型的地方，出口也一定认得出、编得回去；两边都认不出的，值从头到尾都是声明写法，不需要编码。

## ★3 一致与复用

以前定过什么（都还算数）：
- 2026-11-13 定过下拉修值只在渲染层发送前做（`fixDropdownsBeforeSend`），这次保持不变，只是它调用的 `resolveModelParams` 先过门。
- `parameterControlModel.test.ts:16` 记过一条真实旧案：数字下拉发了字符串，被供应商 400。这次照旧按供应商声明的类型发，数字档案发数字。
- 「值摆不成原样就取最近、付费前写明」，不改。
- 参数面板、节点底栏、模型菜单三处是同一套组件，不改。
- 「门口把关一次、门里不再防守；进程间、外部助手、导入文件、供应商回包仍然在门口解析」，照做。

三条路：
- 沿原方向修：只在分镜改时长那里补一个 Number。最便宜，但范围计算、估时、严格比较照样会再出问题，第二处转换还是写得出来。不选。
- 换一种做法：进门统一、出口编码。**选这条**，复盘推荐的，用户 2026-11-17 拍板。
- 删掉：单独删防守，旧字符串进来会更糟，所以只作为第二条路的一部分，同提交删。

复用：
- 值门用 Zod，已经装了。
- 声明规整挂在已有的档案唯一入口上，不另立第二个档案读取口。
- 出口用已有的 `applyHeadlessParamDefaults` 这一处，不新增出口。
- ESLint：仓库现有的守都是内置 `no-restricted-syntax` 加选择器，选择器看不到「这个变量是从参数袋里读出来的」，挡不住改名复制和内联。所以这一条用 ESLint 标准的规则接口（`create(context)` 加作用域查询）写一条小规则，判据和豁免名单放在 `scripts/` 下一个模块里（照 `scripts/ui-money-format.mjs` 的做法：数据住脚本，`eslint.config.mjs` 只加我们这一段注册）。

和复盘字面说法的一处偏离：复盘写的是「发送出口复用 paramMap 一次编码」。本线改成在 `applyHeadlessParamDefaults` 里照档案声明的报文值编码。理由有三：
1. paramMap 是按供应商操作存进用户 `model-catalog.json` 的。给 20 个控件逐家加 toString，就要改存盘操作，还要处理老用户目录的刷新。
2. 照声明编码不用碰存盘，中转草稿也一并覆盖。
3. 编码之后 paramMap 照常运行，它看到的值和今天一字不差，所以报文不变。

不做的：不把全仓 `parameters: Record<string, unknown>` 改成品牌类型，那样要牵动几百处调用。品牌类型只加在门的产出上，也就是 `resolveModelParams` 的结果和 `encodeParamsForWire` 的入参。其余地方靠 ESLint 规则拦住门里的再转换。守不住的形状如实写在 ★9。

自写登记：`paramValue.ts` 里只有「规范数字串」这条判据，以及时长按角色认，这是供应商声明带来的领域约束；解析本身交给 Zod。它落在已登记的领域目录 `electron/shared/videoCapabilities/` 下，不用另登记。ESLint 小规则 `scripts/param-value-door-rule.mjs` 登记进 `docs/engineering/self-written.json`（只加这一条，理由「判断变量是否来自参数袋，是领域判断」）。

登记与合同：六个门（`paramValue.ts` 的五个加 `storyboardPlanSchema.ts` 的 `reconcileShotDuration`）登记成一个概念 `docs/engineering/concept-owners/generation.param-value-type.json`；根因合同 `docs/fixes/2026-11-17-param-value-type.root-cause.json`；画布控件里「选中的串换回声明值」那条旧边界随函数搬进 `paramValue.ts`，在 `scripts/boundary-owners-ledger.json` 记一行改锚，判法不变。
