## 2. 全部发现（14 条，按「模型有没有可能做对」分组）

### A · 模型**不可能**做对的（宿主要了它拿不到的东西）

| # | 问题 | 后果 |
|---|---|---|
| A1 | 多镜 `draft_shots` 要求模型自己填整只 `candidate`（`candidateId`/`providerId`/传输层接线）| 分镜天生多镜 → **这条路 100% 失败**。单镜路早就修过同一个毛病并写下了理由（「让模型不必去发明内部 candidate ID 和供应商接线，之前的行为表现为一次假拒绝」），只修了 N=1 那个 arity |
| A2 | 参考图要求 `contentHash` + `version`，而**没有任何读工具返回 `contentHash`** | Agent 挂的参考图**一张都递不进去**。真机 27 次失败里 11 次是它 |

### B · 模型做对了，被我们弄丢或拒掉的

| # | 问题 | 后果 |
|---|---|---|
| B1 | 动词声明了每镜 `title`，宿主 `shots[]` 是 `.strict()` 不认 | 整次调用被拒。模型填的是**我们说明书上的字段** |
| B2 | `title` 从动词到两个终点（画布节点标签、花钱确认卡）中途被**五处手写的逐字段重建各丢一次** | 每个节点叫「镜头 shot-1」，花钱卡上是被砍断的提示词前 120 字。编译期全合法、测试全绿 |
| B3 | 翻译层把每镜与顶层的 `candidate.providerId/modelId` **整个丢掉** | 模型说「用 apimart 的 image-1」，宿主拿用户默认模型去花钱，**没有任何人报错** |
| B4 | `shotId` 在没有 `draftId` 时被剥掉 | 模型以为改了第 3 镜，实际新建了一份草稿 |
| B5 | `read_script` 的 `scope`：内部 lane 手写 `?? "full"` 兜住，外部 MCP 面没有这行 | 外部宿主上 `nomi_document_read` 直接失败 |

## 6. §5 那一问的答案（2026-09-18 当日回来的）

正本：`docs/plan/2026-09-18-tool-layer-prior-art-verdict.md`（分支 `research/tool-layer-prior-art-20260918` @ `0470dfc30`）。
查了六个面：MCP 2026-07-28 规范 + TS SDK、Claude Agent SDK、Messages API、pi、Codex、ChatCut。

### 裁决：**对了一半，错了关键的一半**

- **对的那半**：两道运行时动作（准入校验 + 审批）必须存在，且审批归宿主。
  **这个前提与「跨不跨进程」无关**——所以我说「关卡不能拆」是对的，但我给的理由（跨进程）不是真正的理由。
- **错的那半**：把它做成**两份手写 schema + 一张对照表**。
  别人的做法是**一份 schema 两个用途**：宿主契约 schema 是唯一真相，模型面是它的**投影**（`hide` + 描述），
  宿主自补写成显式 `fill`，而且**补完要重过同一份 schema**（Claude Code 原话）——最后这条我们没有。
  唯一两处手写的先例是 Codex，而它**已经量到漂移**（`timeout_ms` 宿主收、模型不知道）。

我们那张对照表上 9 条 rename，**7 条的理由是命名偏好**——按我们自己的 R5.5（偏差理由只许领域约束、不许偏好）
这 7 条不合法。

**它为什么能一直活着**：`RuntimeToolCall.args: unknown`（`transportContracts.ts:22-26`）把类型抹平了。
类型一旦抹平，两份手写 schema 就永远不会在编译期对上账。

### §4 九项的逐项判定

| 判定 | 项 |
|---|---|
| 方向对、实现对 | 候选合成器 · 信封单源 · 参考图宿主解析 · 技能不复述 · 失败出口收敛 · owner 核 |
| 对的方向、**为一条本可消掉的缝造的尺子** | 一致性门岗 R1–R3（R4/R5 留着） |
| **对的方向、错的实现** | 翻译派生化——是第二好解；`defaults` 两条与宿主 `inherited` 重复 |
| **只做了一半** | superRefine 搬动词面——**不进 JSON Schema，模型在发出调用前看不见**，只在被拒时读到 |

最后那条要记住：我以为「搬到动词面 = 模型提前知道」，实际上 `superRefine` 不进 published JSON Schema，
**模型仍然只能撞上去才知道**，只是拒绝信息好了一些。这条没做到它声称的事。

### 清单里 14 条都没覆盖的那一条（我已独立核实）

**外部 MCP 面上同一个重命名存在第三份手写实现。**
`mcpGenerationToolCatalog.ts:33-52` 的 `buildOperationCreateParams` 是一份逐字段手抄（14 个字段一个个列），
里面带着**第三份** `modelKey → modelId` / `vendor → providerId` 翻译。注释自己写着「字段拷贝」。
`check-mcp-operation-constructible` 只核「可不可构造」，**不核「可不可填」**——所以 A1/A2 那两类
（宿主要了模型拿不到的东西）在外部面以另一种形式仍然存在。

所以 §3 那句「重复表述四遍」**说少了**。
