# 方向检查：gate-family

> 📋 方案待拍板 · 状态由 docs-autosync 自动登记，作者请按实修改

## 0. 一句话根因

`gate-family`（自写登记 id）把通用 Git 历史比较编排和 Nomi 语义债务规则绑在一个脚本里；每次分支拓扑出现新边界，就容易在同一门岗继续补条件。

## 1. 归类

| 提交 / 问题 | 直接原因 | 类根因 |
|---|---|---|
| 发布分支被 main 后续债务收敛判红 | resolver 同时使用多个历史快照 | 没有独立的、可复用的单一基线选择策略 |

## 2. 为什么会重复

Git 祖先关系是通用能力，但当前门岗还同时负责 Nomi 词汇扫描、债务语义和输出格式。边界没有拆开时，任何新发布流都会继续在这里增加特殊分支。

## 3. 不改结构的预测

- 下一次发布分支出现不同的 merge-base 形态时，会再加一个 ref 特例。
- 其他只需要历史棘轮的门岗会复制同样的多参照选择逻辑。

## 4. 独立性检查

特征测试先用真实临时 Git 仓库锁住两种拓扑：HEAD 包含 main、以及分叉 release 只取 merge-base。测试结果由 `scripts/check-vocabularies.node-test.mjs` 自己判定，不依赖评分器或 UI。

## 5. P0：是否有现成方案

`git merge-base` 与 `git merge-base --is-ancestor` 是现成标准能力，本次已直接接入，没有新增自写 Git 算法。词汇扫描、债务解释和 fail-closed 输出属于 Nomi 的领域门岗约束，暂不能由通用库替代。登记条目：`gate-family`。长期替换条件：把“历史快照选择”抽成独立可版本化库，并让至少两个门岗复用同一 API；在此之前继续修现有共享边界会减少复制。

## 6. 选项

| 选项 | 代价 / 风险 | 建议 |
|---|---|---|
| 接入现成 Git 标准 | 已可用，但仍需 Nomi 的单参照政策 | **本次采用** |
| 补当前脚本 | 短期改动小，长期仍有门岗耦合 | 仅作过渡 |
| 重写为独立基线库 | 需要第二个消费者和迁移窗口 | 达到上述替换条件后采用 |
| 删除门岗 | 失去债务棘轮，发布回归无自动拦截 | 不采用 |

## 7. 用户要权衡的核心

现在保留 Nomi 专属门岗能立即阻止错误基线误报；代价是 `gate-family` 仍需在后续有第二个消费者出现时拆分，届时再做一次结构迁移。
