## 为什么做

英文界面下，设置→AI 的系统提示词编辑框显示整段中文。那个框是**邀请用户改**的（可编辑、可覆盖、
可重置、还能自建），模式名早就翻译了、正文没有——于是英文用户看到一个「请你来定制」的框，
里面是他读不懂更不敢动的中文，这个功能对他等于关闭。

2026-09-02 走查发现（EN-DOM 断言网 `tests/ux/i18n-sweep.walk.mjs`），当时按「提示词是发给模型的
本体、翻译会改行为」先豁免了，并明确记为「产品决定，另开任务」。本文件是那个决定的落点。

## 用户已拍板的两条（2026-09-02）

**① 七条全出英文版**（不是只翻短的、也不是只加英文说明）。

**② 英文一路到底：指令英文，产物也英文。**
这一条是真正的分叉点，必须写清楚它的代价：`assetMasterPrompt.ts` 的产物是**喂给图像/视频模型的
提示词**，而它明写着要中文——

- `assetMasterPrompt.ts:30` 输出语言：纯中文自然语言，禁止英文标签（技术术语除外）
- `assetMasterPrompt.ts:516` 所有提示词使用纯中文自然语言，禁止英文标签
- `:346` / `:480` 【中文AI提示词】（500-800字 / 200-400字）

Nomi 现役图像/视频模型（Seedream / Seedance / 可灵 / 即梦）是中文调优的，上面那两行「禁止英文
标签」很像是**已经交过的学费**。所以「产物也英文」有真实的画质下行风险。用户知情后仍选它，
条件是：**必须真实生成 A/B 验收过才算完成**（见下方验收门）。这不是可省的一步。

## 机制设计

`getCreationAiMode()` 是**同步**函数且在渲染期被调用（`CreationAiPanel.tsx:133`），所以语言解析
必须同步。沿用仓内既有做法：`i18n.resolvedLanguage` 同步读，与 `translateModelDisplayText` 同构。

落点选在**已经存在的** `defaultCreationAiPrompt(modeId)`（`creationAiModes.ts:142`）——它本来就是
「这个模式的默认正文」的唯一出口，`listCreationAiModes()` / `getCreationAiMode()` 都经它。把语言
解析放进这一处，两个出口自动跟着走，不新增并行读方（P1）。

### 覆盖（override）与切语言的语义

覆盖按 modeId 存**整段正文**，取值是 `resolveEffectivePrompt(默认正文, 覆盖)`。默认正文变成随语言
解析之后：

- 没改过的用户：切语言 → 拿到该语言的默认正文。**这正是本次要的效果。**
- 改过的用户：切语言 → 仍拿到他自己那段（显式编辑优先）。于是英文界面里可能显示他当初写的中文，
  `hasPromptOverride` 也会正确地把它标成「已自定义」。

**刻意不做迁移**：用户显式写下的正文不该被系统按语言换掉——那是替他决定他想要什么。这条语义
写进测试钉住，别让后来的人以为是漏改。

## 验收门 3 实测结果（2026-09-02）

**方法**：同一个英文三镜头故事（灯塔看守人的女儿 Maren，三镜头都出现，要求长成同一个人）。
两臂唯一变量是系统提示词用中文版还是英文版。文本 `deepseek-v4-pro`（temperature 0.3），
图像 `doubao-seedream-4.5`（2K），视频 `doubao-seedance-2.0`（4s/720p），全部走 APIMart。
产物与图存 `outputs/en-prompt-ab-20260902/`。

**先修了一处实验设计错误**：头一次只发故事，中文臂自作主张按默认往下做了（8049 字符），
英文臂老老实实停在「先确认画面类型/题材/…」那一关（589 字符）。两版提示词的启动段是逐句
对应的忠实翻译，都写着「首次启动必须询问」——所以那一轮量的是「模型会不会擅自跳过确认关」，
不是资产提示词好不好。改成两轮对话、两臂用**同一份确认答复**过关，才隔离出真变量。

**结果**：

| 维度 | 中文臂 | 英文臂 |
|---|---|---|
| 产出规模 | 16.9K / 25.9K 字符 | 46.1K / 40.1K 字符 |
| 结构完整性 | 七层场景 + 角色 + 道具齐全 | 同左，标记与分节编号一一对应 |
| **跨镜头角色一致性**（最重） | 3 张里 1 张干净、1 张混入无关成年人、**1 张直接画成成年男人** | 3 张全是同一个 12 岁女孩，同一套服装（黄油布外套/深蓝裙/棕靴/辫子） |
| 场景图遵循度 | 高：炉门「CLYDE 1897」按提示词铸出来了 | 高：罐子「Flour/Sugar/Tea」按提示词写对了 |
| 缺陷 | 角色年龄/性别失守（1/3） | 角色页被画成设定图，标签文字乱码（"Coustome color"/"Javline Horizontal"）；瞳色画成紫色（提示词写的是灰蓝） |

**结论：英文产物不比中文差；在最该称量的跨镜头角色一致性上明显更好。**（中文臂那张成年男人
是硬失败——Nomi 的核心价值就是同一个人在多镜头里长得一样。）

**顺带推翻了本次的前提假设**：中文版明写「输出语言：纯中文自然语言，禁止英文标签」，但
两次运行里**有一次整篇产出的是英文提示词**（A-zh-run1，25,893 字符里只有 979 个汉字）——
故事是英文时，那条中文硬约束本来就守不住。所以「中文产物」并不是一个稳定现状，
「换成英文会丢掉已验证的中文调优」这个担心，前提并不成立。

**seedance 英文运镜词（另一条同类风险）**：同一主体各出 4 秒视频比首尾帧——
`环绕镜头` 与 `orbit camera move` 都出现了视角转动；`推镜头` 与 `push in` 都出现了明显推进
（中文那条推进幅度略大）。**英文运镜词被 Seedance 认，不需要回退中文词表。**

**这次实测的边界（别当成定论）**：单一故事、单一图像模型、角色 3 张/场景 2 张/视频 4 段、
单一文本模型。中文臂那张成年男人有可能是运气差。真要下死结论得多故事多模型跑。
但就「要不要因为画质下行而回退」这个问题，证据方向是明确的：不回退。

**留下的两个真缺陷**（不影响本次结论，另行处理）：
1. 英文角色提示词偏长（3,997 字符 vs 中文 1,227），且带「多视图 + 色卡」规格语，把图像模型
   带成了画设定图并渲染出乱码英文标签。要么在英文版里压掉那段版式语，要么产品侧明确
   「角色图就是要设定图」。
2. 英文臂瞳色画错（紫 vs 灰蓝），中文臂没错。样本太少不足以定性，但值得盯。

## 残留风险

- 537 行的 `ASSET_MASTER_PROMPT` 带大量字数约束（「500-800字」「30-50字」）。中文「字」与英文
  word 不等量，直译会把长度语义弄坏；英文版必须换算成 word 数并在 A/B 里核对实际产出长度。
- 该提示词有 A.1.2 / B.2 / C.1 这类**内部交叉引用**，翻译时编号必须原样保留，否则模型会找不到
  它自己引用的小节。
- 中英两份 537 行提示词此后要**同步维护**，改中文忘了改英文会静默漂移。本次先不做同步门岗，
  记在这里；若漂移真的发生，再考虑给它加结构校验（章节数/编号集合一致）。
