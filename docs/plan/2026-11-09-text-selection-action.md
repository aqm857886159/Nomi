改动名：选区浮条「生成」簇收成一张动作表 + 一个分派函数　类别：[其他]（看不见的修复；看得见的那半交出图）

## 用户报的问题与真实复现

- 原话（2026-11-08）：「我在文本区域点击了，滑中句子，点击视频icon，然后为什么发送了文字，这个是个问题。」
- 修前真机复现（隔离资料、loopback 夹具模型、零花费，开发构建，中 / 英各一遍）：创作页点正文 → 鼠标拖选一句 → 浮条右侧三颗图标依次点。
  - 第二颗**摄像机**（「生成视频」）：建一个视频节点（提示词 = 这句），切到生成画布；夹具文本请求 0 次，对话里没有消息。这是拍板设计（`docs/design/boards/2026-10-19/CreationAiRewrite.board.json` FUN-06）。
  - 第三颗**胶片**（`IconMovie`，「拆成镜头」）：选中的句子作为一条用户消息发进右侧 Agent 对话，夹具收到 1 次文本请求；气泡上只有这句话和一颗印着原始 key `workbench.storyboard.planner` 的小签。**这就是「发送了文字」**：胶片在设计系统盲测下读作「视频」，后果却是把文字发进对话。
- 和用户那次的差别：夹具模型不是真模型（这里只看「发出去的是什么」，与模型无关）；用户原图没有留，用户点的是哪一颗由「发送了文字」这个后果反推（只有胶片会发）。

## 设计卡（★ 5 格）

- ★1 用户怎么用：当我在创作文档里拖选一句、点浮条上的某颗生成图标，我想要那颗图标说的那件事（图片节点 / 视频节点 / 交给 Agent 拆镜头），以便不用再读一遍才知道自己触发了什么。不做：本次不换图标、不改文案、不改气泡（都是看得见的改动，出图交用户）；已知坑：胶片图标读作「视频」，修好要换图标（推荐设计系统 §7 分镜的 `IconLayoutRows`）。量具：`tests/ux/creation-selection-actions.walk.mjs`（中 / 英）+ `src/workbench/creation/selectionActions.test.ts`。老用户：不碰存量数据，不适用。
- ★2 谁说了算：「选区 → 生成簇哪颗钮做什么」只在 `src/workbench/creation/selectionActions.ts` 的 `SELECTION_GENERATE_ACTIONS`（长相、名字、去处）和 `runSelectionAction`（唯一分派）；浮条只按表出钮。删掉旧的两条分派路（`handleCreate(kind)` 与内联 `onStoryboard?.(); onCreated?.()`）和旧文件 `createNodeFromSelection.ts`；删掉没人读的 `creationSelectionText`（每次选区变化都写、全仓零读者）。证据：`node scripts/door-map.mjs createNodeFromSelection`（修前 1 扇写门）、`node scripts/door-map.mjs runSelectionAction`（修后 1 扇）。
- ★3 一致与复用：以前定过——08-26 F3 把「拆成镜头」放进浮条，和 AI 面板入口共用同一个分镜启动器（`docs/plan/2026-08-25-ux-f3-f16b.md`，仍算数）；10-19 拍板板把图片 / 视频 / 拆成镜头标为「原有，不动」（仍算数，所以本次不改样子）。三条路：沿原代码修这一处（没有可修的逻辑错：两颗钮都照设计走）／换成 TipTap 自带 BubbleMenu（只换定位，解决不了「图标和后果对不上」，同一面也没有未结的定位问题，不做）／删掉一个入口（删胶片入口要推翻 08-26 拍板，交用户）。选：把分派收成一处（看不见），看得见的换图标交出图。复用：节点仍经 `generationCanvasStore.addNode`，分镜仍经常驻 Agent 发布的 `storyboardPlannerLauncher`。
- ★4 全状态：没选中 / 只选了空白 → 浮条不出（不变）；选中 → 三颗都在，没有分镜启动器（不在创作面）时「拆成镜头」灰（不变）；点图片 / 视频 → 建节点并切画布（不变）；点拆成镜头 → 发给 Agent，加载 / 失败 / 取消照 Agent 面板现有状态（不变）；能力不可用 = 没有启动器，灰着，下一步是回到创作面（不变）。
