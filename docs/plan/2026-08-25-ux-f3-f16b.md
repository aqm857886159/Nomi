# 2026-08-25 · F3 / F16b UI implementation plan

## Scope and accounting baseline

Owner-approved sample geometry (viewport 1440×842):

- Creation selection popover: `(337,103)`, `210×40`; six controls at `y=108`: bold `(342)`, italic `(373)`, H1 `(404)`, H2 `(435)`, divider, image `(478)`, video `(511)`.
- Assistant storyboard action: `[data-action-run="storyboard"]`, `(998,217)`, `162×28`, label `拆成镜头 · 落画布`.

The changes are deliberately limited to the approved surfaces. The selection popover gains a third generate-family icon after image/video (target width approximately `240–285px`, keeping the existing compact visual rhythm). The existing assistant action remains, and both entry points call the same `launchStoryboardPlanning` implementation; no second planner path is introduced.

## F3 implementation

1. Lift the existing storyboard planner launch callback to the shared creation workspace boundary so `WorkbenchEditor` can invoke it without duplicating the handler.
2. Pass that callback into `SelectionGeneratePopover`; add a Tabler movie/clapperboard icon with the existing icon-button treatment and bilingual `aria-label/title`.
3. Preserve the assistant card/button and its handler unchanged except for receiving the shared callback.

## F16b implementation

1. Inspect the existing generation funnel: `runGenerationNode` currently asks `requestAssetUploadConsent` before the paid confirmation, while `confirmGenerationSpend` owns `SpendConfirmDialog`. The standalone hosting dialog is only used by this runner path; existing unit coverage is for that helper.
2. Replace the runner's second dialog path with a hosting-disclosure descriptor resolved from the same local-reference/KIE/policy checks. When the generation confirmation is chargeable and the descriptor says anonymous hosting is needed under `anonymousAssetHosting='ask'`, render the disclosure block inside `SpendConfirmDialog` and a `记住我的选择，以后不再问` checkbox.
3. The primary confirmation authorizes both spend and upload. On a remembered choice, persist the existing `anonymousAssetHosting` setting as `'allow'` through `desktop.settings.automationPolicy.set`; cancellation resolves both as false. Non-hosting and non-chargeable flows retain today's card shape.
4. The repository scan found only the generation runner calling the old dialog helper. It now uses the new non-UI resolver before the spend card; the old `requestAssetUploadConsent` popup remains only as a direct-run fallback when a caller bypasses the spend funnel (so an unconfirmed autonomous run is never silently uploaded), and is not reachable after the normal paid generation card. No second card follows a normal spend confirmation.

## Non-goals / rollback

- Do not redesign the toolbar or assistant card; do not change the storyboard planner implementation.
- Do not add a new settings key; `anonymousAssetHosting` remains the single source of truth.
- Rollback is a single commit revert; no data migration is required.

## Acceptance gates

- Bilingual copy passes `check:i18n`; all new geometry/color uses existing tokens/classes.
- UX walk proves: selection `拆成镜头` is visible/clickable and reaches the same planner handler; hosting-needed generation shows one card with full disclosure + remember checkbox and no second card; remember writes policy `'allow'`. Include positive probe before `expectAbsent`, and light/dark screenshots.
- Isolated walkthrough sets `NOMI_ELECTRON_USER_DATA_DIR`, `NOMI_SETTINGS_DIR`, `NOMI_PROJECTS_DIR`, and `NOMI_CAPABILITY_DIR`.
- `pnpm run gates` exits 0 without piping `test` or `build` output.
