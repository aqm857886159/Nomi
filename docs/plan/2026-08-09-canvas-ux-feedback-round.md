## 2. 统一判断

这些不是六个孤立的 CSS 问题，统一根因是**操作层级失控**：

- 窗口级 chrome 与产品级导航混排，Windows 比 macOS 多一层产品按钮。
- 任务面板依赖固定 `TOP_OFFSET = 64`，没有跟随触发按钮的位置。
- 汇总条和分组标题同时说“进行中”，同一状态被两个组件重复拥有。
- 节点把同类动作平铺；低频图片动作没有进入同一个长尾容器。
- 行业术语直接露出，没有翻译成用户可预期的结果。
- Toast 只按消息创建，没有节点级稳定 ID，重复失败就重复堆叠。
- 弹窗 header 未把固定标题、次级节点名、关闭动作拆成三个布局职责。

## 3. 建议方案与核心取舍

| 方案 | 用户看到什么 | 代价 |
|---|---|---|
| A. 只缩字号和间距 | 同一批按钮仍平铺，只是更挤 | 不解决认知分组，也不能防止遮挡和重复状态 |
| B. **分组 + 去重 + 就近锚定（推荐）** | 窗口栏只管窗口；AppBar 只管产品；任务面板贴任务按钮；节点工具栏按“建参考 / 改这张 / 更多 / 查看”分组 | 需要调整面板定位、工具栏菜单和文案；常用操作仍一次点击可达 |
| C. 全部收进“更多” | 画面最干净 | 高频动作多一次点击，违背“先去重和归位，最后才收纳” |

推荐 B。真正要权衡的只有一件事：**为了减少同屏噪音，是否接受低频动作多一次点击**。样张把这个代价限制在“画板、切图、变换”三类长尾动作，不动裁剪、抠图、AI 编辑等中频动作。

## 3.1 商业级审美与 UX 审查

### 一句话结论

- 这个界面服务的是密集型 AI 视频生产，不应该像营销页一样靠装饰建立层级。
- 当前最大问题不是“不够好看”，而是**同一视觉权重上放了太多不同层级的动作和重复状态**，导致用户需要读完整条工具栏才能决定下一步。

### P0 / P1 / P2

#### P0-1 Windows 顶栏与任务面板

- 现象：Windows 自绘栏含产品按钮；任务面板盖住下方 AppBar。
- 影响：用户无法稳定点击被遮挡的顶栏动作，平台间位置记忆失效。
- 原因假设：窗口 chrome 与产品导航没有职责边界，面板又使用固定 top 偏移。
- 修改建议：窗口栏只保留窗口职责；面板依据任务按钮 rect 定位并做视口钳制。

#### P0-2 抠图错误重复通知

- 现象：同一次失败连续出现三条完全相同的错误 Toast。
- 影响：错误反过来遮挡用户修复问题所需的工具栏，且重复信息没有新增行动价值。
- 原因假设：通用 `toast(message, type)` 每次生成新通知，没有动作/节点级稳定 ID。
- 修改建议：使用 `remove-background:${node.id}` 原位更新；单条错误含短原因与“重试”。

#### P1-1 节点工具栏信息密度

- 现象：视频三个同类动作、图片九类动作同时常驻。
- 影响：高频动作与低频动作权重相同，扫描成本超过操作成本。
- 原因假设：之前只做了视觉分隔，没有继续验证真实用户对词义和分组的理解。
- 修改建议：视频收为“取画面”；图片保留四个高/中频入口，长尾放一个扁平菜单，工具图标维持右侧。

#### P1-2 “定妆”术语

- 现象：按钮只写行业词，用户不知道点击后会新建一个什么对象。
- 影响：即使功能有价值，也会因为风险不明而不敢点。
- 原因假设：命名站在制作流程内部，不是站在点击后的可见结果。
- 修改建议：节点级入口改“建参考图”，Tooltip 解释“以这张图为基础，新建角色或场景参考节点”。

#### P1-3 生成记录标题

- 现象：固定标题和任意长度节点名共用一个 `h2`，关闭按钮同排竞争空间。
- 影响：长名字下关闭动作像插进标题，弹窗看起来损坏。
- 原因假设：header 没有明确的固定区、弹性区、动作区。
- 修改建议：两列 grid；左侧固定标题 + 单行节点副名，右侧固定 28px 关闭命中区。

#### P2-1 边界状态

- 现象：长菜单、窄视口、禁用/忙态尚未在同一体验合同里描述。
- 影响：主样张正确，但极端内容可能溢出或让用户不知道为何不可点。
- 原因假设：实现注意力集中在正常态。
- 修改建议：菜单做视口钳制；所有禁用入口保留原因 Tooltip；忙态不改变工具栏宽度；英文最长文案做单独断言。

### 样式 Tokens

本轮不新增颜色、字号、圆角或阴影，全部复用设计系统：

| 类别 | 使用 |
|---|---|
| Typography | 面板标题 `text-title`；工具栏 `text-body-sm`；元数据 `text-caption`；分组/状态 `text-micro` |
| Spacing | 只用 4 / 8 / 12 / 16 / 24；按钮命中区沿用现有 32px 工具栏档 |
| Color | `bg-nomi-bg` / `bg-nomi-paper` / `text-nomi-ink*` / `border-nomi-line*` / `text-nomi-accent` / `text-nomi-danger` |
| Radius | 工具按钮 `rounded-nomi-sm`；面板 `rounded-nomi-lg`；状态按钮 `rounded-full` |
| Shadow | 工具菜单 `shadow-workbench-pop`；面板/Toast `shadow-nomi-lg` |
| Icons | `@tabler/icons-react`；节点浮条 16 / 1.6，AppBar 18 / 1.5–1.6 |

### Quick Wins

1. 立即删除普通任务状态的重复 SummaryBar，仅保留分组标题。
2. 把任务面板 top 从常量改为触发按钮锚点，先解决遮挡。
3. 抠图 Toast 传稳定 ID，先阻止重复堆叠，再处理资源根因。
4. 生成记录把节点名挪到副标题并单行省略，不动正文数据结构。
5. “定妆”先改“建参考图”并补 Tooltip，底层动作保持不自动生成。
6. 视频三个入口合并成扁平菜单，不改现有抽帧/拆镜执行函数。

## 4. 目标交互

### 4.1 Windows 顶栏与任务中心（P0）

1. 自绘窗口栏只保留品牌、拖拽区、最小化、最大化、关闭。
2. 浏览器回到 `NomiAppBar`，与 macOS 同一位置和语义。
3. `TaskCenterPanel` 通过任务按钮的 `getBoundingClientRect()` 定位：`top = rect.bottom + 8`，`right = viewportWidth - rect.right`，不再使用固定 top 偏移。
4. 正常状态不显示 SummaryBar；只显示“进行中 / 排队 / 已完成”分组。SummaryBar 仅在连续失败暂停或需要用户决策时出现。

### 4.2 视频节点（P1）

1. 三个相近动作合并为 `取画面 ▾`。
2. 菜单内保留“提取首帧 / 提取尾帧 / 按镜头拆分”，与现有两级可达性一致。
3. 全屏、下载、生成记录保持右侧图标工具，不压视频内容。

### 4.3 图片节点（P1）

1. “定妆”改为**“建参考图”**，Tooltip 明确：“以这张图为基础，新建角色或场景参考节点”。行为不改：只创建预填节点，不自动消耗额度。
2. 常驻保留：建参考图、AI 编辑、裁剪、抠图。
3. `更多 ▾` 收纳切图、旋转/翻转、画板。菜单内使用分组标题，避免三级嵌套。
4. 全屏、下载、生成记录仍是图标动作，固定在“查看与拿走”一组。

### 4.4 抠图失败（P0）

1. 先复现并记录失败原因，确认 `@imgly/background-removal` 的模型/WASM 资源是否仍走 CDN；若确认是网络依赖，正式实现改为随应用打包并通过 `publicPath` 指向本地资源。
2. Toast 使用稳定 ID：`remove-background:${node.id}`。同一节点同一动作只更新原通知，不叠加多条。
3. 失败通知只显示一条短原因，并提供明确的“重试”动作；详细诊断进入节点级技术自检，不把错误堆栈塞进通知。

### 4.5 生成记录（P1）

1. 弹窗标题固定为“生成记录”。
2. 节点名放在标题下方的次级单行区域，超长单行省略并保留 Tooltip 完整值。
3. 关闭按钮固定在 header 右上角，标题区 `min-width: 0`，不允许长文案挤占关闭动作。

## 5. 6 角色评审（样张前置）

| 角色 | 结论 | 必须保留的约束 |
|---|---|---|
| CTO | 方向正确，关键是消灭固定偏移与第二状态真相源 | 面板定位只依赖按钮 rect；SummaryBar 只渲染决策态 |
| 设计师 | 暗色工作区的暖中性底 + 蓝紫强调可延续现有 Nomi 视觉 | 使用 `nomi-*` / `workbench-*` token；分组要有可读名称，不只放淡分隔线 |
| 产品经理 | 反馈集中在“我不知道该点哪儿”和“系统挡住我” | 常用动作不做三级菜单；“建参考图”必须说明产物 |
| 前端 | 工具栏已有共享壳和菜单，可局部收口；任务面板可抽定位 hook | 不在各 toolbar 复制菜单；稳定 ID 从调用方传入 toast |
| 后端/运行时 | 抠图失败很可能是模型/WASM 资源可达性问题，不应只改提示文案 | 先核查 CDN/本地资源，再决定打包路径；不伪造“可取消” |
| 真实用户 | 一眼看到主动作，点更多后能找到长尾；失败只弹一次并能重试 | 文字要说结果，不用“定妆”等影视术语做唯一入口 |
