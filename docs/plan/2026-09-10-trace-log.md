# C70 · Agent 轨迹日志

状态：✅ 已实现并验证；完整 gates 通过，按任务授权推送分支并开 PR，不合并。

目标：每次 Agent 会话保留可读、可查询的逐回合轨迹；pi 原生 JSONL 是唯一真源。设置「日志」打开项目会话目录，会话菜单「查看轨迹」打开该会话派生目录。只访问隔离测试资料，不读取真实资料库。

## 先查别人

- **Claude Code transcript 与费用**：规范链接 https://code.claude.com/docs/en/hooks#common-input-fields 和 https://code.claude.com/docs/en/costs 。2026-09-10 实读官方 hooks：`transcript_path` 示例为 `~/.claude/projects/.../transcript.jsonl`，且异步写入可能落后于 hook；当前 costs 页面主入口已写 `/usage`，不能把旧 `/cost` 命令当作稳定文件协议。我们的偏差：保留 pi 转录，另生人读摘要，不仿制 Claude 内部 schema；费用标为估算，不充当账单。偏差理由：本产品已有 pi 会话恢复和多供应商价格配置，复制私有转录只会产生两份真相。
- **Codex CLI session**：规范链接 https://github.com/openai/codex/blob/main/codex-rs/rollout/src/recorder.rs ，原 core 路径 https://github.com/openai/codex/blob/main/codex-rs/core/src/rollout.rs 已重导出 `codex_rollout`。2026-09-10 实读 recorder：JSONL 可供 `jq` 检查，存入 `sessions/YYYY/MM/DD/rollout-...jsonl`，支持 flush。我们的偏差：不建全局 `~/.codex` 类目录或第二套 recorder；在现有项目会话目录派生一回合一行。偏差理由：Nomi 项目隔离与既有 sessionId 才是归属依据。
- **pi 0.85.1 原生会话**：规范链接 https://github.com/earendil-works/pi/tree/main/packages/agent/src/harness/session ，本次可复核版本为安装包 `node_modules/@earendil-works/pi-agent-core/package.json` 的 0.85.1；接口见 `dist/harness/session/types.d.ts`、`jsonl/repo.d.ts`、`jsonl/types.d.ts`。实际接入 `electron/agentLane/laneSession.mts` 使用 `JsonlSessionRepo`，格式 v4 / storageVersion 1，**不是旧 pi-coding-agent 的 SessionManager v3**。我们的偏差：只用标准 `custom` entry 补充工具计时、审批等宿主观测，`session.findEntries` 读取原生条目派生摘要；不手写原生 JSONL parser 或旁路事件存储。偏差理由：原生 reader 已处理事务、序号、恢复与版本细节，用户要求沿扩展点增加字段。
- **OpenTelemetry GenAI**：规范链接 https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-spans.md 和 https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-agent-spans.md 。旧 https://github.com/open-telemetry/semantic-conventions/blob/main/docs/gen-ai/gen-ai-spans.md 现已迁移。2026-09-10 实读：模型 span 名为 `{gen_ai.operation.name} {gen_ai.request.model}`，工具操作为 `execute_tool`，输入 token 包含缓存；该约定仍为 Development。我们的偏差：本地回合视图采用可读字段并记录语义映射，不引 OTel exporter，不宣称本地 JSONL 是 OTLP。偏差理由：任务需要离线诊断，不需要新遥测后台；pi input/cacheRead/cacheWrite 分列保留，避免把不含缓存的原生 input 冒充 OTel 总输入。

## 实施与边界

1. 原生消息保留提示文本、模型回复、工具调用及结果；读取原生 `usage` 的 input/cacheRead/cacheWrite/output 和 cost，并注明币种、估算及价格依据。未知价格/时长明确缺失，不能以 0 伪装已知。每个用户回合汇总其所有模型响应及工具，不把一轮工具循环拆成多个用户回合；保留稳定 sessionId / 回合标识供重建与去重。
2. 原生工具结果没有独立执行开始时间，不能用前一条消息时间假装准确耗时。沿 pi 公开 `Session.mutate` 写入 detached 标准 `custom` entry 增补 `nomi.ui.trace` 宿主元数据：run start/end、toolCallId 对应耗时、审批结果、必要价格依据。只记录原生缺失的观测，不复制消息原文；不改 branch tip，避免事件回调写分支与下一轮输入竞争。另以 `nomi.ui.trace-redactions` 记录 entryId / JSON 路径 / 字符区间，保存脱敏位置而非 key；每次派生统一应用，冷重建不依赖仍持有原 key。恢复时由原生 entries 重建；无观测的旧会话显示未知。
3. 派生位置为 `dirname(session.metadata.path)/<sessionId>.trace/trace.md` 与 `trace.jsonl`。这是同一原生会话目录内的派生子目录。不能把 `trace.jsonl` 平铺顶层：pi repo 与既有走查会扫描该层 `*.jsonl`，且一个 lane slug 可能容纳多会话；子目录同时避免污染原生扫描和会话间覆盖。不改现有扫描断言迁就新文件。
4. `trace.jsonl` 每回合一行，`trace.md` 同源渲染并带会话总计。设置入口定位项目会话根，能跨会话查阅；会话入口定位对应派生目录。派生可重建，写入失败应可诊断，不使主会话不可用。写入使用完整快照替换，避免重复刷新追加出重复回合。
5. 隐私只在本地：保存用户普通文本原文；不输出 key、认证头、令牌或原图二进制；图片内容只留文字占位/必要元数据。凭据字段及文本中的凭据需要脱敏，测试覆盖嵌套参数、结果与错误。禁止将 provider 配置/HTTP headers 整体写入 custom entry。只脱敏复制到日志的内容，不变更模型实际请求。
6. UI 沿用真实设置外壳和现有会话菜单分组，按设计系统使用现有按钮/菜单；只新增本任务两个入口。改前先读完整外壳/真实截图，改后隔离 Electron 真机截图进入 PR，不将局部 mock 当作真实 UI。
