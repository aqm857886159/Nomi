# 预演实测共用量尺

类别：其他（既有量具纠错；不新增界面、模型调用或付费入口）。负责人：实现线。

## ★1 用户任务与量具

当创作者查看预演、让 Agent 核对镜头或把预演挂到视频镜头时，我想看到实际主体的景别和机位坐标系下的运镜，以便决定是否调整镜头。
步骤：建预演 → 编译每镜机位与主体 → 打开导演视图 → 点镜头 → 看实测标签 → Agent 核对 → 挂接时复用标签。
主指标：合成三人街头首镜产品/评测主体取样一致率 100%，量具 `directorShotSummaries.test.ts` 和 `evals/director/previzRuler.test.ts`。
质量指标：四个方向机位的左右横移识别正确率 100%；人物画高比 0.17/0.19/0.21 全部是远景；量具同上及 `directorEvalMeasurement.test.ts`。
护栏：模板仍实体渲染并参与遮挡，取景不受楼体尺寸影响；量具模板/总览回归测试。真实任务为用户手搭台、Agent 三镜台、预演挂接视频；本线只用隔离合成工程验证标签及无模型挂接路径，真实用户计划/真模型任务未验证，协调执行。
已知边界：不修追逐、横插、街轴、群组机位和动作表达；不改补丁格式及上下文。
连带界面：导演镜头标签、Agent 实测回执、预演视频提示词共用 `summarizeDirectorShots`，无新增文案，复用中英词典。

## ★2 数据归属与入口

工程相机持有该镜显式主体（对象及可选锚点）；主体身份只有编译器能写，其余入口只许「原样带过」或「随 id 一起改写」，不许另写。四扇门：
1. 编译器写入（`directorPlanCompiler.ts`）。
2. 正规化保留（`normalizeCamera`）：缺省与失效分开记，失效事实不降格为整个人或手搭。
3. **id 改写门**：`directorProject.ts#remapSceneIds` 是复制场景层（`duplicateSceneLayer`）、跨层复制（`copyEntitiesToScene` 的复制档）、导入场景（`importScene`）换实体 id 的唯一入口。场景里每一种引用对象 id 的字段都必须过它的 idMap（父子、看向、轨迹点看向、视线片段目标、特写目标、轨道顺序，以及本字段）；这是写，不是「带过」。它按字段名逐个点名，door-map 按名字数不到「该改没改」，所以这扇门的守卫是类级检查（整棵副本 JSON 里不许剩下旧实体 id），不靠人记。
4. **手改覆盖门**：`planOverrides.ts` 不把本字段当手改，既不进指纹也不进覆盖层，重编译时由编译器重写；否则失效记录被当成手改反复重放，重编译救不回来，回执还谎报「手改被替换」。

取景对象与物理辅助标志分离，模板仅在 `s1SceneTemplates.ts` 声明为背景。测量模块唯一拥有主体取样和方向判定。摘要 8 扇和 isAuxiliary 14 扇已用 door-map 实查，根因合同保存生成门表；所有摘要消费者仅消费同一个上游，不各自修。

## ★3 复用

复用现有投影、景别档位、轨迹和机位求值。删除评测的主体取样实现及世界 X 方向判据，import 产品函数；左右基向量由向量层共享，编译器 sideways 与测量用同一定义。不新增依赖。

## ★4 全状态

空工程仍无镜头；有效记录直接量指定主体（即使主体出画也不换成楼）；缺失记录的手搭台先选可测人物，无人物才选道具；显式记录丢失对象/锚点则不可测，不猜别的主体。无可测主体景别为空；加载/失败/取消/过期均沿用现有工程状态，本次无异步过程。中英标签沿用词典。
