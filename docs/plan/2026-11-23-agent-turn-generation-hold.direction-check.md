## 0–2. 现象、范围、根因

| 场景 | 直接原因 | 依赖结果 |
| --- | --- | --- |
| P30 六镜时长修改 | 草稿回执只给草案和计划写了停止条件 | 六镜都保存为八秒，回合结束 |
| 明确先别生成，模型仍提交一批镜头 | 付费准备只知道工具参数和档位 | 工具在现有审批之前被拒 |
| 旧草稿曾出价，本轮再次修改候选 | 适配器把一次候选修改当成代答时机 | 候选保存成功，生成须从出价入口进入 |

意图和工作成果分别在 Agent 转录与 Run 中有主。错误来自二者在审批前缺少连接，以及本地编辑带了额外的生成副作用。铁律⑩由六镜时长读回和提交计数共同验证。未新增用户操作。

## 3–4. 预测和量具

- 沿用旧结构时，单镜和批量都可在模型无视 hold 后到达出价，使用 `laneExtendedDesktopPorts.test.ts` 验证。
- 沿用候选修改触发代答时，过去出过价的 Run 在全自动档可被重新交接，使用 `generationTransportAdapters.test.ts` 验证。
- 使用 P30 已有的零调用判据。另用真实流程形状的明确生成请求判断是否误拦。独立验收由后续协调线给出。

## 5. 这一整块归谁

这一整块：Agent 当前用户输入到媒体生成准入。

归谁：pi 0.85.1 管当前已消费输入与执行，既有 `laneInputIntent` 读取输入，`electron/agentLane/laneHost.mts:426` 先走工具准备，再走审批。Run 继续持有出价和后续执行。

我们哪里绕开了它：旧草稿更新在 `electron/capabilityCore/generationTransportAdapters.ts:599` 依据卡是否可见触发代答。卡可见是旧出价事实，候选修改只能更新候选。原版工具准备门也没有载入当轮指令。

## 6–7. 三条路与取舍

| 选项 | 结果 |
| --- | --- |
| 只修草稿回执 | 减少模型误发。模型违令或旧草稿更新仍可进入生成。 |
| 在执行入口消费 hold，删掉 patch 的代答副作用 | 确定性约束单镜和批量，保留明确请求生成时的原审批路径。采用这一项。 |
| 禁掉 Agent 生成 | 所有明确生成请求都需要用户另走一遍流程。 |

全自动档省去用户已经授权的逐次确认。用户手上这轮只改草稿时，保存候选和执行生成仍是两个动作。
