# 方向检查复盘：gate-family（自写门岗族）连修

> 来源：#1015 的方向检查（自写登记条目 30 天内第 2 个 fix 就命中）对 `gate-family`（`scripts/check-*.mjs`、`scripts/run-gates-contracts.mjs`）命中；近 30 天已有 100 多个 fix 提交碰过它。一份复盘可被多个提交引用，本文点名登记条目 id：**gate-family**。
> 触发提交：`rules/test-routing` 分支里对 PR 正文判据的修补（可打断判据把测试文件里的 AbortController 也扫进去，#1038 误判成四类）。

## 0. 一句话根因

这些门岗大多是「用正则 / 字符串启发式去猜 diff 或正文的语义」（路径名、正文用词、新增行文本），启发式的边界一直在漏、一直在误报，于是每次误报 / 漏报都变成对门岗脚本的一个 fix。

## 1. 归类表

| 提交 / bug | 直接原因 | 类 |
|---|---|---|
| 逃逸判据看正文用词（#1025 误报、#1026 漏报） | 判据靠正文关键词 | 启发式看文本 |
| 可打断判据扫所有新增行（#1038 误判四类） | 新增行没按文件排除测试 | 启发式看文本 |
| 概念门岗把 37 处存量债当「红」挂在 advisory | 缺棘轮、文案说假话 | 门岗状态没有账 |

## 2. 为什么一直冒

门岗判据没有结构化输入：靠拼 diff 文本、PR 正文、路径正则。每个新场景都要加一条例外，下一个场景再漏。

## 3. 不改结构接下来会冒出什么

- 下一个只改测试 / 文档的 PR 被别的路径正则误判（验证：拿最近 10 个合并 PR 回放 `merge-preflight --enforce`）。
- 正文判据在新模板下继续漏判（验证：#1029–#1038 实跑）。

## 4. 靶子独立性

这批门岗的「靶子」是真实 PR 的形状；回放用的是真实合并的 PR，不是同一条线手写的样例，靶子独立。

## 5. P0：是我们独有的吗？现成方案

「路径 → 类别 → 必交证据」的路由表是 Nomi 领域独有的；但「按改动文件与标签决定跑什么检查」有现成做法（Playwright tag / annotation、GitHub CODEOWNERS 与路径过滤式工作流）。外包卡 21 的调研（#1035）给出了各层现成工具；门岗族整体的接入评估由协调会话在 2026-10-25 前出结论（早于 `gate-family` 的评估期限 2026-10-31）。

## 6. 接入 / 补 / 重写 / 删 对比表 + 推荐

| 选项 | 做什么 | 代价 | 风险 | 推荐 |
|---|---|---|---|---|
| 接入现成方案 | 路径过滤交给 GitHub 工作流路径条件 + Playwright tag；判据尽量结构化（按文件取新增行、读状态转换） | 要改工作流与测试标注 | 过渡期两套并存 | 长期推荐；本次已把「按文件取新增行」「看账本状态转换」这类结构化输入做进判据 |
| 补 | 继续在脚本里加例外 | 低 | 误报 / 漏报继续 | 否 |
| 重写（限一个模块） | 把 PR 判据统一收进 `pr-judgement-lib.mjs` 一份 | 中 | 回归 | 本次已做（判据只留一份，merge-preflight 与 CI 同源） |
| 删 | 删掉不挣命的门岗 | 低 | 丢保护 | 由 10-25 的评估结论决定 |

## 7. 用户要权衡的核心

门岗族是继续自写启发式、还是把「路径 → 检查」交给现成的路径过滤与标签体系——本次先把判据收成一份并结构化输入，接入评估在 10-25 前给结论。
