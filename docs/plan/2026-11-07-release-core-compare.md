# 核心任务版本对比

## 短版设计卡

- ★1 用户怎么用：发版协调构建上一正式版和候选版的隔离源码副本，用同一输入文件、中文故事、文本模型（`DEFAULT_PAID_BRAIN`）、图片模型及参数各跑一次，再读两份 JSON；量具为 `tests/ux/release-core-compare.paid.mjs`、共用步骤的 `release-core-compare.rehearsal.walk.mjs` 和结果比较脚本；目标是没有退化且证据齐全。演练覆盖两版 × zh/en，故事内容固定中文；真实质量与平台打包差异不由假模型证明。1b 不改产品界面；1c 不触碰真实旧资料或迁移，只有自建隔离项目。
- ★2 谁说了算：分镜与节点结局来自被测应用落盘项目，工具调用/错误来自 lane transcript；构建戳由既有 `assertPaidBuildReady`/启动器核对；对比脚本只消费带版本、模式、输入指纹和完整度的收据，不把缺证据当持平。不改产品 owner、共享 helper 或被测代码。
- ★3 一致与复用：沿用 `docs/release-process.md` §4 同输入同模型硬门，复用 `_paidRun.mjs` 的统一付费护栏、`agent-runtime-walk-support.mjs` 的起草步骤和转录读法、`_generationLockExitSteps.mjs` 的分镜批量入口及 `_generationLockExitHosting.mjs` 的确认步骤。沿原方向增加小型共用走查；不复制整条锁退出大走查（多于五张、含重试），不删掉对比（会失去发版证据）；无新依赖，无产品功能和自动修复。
- ★4 全状态：空/缺字段/输入或模型参数不符/模式不同/未完成均拒绝比较并退出非零；运行中记录阶段与耗时，成功/失败/卡住逐镜保留；部分成功必须如实记录并可比较；取消中先收尾自建进程再保留失败收据；上游或界面不可用写 partial/blocked 及具体一步；不自动重发真实图，不自动补对话，缺资源由协调处理。
- ★9 验收与回滚：先单独提交本卡再写脚本；四遍演练均真实启动对应源码构建，真实创建空项目、Agent 单轮起草、导入相同五镜数据、从分镜表点击全部生成并确认，校验五镜结局、忙碌解除、心跳采样非空和零公网调用；比较同输入结果、再将候选假数据一镜改失败，必须输出变差且非零；边界自检覆盖缺值/NaN、重复镜头、模式/输入不符、失败或 incomplete 收据不得通过、阈值边界、改善不能覆盖任一退化。执行推送前快检，付费由协调另跑一次；回滚仅撤销本任务的测试/文档提交。

## 动手前固定的比较规则

任何一项变差，总结论均为变差；无变差且至少一项变好才是变好，否则持平。未知值不能参与三档判定，直接阻断。测试设施异常、被阻断的步骤不能当作产品失败数。

| 指标 | 候选变差 | 候选变好 | 其他 |
| --- | --- | --- | --- |
| 起草成功 | 上版成功而候选不成功 | 上版失败而候选成功 | 持平 |
| 分镜落成镜数 | 更少 | 更多（合格起草仍须 3–5 镜） | 持平 |
| 工具调用/失败/失败后同工具重试次数 | 任一增加 | 减少 | 持平；错误保留完整原文 |
| 用户手动补步骤/遗留占位节点数 | 增加 | 减少 | 持平；请示卡、未完成起草均记需要补步骤 |
| 起草耗时/批量总耗时 | 比上版增加超过 max(20%, 2000ms) | 减少超过同一阈值 | 持平 |
| 五镜结局（按固定 shotId） | 成功→失败/卡住，或失败→卡住 | 失败/卡住→成功，或卡住→失败 | 持平；逐镜不能被总数掩盖 |
| 最长界面无响应 | 从 ≤1000ms 到 >1000ms，或增加超过 max(20%, 200ms) | 从 >1000ms 到 ≤1000ms，或减少超过同一阈值 | 持平；使用 renderer 定时器延迟及 Node→renderer 往返，取较大值 |
| 结束后解除忙碌 | true→false | false→true | 持平 |
| 被拒重试数 | 增加 | 减少 | 持平；不额外点真实重试，读实际轨迹，无发生则 0 |

## 输入和费用边界

固定四镜短故事只起草不出图；固定五镜分镜无参考卡/首帧/视频，用同一图片模型和相同尺寸/比例等参数。每版一个 Agent 用户回合，最多五次真实图片提交，不自动补发失败图；Agent 内部工具来回另计。演练与付费共用步骤，演练仅把文本和媒体远端换成本机夹具。构建副本从 git archive 导出，仅初始化独立 git 元数据以满足原有构建指纹，不修改其产品文件；依赖首先链接任务树。源码构建不能代替安装包验证，报告明确标注。
