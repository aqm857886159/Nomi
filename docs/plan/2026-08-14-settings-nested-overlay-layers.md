# 设置页嵌套弹层层级根因修复

日期：2026-08-14

## 为什么

设置页是 Portal 到 `body` 的 `z=9000` 模态面；「模型」tab 直接复用 `OnboardingDrawer`。抽屉里的
接入向导、自定义调用编辑器、下拉和确认框也各自 Portal 到 `body`，但仍沿用浮卡时代的 `z=4100`、
Mantine 默认 `z=200/300` 或确认框 `z=5000`。React 组件树里的父子关系不会约束这些 Portal 的视觉层级，
因此从设置里打开二级界面时，二级界面会被设置页盖住。

这不是一个按钮的样式问题，而是全局浮层没有共同的层级契约。已确认的同类入口包括：

- 设置 -> 模型 -> 添加模型 / 中转：接入向导在设置页下面；
- 设置 -> 模型 -> 自定义调用：编辑器使用 Mantine 默认层级，也在设置页下面；
- 设置 -> 模型 -> ComfyUI 工作流整页 -> 删除：全局确认框在整页下面；
- 上述二级界面里的 Portal 下拉：默认或旧的 `z=300/4500`，仍可能在设置页下面。

## 范围

1. 在设计系统新增单一浮层层级表：浮卡 < 应用模态面 < 子对话框/整页 < 下拉 < 确认框 < 通知。
2. 设置页、模型浮卡、DesignModal/Drawer、Mantine Select/Popover、NomiSelect、ComfyUI 整页与确认框改用该表。
3. 新增层级不变量单测，以及真实 Electron 走查：从设置页打开中转向导，断言顶层命中、可交互并截图。

## 不动项

- 不改设置页、模型列表和接入向导的既有布局、尺寸、颜色、文案与交互流程。
- 不改变「设置是家、画布浮卡是加速器」的既有信息架构。
- 不修改模型接入、HTTP 校验或目录数据逻辑。

本次视觉基准就是当前已拍板并已渲染的设置/接入界面；修复后除正确出现在最上层外，像素形态应保持一致，
因此不另造新 mockup。

## 回滚

回滚本次层级常量、调用点和测试即可；不涉及用户数据、目录格式或 IPC 合约。

## 验收门

1. 层级单测锁住严格顺序，禁止再散落本次涉及的魔法数字。
2. Electron 真机走查在桌面与窄窗口完成：设置 -> 模型 -> 接入生成模型 -> 添加模型 / 中转；
   对话框中心点命中自身、表单可输入、Escape 只关闭最上层。
3. 核查自定义调用、ComfyUI 工作流确认框与向导下拉均高于其宿主。
4. `check:filesize`、`check:tokens`、`check:i18n`、`lint:ci`、`typecheck`、`test`、`build` 全过。
