### 0. 一句话根因

付费范围只有「点名」有主人（09-19 收进 Run 变更边界做原子校验），「没点名」的默认没有主人：四扇门各写一份「没给就全量」的回退，第一扇门（MCP handler）还把「没点名」翻译成「点名全部」，后面每一层都分不清两者。

### 2. 为什么这一类会一直出现

表示层的问题：`shotIds?: string[]` 一个可选数组同时承载「点名了」和「没点名 = 让系统按事实决定」，缺省值由每个读它的人自己补。补的人手里都有「计划里有哪些镜」，却只有出价账知道「这一次出价还没定哪几镜」——所以最省事的缺省永远是「全部」。修一处，下一扇门（新车道、外部宿主、文稿方案、reducer）又各补一份。
`mcpGenerationTools.ts` 是生成域的总入口（冻结在 1034 行），任何生成问题都从它过，热点统计会一直命中它。这不是范围这一类的根因，但它说明「修在 handler」是错的边界：handler 应当原样转交，事实所在的那一层（出价账 / reducer）才是最早的共享边界。

| 铁律 | 判断 | 最小证据 |
|---|---|---|
| ⑩ 说的=摆的 | 适用：Agent 说「剩下没点的」，卡上摆的必须就是那几镜；回执 `shots` 必须等于卡 | 设计卡 ★9 A1、A2（卡与回执同断言） |
| ⑪ 能选到 | 不适用：不涉及模型参数清单 | — |
| ⑫ 点了=以为的 | 适用：用户点「生成」只花卡上那几镜；「直接生成」档只替这一次出价摆的镜决定 | ★9 A12 + `spend-walks` 阻断子集 |

### 4. 靶子独立性检查

- 靶子是任务书规则（协调定）加上出价账既有的事实（`offerShots` / `generationPresentationOutcome`，09-30 起），不是本线写的；复现跑在现有 e2e 世界（`spendWorld`）上，没有新造夹具。
- 「修对了反而红」的先例有两条：`electron/capabilityCore/agentPanelSpendCardStop.e2e.test.ts:119`、`:133` 把「卡上两镜都在交时不点名再出价 = 整份再摆」写成了预期。按新规则它们会红——这是靶子跟着旧行为写的，要改的是这两条的预期（设计卡 D3），需要拍板。
- 真模型评测（Agent 收到拒绝后会不会点名）本线跑不了（要额度），交协调。

### 5. P0：这些是我们独有的吗？现成方案有哪些

是。按镜头的花钱语义在 `docs/engineering/self-written.json` 的领域目录里，「这一次出价还没定哪几镜」是我们出价账上的事实，没有可接的库；本次不新增通用能力，也没有命中自写登记条目。点名数组的校验十来行，不引库。

### 6. 接入 / 补 / 重写 / 删 对比表 + 推荐

| 选项 | 做什么 | 代价 | 风险 | 推荐 |
|---|---|---|---|---|
| 接入现成方案 | 无：范围事实是我们的出价账 | — | — | 不适用 |
| 补 | 四扇门各自把回退改成读卡 | 小 | 第五扇门再写一份；「这一镜还能封吗」两份定义继续漂 | 不推荐 |
| 换（一个范围规则） | 新 `resolveUndecidedGenerationShotScope`，事实所在层算，handler 原样转交，删四份回退和旧函数 | 中：7 扇门改调；两条 e2e 预期要改；测试夹具改一处（26 个测试文件经它） | Agent 在「卡上没剩没定的」时要多一步点名 | **推荐** |
| 删（`shotIds` 必填） | 结构上没有缺省 | 每次出价 Agent 都要列全镜号，第一次出价也要；外部 gate 不收 `shotIds`，要改外部工具面 | 模型漏写时每次多一轮；外部宿主要升级 | 不推荐：代价落在每一次出价上，换来的安全「换」已经拿到 |

### 7. 用户要权衡的核心

不点名的 `generate` 还要不要有默认：保留「只重摆最近一张卡上还没定的（第一次 = 勾着、没送过的）」，Agent 少写一步，代价是这条默认要有唯一主人、卡上没剩时拒绝；还是让 `shotIds` 必填，每次出价都点名，代价是每次多一份清单、外部工具面要改。
