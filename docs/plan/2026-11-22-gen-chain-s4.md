## ★1 用户怎么用

**当**创作者让 Agent 拆镜头、或在画布上点生成，而账户余额不够这次请求被预扣的量，**我想**第一次就看到「余额不足」和能做的事（充值 / 换模型），Agent 不再替我重发，**以便**不去查一把没问题的 Key、不等四倍的时间换同一个结果；余额够的时候，因为每次请求都带了上限，被预扣的量是「这次最多写多少」而不是「这个模型最多能写多少」。

1. 创作者在面板里发一句话 → 大脑请求带上 `min(声明上限, lane 默认)`；
2. 余额不够 → 上游回 402 或 403 + 码 → 归一成余额不足，不重试；
3. 面板那一行说余额不足 + 下一步；本轮结束；
4. Agent 在一轮里调生成工具，供应商当场回余额不足 → 工具失败信封告诉模型「余额不足、别重试、告诉用户」，`laneTurnBudget` 停住这一轮；
5. 画布节点失败卡显示余额不足（不再是「API Key 无效」）；
6. 创作者充值或换模型 → 发下一条消息 / 再点生成，照常。

**不做什么**：不在发送前按余额拦（D-1113-blocks）；不查余额接口；不改价目；不新增界面元素；不按供应商写分支；不碰取回轮询（`catalogTaskActions.ts` / `pollTaskToTerminal.ts`）和改写会话（`rewriteSession.ts`）。

**已知坑**：①上限含推理 token（OpenAI 两份文档都这么写），推理型模型的上限给小了，正文会空、`finish_reason` 是 `length`（`apimartTexts.ts:131-134` 已记过一次）；②pi 会把上限夹到上下文窗口里，没声明窗口时按 128k 算（`laneModelProvider.mts:197`）；③声明里的上限如果是上游写错的小数，`min()` 会把错带进来（见问题 f）。

## ★7 性能（按 token，不写金额）

- 新增的用户操作：无。归一多读响应体里的三格，每次失败一次，规模与响应体大小同阶（响应体已有上限，`vendorHttp.ts` 的 response limit）——perf 场景不适用：没有新交互、没有新的循环。
- 预扣（这是本刀真正动的「性能」）：设 lane 默认为 C（数值待定，问题 f），声明上限为 M。单次请求被预扣的**输出部分**从 M 变成 min(M, C)。内置文本模型的 M（公开价目接口 `limits.max_output_tokens`，离线取，`/Users/aoqimin/Nomi-coord/tmp/I-gen-chain-s4/pricing/limits.txt`）：12,800（2 个）、16,000（2 个）、65,535–65,536（3 个）、100,000–104,857（2 个）、128,000（6 个）、131,072（5 个）、393,216（DeepSeek 一族）、1,000,000（`claude-fable-5.1`）。举例（只是算比例，不是提议 C 的值）：若 C = 32,768，fable 降到约 1/30，128k 那一档降到约 1/4，DeepSeek 一族约 1/12，12,800 / 16,000 那几行不变。
- 一轮 30 次请求的最坏情况：Agent 的模型请求是**串行**的（工具一个接一个跑），预扣不叠加——峰值 = 1 次请求的 min(M, C) + 输入；实扣按实际用量，和上限无关。真正被上限封住的是「失控」的最坏：一轮 30 次都写满时，输出总量上界从 30 × M 变成 30 × min(M, C)。并行的只有画布上同时跑的文本任务：峰值 = 并发数 × min(M, C)。
- 等待时间：上限不改首字时间；只在模型本来要写超过 C 的时候提前停（这正是护栏指标要盯的）。

## 要协调拍板的问题（每题：选项 · 推荐 · 代价）

- **a 上限字段名**：①交 pi 的 `compat`（APIMart 上 Chat 发 `max_completion_tokens`、Responses 发 `max_output_tokens`，声明可覆盖）；②保留我们手写的 `max_tokens`（Responses 仍 `max_output_tokens`）。**推荐①**：一份规矩、符合 D-1122-gpt6-responses-no-ab，new-api 两个名字都读（`relay/request_billing.go:29`）。代价：APIMart 文档只写 `max_tokens`，它的预扣认不认另两个名字不知道——要靠协调那一次付费核对（★8）来答；不认的话 fable 仍会 402，届时在 APIMart 内置行的声明 `compat` 里写 `maxTokensField: max_tokens` 一格即可，不写分支。
