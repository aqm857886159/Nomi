# 方向检查：节点「几版」生命周期（2026-10-06，L-vcard）

触发：`node scripts/fix-churn.mjs` 命中 `nodes/useNodeImageEditing.ts`（14 天第 3 刀）、`nodes/whiteboard/WhiteboardModal.tsx`（第 3 刀，目录同概念）、`store/canvasStoreTypes.ts`（第 3 刀）。V1 草稿还碰了 `store/canvasSnapshotNormalizer.ts`（第 4 刀），本次已撤回那一处改动，改在打开项目的迁移口补号。

### 0. 一句话根因

「给节点加一版 / 删一版 / 换主图 / 删文件」没有唯一主人：同一件事有三份手抄合并、两份「文件还有没有人用」判定、两份「设主图」动作，于是每次有人改其中一份，另几份就悄悄不一样。

### 1. 归类表

| 提交 / bug | 直接原因 | 类 |
|---|---|---|
| 「第 N 版」增删就漂 | 标签用列表下标 | 编号无主 |
| 旧版设主图后再出一版，顺序乱 | 三份合并都把主图挪到最前 | 追加口三份 |
| 删一版后 ⌘Z 回来是空卡 | 存盘后当场删文件 | 删文件时机无主 |
| V1 草稿：关窗就删光还能撤销的文件 | pagehide 上又挂了一条「全删」 | 删文件时机两条口 |
| 时间轴还在播的那一版被删掉文件 | 引用判定只看画布 | 引用判定两份、都漏时间轴 |
| 本文件 14 天里另外两刀（图片编辑 / 白板） | 不同概念（编辑交互、白板保存），与本类无关 | — |

### 2. 为什么会一直出现

版本列表是一个**数组字段**，谁都能拼；没有一个函数是「加一版」的唯一入口，类型系统也拦不住。铁律 ⑫（点了 = 以为的）：用户点「撤销」以为版本和文件都回来，实际文件没了。

### 3. 不改结构会冒出什么

| 预测 | 怎么验证 |
|---|---|
| 新加的产出方（如 3D 编辑结果）又抄一份合并，编号不连续 | `rg "history:\s*\[" src` 出现新的拼数组 |
| 新的删除入口绕过时间轴判定 | 删一版后时间轴片段变黑 |

### 4. 靶子独立性

测试直接打在真 store + 真撤销日志上（`deleteAssetResult.realStore.test.ts`），变异校验 6 条全红后恢复（见 PR 正文）；没有用 mock 的撤销日志当证据。

### 5. P0：是我们独有的吗

版本编号、按镜头的删除撤销窗口是领域约束（`self-written.json` 领域目录：画布 / 素材）；撤销本身沿用已有撤销日志，不另写。

### 6. 对比与推荐

| 选项 | 做什么 | 代价 | 风险 | 推荐 |
|---|---|---|---|---|
| 接入现成方案 | 无现成库管「节点版本 + 撤销窗口内延后删文件」 | — | — | 不适用 |
| 补 | 在三份合并里各自补编号 | 小 | 第四份照样会出 | 否 |
| 收成唯一主人（本次） | `nodeResultLifecycle.ts` 一个追加口；`pendingAssetDeletions.ts` 一个删文件时机；`isProjectFileReferenced` 一个判定；删三份手抄与 `rollbackHistory` | 中 | 改动面跨 3 个产出方，已有测试覆盖 | **是** |
| 删 | 不做版本卡片 | — | 用户已拍板要做 | 否 |

### 7. 用户要权衡的核心

无新的结构取舍：这是把已有行为收口，不改用户看到的规则。
