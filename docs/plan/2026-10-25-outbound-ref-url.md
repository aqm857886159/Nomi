| ★0 先查别人 | ① WHATWG URL Standard（https://url.spec.whatwg.org/，2026-10-25 查）· 空格在路径与查询的转义集合里；解析时去掉首尾空白与制表 / 换行；`%` 不在转义集合里，已有的 `%20` 原样；规范把「解析后序列化」的幂等列为目标 · **确认了**「用平台 URL 解析器、不自写编码」和验收项「已编码 / 签名链接逐字不变」。② Node 内置 `fetch`（undici，https://github.com/nodejs/undici/blob/main/lib/web/fetch/request.js）· Request 构造对字符串输入 `new URL(input, baseUrl)`，存的是解析后的 URL 记录，不是原字符串 · **确认了** multipart 取字节、文本任务把图片取成字节内联这两条路本来就按标准写法发（合同记 not-affected），不另补。③ Python requests 的 `requote_uri`（https://github.com/psf/requests/blob/main/src/requests/utils.py）· 发请求前在一处「解码再编码」：空格编成 `%20`，但会把未保留字符的转义（如 `%7E`）解回原字，带签名的链接可能被改 · **改了**编码方式的取舍：不走「解码再编码」，用 WHATWG 序列化（不解任何已有转义）。④ 本仓第 1 轮（d2ad49331）· 在传输层按发出去的字段名另写键表改写 · **改了**收口位置与键的来源：字段名是供应商的、补不全（类级测试红 51 格），传输层改写还会改掉自定义调用脚本已签过名的请求体——改为在参数层收口、只认共享键表 `GENERIC_REFERENCE_KEYS`。 | 链接；`electron/catalog/outboundReferenceUrl.matrix.test.ts` |
