# Nomi 官方额度：内置中转 · 成本路由 · 兜底 · 额度

状态：⏳ 已拍板·未开工 · 2026-09-24 用户拍板：D1 网关翻译（现设计）、D2 加价 30%、D3 体验包只送图片 + GLM、D4 本期不接支付只用兑换码 · 价格与文档为当日实查（apimart / kie / z.ai 官方页面与接口）；网关现状以 `1251912798/Nomi-service@ce050cd` 为准

## 0. 一句话

用户登录 Nomi 就能用我们挑好的约 10 个模型，按次扣 Nomi 余额；网关把每次请求派给**当下最便宜且健康**的那家（apimart / kie），失败自动换家；钱按「先冻结 → 成功才扣 → 失败全退」走账本。

## 1. 结论先行

1. **不从零造。** `Nomi-service`（Go 单体网关）已经有账本冻结/结算/退款、兑换码、任务状态机、提交阶段降级、花费熔断、管理后台（见其 `nomi-service-doc.md` 附录 C）。本方案只补缺口，不另起一套。
2. **上游请求体由网关翻译（已拍板，沿用现设计）**（§3.1）。代价是「apimart / kie 的字段怎么翻译」在客户端 TS 和网关 Go 各有一份；用两招压住：精选清单只有约 9 个模型（Go 侧工作量可控），以及一道**跨仓对账测试**——客户端导出「标准参数 → 请求体」样例，网关 CI 逐条比对，漂移即红。
3. **两家同模型价差 1.4–3.8 倍**（§3.2），比任何「稍微加一点」的加价都大 → 兜底到贵的那家，**单笔一定亏钱**。解法不是每笔保本，而是**按期望成本定价 + 每日兜底亏损预算**（§3.4）。
4. **加价 30%（已拍板），不是 5–10%。** 支付手续费、兜底溢价、失败与孤儿任务、赠送额度加起来要吃掉 10–15%。加 30% 后，大多数模型我们的价**仍低于用户自己去 kie 买**（Seedance 2.5 720p 5 秒：我们 ¥9.4，kie 直购 ¥10.6）。
5. **本期不接在线支付，兑换码承担充值（已拍板）。** 网关的兑换码已上线，够小范围运营。将来接支付时的调研结论留在 §3.6：马来西亚的 Stripe 账户能收支付宝、**收不了微信支付**；不接「易支付」类聚合（二清风险）。

## 3. 设计

### 3.1 上游请求体谁来拼：网关翻译（已拍板）

**现状事实：**
- 客户端里已经有 apimart 36 条、kie 22 条模型的**声明式请求配方**（例：`electron/catalog/apimartVideos.ts`，含字段翻译 `paramTranslate`、比例/分辨率换算、参考槽映射），背后是一套供应商无关的「档案」（09-03 统计 89 个）。自带 key 的用户今天就走这套。
- 网关按「服务端持有标准参数 + Go 适配器翻译」设计（`nomi-service-doc.md` §5.6），目前只实现了 `kling`、`openai_images` 两个协议。

**当时对比过的两条路：**

| 方案 | 怎么走 | 代价 |
|---|---|---|
| **A. 网关翻译（✅ 已选，沿用现设计）** | 客户端只传标准参数，Go 适配器翻译成 apimart / kie 请求体 | 「apimart / kie 字段怎么拼」写两份：TS 给自带 key 用户，Go 给官方额度用户 |
| B. 客户端拼、网关定价守门（未选） | 客户端用现成配方同时拼出两家请求体，网关只校验、抽计价维度、挑一家发 | 网关要为每个（模型, 厂商）维护字段白名单；上游改字段要发客户端版本 |

**选 A 的好处**：网关能不发客户端版本就热修上游改动；开源客户端里不需要任何防伪造的计价校验，价格只由网关按标准参数算。

**选 A 必须补上的三件事（否则两份翻译会悄悄漂移，违反 P1 的本意）：**

1. **参数只有一份定义：** 网关每个 SKU 的参数 schema 从客户端档案导出（SKU code = 档案 id + 模式），而不是在网关里另写一套。客户端界面照旧由档案渲染（P4：不为官方额度另做一套 UI）。
2. **跨仓对账测试：** Nomi 仓库加一个导出脚本，对每个上架 SKU × 厂商生成样例「标准参数 → 客户端配方渲染出的请求体」（JSON）；Nomi-service CI 读这份样例，断言 Go `Translate` 输出与之逐字段相等。任何一边改了翻译而另一边没改，CI 就红。
3. **范围收窄：** Go 侧只为 §3.2 的约 9 个模型 × 2 家写翻译，不追客户端的全量配方。apimart 图片/视频共用 `/v1/images|videos/generations` + `/v1/tasks/{id}`，kie 市场模型共用 `createTask` + `recordInfo`，所以是两个协议适配器 + 每模型一段字段映射（多数能用网关现有的 `rename` 声明式搞定）。

### 3.3 路由与兜底

**3.3.1 候选怎么挑（每次请求现算，不是每个模型固定一张表）**

1. **能力交集：** 这一次请求用到的能力，这家都支持才进候选。例：用了参考视频、尾帧、或 Agent 对话超过 128k 上下文（apimart 的 GLM-5.3-Flash 上限 128k，z.ai 官方 1M），不支持的那家直接出局。
2. **过滤：** 该（厂商, 上游模型）熔断打开 / 厂商余额不足 / 限流令牌用尽 → 跳过。
3. **排序：** 按当日成本升序；成本差 < 10% 视为平手，再比近 1 小时成功率和出片中位时长。
4. **探针流量：** 只在价差 < 1.5 倍的模型上，把约 5% 请求派给第二名，让它的健康数据保持新鲜。价差大的不做（每次探针都是真亏钱）。

这是 OpenRouter 公开的规则改造而来：它先排除「最近 30 秒出过故障」的家，再在稳定的家里按价格反平方加权随机（[Provider Routing](https://openrouter.ai/docs/guides/routing/provider-selection)）。我们量小，确定性排序 + 小比例探针更容易对账。

**3.3.2 错误分类：按「厂商 + 业务码 + 文案」，不只看 HTTP 码**

实例：z.ai 的「余额不足」是业务码 1113、HTTP **429**，长得像限流（[z.ai 错误码](https://docs.z.ai/api-reference/api-code.md)）；apimart 的「用户额度不足」是 403。只看 HTTP 码会把「我们欠费」当成「对方限流」去重试。

| 类别 | 例子 | 换家？ | 熔断记账 | 其他 |
|---|---|---|---|---|
| 我们欠费 / key 失效 | apimart 403 额度不足、z.ai 1113、401 | 换 | **厂商级**立即熔断 | 告警，人工充值 |
| 限流 | kie 429（每账户 10 秒 20 次）、z.ai 1302 | 换 | 不计失败，短冷却 | 网关侧令牌桶防止撞上 |
| 厂商侧故障 | 5xx、overloaded、`No available channel for model`、网络错误 | 换 | **（厂商, 模型）级**计数 | — |
| 参数错 | 400 / 422 参数非法 | 不换 | 不计 | 客户端校验过还出现 = 我们的 bug，告警 |
| 内容审核 | 敏感内容拒绝（z.ai 1301 等） | **不换** | 不计 | 换家等于帮用户找审核松的那家 |

LiteLLM 也是这个思路：按异常类型分别设重试次数和熔断阈值，内容审核错误不计入熔断（[LiteLLM Routing](https://docs.litellm.ai/docs/routing)）。分类表放成数据文件，每条带一个测试样本。

**3.3.3 四个时点的兜底**

| 时点 | 现在 | 改成 |
|---|---|---|
| 提交前 | 熔断/并发满 → 跳过 | 加上余额、令牌桶、能力交集过滤 |
| 提交时报错 | 5xx / 网络 / 429 / 401-403 → 换家；400/413/415/422 → 不换 | 按 §3.3.2 分类表 |
| **提交超时（结果未知）** | ⚠️ 没实现 Lookup，于是**直接换家**（`router.go:225-235`）。如果第一家其实已经受理，会**两家各生成一次、各扣一次钱** | 单价 ≤ ¥3：换家（偶发双扣可接受）；单价 > ¥3：不换，任务失败并全额退回，标记孤儿，次日用两家用量接口对账。apimart / kie 都不支持按客户端 ID 反查任务，Lookup 做不出来 |
| **提交后上游失败（新增）** | 直接退款结束（`worker.go:229`） | 上游终态失败，且原因属于「厂商侧故障」→ 在**同一笔冻结**下换下一家重提，最多一次；总时限图片 5 分钟、视频 30 分钟；审核失败不换 |

**永远不做：并发对冲**（同时发两家、谁先回来用谁）。视频按次计费，对冲 = 每次付双倍。

**3.3.4 熔断粒度：** 改成（厂商, 上游模型）级。只有鉴权 / 余额 / 网络错误才升级成厂商级。

**3.3.5 限流：** kie 默认每账户每 10 秒 20 个新生成请求，超了直接 429、不排队（[kie 入门指南](https://docs.kie.ai/cn.md) §8）。网关侧放一个令牌桶：满了先排队几秒，再不行派给另一家，不让用户看到 429。

### 3.4 定价与加价

**公式：** 售价 = 当日首选那家的成本 × (1 + m)，按积分向上取整。**m = 30%（已拍板）。**

**为什么不能只加 5–10%：** 下面这些都要从加价里出。

| 成本项 | 量级 | 依据 |
|---|---|---|
| 收款手续费 | 本期兑换码手动收款，视渠道而定；将来接 Stripe：¥98 档约 4.4%、¥30 档约 8% | Stripe 马来西亚：支付宝 2.9% + RM1/笔；银行卡 3% + RM1，境外卡 +1%，需换汇再 +2%（[Stripe MY 定价](https://stripe.com/my/pricing)） |
| 兜底溢价 | 2–5%（取决于兜底率） | §3.2 表最后一列 |
| 失败 / 孤儿 / 上游违规费 | 1–3%（待实测） | §4 第 1、3、4 条 |
| 赠送额度 | 每个新用户固定约 ¥3–4 | §3.5 |
| 服务器、R2、邮件 | 固定每月约 $30 | 网关部署方案 |

合计约占营收 10–15% → 加 30% 后净利约为营收的 8–13%；本期不接在线支付，手续费这一项暂时省下，留作接支付后的余量。加价后仍然便宜：Seedance 2.5 720p 5 秒我们卖 ¥9.4，kie 直购 ¥10.6，ComfyUI 同档位约 ¥11（见 §5）。

**兜底什么时候开始亏本：** 售价 1.3 倍成本，扣掉约占营收 10% 的其他成本，留给上游的预算约 1.17 倍，即余量 m′ ≈ 17%。价差 r 倍时，兜底率超过 **p\* = m′ / (r − 1)** 就整体亏。r = 3.8（GPT Image 2.5 4K）时 p\* ≈ 6%；r = 1.46（Seedance 2.5 720p）时 p\* ≈ 37%。所以：

- 照常兜底、单笔允许亏（采纳网关 09-17 方案的 D3 = A）；
- 每个模型每天监控实际兜底率；超过 p\* 的一半就告警——说明首选那家不稳，该重新排序或重新定价；
- 设每日「兜底亏损预算」，超了之后，价差 > 2 倍的档位停止兜底、改为失败退款，并告警。

**价格变动：两家其实都有结构化价格接口，不用抓网页**（这一点更新网关 09-17 方案 §3.1 的判断）：
- apimart：`GET https://api.apimart.ai/api/pricing/model?model=<id>`，免鉴权，返回分辨率档价格与折扣（[文档](https://docs.apimart.ai/cn/api-reference/texts/qwen3.8-max/pricing.md)）。注意它的「分组倍率」：真实扣费按账户分组，可能比展示价低——**大客户分组值得去谈**。
- kie：`POST https://api.kie.ai/client/v1/model-pricing/page`（官网价格页自己调用的接口，非公开文档，可能改）。
- 每日拉一次 → 更新成本表 → 算毛利 → 跌破阈值告警。**售价不自动跟随成本**（采纳 09-17 方案 D2 = A），人工决定是否调价。折扣有到期日是真实情况：网关 09-17 方案就记录了 Seedance 2.5 1080p、Seedance 2.0 Fast / Mini 限时折扣的到期时间。

**用户看到的价格：** 生成按钮上直接写「≈ ¥0.13 / 张」（D1：先出效果、一眼看到这次花多少）。另建议把积分单位改成 **1 积分 = ¥0.01**：现在的 ¥0.036 心算不了（上线前改成本几乎为零，属小决策，我的默认）。

### 3.5 额度：两个桶、体验包、防薅

**两个桶：**

| | 赠送桶 | 付费桶 |
|---|---|---|
| 来源 | 注册体验包、活动兑换码 | 售出的兑换码（本期）；将来的在线充值 |
| 能买什么 | 限定模型（便宜档） | 全部 |
| 过期 | 30 天 | 不过期（沿用网关决定） |
| 可退 | 不可退 | 未消耗部分 7 天内可退（对齐 apimart 自己的规则） |

- 扣费顺序：先扣赠送桶（模型在范围内时），再扣付费桶。
- 冻结要记下「钱来自哪个桶」，退款回原桶。赠送桶在任务进行中过期 → 仍退回原桶，再由过期任务清掉。
- **兑换码批次要带「入哪个桶」**（本期充值全靠兑换码，这一步是必须的）：卖出去的码 → 付费桶；活动送的码 → 赠送桶（带范围和有效期）。网关现有 `redeem_batches` 表加一列即可，兑换事务照旧。
- 先例：DeepSeek 开放平台把「赠送余额」和「充值余额」分开、先扣赠送；new-api 的 `service/funding_source.go` 把资金来源抽象成接口（钱包 / 订阅各一种实现）。

**体验包（给新用户的「第一口」，已拍板：只送图片 + GLM）：** 成本约 ¥3–4、30 天有效，范围：

- 图片：Nano Banana 2 / GPT Image 2.5 / Z-Image / Seedream 的 1K–2K 档 → 约 20 张；
- 文本：GLM-5.3-Flash → 约 10 次完整分镜对话（按每次 60 万输入 token、80% 命中缓存估算，需实测）。
- 不含视频。想让用户体验视频，可以单独发活动兑换码（入赠送桶、只限 Seedance 2.0 Mini 480p，一条成本 ¥0.35）。

**防薅（缺一条就会被脚本刷）：**
1. 邮箱验证后才发；一次性邮箱域名黑名单；
2. 每台设备只发一次（设备 ID 哈希存服务端）；每 IP 每天发放上限；
3. 赠送桶只能买便宜档；每账户每天从赠送桶最多花 ¥2；
4. 全站每日发放总预算，超了当天停发（自动熔断 + 告警）；
5. 需要时再加「绑手机号再送一份」。

### 3.6 支付（本期不做，留作下一阶段）

**已拍板：本期不接在线支付，充值全部走兑换码**（网关已上线：80 bit 熵、只存哈希、防刷、可整批禁用）。兑换码怎么卖、用什么渠道手动收款由你定；唯一的硬要求是**卖出的码入付费桶**（§3.5）。

以下是本轮调研的结论，接支付时直接用。

**渠道对比：**

| 渠道 | 要什么主体 | 支付宝 | 微信支付 | 费率 | 拒付风险 | 结论 |
|---|---|---|---|---|---|---|
| Stripe · 马来西亚账户 | 马来个人或公司 | ✅ | ❌ | 支付宝 2.9% + RM1；卡 3% + RM1 起；争议费 RM90/笔 | 卡有；支付宝/微信**没有**争议拒付流程 | 主体在马来就先用它 |
| Stripe · 香港 / 新加坡 / 美国账户 | 当地公司（如 Stripe Atlas 美国 LLC） | ✅ | ✅ | 按当地 | 同上 | 要微信支付就得这个 |
| Paddle（代理商户，代缴税） | 任意 | ✅ 需额外审批 | ❌ | 5% + $0.50 | 由它承担 | 海外收入多了、需要代缴各国税时再上 |
| Creem（代理商户） | 任意 | 即将支持 | 即将支持 | 3.9% + 40¢ | 由它承担 | 暂不 |
| 国内支付宝 / 微信官方 | 大陆企业 + 已备案域名 | ✅ | ✅ | 约 0.6% | 低 | 远期，要大陆公司 |
| 易支付 / 码支付类聚合 | 无 | — | — | — | 资金被第三方代收（二清）、冻结、跑路 | **不接**。new-api 默认内置它，但不要用 |

依据：[Stripe 支付宝](https://docs.stripe.com/payments/alipay)（支持主体含 MY）、[Stripe 微信支付](https://docs.stripe.com/payments/wechat-pay)（支持主体不含 MY）、[Paddle 支付方式](https://www.paddle.com/help/start/intro-to-paddle/which-payment-methods-do-you-support)、[Creem 定价](https://www.creem.io/pricing)。

**流程：** 沿用网关附录 A 的 `products / orders / payment_events` 表，另加：

1. **以 Stripe 回调为准入账，不以客户端跳转为准。** 入账条件是 `payment_status = paid`；延迟到账的支付方式要额外处理 `checkout.session.async_payment_succeeded`。
2. 回调按 `event_id` 去重；入账幂等键 `recharge:{order_id}`（账本已支持）；金额以 Stripe 回传为准，和订单比对。
3. **防盗刷卡：** 盗来的卡买额度 → 跑一堆视频 → 持卡人拒付，我们同时损失上游成本、退款和 RM90 争议费。对策：强制 3DS、Radar、新账户首充上限（如 ¥100）、同卡/同设备频率限制。支付宝和微信支付没有拒付流程，国内用户优先引导这两个。
4. **最低充值约 ¥50。** 每笔固定 RM1（约 ¥1.5）在 ¥30 档吃掉 5%。
5. 退款：只退未消耗的付费积分；支付宝 90 天内、微信支付 180 天内可原路退（Stripe 文档）。
6. **发票：** 境外主体开不了中国增值税发票，企业客户要提前说明（D4 诚实交付）。
7. 会计：未消耗的付费积分是负债。监控「上游预充余额 ÷ 7 天消耗」，低于 1 就告警（上游要提前充值，不能等用户付了钱才去充）。

### 3.7 GLM：Agent 大脑

| 渠道 | 输入 / 缓存 / 输出（$ 每百万 token） | 上下文 |
|---|---|---|
| apimart `glm-5.3-flash` | 0.06 / 0.012 / 0.20 | 128k |
| z.ai 官方 `glm-5.3-flash` | 0.15 / 0.03 / 0.50 | 1M |
| z.ai 官方 `glm-4.7-flash` | 免费 | — |

来源：apimart 价格接口（当日）、[z.ai Pricing](https://docs.z.ai/guides/overview/pricing.md)。

- 默认 GLM-5.3-Flash；**首选 apimart**（便宜 2.5 倍），上下文超过 128k 或 apimart 故障 → z.ai。
- 不要拿免费的 GLM-4.7-Flash 撑体验包：免费档并发低、条款随时变，所有用户挤一个 key 会排队。
- 不要用 GLM Coding Plan 的 key 转售：会触发 1313「公平使用」限流。
- 计费：冻结 =「输入 token 估算 + max_tokens × 输出价」，结算按上游 `usage`（流式请求要带 `stream_options.include_usage`）。用户中途断开 → 按已流出的 token 结算（new-api 就栽过：[#7231](https://github.com/QuantumNous/new-api/issues/7231) 客户端超时后上游继续跑并扣费）。流式请求**只能在第一个 token 之前换家**。
- 客户端开放项：Nomi 的 Agent 运行在 pi SDK 上，网关 access token 15 分钟过期 → 需要确认 pi 的 provider 能否每次请求动态取 token（否则要在主进程加本地转发）。**待查，未验证。**

## 6. 六角色评审（R7）

- **CTO：** 选 A 后最大风险是两份翻译漂移。缓解：参数 schema 从档案导出（一份定义）+ 跨仓对账测试（两份翻译被机器对齐）+ Go 侧只做精选的约 9 个模型。
- **设计：** 余额入口、按次价格、余额不足时的「输入兑换码」入口都是新 UI，**必须先出样张再做**（R8），并走 §1.5 控件层级（余额放 L1 常驻，兑换码放 L2）。
- **PM：** 卖点一句话：「不用注册任何平台、不用配 key，比你自己去买还便宜」。北极星指标：新用户第一天用体验包出第一张图的比例；体验包用完 → 兑换码转化率。
- **前端：** 登录回跳（`nomi://`）、「Nomi 官方」作为一个 vendor 接入现有模型设置（P4：不另做一套 UI）、按次价格来自网关 `estimate`、本地素材上传改走网关上传桶。
- **后端：** 账本加「桶」维度是最敏感的改动：冻结/结算/退款三个事务要带桶，并发测试先行。
- **真实用户：** 「积分」是不是游戏币的感觉？→ 按钮上直接显示人民币。「钱会不会被吞？」→ 失败自动退款在历史记录里写清楚每一笔。

## 8. 实施顺序

| 阶段 | 内容 | 验收门 |
|---|---|---|
| **P0 实测** | ① 每个精选模型 × 两家 × 一组固定 prompt，对齐分辨率 / 时长 / 水印 / 音频 / 耗时；② 故意触发参数错误和审核拒绝，看两家余额有没有被扣 | 一张对齐表 + 一张「失败是否计费」表；预算约 $10 |
| P1 | 成本表 + 每日价格拉取 + 毛利可见（合并 09-17 方案 P1/P2） | 管理后台每笔显示成本 / 毛利 |
| P2 | Go 翻译补齐精选模型 × 两家 + 跨仓对账测试（Nomi 仓库导出样例，网关 CI 比对） | 对账测试在两个仓库都能跑；故意改一边翻译，CI 变红 |
| P3 | 路由改造：熔断粒度、错误分类表、超时换家阈值、提交后失败换家、kie 令牌桶、上游余额监控 | 故障注入测试：一个模型挂、一家欠费、一家 429、提交超时、上游终态失败——各自走到预期分支 |
| P4 | 两个桶 + 体验包（图片 + GLM）+ 防薅 + 兑换码批次带桶 | 账本不变量按桶校验；并发冻结测试 |
| P5 | 客户端接入（登录、「Nomi 官方」作为一个供应商、按次价格、上传走网关、GLM provider、兑换码入口） | 先出样张并获批（R8） |
| P6 | 真实用户任务走查（R16） | 新用户：登录 → 体验包出图 → 用 GLM 做一次分镜 → 余额不足 → 输入兑换码 → 继续生成视频，全程截图人眼判断 |
| 后置 | 在线支付（Stripe Checkout + 回调 + 对账 + 退款），见 §3.6 | 触发条件：兑换码手动发放忙不过来 |

**不动：** 自带 key 模式完整保留；账本三事务的语义不变（只加桶维度）。
**回滚：** 网关每个 SKU 有 `enabled` 开关、`provider_runtime` 可停单家；客户端「Nomi 官方」vendor 可隐藏。
