# AGPL-only 与不要求 CLA

> 状态：✅ 已交付

## 决策

Nomi 只发布 `AGPL-3.0-only` 开源版本，不再提供闭源商业授权，也不要求贡献者、普通用户、内部使用者或视频客户签署 CLA。旧的 CLA 文件保留为说明页，避免历史链接把人带到错误的签署流程；CLA workflow 和签名账本不再运行。

这项决策把许可证和贡献政策变成一条简单规则：贡献者只需确认自己有权提交内容，贡献按 AGPL 接受；用户按 AGPL 使用、修改和分发 Nomi。团队仍可收费提供 AGPL 合规的定制开发、系统与模型集成、部署、培训、视频制作和持续迭代服务，但不能承诺只交安装包、隐瞒对应源代码的闭源 Nomi 版本。

## 为什么改

原 CLA 是为“AGPL 社区版 + 闭源商业授权”双轨模式准备的，导致 PR 需要签字、机器人还要写独立签名账本。当前产品方向已经明确为 AGPL-only，继续保留这套授权链只增加贡献摩擦，也让 README、营销站和业务表单容易继续暗示存在闭源例外。

## 影响范围

- 删除 `.github/workflows/cla.yml`，贡献 PR 不再触发 contributor-assistant。
- `CLA.md` 改为中英文政策说明，不包含签署口令或授权合同。
- README、业务咨询表单、营销源文案与生成后的双语页面统一使用 AGPL 合规定制/部署表达。
- 研究 HTML 和旧 CLA 方案明确标注现行政策，避免把历史双轨方案当成当前承诺。
- 不删除远端 `cla-signatures` 分支或历史签名；它们是历史记录，不再是当前交付门槛。

## AGPL 交付场景

个人使用、公司内部使用、修改后自用和为客户提供合规部署服务，都可以按 AGPL 使用。把修改后的 Nomi 分发给客户，或向他人提供基于 Nomi 的网络服务时，应按 AGPL 提供对应源代码和许可证信息。收费可以来自开发、集成、部署、培训、维护或用 Nomi 制作视频的服务本身，而不是另卖一份隐藏源码的闭源 Nomi 许可。

## 回滚与验收

回滚需要恢复 CLA workflow、旧的 CLA 合同文案、业务/营销中的历史表述，并恢复对应门禁测试；历史签名分支无需删除。验收要求：`check:cla-workflow` 证明没有 CLA automation；文档索引、状态、交付账本和根因合同门禁通过；站点源文案与生成 HTML 一致；全量单测、类型检查、构建和站点静态检查通过。
