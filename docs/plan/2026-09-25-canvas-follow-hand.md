## 执行记录（2026-09-25，评审与调研之后的调整）

- **砍掉**：根因 9「导演台一直渲染」——3D 画布只在全屏编辑器打开时挂载，`always` 是 09-09 方案有意定的（六角色评审）。「提示词本地草稿」——生态实查表明卡的是订阅太宽不是写得频繁，草稿还会连带撤销合并、Agent 改写、付费确认读旧值三个坑；改为收窄订阅 + 编辑器选项引用稳定。
- **不加持久化尺寸字段**：复活 `3a72f0ce7` 时去掉 `result.width/height`（2026-09-20 几何审计：不添加持久化字段真源）；没量过尺寸的视频卡临时挂只读元数据的 `<video>` 量完即卸，尺寸 owner 仍是 `useNodeMediaMeasurement`。
- **交出去**：节点下方浮框的放置（贴节点、删躲避与常驻 rAF、加展开按钮）与「程序不再主动移动视口」（含动画期间每帧写 workbenchStore）——用户 2026-09-25 拍板，归 `claude/canvas-ux-batch`，本分支不碰。
- **加进来**（实测 / 用户新报）：自动保存在界面线程同步读回整份项目（每次 41–154ms）；@ 被 `673e6c5f4` 接到拖线的首尾帧规则（图生视频 @ 视频 30/30 不出 chip）→ 新增 @ 专用规则 `resolveMentionReference`（用户：「用 @ 就该是参考图模式」）；方向键微移失灵（`b65ce1c743`，授权靠微任务时间窗口）；RC 上的不稳定测试；9 个脚本 Windows 入口判断永远为假（door-map 与 5 道门岗在 Windows 本机空跑绿）。
- **@ 缩略图 1–3 秒的真根因**：候选项不带缩略图——图片加载原图、视频各抽 16 帧胶片条（同时 2 个 ffmpeg）；视频封面在全应用收成落盘边界一个来源。
- **粘鼠标的真根因**：React Flow 只在 window 收到 mouseup 时结束拖动，没有松手丢失时的兜底（0.21 自研拖动有）；我们的取消只清了自己的状态、内核仍在拖。「原生控件吞 mouseup」的假设被 Chromium 源码推翻。
- 先查别人：[`docs/research/2026-09-25-canvas-follow-hand/prior-art.md`](../research/2026-09-25-canvas-follow-hand/prior-art.md)；结构复核：[`docs/audit/2026-09-25-generation-canvas-ownership-review.md`](../audit/2026-09-25-generation-canvas-ownership-review.md)。

## 先查别人

- <https://reactflow.dev/learn/advanced-use/performance> —— React Flow 官方性能指南（2026-09-25 经 Context7 `/websites/reactflow_dev` 取回）：自定义节点要 memo；`nodeTypes` 与传给 `<ReactFlow>` 的函数/对象要引用稳定；**组件里不要读整个 nodes 数组**（拖动、缩放时它一直在变），把需要的那份数据单独拆出来；`useStore` 要带 selector，多值配 `shallow`。
- <https://reactflow.dev/api-reference/hooks/use-viewport> 与本仓 `src/workbench/generationCanvas/reactFlow/canvasViewportScale.ts:15-18` —— `useViewport()` 按 x/y/zoom 三个标量比较，**平移也会让用它的组件重渲**；只要缩放的消费者应该只订 `transform[2]`（本仓已有 `useCanvasLiveZoom()`，节点外壳没用上）。
- <https://reactflow.dev/api-reference/hooks/use-nodes-data> —— 官方的「每个组件只订自己那一个节点」原语。
- 本仓提交 `3a72f0ce7`（PR #787，2026-09-14）—— **封面 + 交互后才建 `<video>` 我们自己已经做过一次**，真素材下拖动最长帧 125 → 9 ms、交互前播放器 24 → 0；09-15 因同一笔里的「屏幕尺寸轻量渲染」有真 bug 被 `fae43a80e` + `29e232a31` 整笔撤回，封面那半被连带撤掉。主进程封面派生（`a20bf49ce`，`electron/assets/assetPreview.ts:22` 注释：「画布首屏只挂 `<img>`，交互后才创建 `<video>`」）留在 main 上，前端没人消费。
- 同类产品对画布 / 网格里大量视频的处理（tldraw 视频形状、相册类时间线的悬停预览、Chromium `preload` 行为、原生 `controls` 与外层拖动的事件关系）：见 `docs/research/2026-09-25-canvas-follow-hand/prior-art.md`（调研中，结论回填本节）。

**结论：先把「我们自己已经写过、被误撤的」接回来，再按 React Flow 官方口径改订阅粒度；不自研新机制。**
官方指南只管框架那一层（摆放、拖动、只画屏幕内节点）；**节点里装了什么（视频）不归它管**——实测最大的一项恰恰在这一层，所以两条腿都要走。

1. **内存压力**：32 个视频 GPU 进程 1.3–2.0 GB；Mac 是 CPU/GPU 共用内存，压力上来整机迟钝，光标反馈跟着慢。修法同第 1 刀，修完用户体感即可验证；也可在 Mac「活动监视器」看「内存压力」与「Nomi Helper (GPU)」。

## 为什么之前几轮没修好（调研结论，证据见 `docs/audit` 与 git 历史）

1. **量的不是这块画布。** 存档测量里页面上实际只挂 6–24 个节点、≤ 6 个视频；名义上的「96 / 320 节点」被视口裁剪吃掉；夹具视频多数根本没加载。「30 多个视频同时在屏上、节点数又低于轻量渲染门槛 80」这个区间从没量过。
2. **测的不是卡的动作。** 悬停响应、打字、@、时长滑杆、新建节点从没有过延迟场景——这些路径也恰好从没修过。
3. **最对症的一刀被连带撤回，没人记账。** 见上「先查别人」第 4 条；TODO T-CV-01 至今写着「海报那半已进」，与 main 不符。
4. **门岗看不见。** CI「Canvas Performance (Linux)」近 150 次 77 次被跳过（改提示词框、参数控件、store 都不触发它）；跑的时候是 Linux 软件渲染 + P95 53 ms（≈ 19 fps）预算，永远绿；从没在 Mac 上跑过；真素材要求被登记成欠账（10-14 到期）。
5. **每轮只关自己量到的那项。** #763 的硬指标没达成就改成「只记录不判」；后来的功能又把重活加回热路径，是人工审计才发现。

## 分步（每步一个提交，前后都量；每步可单独回滚）

0. **量具先行。** 把这次的测量脚本收成 `tests/ux/canvas-follow-hand.perf.mjs`：用户那块画布（真实 15 秒 1080p 片子 × 32 视频节点 + 图文节点，缩放到全部在屏上），九个动作，每项同时记**时延**和**结构计数**（挂载的 `<video>` 数、每次输入重渲的组件数、连带重渲的别的节点数）。先在 main 上跑出基线，入库。
1. **视频封面（根因 1）。** 复活 `3a72f0ce7` 的封面半（不含屏幕尺寸轻量渲染）：卡片平时画 `result.thumbnailUrl`；悬停 / 选中 / 聚焦才建 `<video>`，封面垫在下面直到第一帧出来（不闪黑）；移开且未选中、未在用户主动播放 → 销毁 `<video>` 释放解码器；**全画布同时最多一个在播**（新的一个开始，上一个停）。老节点没有 `thumbnailUrl` → 按资产找主进程已有的封面缓存（`assetPreview.ts` sidecar），没有就当场抽一帧并回写。导出 / 时间轴 / 大图预览仍用源 `result.url`。
2. **高频输入走本地草稿（根因 2、6）。** 提示词编辑器本地草稿，停顿 300 ms / 失焦 / 切节点 / 关项目时提交（一次提交 = 一步撤销）；滑杆拖动只改本地值，松手 `onChangeEnd` 提交一次；`PromptEditor` 的 extensions 引用稳定；@ 候选缩略图走小预览。落 T-CV-18「节点内受控输入」门岗。
3. **订阅粒度（根因 3、4、5）。** 按上表逐个把整表订阅换成只订自己；节点外壳换 `useCanvasLiveZoom()`、删节点总数订阅；视口动画只在结束写 store；composer 挂载延后一帧（`startTransition`），放置改成事件驱动、删常驻 rAF。
4. **设计层延迟与导演台（根因 7、9）。**
5. **粘鼠标（根因 8）。** 等复现证据定层再修；修法必须带「松手后节点不再跟随」的断言。
6. **守住。** 见下节。每步做完在同一量具上出前后对照，写进 PR。

## 不影响功能：每一步都要过的等价检查

- 现有：`test:core-smoke`（empty / used）、画布走查（含 `canvas-batch-production`，就是上次把封面连带撤掉的那条）、`at-mention-edge` 走查、单测。
- 这次新增的行为断言（量具里一起跑）：
  - 打完字立刻切节点 / 关项目 / 退出 → 文字已存盘；撤销一次回到打字前；自动保存照常。
  - 滑杆松手后值落盘；一次拖动 = 一步撤销。
  - @ 连续 30 次选中，chip 30/30 进输入框（快速连选、滚动后选、回车选、点选、选完立刻打字）。
  - 视频：悬停后开始播放（记起播时延）；选中可带声播放；任何时刻播放中的 `<video>` ≤ 1；节点尺寸 / 时长与改前一致；导出、加入时间轴、大图预览拿到的仍是源文件。
  - 拖动：叠放 10 个逐个拖出，松手后 0 个节点继续跟随鼠标。
- 唯一有意改变的行为：视频节点平时是封面（用户已拍板）；外观上封面 = 首帧，和现在暂停的视频看起来一样。

## 守住（这次和之前几轮最大的不同）

1. **结构断言进 CI，所有非纯文档 PR 都跑**（像 Core Flow Smoke 一样不许 skip，控制在 2 分钟内）：空闲时挂载的 `<video>` = 0；打一个字只重渲这一张卡；新建节点连带重渲 0 个别的节点；@ 30/30。结构计数与平台和机器快慢无关，Linux 上也判得准——**封面这件事被连带撤掉那天，这条会当场变红**。
2. **时延按「和 main 同机比」判，不判固定天花板**：Linux CI 上跑同一量具，比值变差超过阈值即红；「只记录不判」的项必须带到期日。
