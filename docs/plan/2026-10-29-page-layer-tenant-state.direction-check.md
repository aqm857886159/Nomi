### 0. 一句话根因

页格层的“开着”寄存在画布节点组件中，而画布会裁剪、卸载、重挂节点；状态归属比它承载的 UI 寿命短。

### 1. 归类表

| 表现 | 直接原因 | 类 |
|---|---|---|
| 全景切创作再返回自动关闭 | 视口宽度回弹时 React Flow 移除边缘节点，本地 `fullscreen` 丢失 | 页格会话事实归节点组件 |
| 导演台当前未复现 | `open` 同样是节点组件本地 state，节点碰巧没有被裁掉 | 同类入口，仍需修 |

### 2. 为什么会一直出现

`onlyRenderVisibleElements` 合理地按可见视口渲染节点；任何节点级 open state 都跟着组件卸载丢。修一处视口尺寸或把节点钉住只会掩盖这次触发。铁律 ⑫ 适用：用户预期切回仍开，实际全景关闭；走查 `7.back` 与类级测试对照。

### 3. 不改结构的预测

| 预测 | 验证 |
|---|---|
| 导演台节点放到视口边缘也会丢 open | 走查 `7b.edge-back` |
| 以后新页格租户仍可能把 open 放本地 | `pageLayerCensus.test.ts` 遍历全部登记租户的重挂和删除生命周期 |

### 4. 靶子独立性

独立验收线 V 先在 Mac 生产构建复现。实现线本轮只给挂载日志补节点和视口矩形：回生成时视口右缘 1432→1117，全景节点左缘 1258；remove 后 77ms add，节点数据未变。尺寸裁剪解释触发，但修法不依赖这个解释。

### 5. P0

React Flow 的可见节点裁剪是现成通用能力，保留。按节点 id 保存页格会话状态是 Nomi 页格租户的归属规则；用现有 Zustand 与 `storeLifetimeRegistry`，不装包。

### 6. 方案

| 选项 | 结果 | 判断 |
|---|---|
| 页格层统一持有两个租户的 open；节点只读 / 发意图；真删节点与项目释放清理 | 重挂不会丢开态，唯一事实 | **已拍板** |
| 关闭视口裁剪或固定节点渲染 | 只能掩盖这次卸载原因，还增加画布成本 | 否决 |
| 只修全景 | 导演台仍有同类缺口 | 否决 |

### 7. 用户要权衡的核心

用户已定：页格层会话要跨节点组件寿命，删节点和离开项目才结束；这轮只本地提交。

## 特征测试

`src/workbench/pageLayerCensus.test.ts` 遍历全部页格租户：打开、卸载并重挂、真删节点、项目释放。`tests/ux/director-layer-in-page.walk.mjs` 中英两轨测导演台边缘节点与全景 `7.back`。
