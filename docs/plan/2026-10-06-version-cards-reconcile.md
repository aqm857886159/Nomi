## 4. 顺手查实的老问题（不在本线范围，报给协调会话）

**⌘Z 会把撤销点之后落地的生成结果一起撤掉。** 撤销 = 撤销日志前缀重放（`canvasUndoJournal.ts` 的 `popUndo`），生成落地的 `canvas.node.run-updated` 事件也在日志里，于是「做一个手势 → 一张图生成好落到节点上 → 按 ⌘Z」，那张图从节点上消失（文件还在盘上，钱已经花了）。临时测试实证：锁节点 → 落一张结果 → 撤销 → 节点上 `result` 为空、`history` 长度 0。版本卡片让「撤销」更常用，所以本线的提示条只在删除仍是最后一件事时给「撤销」；⌘Z 本身的这个类问题要另开一条线修（花钱边界）。

## 7. 用户 10-06 改向：和节点一样、宫格、去掉图标（样张待拍板）

原话：「重拍这镜这个按钮需要吗，可以删掉吗？我记得我的设计里面是和原来的图片一样的东西，而且排列按照宫格排列，要不然就会一长排；icon 能不能删掉，就靠点击后面那个卡片那里？」

### 7.1 「重拍这镜」可以删：核实结论

- 失败的制作镜头卡面上的「重试」（`NodeErrorReport` → `useProductionNodeRetry`）对多镜批次走的就是 `reworkProductionShot`——和浮条「重拍这镜」是同一个函数。
- 主进程 `reworkProductionShot`（`electron/capabilityCore/appIntegrationProductionActions.ts`）重新授权这一镜之后，如果批次是因为这一镜失败停下的（`retryLiftsStop`），会顺手 resume，批次接着跑。
- 所以「失败 → 重试 → 批次接着跑」不靠浮条按钮；对成功的镜头，浮条「重拍这镜」和节点 ↑「再出一版」对用户是同一件事，两个按钮分不清。
- 结论：浮条「重拍这镜」可以删，入口、文案、测试、走查 pb01 那条一起删；单镜制作节点本来就走节点 ↑。
- 剩下一个小缝：用户先点「收起失败卡」再想重试，失败卡没了，就只剩节点 ↑（新开单镜 Run，不会让停下的批次接着跑）。这时批次要靠任务卡上的「继续剩余」。这条照现状，不另加入口。
- 删除和宫格样张一起给用户看，拍板后随 V2 一起提交。

### 7.2 宫格样张（设计实验室真组件，屏 `version-cards`）

- 入口：去掉节点右侧的版本图标和「N 版」角标，入口就是节点身后叠着的那几张卡。悬停时叠卡轻轻扇开、露出「N 版」小标，指针变成手型；点叠卡就铺开。铺开后叠卡原位置留一个淡轮廓当把手，再点它或按 Esc 收起。只有 1 版的节点没有叠卡，也就没有入口。
- 宫格：版本卡和节点一样大，长得一样，就是那张图本身。版本号是角上的小字，主图带「✓ 主图」。列数 = ⌈√n⌉：2 张 1×2、3–4 张 2×2、5–6 张 3×2、7–9 张 3×3；超过 9 张时前 8 格 +「+N」，点开后全部按同一条规则排（12 张 4×3）。最新一版离节点最近；右边放不下往左铺，整块镜像。
- 生成中：铺开时在节点上再出一版，宫格最前一格是「生成中」占位。它只是告诉你新的一版会落在哪，不是按钮。
- 保留 09-28 的拍板：盖住邻居时盖在上面、点中浮起；删除不弹框、提示条给撤销；悬停条 = 设为主图 / 下载 / 删除；点卡 = 预览。
- 组件：`src/workbench/generationCanvas/nodes/versionCards/`（几何纯函数 `versionGridLayout.ts` + `NodeVersionCards.tsx`），实验室 `src/devlab/designLab/versionCards/`，走查 `node tests/ux/design-lab-version-cards.walk.mjs`。还没接进节点；用户拍板后 V2 接线，同时删掉旧小窗 `NodeResultStack.tsx` 和「N 版」胶囊。
