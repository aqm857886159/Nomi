## 已定的一件事（协调 2026-10-16 定选项 A）

**按钮本身不花钱。**「出成片」= 把整段预演挂到视频镜头上、预填好提示词，然后带用户回到画布、选中那个视频节点；**真正花钱仍是用户在那个节点上点 ↑**，走现有的节点生成入口和主进程准入（预演闸在那里）。

为什么这样定：
1. 先例：用户 2026-10-05 对「一键派生」拍板过「只建节点、连参考、填提示词，用户点 ↑ 才花钱」（`quickActions/deriveFromNode.ts` 头注释）。「出成片」是同一类动作，照同一条规矩。
2. 不新开花钱口：不新增任何提交、批准、派发调用；节点 ↑ 和 Agent 的 `generate` 已经经过同一个主进程准入（`electron/capabilityCore/appIntegrationCanvasShot.ts:16,74-75` 的预演闸）。
3. 不依赖 Agent 模型：没配 Agent 的用户也能用；配了 Agent 的用户照样可以在对话里说「出成片」，由 `generate` 出报价卡（这条路已经在 3b 做完）。

| 选项 | 做法 | 代价 |
|---|---|---|
| **A（推荐）准备 + 交回节点** | 挂预演、填提示词 → 关导演台 → 画布选中视频节点，视野移过去；用户点 ↑ 花钱 | 比 B 多一次点击（节点 ↑） |
| B 交给 Agent | 按钮往 Agent 输入框发「用这段预演出成片」，Agent 调 `generate` 出报价卡 | 没配 Agent 模型就用不了；多花一轮文本额度；按钮行为取决于模型理解 |
| C 按钮直接提交 | 按钮里直接跑节点生成 + 弹付费确认 | 新开一个花钱入口，和「派生只准备」的拍板冲突 |
