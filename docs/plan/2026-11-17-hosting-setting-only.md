# 设计卡：用不用第三方公共临时托管，只由设置里的开关说了算

状态：动手前核准；实现依据 2026-11-17 用户决定。一个 PR，以删为主。
类别：四类（素材离开本机；动到花钱确认处上的一段文字）。修复，不是新功能；没有新增交互，★7 写不适用。
来历：这件事先按「点生成时问一次、同意绑到具体素材」做了两个本机提交，独立验收两次没过（界面代码不出确认也能要到同意）。没参与过的线做了方向检查，用户 2026-11-17 定：**删掉按次同意，同意就是设置里的开关**。那两个提交不合并。

## ★0 先查别人

- Terraform `apply -input=false`（https://developer.hashicorp.com/terraform/cli/commands/apply ，协调亲眼打开过）· 没人可问时保守地当作不同意、明确失败，要自动放行就事先写进配置 · **确认了**：没开开关就停下、说清，不在流程里临时放行。
- ComfyUI 服务端说明（https://raw.githubusercontent.com/Comfy-Org/docs/main/development/comfyui-server/comms_overview.mdx ，协调亲眼打开过）· 执行的那一层只认提交上来的东西，不认界面后来的状态 · **确认了**：放不放行由做事的那一层自己读自己的设置，不由界面带一个「已同意」过来。
- 两种写代码的助手的权限说明（https://code.claude.com/docs/en/permissions ，调研线打开的，协调没亲眼看）· 「这一次同意」和「以后都允许」分开存，后者是一条设置 · **改了**：我们只留后者。前者在发版软件的默认通道下走不到，为它维持一套签发和兑换不值。
- 出口：开关随时可开可关；关着时走不通会停在一张写明原因和下一步的卡上，可以重试、换小一点的文件、换一个带上传通道的供应商，或去设置里打开开关。

## ★1 用户怎么用

当我给一个节点接了本地参考图、点生成时，我想让图只去我选的供应商、我接入的别家或 Nomi 中转；这些都传不上去的时候，除非我自己在设置里开过「允许第三方公共临时托管」，否则图不离开这几处，并且我知道为什么停了、能做什么。

步骤：①接参考图 → ②点生成（确认处不再有托管告知）→ ③按顺序试通道：所选供应商 → 接入的别家 → Nomi 中转 → ④都失败：开关开着就换到第三方图床；关着就停，节点上出现「参考图没传上去」的卡 → ⑤卡上两句话：哪条通道没传上去、为什么；下一步是什么 → ⑥重试，或去设置打开开关后重试。

不做：不新增任何确认；不改确认卡和错误卡的样子（只删卡上一段、改几句字）；不给直传、云端转写、本机命令行工具加许可（它们到不了第三方图床）；不动通道顺序和「一条装不下换下一条」。
已知坑：开关的存储值不改（`ask` / `allow`），只改它在界面上的名字和说明——`ask` 从「先问我」变成「不用」。

真实任务：
1. 自接的供应商没有上传通道，本地参考图 1 张，开关关着（默认），中转正常：不出任何告知，图到中转，第三方图床收到 0，生成 1。
2. 同上但中转回 503：停，第三方图床 0、生成 0；卡上写明是 Nomi 中转没传上去和三条下一步。去设置打开开关后重试：第三方图床收到的正是这一张，生成 1。
3. 内置供应商（有自己的上传通道）：图只到供应商，其余 0。
4. 助手起草一张带参考的图，从确认条点生成：确认条上没有托管告知；结果同任务 1、2。
5. 批量 12 镜、下游用同批上游的产物当参考，开关关着：全程不问，全部发出；第三方图床 0。

指标与量具：
- 开关关着时第三方图床收到的字节 = 0 · 量具：走查脚本从真实入口走到本机回环假服务，按收到的请求与文件摘要核（修前基线：主分支 1 次、已发版本 1 次，均已复现）。
- 托管相关的询问次数 = 0 · 量具：同一脚本读确认处的文字。
- 能把文件发到第三方图床的代码处数 = 1，且它只读主进程自己的设置 · 量具：`node scripts/door-map.mjs` 加一条边界检查。

### ★1b 连带界面

- 画布确认、批量确认、助手确认条、「结果未知要不要重发」的确认：删掉托管告知那一段和「记住我的选择，以后不再问」。
- 设置 → AI 策略 → 数据上传：开关改名「允许第三方公共临时托管」，说明两句：别的上传通道都传不上去时，把参考素材临时传到第三方图床，链接任何人可访问、短期有效；关着时会停下来告诉你。默认关。删掉说明里「未配置 KIE 时…」的旧话。
- 没人可问的回执（助手、外部助手、试跑）：一句「参考素材没传上去；需要的话可以在设置里允许第三方公共临时托管」，沿用现有错误码，中英文。

### ★1c 老用户

- 以前设成「直接上传」或勾过「以后不再问」的（存的是 `allow`）：升级后开关是开的，行为不变，不多问。
- 以前是默认「先问我」的（存的是 `ask`）：升级后开关是关的。以前会在确认处被问、点同意就传；现在不问，走不通时停下，要用得自己去开一次。这是这次唯一的行为变化。
- 设置文件里是 `deny` 的（界面上设不出来，只可能手改）：按关着处理，读到后规整成 `ask`。
- 存储格式不变，退回上一版照常打开。验证用已发的 0.24.1 真实做出的三份资料目录（直接上传、记住并允许、批量发到一半）。

## ★2 谁说了算

- 唯一的家：主进程里的素材上传循环（`electron/catalog/assetLocalization.ts:555`）；共用的设置判据 `anonymousHostingEnabled` 在 `electron/catalog/assetLocalization.ts:47`，发前预检在同文件 `assertLocalAssetTransportReady`（202 行）。第三方图床的通道定义只在 `electron/catalog/assetIngestionRegistry.ts`，只被这个循环用。循环自己读主进程持有的设置；别人传不进「允许」。
- 界面：只有设置页那个开关能改这条设置（已有的设置读写口）。确认处、发送端、交接、调用方都不带任何托管相关的字段。
- 删掉的家：界面侧算「要不要告知」的几处、发送端自带的允许、附加字段里的同意、缺省允许。门数：现在 6 处在算、4 处能自己放行；做完 1 处在算、0 处能自己放行（实现线用 `door-map` 重数）。

## ★3 一致与复用

- 以前定过：发送前只在三种情况停——确定白花钱、确定丢作品、文件第一次去新的第三方时同意一次（2026-11-13）。这次把「同意一次」落成设置里的一次开关，不落成流程里的一次确认。
- 三条路：沿原方向修（主进程发起询问再签发，仍留签发 / 兑换）——同一处已两轮没过；换一种做法（主进程握住那次询问、直接放行这一次，独立方向检查的推荐）；删掉按次同意（选这条）。理由：按「只有第三方图床是唯一出路才问」的判据，发版软件的默认通道下走不到那一步；删掉后没有「同意」这个可被调用的口。代价（方向检查指出、用户已接受）：一次性、限定素材的同意换成了长期开关。
- 复用：现有设置项与它的读写口、现有通道顺序、现有「所有通道失败」错误卡。不引库，不加新对象。

## ★4 全状态

- 空（没有本地素材）：原流程。
- 加载：不变。
- 成功：照常生成。
- 失败：通道都没传上去——现有错误卡，两句话：哪条通道、为什么；下一步。
- 部分成功：批量里某一镜没传上去——那一镜出错误卡，别的镜照常。
- 取消中：不变；第一次上传之前取消，上传 0。
- 过期：没有会过期的同意。上传中途把开关关掉：之后的通道选择按新值。
- 能力不可用：没有任何通道收这类素材——现有文案加下一步（配一个带上传通道的供应商，或打开开关）。
- 最大值：一次 40 镜、每镜 3 张；最长文字：错误卡两句以内，通道名最长的是自定义中转的主机名，用现有截断。

## 6 外部数据与失败

- 供应商的上传接口：各家文档没写大小上限，用 413 当「这条装不下」的信号（2026-08-20 的做法，保留）；失败时写明是哪一家的通道。
- Nomi 中转：返回非 2xx 或超时算失败，重试次数不变；失败时写「Nomi 中转暂时不可用」，不说成用户的 key 有问题。
- 第三方图床：只有开关开着才会碰；它失败时按现有链上的下一家。
- 设置文件：值不认识时按 `ask`（关）。

## ★9 验收与回滚

应该通过：
1. 上面五条真实任务（中文、英文各一遍）。
2. 开关关着：从每个会经过上传循环的入口各走一次——画布单节点、批量、分镜批量、助手单张、助手多张、自定义脚本生成、映射试跑、助手试模型、外部助手语义生成、语义返工——第三方图床收到 0。
3. 开关开着：中转失败后换到第三方图床，生成照常，全程不出任何询问。
4. 三份真实旧资料：`allow` 的两份升级后开关是开的、不多问；`ask` 的那份开关是关的，在途任务已发出的只查、不出现第二个生成请求。
5. 设置文件里写 `deny`：读回按关着，行为同 `ask`。
6. 供应商通道回 413、下一条是中转：换过去，照常。
7. 确认处四个地方都没有托管告知和「记住我的选择」。
8. 错误卡不点开详情就看得出是哪条通道、下一步是什么；最窄宽度不撑破。

故意改坏必须报红（实现线交「反例 → 改坏后哪条检查红 → 还原后绿」表；验收线只按这张表和上面八条核，不另立判据）：
- 上传循环在开关关着时仍把第三方图床当候选。
- 发送端、交接或任何调用方带一个「允许」字段进来并被采纳。
- 上传循环缺省当作允许。
- 循环之外的任何地方引用第三方图床的通道定义或自己拼它的地址。
- 界面侧在设置页之外改这条设置。
- 把 `deny` 或不认识的值当作允许。
- 恢复确认处的托管告知或「记住我的选择」。
- 通道失败时不写是哪条通道。

这一类还会从哪里回来：将来新增一条上传通道或一个新入口时自带放行；新的「临时允许」参数；设置之外的第二个开关。由「只有一处能发、它只读自己的设置」这条边界检查守。

真实场景复现：创作者把托管设成「先问我」，助手起草带参考的一张图，确认条没有告知，点生成后图被传到第三方图床（主分支和已发的 0.24.1 都看到匿名端收到同一份文件）。修后判据——同样的设置和操作，第三方图床收到 0；中转正常时照常出图，中转失败时停在写明原因的卡上。和用户那次的差别：样图、本机回环的假服务。

回滚：一个 PR，`git revert` 合并提交即可；不改数据格式。
独立验收：另一条线按本格清单验，报告链接放 PR 正文。
