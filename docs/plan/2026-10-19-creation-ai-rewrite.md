### ★0 先查别人

- Notion AI（<https://www.notion.com/help/guides/notion-ai-for-docs>）· 选中文字出菜单：改善写作 / 缩短 / 扩写 / 改语气 / 翻译，结果就地出，接受 / 放弃 / 重试 · **确认了**「常用改法一行 + 输入框」的菜单形状；**改了**：不做「候选 / 重试」三件套，只留 ✓ ✕ 和输入框右端 ↻（用户「太冗余了，要优雅」）。
- Cursor 行内编辑（<https://docs.cursor.com/en/cmdk/overview>）· 改动以新旧对比叠在原文上，Enter 接受 Esc 放弃，输入框里可追加要求 · **确认了**Enter / Esc 键位与「追加要求 = 改输入框再回车」；**改了**：追加要求仍从同一段原文出发（不叠在上一版结果上），避免越改越偏。
- jsdiff（<https://github.com/kpdecker/jsdiff>，Context7 `/kpdecker/jsdiff`）· `diffWords` 的 `intlSegmenter` 选项专门给中文这类无空格文字按词切 · **确认了**不自写比较算法、中文走 `Intl.Segmenter`；**改了**：不按字比（按字比出的删加碎成一地，读不了）。
- ProseMirror 装饰（<https://prosemirror.net/docs/ref/#view.Decoration>）· 装饰是叠在文档上的「画」，不进文档、不进历史 · **确认了**「接受之前文档一字不动、接受 = 单事务一条撤销」；**改了**：不先写进文档再让用户回滚（那样放弃也会进撤销栈、协同 / 自动保存会把半成品存下去）。

### ★1 用户怎么用

当用户在写剧本时觉得某句太长，我想选中它、说「缩短」，就地看到改了什么，满意按 Enter，不满意按 Esc，以便不离开正文、不开右侧 Agent。

1. 选中一段字，选区浮条上出现「AI 编辑」（Nomi 标记带底），原有加粗 / 斜体 / 标题 / 生图 / 生视频 / 拆成镜头原样在。
2. 点它：段后出现输入框「告诉 Nomi 怎么改…」，下面一行常用改法：改写、缩短、扩写、改语气 ▾、翻译 ▾，再接用户自己的写作 Skill。
3. 点一项或输入要求回车：原文标成待改、输入框转圈；结果回来后原文里删掉的划线、新加的标出来，段尾只跟 ✓ ✕。
4. Enter 接受（正文换成新的，Ctrl+Z 一步撤回）；Esc 放弃（原文不变）。
5. 看结果时输入框留在原处并保留这次的要求：改了字再回车 = 追加要求；右端 ↻ = 用原要求重来。两者都从**打开那一刻的原文**出发。

不做：分场、目录、布局；空行续写（WD2）；候选 1/3、三视图、一排四个按钮；不替用户选模型（用 Agent 面板选的那个文本模型）。
已知坑：选区跨多个块时接受后换成按空行分的几个普通段落（原块类型不保留）；改写中途用户点去别处 = 取消（结果回来也不落）；**单段接受时，选区里混排的粗体 / 斜体、硬换行这类行内格式会丢**（新文字只沿用选区起点处的格式；Ctrl+Z 一步能撤回，数据不丢）。

真实任务（不花钱，假模型走真路径）：① 剧本里一句话「缩短」→ 接受 → 撤销；② 同一句「缩短，再冷一点」追加要求后 ↻；③ 结果出来前点别处，确认什么都没写。
指标与量具：主指标「接受后正文与结果一致、撤销回原样」——量具 `src/workbench/creation/aiRewrite/aiRewrite.test.ts`；质量指标「失败时原文不变且写清没改成 + 原因」——同上；真键鼠走查 `tests/ux/design-lab-creation-ai-rewrite.walk.mjs`（`rewrite-live-zh-light`）。采纳率 / 放弃率：未验证：缺量具（本 PR 不加遥测，见 ★9）。真模型效果：未验证：协调会话用真模型走一次。

### ★1b 连带界面

- Agent 回执 / 通知 / 任务列表：不涉及（不走 Agent、不建任务、不进任务中心）。
- 错误：只在 AI 编辑条里一行「没改成：<原因>」（中）/ `Could not edit: <reason>`（英）；没有文本模型写「到设置 → 模型启用一个」。
- 撤销提示：沿用编辑器自己的撤销，无新提示。

### ★2 谁说了算

| 概念 | 唯一 owner | 说明 |
|---|---|---|
| 一次 AI 编辑会话（区间、原文、要求、结果、状态） | 创作编辑器的 ProseMirror 插件状态（`rewriteSession.ts`） | 没有第二份；React 只读它（`useSyncExternalStore`） |
| 正文 | 文稿文档（`workbenchDocuments`，经编辑器 `onUpdate`） | 接受前不动；接受 = 一笔事务 |
| 模型选择 | Agent 面板的模型偏好（`getTextBrain`） | 不另设 |
| 写作 Skill 清单 | 技能库（`listWorkbenchSkills`） | 只筛不存 |

碰 4 个概念，都是读或经现有入口写。没有靠「东西不见了」去猜意图：关会话是显式事件（Esc / ✕ / 选了别处）。`node scripts/door-map.mjs` 不适用（无新增 IPC / 入口）。

### ★3 一致与复用

选区浮条（`SelectionGeneratePopover`）加一颗；图标 `NomiLogoMark`（带底，不用闪光）；常用改法 / 失败提示的文字管线 = 提示词翻译 / 优化同一条（`getTextBrain({strict})` + `runWorkbenchTextTaskStream('prompt_refine')` + `withProjectAction`）；提示词模式 `creationAiModes` 的专长层（自由写作模式）当文体约定带进去；Skill 清单 `listWorkbenchSkills` + `skillDisplayTitle`；图标全在词典里（IconBooks = Skill，IconRefresh，IconArrowUp，IconChevronDown，✓ ✕ = Tabler check / x）。第二份定义：文档里的 ✓ ✕ 是 ProseMirror 裸 DOM 小部件进不了 React 树，所以画的是同一套 Tabler 路径（已在代码注释说明）。

### ★4 全状态

| 状态 | 用户看到 |
|---|---|
| 空（没选字 / 只选空白） | 浮条不出现；点不到 AI 编辑 |
| 菜单 | 输入框 + 常用改法 + Skill；原文标成淡蓝 |
| 加载 / 进行中 | 输入框右端转圈（Nomi 标记）；原文淡蓝；Esc 取消 |
| 成功 | 删划线 / 新字标出；段尾 ✓ ✕；输入框保留要求 + ↻ |
| 失败 | 输入框下一行红字「没改成：原因」；原文不变；↻ 可重来 |
| 部分成功 | 不适用：一次只改一段，要么出结果要么没改成 |
| 取消中 | 点别处 / Esc：条立即消失，请求被中断，迟到的结果直接丢弃 |
| 过期 | 原文被编辑过：会话作废，条消失，不覆盖用户刚写的字 |
| 能力不可用 | 没文本模型：「没改成：还没有可用的文本模型，到「设置 → 模型」启用一个」；没打开项目：「没改成：当前没有打开的项目」 |

### 5 中途表（模型调用可打断）

| 状态 × 打断 | 停 / 点 Esc | 关窗 / 切文稿 | 断网 | 重启 | 连点 |
|---|---|---|---|---|---|
| 进行中 | 请求取消，原文不变，不扣不写 | 换文稿（含正文一模一样的另一篇、整份复制的另一个项目）：会话身份是「项目 + 文稿」，身份一变会话作废、请求取消、结果无处可写，并提示「文稿已切换，这次改写没有写入」；关编辑器：控制器 dispose → 请求取消 | 报错 → 没改成 + 原因 | 会话在内存，重启即无，文档未被改 | 第二次提交被忽略（只有一个请求在飞） |
| 结果已出 | Esc = 放弃 | 同上，文档未被改 | 不涉及 | 同上 | Enter 连按：第一次接受，会话已关，第二次是普通换行 |
| 失败 | Esc = 关 | 同上 | ↻ 再试 | 同上 | ↻ 连点：进行中忽略 |

花费：每次提交 = 一次文本模型调用（走用户自己选的模型）；本 PR 不引入价格判断、不弹确认（和提示词翻译 / 优化一致）。

### 6 外部数据与失败

外部来源：文本模型回包（经现有流式任务）、用户的 Skill 正文。模型回包被代码围栏 / 引号包住 → `cleanRewriteOutput` 剥掉；空 → 没改成「模型没有返回内容」；和原文一样 → 没改成「模型返回的内容和原文一样」；未知失败带原始原因，不甩给用户的 key。Skill 正文截 6000 字，去 frontmatter。

### ★7 性能（新功能）

①新增操作：点 AI 编辑、输入、点常用改法、Enter / Esc、↻、结果上屏。②最坏规模：2000 段文稿、选区 8000 字（180 段）、结果同长。③预算：操作到可见反馈 ≤100ms（默认预算，不放宽）。④场景 `creation-ai-rewrite-result-8000`（`tests/perf/scenarios/`，驱动 `tests/perf/canvas-scale-bench.mjs` 的 `creation-ai-rewrite-result`，真 Electron、隔离资料目录、零花费）：点「AI 编辑」→ 条出现、结果回来 → 新旧对比上屏，两个时刻各量一次取较慢者，每次采样用不同的结果文字（不吃缓存）。**基线 中位数 31.8ms / p95 32.6ms / 预算 100ms**，5 次，状态 ok，预算状态 `proposed`（待协调改 approved）。

优化记录：第一版整块词比较，8000 字冷启动首次 195ms（超预算）。修法：段数不变就一段一段比，整块比加 60ms 时间上限（超了退回整段删加）；冷启动首次降到 51ms，热的中位数 32ms。

## 和样张 WD1 不一致的地方

1. 新旧对比的粒度：样张整句划掉再整句新写；实现按词 diff（保留相同的词），更省读但和样张的「整句换」不同。
2. 选区浮条出现在选区上方，会压住上一段的一部分字（浮条位置是既有逻辑，样张画在段间空白里）；本 PR 不改浮条定位。
3. 「拆成镜头」在没有分镜入口的上下文里是灰的（既有行为），实验室里可见。
4. 英文长句时 ✓ ✕ 可能折到下一行（跟在段尾，行满则折行）。
5. 改语气 ▾ / 翻译 ▾ 点开是条里多出一行选项（而不是浮出菜单），选项：更正式 / 更口语 / 更克制 / 更温暖，英文 / 中文 / 日文——样张没画展开态。
6. 样张的 Skill 小图标是「笔记本」，实现用技能库同一个图标 IconBooks。
7. 悬停 ✓ 的「接受 Enter」提示：已实现，只在真悬停时出现（走查 `live-03-result.png` 里可见，其它格不悬停）。
