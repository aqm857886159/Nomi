# Nomi 视频拆解能力执行计划

日期：2026-08-08
状态：实现与真实旅程完成，待全量门禁和对抗评审
依据：`docs/research/2026-08-08-chatcut-codex-video-marketing-analysis.md`

## 用户摩擦与产品判断

用户拿到参考视频时，真正需要的不是“切出 38 张图”，而是知道：开头为什么抓人、每段承担什么营销任务、哪些镜头要实拍、哪些可以生成、怎样只借节奏和结构做一条不抄袭的新片。

Nomi 已有“按镜头拆”物理切分、预览勾选和落画布能力。新增能力必须升级这个入口，不能再造一套独立分析页。e-cut 当前没有仓库许可证声明，因此本轮只对接其本地 HTTP 契约，不复制源码。分析引擎必须可替换，基础物理切分在引擎离线时仍可用。

## 范围

### 本轮必须完成

- 保留视频节点原有入口，用唯一的 `VideoDeconstructionPanel` 替换旧 `NodeShotCutPanel`，在一个面板内提供“镜头切点 / 内容结构”两种视图。
- 主进程增加仅允许 loopback 的视频分析引擎适配器。
- 通过本地文件流向 e-cut 提交视频，不把绝对路径交给 renderer 或服务。
- 持久化分析任务、阶段、外部 task id、结果和错误；应用重启后可恢复轮询。
- 任务中心显示真实阶段、已耗时、可否取消和失败动作，不显示假百分比。
- 结构结果展示段落、营销角色、时间范围、关键帧、原始 OCR/ASR 与模型解释边界。
- 用户勾选后复用现有抽帧和成组逻辑落画布；节点带时间、角色、画面描述和证据引用。
- 提供“沿用结构写新方案”动作，只复用节奏/角色，不复制原文和品牌资产。
- 设置页增加分析引擎状态、外部推理许可、源文件副本和缓存清理边界。
- 中英文文案、token、控件契约、路径安全、重启恢复和 Electron 真实旅程全部验收。

### 不做

- 不把 e-cut Python 依赖打包进本轮 Nomi 安装包。
- 不复制第三方视频、脚本、演员或品牌资产。
- 不宣称模型推断等于事实；所有结论必须能回到时间戳和原帧。
- 不允许任意公网分析引擎 URL；首版只接受 `127.0.0.1`、`localhost` 和 `[::1]`。
- 不从 renderer 接受绝对文件路径、任务完成状态或分析结果。

## 状态与数据契约

任务阶段固定为：

`queued → reading_media → detecting_shots → transcribing → extracting_text → structuring → completed`

异常状态：`failed`、`submission_unknown`、`cancel_requested`、`cancelled`、`engine_unreachable`、`engine_incompatible`。只有引擎返回可验证的阶段时才显示阶段；不从日志行数伪造百分比。

持久化目录位于项目内：

```text
analysis/video/<analysisId>/
  task.json
  result.json
  evidence.json
```

`task.json` 不保存密钥、绝对路径或原始 prompt。`result.json` 保存经过 schema 校验的 scenes/shots/patterns/metrics。`evidence.json` 保存源素材的项目相对路径、内容 hash、引擎和模型版本以及结果 hash。

## 安全与权限

- renderer 只能提交 `projectId + asset origin + analysis options`。
- 主进程解析项目素材真实路径并验证仍在项目根下。
- 引擎 URL 规范化后必须是 loopback HTTP；禁止凭 DNS 结果放行公网地址。
- 外部推理默认关闭。开启时 UI 明示“媒体仍传给本机 e-cut；e-cut 可能把关键帧/文本发送到其配置的模型 API”。
- 关闭外部推理时请求本地确定性分析；若引擎不支持则明确失败，不静默改为外部调用。
- 重试复用同一分析 identity。提交回执未知时，Nomi 自动用 request ID 走 lookup-only 对账；查不到才继续保持未知状态，绝不再次 POST 视频。

## 执行切片

1. 契约与安全适配器：URL 守卫、health、提交、轮询、schema、持久化和恢复测试。
2. typed IPC/preload：start/list/read/cancel，renderer 无路径和结果写权限。
3. 任务中心投影：真实阶段、耗时、错误和恢复动作。
4. 拆解面板：删除旧面板实现，以唯一 `VideoDeconstructionPanel` 承载镜头切点、结构与证据；小于 1200px 时使用横向全宽布局，1200px 起停靠右侧。
5. 落画布：复用 `extractShotCutsToNodes`，附加结构注释并成组。
6. 设置：引擎状态、外部推理许可与缓存策略。
7. Electron fixture + light/dark 截图 + 断网/重启/恶意 URL/长 OCR/真实视频旅程。

## 最终实现事实

- 本地确定性模式只输出“证据段落”，角色显示为“证据”；它不能触发“沿用结构写新方案”，只能引导用户在设置中显式允许外部结构分析。
- 模型或人工编辑的语义结果才允许复用结构；生成给助手的草稿跟随当前语言，并明确禁止复制原片措辞、品牌、人物、镜头和视觉资产。
- “检查设置 / 配置结构分析”会打开“自动化与权限”并直接滚动到“视频拆解引擎”，用户立即看到引擎地址、密钥状态、外部推理和保留策略。
- “放到画布”以显式 project ID 抽帧，并在完成前强制持久化；刷新后节点仍保留 `analysisId`、时间范围和证据引用。
- 任务提交先持久化 intent；丢失回执或重启后自动通过 request ID 查询已接收任务，已验证全程只有一次 POST。
- 延迟媒体组件使用稳定媒体身份和安全 ref 生命周期；画布视频逐个加载到首帧可绘制后才显示，避免刷新后出现无错误的黑块。
- R16 使用真实 65 秒参考视频、真实 e-cut 服务与真实 Electron，覆盖在线、离线降级和丢回执重启三条旅程；最终为 38 项断言、13 张人工检查截图。

## 回滚

每个切片独立提交。关闭增强分析设置或移除适配器后，现有 `detectShotCuts`、抽帧、节点成组和视频生成链保持原样。不得保留第二个入口或隐藏 fallback。

## 验收门

- e-cut 在线：真实 65 秒 ChatCut 参考片从 Nomi 发起，阶段可见，结果可恢复，38 个确定性证据段落可核对；语义结构由显式允许外部推理的独立 fixture 验证。
- e-cut 离线：基本切点仍可用；结构页说明引擎不可达并给设置动作。
- 外部推理关闭：不发生外部模型调用，UI 不冒充已有结构结果。
- 重启：已提交任务继续轮询；`submission_unknown` 自动 lookup 对账但不自动重提。
- 安全：公网 URL、路径穿越、伪造完成结果和错误项目资产全部拒绝。
- 体验：全过程最多一个主动作，没有假百分比，没有绝对路径，没有卡住无反馈超过一个阶段周期。
- 全门：按 `check:filesize → check:tokens → check:i18n → lint:ci → typecheck → test → build` 顺序通过；生产 Electron R16 和人工截图对账通过。
