# F-A Step 1 生成失败归因与重试设计卡

PR #1635 修复任务 IPC 与 Run 读盘时丢失的失败类别，以及渲染器对已分类终态的三次执行放大。

| 格 | 决定与验收 |
|---|---|
| 0 先例 | 11-21 retry-one-home 将再次提交的资格交给主进程。现有 IPC 错误封包与 Run 的磁盘安全字段投影分别提供两条传递分类的边界。 |
| 1 目标 | 创作者在工作台或画布提交图片、视频或一批镜头后，看到一次执行的真实结果。恢复 Run 后仍能看到已经判定的失败类别。用 telemetry 矩阵量类别，用 Run 测试量读盘结果，用 failedAttemptIdentity 量执行次数。历史 Run 和事件已经丢失的类别无法补回。 |
| 2 主人 | 共享失败分类器解释已知证据，任务 IPC 和 Run 保存证据，主进程提交账本拥有媒体重派决定。入口清单见根因合同的 door-map。 |
| 3 数据流 | 适配器异常 → IPC 封包 → 遥测，或轮询终态 → Run 安全投影 → 读盘分类。画布执行器收到已分类终态即结束本次重试循环。 |
| 4 全状态 | 成功、进行中、取消和待取回按 Run 生命周期投影。已分类的失败保留类别，缺少证据的失败保留通用提示。用户可在主进程允许时发起新的提交意图。 |
| 5 打断 | 取消、结果未知和待取回归原 Run。停等、关窗、断网、重启和连点后的媒体重派资格由提交账本判定。 |
| 6 外部数据 | 校验使用替身供应商、真实异常类型、磁盘 Run 仓库和回环 HTTP。只投影安全类别和状态码。 |
| 7 性能 | 失败投影复用现有轮询和 IPC，画布每个已分类终态只执行一次。 |
| 8 真实条件 | 未验证真实付费生成或线上历史事件归因。现有本地证据见方向复盘。 |
| 9 验收 | IPC 裸异常及包装异常类别一致，工作台与画布遥测保留类别，两个 Run 引擎读盘保留配额和模型不可用分类。真实未知保留。单镜图片和视频各执行一次，九笔独立意图的用例从 27 次降为 9 次，两镜批次从 6 次降为 2 次。全部拦下会破坏新意图与可用参考链接用例。回滚用 Step 1 修复的反向提交。 |

出口：不涉及：已分类终态结束本次渲染器执行，用户仍按主进程的派发证据决定是否重试。

## F-A Step 2 · RW-2

`electron/productionRun/referenceLinkDispatchLedger.test.ts` 的回环服务模拟了过期 S3 预签名链接返回 `403 AccessDenied` 和 `application/xml`。将探针的 403 改为 `unknown` 后，带签名与不带签名的两个过期链接用例均跳过供应商私有 `uploadsTo`，直接向 `/v1/generate` 发请求。Step 1 恢复基线，保住私有重传路径。公共托管为 `deny` 时如何处理仅 Range 请求被拒的可用链接，归 `electron/catalog/assetLocalization.ts` 的 RW-2，待 #1586 用户热点签字。
