# F-A 生成可靠性修复设计卡

| 格 | 决定与验收 |
|---|---|
| 0 先例 | 0.24.1 的 reference-link-delivery 合同负责失效链接重传。11-13 出网裁决取消按本地 DNS 拒绝。11-21 retry-one-home 规定主进程决定再次提交的资格。三者分别约束有效输入、托管授权和执行次数。 |
| 1 目标 | 创作者用可读取的原件生成，不同入口都能收到已知失败原因。用 referenceLinkDelivery.matrix 的生成请求、脚本参数、冻结 URL、上传字节验证。用 taskIpcGuard 与两种 Run 的重新读取量类别，用 failedAttemptIdentity 数执行。旧 Run 已经丢失的类别不能还原。 |
| 2 主人 | 临时链接试探只报告当次读取事实；生成服务拥有输出；主进程账本拥有付费派发；任务 IPC 把证据交给共享分类器。 |
| 3 数据流 | 原件 → 免费试探 → 已有授权的传输 → 一次提交 → 观察终态 → Run / IPC → 低基数错误类别。 |
| 4 取舍 | 见方向复盘。新增分类猜测或全局禁发都会让可继续的一次创作失败。 |
| 5 打断 | 取消、结果未知、待取回归原 Run，旧事件没有必要重放。 |
| 6 花钱 | 本次只用内存与回环服务。确认过的服务商和第三方托管授权按原设置执行。 |
| 7 性能 | 探测次数由现有一次 Range GET 及缓存控制，失败投影不发网络请求。 |
| 8 可观察性 | 按错误类别、上游状态、失败阶段分别计数，区分事件、执行次数与实际 POST。 |
| 9 验收 | Range 被拒但当前原件能读，六扇门继续；明确不存在且公共托管关闭时零上传。已知类别在直接、包装与落盘读取后相同。真实未知保留，普通用户的新意图仍能发，确定未派发的媒体不得因 timeout 字样自动重跑。历史 557 / 27 的具体归因待生产证据。 |
