# 第九批夜跑走查现役契约同步（#1586 / #1121）

## 短版设计卡

- ★1 夜跑维护者需要从实窗结果判断用户操作是否成立。以原夜跑日志和同构建上的逐条 `node tests/ux/<name>.walk.mjs` 退出码核对 5–8 条由红转绿，以外部网闸日志核对供应商付费请求为零，以 `git status --porcelain` 和隔离实例登记、子进程扫描逐条验收退出。保留确认、拒绝、撤销、写入读回和超上限、低于下限警示等适用的业务结果判据。
- ★2 生产面板、文案、工具入口归 `src/workbench/ai/`、`src/i18n/`、`electron/agentLane/`，外壳走 `tests/ux/_shell.mjs`，隔离目录走 `scripts/_test-temp.mjs`。`door-map V4ToolReceipt` 枚举面板单条、收据组内部和设计实验室三处读入口；`door-map useStoryboardStrategy` 只找到分镜编辑器一个入口。另用全仓搜索核对 `PROCESS`、`openProcess`、分镜行警示、创作文稿和浏览器回执的其他走查消费者，保留共享契约。
- ★3 这次属于 recurring 的测试契约漂移。同类样本包括共用过程行的切形态与重试走查、共用临时目录门岗的时间轴与分镜走查。最早可拦步骤是生产契约变更时运行对应真窗消费者，现有静态门岗只检查目录和走查结构，缺少现役 UI 证明。本批复用共享入口并更新候选消费端；自写驱动会重复外壳契约，删掉走查会丢失用户结果证据。生产与门岗实现无需迁移，依赖生命周期不适用。
- ★4 只改候选走查和本卡。按 `launcherDirs.test.mjs` 维护登记边界，`check:test-temp-static` 核对临时目录，`check:walkthroughs` 和 `check:test-types` 查结构及类型。用户数据保留现役格式，使用脚本原有隔离种子及本机模型夹具。出现真实回归、已删除功能或无法确认语义时，恢复候选脚本并在本卡登记。
- ★9 每条原始失败和现役真窗结果配对，保留成功和失败两侧判据；拒绝全失败的「实现」还需通过真实成功结果落盘或读取，空执行还需通过实际操作后的界面变化及结果读回。变异 A 把用户行向下位移，检测器须抓到行碰撞；变异 B 暂时去掉思考预览的裁切，检测器须抓到正文越界，恢复裁切与展开完整过程后都须无碰撞。用两种语言跑思考重叠走查并打开截图核对。最后用 `checkDesignCard` 验短档五格，提交前核对在途路径清单和工作树。

## 系统改进

最早能拦下这类漂移的是变更契约时执行受影响的真实消费者。`.github/workflows/nightly-walkthroughs.yml` 已逐条执行，静态检查无法判断过程折叠是否遮住回执，也无法判断虚拟列表何时挂载一行。由现有 `openProcess`、现役行锚和仓外临时目录助手接住这些契约。以本次分镜拆条和同类旧案「切形态前回执隐藏」证明过期读法会失败，以时间轴原有的真实批准、落盘、撤销闭环证明对照行为通过。预测为这六条的上述失败签名在最新提交触发的后续夜跑归零，量具为逐条退出码与失败摘要，复查日 2026-11-26。
