# 设计卡：没验证过的连接和模型也能选、能发——验证只提醒，不拦

状态：动手前写的；★2 的行号由实现线读代码后补。一个 PR。
类别：四类（花钱——没验证的连接也会发出付费请求）。修复：用户 2026-11-13 定过「没验过的 key 也能用」，一直没落地；2026-11-16 两位创作者在群里撞到。
已复现（主分支和已发的 0.24.1，真窗口）：保存一个自接中转、不点验证，或验证失败 → 它的模型在「新建卡片默认模型」下拉和画布模型框里都不出现；同一个模型后来验证成功了，旧的失败提示仍并排挂着。

## ★0 先查别人

以下三条是调研线亲自打开原文记的，协调没亲眼看：
- Open WebUI 接兼容端点（https://docs.openwebui.com/getting-started/quick-start/connect-a-provider/starting-with-openai-compatible/ ）· 保存不验证；拉模型列表报错时仍可手填模型名并使用 · **确认了**：列表探测失败只说明探测失败，不说明不能用。
- Cherry Studio 模型服务设置（https://docs.cherry-studio-ai.com/pre-basic/settings/providers ）· 加了模型、启用了服务商就进选择器；「检查」是独立动作，文档还提醒检查用的模型可能不支持 · **确认了**：把「加入 / 启用」和「诊断」分开。
- LibreChat 自定义端点（https://www.librechat.ai/docs/configuration/librechat_yaml/object_structure/custom_endpoint ）· 模型清单可以直接声明，抓取失败回到声明的清单 · **确认了**：声明过的模型不依赖探测结果。
- 出口：Cherry Studio 模型服务设置（https://docs.cherry-studio-ai.com/pre-basic/settings/providers ） · 「检查」没过时服务商和模型照样留在列表里，人可以改配置再查，也可以直接用 · **确认了**我们的出口：每个连接、每个模型都能手动停用；密钥能删；验证随时可以重新点；真发出去被上游拒绝时，错误卡照现有分类指回模型设置。

## ★1 用户怎么用

当我接了一个中转或自己的 key、还没验证或者验证没过时，我想照样在模型框里选到它的模型并发出去，以便不被一个可能误判的检查挡住；同时我看得出它没验证过，出了错知道去哪。

步骤：①设置 → 模型，保存连接 → ②（可选）点验证；没点、没过都行 → ③它名下「有请求格式」的模型出现在默认模型下拉、画布模型框、助手选模型里 → ④设置里这一行标「未验证」 → ⑤发出去：成了，「未验证」自动消失；被上游拒了，照现有错误卡说明并指回这一行 → ⑥旧的失败提示在同一个模型后来成功或当前可用时自己退掉。

不做：不删「验证」这个动作（它仍能提前发现问题）；不改验证本身发什么请求；没有请求格式的模型（比如编不出调用方式的视频模型）照旧不能选，指到它唯一的配置入口；不在模型框里加「未验证」字样；不改接入流程的页面结构。
已知坑：以前「没验证 = 停用」是为了不出现「设置里说 28 个可用、实际一个都发不出去」（2026-09-01 的事故）。这次保住那条底线的办法换成：能不能用只看「有没有请求格式 + 有没有密钥」，这两样都是本机确定的事实；验证结果只当提示。

真实任务：
1. 自接一个兼容中转（本机回环假服务，模型列表正常），保存、不点验证：它的图片模型出现在默认模型下拉和画布模型框；选它生成，请求发到假服务，出图；设置里那一行的「未验证」消失。
2. 同上，点验证但假服务让验证失败（401 或超时）：模型照样可选可发；设置里标「未验证」（绿点，能用；列表行与连接详情徽标同一个词，同一函数取）；真发时假服务回 401 → 现有的鉴权错误卡，指回这一行。
3. 一个没有请求格式的视频模型：不出现在选择器；设置里写明缺什么、去哪配。
4. 同一个模型先验证失败、再验证成功：模型页不再并排挂旧失败。
5. 内置供应商（有 key、没验证）：照样可选可发，行为和今天一致或更宽，不更严。

指标与量具：
- 「有请求格式 + 有密钥」却选不到的模型数 = 0 · 量具：走查脚本读三个选择器的选项，对目录里的事实逐个核。
- 「设置里显示可用」却发不出去（本机就拦下）的模型数 = 0 · 量具：同一脚本对每个显示可用的模型取一次可执行模型，必须取得到。
- 过期失败提示数 = 0 · 量具：走查任务 4 的截图与读回。

### ★1b 连带界面

- 设置 → 模型：连接行、模型行、连接详情徽标的状态字（未验证 / 可使用；「验证没通过，仍可使用」「未通过」已删，协调 2026-11-17：401/403 改回拒收后剩下的没验成只有断网 / 超时 / 供应商出错，对创作者和没验证一样）；「N 个可使用 · M 个待设置」的计数——没验证但能用的算进「可使用」。
- 默认模型下拉、画布模型框、助手选模型：只是多出这些模型，不加字。
- 生成失败的错误卡：沿用现有鉴权 / 配置分类，不新增。
- 外部助手接入卡、手工认证的任务列表：按当前真相退掉过期失败。

### ★1c 老用户

- 升级后第一次打开，只做一次：①带待验证标记的连接和它的模型 → 可选可发，标「未验证」；②停用着、带验证失败记录、而且有请求格式的模型 → 启用，标「未验证」。
- 停用着、**没有**验证失败记录的模型（验证过之后自己关掉的、从没验过自己关掉的）：保持关着。
- 明着写的限制（实现线 11-17 用生产写口回放证实）：旧记录里「验证没过所以一直没启用」和「验证没过、自己手动开过又关掉」落成一模一样的一行，分不开。这种按第②条启用——依据是用户 11-13「拿不准的只提醒、让他发」：错开一个，下拉里多一项、能再关；错关一个，接上的模型继续选不到，就是群里那条反馈。这一次之后再手动关掉的，重启不会被再打开。
- 升级前已验证的：不变。
- 「只做一次」**不升目录版本号**（11-17 第二次裁定）：这次不改文件格式；实现线从已发的 0.24.1 安装包里查实，目录版本一升，旧版读到新文件会进只读（改不了模型设置），也不会自己去读升级前的留底。为一次数据修正把装回旧版的人锁成只读，不值。「做没做过」按这个顺序找地方记：①已有的「上次运行的版本号」之类的记录，判断这是升级后的第一次启动；②已有的一次性数据修正记录；③都没有，才加一个只增不改的标记，前提是 0.24.1 读得了、写得了带这个标记的文件。
- 退回上一版：0.24.1 照常打开、能改模型设置；它会按自己的旧规则把没验证的重新算成停用。再升回来时这次修正可能再做一遍（旧版写文件时可能丢掉标记）——明着接受。
- 验证用已发的 0.24.1 真实写出的资料目录：「保存没验证」「验证失败」「验证成功后手动停用」各一份。

## ★2 谁说了算

- 「能不能用」唯一的家：共享的可用性判定（`electron/shared/modelAvailability.ts`），三个选择器和三个首用发送入口（生成、文本、目录服务）都读它，不各判一份。改这一处和给它喂数据的发布判定，不在任何选择器里加特例。
- 验证结果归谁：凭据 / 模型记录上的验证状态，只用于显示和提示，不再进「能不能用」。
- 真实调用成功后清「未验证」：在共享的执行出口记一次，三个入口共用。
- 失败提示的显示规则归模型页那一处的可见性函数。
- 门数由实现线用 `node scripts/door-map.mjs` 重数并写进卡。

## ★3 一致与复用

- 以前定过：2026-09-10「未验证先不发布」（为了说可用就真能用）；2026-11-13 用户「没验过的 key 也能用」「拿不准的只提醒、让他发」。后者取代前者；前者要保的底线用 ★1 的第二个指标守住。
- 三条路：只提醒不拦（选这条）；只给内置供应商免验证（解决不了群里说的自接中转和残留失败提示）；整步删掉验证（会丢「缺请求格式」的提前诊断，视频模型没有请求格式本来就发不出去）。
- 复用：现有可用性判定、发布判定、错误分类、验证动作。不引库，不加新状态机。

## ★4 全状态

- 空（没有任何连接）：不变。
- 加载（验证进行中）：模型已可选；行上显示验证中。
- 成功（验证过 / 真发成功）：可使用，无标记。
- 失败（断网 / 超时 / 供应商出错，没验成）：可选可发，行上和详情徽标都写「未验证」（绿点），可重新验证。
- 部分成功（同一连接下有的模型有请求格式、有的没有）：各按各的。
- 取消中（验证点了取消）：回到未验证，可用。
- 过期（密钥被改）：新密钥按未验证，可用；旧的验证结果不沿用。供应商明确拒绝（401/403）的密钥不保存，原密钥保留（离线 / 超时 / 5xx / 付费探测被拒不算拒绝，仍按未验证可用）。
- 能力不可用（没有请求格式）：不可选；写明缺什么、去哪配。
- 最大值：一个连接 200 个模型、其中一半未验证——设置列表不卡、计数正确；最长的连接名用现有截断。

## 6 外部数据与失败

- 模型列表接口（`/models`、`/v1/models`）：各家返回形状不一、有的没有这个接口；失败只标「未验证」，不说 key 无效。
- 真实生成接口回 401 / 403：这才说「密钥被拒绝」，指回连接行。
- 回 404 / 模型不存在：说「这家没有这个模型」，不清「未验证」。
- 网络失败：按现有网络类错误，不清也不加标记。

## ★9 验收与回滚

应该通过：
1. 上面五条真实任务（中文、英文各一遍）。
2. 三个选择器（默认模型下拉、画布模型框、助手选模型）对同一批模型的结论一致。
3. 三个首用发送入口（生成、文本、目录服务）对未验证的连接都发得出去。
4. 三份真实旧资料：「保存没验证」「验证失败」的变可用并带各自的状态字；「验证成功后手动停用」的仍停用。升级后把一个带验证失败记录的模型手动关掉、重启：仍是关的。升级后的资料交回 0.24.1：能打开、能改模型设置，不是只读。
5. 设置里的计数与三个选择器里能选到的数量对得上。
6. 真发成功后「未验证」消失；真发 401 后出现鉴权错误卡、标记保留。
7. 改密钥后旧的验证结果不沿用。
8. 没有请求格式的模型在三个选择器里都不出现。

故意改坏必须报红（实现线交「反例 → 改坏后哪条检查红 → 还原后绿」表；验收线只按这张表和上面八条核，不另立判据）：
- 可用性判定重新把「未验证」算成不可用。
- 任何一个选择器自己加一条按验证状态的过滤。
- 首用发送入口在验证没成时抛错或返回「未配置」。
- 把没有请求格式的模型放进选择器。
- 升级时把没有验证失败记录的停用模型也启用。
- 迁移每次启动都跑（升级后手动关掉的又被打开）。
- 这次修正升了目录版本号（0.24.1 读升级后的目录变只读）。
- 迁移把没有请求格式的模型也启用。
- 真发成功后不清标记；或真发 401 后清了标记。
- 同一模型有更新的成功后仍显示旧失败。
- 设置里显示可用、但取不到可执行模型。
- 列表行或连接详情徽标自己另写一份「没验成」的词或点色（不经 unverifiedUsableStatus）→ `src/ui/onboarding/modelSettingsHome.test.ts` 的「one word」组红；旧词条放回 → `unverifiedUsableCopy.test.ts` 红。
- 401 的新密钥顶掉了旧密钥（把凭据探测的 invalid-key 当未验证存下）→ `electron/catalog/seedProbeRejection.test.ts` 的 401 / 403 / 首次接入 401 三条红。

这一类还会从哪里回来：新加一个选择器或发送入口时自己判一份「能不能用」；新的验证种类又被接进可用性；接入助手的会话卡另存一份失败状态。由「三个选择器 + 三个发送入口同读一处」的测试守。

真实场景复现：创作者接了一个中转没验证（或验证失败），到「新建卡片默认模型」里选不到它的模型，模型页一直挂着失败。复现办法：隔离的应用加本机回环的假中转，照同一条路走；修前判据——下拉里只有本地会员项（主分支和 0.24.1 都已看到）；修后判据——有请求格式的模型出现并能发出去。和用户那次的差别：没有他们的真实地址、key 和具体模型；他们遇到的视频模型如果本来就没有请求格式，修后仍不可选，但会写明缺什么。

回滚：一个 PR，`git revert` 合并提交即可；不改数据格式。
独立验收：另一条线按本格清单验，报告链接放 PR 正文。


## 实现的系统改进与一次性收据

最早应拦在验收的可用性一致性矩阵：旧矩阵把「没认证就不发布」当正确答案，只核投影一致，没有以保存后的请求格式和凭据事实核执行解析。现在同一真实目录逐模型走默认下拉、画布模式、助手角色与可执行解析；此例的 pending/failed、旧案 2026-09-01 的 UI 可用却解析不到和反面样本缺格式/用户停用一并覆盖。预测：本机事实齐全而任何一门拒绝的模型数为 0；复查日 2026-11-24，非零重开。

更新提醒 `electron/update/updateReminderStore.ts:21` 只有应用版本号，当前源码和已发版同为 0.24.1，无法标识本次源码修正。已有目录修正均靠格式版本，没有可复用的一次性修正账本。因此在目录顶层记录 `unverifiedUsableRecovered: true`，只增不改；不改模型行，不升目录版本；沿用迁移前版本留底，在 v13 首次修正前也保存原始字节，后续日常写入不覆盖这份留底。真实 0.24.1 编译模块的读写回放必须通过。降版仍可能按旧规则停用未验证模型，旧版若丢收据则再升级可能重做，此限制已接受。

凭据 pending 的一次性修正恢复连接和凭据；模型已被停用且没有失败证据时保持关闭，包括同一 pending 连接下的模型，避免用恢复连接覆盖手动停用。更换密钥在共享写口退役旧模型验证状态，保留执行声明。

真实回放发现重新验证会换候选连接 ID，旧失败与新成功的 vendorKey 不同。失败可见性投影操作账本已有的 sourceVendorKey 精确归属，不按共享内置 root 合并独立连接；外部助手卡按会话已有 childRunRef 找同一认证任务，删掉按名称和地址猜连接的路径。不同连接的同名模型不互相清失败，活动中的任务照常显示。旧归档缺少精确来源时保留失败，不猜连接；不暴露含密钥派生信息的 connectionFingerprint。
