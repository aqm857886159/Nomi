# 反馈通道收尾：旧件不丢、地址不出门、清单说实话

协调会话写，2026-11-02。反馈通道主 PR 独立验收提的五条，都不挡它合并，合并后一个小 PR 补完，随下一版发。

## ★1 用户怎么用

**场景一。** 断网时我攒了几份反馈，卡上说「已存在本机，之后自动重发」。恢复时队列文件刚好被占用，我又点了一次发送。旧的几份不能悄悄没了。

**场景二。** 我用自己的中转，生成失败时上游报错原话里带着我网关的地址。我点发送反馈，默认不勾附件。我网关的地址不该出门。

**场景三。** 我升级前有一份没发出去的反馈，那份是旧版组的包，带着网关地址和导入的工作流。升级后第一次启动补发时，这些不该出门。

**场景四。** 我接了第二条自己的中转，模型名是公司内部命名。发反馈前我读清单，清单说的要和真发的一致。

**不做什么：** 不改接收端、不改重发节奏、不改卡片布局。自建连接名下的模型名照带（判定在 ★9），只把句子写准。

### ★1c 老用户

队列文件格式不变。升级后第一次读到旧版排队的包，按旧形状处理（场景三）。读不出来的队列文件原样留着，不是删。

## ★2 谁说了算

- 队列读写：`electron/telemetry/intakeQueue.ts` 的 `readStore` 和它的读改写。
- 什么地址算自建：`electron/feedback/feedbackCatalog.ts` 现成的 `<custom-address>` 判定，摘要共用它，不另写一份。
- 摘要出门前的清洗：`electron/feedback/feedbackReport.ts` 的 `text()`（调用在组包处）。
- 清单文案：`src/i18n/locales/feedbackReport.ts`（zh/en）和写进包里的 `electron/feedback/feedbackReport.ts` 同一句，两处说法一致。

## ★3 一致与复用

不新增组件、不新增按钮。复用现有 `<custom-address>`、现有补发路径、现有「存不上」的提示。测试落在现有的整包回归 `electron/feedback/feedbackOutbound.test.ts`。单测底稿在 `验收线提供的只读 probe 目录`（`readfail.probe.test.ts`、`cells.probe.test.ts`、`criterion.probe.test.ts`、`host.probe.test.ts`），只读，抄进仓库时去掉本机路径。

## ★4 全状态

| 状态 | 结果 |
|---|---|
| 队列文件不存在 | 当空队列，照常写 |
| 队列文件 JSON 坏了 | 挪到一边留底，从空开始（现状行为加留底） |
| 队列文件这一刻读不了（占用、权限） | 这次读改写放弃写盘，文件原样不动；调用方拿到失败，走现有「存不上」的路，不显示「已存在本机」 |
| 摘要里有内置 host | 留着 |
| 摘要里有不认识的 host | 换成 `<custom-address>` |
| 旧形状的排队包 | 去掉目录附件再发，其余照发，日志记一行 |
| 新形状的排队包 | 不变 |

## ★9 验收与回滚

### 实现范围

1. **队列读失败不清旧件。** 按 ★4 三种情况分开。
2. **宿主定时器单测。** 给 `FeedbackShareHost` 补一条，改掉 `clearTimeout` 必红。
3. **摘要 host。** `text()` 走目录那套判定。`electron/feedback/feedbackReport.test.ts:82` 起那条的夹具已经是私有中转，补上「host 没了」的断言。整包回归种这一格。用户自己写的留言不动，那是用户自己写的话。
4. **旧形状包。** 补发前去掉目录附件。先确认新旧包能靠字段分开；分不开就停，写进报告，不猜。把 `docs/plan/2026-11-01-feedback-delivery.md:64` 那句「那一版的清单就是这么写的」改成实话：旧清单写的是「模型目录（密钥、代理地址、自定义头全部抹掉）」，没有说地址和工作流会带。
5. **清单那句（协调已判定）。** 不改行为，只改句子。兄弟连接 `<内置 root>--<连接名>` 带自己网关、或内置 root 被改成自己网关时，名下模型名照带：查模型配置要靠它，地址、连接名、密钥不带。中文改成「自建连接不带地址、连接名和密钥；模型名会带，用来查模型配置」，英文同义，`src/i18n/locales/feedbackReport.ts:29` 和 `electron/feedback/feedbackReport.ts:227` 两处。整包回归种这一格：地址、连接名、密钥零命中，模型名在。
