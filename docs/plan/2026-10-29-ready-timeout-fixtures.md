# 就绪后验证超时的门岗自测

类别：其他（仅测试与共享测试助手）。

## ★0 先查别人

- [后代终止用例源码](https://github.com/sindresorhus/execa/blob/main/test/terminate/kill-descendants.js) · 先取得后代 PID 并断言活着，终止后再等 PID 消失 · 确认存活前提与退出检查必须成对，不能缺 PID 就跳过。
- [短超时用例源码](https://github.com/sindresorhus/execa/blob/main/test/terminate/timeout.js) · 极短预算只断言超时状态，不读子进程副作用 · 确认同步重试策略和进程启动/终止证据要分层。
- [运行时短超时用例源码](https://github.com/nodejs/node/blob/main/test/parallel/test-child-process-fork-timeout-kill-signal.js) · 只断言信号和监听器注销，不假设用户代码已经执行 · 确认保持生产启动即计时，只在测试控制时钟。

## ★1 任务与指标

当开发者运行推送前门岗时，自测应验证真正的超时终止，同时不把运行时启动延迟判成产品失败。流程：创建隔离夹具 → 可注入写 PID 前同步延迟 → 启动生产 runner → 等子孙各自写 PID → 确认两者存活 → 推进测试期限 → 确认两者消失 → 核对软超时与真红。任务：相关单测软超时；同步只读重试后成功；同步只读重试耗尽。量具：目标 node:test、临时重复脚本记录墙钟；目标为注入20/20绿、空闲20/20绿、空闲中位数增量≤1000ms、只杀直接子进程变异必红。界面及连带界面：不适用。

## ★2 状态归属

测试助手拥有夹具就绪及退出证据，测试时钟由 node:test mock.timers 管理；生产 runner 继续拥有真实期限及整树终止。同步策略的系统命令边界用已观察到的超时结果隔离；实际超时执行与重试策略分层，原有真命令成功/404覆盖保留。数门：`node scripts/door-map.mjs runNode runRelatedTests execGhReadSync --roots=scripts --include-tests`。

## ★3 复用

复用 `_test-temp.mjs`、Node mock.timers、现有 `runNode` 和进程树终止边界；沿用 processTree.node-test / _test-temp.node-test 的条件就绪写法。统一共享测试助手提供夹具、延迟、PID有效性、存活及消失检查。删掉原来的三个短期限后读取子进程副作用的组合夹具。生产文件不新增测试回调，不新增门岗。

## ★4 状态

准备中：真实时钟有界等PID；成功：有效且存活的子孙都被期限终止；失败：未就绪、非法PID、提前结束、未超时或存活残留均红；失败收尾：只按本轮记录的PID清理。无界面，空/取消/过期/能力不可用不适用。不吞缺失文件，不跳过终止断言。

## ★9 验收与反例（实施前）

- 修前注入2000ms：目标用例5次均ENOENT；空闲基线20次。
- 修后注入2000ms：目标用例20次；不注入空闲20次；逐次退出0且无skip，中位数增量≤1000ms。
- 两条同步重试用例分别以共享真实超时树建立前提；注入/不注入分别重复（至少各3次），每次均检查超时前子孙活、超时后都死；重试次数、预算、错误消息与成功结果继续断言。
- 反例：生产整树终止临时变为只杀直接子进程，三条用例都应红；恢复后再跑，变异不提交。
- 真红夹具仍在正常预算内返回失败并拦截。
- 全文件node:test、根因合同检查、fix-churn --staged、pnpm run gates、推送前快检。
- 无新界面/花钱/长跑产品行为；独立验收不适用。回滚为撤回本次本地修复提交；未推送。
