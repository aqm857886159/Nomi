# M4 方向检查：零余额、公开估价和充值动作

独立复盘线 V-model-surface-balance，故障基线 bed56f45e。11 月 8 日用户明确回复「采用推荐规则」：画布中已显示充值的按钮，快照过期时此次点击只刷新，生成次数必须为零；账户仍有余额时公开估价短差仅提示。修后验收与合并授权另记。

## 触发与旧决定

fix-churn 报 NodeGenerationComposer.tsx 近 14 天有两次 fix。11 月 2 日的 3797fde0c 修生成拒绝后的重发，adbe5b6f7 修项目归属及预检错误。上一份[生成锁复盘](../plan/2026-11-02-generation-lock-exit.direction-check.md)处理运行归属。本次碰同一文件，讨论发送键动作由哪些事实决定。

[拍板图](../design/boards/2026-11-07-model-surfaces/ModelSurfaces.board.json)中 cost.send-pill 和 cost.hover 使用公开估价，cost.low-balance 引导充值，cost.provenance 才展示生成回执。[本次设计卡](../plan/2026-11-08-model-surface-implementation.md)进一步规定会员价可能更低，非零余额低于公开估价仍能走原批准；未知保留未知。

## 复现与类根因

| bed56f45e 上的输入 | 实际结果 | 问题归类 |
| --- | --- | --- |
| 有效 Key，新近确认可用额度 0，公开正价同为 0.34776 积分 | 固定价显示充值；改为只估输出 token 后显示生成 | 差额的计算条件意外决定了能否看到零余额 |
| 显示「去充值」的同一按钮，点击发生在快照第 29,999 毫秒 | 打开充值页 | 与可见动作相符 |
| 同一按钮没有重新渲染，点击发生在第 30,000 或 30,001 毫秒 | 调用 handleGenerate，接着可进入 startGenerationFromComposer | 时钟改变了用户刚刚点的动作 |

复现用 TypeScript 从基线文件提取 shortfall、zeroBalance 与 JSX onClick 原表达式，在隔离进程用可控时钟和记录回调执行；无网络、生成或扣费。旧 Mac 免费真窗覆盖中英视频固定估价和零余额，未覆盖按输出估价或过期点击。缺失的不变量是账户资金的确定程度、价格的确定程度、按钮将做什么这三件事，各自需要不同的依据。

## 三条路与建议

| 做法 | 能保住什么 | 代价与风险 |
| --- | --- | --- |
| 在组件差额公式里给输出估价加特例 | 修眼前的图片例子 | 新计价方式还会漏，过期充值点击仍可能启动生成 |
| **用共享的资金/估价状态给按钮选择动作** | 新近有效的 0 由账户或有限 Key 决定；可以计算的短差只作提示；充值动作绝无进入生成的出口 | 需要覆盖未知和过期，避免由公开价推断真实余额不足 |
| 删掉充值态，只保留原发送按钮 | 能保持原审批权限 | 已知零余额仍让创作者送出失败请求，丢失拍板图的充值入口 |

已采用第二条。沿用已有主进程账户与报价、GET、有效期、批准入口和 React 按钮。连接、Key 类型与会员价格由供应商事实决定，通用账务库没有这份连接状态或按镜头的付款语义，无需新支付依赖。保留旧项目字段和任务。规则只用于画布，批量和 Agent 的实际提交继续走既有 Run/授权体系。未知报价容许原批准，余额来源不明或过期不用于禁止生成。已显示「充值」的按钮在快照仍有效时打开账单；过期时这一次只刷新。生成需要界面重新显示「生成」后由创作者再点。

## 特征测试与范围

- 新近有效、正价已知、账户或有限 Key 任一为 0，固定价和仅估输出均显示充值。无限 Key 的数值槽不构成限制。非零且低于固定公开价只提示差额；按 token 输出估价不计算确定差额。
- 缺报价、读失败、过期、不同连接、待确认参考/运行中、旧项目保留原行为。成功读回非零时不用重填草稿。两笔异步返回不许把另一连接或旧参数套到当前按钮。
- 用同一次渲染跨越 30 秒再点充值，记录充值、刷新、生成入口调用次数，生成次数必须为 0；点击明确的生成才走原批准。付费行为不靠真扣款做确定性测试。
- door-map：NodeGenerationComposer 经 BaseGenerationNode 和 LazyNodeGenerationComposer 挂载；useNodePricePreview 只有该组件一个读者；useVendorAccountFacts 有设置账户卡和该组件两个读者。两种主进程读数各只有 onboarding IPC 一个入口。设置页照实显示账户，实际任务回执独立于两种读数。不能将画布余额提示推广成全局硬闸。
- 独立尺子是明确可见的按钮动作、调用轨迹及实际输入。历史样张的 0.35 / 0.32 是排版示例，无相应账单时不报告估价误差。发布仍由最终目标头上的走查、门岗及真实资源确认。

## 本轮拍板

2026-11-08 协调会话记录用户选择「采用推荐规则」。仅限画布：刚查实账户或有限 Key 的可用额度为零，且任务有正的固定估价或输出估价时，发送位置显示去充值。该按钮点击时若数据过期只刷新，本次不进入生成；非零额度低于公开估价仅提示，仍保留原发送与授权。输出估价按 token 回执结算，不由它推断精确差额。
