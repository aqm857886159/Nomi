## 第 0 步：有没有家（设计系统 §1.0）

- **技能的家 = 技能库**（左栏和页签叫「Skill」，10-08 拍板）：给 Nomi 的「方法」。内置 49 个（创作流程 10、导演 13、编剧 11、广告 8、角色与场景 7）+ 我导入或用 AI 写的。唯一主动作「放进对话」（就是现在的「引用到 Agent」，行为不变）。
- **提示词的家 = 提示词库**：放进节点提示词框的那段话。我的 + 内置（表情预设 25、效果 44）+ 公开库（5 个公开仓库，打包快照各 30 条，在线更多）。唯一主动作「放上画布」（新建节点）。
- **效果**（`skills/effect-*` 里 `kind: effect` 的 44 个 SKILL.md）住哪是这次唯一的产品题（Q1）。推荐住提示词库：它的用法是「填进这个节点」，和提示词是同一件事；节点「提示词预设」弹层、空节点推荐、图片浮条快捷动作本来就读提示词库。数据仍是 SKILL.md，不动；现在主进程 `electron/promptLibrary/curatedPrompts.ts` 已经是效果离开技能目录的唯一出口。
- **别处只指过去**：Agent「/」弹层、节点「提示词预设」弹层、空节点 4 个推荐效果、图片浮条快捷动作、创作区 AI 改写条里的我的技能。读同一份数据，长得和家里一样，点一下 = 用；要改去家里改，或跟 Nomi 说一句。

## ★1 用户怎么用

- 一句话：当我在做一个视频、想让 Nomi 按某个方法干活，或想给某个镜头找一个起点 / 一种效果时，我想在几秒内找到它并用上，以便不必自己写一大段话。
- 步骤（提示词，5 步）：开左栏「提示词」→ 在分类里点「运镜」（或直接搜）→ 看封面挑一张 → 点开详情看全文 → 「放上画布」（新建节点，带参考图）。往已有节点里加：在节点生成框里点「提示词预设」挑。
- 步骤（技能，5 步）：开左栏「Skill」→ 在分类里点「导演」→ 看名字和两行简介挑 → 点开详情读方法 → 「放进对话」，然后跟 Nomi 说要做什么。
- 不做什么：不加新功能（拖卡片、右键、卡上复制、悬停播放、提示词导入导出、库里改 SKILL.md 都不加）；不改数据和导入导出。
- 已知坑：公开库示例媒体在国内网络下可能打不开（现有失效占位照旧）；用户自己导入的外部技能没有封面和中英文名；英文界面里部分分组名、来源名只有中文（另修）。
- 真实任务（不是合成夹具）：
  1. 「雨夜来信」项目里给第 3 镜（怀表落在积水里）找一个运镜：提示词库 → 运镜 → 推轨跟拍 → 放上画布。
  2. 用「剧本审查」检查一份剧本：技能库 → 编剧 → 剧本审查 → 放进对话 →「帮我审一下这份剧本」。
  3. 把同事发来的技能文件夹拖进 Skill 抽屉，在「我的」里找到它，放进对话。
- 指标（目标 → 信号 → 指标；每个都点名量具）：
  - 主指标：找到并用上一个库里条目的步数与时间。量具：未验证——缺量具（实现时在走查 `tests/ux/skill-library-cards.walk.mjs` 一类脚本里加「从打开库到放上画布 / 放进对话」的计时和步数）。目标：上面两条路径都 ≤5 步。
  - 质量指标：首屏能看到真实内容的组数占比（首屏露出卡片的组 / 首屏可见的组）。量具：同上走查里数 DOM。基线：现状技能页签首屏 9 组里 1 组露卡（≈11%）；目标 100%。
  - 护栏指标：打开库时的媒体请求数 / 首屏可见卡片数（★7）。量具：★7 的新场景。基线：61 / 8；目标 ≤ 1 + 一屏预取。
- 新界面 brief：一个库只装一类东西；分类有名字、常驻可见；卡片只负责被看见，动作在详情里。新手人设：第一次打开，想知道「这里有什么」→ 首页每组露一行；老手人设：知道要哪一类 → 左侧分类一点即全摊、或直接搜。每步「预期 → 实际」用走查截图对。

## ★2 谁说了算
