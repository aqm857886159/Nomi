# 方向检查：视图切换后的输入与素材删除

## 0. 一句话根因

共享 store 没有收齐操作的前置条件：视图各自决定谁能接输入，文件删除也存在绕过领域引用保护的捷径。

## 1. 归类表

| 症状 | 直接原因 | 类 |
|---|---|---|
| 列表 Delete / 撤销触碰隐藏画布 | offsetParent 把 invisible + inert 当成可见 | 缺显式交互宿主合同 |
| 托盘删除破坏画布和时间轴媒体 | 直接调用文件回收 IPC，没走素材删除规划 | 同意图的命令分叉 |

用户原话：「另一个使用反馈 关于我们的画布的列表模式 对于文本框而言 是没法做编辑的 所以画布的列表模式和画布模式 对于同一个文本节点而言 操作不一致 这个是需要仔细查的 而且类似的不一致问题也一直发生 这个我们在架构地基那里也看到了类似的错误 这部分需要修复 同时也需要重新查一下有没有类似的问题没有被找到和发现 重新处理」。方向拍板原话：「按三刀修」。

## 2. 为什么持续出现

共享写口只统一最终数据，没有统一交互权限、引用与撤销前置。⑫「点了=以为的」适用；⑩、⑪的生成参数合同不在本刀范围。结账挂隐藏面输入矩阵、素材删除边界反例及真实双语走查，不靠文字规则。

## 3. 可验证预测

| 预测 | 验证 |
|---|---|
| 不止 Delete，隐藏画布也响应撤销/复制/粘贴等 | 每个隐藏形状 × 快捷键矩阵 |
| 切过预览后隐藏时间轴也可能抢键 | 预览/生成时间轴分别测试 |
| 托盘的白板图层引用也会悬空 | 用现有 planAssetDeletion 的图层夹具跨入口对照 |

## 4. 靶子独立性

本线写回归；独立验收待协调派线。本机已用真实鼠标/键盘复现列表删节点、列表撤画布副本；真实托盘删除后原 URL 返回 404，重载画布出现加载失败、时间轴缩略图损坏。已纠正两种探针错误：普通 asset URL 不接受 query；同文档 Image 可复用已加载资源，不能把它当成新磁盘请求。

## 5. P0

输入事件使用 DOM 原生事件，异步转交复用现有 rendererBridge（绑定收件人及超时），删除复用 planAssetDeletion / deleteAssetResult / 撤销日志。领域约束是 Nomi 的画布/列表/时间轴宿主与版本引用，不自造通用 RPC、事件总线或回收站实现，不装包。

## 6. 选择与删除清单

| 选项 | 代价与风险 | 结论 |
|---|---|---|
| 继续补 CSS 可见性判断 | 每种新藏法还会漏 | 不选 |
| 由宿主 active 显式投影输入权 | 需要所有 window 输入消费者守同一边界 | 本刀采用 |
| 托盘独立复制引用扫描 | 独立窗口读到空/过期 store | 不选 |
| 转交主窗口现有删除命令 | 需要固定项目绑定、复用现有请求桥 | 本刀采用 |

删：offsetParent/isShown 判据、托盘直接回收文件路径、pending 与领域命令内重复桥调用（合为一个文件回收模块）。不删选区；不改布局；不新增提示组件。

三刀：本刀只处理输入权限和删除引用保护；下一刀节点能力合同与列表正文/音频/点选往返/主版本；第三刀其它视图的生成对等门岗。后两刀不在本变更实现。

## 7. 核心权衡

保留常驻画布和选区，同时把输入权交给此刻在前的宿主；删除沿用已有保护语义，不能为了托盘上的“删掉了”破坏作品引用。

## 特征测试

修前真窗证据存于本线隔离报告；产品修改前补输入矩阵与文件桥边界反例。没有使用合成测试替代真窗复现。
