## 0. 一句话根因

这批界面的样张、实现、验收**都只在「正常摆位、正常网络、有模型」这一个点上验过**：浮层定位允许「拿按钮位置冒充点位」、实验室只摆中间、走查绕过按钮直接调函数、设计卡没有「能力不可用」这一格——三个问题是同一个缺口在三处露出来：**边界态没有登记处，所以没有检查会去看它**。

## 1. 归类表

| 问题 | 直接原因 | 类 |
|---|---|---|
| 「改图 ▾」菜单压住浮条、盖住「宫格」（节点靠画布上沿） | `ToolbarActionMenu` 把菜单贴在「按钮上沿往上 6px」那个**点**上再 `side="top"`；头顶放不下时 Radix 翻边，翻的是 0×0 的点，菜单上沿落在按钮上方 | 浮层定位：锚点用点不用矩形，翻边会跨过触发钮（同类还有分镜表锚点行「⋯」，按钮下沿 +4px 当点） |
| 「多机位九宫格 ｜ ▾」中间有竖线，和「宫格 ▾」不一样 | 10-05 样张拍板时就画了 1px 竖线；浮条上的下拉有三种写法（菜单、自拼点阵、调用方手画分体） | 同一件事多份写法，外观和行为各漂各的 |

| 本轮自己带出的回归（CI Unit）：浮层里打开子下拉、页面滚动后锚点出窗，新放置把浮层算到窗口外 | 放置函数改写时漏了旧版最后一步「夹回窗口」；量高用了外壳 scrollHeight（会被浮层里绝对定位的子下拉撑高） | 同上一类：浮层不变量只写了「不压锚点」，没写「锚点看不见时仍在窗口里」——已补进放置函数与单测 |

## 4. 靶子独立性

- 弹层几何普查（`tests/ux/design-lab/popupGeometry.mjs`）只认 DOM 几何 + `aria-haspopup / aria-expanded` + `[role=toolbar]`，不认组件名，不是实现线自己写的判据复读；变异：把锚点改回「点」，3 格当场红。
- 抠图走查改成**点按钮**，断言落盘的 PNG 角 α≈0、主体 α≈255，而不是「函数返回了一个 blob」。

## 5. P0：独有的吗？现成方案

- 菜单 / 浮层定位：不是独有。行为全走 Radix（`@radix-ui/react-dropdown-menu`，用它的翻边 + `--radix-dropdown-menu-content-available-height`）；我们只补「锚点是哪块矩形」这一条领域约束（浮条那一排是触发钮的一部分）。`AnchoredPopover` 的几何是已登记的自写件，本次只改不变量，不加新件。
- 抠图：继续用 `@imgly/background-removal` 1.7.0，只改 `publicPath`（官方配置项）指向自己的镜像；下载进度 / 卡住判定是包一层 `fetch`，不改第三方。
- 高清：不自写放大；接中转里现成的放大模型（kie 的 Topaz Image Upscale、Recraft Crisp Upscale），见 C 设计卡。
- 自写登记 `gate-family`（门岗族，评估中）：本次只动 `scripts/check-file-sizes.mjs` 一行基线（`BaseGenerationNode.tsx` 557 → 555，门岗自己要求「瘦身后下调以锁定」），不加新门岗逻辑；弹层几何普查放在 `tests/ux/design-lab/`（走查工具，不是门岗脚本），判据只认 DOM 几何。为什么现在不换现成方案：文件体积棘轮的替代（如 ESLint `max-lines` 加基线）要整族一起评估，那是 `gate-family` 那张登记的事，不在这一刀里换；哪天换跟那张登记的评估结论走。

## 7. 用户要权衡的核心

抠图模型放哪儿（已拍板：放自己的 R2 镜像，包体不变、国内更稳，代价是升级 @imgly 时要先同步镜像）；高清是「引导去添加放大模型」还是「随包带本地放大」（C 设计卡给推荐）。
