## 短版设计卡

- ★1 用户怎么用　创作者打开项目，按原旅程选入口，执行素材盒、分镜计划、视频派生或场景资产操作，查看结果并从记录或第二个界面读回。夜跑维护者要能区分脚本过期和产品故障。主指标由同名 `.walk.mjs` 的夜跑日志和隔离窗口退出码测量，入选脚本各有 FAIL → PASS。质量指标由脚本中的热区、授权前请求数、成片文件及节点/引用断言测量，仍应拦下各自关键动作的失败。护栏由 `git status --porcelain`、本次测试进程树、`check:test-temp-static` 和 `launcherDirs.test.mjs` 测量，仓内污染与残留进程为零。真实素材任务包括 1080p 直剪，真人镜头深度提取用于候选排查。Agent 任务使用回环供应商并检查请求数。涉及入口、通知和回执的现役表现以生产面读回。老数据升级判据不适用，本批只改走查。
- ★2 谁说了算　用 `node scripts/door-map.mjs` 和 `rg` 查入口与消费者。`ShellTopBar` 有四个读入口，内置浏览器工具条拥有素材盒开关，主进程拥有浮层窗口。`StoryboardAnchorZone` 有五个读入口，生产调用在 `StoryboardPlanEditor`。`ProductionRunTaskCard` 的唯一生产调用在 `TaskCenterPanel`。画布节点、生成栏和持久态分别沿画布生产组件及项目 API 取证，导演台脚本沿 `_directorLab.mjs` 的真实渲染面取证。脚本到点失败，产品状态仍归各生产 owner。门岗判据以 `launcherDirs.json`、`_test-temp.mjs` 和夜跑树守卫为准。
- ★3 一致与复用　归类为 `recurring` 测试契约漂移。最早可发现的位置是生产入口变更后的走查重跑。夜跑能抓到行为差异，旧探针留在已变更入口内时仍需更新消费者。沿现有旅程改读真实入口、结果身份及落定信号，复用 `_shell.mjs`、现有 Playwright 等待和 `makeTempDir`。新增共用探针会扩大本批改动，删掉旅程会丢失覆盖。以 `git log`、现役代码与夜跑日志核对历史决策。生产代码修复合同不适用于这批测试消费者。
- ★4 全状态　空态从隔离资料起步。加载等本次操作信号。成功核对资产或落盘结果。失败打印现有异常和截图。部分通过保留分项。取消等原有回收或保留语义。过期对照旧结果的身份。模型或硬件不可用时记未验证，重跑需要满足原旅程资源条件。量具是同名走查日志和截图。拍板图流程不适用，界面没有改动。
- ★9 验收与回滚　隔离窗口串行跑，每次查退出码、工作树及应用进程。用夜跑同名日志记录红灯，用本地真实渲染窗口记录绿灯。反例一，保留遮挡参考区的失败提示直接点击展开，应当在进入参考行前失败。反例二，选定 1080p 素材后不执行直剪，新增结果 ID 与成功断言必须报红。反例三，草稿无任何持久化结果或提前触发生图，草稿身份及请求数断言必须报红。保留真实缺陷和退役功能的原脚本。提交后逐道跑任务指定的七项门岗，核对提交与在途路径；回退使用本批提交的 `git revert`。
