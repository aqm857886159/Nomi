> 核心场景（用户原话）：**拖入一个对标视频 → 用自己的商品图 → 描述改一改 → 生成复刻视频做广告用。**

---

## 0. 一句话

把「按镜头拆」（已有，纯 ffmpeg 找切点）升级成**看得懂内容**的拆解：切镜 + 多帧读图 + 口播转写 → 落成一张**可编辑、可自己长列**的分镜表；而这张表**不是新造的数据结构，是「拆自 xxx.mp4」那一组镜头节点的另一种看法**。

---

## 1. 为什么这么拍（三条底层判断）

### 1.1 表格不是新节点，是节点组的视图

画布上**没有任何表格类节点**（15 种 kind 全是单值卡片，`nodes/registry.ts:57-259`）。造一个「表格节点」= 新开一套平行数据模型，违反 P1。

而「按镜头拆」**本来就会自动成组**（`extractShotCutsToNodes.ts:74-79` 调 `createGroup`），镜头节点**本来就有**参考槽、模型选择、参数条、单节点生成按钮、变体、历史、provenance。

所以：**一行 = 一个镜头节点，单元格 = 该节点的字段**。表格只是换个布局渲染，不换数据。这样「落画布」这一步直接消失——它本来就在画布上。

### 1.2 原片帧必须和参考图分开

复刻广告的本质是：**原片那一帧恰恰是你不想要的**。把原帧默认填进参考槽 → 模型照着原片主体生成 → 出来是原片翻版，且拿他人成片帧当生成参考版权上站不住。

故拆分成两个位置：**原片帧 = 只读对照**（不参与生成）＋ **参考图 = 你自己放的**（喂模型）。中间给一键「用作参考」，默认关。

### 1.3 自定义列要能影响出片，否则只是电子表格

列有两种：**给人看的**（景别/情绪/对白）和**喂模型的**（提示词/参考）。用户要的「自由发挥空间」，只有落到第二类才有价值。

故自定义列带两个开关：
- **「让 AI 拆解时填」** → 列的说明**动态拼进 VLM 的输出 schema**，AI 就会专门去看这个维度（derive 不 hardcode）
- **「参与生成」** → 值拼进该镜提示词

这让表格从「填表」变成**给 AI 下指令的界面**。也让「要不要内置场景列/角色图列/深度列」这类问题一次性消失——不用猜，用户自己长。

## 2. 实测契约（真实调用得来，2026-08-12/13）

### 2.1 画面理解：`gemini-3.5-flash`（apimart，OpenAI 兼容 chat）

| 项 | 实测 |
|---|---|
| 单镜分镜提取 | 1178 token 进（**图片占 1058**）/ 1160 出 / **10.4s** |
| 密集中文小字 OCR | 表头 14 列**全中 14/14**；下载弹窗读出「我在盛唐写天下.csv 21.1 KB · 完成」一字不差 |
| 分辨率 | 1280px 与 2114px **image_tokens 都是 1058** —— 服务端统一降采样，**传大图既不多花钱也不更清晰** |
| 多帧 | 3 帧 = 3174 image token（线性），**11.1s（比单帧 8.8s 只慢 26%）** |
| 时序判断 | 跨帧可用：准确指出「创意视图只在第 1 帧」「下载弹窗只在第 3 帧」 |

**推论**：① 不需要单独接 OCR 引擎；② **单帧会漏掉「出现又消失」的字幕/角标/价格**，必须多帧；③ 多帧 token 线性涨但墙钟几乎不涨（瓶颈在思考不在传图）→ **默认 3 帧/镜**。

⚠️ 它是**思考型模型**：回「可用」两字就烧 47 completion_tokens。maxTokens 给小 → 正文空 + `finishReason='length'`，看着像模型不行其实是自己截断。

### 2.2 口播转写：`whisper-1`（apimart，**已接好**，勿加第二家）

| 项 | 实测 |
|---|---|
| 速度 | 82 秒音频 **7.3s** 转完（11× 实时） |
| 时间戳 | **35 条 segment，每条带 start/end** ✓ |
| 中文准确率 | 目测 95%+，专业词基本全中 |
| 代码状态 | `audioTaskRunner.runTranscribe` 已请求 `verbose_json`，**整个 json 原样存进 `raw`**，segments 没被丢 |

**唯一缺口：全仓没有「视频 → 音轨」的代码路径**（`grep -rn "extractAudio\|-vn "` 零命中）。实测 `ffmpeg -vn -ac 1 -ar 16000 -b:a 64k` 把 82 秒视频出成 644 KB mp3 可直接喂。ffmpeg 已打包（`@ffmpeg-installer`）。

### 2.3 参考槽是模型声明的，不是固定的

`seedance25Apimart.ts` 实证：同一模型不同模式槽位完全不同——
- `t2v`：`slots: []`（一个都没有）
- `first`：`first_frame` ×1
- `omni`（全能参考）：`image_ref` 0–30 ＋ `video_ref` 0–10 ＋ `audio_ref` 0–10

故**参考列必须跟着当前模型/模式的槽位声明渲染**，不能画死。好消息：参考值**跨模式持久**，只在传输时按当前 mode 投影（`buildArchetypeInputParams`），换模型不丢数据。

### 2.4 已否决：本地化

| 组件 | 体积 |
|---|---|
| Qwen3-VL-4B GGUF Q4_K_M | **2.5 GB** + mmproj 454–836 MB |
| whisper.cpp large-v3-turbo | ~1.5 GB |
| macOS Vision OCR | 0 MB（但**边际价值低**：VLM 读帧时已顺手读字，OCR 从不是独立一步）|

Nomi 现 576 MB → 全本地 3.5 GB+。加上 native 二进制的签名/公证风险（记忆 `electron-xprotect-false-positive-resign` 已踩过）、三平台自建构建、硬件差异导致体验不可预测、以及**本地 4B 识别质量打不过 gemini（拆解价值全建立在读得准上）** —— 用户 2026-08-13 拍板：**不做本地化**。

## 3. 范围

### 3.1 做（分三批）

**批 1 · 拆解管线（无 UI，可独立验收）**
1. `electron/video/extractAudioTrack.ts` —— 视频 → 单声道 16k mp3（新，唯一的 ffmpeg 新增）
2. `electron/video/deconstructVideo.ts` —— 编排：复用 `detectShotCuts` 找切点 → 每镜按首/中/尾抽 3 帧 → 并发喂 `image_to_prompt`（gemini-3.5-flash）→ 同时跑 whisper → **按时间戳把 segment 归属到镜头**
3. 归属规则（**必须定死，否则整列串行**）：句子按**起始时间**归属所在镜头；跨镜长句不切分，整句归起始镜，并在结束镜标注「承接上镜」

**批 2 · 分镜表视图（用户可见，对样张 v4 验收）**
4. 表格视图组件：一行一节点；内置列 = 镜号｜原片帧(只读)｜时长｜景别｜情绪｜画面描述｜对白｜参考｜画面提示词｜生成
5. 参考列按当前模型槽位声明渲染（多类型：图/视频/音频，带容量 n/max），点加号复用现成 `AssetPicker`
6. 原片帧「用作参考」一键升级
7. 主体锚条：一键换商品图（复用 `PlanAnchor`，改一处全镜跟着换）
8. 逐行生成（→ `confirmAndRunNode`）＋ 批量（→ `run_generation_batch`）＋ 重新生成
9. 创意视图（卡片态，每镜一张分镜图）＋ 双视图切换
10. 导出表格（CSV，自定义列一并带出）

**批 3 · 自定义列**
11. 加/删/改列；两个开关（AI 填 / 参与生成）
12. AI 填 → 列的 `hint` 动态拼进 VLM 输出 schema
13. 参与生成 → 值**默认直接拼**进该镜提示词（不带列名前缀，避免模型被填表格式带偏），前缀模板可改
14. 列定义可存为**模板**，跨项目复用
15. 内置列**能隐藏、不能删**（它们是 AI 拆解的标准产出，删了下次还会回来）

### 3.2 明确不做（防范围蔓延）

- ❌ 不造「表格节点」/ 不新增 canvas node kind
- ❌ 不改 `StoryboardPlan` 既有字段语义（自定义列走 `node.meta`）
- ❌ 不动「按镜头拆」现有行为（仅改文案为「只抽帧」以区分）
- ❌ 不接第二家 ASR/OCR 供应商
- ❌ 不做本地模型
- ❌ 不改 `chooseTextModel()` 默认选型（`resolveTextBrainKeys` 不传 `preferImageInput` 是**独立 bug**，单独修）
- ⏸ 一致性对账（生成后比对 6 镜商品是否漂）—— 我提议过，**用户未拍板，留 backlog**

### 3.3 已拍板的形态决策

| 问题 | 定论 |
|---|---|
| 功能落点 | 生成画布（不是创作页） |
| 一行两节点（先出图再转视频） | 一行两个按钮（出图 / 转视频），不拆两行 |
| 表格形态 | **底部升起占半屏**（长时间编辑，浮层盖画布憋屈） |
| 拆解粒度 | 给灵敏度滑杆，**默认保守**（每多一镜 ≈ +10s +3.2k token） |
| 维度取舍 | 按复刻广告裁；砍音效/光影氛围；**情绪保留**（它真的改变出图，且只两字） |
| 入口 | 视频节点浮条「取画面 ▾」菜单内（L3，不新增常驻按钮，遵设计系统 §1.5） |

## 4. 数据模型

**不新增顶层结构**。自定义列落在节点 meta：

```
node.meta.storyboard = {
  shotSize?: string        // 景别
  mood?: string            // 情绪
  visual?: string          // 画面描述
  dialogue?: string        // 对白/口播（whisper 归属而来）
  sourceFrameUrl?: string  // 原片帧（只读对照）
  sourceFramePromoted?: boolean
  custom?: Record<string, string>   // 自定义列值，键 = 列名
}
```

列**定义**（跨镜共享）存在组上或项目级：

```
columnDefs: Array<{ name; hint; aiFill: boolean; intoPrompt: boolean; hidden?: boolean }>
```

模板保存复用现有 prompt library 的存取范式（不新造存储层）。

## 7. 注意（踩过或预判的坑）

1. **Portal 配色**：表格若 Portal 到画布视口，配色必须用 `--nomi-*`；`--workbench-*` 只在 `.workbench-shell` 作用域内有定义，够不到会**静默退回继承色**（`NodeShotCutPanel.tsx` 头注释记着这坑）
2. **maxTokens 要给足**：gemini-3.5-flash 先烧 thinking token，给小了正文为空且 `finishReason='length'`
3. **别把联系表写进素材库**：可再生的中间产物落 `.nomi/cache/`（胶片条栽过）
4. **自定义列不是免费的**：每多一个 AI 填的列，输出 token 涨、模型注意力分散。UI 上必须让用户看得见（样张 v4 底部已有 token 估算条）
5. **列会失控**：对标产品 14 列已需横滚。列显隐控制是必需品不是加分项
6. **拆解会把用户素材帧外传**——与「本地优先」定位有张力。应**明着告诉用户**，并考虑给敏感素材一个降级模式（只本地 ASR、不传帧、画面描述自己填）。比塞 3 GB 模型更贴招牌，且几乎零成本
