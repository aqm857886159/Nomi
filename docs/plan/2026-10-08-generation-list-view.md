## ★1 用户怎么用

- 当我在生成页想一口气看完所有镜头、挑出要改的那几张时，我想切到「列表」按镜号扫一遍、点一张在右侧改它，以便不用在画布上找、拖、缩放。
- 步骤：
  1. 生成页左上「画布 | 列表」切到「列表」；
  2. 最上面是分镜（按镜号，带视觉锚条与「接上一镜」小圆钮），然后是画布分组，最后是未分组；
  3. 点一张卡 → 右侧检查器就是画布节点那张生成框（`NodeGenerationComposer host="panel"`），改提示词 / 模型 / 参数，改的就是画布上那个节点；
  4. 检查器「在画布里看」→ 切回画布并定位到这个节点；画布上镜头节点选中时「在列表里看」→ 切回列表并打开它；
  5. 创作页点一份「分镜方案」→ 生成页列表只看这份分镜，点 × 回到全部；
  6. 分区表头「生成整组」→ 同一张付费确认框逐项勾（第二步，见 ★2 / 格 5）。
- 不做：批量条、卡片勾选、「已选 N」、按类型改模型 / 参数、「生成已选」（10-08 用户：「批量条我们以前不是讨论过没必要做」「节点的模型创建的时候是选好的 没必要选模型吧」）；未分组区没有「生成整组」；列表里不新建节点、不拖动排版；自动引用（第二阶段）。
- 已知坑：
  - 画布节点已有一套全局镜号（`shotIndex`，「镜头 N」），分镜方案自有镜序（`shot.index`）——同一镜两种号，见「待定冲突」；
  - 方案里还没落画布的镜头没有节点，检查器里没有生成框可改（第二步账本合一之前的缺口）；
  - 「本次跳过」只存在于分镜编辑器的本地状态里，不落盘，列表看不到。
- 真实任务：
  - T1 打开一个有 6 镜分镜 + 1 个画布分组 + 2 个未分组素材 + 1 个导演台的项目，切到列表，点镜 2，把模型参数改一档，切回画布确认节点同步变了；
  - T2 0.23.1 存的、画布里有分镜表节点的旧项目打开 → 表节点被移除、出一条可见提示，镜头都在列表里；
  - T3 30 镜分镜 + 200 个节点的项目切列表、上下滚动、点开检查器。
- 指标：主指标 = 列表与画布同一镜的提示词 / 模型 / 参数逐字一致率 100%（同一个节点对象）；质量指标 = 旧项目打开失败数 0、分镜表节点残留数 0；护栏 = 「生成整组」取消后新增节点数 0、派发数 0。基线：今天画布里自动建表、分镜与画布是两处。
- 新界面 brief：一个按镜号排好的大画面网格 + 一个侧滑检查器。新手：第一次做片、画布找不到东西的创作者；老手：几十镜要逐镜微调的人。每步「预期 → 实际」记在 `docs/evidence/2026-10-08-generation-list-view/README.md`。

## ★2 谁说了算

- 新概念 `generation.list-view`（登记 `docs/engineering/concept-owners/generation.list-view.json`）：列表是**投影**，唯一 owner = 纯函数 `deriveGenerationList`（`src/workbench/generation/list/generationListModel.ts`），零写入、零缓存。
  - 镜头数据仍归原 owner：节点 = 画布 store（`useGenerationCanvasStore`）；还没落画布的方案镜 = 分镜方案（`StoryboardDesign.plan`，第二步账本合一前的现状）；行状态词表 = `storyboardRowStatus.ts`（`SHOT_ROW_STATUSES`，不另立词表）。
  - 同一份事实存了几份：1。列表不存镜头，不存节点副本；检查器的生成框不包 `NodeWriteAccessProvider`，写口就是画布 store 那一个。
- 视图状态（画布 / 列表、筛选的分镜、检查器开着哪张）= `useGenerationViewStore`（项目级寿命，切项目清空），不进项目文件。
- 花钱入口：列表只新增**一扇门**——分区表头「生成整组」，复用画布编组同一个按钮（`CanvasGroupToolbar.tsx` 的 `ToolbarButton + IconPlayerPlay + generationCommon.canvas.group.toolbarGenerate`）与同一条派发路径（`useCanvasFrameActions.runFrameAction('generate')` → `confirmAndRunPlan`）。门表见 `docs/plan/2026-10-08-generation-list-view.door-map.md`。**第二步**：等 #1107 合入，给 `SpendConfirmRequest.details` 加「可勾」字段，在同一张 `SpendConfirmDialog` 里逐项勾。
- 不靠「东西不见了」猜意图：分镜表节点的移除是读盘时的显式迁移（格「数据格式」），不在渲染时偷偷过滤。

## ★3 一致与复用

- 检查器正文 = 现役 `NodeGenerationComposer host="panel"`（与 Agent 付费卡同一件）；卡上提示词 = 现役 `PromptEditor` 只读 + `currentReferenceMedia`（chip 编号与画布同源）。
- 卡片媒体 = `resolveLightweightNodePreview` + `DeferredNodeImage` / `DeferredNodeVideo`（画布轻量档同一套，带加载队列）。
- 状态标签 = `deriveNodeRowExec` / `deriveStoryboardRowRuntimes` + `shotTable.status.*` 文案（分镜表的行状态词表，不另立）；视觉锚 = `deriveAnchorCardRuntimes`。
- 版本条 = `nodeVersionEntries` + 画布 store `setNodeMainResult`（版本唯一 owner `nodeResultLifecycle`）。
- 「接上一镜」= 画布已有的首帧接力（`connectNodes(prev, next, 'first_frame')` / `disconnectEdge`；视频源由 `generationReferenceResolver` 自动走尾帧接力）。
- 定位节点 = 现役 `FOCUS_GENERATION_NODE_EVENT`（画布监听：切分类、选中、居中）。
- 长列表虚拟化 = 仓库已装的 `@tanstack/react-virtual`（素材库、提示词库同款）。
- 切换控件 = `DesignSegmentedControl`；按钮 = `WorkbenchButton` / `WorkbenchIconButton`；徽标 = `DesignBadge`。
- 自写的：列表投影（领域：分镜镜序 × 画布分组 × 参考归属，框架里没有这件事）。不新增通用机制文件（无 `use*.ts` 新文件）。

## ★4 全状态

- 空：画布没有任何生成节点 → 「暂无生成节点」+「返回画布」。
- 加载：卡片媒体走加载队列，排队的画静态底，拿到槽位的扫光。
- 成功：状态标签「已生成」；生成中：「生成中」+ 检查器里节点自己的进度；失败：「生成失败」；可找回：「可找回」；锁定：「已锁定」；未生成：「未生成」。
- 部分成功：分区里各卡各显各的状态。
- 取消中：列表本身没有长跑动作；「生成整组」确认框取消 = 什么都没发生（第二步）。
- 过期 / 来源丢失：筛选的分镜方案被删了 → 筛选条消失、回到全部；检查器开着的节点被删了 → 检查器自动收起。
- 能力不可用：方案镜还没落画布时检查器里没有生成框 → 显示「这一镜还没上画布」+ 下一步「在分镜方案里改」（打开分镜编辑器那一镜）。
- 旧项目：分镜表节点被移除时出一条可见提示「旧版画布里的分镜表已收进生成页『列表』」+ 下一步「去列表看」。
- 文案全部走 i18n（zh / en），不写钱话。

## 6 外部数据与失败

- 外部来源：无新的供应商 / 网络调用；读的是本地项目文件（含 0.23.1 及更早写的分镜表节点）。
- 0.23.1 分镜表节点三种来源：`storyboard`（方案视图）、`production`（Agent 分镜视图）——**删**；`deconstruction`（拆参考片的事实表）——**保留**（用户拍板，那是参考资料分析，不是镜头）。
- 失败时用户看到：迁移只删视图节点、不碰镜头节点和方案；读不出的分镜表 meta 照旧走 `normalizeShotTableMeta` 的 fail-closed（不新增静默丢弃）。

## 待定冲突（不替用户选）

1. **镜号两套**：画布节点框外已有「镜头 N」（全局 `shotIndex`，Agent / 时间轴都读它）；样张要的是分镜镜序「镜 03」角标。本实现：列表分镜卡用分镜镜序（与创作页分镜编辑器一致），画布上分镜镜头加「镜 03」角标，原有「镜头 N」不动 → 同一个节点上会同时看到两个号。选项：A 分镜镜头只显示分镜镜序（要改 Agent / 时间轴读的号）；B 全部只用全局 `shotIndex`（列表镜号不再是 01–06）；C 维持两号（本实现）。
2. **创作页「分镜方案」点进来 = 列表**：分镜编辑器里只有方案能改的东西（视觉锚、分场、时长、加删镜头、执行计划、还没落画布的镜头）列表第一阶段都没有。本实现：点方案行 → 列表筛到这份分镜；方案行 ⋯ 菜单加「编辑分镜方案」仍能打开原编辑器。待第二步账本合一后再删编辑器。
3. **还没落画布的方案镜**：列表要显示（「生成整组」要能勾它），但它没有节点，检查器没有生成框。本实现：卡片显示方案提示词与「未生成」，检查器给「在分镜方案里改」。
4. **画布编组的「生成整组」也会带上逐项勾**：列表分区与画布编组同一个按钮、同一条路径，所以画布编组点开后也会看到逐项勾（已生成的默认不勾）——画布编组今天只发未生成 / 失败的节点，加勾后用户可以主动勾上已生成的重生成。（第二步实现时生效）
5. **「本次跳过」**：样张有这个标签，但它只是分镜编辑器里的临时选择、不落盘，列表读不到。本实现不显示。
