# 设计卡：生成方式按输入现算，底栏「模型｜方式｜参数」

```
改动名：方式按输入现算 + 底栏方式格        线/负责人：实现线（独立验收另派）        类别：[花钱][新界面]
```

用户 2026-11-12：视频 / 图片节点「选了图生图却没图」，生成钮灰着；同日改向——照 LibTV 的思路，把方式放回底栏让创作者确认（「按照他的思路改…不同模型的选择有时候也不一致…他已经是成熟产品了」）。拍板图：`docs/design/boards/2026-11-12-mode-bar/ModeBar.board.json`（A–J + 边界 K1–K5）。

## ★0 先查别人

| 出处 | 它怎么做 | 对哪个决定的影响 |
|---|---|---|
| LibTV 视频 / 图片节点（登录实测 37 个视频模型、25 个图片模型） | 底栏「模型｜方式｜参数」；方式是一格下拉、每个模型 2–8 种；放不下当前输入的方式置灰并报数；图片节点没有方式格 | **确认了**：底栏加方式格、图片节点不加；**改了**：原来方式藏在参数面板顶部，现在删掉那一段 |
| OpenAI 图像生成指南 <https://developers.openai.com/api/docs/guides/image-generation> | `image_generation` 工具 `action` 默认 `auto`，按上下文有没有图决定生成还是改图；强制 `edit` 却没有图会报错 | **确认了**：默认按输入算；「带图方式却没图」只在强制时出现——我们不让它被写成真相 |
| Luma Dream Machine API <https://docs.lumalabs.ai/docs/video-generation> | 文生、图生同一端点，区别只在有没有 `keyframes`；`frame0` / `frame1` 都可选 | **改了**：「首帧必须有」不写死，按档案每个方式声明的槽 `min` 判（对调钮的置灰也按这个判） |
| Kling 首尾帧 <https://kling.ai/quickstart/ai-video-start-end-frames> | 首尾帧是图生视频里的「Add End Frame」选项，不是另一种任务 | **确认了**：首帧 / 首尾帧当「图怎么摆」，手选的写成偏好 |
| Google Flow 帮助 <https://support.google.com/flow/answer/16353334?hl=en> | 默认文字生成，要用帧或素材在菜单里手选 | **确认了**：留人手选的方式；**改了**：手选的放不下当前输入时不硬套 |

出口：不涉及新增挡人保护——这次删掉的是两道「方式和输入对不上」的拦截；剩下「模型没有任何方式收得下这些输入」时方式格留在收得最多的那种、多出的淡显「不会发」、行尾写「最多 N 张，多出的先移走」，创作者删图或换模型就能继续。

## ★1 用户怎么用

当我在画布上放了图（或没放）准备生成时，我想一眼看到「这次按哪种方式发」并能改，以便不再碰到「方式要图却没图、钮灰着」「放了一堆参考图却按首尾帧只发两张」。
1. 空视频节点写提示词 → 方式格写「文生视频」→ 直接点生成。
2. 连 1 张图 → 方式格自动变成放得下它的默认方式（Seedance：全能参考），行尾「参考图 1 张」。
3. 点方式格选「首尾帧」→ 参考行变成首帧 / 尾帧两格；连第 3 张 → 首尾帧放不下，自动换成全能参考，行尾「放了 3 张，已改成全能参考」，菜单里首尾帧那行置灰并报数。
4. 删回 2 张 / 删光 → 方式不跳回（删光回到文生视频）。
5. 换到可灵 4.0（只收 2 张）且连着 3 张 → 菜单只列可灵的方式；没有哪种收得下 3 张时留在最宽的那种，第 3 张淡显不会发、行尾写明。
6. 图片节点：没有方式格，行尾「参考图 N 张 · 按图改」。

不做什么：不改档案的参数档位、槽上限、请求字段；不动模型菜单的行、变体格、模型排序和隐藏；不动分镜行、批量条、声音、3D 的方式栏样子；不动主进程、Agent、MCP 的行为。
已知坑：①方式还决定参数选项，参数要按现算的方式取；②画布边自带角色（首帧 / 尾帧 / 参考），它本身就是输入；③声音档案的方式是真的任务选择（续写 / 翻唱），不按输入算；④旧工程里按槽存的图（旧键）当时被藏着的，打开后先放一边，不算这次的输入。
真实任务：①用户 11-12 那一幕（选了带图的方式却没图）；②放了很多参考图节点却停在首尾帧；③Seedance 2.5 首尾两张图。
指标（目标 → 信号 → 指标）：
- 主指标：方式格显示的 = 这次真发的方式，输入与方式对不上的节点占比 = 0。量具：`electron/shared/modelArchetypes/modeForInputs.exhaustive.test.ts`（全部档案 × 每个存着的方式 + 乱写的方式 × 9 种输入）、`src/workbench/generationCanvas/store/canvasModeNineStates.test.ts`（九种状态各一条）。真实项目里的比例：未验证：缺量具。
- 质量指标：请求体只在「原来会拦 / 发错方式」的格子里变。量具：`electron/parity/` 对等夹具、`tests/ux/_referenceLeakWire.test.mjs`。
- 护栏指标：因方式被拦的次数 → 0。量具：未验证：缺量具（遥测没按拦截原因上报）。
新手 / 老手：新手只看方式格的字；老手点开菜单看每行一句说明和置灰原因。每步「预期 → 实际」记在走查 `tests/ux/mode-bar.walk.mjs` 的断言名里。

### ★1b 连带界面
- 参数面板：删掉「生成方式」一段，只剩参数。
- 分镜镜头行：样子不变；它的参数按镜头计划的方式取（不按画布节点现算）。
- 共享参考行（`AssetReference`）：行尾那句话钉在图区外、整句不折；淡图不逐张写字；计数按类型；首尾帧对调钮按「对调后发得出去」决定能不能点（协调定，待用户点头）。
- 生成钮悬停原因：删掉「…或切回『文生图』」一类文案。
- Agent / MCP / 付费确认卡：不改（任务书范围外）。

### ★1c 老用户
- 项目里存着的方式：**不迁移、不改盘**。打开时当偏好读：放得下当前全部输入、必填格满足才用；否则按输入现算。老项目里「带图方式没图」打开后就是文生，「首尾帧连着 5 张」打开后是全能参考、5 张都发。
- 人手在方式格选的写偏好并带 `chosenBy: 'human'`；旧版本不认识这个标记，忽略。
- 旧工程按槽存的图：当时藏着的先放一边（淡显、悬停「没在用，点一下用上」），一张不丢。
- 退回上一版：旧版本照读 `modeId`，节点和参考一张不少。
- 量具：`tests/fixtures/old-user-data/` 的升级测试、`canvasModeNineStates.test.ts` 的老项目格。

## ★2 谁说了算

概念「这一次按哪种方式发」→ 唯一 owner：`modeForInputs(archetype, inputs, preference, { firstFrameEmpty })`（`electron/shared/modelArchetypes/modeForInputs.ts`，纯函数、同步、不认供应商名）。
- 渲染层只经 `effectiveArchetypeMode` / `sendArchetypeMode`（`archetypeMeta.ts`）调它；输入由 `collectModeInputs` 一处收集（画布边带角色 + 上传列表）。
- 偏好只由人手在方式格写（`canvasModeChoiceForget` 在放不下时忘掉它）；连线、换模型、自动参考、运镜、@提及、交付等机器写方式的口全部删掉。
- 结构上做不出来：`applyArchetypeModeSwitch` / `currentArchetypeMode` 删除；测试辅助 `modeTestHelpers` 被 eslint 禁止进生产代码。
- 门表（`node scripts/door-map.mjs`）：改前 写 14 / 读 20 = 34 扇；改后 写 5 / 读 27 = 32 扇；纠正同一事实的地方从 6 处（4 个派生 + 2 道拦截）变 1 处。没有靠「东西不见了」猜意图。
- 首尾帧对调的能不能点：`frameSwapKeepsSendable(mode, filled)`，同一文件，判据只看档案槽的必填声明。

## ★3 一致与复用

以前定过：ComposerB3（10-18 / 10-19）「方式放参数面板顶部」「永远没有文生视频选项」「未用到淡格 + 行尾问要不要当首尾帧」——11-12 用户改向后作废，清单里标 `dropped` 并写去处；B3j「换模型时图跟着走、不掉成文生」照旧；#1269 旧工程先放一边照旧。
三条路：沿现状给每个漏网入口补派生（第 21 个入口还会漏）/ **发送时现算、只留人手偏好（选）** / 彻底不存方式（人手选的首尾帧没处放，丢功能）。
复用：排序复用原来的参考类优先规则（搬进 shared）；落格复用 `placeUploadedImages`；传输桶复用 `modeTransportFor`；方式格用 `NomiSelect`；图标全用 Tabler。`check:self-written` 不新增条目。

| 状态 | 方式格 | 菜单 | 行尾 | 生成钮 |

| 没放输入 | 文生视频 | 带图的方式置灰：「先放 1 张图」等 | 无 | 可点 |
| 放了输入、没手选 | 放得下全部的默认那种 | 文生置灰：「已放 N 张图，文生视频不带图」 | 「参考图 N 张」 | 可点 |

## 5 中途表

现算是纯函数、同步、不碰网络；打断面不变：停 / 关窗 / 断网 / 重启 / 连点都走现有生成生命周期（不扣 / 已扣找回照旧）。方式在点生成那一刻定下随请求带走，找回任务用请求里的那个，不回写节点。连点之间改了输入，第二次按新输入算——就是他看到的。

## 6 外部数据与失败

外部来源：档案声明（各档案带 `sources`）、老项目里存着的方式、Agent / MCP 写的方式（本次不改它们的行为，读时一样当偏好）。档案声明错（某方式其实收不了）→ 供应商报错照旧走错误面，不归咎用户 Key。

## ★7 性能

①新增操作：打开方式菜单、在方式格选一种、删一张参考（方式重算）。②最坏规模：一个节点连 30 张图 + 10 段视频 + 10 段音频（Seedance 2.5 全能参考上限）。③预算：操作到可见反馈 ≤100ms，交互期间 >50ms 长任务 0 个。④场景与基线（darwin arm64 / 5 次）：
- `composer-open-mode-menu-refs-30`：中位数 32.1 / p95 32.3 / 预算 100
- `composer-remove-ref-refs-30`：中位数 23.3 / p95 24 / 预算 100
- `composer-open-params-refs-30`（已有场景复跑）：中位数 32.2 / p95 38.3（改前 45.6 / 46.8）
删掉 `liveInputNodeIds` 一类订阅后每次节点变更少一次全图扫描（净减）。

## ★9 验收与回滚

真实场景复现（`tests/ux/mode-bar-replay.walk.mjs`，生产构建的真 Electron 窗、隔离资料、本机 APIMart 夹具，零花费）：
- 用户的流程：视频 / 图片节点上选了带图的方式却没放图，生成钮灰着。
- 我走的：按 ★1 的 1–6 步：空视频节点 → 连 1 张 → 手选首尾帧（2 张）后连第 3 张 → 删回 2 张、删光 → 底栏换到可灵 4.0 且连着 3 张 → 停应用、重开老项目（一个存着首尾帧却没输入的老节点、一个旧按槽键存图的老节点）。每幕点底栏真的发送钮，夹具收下请求体，按上传记录把图认回文件名，和方式格的字、参考行在用的图逐一对上；没在用的图一张都不许出现在请求里。
- 结果 10 幕全对：空节点「文生视频」不带图；1 张「全能参考」发 [a]；手选首尾帧发 first/last [a, b]；第 3 张自动「全能参考」发 [a, b, c]；删回 2 张仍是全能参考发 [a, b]；删光「文生视频」；可灵 4.0「图生视频」只发 first_frame_image / last_frame_image [a, b]、c 不发；老首尾帧空节点打开是「文生视频」能直接发；旧按槽键的老节点「首尾帧」发 [old-first, old-last]。老项目打开后老节点的 meta 字节不变（文件里变的只有保存时间、版本号、`renderKind` 这些 main 已有的读入补齐，本分支不碰）。
- 复现中抓到的新问题：APIMart 的 Seedance 2.0 菜单里两行同叫「图生视频」、两行没图标（按槽形状归类撞了名）。修法见 `modeMenuModel.ts` 的撞名消解：撞名时按档案自己的方式名归类，仍撞才退成档案原名；全部 47 份档案逐一比过，只有这一份的名字变了。回放里每次点开方式菜单都核：不许同名、每行有图标。
- 差别：不是真扣费，用的是本机假服务（只看发出去的是什么，与模型无关）；修前的 main 构建没在本工作树里另跑（不切分支），修前那一幕由第一次回放的失败截图留底（菜单找不到「首尾帧」）。
- SecurityAgent：起窗前后都没有。
