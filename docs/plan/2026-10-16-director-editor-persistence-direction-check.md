# 方向检查：导演编辑器「谁把工程写回节点」按开关分叉（S2，2026-10-16）

> 触发：`node scripts/fix-churn.mjs src/workbench/generationCanvas/nodes/director/DirectorEditor.tsx` 命中（14 天内第 3 个 fix）。
> 背景：用户 10-16 拍板 3D-BOX 默认打开、开关代码保留、留「切回旧导演台」入口；协调定入口**只切界面**（全屏、底部 AI 胶囊、默认进精修），单写者同步与 Agent 工具面都不切。
> F7 原题（「中途关导演台，同一轮下一次请求还带 stage_shot」）按入口 a 关账：a = 开关开时 stage_shot 一直常驻，主进程没有「当前场景」这个状态，这是预期行为，不是缺陷。

### 0. 一句话根因

编辑器把工程写回画布节点的那套规矩（单写者、外部改动重载、撤销前落盘、自动保存不重复写）散在 450 行组件里，而且**按 3D-BOX 开关二选一**：开关关时整套不建。所以任何「看开关决定界面」的改动，都会顺手把写回规矩也关掉。

### 2. 为什么这一类会一直出现

写回规矩没有一个 owner：`createDirectorNodeSync` 只管记账，真正的接线（谁调 `persist`、自动保存怎么判、退出时写不写、撤销前落盘登记）都在 `DirectorEditor` 的五个 effect 里，又被 `if (director3dBox && …)` 包住。改界面的人只要碰开关，就会碰到写回。

铁律对照：⑫「点了 = 以为的」——用户点「撤销」以为回去了，2 秒后被自动保存写回来，正是这条被破坏。

### 4. 靶子独立性检查

不涉及评测分数。新测试用真编辑器 store（`createDirectorStore`）+ 真外部写口（`writeExternalDirectorProject`）+ 假计时器，不 mock 被测逻辑。

### 5. P0：是我们独有的吗

是。「编辑器开着时 store 是唯一写者、节点 meta 是持久化、Agent 写入与撤销同一本历史」是 3D-BOX 方案 §3 / §7 的领域约束。通用的部分（状态库订阅、计时器）已经在用 zustand 与平台计时器，不自写。

### 6. 补 / 换 / 删

| 选项 | 做什么 | 代价 | 风险 | 推荐 |
|---|---|---|---|---|
| 补 | 切回入口实现时记得别碰 `syncRef` 的开关判断 | 0 | 下一个改界面的人照样会碰到 | 否 |
| **换** | 写回规矩收成一个不看开关、不看界面的控制器 `directorEditorPersistence.ts`（单写者记账 + 自动保存 + 退出保存 + 撤销前落盘登记），编辑器只接线；同一提交删掉组件里的五段散落逻辑和开关判断 | 一个新文件 + 编辑器减行 | 开关关时也建同步：旧导演台从此也会在外部改动后重载、自动保存不重复写——这是更正确的行为 | **是** |
| 删 | 不留切回入口 | — | 违背用户 10-16 拍板 | 否 |

结构保证：控制器的参数里没有开关、没有界面模式，想「按模式关掉写回」必须改控制器本身；外加一条结构测试，钉住编辑器不按开关建持久化。

### 7. 用户要权衡的核心

没有要用户权衡的：切回入口只切界面，这一刀让「写回规矩不跟着界面切」从约定变成结构。
