## 0. 一句话根因

编译器把「谁、在哪、对着谁」这种**语义计划**一步降成「cube + 坐标 + scale」这种**渲染原语**，中间没有一层「舞台模型」来唯一地回答「这东西是什么、多大、底在哪、人能站哪、哪边是里面」；于是摆位、走位、机位避让、测量、提示词各自从坐标和名字里**反推**这些事实，各推一份、两两打补丁；而唯一的验收（分数）不量物理、靶子又是同一条线写的，所以修对了会被回滚、修错了会留下，物理错误只能靠用户截图一个一个暴露。

## 2. 为什么这一类会一直出现（设计层）

1. **降级有损，再从残骸里反推**。`actorObject()`（`directorPlanCompiler.ts:98-112`）把 person / vehicle / product / prop 抹成 `character` / `cube` + scale；之后每一步都需要「这是车吗、多高、能不能踩」，只好从名字后缀、scale、正则（`GROUND_KIND`、`WALKABLE_HEIGHT=0.3`）里猜。每猜一处就多一份事实，下一处不一致就是下一个 bug。
2. **几何真值不是数据**。它写在 JSX 里，模型层 import 不了，只能手抄，手抄表注释写着「checked against」——靠人对账。
3. **不变量写在动作里，不写在数据上**。编辑器之所以从不出「有片段不在轴上」「人悬空」，是因为人只能通过那几个动作改工程（拖片段、在地面上画盒子）。任何新写者都得自己重抄一遍规则，现在已经 4 个写者。
4. **贪心两两求解 + 无语义坐标**。`clearOf` 只看「最近的空位」，不知道墙哪边是里面、门前站哪；每遇到一种新组合（人-门、人-墙、车-机位）就得加一条特例。组合数 = 种类 × 关系 × 动词，修不完。
5. **方向盘不量物理**。分数量的是标签和取景，物理检查只有出过事的那几条，而且和被测者共用一张表；oracle 是同一条线写的、同一个编译器编的。所以「分数涨」不等于「画面对」，物理上对的修复会因分数下降被回滚。

## 3. P0：这些是我们独有的吗？现成的能用哪些

不是独有的：包围盒、落地、互穿、视线、寻路都是通用空间计算。**独有的只有**：分镜关系词（「在院门前」「拿着信」「正反打」）到站位 / 机位的映射、每个场景模板里「人能站哪、机位能放哪」的取景知识。

| 候选 | 接入代价 | 能消灭 | 留下 |
|---|---|---|---|
| three.js `Box3` / `BufferGeometry.computeBoundingBox`（已是依赖） | 小：把原语几何（构造器 + 参数 + 网格偏移）从 JSX 抽成一份数据，渲染组件和模型层都读它；包围盒由 three 现算，删手抄表 | (a) 的尺寸 / 原点分叉（#2,#4,#7,#8,#11,#15,#21）；测量与编译器同错 | 不管语义（e），不管 GLB（需在素材入库时存一份包围盒） |
| `three-mesh-bvh`（已在锁文件，drei 间接带入 0.8.3，用要升为直接依赖） | 小-中 | 精确视线 / 遮挡（#17,#18）、真 GLB 网格射线 | 不管摆在哪 |
| 物理库 `@dimforge/rapier3d-compat`（Apache-2.0，WASM，有确定性构建） | 中：WASM 包约 MB 级（未实测）、异步初始化、要把场景同步成刚体 | 互穿、落地（重力落定）、角色胶囊、射线 | 仍不知道「墙哪边是里面」；我们是预演不是模拟，大多数能力用不上——**现在不接** |
| 导航网格 `recast-navigation-js`（MIT，WASM） | 中 | 走位绕障（替掉手写 `routeAround`） | 站位语义仍缺；S1 只有 4 个模板，直线 + 模板手标路径够用——**延后** |
| 约束求解 `kiwi.js`（Cassowary） | 小 | 左右 / 前后间距这类线性关系 | 「不互穿」是析取约束，它表达不了——**不接** |
| FilmAgent 的离散站位（Apache-2.0，需署名；只借结构不搬数据） | 中：每个模板手标 5-10 个命名站位（id、描述、朝向、可坐、所在区域）+ 可选机位区 | (e) 全部（#1,#10,#16,#17）：人只站在作者验证过的点上；(a) 里的摆位部分 | 机位求解仍是自由的（但只需对已知站位做一次性验证） |

结论：**尺寸 / 原点 / 视线用现成的（three `Box3` + `three-mesh-bvh`），站位语义借 FilmAgent 结构自己标**——后者是领域约束（取景知识），可以登记为自写。物理库和导航网格不接。

## 4. 三个选项

| | ① 补：在现结构上加统一事实和检查 | ② 重写一层：在计划与工程之间插「舞台模型」 | ③ 删：砍掉自由坐标，只许离散站位 |
|---|---|---|---|
| 做什么 | 几何真值抽成一份数据（渲染 / 编译器 / 测量 / AiSceneBar 共读，删手抄表）；`normalizeDirectorProject` 里由片段推出 `inTimeline`；特征测试的 6 条判据升格为生产函数，进 L0；删 `y≥0` 夹子 | ① 全部 + 新模块「舞台模型」：每个实体带语义种类（不再抹成 cube）、真包围盒、支撑面；模板带命名站位和区域；关系词在这里一次性解析成站位；携带物用父子关系；出工程走一个共享的 `projectBuilder`（编译器、AI 搭场景、迁移共用） | 计划 schema 改成 `placement.ref` 只能是站位 id；dressing 只许 [x,z]（像旧版 `legacySceneBuilders` 那样贴地）；未知场景件报问题不造盒子；走位只在站位之间 |

| 消灭 | a（原语部分）、b（inTimeline）、c | a、b、c、e | a、e 最彻底；b、c 仍要做 ① |
| 不消灭 | e：两两猜的特例照旧出现，只是从「用户截图发现」变成「门岗发现」 | 机位求解仍是自由的；GLB 包围盒要素材入库时补 | 自由布局的表达力（S1 只有 4 个模板，影响小）；规划器与题库要返工 |
| 工作量（估） | 2-3 天 | 5-7 天（含 ①） | 7-10 天（含 ①，加 schema / 提示词 / 回归计划重生成） |

**推荐 ②，先做其中 ① 的部分**。理由一句话：bug 的源头是编译器逐对猜空间语义，只有一层专门拥有这些语义的模块能让「新组合」不再变成新 bug，而它可以不碰 3b 正在定的契约。

建议顺序：第 1 步（=①，2-3 天）几何真值一份 + inTimeline 推导 + 物理判据进 L0（先单列一栏「物理层」跑一轮，让分数下降可归因，再并入 L0）+ 修 oracle（删环境词灰盒、题卡种类）；同时修已发版的 AiSceneBar 悬空（它不在编译器里，但同病）。第 2 步舞台模型 + 命名站位。第 1 步完成前，**冻结编译器的两两特例修复**，r5 的 F15 WIP 不再续做。

## 5. 用户要权衡的核心

用约一周时间和一次如实的分数下跌，换掉「AI 给任意坐标、编译器逐对猜」的做法——之后人物只站在模板里标好、验证过的位置上，自由度换可靠。
