# 类根因复盘：上游错误文案边界

## 0. 一句话根因

错误文案反复被“界面不谈钱”扫描器误伤，是因为服务商返回的余额、额度和限速状态与 Nomi 对本步骤花费的断言共用同一词典扫描边界；本轮必须恢复可行动的上游原文，同时把例外收紧为有理由的错误/账号状态 key。

## 1. 归类

| 现象 | 直接原因 | 类根因 |
|---|---|---|
| 402、额度、429 提示被改成模糊动作 | 正向花费扫描器只按文本命中，不识别“服务商返回” | 错误状态与产品承诺共用文案扫描入口，缺少结构化的上游错误登记约束 |
| NOT_MONEY 曾可用无理由数组 | 白名单接口没有强制理由和 key 类型 | 门岗只验证“跳过了”，没有验证“为什么跳过” |

## 2. 为什么会重复出现

同一份本地化词典同时承载用户承诺和外部错误转述；每次文案审查都会在值层发现“余额/额度/充值”等词。仅改某条文案会让用户失去行动信息，或让界面重新出现未经证明的花费断言。缺少结构化白名单约束是共享缺口。

## 3. 不改结构的可验证预测

| 预测 | 验证 |
|---|---|
| 任意无理由或普通 UI key 加入 NOT_MONEY 都会失败 | `node --test scripts/check-i18n-no-cost-claims.node-test.mjs` 反例测试 |
| 服务商错误文案仍能保留 402/额度/429 和行动建议 | `node scripts/check-i18n-no-cost-claims.mjs` 与相关 vitest |

## 4. 独立性检查

扫描器测试直接构造中英文词典，和 UI 走查 oracle 分离；TikHub 走查只验证真实宿主中的错误呈现。没有回滚评测先例。

## 5. P0 现成方案

本轮能力是 Nomi 独有的“界面不谈钱”文案政策与上游错误转述边界，通用 i18n 库无法表达“仅错误/账号状态 key 且必须有理由”的产品约束。保留现有扫描器，在其入口增加结构化校验；后续若错误目录迁移到类型化 catalog，再移除值层例外。登记条目：`gate-family`。

## 6. 方案比较

| 方案 | 代价 | 风险 | 结论 |
|---|---|---|---|
| 接入通用 i18n 库 | 无法提供本项目的错误状态白名单语义 | 仍会漏放普通文案 | 不适用 |
| 保留扫描器并强制 reason + key 类型 | 维护少量登记表 | 新错误 key 需登记 | 本轮推荐 |
| 重写完整错误 catalog | 迁移范围大，超出本轮错误恢复 | 影响既有调用方 | 后续方向 |

## 7. 用户权衡

用户需要知道服务商说了什么以及下一步怎么做，同时 Nomi 不能替服务商断言这一步是否花钱；因此允许带来源的上游错误原文，禁止 Nomi 自己的花费结论。
