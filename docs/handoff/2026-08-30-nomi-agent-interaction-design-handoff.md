## 1. 用户真正要解决的问题

Nomi 的 Agent 未来会出现在 3 个顶层工作区和 1 个独立浏览器上下文入口：

- 创作：文本、剧本、段落和选区。
- 生成：画布节点、图片、视频、音频、3D 对象和多节点关系。
- 预览：播放器当前帧，以及同一预览工作区内的时间线区间。
- 浏览器：网页选区、图片/视频/音乐等外部素材和来源信息。

它们不是四个互不相干的 Agent。用户希望它们共享同一个项目 Agent、Thread、任务、授权、队列和结果历史，但每个专业工作面的就近入口与引用对象可以不同。浏览器不是第四个顶层 Tab。

本轮要回答的核心问题是：

1. 用户在任何工作面如何快速把“这里”交给 Agent，而不必解释坐标、时间码或对象身份。
2. 技能、提示词、工作方式、操作授权、Agent 模型和制作模型如何被清楚区分，又不把 340px 输入区堆成控制台。
3. 图片、视频、音频、3D 和网页素材在聊天里显示到什么程度，何时回到画布或专业界面。
4. Agent 忙碌、排队、确认、失败、完成或收起时，用户如何持续知道它在做什么。
5. 同一个 Agent 横跨工作面时，哪些状态必须连续，哪些 UI 可以因工作面而变化。

最终交付不是功能列表，而是一套用户能够实际使用、设计系统一致、工程上能形成清晰状态合同的方案。

## 4. 已经拍板的产品与交互决策

以下内容来自用户后续逐轮反馈，优先级高于早期文档中的冲突描述。

### 4.1 平台与真实应用结构

- 本轮只考虑网页和桌面端。
- 禁止重新加入移动端断点、触屏专用分支或移动端用法说明。
- 已从样张删除 `390/620/720px` 移动端断点、`hover:none` 分支和 `.method-mobile-use`。
- 保留 `prefers-reduced-motion`，这是桌面无障碍能力，不是移动端逻辑。
- 设计前必须看 Nomi 真实页面，不能凭通用聊天应用想象。
- 顶层工作区为“创作 / 生成 / 预览”。
- 预览器与时间线属于同一个预览工作区，不能拆成两个平行页面。
- 浏览器是独立入口，不应伪装成第四个普通工作区 Tab。
- Agent Dock 目标宽度约 340px。
- 常规控件统一 28px 高；当前真机样张使用 6px 控件圆角。
- 36px 缩小药丸必须保留，它是同一 Agent 的状态投影，不是第二个 Agent。

### 4.2 同一个 Agent，多个工作面

- 项目只创建一个 Agent Host。
- Thread、队列、确认、授权、任务状态和产物关系不因切换工作面而重建。
- 工作面只负责提供本地上下文和就近入口：文本段落、画布节点、预览帧、时间线区间、网页选区。
- 结果在聊天里给轻量预览、状态和回执；正式可编辑产物仍以画布或专业工作面为真相源。
- “来源于哪个工作面”只用于解释和定位，不能暗中改变权限或授权。
- 3D 专业界面继续独立存在；聊天里可以显示截图/轻量占位，点击后定位到真实 3D 对象或工作面。

### 4.3 输入语义

四种入口必须是一套稳定语义：

| 入口 | 含义 | 例子 |
|---|---|---|
| 拖入 / 回形针 | 添加本地文件 | 图片、视频、音频、文档 |
| `@` | 引用当前项目或外部现场 | 画布节点、文本选区、预览帧、时间线区间、网页选区 |
| `/` | 快速调用技能 | 分镜导演、角色一致性、3D 预演、素材研究 |
| 就近“引用”按钮 | 不记快捷键时的可发现入口 | 节点工具条、文本选区、预览帧、时间线区间 |

不创建笼统的“引用模式”。用户应直接选对象、点引用、拖文件或输入 `@`。

所有随本轮发送的文字、附件、引用版本、裁剪范围、时间区间、3D 视角、技能、提示词、工作方式、授权和模型选择都应在发送时冻结，防止切页或原对象变化后历史指令语义漂移。

### 4.4 技能、提示词、工作方式和模型必须分开

- 技能是完整工作流，不是一个名字或文风标签。
- 技能选择应先让用户看结果：悬停或键盘聚焦可显示图片或静音视频演示，并列出输入、产物、步骤和能力依赖。
- 没有真实演示媒体时显示结构化能力说明，不能造假封面。
- 默认由 Agent 自动匹配技能；用户不应被迫先配置。
- 提示词只改变本轮表达或分析侧重，不调用完整工作流。
- 提示词应显示完整正文，选中后作为可移除 token 持续可见。
- 工作方式与操作授权使用同一个入口，这是用户明确要求。
- 技能、提示词、工作方式/授权和模型不能塞进同一个总选择器。
- Connector 不做常驻按钮。浏览器、图库、音乐库等通过 Agent 调用、`@` 引用或技能依赖进入。

### 4.5 模型默认

模型入口放在输入栏外显位置，不能只用一个意义不明的图标。

当前分为五类：

- Agent：规划、推理和工具调用模型。
- 图片：生成与编辑。
- 视频：文生与图生。
- 音频：配音、转写和相关音频处理。
- 3D：文生与图生 3D。

每类必须保留“自动选择”作为默认值，由 Nomi 内置路由选择；高级用户可以覆盖单类默认模型。入口应显示“模型”文字和覆盖类别数量，而不是要求用户记住图标。

当前 HTML 中的具体模型名只是样张数据，不应直接视为产品最终目录；正式目录应从设置和真实 Provider/Capability 数据派生。

### 4.6 控件可理解性

“模型纯图标看不懂”不是单点问题，而是通用设计问题。根因有三层：

1. 状态型选择器没有显示用途和当前状态。
2. 可点击控件没有强制要求产生可见反馈。
3. 340px 输入栏没有用真实长数据和多状态做宽度门岗。

纯图标只适合熟悉、即时、可逆且结果立刻可见的动作，例如附件、发送、收起。模型、模式、授权、作用域和多值配置必须显示文字或当前状态，不能只靠 tooltip。

选择器、下拉菜单、按钮和图标必须使用同一尺寸系统；不能有的很大、有的很小。样张中的同排动作按钮遵循：同高、等宽均分、主次只用颜色表达，一排最多 3 个。

## 6. 已知不能宣称完成的地方

当前样张是中途版本。以下问题均为“待完成”，必须在下一轮明确处理或诚实标注。

### 6.1 可点击但反馈不完整

- 画布节点工具条中的“替换 / 裁剪”仍是静态示意按钮。
- 17/18/21 种反馈形态区中的部分按钮仍是视觉示意，没有行为。
- 浏览器入口虽然视觉上是独立入口，演示代码仍在同一个 Host 内替换内容；需要判断这是可接受的原型折中，还是会误导评审者。
- 会话切换只更新 Thread 标签和一条状态文字，没有真正切换消息历史。
- “回到现场”目前只做闪烁反馈，没有滚动或定位到一个明确对象。
- 发送只模拟“加入队列”，没有真实的队列编辑、删除、重排和暂停。
- 主反馈区中的停止、撤销、重试、确认、查看日志等按钮大多仍是静态示意。

对这些控件只能二选一：补最小但明确的交互反馈，或把它们改成明显不可交互的背景示意。不能继续让用户以为可以点却什么都不发生。

### 6.2 “发送时冻结”目前主要是设计合同

Dock 发送函数会把 token 文本写入消息摘要并清空输入，但没有持久化一个包含技能、提示词、模型、工作方式、授权、引用版本和附件元数据的完整 `TurnDraft` 对象。

因此当前页面可以演示“冻结”的可见语义，但不能声称已经验证了真实快照数据。若继续强化样张，应至少让发送后的回显包含本轮关键配置；生产实现则必须使用结构化快照。

### 6.3 响应与键盘细节仍需复测

- 菜单打开后，焦点移动通过 `setTimeout(..., 0)` 完成。自动化测试必须等待一个 event loop 后再断言焦点。
- 需要检查 Tab 顺序、Escape 返回原触发器、方向键边界和菜单关闭后的焦点恢复。
- 需要检查技能视频在 `prefers-reduced-motion` 下不会自动播放。
- 需要检查所有常驻控件在真实长文案、模型覆盖数量 0 到 5 和中文/英文混排下不溢出。

### 6.4 样张命名和数量冲突

当前页面存在明显不一致：

- `<title>` 与 H1 写“17 种形态”。
- 页面说明写“前 18 种反馈形态”。
- `nomi-agent-interaction.md` 定义的是 21 种对话形态。

不要只改一个数字掩盖问题。先明确页面到底展示哪一组：基础反馈形态、扩展输入形态还是完整 21 种词汇，然后让标题、说明、自动播放和文档一致。

### 6.5 圆角真相源冲突

当前样张和用户最近要求按真实应用采用 6px 控件圆角；但 `nomi-agent-interaction.md` §8.1 仍写 `--workbench-control-radius: 7px`。下一位 AI 必须读取真实组件/token 源码和当前应用截图后解决这一冲突，不能凭偏好选择。

## 10. 下一轮设计评审的判断框架

每个常驻控件和每条交互都要依次回答以下问题：

### 用户理解

- 用户不看 tooltip 能否知道它是什么。
- 控件显示的是动作、当前状态，还是配置类别；三者不能混淆。
- 用户点击后能否立刻看到结果、状态变化或下一步。
- 同一件事是否在多个地方重复出现。
- 默认路径是否允许用户直接说需求，不要求先配置。

### 任务连续性

- 切换创作、生成、预览或浏览器后 Thread 是否仍是同一个。
- 当前上下文发生变化时，旧消息是否仍能解释当时引用的对象。
- Agent 忙时输入是否保存完整，而不是只保存文字。
- 收起成药丸后，确认、失败、排队和完成是否仍可见。

### 视觉一致性

- 常驻控件是否统一 28px 高。
- 图标大小、stroke、圆角、内边距、菜单行高和触发器高度是否来自同一规格。
- 340px Dock 是否在最坏数据下不换成混乱的两层控制条。
- 文字是否截断在次要描述，必要语义是否仍完整可见。
- 页面是否保持 Nomi 的安静、克制、工作型界面，而不是卡片堆叠或装饰性 Agent 面板。

### 无障碍与键盘

- 图标按钮是否有明确 `aria-label`。
- 状态选择器是否有 `aria-expanded`，菜单打开和关闭后焦点是否正确。
- `Enter` / `Shift+Enter`、Escape、上下方向键和 Tab 顺序是否符合预期。
- reduced motion 下没有持续运动或自动播放。

### 工程可落地性

- UI 状态是否能对应一个结构化数据模型，而不是靠文案猜状态。
- 工作面来源、操作权限、模型选择和结果落点是否是独立字段。
- 设置页的默认模型与 Composer 的临时覆盖是否有单一真相源。
- 会话、任务、产物和引用是否有稳定 ID。
- 新交互是否能复用 Nomi 现有组件，而不是在 HTML 样张里发明无法落地的控件。

## 11. 下一位 AI 必须执行的桌面回归

修复前先从刷新页面后的初始状态做一次基线回归；修复后再完整执行本节作为验收回归。至少覆盖一个普通桌面宽度和一个较窄桌面窗口。不要加入或验证移动端布局。

### 11.1 页面与布局

- 检查 HTML、H1、说明文字和实际形态数量一致。
- 检查 Agent Dock 实际宽度约 340px。
- 测量所有常驻按钮和选择器的高度、圆角、图标尺寸和间距。
- 检查所有可见文字没有与相邻控件重叠。
- 检查模型覆盖数量从 0、1、2、3、4 到 5 时输入栏均无横向溢出。
- 检查“策略自动”、最长技能名、最长提示词名和最长 Thread 名。
- 检查预览器与时间线始终在同一预览工作区。
- 检查浏览器入口在视觉和行为说明上都足够诚实。

### 11.2 输入与快捷方式

- 空输入、无 token 时发送禁用。
- 仅文字可发送。
- 仅附件可发送。
- 仅引用可发送。
- 文件选择和拖入均生成 token，最多数量逻辑明确。
- `@` 打开引用菜单，选择画布、文本、帧、时间线和网页引用后生成正确 token。
- `/` 打开技能菜单，选择和移除后状态正确。
- `Enter` 发送，`Shift+Enter` 换行。
- 发送后草稿与 token 清空，消息回显包含本轮必要配置。

### 11.3 技能、提示词、工作方式和模型

- 技能默认自动匹配。
- 鼠标悬停和键盘聚焦均更新技能演示。
- 图片、静音视频和无媒体说明三种预览都合理。
- 删除技能 token 后，发送快照确实恢复自动匹配。
- 删除提示词 token 后，发送快照确实恢复“不使用预设”。
- 工作方式/授权菜单选择后，触发器显示清楚且不溢出。
- 五类模型都能从自动切到具体值并恢复自动。
- 模型覆盖摘要与真实选择数量一致。
- 模型、技能、提示词和工作方式没有被合并成一个选择器。

### 11.4 跨工作面与结果

- 创作文本选区引用后，Dock 自动展开并显示可见 token。
- 画布节点引用后可回到原节点。
- 预览当前帧和时间线区间生成两个不同语义的引用。
- 浏览器选区保留来源语义。
- 结果“播放”进入预览工作区。
- 结果“画布定位”回到生成画布并产生明确定位反馈。
- 切换工作面后 Agent 的 Thread、任务状态和草稿不丢。
- 切换 Thread 后至少让用户清楚知道消息内容是否真的切换；不能只换标题伪装完成。
- 收起 Agent 后药丸显示当前最重要状态，点击可恢复。

### 11.5 键盘与状态反馈

- 打开菜单后等待一个 event loop，再断言第一个选项获得焦点。
- 上下方向键循环移动焦点。
- Escape 关闭菜单并把焦点还给原触发器。
- 点击页面外关闭弹层。
- `aria-expanded` 与实际开关状态一致。
- 每个看起来能点的控件都有可见反馈；否则改为非交互示意。

## 11.7 生成/预览共享时间线布局增量（2026-08-30）

真实 Nomi 页面中，生成工作区下方已经有主时间线，预览工作区也沿用同一条时间线。之前样张只在预览里演示，错误地让生成画布仍占满上方空间，无法验证用户实际会遇到的“时间线向上扩展、上方工作面让位”关系。

- 样张现在把生成与预览统一为“上方工作面 + 下方全宽主时间线”：生成页上方是画布，预览页上方是素材栏/播放器；两者的时间线都不再与 Dock 争夺横向列宽。
- Agent Dock 只停靠在上方工作面右侧，仍为 340px；它不会盖住下方时间线。生成画布和预览播放器在 Dock 展开时只缩短上方可用宽度，时间线保持全 Host 宽度。
- 两个工作区共用同一条可见分隔条（键盘焦点为 `role=separator`）：默认高度约 206px，可用指针上下拖拽或 ArrowUp/ArrowDown、Home/End 调整到 140–300px；时间线向上扩展时，上方生成/预览工作面同步缩小。
- 高度只在本次 Host 运行时保留，生成↔预览切换会保持同一高度，因为它们编辑的是同一条主时间线；离开这两个工作区或刷新样张时回到 206px，不做跨次进入的永久记忆。
- 这是样张层的布局合同，生产实现仍需决定真实时间线缩放刻度、Dock 在上方区域过小时的折叠阈值，以及是否提供快捷键。
