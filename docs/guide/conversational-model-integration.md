# 对话式模型接入

安装版 Nomi 可以通过 Codex、Claude Code、WorkBuddy 或其他带签名身份的 MCP 宿主接入模型。你只需要对助手说：

> 把这个 API 地址和官方文档里的模型接进 Nomi；需要密钥时请在 Nomi 里打开安全输入页。

助手会先用这个地址的 `/models` 或 `/v1/models` 接口探测模型清单，再让你在 Nomi 安全界面输入密钥。密钥只在 Nomi 主进程的安全存储里使用，助手只能看到“缺少 / 已保存 / 需要重新保存”等状态。带有 OpenRouter 架构字段的清单会直接推导输入输出能力；只有模型 ID 时优先匹配 Nomi 已有档案，匹配不到就按纯文本模型接入并明确标注。

如果中转站没有模型清单接口，助手会说明缺少什么，并请你手动提供 model ID；这条兜底不会伪装成已探测。探测完成后仍会用真实的最小生产请求做健康检查，确认模型确实可用。

“已保存”不等于“已接入”。Nomi 会用你实际选择的模型走一次正式生产入口，检查返回内容和媒体文件，再把通过的 mode 发布到普通模型选择器。某个模型失败不会拖垮其它成功项；页面会显示原因和唯一下一步。

ComfyUI 支持原生 Server 的 API workflow 和普通 Save/UI workflow。工作流中的图片、视频和参数按节点与 input key 显式绑定，不按控件位置猜字段；`frame_rate` 等数值不会被图片文件名覆盖。Cloud/Serverless 专用接口请按普通 HTTP provider 接入。

应用关闭或升级后，session、提交账本和已通过模型都从同一 userData 恢复。提交回执丢失时 Nomi 只用已保存的远程任务 id 对账，不重复创建任务。损坏的 session 会进入可诊断恢复状态，不会静默回退为空。

## MCP 配置

在 Nomi 设置里选择 Codex 或 Claude Code 的一键配置；WorkBuddy 或其它宿主使用“复制通用 MCP 配置”。配置带 Nomi 签名客户端身份，未签名的 `external` 身份只能读取公开描述，不能创建接入会话或启动会消耗额度的认证。

## 结果含义

- **已安全保存，尚未验证**：密钥已进安全存储，但还没有生产证明。
- **配置中 / 待补信息**：还缺完整模型声明、工作流绑定或用户回答。
- **部分完成**：部分 model/mode 已验证；其它项按页面给出的原因处理。
- **已验证可用**：正式生产调用、媒体验证、耐久提交和独立进程读回都通过。
