# LibTV 差距补齐：深度构建调研 + 对抗评测

## 第一部分 · 逐项深度构建调研

> 每项格式：**真实用户任务**（R16 口径）→ **候选路线对比**（R3 对比表）→ **架构落点**（改动触点）→ **关键调研结论**。
> 选型总原则：R20 build-vs-buy（通用能力用标准实现，护城河内自研）；P1 加新删旧（不留并行版）；P4 模型无关（能力走档案声明槽，不写供应商 if-else）。

### R1. 扩图（outpaint）

**真实用户任务**：「我有一张 3:4 的角色图，要在时间轴里当 16:9 视频的首帧，把画面补全。」

| 路线 | 做法 | 依赖 | 成本 | 风险 | 判定 |
|---|---|---|---|---|---|
| A. 基准图合成 + 图生图 | 前端 canvas 把原图按目标画幅居中贴底（边缘留白/镜像羽化），连同「补全四周，保持原图内容不变」指令发给现有图生图档案 | 仅复用现有图像档案（Nano Banana 2 / Seedream 5 Pro 均支持） | 零新增模型成本 | 留白处理不当会产生白边伪影 → 用镜像填充而非纯白 | **选 A** |
| B. 接入专用 outpaint 模型档案 | 找支持 mask+outpaint 的模型（SD 系/魔搭）新增档案槽 | 新增档案 + 对账工作 | 单独一份模型维护成本 | 与 A 产出差距不大 | 不选（R20：无必要） |

**架构落点**：`useNodeImageEditing.ts` 加 `outpaint` 动作；目标画幅选择复用现有比例枚举；合成基准图属轻量 canvas 操作（过 `check:heavy-path`：不进 store、不留双真相源）。
**调研结论**：Nano Banana 2 与 Seedream 5 Pro 对「外扩补全」指令响应稳定（两家官方文档均列 expand 能力）；唯一坑是低分辨率原图外扩后清晰度下降 → 生成后自动追加一档已有高清放大。

### R2. 重绘 / 擦除（inpaint）

**真实用户任务**：「这张图里的角色手部崩了，我涂一下那只手，说『改成握剑』，别的地方别动。」

| 路线 | 做法 | 判定 |
|---|---|---|
| A. 指令式精准编辑 | 涂抹生成 mask → 把「标注图 + 修改指令」发给 Nano Banana 2 / Seedream 5 Pro（两者官方均支持框选/指代式精准编辑，LibTV 对 Seedream 5 Pro 的宣传点也是这个） | **选 A 起步** |
| B. 传统 mask-inpaint 档案 | 接 SD-inpaint/魔搭 Edit 类档案，真·mask 输入 | 二期：当 A 在精细区域（手部/文字）失败率不可接受时再加，届时删 A 中对应妥协逻辑（P1） |

**架构落点**：涂抹 UI **复用画板节点（Leafer）的笔刷能力**，不自研涂抹组件；mask 导出为半透明叠加图 + 指令词进现有图生图请求。擦除 = 重绘指令为「移除该区域内容并自然补背景」的特例，同一链路，**不做两套**。
**调研结论**：指令式编辑在「大面积区域」表现好、「极小区域（手指、logo 小字）」偶有漂移 → 预设里带一条「仅修改标注区域，标注区域外保持像素级不变」的系统词。

### R3. 智能续写

**真实用户任务**：「这条 8 秒视频第 5 秒后的走向我不满意，从 5 秒开始接着拍，人物和场景别变。」

**构建**（无候选分歧，纯串联）：
1. 视频节点工具栏加「续写」→ 时间轴选起点（复用 ClipNode/切镜面板的选区交互）；
2. 起点帧抽取：已有 `extractVideoFrameToNode.ts`（≤ 起点用现帧抽取，> 起点已有 `return_last_frame` 能力）→ 落关键帧节点；
3. 自动新建 i2v 视频节点并连线（复用连线 API），续写提示词输入框预填上游 prompt；
4. 生成结果回流为普通视频节点，可再续写（链式）或直接进时间轴。

**架构落点**：一个面板 + 两个已有原子动作的编排，新增代码集中在一个动作文件（<300 行，R9）。
**调研结论**：Seedance 2.5 `return_last_frame` 已对账（`seedance25.ts:4-45`）；非 Seedance 模型走「抽帧 → i2v」通用路径，P4 兼容——续写能力声明放在档案槽（`supportsContinue: boolean`），UI 只对声明了能力的模型亮按钮。

### R4. 音频三件套（截取 / 变速 / 切分）

**真实用户任务**：「这段 BGM 只想要副歌 15 秒，还得加速 1.2 倍卡上视频节奏。」

**构建**：音频节点工具栏加三按钮，全部走主进程 ffmpeg（基建在 `electron/export/` 已有 20+ 文件）：
- 截取 `atrim` + 精度控件（复用时间轴选区交互的键盘习惯：←→ 移动、↑↓ 伸缩、I/O 打点——与 LibTV 一致，用户零学习成本）；
- 变速 `atempo`（0.5–2.0；超范围级联两段 atempo，调研已确认 ffmpeg 官方做法）；
- 切分 `asplit`+`atrim` 按时间点列表生成多音频节点。
**架构落点**：一个 `electron/audio/editAudio.ts` + 前端一个面板；产出落回画布为普通音频节点。
**调研结论**：无技术不确定项。唯一设计点：变速是否改音高（`atempo` 保音高，`asetrate` 变音高）→ 提供两档：节奏变速（保音高，默认）/ 磁带变速（变音高，创意用）。

### R5. 分离音视频 + 人声/背景音分离

**真实用户任务**：「这个参考视频的口播不错，把人声抽出来当配音参考；BGM 也留着以后套用。」

| 路线 | 做法 | 成本 | 质量 | 判定 |
|---|---|---|---|---|
| A. ElevenLabs audio-isolation API | `POST /v1/audio-isolation`，供应商栈已有 key 体系 | 按 1000 字符/分钟计费 | SOTA，≤500MB/1h | **先做 A** |
| B. 本地 Demucs / MossFormer2 | Python venv 拉模型，主进程子进程调用 | 零 API 成本，首次下模型 ~ hundreds MB | 接近 SOTA（MossFormer2 SDR 24+） | **二期做 B**，作为离线档（P4：同为档案槽，本地/云双声明） |

**架构落点**：分离音视频 = ffmpeg 一行（`-vn/-an`），与人声分离做成视频节点「音频▾」菜单的两项；产出为独立音频节点。
**调研结论**：Eleven 接口对流式/PCM 有延迟优化选项；本地方案与用户已有的本地 Whisper 先例同构，运维负担可控。**先 API 后本地**的原因：先用最小成本验证「用户真用不用」再投入本地打包工程。

### R6. 片段重拍

**真实用户任务**：「这条 30 秒片子里第 12–15 秒和第 22–24 秒动作不对，其他都好，只重拍这两段。」

**构建**：
1. 视频节点「重拍」→ 复用时间轴组件弹出选段层（多段选区，每段一个文字描述框）；
2. 每段生成一个重拍任务：`原段首帧（抽帧已有）+ 段落描述 → i2v`，任务组走现有依赖波次队列（`dependencyWaves.ts`）；
3. 结果预览用并排对比（原段 vs 重拍段），用户逐段采纳 → 自动替换回时间轴对应区间（走已有时间轴编辑 API + 撤销栈）。

**架构落点**：复用 R3 的抽帧与 i2v 编排 + 时间轴替换动作；新代码 = 选段 UI + 采纳替换逻辑。
**调研结论**：LibTV 同能力的时间粒度是毫秒级（本产品对齐到 0.01s 已够，视频模型首帧精度本身不高于此）；关键风险是「重拍段与前后段衔接」——缓解：采纳时提示可对相邻 1 秒追加续写衔接（复用 R3）。

### R7. 视频高清化 / 超分

**真实用户任务**：「这条 720p 的生成片段要放进 4K 成片，放大后别糊。」

| 路线 | 做法 | 成本 | 上限 | 判定 |
|---|---|---|---|---|
| A. Replicate real-esrgan-video | 新增 `videoUpscale` 任务档案（Replicate 接入先例：qwen-image-layered） | 便宜、按次 | ≤4K，短片快 | **选 A 起步** |
| B. runwayml/upscale-v1 / topazlabs | 同档案槽换模型声明 | 贵但质量高 | 4K/40s | B 作为同档案的高质量档（P4：一个档案多模型声明，非并行版） |
| C. 本地 Real-ESRGAN（ncnn-vulkan） | 零 API 成本，Mac GPU 跑 | 免费但慢 | 依机器 | 二期，与 B 同槽 |

**架构落点**：主进程新任务类型 + 接入常驻队列与进度面板（已有基建）；**长视频分片**：>60s 按 10s 分片并行 + ffmpeg concat（调研确认 concat 无缝需统一编码参数，分片边界在切点检测的静帧处更稳）。
**调研结论**：帧率提升（30/60fps）用 ffmpeg `minterpolate` 而非模型补帧——质量差异对生成素材可接受，成本差一个数量级；慢动作 = `setpts` + 变速联动（与 R4 音频慢放参数对齐）。

### R8. 音色克隆面板

**真实用户任务**：「录一段我自己的声音，以后所有旁白都用我的音色。」

**构建**（调研已确认 API 细节，见总览方案 B2）：
1. 音频节点 TTS 模式加「我的音色」入口 → 上传样本（10s–5min，mp3/m4a/wav）→ 调 MiniMax File Upload + `/v1/voice_clone` → 返回 voice_id；
2. voice_id 持久化在本地音色库（含名字/样本/试听）；
3. TTS 档案槽加「音色来源」声明：预设枚举 / 克隆库——**供应商差异由档案声明吸收**（MiniMax 克隆参数 vs Runway 参考音频 vs Eleven 克隆，同一 UI 三种声明）。
**架构落点**：`doubaoTtsArchetype.ts` 同目录新增 clone 槽位声明；音色库面板 ~400 行。
**调研结论**：国内版需企业认证 + 7 天不用即清（首次合成时收 9.9 元解锁费，需在 spend/ 消费确认中显式提示）；国际版无 7 天限制 → 两个区域声明写进档案（P4 样板案例）。**攻角预判见对抗评测 E8。**

### R9. 提示词预设大礼包（一次覆盖 10 项 🟡/❌）

**真实用户任务**：「给我这张图出一组多机位」「把 AI 味去掉」「这个人改成愤怒表情」……

**构建**：提示词库新增官方分组「LibTV 对标预设」，每组 = 调优过的提示词模板 + 注入动线 + 验收样张：
- 分镜预演组：多机位九宫格 / 剧情推演四宫格 / 25宫格连贯分镜 / 调度故事板；
- 质感修复组：人像去塑料感 / 电影级光影矫正；
- 表情组：情绪调节 25 表情词表；
- 构图组：镜头聚焦（框选→特写）、摄像机参数（相机/焦距/光圈片段库）、三视图/角色设定图、画面推演前后帧。
**架构落点**：纯数据 + 已有提示词库/切图/图生图链路；**零新模型、零新管线**。
**调研结论**：这是「无模型壁垒、纯调词」的活——每条预设的验收标准是与 LibTV 公开 showcase 同题对比，人眼判定不落下风。预估 3–5 天（大头在调词与验收，不在工程）。

### R10. 全局生成历史面板

**构建**：聚合画布所有节点 `runs[]` 的时间线视图（缩略图网格 + 按节点/时间/类型过滤），支持批量「发送到画布/下载」。
**架构落点**：数据已有（`canvasRunActions.ts`），纯新 UI 面板；批量操作复用素材库批量语义。
**调研结论**：唯一注意点是历史大时的虚拟滚动（素材库面板已有同款处理可抄）。

### R11. AutoLink 实时引用

**构建**：PromptEditor 输入时对画布内素材名/资产名做拼音+关键词模糊匹配（复用 `AssetMentionSuggestion.ts`），命中即弹出建议 chip：Tab 单收 / Shift+Tab 全收（对齐 LibTV 交互习惯）。
**架构落点**：一个输入监听 + 候选排序函数；匹配算法先中文别名表，不引分词库（R20）。
**调研结论**：LibTV 的匹配是「名称一致或语义相似」——一期做名称/别名精确+模糊，语义相似（embedding）二期再看真实使用率。

### R12. 逐帧拉片 → 多参考闭环

**构建**：拉片结果面板每个镜头加「用作参考」→ 镜头首帧落关键帧节点 + 镜头运镜/画面描述注入目标视频节点 prompt（走已有参考槽与 mention 体系）。
**调研结论**：原子能力全齐（拉片、抽帧、参考槽、mention），只差动线编排。

### R13. 深度动作捕捉（观望项 · 调研结论）

Replicate 有 depth-anything-video 现成 API；本地 DepthCrafter 时序更稳但需 GPU。**先做一周 spike**：拉 3 条真实视频提深度 → 喂 Seedance 2.5 多参考 → 与不喂深度对比。收益不显著则关闭此线（写进 lessons，防止半年后再议）。**不预先排期，spike 结论决定生死。**

### R14. 智能剪辑编排（独立大项 · 立项预告）

口播去口水词（Whisper 时间戳已有 → 定位口水词/停顿 → ffmpeg 剪）、字幕上屏（时间轴文本轨已有）、批量广告变体（产品图 × 提示词模板矩阵 → 波次队列已有）。**地基全在，缺的是「一句话任务 → 编排计划 → 时间轴成片」的 Agent 编排层。**按 R4 单独写 `docs/plan` 立项，不在本批次。

## 第二部分 · 对抗评测（红队评审）

> 评测方法：设三个红队角色，对第一部分每条方案做定向攻击——
> **T1 功能击穿者**：复现 LibTV 原始 showcase 用例，证明方案解决不了或体验差；
> **T2 架构洁癖**：审计是否违反 P1（并行版）/P4（供应商耦合）/R2（信息噪音）/R9（巨壳）/R15（i18n）/R17（重活）；
> **T3 边界与成本审计**：极端输入（超长/超大/失败/断网/退款）与成本爆炸。

### 逐项对抗评测表

| # | 方案 | T1 功能击穿尝试 | T2 架构审计 | T3 边界/成本 | 结论 |
|---|---|---|---|---|---|
| E1 | 扩图 A 路线 | 攻击：极端画幅（1:8 竖幅）外扩，模型可能把留白区画成第二主体 → 缓解：极端画幅限走「多次递进外扩」（每次 ≤2 倍面积） | 通过：无新增档案、无供应商耦合 | 攻击：6K 外扩请求超模型输出上限 → 档案已有尺寸校验拦截并提示分段 | **PASS** |
| E2 | 重绘指令式 | 攻击：小区域（手指）编辑漂移 → 系统词兜底 + 失败可「提高标注区域占比重试」；真不行走 B 路线（预案在案） | 攻击：擦除与重绘是否两套？→ 确认同一链路特例，无并行版 | 攻击：mask 图是否 base64 进 store？→ 违反 R17；走临时文件路径传递 | **PASS（带预案）** |
| E3 | 智能续写 | 攻击：非 Seedance 模型抽帧续写画风漂移 → 这是模型物理极限非方案缺陷；缓解：续写预填上游 prompt + 首帧锚定已是最优实践 | 攻击：`supportsContinue` 会不会变成第二套生成入口？→ 不会，仍是 i2v 请求，只是参数预填 | 攻击：链式续写 20 次导致节点爆炸 → 每次续写产出独立节点自然成链，画布语义自洽；无限流问题 | **PASS** |
| E4 | 音频三件套 | 攻击：变速后音高失真 → 双模式显式暴露，默认保音高 | 通过：ffmpeg 标准滤镜，无自研 DSP | 攻击：2 小时长音频全轨 atempo 卡 UI → 主进程后台任务 + 进度条（复用队列） | **PASS** |
| E5 | 人声分离 | 攻击：纯音乐无人声，Eleven 返回什么？→ 调研：返回近似空白轨；UI 需提示「未检测到人声」而非静默空文件 | 攻击：先 API 后本地是否双实现？→ 是**同槽双声明**（云/离线档），P4 允许且必要；本地上线时不删 API 档（两者质量/成本互备，属能力档位非并行版本，此判定记入 ADR 备查） | 攻击：Eleven 计费失控 → 走 spend/ 消费确认，>阈值需授权 | **PASS** |
| E6 | 片段重拍 | 攻击：重拍段与原片色调不一致，拼接突兀 → 缓解：重拍 prompt 自动携带原段拉片描述（复用 R12）+ 相邻续写衔接；体验上限=模型极限，方案已到最优 | 攻击：选段 UI 与剪辑 UI 是否重复造？→ 复用同一时间轴组件，仅新增选段层 | 攻击：8 段重拍并发成本 → 波次队列天然限流 + spend 确认 | **PASS** |
| E7 | 视频超分 | 攻击：60 分钟视频跑超分，用户等到天荒地老 → 硬性上限：单次 ≤10min，超限引导分轨；分片并行已规划 | 攻击：分片拼接边界闪烁 → 切点检测静帧处切 + 统一编码参数（调研已确认） | 攻击：Replicate 限额/宕机 → 档案槽多模型声明（A/B/C 三档），一键降级 | **PASS** |
| E8 | 音色克隆 | 攻击：**克隆他人声音**（伦理/合规红域）→ 采集时强制朗读随机校验句（MiniMax `text_validation` ASR 相似度校验，官方接口自带）+ 本地留存授权确认记录；这既是合规也是产品信任资产 | 攻击：三供应商三种克隆参数是否三套 UI？→ 否：档案槽声明「音色来源类型」，UI 一套 | 攻击：7 天失效（国内版）静默失败 → 音色库标注有效期 + 合成失败时明确报因；解锁费走 spend 确认 | **PASS（合规项为硬门）** |
| E9 | 预设大礼包 | 攻击：预设效果不及 LibTV showcase → 验收标准即「同题对比不落下风」；个别预设（如 25 宫格连贯性）可能达不到 → 上线时按实测分级：达标进官方组，未达标不硬上（宁缺毋滥，R2） | 攻击：预设是否 hardcode 进代码？→ 进提示词库数据文件，可更新不发版 | 成本：纯提示词，无新增成本面 | **PASS（验收即门槛）** |

| E12 | 拉片→多参考闭环 | 攻击：注入的运镜描述与用户 prompt 冲突 → 注入内容以可编辑草稿形态进 prompt（不静默追加） | 通过 | 通过 | **PASS** |

### 对抗评测总评

- **12/12 PASS，其中 2 项带预案**（重绘的 B 路线备胎、人声分离的双档声明需 ADR 备查）；
- **1 项升级为硬门**：音色克隆的「采集端本人校验」是合规红线，不通过则功能不上线；
- **方案整体优雅性结论**：14 项补齐中 **0 项引入新供应商耦合 if-else、0 项产生并行版本、4 项复用画板/时间轴/队列等既有基建、3 项复用同一链路（重绘/擦除/标注；续写/重拍/衔接）**——P1/P4/R20 全部成立；
- **体系级剩余风险（红队无法在本方案内消解，明示）**：① 指令式编辑模型的「区域精准度」是供应商能力，Nomi 只能靠系统词与备胎路线缓解；② 超长视频（>10min）的高清化在本地 Mac 上不可行，是硬件边界不是方案边界；③ LibTV 的 5min 一键直出属于供应商侧能力，若 apimart/供应商开放同能力，Nomi 走档案槽当天可接（radar:models 持续盯）。

## 第三部分 · 量化验收门（「解决得好不好」的判定标准）

每个功能交付时必须同时满足（缺一不算完成，P3/R16）：

| 维度 | 门 |
|---|---|
| **功能通过率** | 5 条真实用户任务（含 1 条极端输入）端到端跑通率 100%；LibTV 同题 showcase 复现 ≥4/5 达到「可用」人眼判定 |
| **对照基线** | 与 LibTV 同功能结果并排截图对比，不落下风（记录对比表进 PR 描述） |
| **优雅性** | `check:tokens`/`check:filesize`/`check:heavy-path`/`check:vocabularies`/`check:i18n` 全绿；无新增供应商分支；删旧清单齐全（P1） |
| **成本** | 单次典型使用成本明示在 UI（走 spend/）；无意外计费路径（音色克隆解锁费、Eleven 分钟计费必须前置提示） |
| **失败路径** | 每个功能至少 1 条失败场景（断网/超限/模型拒绝）有明确人话报错与下一步指引（R2：报错有行动价值） |
| **回归** | `test:system:focused` + contracts 全绿；真实浏览器走查截图人眼确认 |

**整体方案的「最终对局」判定**：P0+P1 交付后，用 81 项对比表重测一遍——目标：❌ 缺失从 14 → ≤2（只剩深度动捕与智能剪辑编排两个大项），🟡 从 16 → ≤8；届时 LibTV 对 Nomi 的功能面优势清零，叙事切换为「Nomi 领先项 17+、追平项 60+」。
