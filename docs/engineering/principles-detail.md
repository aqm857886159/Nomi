# 核心原则全文（L2）：P2 · P3 · P5

> 从 CLAUDE.md 搬来的完整表述；CLAUDE.md 只留各一两行。**用到时怎么保证看到**：`self-check.sh` 在用户消息含「bug / 回归 / 根因 / 修」（P2）、「做完 / 修好 / 验收 / 走查 / 交付」（P3）、「设计 / 样张 / 界面 / 新页面 / 重做」（P5）时注入对应一段的指针；P2 另有 `root-cause-remediation` 技能；P5 另有 `nomi-design-flow` 技能。

**P2 修根因不修症状** — 任何 bug、回归、CI/平台失败、性能/安全问题或审计发现，动生产代码前必须执行 `.agents/skills/root-cause-remediation/SKILL.md`。详细流程住在该 skill；L1 判断闸：分清症状/直接原因/类根因，判断 `one_off`/`recurring`，实扫同类入口，修在最早共享边界。**先数门**：动生产代码前跑 `node scripts/door-map.mjs <mutator 符号或文件>` 数清这份状态的全部写/读入口，门表进合同 `doors`（R21.3）——「实扫同类入口」不许再靠人临时 grep。自检：「同类问题还能从另一个调用者、供应商、版本、平台或旧数据回来吗？」答不出"不能" = 没解决。

**P3 全绿 ≠ 完成** — CI 五门只证代码健康，证不了体验对不对。用户可见改动报完成前：① 和获批样张逐项并排对账；② 真体感走查（Playwright 截图人眼判断，不是 expect 断言）。缺一不算完成。**功能交付（尤其用户可见/体感）另过 R13 第二档（原 R16）：建几条「真实用户任务」端到端测试系统、带着真实任务跑通整个使用闭环、把过程中冒出的体验/设计/UI/UX/产品感/功能问题全修掉——才算真完成（2026-08-01 用户拍板：不留半成品）。**

**P5 想清楚再动手** — UI 改动先读设计系统 `docs/design/nomi-design-system.md`（token/组件/规范）再画，再由设计实验室用生产组件 + 真实宿主数据（ShellStage 手法）出屏并用户拍板；手写 HTML / widget 只作标明的 `exploration` 方向探索，不能作实现合同；**改/扩现有 UI 先看它真实样子**（读完整外壳组件或真实截图，样张是真实布局+改动、不是脑补）；**接线前先看真实数据**（实验室组件必须由真实宿主数据驱动；基线绿≠可接线）；**加/挪控件先过 §1.5 控件层级规则**（L1 常驻/L2–L4·一功能一个家·先分组→去重→归位→最后才收纳）；架构改动先查 Context7 + 读顶尖开源代码 + 6 角色评审；多文件改动先写 `docs/plan` 文档；**动手前先 grill**（2026-09-11 用户拍板）：重要改动（产品行为 / 架构 / 外部契约 / 用户可见流程 / 花钱边界 / 会连带别的面）派实施前，先按 grill-me 方式把问题**一轮批量**问清——每题带默认答案、**连带面单独成题**（同一组件多宿主、改 A 面会带动 B 面的，必须单独问「B 也变吗」）、直到没有静默假设；讨论定不了的先做可丢弃原型再回来问；纯 bug 修复（根因明确、不改行为）不问，参考 https://aihero.dev/skills-grill-me 。
