# 类根因复盘：花钱文案从事实滑成承诺

## 0 一句话根因
花钱相关词条没有统一的“事实来源/未知即不承诺”边界，新增入口可以直接写“免费、预算、已花费”而没有被现有 no-cost 检查覆盖。

## 1 归类表
| 提交 / bug | 直接原因 | 类根因 |
|---|---|---|
| 取回失败提示写“免费重取” | 词条把“不会重新生成”偷换成“免费” | 文案没有绑定已知价格、实际扣款或本地执行事实 |
| KIE 上传写“免费解锁” | 接入能力与费用承诺混在一条宣传语里 | 供应商/上传通道词条绕过统一花钱判据 |
| 模型标签写“免费” | 历史目录标签把供应商额度当成普遍零费用 | 词典没有按账户、额度和时间限定外部价格事实 |

## 2 为什么反复出现
词典是多个入口的共享事实面，但检查器只覆盖“不花钱/不收费”句式，并通过白名单放行少数历史词条；“免费额度、免费上传、免费重取”仍能从其他键进入用户界面。

## 3 不改结构的预测
| 预测 | 验证 |
|---|---|
| 新增“免费”变体会绕过现有测试 | 给词典加入 `免费上传` / `free retry` 夹具并运行现有 i18n 测试 |
| 同一事实在 zh/en 会漂移 | 对加载后的双语词典按 key 扫描禁用词 |
| 只改一个入口会在桌面文案复现 | 同时扫描 `desktopStrings` 与 renderer 词典 |

## 4 P0
这是领域独有的“花钱语义与用户确认”约束；通用 i18n 库不能判断供应商费用事实。接入现有词典加载和测试基础设施，不重写框架。

## 5 接入 / 补 / 重写 / 删
| 选项 | 代价 | 风险 |
|---|---|---|---|
| 接入现有 `check:i18n` 与词典加载 | 低 | 仍需维护明确白名单 |
| 补更多分散正则 | 中 | 继续漏掉新词形 |
| 重写整套 i18n | 高 | 触及大量无关词条 |
| 删掉无法证明的承诺 | 低 | 少量营销语变中性 | 采用 |

## 6 用户权衡
用户要的是在提交前知道“这次会不会产生可归责的费用”；中性地说“价格暂时算不出/重新拉取结果”比给出一个未经证实的零元承诺更诚实。

## 特征测试
现有：`scripts/check-i18n-no-cost-claims.node-test.mjs`。
新增：同一测试覆盖“免费上传/免费重取/Free upload/free retry/￥0/$0”等变体，并保留只因本地离线能力或明确外部官方额度而存在的白名单理由。
## 触发的自写登记
- `gate-family`（under-review）：本次只是扩展仓库已有的 i18n 事实检查与词典白名单，不能替换为通用库，因为“免费/未知/已扣款”的判定依赖 Nomi 的领域语义与现有键级白名单；通用 i18n lint 不知道哪些本地能力、供应商额度和非花钱语义可保留。目标迁移日：2026-12-01；迁移前提是把 Nomi 的花钱事实契约导出为稳定 schema，并由通用 lint 只执行 schema，不再维护领域正则。

## 放行

- 2026-10-08 协调会话放行：只改花钱相关的静态文案与现有 `check-i18n-no-cost-claims` 扫描器（禁用词扩到预算 / 已花费 0 / ¥0 / $0 / 免费），真事实保留（「重新拉取」取回已生成结果不扣费）；不改计价、扣费、预算逻辑。任务中心、制作详情两处截图由独立验收线补。
