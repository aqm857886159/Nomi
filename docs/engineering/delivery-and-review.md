# 交付与评审（L2）：push 前分层 · 交付身份 · 合并前检查

> 从 CLAUDE.md 搬来（规则体系瘦身）。**用到时怎么保证看到**：`self-check.sh` 在用户消息含「合并 / merge / 收据 / verify-merged / preflight / 开 PR / 交工 / 推送」时注入【交付】块（带合并规矩要点与本文件指针）；CLAUDE.md 的「常用命令」一节也直接指向本文件；push 时 pre-push 闸门自己拦没过的。
> 详解在 `docs/engineering-rules.md` 的 R11 / R22；编排侧见 `docs/engineering/agent-orchestration-playbook.md` §19。

## Push 前按风险面分层（R22）

contracts 始终跑（一次跑完全部门岗再汇总，不再第一个红就停；`check:concept-owners` 只出 warning 不阻断；`check:docs-index` / `check:doc-status` / `check:ledger` 已移出 PR 的 Contracts——合入 main 后由 `docs-autosync` workflow 自动补齐回写；档案默认值生成物由 `archetype-autosync` 工作流自动重生成；`check:root-cause-contracts` 只对 schema 不合法阻断）；unit 独立选 focused/full（**本机 `pnpm run gates` 也按同一份 `scripts/validation-policy.mjs` 分档**，全量一万两千多个测试交给 CI 并行机器，不再占着全机那把 gates 锁；想本机兜底跑全量用 `pnpm run gates:full`）；Electron、真实旅程、React Flow 画布、性能和 macOS package 各按受影响路径独立触发，`main` push 也按真实 `before..after` 分类，不因事件名自动全量。删除/重命名、空 diff、测试/CI 分类器自身和手动发布边界 fail-closed 到全维度。连续小修先在本地收敛，再一次性验证和 push，不让每个微提交反复触发全套 CI。

## 交付身份只走统一命令（R11）

任务开始先跑 `delivery:preflight`；PR 合并后**立即**在 Git fetch 得到的真实 merge SHA 上跑 `delivery:verify-merged`：非纯文档的 merge 必须看到该 SHA 上 `Core Flow Smoke (empty)` / `(used)` 都是 success 才发收据（skipped / 缺席一律拒绝）。**合并规矩（2026-10-01 用户拍板；只由协调会话做，其他会话开 PR 后把号发给它、不自己合）**：CI 绿 + 扫描干净就合；**最多 3 个合并在等收据**（`quality-gate.yml` 按 SHA 分组，每个合并提交各跑一套），任何一个收据红了**立刻停止再合**，交人定修还是回滚（冒烟红了不自动回滚）。任务 commit、PR head、merge commit 与 tree 分开报告；禁止用 REST compare 文件列表重建 Git tree/commit，禁止把 `same-tree-different-commit` 叫成代码不匹配。

## 合并前检查：设计卡 + 独立验收（取代旧的交工前评审，R24 由 PR #223 保留）

2026-10-02 起，原来的交工前评审（适配器、收据、延后账本、`review:branch`、PR 正文评审小节）整套删除，用两个暂停点代替：

- **暂停点①设计卡**：碰花钱 / 长跑 / 可打断 / 新界面，动手前写一页卡（`docs/engineering/design-card.md`），PR 正文 `## 设计卡` 放链接或全文；其余改动只填 ★ 格。
- **暂停点②独立验收**：四类改动合并前由另一条线验收，PR 正文 `## 独立验收` 带报告链接和验收线编号，编号不得与实现线相同。
- **协调会话合并前跑** `node scripts/merge-preflight.mjs <PR 号>`：按路径判是否四类、查卡格是否填全、查独立验收、修逃逸 bug 时查带 `detected_by` 的根因合同；碰到规则 / 门岗文件（CLAUDE.md、rules.json、`scripts/check-*`、门岗基线、workflow 等）时正文「碰到的规则与门岗」一节必须逐个点名、整文件删除写「删除：理由」，逃逸账本条目不许消失（#1032 用旧分支回退 #1031 后加）；**路径推出「花钱」类的 PR 还查真付费证据行**（见下文「花钱路径的真实验收」，2026-10-16 起）。脚本只打印结论，不合并。

## 用户可见改动的验收交付：测试表 + 真截图 + 验收页（2026-09-29 用户拍板）

- PR 正文有「用户能力变化：新增 / 改变 / 去掉」三栏，**去掉或挡住已有能力必须用户点头**；再附测试表（编号 ｜ 在哪、做什么 ｜ 应该看到什么 ｜ 我们的结果 ｜ 用户的结果），新装机 / 老装机升级、中文 / 英文分开列，每行是用户能照着做的动作，不写代码术语（五层体系见 `docs/plan/2026-09-29-quality-system.md`）。
- 我们先把表**逐条真跑完**：截图必须来自要发的那个包、自己亲眼看过每一张，至少一次真实调用，不能全是本机模拟。
- 交一个**验收页**（每行测试表配截图，不通过的排最前，带勾选框），用户扫一遍打勾就算验收；单个改动不要求用户装测试版亲手试。**发版前用户亲手用候选版 30 分钟那一关保留**：截图只能验我们想到的路，没想到的路只有亲手用才碰得到。
- 门岗、文档、测试基础设施这类内部改动不需要验收页。
- 删内置的老模型**不许自己直接删**：先出「建议删除」清单，每个写明证据（上游还在不在、是否被同家新版取代、用户项目里用过没有），用户逐个勾选后才删；旧项目里用过的节点要照常能打开（显示「模型已下架」，不报错），PR 正文列勾选记录。

## 花钱路径的真实验收

- **花钱路径（生成、派发、认领、授权、下载落盘）的 PR，合并前必须有真 App 按用户动作走一遍的收据**。零额度夹具 + 离屏真 App 只是前一步，真实测试 = 真 App + 真模型 + 真实任务闭环（结果落到节点，请求次数与预期对得上）；不能拿「pending-real-app」一直挂着。
- **绕过真实边界的测试不算证据**：直接往仓库写数据、跳过 IPC / 校验层、前提状态和真实调用顺序不符。2026-09-29 的真额度验收就查出测试直接写 detach 绕过了 IPC 校验，全绿但功能是坏的。查到吞错（空 `catch {}`）当同类问题扫全仓并用门岗拦新增（渲染层空 catch 曾把主进程的拒收吞了一个多月）。
- **花钱路径合并前，由协调会话亲自用真模型做最小量验收**：动手前先写清要证什么、最少几次请求、为什么少了不够，能用零额度夹具证明的就不花钱、同一条路径不重复花；跑完核对实际请求次数与预期一致，并如实报告（不知道就写「未知」，不估数）。子 agent 不认转述的同意，所以不由它们跑；隔离纪律照旧：不碰用户真实资料，跑前跑后核对，跑完清理。
- **这条有门岗了（2026-10-16）**：路径推出「花钱」类（或设计卡「功能分类」勾了花钱）的 PR，合并前扫描（`scripts/merge-preflight.mjs`）要求正文 `## 验收证据` 里有一行 **`spend-paid-sample：<运行号 / 报告链接>`**（协调会话跑的最小量真付费抽检的凭据），或 **`spend-paid-sample：协调豁免：<理由>`**（协调会话明示豁免；理由至少几个字，扫描会把它醒目打在报告里，合并前再看一眼）。没有这一行就红、不合。**不放行**：「未验证：…」、裸 PR 号（`#1203`）、别名行（「真付费：…」）——别的证据项接受「未验证」，这一项不接受。只有合并前扫描判这一条（`paidStrict`）；CI 的 `check:pr-judgement` 与推送前口径不变，免得 PR 一开就红到真付费跑完。豁免正文谁都写得出，所以它不是权限，只是把「跳过」变成合并前一行看得见的字。起因：#1203（Agent 权限两档 + 两刹车，花钱类）写了一行「未验证」，扫描绿、CI 绿，被合并循环合入，真付费验收被跳过——门槛只写在上面这几条文字里，没有门岗。
- **真付费只跑一次（2026-10-17，规则 P3）**。前置三关缺一不跑：①同一脚本、同一构建的免费本地演练（loopback 夹具）先过；②构建成功，且产物含被验修复的标记——标记用**会原样进产物的字面量**（界面文案、错误码、日志前缀），函数名 / 变量名会被压缩，不能当标记；③在无人改动的专用工作树里跑（别的线在同一工作树改文件会让构建失败、走查跑在旧产物上）。②已由入口强制：`tests/ux/_paidRun.mjs` 的 `openPaidWalk` 开跑前调 `assertPaidBuildReady`，核两件事——构建戳（`scripts/package-build-stamp.mjs` 的 `verifyBuild`，戳 = 构建当时的源码树指纹，源码之后又变过、构建失败或没构建都对不上）、调用方传的 `buildMarkers` 逐个在 `dist/`、`dist-electron/` 里找得到；不满足抛错拒跑，在建隔离副本、拷凭据之前，一分钱不花（`--packaged` 跑安装包自带产物，不适用）。验某个修复的付费走查必须传 `buildMarkers`。另：**产品规则一改，同一个 PR 必须同步改对应的付费走查**（不然走查按旧预期判失败，白花一次）。必红测试 `tests/ux/_paidRun.test.mjs`。
- 用真实资料副本测试前必须断开副本与真实项目的联系，见教训 [资料副本里的项目登记会指回用户的真实项目](lessons/profile-copy-registry-points-at-real-projects.md)。
- **变异校验（「改回旧行为必红」）**：先做 WIP 提交或只备份被变异的那一个文件，用备份还原并核 SHA，**绝不 `git checkout -- <目录>`**，见教训 [变异校验用单文件备份还原](lessons/mutation-check-restore-one-file-not-the-directory.md)。

## 一次做好，不反复验证（2026-10-17 用户：「不能反复出现问题 反复验证 反复测试 最好一次性做好」）

**实证**：一次视频取回修复验了 6 轮，每轮验收线找到一类新反例，实现线才去修；一项权限两档的真付费验收跑了 5 次，其中 2 次是流程失误白跑（见上文「真付费只跑一次」）。共同点：该想的类没在动手前想全，检查项是验收线边验边想出来的。

1. **验收清单前移**（规则 DC，设计卡 ★9）：派活时，把验收线会用的全部检查项与反例写进任务书 / 设计卡 ★9；实现线按同一份清单自验，交付附「反例 → 结果 → 证据」表才算交付；验收线**只核这份清单**，不临时扩范围。验收中新发现的先记后续，除非属于「本 PR 引入 + 丢数据 / 花错钱 / 崩溃 / 安全」——这一类必须当场拦。
2. **同类一次想全**（规则 P2）：修 bug 交付前列出这一类会从哪些入口、形状、边界、版本回来（`door-map` 的入口表是起点），全部写成测试；只测报错的这一例不算完成。
3. **真付费只跑一次**（规则 P3）：前置三关，见上文「花钱路径的真实验收」。
4. **二次不过先找根因**（规则 RW，与「同一条线第 3 轮修补」合并）：同一 PR 的验收第二次不通过就停下，先答「为什么前面没想到」，把漏掉的那一类补进验收清单与门岗，再继续修。

## 减少评审返工（2026-10-09 用户问「为什么不能一次审完」）

**实证**：同一天 #1135 三轮都是同一类判忙与安装不同刻（第三轮才收成唯一安装入口）；#1133 三轮都是「出处边能被伪造」；#1128 拍板写死的「逐项勾选」实现线没做，推送前也没对出来；4 个 PR 本机检查全绿、CI 却各红几处。每轮修复产生新代码、要再审；一轮 CI 40 分钟。返工的主因不是评审漏，而是：修了实例没修类、设计阶段没人问「怎么被绕过」、交货不对合同、本机检查和 CI 不一致。目标：每个 PR 从 3–4 轮降到 1–2 轮。

1. **先审设计再写码**：花钱、数据、安全边界类改动，动手前先让独立线对设计卡 + `door-map` 做一次「怎么被绕过」审查，审过再写。
2. **第一次就修一类**：每个评审发现先归类，修法覆盖整类入口；协调会话出修法时也按这条把关，不等到第三轮。
3. **交货前自审 + 合同对账**：实现线用对抗评审模板（`codex/templates/adversarial-review.md`）自审；PR 正文「## 合同对账」逐条列用户拍板及证据，缺一条不推。
4. **本机检查和 CI 对齐**；修 CI 红和修评审意见合在同一轮。
5. **复审 = 全量看一遍 + 核上轮**，不只核上轮那几条。
6. **任务书列全连带界面**：凡是新能力，合同要逐个写出它在现有界面露出的每处文字（回执 / 通知 / 任务列表 / 错误卡），验收逐行核对「说的 = 做的」。2026-10-09 「给 Agent 加写正文的工具」看着是后台改动，其实会在回执上露一行字；任务书没写这行字该说什么，面板按工具名片段猜，显示成「创建或修改镜头卡」，验收只核了工具名没核面板上的字。
