# 方向检查：预演量尺的量测主体在复制层时丢了（RW）· 2026-10-31

> 触发：CLAUDE.md P1「同一 PR 验收第 2 次不过」。#1385（预演共用量尺）第 2 次独立验收有条件通过，挡合并的一条是：复制场景层、跨层复制、导入场景之后，副本里每台编译机位的量测主体还指着旧对象，30 份计划共 57 镜全丢景别、24 镜运镜读错（推近显示成右横移），不报，界面头上还写「实测值」。main 上没有这个问题，是这个 PR 新加的持久化字段引入的。
> 结构性结论由用户拍板，见文末「裁定」。设计卡：`docs/plan/2026-10-30-previz-ruler.md`。

## 0. 一句话根因

场景里有好几种字段引用对象 id，但没有一份清单。每加一种新字段，都要靠人记得去改复制、导入、删除这些按字段名点名的地方；门图工具只能数「写了哪里」，看不见「该写没写」。

## 1. 归类表

| bug | 直接原因 | 类 |
|---|---|---|
| 复制场景层、跨层复制、导入场景后，57 镜全丢景别，24 镜运镜读错，不报 | `remapSceneIds` 换了父子、看向、特写目标的 id，唯独没换 `camera.measurementSubject.objectId`（本 PR 新加的字段） | 引用 id 的字段没有单一清单，新字段漏改写门 |
| 第 1 次独立验收的「损坏锚点被正规化成整个人」（已修） | 正规化把非法锚点丢了，退回量整个人 | 同一个新字段的另一扇门没想到：写门之外还有正规化门 |
| 重编译救不回失效记录，回执还说「手改被替换」 | `deriveDirectorOverrides` 按属性泛型遍历，把失效的 `measurementSubject` 当成手改，重编译时盖掉编译器写的有效值 | 同一个新字段的第三扇门：手改覆盖门 |

三个都不是量具的算法错，都是这个新持久化字段在某一扇门上没被接住。

## 2. 为什么这一类会一直出现

- 设计卡 ★2 写「编译器唯一写入」，没把 id 改写和手改重放算成写。
- `door-map` 按名字数入口：`remapSceneIds` 和 `planOverrides.ts` 里一次都没出现 `measurementSubject` 这个名字（前者按已知字段逐个点名，后者按属性泛型遍历），所以数不到；「该写没写」本来就不是一个能被按名字数出来的东西。根因合同当时搜这两处都是 0 处。
- 门测试（`directorStore`、`directorSceneTransactions`、`storeAssetActions`、`planOverrides` 两份）5 个文件 62 项全绿，里面一次都没提这个字段：它们只测已知字段。
- 同类的点名处还有 `deleteObject`、`copyEntitiesToScene` 里别的字段处理，新字段都要靠人记得同步。

铁律 ⑩「说的=摆的」：界面头上写「实测值」，副本层显示的却是错的。结账挂的类检查见下面第 6 节和特征测试清单。
