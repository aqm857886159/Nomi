# 方向检查：托管同意只保留设置开关

全图：素材发出前的权限交接，属交接表外；与「生成结果→项目」不同。入口清单见 docs/plan/2026-11-17-hosting-setting-only.md ★9。

### 0. 一句话根因
界面和执行层分别决定是否允许托管，调用方能够自行补一个 allow；之前的签发与兑换修补又把自授口搬到了签发处。

### 1. 归类表：bug → 直接原因 → 类
| 版本 | 直接原因 | 类 |
|---|---|---|
| main / 0.24.1 | 发送端按本地参考填 allow，上传循环缺省 allow | 决定与发送分家 |
| 第一轮许可修补 | 兑换接口接受空范围和缺省同意 | 缺少人的决定边界 |
| 第二轮许可修补 | 无待决确认即可签发；独立验收无卡也拿到许可 | 自授口迁移 |

### 2. 为什么这一类会一直出现
实现测试只查凭据真假，不查它如何产生；字段扫描无法约束真正批准权。对应铁律⑫「点了=以为的」：点生成不能被解释成额外允许公共托管。独立方向检查已对两轮修补做过只读复盘，本轮按用户 2026-11-17 决定删掉按次同意。

### 3. 不改结构的话，接下来会冒出什么
| 预测 | 验证 |
|---|---|

| 新匿名通道绕过循环 | 边界检查引用/硬编码匿名端点必须红 |

### 4. 靶子独立性检查
既有两次独立验收证明了自授，方向复盘由未参与实现的线完成；其推荐 B 保留主进程待决，但明确 C 需要产品决定。用户已接受 C 的取舍，本轮不合入两次修补。没有修对后被评测回滚的证据。八条反例按动手前设计卡，不倒写判据。

### 5. P0：独有的是什么，复用什么
素材能去哪是创作领域的边界；设置、上传通道顺序、现有失败卡均已存在。复用现有设置读写，不新增库、计划、签发或兑换协议。边界检查复用仓库归属/依赖检查。

连带命中自写登记 `network-stack`：现成路线优先是登记已列的 undici ProxyAgent（https://undici.nodejs.org/#/docs/api/ProxyAgent）、socks-proxy-agent 和 Electron session.setProxy。本次只把 `proxyProbe.ts` 对匿名通道定义的读取换成上传模块提供的 origins；不改代理、dispatcher 或网络判据，也不新增网络栈分支。代理库不能替创作者决定是否允许匿名托管，而任务要求保持代理配置和通道顺序，所以此次不把通用代理栈迁移混进权限删除。沿该登记既有的 2026-11-30 复查日评估接入方案；整体替换日期尚未确定，不将本次计为已完成网络栈迁移。

### 6. 三条路对比表 + 选择
| 路 | 做什么 | 代价与风险 | 选择 |
|---|---|---|---|
| 沿原方向修 | 主进程待决后签发、再兑换 | 维护凭据、取消、范围与批量生命周期 | 不选 |
| 换一种做法 | 主进程待决后直接执行 | 少一层凭据，仍维护按次批准状态 | 独立复盘推荐，本轮不选 |
| 删掉 | 删除确认披露与所有按次允许字段，仅设置 allow 可用第三方图床 | 丢失一次性限定素材授权；ask 走不通时要去设置开关 | 用户 2026-11-17「删掉，用设置开关」，已选 |

最小删除单位是按次托管同意，不删供应商/中转上传与失败换路。旧 allow 保留、ask 关闭、deny 和未知读成 ask，存储格式不变。

### 7. 用户要权衡的核心
少维护一套按次同意，代价是需要第三方托管的人要明确开启长期设置；用户已经接受。

特征测试：现有 assetLocalization.test.ts 的通道排序、413 换路与真实旧版资料；本轮新增回环字节类检查。系统改进结账挂共享上传循环与边界检查，预测为开关关闭匿名接收 0、自授口 0，候选提交交独立验收时复查；不通过即重开方向判断。
