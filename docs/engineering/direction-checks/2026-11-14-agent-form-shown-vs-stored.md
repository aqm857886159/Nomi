# 方向检查：Nomi 形态（小球 / 浮窗 / 停靠）在窄窗里反复出问题，类根因复盘

写于 2026-11-14，基于窄窗外壳 PR 的头 6eb3bfd13（未合入）。作者没参与过这一块的设计、实现、验收和修复。用到的材料：用户原话和拍板清单、两次独立验收报告、复验线的真窗探针结果表、git 历史、代码、单测，以及我在 store 层做的复现（见第 3 节）。

## 0. 一句话根因

这个 store 里同时住着三种东西：人选的、要存的；此刻怎么摆、不该存的；从前两样算出来的。代码只用一个三值的 `form`（ball / float / dock）加几个旁挂字段来表示：
- 「此刻怎么摆」只有整窗一份，没有按页分。
- 「打开时摆在哪」根本没地方存。
- 读的人有三种读法。

所以每修一条写回，就会从另一个读法或另一个页冒出下一条。

## 2. 为什么这一类会一直出现

**三种东西现在怎么摆的**

| 性质 | 字段 | 类型上分得开吗 | 写入口分得开吗 |
|---|---|---|---|
| 人选的、要存的 | `bySurface[页].form / float / ball` | 不分。`form` 一个值同时表示「开没开」和「开着时摆在哪」 | `setForm`、`requestForm`（宽窗时就是写）、`chooseForm`，三个口都能写 |
| 此刻怎么摆、不该存的 | `windowNarrow`、`narrowShown`、`narrowMotion`、`dockSuppressed` | 靠 `partialize` 挡住不落盘（`agentFormStore.ts:153`），这一层没问题。但 `narrowShown` 是整窗一份，不按页 | 只由 `requestForm` 和 `setWindowNarrow` 写 |
| 从前两样算出来的 | `effectiveAgentForm(...)` | 是个函数，没有变成唯一入口 | 不涉及 |

几个关键事实：

1. **「开着时摆在哪」没地方存。** 三值的 `form` 收成 `ball` 那一刻，就丢掉了「刚才是浮窗还是停靠」。所以打开时只能靠 `openFormFor` 按页猜（`ShellAgentHost.tsx:54-56`）。14d1d609b 修的那一条，就是这个猜出来的值被写进了存档。宽窗里同样的丢失今天就能复现（第 3 节预测 3）。
2. **「此刻怎么摆」只有一份。** 窄窗档是照 `dockSuppressed` 的样子做的：一个整窗布尔值，派生时叠上去，代码注释里写着「同 dockSuppressed」。可是 `dockSuppressed` 从 10-08 起就没有任何生产代码写过它（`git grep setDockSuppressed` 只命中 store 本身和单测），是条死路。照着一条死路的形状去做一份本该按页的状态，就有了条件 1。
3. **「此刻显示的形态」有三种读法。**
   - 读存档：`ProjectAgentResidentShell.tsx:275`（挑参考图）、`ShellAgentHost.tsx:153-154`（小球悬停提示和收拢动画）、`chooseForm` 里的判断（`agentFormStore.ts:141`）。
   - 派生，含 `dockSuppressed`：`useEffectiveAgentForm` / `readEffectiveAgentForm`，用在 `ShellAgentHost.tsx:270`、`WorkbenchShell.tsx:234`、`NodePointerReturnDock.tsx:21`、`revealNodeFromChat.ts:51`。
   - 派生，不含 `dockSuppressed`：`shownIgnoringSuppression`，用在 `ShellAgentHost.tsx:62-65`、`:293`、`:319`。

   因为 `dockSuppressed` 永远是 false，后两种读法实际一样，第一种是错的那种。条件 3 就是读成了第一种。
4. **入口按「我要哪个形态」设计，可人做的动作是「打开 / 收起」。** 所以每个调用方都要自己先算「此刻是什么、该要什么」，再把答案传进来。现在一共 5 处在算：`ShellAgentHost` 3 处、`revealNodeFromChat`、`ProjectAgentResidentShell`。算错一处就是一条 bug。

**体验铁律对照**：⑫「点了=以为的」。人点的是「收起」，存下的却是停靠；人在创作页点开，生成页也跟着开。⑩ 和 ⑪ 不适用。

## 4. 靶子独立性检查

- `agentFormNarrowGestures.test.ts` 和外壳走查的「存小球」一段，都是修复那条线在同一个提交 14d1d609b 里写的。单测里**抄了一份** `openFormFor`（第 29 行），并在 store 层重放调用方写法（第 31-46 行）。调用方改了，测试不会知道，等于自己和自己对答案。
- 测试里每一格都只动一个页，从来没有「先在这一页做、再看另一页」，所以串页（条件 1）和反方向串页它都看不见。临时改成按页后照样全绿，说明这份测试对「此刻怎么摆归哪一页」没有立场。
- 没发现把错行为钉成「对」的格子。只有两处现状被钉住，需要人确认是不是要的：窄窗里存浮窗的页选「收起」写成小球，以及宽窗里系统发起的打开 / 收起（挑参考图、指向时让开、别处叫回）照常写存档。
- 真正抓到问题的，是独立验收线自己写的真窗探针（修前抓到 18 格存档被改）。靶子要有独立来源，这次是靠验收线自带的。

## 5. P0：这些是我们独有的吗？现成方案有哪些

- **三种形态加「每页各存各的」是我们的领域**（外壳拍板）。「人选的状态 / 临时显示状态 / 派生值分开放」是通用做法，不该自己发明。
- **仓库里已经在用的**：zustand 4.5 的 `persist` + `partialize`（这个 store 已经在用它挡住临时字段）；immer；没有 XState。
- **现成做法的出处**：
  - zustand 官方的持久化文档：用 `partialize` 只存要存的子集，可以列白名单，也可以排除某些键（[persist 参考](https://zustand.docs.pmnd.rs/middlewares/persist)、[持久化指南](https://zustand.docs.pmnd.rs/reference/integrations/persisting-store-data)）。这次没找到官方关于「派生状态」的专门章节；「派生值不进 partialize、从持久字段现算」这个说法只在社区指南里看到，**未核到官方原文**。
  - React 官方《Choosing the State Structure》里的「避免冗余状态」「避免互相矛盾的状态」是同一原则：能算出来的就不存，两份会互相打架的就合成一份。这一条我凭记忆引用，本次没有打开原文核对。
- **结论**：三种形态，用不上一个状态机库。要换的是表示方式本身，用现成的 zustand 写法就够。

## 6. 三条路对比表 + 推荐

| 选项 | 做什么 | 创作者那一刻的体验 | 动几个文件 | 哪些从结构上做不出来了 | 代价 / 风险 | 推荐 |
|---|---|---|---|---|---|---|
| 沿原方向修 | `narrowShown` 改成按页；挑参考图改读此刻显示的形态；`setForm` 加个 lint 或私有化 | 条件 1、3 消失 | 约 3-4 个文件 | 都做不到。「打开时摆在哪」还是靠猜；读法还是三种；预测 2 已经实测出「修 1 冒 3」 | 小，但这是同一 store 的第 4 刀；下一个新入口（Agent 的 layout.write、新页、Esc 关浮窗）会再算错一次 | 否 |
| 换一种做法 | 按页把人的选择拆成两个字段并持久化：「开着时摆在哪」（float / dock）和「开没开」（是否收成小球）。「此刻怎么摆」作为按页的临时字段，单独放在一个**不挂 persist 的 store** 里。对外只给动作，不给形态：`open(页)` / `collapse(页)` / `choosePlacement(页, float\|dock)`，外加一个唯一的读函数 `shownForm(页)`；去掉 `setForm` / `requestForm` 的公开写法和 `openFormFor`，删掉死字段 `dockSuppressed`。窄窗里 `open` / `collapse` 只写临时那份，`choosePlacement` 照写人选的那份 | 创作页点开不再串到生成页；选过浮窗再收起，点开回到浮窗；窄窗里点什么都不改存档，宽回来是各页自己的样子 | store 1 个 + 调用方 5 个（`ShellAgentHost`、`WorkbenchShell`、`ProjectAgentResidentShell`、`revealNodeFromChat`、`NodePointerReturnDock`）+ 单测。存档格式要迁移：旧 `form` 是 ball 就记「收起」、摆法按页默认；是 float / dock 就记「打开」加对应摆法 | 调用方不用再自己算形态，那 5 处计算没了；临时状态在另一个 store，写不进磁盘；没有第二种读法，读错就成了编译错；按页是类型给的，串页写不出来 | 中。要老用户迁移（★1c），用旧版真实 localStorage 测；宽窗里系统动作要不要写「开没开」要定一次（见第 7 节） | **推荐** |
| 删掉 | 最小可删单位是「窄窗里存档就是小球的页也能临时开浮窗」这条特例，或者整个「窄窗档里点开 / 收起」，变成窄窗里只能通过形态切换真选 | 窄窗里点小球就等于选了浮窗、会写存档，违背拍板 D2「存下的形态不改」；或者窄窗里打不开 Nomi，违背 never-yield「Agent 输入框（打开浮窗后完整）」 | 少 | 窄窗写回这一支没了 | 推翻用户 11-07 的拍板，体验更差 | 否 |

推荐：换一种做法，由一条实现线在这个 PR 合入后单独开一个 PR，按「一个 store + 5 个调用方」为单元一次做完，同一个提交里删掉 `requestForm` / `setForm` / `openFormFor` / `dockSuppressed` 的旧写法。

## 7. 用户要权衡的核心

一句话：Nomi 收成小球之后，再点开要不要回到你上次选的样子（浮窗还是停靠）？还是像今天这样按页面固定回去（生成页浮窗、其余停靠）？

换做法会把「上次选的样子」存下来，这是用户能感觉到的行为变化。另外一个次要的点要一起定：宽窗里系统替你打开 / 收起（挑参考图、指向节点时让开、别处叫回），算不算「你选的」、要不要记住。我建议不记，只有人亲手点开 / 收起才记。

## 系统哪里没拦住（三条问题为什么两轮实现、两次验收才冒出来）

- **设计卡 ★9 那一格。** 14 条验收全是「窗口变宽变窄」和摆放位置，没有一条是「页面 × 存档形态 × 手势 × 之后切页 / 拉宽」的矩阵。拍板约束「每页各存各的」在窄窗里还成不成立，没被写成一条验收。这是最早该拦住的一步。
- **单测**：按单页写，抄了调用方逻辑，看不见跨页和读法错。
- **类型**：`form` 一个类型同时代表人选的和此刻显示的，`setForm` 公开，没有任何结构上的阻止。
- **走查**：只在一个页里来回，没有先在一页做、再看另一页的步骤。
- **探针**：独立验收线自己写的，抓到了，但它不常驻。

按强弱排，我能给出的最强一种是：
1. **删掉**：死字段 `dockSuppressed`、`openFormFor`、公开的 `setForm` 和 `requestForm`。
2. **结构上做不出来**：临时状态放进不持久化的 store，并按页给类型；对外只给动作和唯一读函数，调用方没有形态可以传。
3. **门岗自动拦**：把真窗探针的表（3 种存档 × 4 页 × 手势 × 之后切页 / 拉宽 / 重开）缩成常驻单测，改为直接驱动真实的组件入口，不抄调用方；再加一条结构测试：除 store 自身外，任何文件出现 `bySurface[...].form` 就红。
4. **写规则文字**：设计卡 ★9 对「有存档的界面状态」必须写一条「同一动作在别的页 / 别的窗宽之后」的反例。这条最弱，只作补充。
