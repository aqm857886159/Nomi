# 方向检查：窄窗页面线（PreviewWorkspace 行模板 F2 + TimelinePanel 工具条兜底）

写于 2026-11-08，origin/main 745b3c5b4。作者：没参与过前几轮的复盘线（与 `2026-11-08-workbench-shell-width-writeback.md` 同一作者，那份管外壳线的宽度写回）。材料：R-window-narrow 调研 §2.3、用户 11-07「可以，开做」及 18 张拍板稿（`WindowNarrow.board.json`）、代码、git 历史。放进 PR 时拷到 `docs/engineering/direction-checks/`。

## 0. 一句话根因

两个文件在这 14 天里挨的刀分属别的概念（输入面、预览侧栏存档），这次两刀是新的一类：「页面按窗口大小摆放」，其中一刀（F2）是真缺陷、一刀（时间轴「⋯」兜底）修的是在新最小窗里到不了的状态。

## 1. 归类表

| 提交 / bug | 直接原因 | 类 |
|---|---|---|
| e57081ef0（10-30）PreviewWorkspace / TimelinePanel | 快捷键各自判断谁在输入 | 键盘输入面 |

| 本次：时间轴工具条放不下整组进「⋯」 | 工具条是横向滚动行（09-10 由浮层改来，09-13 钉住行尾），无「放不下」的处理 | 工具条宽度适配 |

结论：
- 文件口径到线，类口径没到。TimelinePanel 前两刀同一类（输入面），与本次无关；PreviewWorkspace 前两刀一刀输入面、一刀存档写回，本次 F2 是 CSS 行模板，不碰存档，与 c97089ff7 只共享「预览页在窄窗下的表现」这个场景，不共享机制。
- 与外壳线那一刀（Agent 面板宽度写回）也不同类：那一刀是「派生值被当意图写回」，与 c97089ff7 同类；F2 是布局约束缺失。三刀（F2、工具条、外壳宽度）合起来不是同一个 bug 反复回来。

## 2. 为什么会挨刀

- PreviewWorkspace 303 行，同时管：存档读写、面板库同步、键盘撤销、网格。每一类窄窗问题都落在它身上，但每次是不同的责任。
- F2 的成因是「同一件事（外壳把工作区装进窗口）四个工作区各写一遍」：生成页写了行模板，预览页没写，创作页 / 分镜页靠 `h-full` 碰巧对。新增一个工作区就可能漏。这是本类 bug 会回来的路径。
- TimelinePanel 的工具条已经是第 3 种形态（浮层 → 滚动行 → 滚动行加钉住的行尾）。再加「⋯」是第 4 种；每一种都是在补上一种的症状。

## 3. 不改结构的话会冒出什么

| 预测 | 怎么验证 |
|---|---|
| 以后新增或改动工作区，又漏掉行模板，矮窗出现「底部按钮在窗外」 | 在 1100×720 逐个工作区（创作 / 分镜 / 生成 / 预览）取付费卡与输入框坐标，断言在窗内（调研 §2.3 同法，`tests/ux` 里可加一条按工作区循环的探针） |
| 工具条「⋯」做出来后只有极少数用户能触发，测试覆盖不到，将来坏了没人发现 | 宽度 < 454 才触发；最小窗 700 时主区 632（D-window-narrow 报告第 12 行），实测在 700 触发不了 |

## 4. 靶子独立性

F2 的尺子是 `getBoundingClientRect`（不是评分）；改后的数字（「生成」2181–2274 × 682–710）来自拍板稿，是按生成页网格写法推的，D-window-narrow 报告自己写了「直接以 720 高打开预览没测」。所以验收必须用真 App、以 720 高直接打开预览，不是从 900 缩到 720。

## 5. P0

这两个问题都不是我们独有的：行高约束是 CSS Grid 自带；工具条溢出菜单仓库里已有 `src/design/menu.tsx`（以及依赖里的 `@radix-ui/react-dropdown-menu`），不必自写测量逻辑。

## 6. 三条路（逐刀）

### F2（PreviewWorkspace）

| 选项 | 做什么 | 代价 | 风险 | 推荐 |
|---|---|---|---|---|
| 沿原方向修 | 预览网格加 `gridTemplateRows: 'minmax(0,1fr)'`（一行） | 1 行 | 低；在 720 高真开预览验证 | **推荐**。这是补一个缺失的约束，不是加特例分支；没有新增状态 |
| 换一种做法 | 四个工作区的外壳网格抽一个共用写法 | 碰 4 个文件，其中 GenerationWorkspace 同样到线 | 中；与外壳线正在改的同批文件打架 | 暂不做，记为后续：四个工作区的 `grid` 容器写法统一 |
| 删 | 无 | — | — | 不适用 |

### 时间轴工具条「⋯」兜底（TimelinePanel）

| 选项 | 做什么 | 代价 | 风险 | 推荐 |
|---|---|---|---|---|
| 沿原方向修 | 保留今天的横向滚动 + 钉住行尾，不改 | 0 | 700 以下才会滚动，而 700 是主进程最小宽 | 兜底已经存在 |
| 换一种做法 | 用 `design/menu.tsx` 做溢出菜单，ResizeObserver 量宽，放不下整组进「⋯」，同提交删滚动行 | 要新增测量逻辑，full / compact 两处都要测，英文宽度更大，两个密度各一遍；P1 要求同提交删旧滚动，即换掉已经修了两轮的结构 | 中：测量与 `resolveTimelineFitScale` 的 ResizeObserver 叠加；无法在 700 以上触发，只能用单测造窄宽度验证 | 不推荐现在做 |
| 删 | 把「⋯」从本次范围里拿掉，拍板稿里这一项标成「放得下，不做」；仍保留横向滚动 | 0；拍板稿 N5 的标注要改一行 | 低：Agent 面板宽的上限 = 视口 − 760（`assistantWidthBounds.ts`），内容区恒 ≥ 700，工具条所需 454 + 两侧留白放得下，是由结构保证的，不是靠运气 | **推荐** |

依据：拍板稿自己写明「⋯ 只作兜底」「700 放得下」（`preview.timeline-toolbar` 条目，label 与 afterNote），D-window-narrow 报告第 12 行：这条规则在 700 宽触发不了。用户 11-07 的「可以，开做」批的是缩到半屏能用，不是这个兜底；它在屏上看不到，也没有任何用户能碰到。这是「删」不是偷懒：触发不了的代码无法验收（P3），而且一旦出错没人会发现。如果协调会话想保留，必须单独成题请用户确认「看不到的兜底也要做」。

## 7. 和外壳线（Agent 面板宽度）在 PreviewWorkspace 上怎么不打架

外壳线在 PreviewWorkspace 的改动：`gridTemplateColumns`（把 `assistantPaneWidth(...)` 换成引用同一个函数 / `minmax`）、`syncSize` 路径上咽喉不再读窗口。F2 的改动：同一个 `style` 对象里加 `gridTemplateRows`。

- 两处改在同一行附近（`PreviewWorkspace.tsx:210-211`），合并冲突几乎必出现，但互不依赖。
- 建议：同一时刻只一个 PR 改这一行。顺序：先合外壳线（改的是同一个 `style` 的列），F2 在其上补一个键；或反过来 F2 先合，因为只有 1 行，外壳线 rebase 成本低。我推荐 F2 先走（1 行、独立、可用 720 高真开预览独立验收），外壳线后合。
- 另一条要对齐的验收：两线都要在预览页 1100×720 与半屏 700×900 各截一张，写进各自 PR，互相引用，避免一个线的修复把另一个线的验收图改掉。

## 8. 用户要权衡的核心

时间轴工具条那个在最小窗里到不了的「⋯」兜底，是要做进去让人安心，还是依靠「内容区恒 ≥ 700」的结构保证、不做。
