## 2. 为什么这一类会一直出现（类根因 5 条）

1. **新功能只落画布节点，分镜行写「不动 / 不声明」**。325237525 提交说明：「分镜行的方式栏不动」；91711c57f：「变体行只在调用方声明…分镜行不声明」。结果 `InlineParameterBar.tsx` 同时留着 `modeMenu`（画布，带说明小字）和 `modeChoices`（分镜，面板内老列表）两套方式选择（props 第 80、82 行），分镜行的方式选择没有「按输入现算 / 灰显报数」。
2. **外壳不是同一份**。分镜行与参考卡共用 `ShotComposerBar.tsx` 里的 `ComposerBarRow`（`border-t … px-2 py-1.5`），画布节点是 `NodeGenerationComposer.tsx` 的 `data-node-composer-footer` 一整块；两份都声明「和画布一致」，没有任何东西核对（用户 10-05 已要求复用，11-04 之后又重复提）。
3. **共用下拉缺能力，各处各绕**。`NomiSelect.tsx` 的菜单高度由「有没有图标」决定（`hasRichRows`，约 279 行）：模型菜单被修成 380，带说明小字但无图标的方式菜单仍是 240，装不下第 6 行；`footerAction`「隐藏模型」被 `InlineParameterBar.tsx` 无条件传入（约 476 行），一家供应商都没接时仍显示；分镜独有的 `leadingModelOption`（约 473 行）把「默认模型」做成无图标的普通行。
4. **同一句话两条生成线**。参考行行尾的数量文案（`referenceRowTail.tsx` 的 `referenceCountText`）和方式菜单的小字（`modeMenuModel.ts` 的 `blockedDescription` / `limitItem`）各自拼「N 张图 / N 个视频」；一边写了复数、素材类型，另一边没有（`assetLibrary.ts` 英文 `count: '{{count}} references'` 无 `_one/_other`；中文 `needsMore` 写死「张图」）。
5. **尾巴在合入前最后一刻或合入后才被发现**：e1686cfc3（独立验收查出，04:39 提交后 24 分钟）、e9c8c5e39（验收「有条件通过」）、312230c4f（单测分片红）、bc7d5642f（第 3 轮验收补测）；同一天 9 个 feat 提交把一件事切成多片，每片各过各的门岗。「同一界面几处出现」没有任何出图前的清单（不知道：出图前是否数过——只看到 `docs/design/boards/2026-11-12-mode-bar/` 一处板）。

三条体验铁律：⑫「点了=以为的」适用（默认模型行看着像标题却可点）；⑩⑪不适用。

## 4. 靶子独立性

截图基线 `tests/ux/design-lab/__baselines__/node-composer-bar/` 只含画布节点底栏，没有分镜行底栏同款；「和画布一致」没有比较对象，只能靠人看。修一处不会让另一处的图变红。

## 5. P0

这几处里**独有**的是领域部分：模型档案槽位 → 能放什么（`electron/shared/modelArchetypes/`）、按输入现算方式。**通用的**是下拉、浮层、外壳（已建在 Mantine Combobox 之上）、数量文案（i18next 自带 `_one/_other` 复数，仓库已用）。通用部分不需要再造新组件，只需要把已有的那一份变成唯一一份。
