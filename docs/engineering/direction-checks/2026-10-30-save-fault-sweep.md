# 保存路径量具：方向检查与采用现成方案

## 0. 一句话根因

性能路由漏掉保存链，主进程同步等待未冻结；原拟新增自写门岗类别又命中 `gate-family`，协调裁定改用已装 ESLint 内置规则和原生 bulk suppressions。

## 1. 归类表

| 事项 | 直接原因 | 类 |
|---|---|---|
| 保存路径无需性能证据 | 旧 `inferRoutes` 对只改 `electron/jsonFile.ts` 返回空类别 | 主进程出错路径缺证据路由 |
| 六处同步等待未冻结 | 原重活门岗无对应判据 | 主进程堵塞缺结构性预防 |
| 原方向检查退出 1 | `gate-family` under-review，30 天 95 个 fix | 自写通用能力持续补规则 |
| 原扫描 44 项立即残留红灯 | 把锁协议允许的下次回收元数据当成当下清理失败 | 测试合同读错；改验同进程与真新进程恢复保存后的严格零残留 |

## 2. 为什么持续出现

渲染层量具不能覆盖主进程保存与失败分支。`gate-family` 的重复补规则不能由本线扩张代批；已采用协调指定的替代方案，不再改 `check-heavy-path.mjs` 或其基线。体验铁律⑩⑪⑫不适用：没有意图、模型选项或可点击目标改动。

## 3. 可验证预测

| 预测 | 证据 |
|---|---|
| 新同步等待会被已有 lint 拦住 | 临时新增生产文件，ESLint 退出 1，命中 Atomics.wait 提示；按字节恢复 |
| 删除旧等待却不收紧会红 | 临时删 jsonFile 调用，ESLint 退出 2，unused suppressions；按字节恢复 |
| 关闭注入会暴露空扫描 | 变异后 `in-window injected rounds >0` 实际红 |
| 下一次操作必须恢复且清零 | 最小 ENOSPC 保留立即残留观察；同进程与真新 pid 保存都须成功且零残留，拒绝恢复或制造残留的变异必须红 |

## 4. 靶子独立性

睡眠用请求毫秒计数，JSON 用保存窗内 ≥1MB 的实际调用次数，不用墙钟猜性能。上限抬高变异实际红。恢复前关闭计量窗，避免把恢复工作混入原基线。锁协议明确允许错误当下的放弃元数据，下次保存必须成功并严格清零；不能把这次合同修正当作产品修复。没有独立验收，本线不自签。

## 5. P0 与现成方案

采用已装 ESLint 10.4.1 的 `no-restricted-syntax` 与原生批量抑制。Context7 核过 [ESLint v10.2.1 CLI 原文](https://github.com/eslint/eslint/blob/v10.2.1/docs/src/use/command-line-interface.md) 的 `--suppress-rule`、`--prune-suppressions` 与 unused 默认退出 2；本机版本也已实跑验证。六处旧债各记 1 次，未给产品加 disable 注释，不加包、不自写新门岗。原登记 `gate-family` 的长期账本评估仍由协调拥有。

## 6. 接入 / 补 / 重写 / 删

| 选项 | 做法 | 代价与风险 | 判断 |
|---|---|---|---|
| 接入现成方案 | ESLint AST 限制加原生文件 × 规则抑制 | 需保证各主进程配置块都带限制；新规则初始六处存量上涨仍需协调收据 | 已按裁定采用，14 项测试与双向变异验证 |
| 补 | 给 heavy-path 增加类别与自写双向判据 | 继续扩大评估中的门岗族 | 已放弃 |
| 重写 | 迁移整套门岗框架 | 超出范围 | 不采用 |
| 删 | 不做同步等待防线 | 留下新增堵塞入口 | 不采用 |

## 7. 核心权衡

通用静态检查交给现成 ESLint；保存语义与真实故障完整性由领域测试负责。`workspaceManifestLock.ts:105–120`、`:229–233`、`:277/:353` 的回收合同要求下一次操作不受残留影响。按此合同复验；若恢复仍失败才交保存修复线，不在本线改产品或新增豁免。

特征核查在原复盘前已运行：旧门岗通过、生产同步等待六处、保存路径无 perf 类别。用户问题的逃逸条目仍由修复线拥有，本线未新立条目；不宣称用户现场卡顿已解决。
