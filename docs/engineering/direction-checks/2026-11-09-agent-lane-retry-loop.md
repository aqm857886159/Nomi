## 0. 一句话根因

失败描述、工具准入、回合是否继续分属不同边界；把报错和计数统一以后，**结束回合仍然寄托在模型听懂拒收正文上，运行时从来没有执行这个终止决定**。这解释了反复空转；首次参数为什么写错是另一件事，要用真模型按错误来源去量，不能拿止损修复冒充参数正确率提高。

## 2. 为什么这一类会一直出现

**09-18 删的和这次要加的不是一回事。** `91e3ec137` 记的用户原话是「为什么要给限制？不要给什么次数限制。」，删掉的是**正常长任务默认 24 次总请求上限**；那次提交同时依靠「同错 3 次拦、5 次终止」处理失控循环（而这个「5 次终止」后来证明到不了）。恢复默认总步数上限会和原话冲突；「被要求停了还重发，就结束当前这一轮」不冲突。

**控制点数清楚了**（`door-map`：6 扇符号门，3 写 3 读，11 处）：

| 状态 | 谁写、谁读、实际在哪判断 |
|---|---|
| 回合预算 | `before_request` 按 run 计数（只有实验脚本传了上限，生产装配不传）；判断却在 `before_tool`。形状错、被拦的调用都是 pi 的**立即结果**（`terminate: false`），到不了 `before_tool`，上限对它们形同虚设。 |
| 工具失败 | 边界的 `settle` 写计数，入口两个：入参拒收和宿主 `after_tool`。计数键是「工具 + 码 + 字段路径」，**每换一个错字段就另起一桶**。 |
| 「别再发」 | 墙立着时只回一条不执行的立即结果，不记数、也不结束回合；4 处 reset 由用户开口 / 答卡 / 改口 / 排队触发——其中「排队」时模型其实还没读到那句话。 |

pi 0.85.1 的 `prepareToolCall` 把这些异常变成 `terminate=false` 的立即结果；未知工具名、普通 prepare 异常、surface / 访问 / 审批拒绝也不全进 settle。**把更多分支塞回 after_tool 仍会漏入口。**

落到铁律 **⑫ 点了 = 以为的**：用户期待起草并拿到可用结果或明确的停点，实际可能只多出一串拒收。必须核最终运行状态、实发请求、已完成的工作和队列恢复。⑩ ⑪（参数意图 / 档案覆盖）是「首次写错」的另一项证据，本复盘没有证明它们已满足；逃逸账本不能据此转 fixed。

## 3. 不改结构，接下来会冒出什么

| 可证伪预测 | 怎么验证（零真模型） |
|---|---|
| 形状错或准入错撞墙后，显式上限 5 也继续请求 | 假模型脚本 10 个错调用：每例 11 次请求；全成功对照上限 5 为 5 次 |
| 同一工具每次换一个错字段，10 次失败没有一次 `breakerTripped` | 同上，默认 / 显式上限两例各 11 次 |
| 一批里同时有对的调用和形状错，不能因为对的那条 terminate 就以为整轮结束 | 上限 1 时预测 2 次请求 |

特征测试：`electron/agentLane/laneToolInputBoundary.test.ts`（修前钉了「10 个错误 11 次请求」和一条 `it.fails`）、`laneRepeatedFailure.test.ts`、`tests/agent-runtime/lane-resilience.test.mts` 的回合上限段。基线特征断言与修复验收断言必须分开。

## 4. 靶子独立性检查

前几轮的实现和特征测试来自同一组提交；本复盘独立核了请求次数和 pi 的停止语义。现有 `it.fails` 把「已知停不下来」的反例计成测试成功；另有断言钉死了「10 个工具错误、11 次请求」——真修好之后这些旧特征测试**反而会红**，必须按新的用户合同改 oracle，不能凭旧绿灯回滚修复。

停止验收要同时断言：停点后不再发模型请求、不再执行工具、运行状态结束、已成功的内容保留、待决卡落定、没被吃进去的用户输入能恢复、续问能继续；还要覆盖成功的长任务、无关读取不洗掉失败、同批混合结果。拒收文案保留可行的下一步，但**不许承诺「模型会总结」，却紧接着结束到根本没有下一次模型请求**。

## 5. P0：这些是我们独有的吗？现成方案有哪些

- **已装 pi-agent-core 0.85.1**：公开 `requestAbort(operationId, context)`（`dist/harness/agent-harness.d.ts`），落持久化的 cancel_requested、把驱动闸置为 aborting，并**交回还没被消费的 steer / followUp**；`abort()` 还要等 drive 收尾，钩子里直接 await 它会等自己。应复用它执行终止，不另造取消循环。
- **pi 的工具级 terminate 不是通用的整轮停止**：校验 / 未知工具先产立即结果；整批 `every(terminate)` 才结束。`before_request` 只能改 streamOptions，抛异常会被记错后吞掉——不能拿 throw 冒充硬停。
- **Vercel AI SDK Loop Control**（<https://ai-sdk.dev/docs/agents/loop-control>）：`stopWhen` 在循环层按步骤结果决定继续，支持自定义条件；`prepareStep` 管每步配置。影响：采用「循环层拥有停止」的结构，不照搬默认步数，不为一个停止条件换掉整套 pi 会话。

自写登记 `lane-repeated-failure`、`lane-tool-input-boundary`：字段解释、镜头参数准入与 zh/en 投影有领域理由；通用的循环、取消与重试没有。依赖建议 **retain-with-exit**：先用 0.85.1 的公开取消原语；只有实验证明它保证不了「下一次请求前关闸 + 完整收尾」时再评估上游升级，不先 fork；将来 pi 有覆盖立即结果的统一 outcome / stop 钩子，再删宿主相应的适配。

## 6. 三条路对比表 + 推荐

| 选项 | 做什么 | 代价 / 风险 | 推荐 |
|---|---|---|---|
| 沿原方向修 | 再补 before_tool / after_tool 判断，或加强「别再发」话术 | 仍绕不过立即结果和未知工具；给所有任务加默认上限又违背 09-18 | 不选 |
| **换一种做法：接现成原语** | 单一回合所有者汇总所有已结算的工具结果；止损按「这个工具自上次成功以来失败几次」计，字段只留诊断；沿用第 3 次提示转路 / 提问，模型再调已封的工具就用 **pi `requestAbort`** 结束当前这一轮。未知工具归统一拒收类，不把不同的随机工具名当新预算。显式实验上限放在真正的下一次请求入口，不设生产默认总上限。 | 防事件重入、混合批次、取消时清队列丢输入；连续改错字段的有限自纠也会被停，需要用户接受这项取舍 | **推荐** |
| 删掉 | 最小可删单位：自写熔断（tracker + 墙）。删掉后保留字段报错，只靠用户手动停、报价卡或总上限 | 用户得盯着空转；报价卡不限制文字模型调用；默认总上限会切断正常长任务 | 不选 |

推荐项同提交删：`before_tool` 里的预算执法分支、按「码 + 字段路径」分桶作为止损依据、无限产生 stopped 立即结果的控制路径和误导性的「会总结」承诺；保留参数校验、字段诊断、审批与已完成结果。现有会话转录不重写；用户纠正**被实际吃进去时**才建立新状态，不能用排队动作提前清零。只把边界报错搬进更多钩子、改一个数字、或默认限制每轮次数，都不算结构改法。

## 7. 用户要权衡的核心

**正常做成的工作可以一直做；同一工具一直做不成，即使不停换错字段，也只给有限纠正机会，之后保住成果并明确停下——接受偶尔提前请用户继续，换取不再无尽空转。**

### 与实现线原方案对照，取了哪些

实现线原方案（下称「原 B」）在独立复盘之前已用假模型做出原型：立即结果绕过上限的证据、在请求入口用 `requestAbort` 收掉这一轮、钩子里只 await `requestAbort`（不 await `abort()`）实测不死锁。两份对照后：

| 点 | 原 B | 复盘 | 取 |
|---|---|---|---|
| 在哪停 | 请求入口（`before_request`）调 `requestAbort`，下一次请求不发 | 同 | 原 B（两边一致） |
| 停的依据 | 沿用「码 + 字段路径」分桶的墙 | 按工具「自上次成功以来失败几次」，字段只留诊断 | **复盘**：换错字段不能再绕过 |
| 宿主上限 | 移到请求入口，不设生产默认 | 同；09-18 删的默认 24 不恢复 | 两边一致 |
| 被交回的用户输入 | 未处理 | 必须能恢复 | **复盘**：`requestAbort` 交回的 steer / followUp 在这一轮收尾后原样排回队里（看得见、能撤回，随下一句话一起发） |
| 何时清零 | 排队时就清 | 被这一轮实际吃进去（`message_end`）才清 | **复盘** |
| 未知工具名 | 没覆盖 | 归统一拒收类 | **复盘**：未知名的失败合成一个「未知工具」计数 |
| 「会总结」措辞 | 删 | 删，且停点那句不许承诺这一轮兑现不了的事 | 两边一致 |

### 已知代价（定：不改计数规则）

真模型基线里有三道参数题都是第 4 次才写对、最后成功，每次错的是不同字段、模型在往对的方向改；新规则会把它们从成功变成被停。免费复现找到了直接原因：**拒收一次只报最先拦下它的那一层**（工具自己的准备步骤 → pi 的形状校验 → 准入），三层各错一处时，照着改也要第 4 次才对（`laneToolInputBoundary.test.ts`「三处错分属三层」）。这笔账靠「拒收一次就把所有错处列全」来还，算在根因修复上，**不放宽止损**；这三题用真模型在 3 次以内写对之前，本改动不合并。
