全图见 `docs/engineering/seams.json` 的 `reference-to-request` 与 `result-to-project`。本次交接为画布单镜／批次 → 主进程提交账本 → 参考链接试探或素材上传 → 模型提交 → 工作台／画布遥测。基点为 `3a18ae6cf`，合入主线 `640158cbd` 后，fix-churn 对控制器、素材本地化、遥测三个文件分别报 14 天内已有 3、2、2 个修复提交。

## 0. 一句话根因

谁点了一次、能否把素材交给模型、请求走到了哪一步，本来各有直接证据。画布、上传预检和遥测却分别从异常文案、历史或缺省值再次做决定。

## 1. 从现场追到共性

| 现场 | 直接原因 | 受影响的结果 |
|---|---|---|
| Step 1 已使九次已分类拒绝只记九条。裸网络异常仍可让单镜执行三次 | 执行器在同一个 run 内重入，批次逐镜调用它 | 一次授权触发多次付费执行尝试。主进程是否实际重复扣费不能从事件数推出 |
| 同一连接以前拒绝过一张图、侧车超过 48 小时、候选通道租期短 | 预检和发出前分别用连接历史、文件年龄、估算时长否决当前素材 | 有效链接或可用上传通道还没试，用户已经被拦 |
| 未开匿名托管，原站仅拒绝 Range | 探针的 `dead` 把「这个请求被拒」和「这个对象已消失」折成一个值 | 可用链接在六个入口被挡；一律放行 403 又会绕过过期 S3 链接的私有重传 |
| 同一笔未派发错误在原始封包里有 reason，事件里却是 unknown | 状态投影在缺 HTTP 时只看供应商类别，没消费主进程的派发证据 | 本机未派发、连接未建立与证据不足在雷达中混到一起 |

原始雷达计到 557 条 unknown，没有逐条可还原的点击、请求与账单身份。九次变二十七条是夹具复现的机制，不能据此给历史二十七条逐条归因。[原始报数](https://github.com/aqm857886159/Nomi/issues/1586#issuecomment-7103051778) · [入口回放](https://github.com/aqm857886159/Nomi/issues/1586#issuecomment-7104949138)

## 2. 反复出现的原因

最早可拦的是设计和验收。旧测试要求同一连接被拒后跳过探测，甚至要求活的 49 小时链接直接走上传；这些断言认可了代理信号。改成直接观察执行器调用数、真实回环服务收到的生成 POST、供应商收到的 URL 和公开事件字段。⑫「点了=以为的」覆盖一击一次和拒绝公开上传，⑩、⑪ 的参数拟合与模型可选项没有改变。

Step 1 基点重数：`door-map isRetryableGenerationError` 只有控制器一扇；`localizeAssetsForVendor` 的读／写都在 `assetTransportRuntime.ts` 的 `localizeForSend`，`judgeReferenceLinks` 只有本地化入口。需沿包装再查常规映射、自定义脚本、语义封存、返工冻结、映射试跑和 try-model 六个消费方。两处独立旧案为 11-21 由主进程决定再次提交（`0bd667843`）及 Step 1 一度放过明确 S3 失败（见下方账本测试）。

## 3. 可证伪的预测

| 输入 | 结果与量具 |
|---|---|
| 图片或视频第一次抛未分类网络异常，用户随后再点一次 | 两次意图各一次执行，第一次失败时计数为 1，第二次结束时累计为 2。用生成控制器和 failedAttemptIdentity 测试读执行器 |
| 同连接另一张活图、老侧车活图、短租约可用通道、仅 Range 被拒 | 实际使用原链接或完成授权上传。未授权匿名上传的字节数为 0。分别在预检与真实发送入口回放 |
| S3 原链接 403 且已配置私有通道；或明确 404／410、成功响应却是网页 | 尝试可用且已获授权的上传通道。通道皆失败时生成 POST 为 0。只有匿名通道且缺同意时，死源提示授权 |
| 两个无 HTTP 的结构化 reason、一个缺事实的对照 | 遥测中依次为 not-sent、network、unknown，模型原文不会进入这些字段 |

## 4. 尺子的独立性

用户裁定一次新意图只派一次、仅真实风险可以拦。回环 HTTP 计数与账本终态来自执行器之外。Step 1 曾把所有 403 当成不可判断，`referenceLinkDispatchLedger.test.ts` 捕获过期 S3 预签名 URL 进入生成请求的回归；这个反例保留。原先 49 小时活图必上传的预期随裁定更新。仅断言「没有匿名上传」会让全拦版本也过，须同时断言可用原链接已交给模型。[S3 回归记录](https://github.com/aqm857886159/Nomi/issues/1586#issuecomment-7106916850)

## 6. 三条路

| 路径 | 对创作者及维护的影响 | 决定 |
|---|---|---|
| 沿原方向补词、放宽时间阈值、加 403 白名单 | 新异常、老素材或新供应商仍会碰到同一问题；无法靠改阈值表示供应商今天能否读图 | 放弃 |
| 重做连接重试与回执格式 | 现有提交账本、供应商传输层和错误封包已持有所需事实；增加另一套格式会使旧 Run 与新入口分流 | 复用已有边界 |
| 删除画布自动重跑和三项猜测否决，遥测直接投影现有字段 | 生成失败可由用户明确再试一次。无法确认的链接可以继续发送；明确死源仍可走私有上传或取得同意后上传。旧项目的侧车直接参与试探 | 采纳，对应 RW-1 + U-2 ①、RW-2、RW-3 |

## 7. 用户要权衡的核心

创作者可接受链接最终被模型拒收，但应自行决定是否再次派发或把素材交给匿名第三方。首次明确点击带来一次真实尝试，失败回执说明这次走到了哪里。[用户裁定](https://github.com/aqm857886159/Nomi/issues/1586#issuecomment-7106156717)

特征量具为 `multiResultLanding.test.ts`、`failedAttemptIdentity.test.ts`、`assetLocalization*.test.ts`、`referenceLinkDelivery.matrix.test.ts`、`referenceLinkDispatchLedger.test.ts` 和 `generationTelemetry.test.ts`。同输入修前／后数字见[本次设计卡](../../plan/2026-11-24-fa-step2-rw-and-u2-1.md)。2026-11-30 按补丁版本复查上述两项事件字段与每次显式意图的尝试数，有结构化 reason 再落 unknown 或出现画布自动重派即重开。
