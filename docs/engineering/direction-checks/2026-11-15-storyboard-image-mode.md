## 2. 为什么会一直冒

画布在 `325237525` 定了：方式是「这次放了什么」算出来的，存着的只当偏好，只有人在方式格里手选才写。那次提交明写「分镜行的方式栏不动」，分镜还是老规矩：存着的方式说了算，参考放不放得进、发不发得出、红不红都跟着它。这个 PR 按用户「三处一套设计」把分镜图片镜的界面对齐画布（不给方式格），可数据还是老规矩，于是存着的方式只剩自动去写的路，没有人工的路，也没有回头的路。三件事是同一个分叉的三个出口。铁律 ⑫「点了=以为的」：点「+」以为放进去了，实际没放；铁律 ⑪ 本身不适用。

### 留在这个 PR，还是先退回再另开

- **推荐：这个 PR 里分镜图片镜退回主线的样子**（图片镜照旧把方式传给参数面板顶上那一组，视频镜保留方式格），PR 先合，「换做法」另开一刀。代价：图片镜和画布暂时不一样多活一个版本；「+」被覆盖的老问题照旧（主线今天就有，但有手动入口可以绕）。
- 留在 PR 里做：代价是这个 PR 已过两次验收的主体（参数面板、底栏窄处让法）被拖住，第三轮还要碰发送那一步的花钱语义，超出这个 PR 的范围和轮次上限。

**什么情况说明选错了**：换做法上线后，反馈里出现「我放了图但不想让它发出去」；或者只收参考图、没有文生方式的模型，分镜上出现大量「先放图」卡住。出现任何一条，回来重看「存着的偏好在没图时还算不算数」。

## 7. 用户要权衡的核心：分镜图片镜要不要像画布一样「放了图就按图改、没图就文生」，不再让人手选方式——选是，就要接受旧镜上原来「不会发」的参考图以后会发出去。

## 系统哪里没拦住

1. 拿掉一个入口时没数「这个存着的值还有谁写、有没有回头路」。改法：设计卡写明——删一个会写存档字段的入口，要列出这个字段的全部写入方和回到默认的路；最强的改法是让分镜和画布问同一个函数，没有东西可数。
2. `325237525` 改画布规则时写了「分镜不动」，但没在计划表里记「分镜什么时候跟上」。改法：同一个概念一处换规则、一处豁免时，豁免必须挂一条计划项和触发条件。
3. 验收把「和画布同一条规则」核成「格子在不在」。改法：「和 X 一致」类的验收项，要在两处各走一遍同样三步（加图、删图、生成）比结果。
