# 方向检查：换模型参数写入边界

## 0. 一句话根因

合法性只有一个主人，但不合法以后怎么办散成九种政策，写入口没有共同的规整边界。
事实来源为协调指定的独立研究报告 R-model-switch-params.md（研究线未参加此前修补）；本实现线按其事实整理，不自称独立验收。

## 2. 为什么这一类会一直出现

研究报告：17 组、35 个写口（door-map 41 处）；按参数类：时长14组、比例12、枚举12、参考数6、类型5，九种做法：全重置默认 / 只修下拉不管数值 / 原样不查 / 清空参数保留时长 / 静默丢换默认 / 钳+说明 / 拦+合并拆条建议 / 拒绝+合法值 / 参考原件保留发送截上限。
7 个热点文件 60 天 28 个修复提交：archetypeMeta 6、useNodeModelAutoSelect 6、plannedNodeMeta 5、storyboardProjection 5、storyboardPlanEdits 3、planResolver 2、buildNodeModelChangePatch 1。
08-26 的同类比例问题只补了下拉值，未补数值。画布换模型 changeset 没有生产消费者。
⑩说的=摆的：意图秒数与模型可收秒数混用；⑪能选到：模式/变体收窄但已存值不跟随；⑫点了=以为的：换模式显示与发送不一致。第 0 步 tests/model-params/contracts.test.mjs 的 13×3 尺子记录缺口，本步保持红33/绿6，不结逃逸账本。

## 4. 靶子独立性检查

研究线独立，尺子由第 0 步实现线写。第 1 步不重写尺子、不改 expected；使用冻结读数与官方 wire 导出双对照。未查到本概念因评测掉分而回滚的证据，不编造。尺子红33/绿6是已知产品缺口，不能冒充产品已合法。

## 5. P0：这些是我们独有的吗

范围/枚举判据继续用 paramConstraints，比例继续用 aspectRatioValue，无新依赖。通用验证库只能判合法，不能替我们决定人手、Agent、发送复查的领域政策。研究报告已比较通用验证/默认值机制，本步不新增外部契约。

## 6. 三条路对比表 + 推荐

| 选项 | 做什么 | 代价 | 风险 | 推荐 |
|---|---|---|---|---|
| 沿原方向修 | 各处补；8–10 文件 | 九种做法继续存在 | 新入口重演28次修补 | 否 |
| 换一种做法 | resolveModelParams 收口；约20文件分0–4步 | 第1步零差异，后续改行为 | 必须保留现状政策差别 | 是，已拍板 |
| 删掉 | 删写时规整，只在发送拦；10–12文件 | 用户发送才发现 | 违背原来就写对 | 否 |

第1步最小删除单位：四处各写的规整实现、没人读的 changeset、拟镜两常量；同提交用共享函数替换。老用户无需迁移，打开不写，保存/请求字节保持现状。

## 7. 用户要权衡的核心

先收成一个主人，再改变写入政策；本步没有产品行为收益，收益是后续只需改同一个边界。
用户拍板原话：「我们都需要做的时候收到一处 然后完整替换」「能不能让他把秒数原来就写对」「能否不发生这个问题 提前发现」。Q2：合法就留，不合法回默认（推荐项）；Q3：参数条旁一行就地说明（推荐项）。本步按任务书只收口，不提前做第2–4步。
