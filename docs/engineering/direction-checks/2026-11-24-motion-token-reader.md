### 0. 一句话根因

设计系统拥有时长、缓动和按压语义，但 CSS 镜像、运行时退出和源码门岗各自推断这些规则，导致同一合同在换一种写法或进入通用组件后失效。

### 1. 归类表：bug → 直接原因 → 类

| 提交 / bug | 直接原因 | 类 |
|---|---|---|
| CSS 退出变量漂移未拦截 | 正则取值再建键值对象，重复声明只剩最后一条 | 镜像丢失声明身份 |
| 原始 CSS 时长、缓动及 Motion 引用逃过门岗 | 旧检查依赖字符串提示，且只读过渡属性里的字面量 | 判据依赖源码形状 |
| 越权 `active:scale-[0.97]` | 批准的按压语义可以按底层类名被直接复制 | 组件权限未落实到行为边界 |
| 采集飞图退出沿用完整入场时长，按钮加载缺独立状态 | 退出目标继承入场过渡，Mantine 的装饰性加载器隐藏其内容 | 共用适配边界遗漏语义 |

### 2. 为什么这一类会一直出现

最早应拦在设计 token 门岗。把 CSS 声明压成键值或仅按源码字面形状判定，都会丢失独立声明和词法绑定。按钮状态属于 `DesignButton`，应由共用组件在忙态子树外发布。⑫ 适用于点击采集和触发加载后看到、听到的反馈。对应的组件测试锁住退出参数和可访问状态，真实采集与屏幕阅读器播报尚未核实。⑩、⑪ 所管的模型参数意图和入口选项与本案无关。

### 6. 三条路对比表 + 推荐

| 选项 | 做什么 | 代价 | 选了以后同一类还会不会出现、从哪出现 | 风险 | 推荐 |
|---|---|---|---|---|---|
| 沿原方向修 | 为每种 CSS / TS 写法扩匹配，按文件放行按压 | 本轮小，后续每种写法单独维护 | 会，嵌入 CSS 的第二套读取和获批文件内新增控件都能复现 | 门岗漏报 | |
| 换一种做法 | 实现线在本轮替换单条门岗的读取，用 PostCSS 8.5.15 读取镜像和可静态提取的 CSS，复用 TypeScript 5.9.3 解析绑定。旧读取同提交删除。所有受检路径共用现有工具类判据，0.97 字面类由既有 token 源集中定义，现有文字按钮和发送按钮消费 token | 调整读取与反向夹具 | 同形输入和各受检路径得到同一判定，动态构造的 CSS 和非本地绑定仍超出本次证据 | 误报会打断合法动效，须对照合法 token 与既有棘轮 | **推荐** |
| 删掉 | 最小单位是独立嵌入 CSS 正则。用同一个解析入口继续校验已有静态样式，原调用方仍用既有变量和组件 | 需保留嵌入字符串位置映射 | 同一声明在两种读取器间行为分裂的路径消失 | 插值模板需测试 | 并入推荐项 |

P1 例外判断：初次暂存的文件级按压特例和嵌入 CSS 的第二套读法使整份门岗补丁超出协调代批范围。最终采用推荐的结构替换。实际样式表和静态 CSS 模板共用 PostCSS 读取，原始按压字面类进入既有工具类判据，唯一原始值留在动效 token 源，基线文件无差异。协调会话按 P1 的结构替换例外代批。

### 7. 用户要权衡的核心
