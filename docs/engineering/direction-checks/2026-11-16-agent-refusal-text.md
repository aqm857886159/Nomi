# 方向检查：拒收文字只保留事实与动作

## 0. 一句话根因

宿主手写的拒收文字同时供应用内 Agent 与外部客户端读取，字段名又在提示词中重复维护；测试钉住措辞，未核对字段是否真实可用。

## 1. 归类表：bug → 直接原因 → 类

| 提交 / bug | 直接原因 | 类 |
|---|---|---|
| 16b8a9cd1：不存在的模型 | 正文指导填写清单从未发布的供应商字段 | 宿主词汇泄入模型面 |
| 67be4fc91：无默认模型 | 下一步动作再次手写同一套字段教法 | 同类重复 |
| f15d05bb2：单一完整名字 | 工具定义已改，共用拒收仍教旧字段，锚指引测试仍钉旧句 | 定义与散文分离 |

## 2. 为什么这一类会一直出现

交接全图 `docs/plan/2026-11-16-agent-writes-params-seam.md` 第 9 步没有按面翻译，工具定义与拒收散文没有引用关系。最早应在实现时删除第二份字段教法；结构门此前只量工具字段和名字拼法，不量散文。对应体验铁律⑪「能选到」；⑩、⑫本轮不改。

## 3. 不改结构的话，接下来会冒出什么

| 预测 | 验证 |
|---|---|
| 共用拒收重新写回字段教法，原测试仍可能绿 | 正文与 Next 的保证测试；改回旧教法须红 |
| 字段修改后，完整规划提示仍保留重复教法 | 规划提示测试断言重复指导消失、列表与锚约束保留 |
| 拼名和截断仍可能绕过原结构门 | 加号拼接、数组 join 和长完整名字反例 |

## 4. 靶子独立性检查

独立复盘与验收先于本修补。旧锚指引测试曾因正确改名而红，说明它量的是原句。替换为业务保证，不把错误原句恢复到生产。领域正文保留收到的值、最近模型、下一步动作；未知字段仍由校验器提供路径。

## 5. P0：现成方案

pi 的工具入参校验从 schema / 校验器产生路径；本仓 `toolInputIssues.ts` 已采用这一边界。保留现有框架与依赖，本轮不引入库，不新写字段说明生成器。唯一需要自写的是模型目录的领域事实与重试动作。

## 6. 三条路对比表 + 推荐

| 选项 | 做什么 | 代价 | 风险 | 推荐 |
|---|---|---|---|---|
| 沿原方向修 | 逐处换成新字段名 | 小 | 再维护一套散文，下次再漂移 | 否 |
| 换一种做法 | 各面从定义生成字段说明并投影回程 | 中 | 涉及两个面，需要独立交付与验证 | 下一步 |
| 删掉 | 删除正文、Next、压缩提示及规划提示里重复教字段的半句；保留目录事实与唯一业务指引 | 最小 | 唯一业务约束不能误删 | 本轮 |

用户于 2026-11-16 批准先删教法、再由下一轮从定义生成；同日裁定完整 JSON 规划提示逐句核对输出定义，重复的删、唯一约束留，列表行不改。无落盘迁移，老用户数据与请求体不变。

## 7. 用户要权衡的核心

先让模型少读一份可能说错的教法，下一步再让必须提到的字段名只能从定义产生。
