## 0. 一句话根因

宽已经量对了（上一轮的「乙」关掉了「量错」），毛病在用量到的宽挑样子：梯子只往下走、每一级都带着前面所有让步，退到「方式只剩图标」时，前面已缩成「5s」的摘要不会补回来。查过的 Fluent 严格优先级也是这种做法。

## 2. 为什么一直冒

梯子是一条固定单行道：新宿主、新语言、胶囊多出的 64px，每种新宽度都落到梯子上某个没人看过的位置，结果要么是顺序之争（11-14 一天三次裁决），要么是这次的「退过不回填」。英文那格的根因是不回填。中文那格不是：一个整值至少 39px，比剩下的 21.5px 大；换顺序（方式只剩图标、换回「720p」）白反而变成约 33px，所以这段白是「值不截半个」的代价，不是 bug。

哪一步本该拦住：验收目标测试 `composer-bar-yield-goals.walk.mjs` 的 G3 只在「换样子的那一点」查不早让，不查换过以后剩下的空位能不能放回东西（判据漏了这种形状），所以主分支实验室的浪费一直是绿的。三条体验铁律（⑩ 说的 = 摆的、⑪ 能选到、⑫ 点了 = 以为的）都不适用，这是布局类；「每个按钮都点得到」在实验室由 G4 守着，真窗口最小窗有一处没守住（见末节「另报」）。

## 4. 靶子独立性 · 特征测试

G2–G4 用叶子余量判、不读产品梯子，是独立的；缺口在 G3 只看紧的一侧，「全部浪费」照样能过。G6 由不实现的线在动手前写好，宽度取走查自己看到的余量差。目前没有「修对了反而掉分」的先例。动手前钉住：`composer-bar-yield-{goals,history,transitions,cycle,calibration}.walk.mjs` 现状全跑一遍留收据；history / transitions / cycle / calibration 读的是 `data-bar-yield-level` 级数，换清单后要改成读样子本身。

## 5. P0：哪些是我们独有的，现成方案有哪些

独有的只有顺序（模型名 > 方式名 > 摘要从后往前的值 > 钮上的字，11-14 裁决）。现成做法从官方源码和文档原文取：

- **Fluent UI `@fluentui/priority-overflow`**（`overflowManager.ts:206`）：「优先级比已藏的高的，也要藏」，展开到第一个放不下就停，不会跳过放不下的去补放得下的；上一份查过的 rc-overflow、Spectrum、Primer 也都是「藏到第一个放不下为止」（pretext 只量字宽）。这几家里**没有「让完再填回去」的现成组件**；按清单挑约 10 行，用同一把尺子、同一批宽。
- **CSS 原生替不掉手写量法**：`flex-shrink` 按比例压，会截半个值；容器查询是写死断点、量不到字宽（Primer #8133 同样取舍）；`text-wrap: balance/pretty` 只管行长均匀，不保证在句号处断；scroll-state 查询按「有没有溢出」改样式，改了又影响溢出，会来回跳。
- **提示分行用平台现成能力**：`Intl.Segmenter` 按句切（MDN：`granularity: "sentence"`，Baseline 2024-04 起各家浏览器都支持）；Radix Tooltip 自带 `--radix-tooltip-content-available-width`（官方文档：「The remaining width between the trigger and the boundary edge」），最宽到窗口可用宽（仓库已有 `@radix-ui/react-tooltip ^1.2.11`）。

同类产品（`docs/design/peers.json`，只看公开页）：
- TapNow · docs `new-canvas/generate-on-a-node`：设置点开改，「按钮上显示预计 Tapies」，和我们的胶囊同一种做法，窄了怎么让没写；它的偏好面板把摘要尾巴截成「15s · With …」。影响：支持不碰胶囊；截半个值正是 D-1117 不许的，排除 CSS 省略号。
- 可灵 · 视频 3.0 官方指南图：生成框底栏只有「多镜头」开关和三个图标，比例、时长不在这一条上。影响：这是「删掉摘要」的实例，但它也丢了「发之前一眼看到值」。
- Google Flow · 帮助中心 16353334：只列比例、条数、模型、时长，没写放哪、窄了怎么让，影响无。查了没看到：Runway 帮助中心被挡；LibTV 更新页没有条目；Luma 文档 404；几家公开页都没展示多行提示怎么断。

## 6. 三条路对比 + 推荐

共用目标测试：保留 G2（宽了一个不让）、G3（不早让）、G4（每个钮点得到、只有一份；「摘要是现在的值」读屏上的字）。**G6 新增**：每种样子下，每个缩过的东西放回一级要的宽都大于当时剩下的空位（四宿主 × 中英 × 400–1200，加约价 600 宽）。**G7 新增**：悬停发送键，换行都落在句子之间，提示不出窗口。

悬停提示（不论选哪条都要做）：`max-w-56` **算违背** D-1117-cost-hover-shared-tooltip「长一个样」——它把提示做成 224px 宽、在词中间断行。主分支上已有至少四处自定多行：`AdvancedSettings.tsx:84` 280px、`LibraryPicker.tsx:73` 和 `AgentPanelV4Composer.tsx:82` 320px 纸色底、`AssetLibraryPanelParts.tsx:459` 224px，实验室 `02-overlays.tsx:171` 还有一份，胶囊是第 6 份。根子不在约价：`src/design/tooltip.tsx` 只有单行一种样子。按 D-1121「只认原料收走，按写法扫描只算提示」，修法是结构上收走：共用提示自己出唯一的多行样子（按句分行、每句不折、最宽到窗口可用宽，只有一句比窗口还宽时才句内折），调用方不再能传宽度和折行；两处纸色底其实是小卡片，改用卡片组件（改样子前先出图）。英文第二句约 85 个字符，一句一行约 500px 宽，嫌宽就改短英文文案（交设计）。拍板图 M4 ① 自己在「公开价｜估」中间断行；D-1117 备注说那块说明只有文字是合同、框不是，所以断行位置不算合同（协调 11-21 定：D-1121-tooltip-multiline-shared），G7 照「只在句间断」写。

D-1118「梯子顺序、样子、文案和行为不改」是不是来源：英文**证实**——浪费正是被冻结的「只往下走」造成的，实验室里 11-14 起就有，胶囊多出的 64px 把默认 600 宽推进同一种情形；中文**推翻**——冻不冻结、换不换顺序都消不掉那段白。只放开「行为」里的「不回填」，顺序、样子、文案照旧。

## 7. 用户要权衡的核心

推荐那条修好英文「有空位还缩」，但底栏缩过以后仍可能留下不到一个值宽的白（中文默认宽带价约 20px）：要填满只能截半个值，或拿方式名换「720p」（白反而变成约 33px），两样都比留白差。用户 11-21 定：接受留白（D-1121-bar-yield-zh-slack-accept）。
