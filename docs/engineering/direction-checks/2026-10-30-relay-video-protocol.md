# 视频协议与成品取回：类根因复盘

## 0. 一句话根因

运行时把「HTTP 成功」和「拿到媒体」混在一起，而声明卡没有结果字节这一角色，未知连接又被赋予未经文档证明的路由。

## 1. 归类表

| 症状 | 直接原因 | 类 |
|---|---|---|
| 已生成但 assets=[] | MP4 被 JSON/text reader 消费 | 返回角色未类型化 |
| 标准文生视频卡非法 | multipart 强制参考文件 | 编码合同借用了图片输入限制 |
| 文档路径与实发不同 | 未知连接沿用单数路径 | 协议选择缺证据 |

## 2. 为什么一直出现

单测沿着现有 JSON URL 形状造上游，没跨过文件响应、解码发布与恢复三个边界。⑩ 说的=摆的：卡上的编码/路径/结果角色必须和实发相同。⑫ 点了=以为的：重新取回只 GET 原任务。⑪ 能选到的模式投影归并行能力线，本刀不更改它。类检查为 tests/relay-onboarding/protocol.test.mjs，普通特征复现来自 tests/relay-onboarding/contracts.test.mjs。

## 3. 可验证预测

| 未改结构会怎样 | 验证 |
|---|---|
| 另一个 /content 中转仍丢片 | 删除 mediaResponse 执行分支，协议矩阵红 |
| 假成功 HTML 当产物 | HTML/JSON/坏字节/MIME 负例不得发布 |
| 重启后重新扣钱 | 清缓存重建，整段 POST 必须仍是 1 |

## 4. 靶子独立性

协议来自公开官方文档及 SDK，MP4 夹具走现役解码与落库，不用 mock 断言代替。实现与本地测试同线，不冒充独立验收；协调另派验收。预算与真服务结果仍须实测。

## 5. P0

复用原生 Fetch/FormData、Node pipeline/backpressure/AbortSignal、现役 vendorHttp 鉴权/重定向门、copyAssetFile 的暂存→解码→发布。无新增依赖，不重写编码器/HTTP 栈/解码器。领域代码只绑定任务身份、声明角色与项目资产。

## 6. 方案比较

| 方案 | 结果与代价 | 结论 |
|---|---|---|
| 接标准与已有边界 | 声明文件结果，pipeline 流式落盘，现有解码发布 | 采用 |
| 加供应商特例 | 每个模型再补路径与字节分支 | 不采用 |
| 重写下载/任务系统 | 新 owner 与迁移面，仍要对接项目身份 | 不采用 |
| 删除隐式选择 | 未知协议先交卡，显式旧 mapping 原样保留 | 同提交完成 |

### 第三轮命中的自写登记（先评估现成方案，P0）

churn 检查点名了两条在评估中的登记，这里写清各自为什么这一刀换不了、哪天换。
