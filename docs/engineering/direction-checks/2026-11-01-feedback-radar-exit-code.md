# 方向检查：反馈雷达的退出码 1，到底是结论还是报错（2026-11-01）

命中（`node scripts/fix-churn.mjs --staged`）：概念「这条反馈记没记（待分诊账）」近 14 天 2 个 fix，这一刀是第 3 个。这个概念是同一个 PR 刚建的，两个 fix 里 `d6726a347` 是建账本身，`68b10f82d` 是杀超时进程树，和这一刀不是一回事。

来源是逃逸账本的修复（`USER-20261101-feedback-radar-missed`）。结账挂的类检查是矩阵测试 `scripts/daily-radar-session.node-test.mjs`。

## 0. 一句话根因

退出码 1 同时表示「雷达跑完了，结论是判停」和「脚本没跑成」，开会话的 hook 只看退出码，于是把一个结论说成一次失败。

| 提交 / bug | 直接原因 | 类 |
|---|---|---|
| `d6726a347` 新反馈漏掉 | 没有账，hook 只留最后 14 行，「新增」被挤没 | 账和摘要 |
| `68b10f82d` 超时不干净 | 超时只杀了父进程 | 门岗的进程管理，不是这个概念的问题 |
| 这一刀 | 判停退出 1，hook 的 else 分支写「今天没查成」 | 退出码一码两义 |

## 2. 为什么这一类会一直出现

版本健康是后加进雷达的。退出非 0 是给发布流程看的：判停就拦放量（`docs/release-process.md`）。hook 比它早，把所有非 0 都当脚本报错。两个读者对同一个码要的东西不一样，而码只有一个。

三条体验铁律都不适用：这是开发侧开会话时读到的一行字，不是用户意图、模型参数或可点目标。

## 3. 不改结构的话，接下来会冒出什么

| 预测 | 怎么验证 |
|---|---|
| 报告最后一行换写法，hook 退回「今天没查成」 | 改 `scripts/lib/intake-radar/health.mjs` 的结论前缀，`真实摘要：过真实的报告渲染` 那条测试变红 |
| 雷达再加一种「跑完了但要拦」的结论，不写成 `停止放量：` 开头，hook 又说没查成 | 同上，新结论走一遍真实渲染 |
| 别的雷达也用退出 1 表示结论 | 现在只认用户反馈雷达这一行的声明，`别的雷达碰巧打了同样一句` 那条测试钉着 |

## 4. 靶子独立性

判据不是 hook 自己定的：`docs/release-process.md` 写定报告最后一行是三种结论之一，`scripts/intake-radar.node-test.mjs` 断言最后一行和退出码。hook 这边的测试用真实的 `renderTerminalSummary` 出摘要，不手写。

## 5. P0：这是我们独有的吗

不是。一个码表示一种意思有现成约定：POSIX 的 `grep` 用 0 / 1 表示结论，大于 1 才是出错（https://pubs.opengroup.org/onlinepubs/9699919799/utilities/grep.html）。

## 6. 对比和推荐

| 选项 | 做什么 | 代价 | 风险 | 推荐 |
|---|---|---|---|---|
| 接入现成约定 | 判停换一个专用退出码，真错误留 1，hook 只看码 | 改 `scripts/intake-radar.mjs`、hook 和两处测试；发布流程文档写的是「非 0」，不用改 | 要确认没有别的地方写死了 1 | 下次碰雷达时做 |
| 补（这一刀） | hook 认「退出码 1 且最后一行以 `停止放量：` 开头」，报已跑加判停 | 一个声明、一个分支 | 依赖最后一行的合同，换写法时测试会红 | 这轮做：协调裁定只修标签，这轮不再加东西 |
| 重写 | 不值，雷达其他部分没问题 | | | 不选 |
| 删 | 判停不再退出非 0，只写在报告里 | 发布流程拦不住放量 | 高 | 不选 |

## 7. 要权衡的核心

现在靠读报告最后一行认判停，小而够用；换专用退出码多改三处，hook 就不用读文字了。
