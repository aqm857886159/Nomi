# 方向检查：出网「按目的地地址拒绝」这一层（第 3 轮，选删）

> 触发：同一条线第 3 轮（#1492 两轮「保留这层、给代理开例外」，验收 `V-outbound-guard` 又找出一个洞）。
> 用户原话：2026-11-12「『发送前被本机拦下』走哪条路怎么说 这种被拦下的东西 最好能不能删掉 遇到类似的问题 太烦了」；
> 2026-11-13 听完这层防什么之后「可以把这个删掉吗」「我觉得我们就一个小本地软件 很多拦截 似乎没有必要吧」。

### 0. 一句话根因

这一层用「本机解析出的地址」判断目的地安不安全，而开着代理（TUN / fake-ip）的电脑上本机解析出的地址根本不是连接要去的地址；每换一种代理默认值（v4 198.18、v6 合成段、探测缓存过期、局域网名字），判据就再错一次。缺的不是又一个例外，是这一层本身对一个创作者自己电脑上的软件不挣命。

### 2. 为什么这一类会一直出现

判据的输入（本机 DNS 答案）在代理环境下不可信，所以每个修法只能靠「证明代理在」的探测 + 例外，探测本身又会被路由器 / 热点劫持骗过。铁律 ⑫（点了 = 以为的）：创作者点「生成」以为会发出去，实际被本机拦下；这层删掉后，点了就发。

### 3. 不改结构的话，接下来会冒出什么

| 预测 | 怎么验证 |
|---|---|
| 新的代理默认段（如 sing-box v6 `fdfe:dcba:9876::/126`）再拦一次开代理的人 | 往 `classifyOutboundAddresses` 喂该段地址 → 拒 |
| 局域网 NAS / 本机中转作为接入地址的取回在跳转后被拒 | V-outbound-guard 探针：同 origin 内部跳转 → 拒 |
| 遥测里 `network.outbound.refused` 全是正常开代理的人 | 拒绝事件按 `syntheticResolver` 切片 |

### 4. 靶子独立性检查

验收线 V-outbound-guard 独立于实现线；它找到的洞来自「例外」本身。没有「修对了反而掉分」的评测。

### 5. P0：这些是我们独有的吗

不是。SSRF 防护是服务端（多租户、云元数据）的通用问题；GitLab 遇到代理同题时直接整段关掉（gitlab-org/gitlab#378267），Stripe smokescreen 把它放到自家出口代理。Nomi 是单用户本地软件、供应商是创作者自己选的，这层没有领域理由。

自写登记条目（提交钩子点名）：
- `network-stack`：这一刀是删，不是补——自写的地址判据整层删掉，只剩丙 4 / 丙 5 用的分类器。剩下的出口本身（hardenedFetch：单次请求上限、类型白名单、带密钥禁跳转）现在换不了现成库：undici / got 都不管「带自定义鉴权头遇跳转即停」与「取回响应头类型白名单」这两条，要换得把这两条挪到调用方，又是多处各写一遍。哪天换：丙 4 / 丙 5 由协调定掉之后，若分类器也删，hardenedFetch 就只剩上限与跳转规则，届时评估换成 undici 原生 `maxRedirections: 0` + 调用方类型校验（随 `docs/engineering/self-written.json` network-stack 条目 reviewBy 2026-11-30 那次评估一起做）。
- `gate-family`：本刀只缩门岗 `check:outbound-policy`（删规则 2），不新增门岗，是减法。门岗族整体换现成方案（eslint 规则 / dependency-cruiser）是门岗族自己的复盘，不在本线；这一刀不给它加任何东西。

### 6. 三条路

| 选项 | 做什么 | 代价 | 风险 | 推荐 |
|---|---|---|---|---|
| 沿原方向修（继续给代理开例外） | 第 3 轮补「解析出的链路本地」+ 局域网名字 | 每种代理默认值一轮 | 已证明例外会打出新洞；用户已明说太烦 | 否 |
| 换一种做法（只警告不拦） | 判成内网时弹提示、仍然发 | 一个新弹窗 + 词条 | 用户每次生成多读一句；判据还是错的，只是不挡人 | 否（不挣命，任务书明令不换成警告） |
| 删掉 | 删「按目的地地址拒绝」整层：提交 / 轮询 / 上传（甲）、取回成片 / 下载 / 探测 / 本机服务（乙）、媒体转发（丙 1-3）；只保留丙 4 / 丙 5（Agent 读文档网址、接入向导抓文档，任意文字进模型）原判据，待协调另定；留下密钥两条：密钥只发往保存时确认的 origin、带密钥遇跳转即停 | 删掉一大批代码与测试 + 门岗 `check:outbound-policy` 里已无对象的 appFetch 棘轮（规则 1 / 3 守丙 4 / 丙 5 还在用的分类器，规则 4 与地址无关，保留） | 见下「残余风险」 | **是** |

老用户怎么过：停在「发送前被本机拦下」的镜头 → 升级后按已删码表读成无码的普通失败卡，点「重试」就发出去（这次不再被拦）；停在「取片被拦」的镜头 → 已删码表把旧码读成取回族（retrieval-download），有任务号就是可找回，「重新取回」照常可点、这次取得回来。

残余风险（照实写）：
- 恶意中转站 / 供应商可以返回一个指向局域网的结果链接，借 Nomi 往局域网发一次**不带密钥**的 GET；取到的内容只落在创作者自己的项目里（媒体类型才收），不会被自动发给第三方。
- 丙 1-3（远程图 → 模型、参考音频 → 转写、输入文件 → 即梦）同样不再按地址判；取回内容只有是图 / 音 / 视频才被用上（类型白名单在 hardenedFetch 的 `allowContentTypes`），带不出有价值的内网文字。
- 丙 4 / 丙 5 本轮不动，待协调定。
- 密钥两条不依赖这一层（`catalog/credentialBinding.ts`、`credentialRedirectPolicy.ts` 与 hardenedFetch 的带密钥禁跳转，三处都不 import 地址判据）。

### 7. 用户要权衡的核心

为了挡住「恶意供应商借 Nomi 往你家局域网发一次不带密钥的请求」这种对单机创作者几乎不发生的事，值不值得让每个开着代理的人隔三差五点生成被拦——用户已答：不值得，删。
