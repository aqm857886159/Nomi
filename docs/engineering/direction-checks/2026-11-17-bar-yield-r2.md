| 乙：只量会变的文字，用 DOM 尺子：每只底栏一个不占位的 `aria-hidden` 宿主，挂关闭的影子根，里面只有纯文字 `span`；宿主带 `text-caption` 等同一组类，字体、字号、字重、字距、`font-feature-settings` 靠 CSS 继承穿过影子边界 | 准：同一排版引擎、同一条字体回退链（`nomi-tokens.css:83`）、字距继承。字体晚到时尺子文字尺寸会变，RO 触发。缩放：都在布局 px 里比，画布的 transform 两边一起缩，不影响比较。外框差（`gap`、`padding`）能从画着的元素 computed style 读的就读，读不到的（① 的两种外框）写成常数，由一条校准测试钉住（见第 6 节） | 未验证：没跑。量规模是每只底栏 ≤ 6 段短文字、一个影子根、几条 RO 记录；量法照 V 的 `storyboard-plan-open`（配好模型）+ `canvas-select-composer-video-200`，和 main `aa86126`（440.5 ms / 53.6 ms）比 | 不会：关闭的影子根里只有文字，没有按钮、角色、`data-*`。`querySelector`、Playwright 的 CSS 和 `getByText`（只穿开放影子根）、读屏（宿主 `aria-hidden`）都找不到 |

## 0. 一句话根因

让级取决于「没画出来的那几种样子」有多宽（方式名、更全的摘要、钮上的字）。这些样子的文字归别的主人（宿主塞进来的 `footer.action`、NomiSelect 的选中项、i18n），底栏主人手里没有它们的数据。三版各用一种方式重新推断：main 手写重算钥匙（漏了语言），第一轮只看画出来的（看不到藏着的），第二轮把带身份的活组件整份复制（复制了按钮、慢 40%）。同时目标和总测试是从这次的坏事（「当场 ≠ 重开」）推出来的，不是从目的（「只在真放不下时才让」）推出来的，所以「处处多让」能全绿通过。

## 2. 为什么这一类会一直出现

1. **表示层（类 A、C）**：`footer.action` 是 ReactNode，方式名藏在 NomiSelect 里，底栏主人既不知道「另一种样子」里写什么，也不知道有没有另一种样子（上表最后一行就是证据）。所以每一版都只能「在别处重新推断另一份结论」，正是四条原则第 1 条要避免的（`.agents/skills/root-cause-remediation/SKILL.md:16`，main 上）。手写钥匙会漏输入；只看画出来的看不到藏着的；整份复制把身份也复制了（同一个 aria-label、`data-*` 出现 N+1 份），身份不再唯一。
2. **判据层（类 B）**：上一轮任务书的目标句（`briefs/20261108-mac/实现线.md:3`）是「每个按钮都点得到，摘要里显示的都是现在的值（放不下就整值少一个…）」，里面没有「只在真放不下时才让」，没有性能，也没有「不多出第二份」。总测试 L58 写的是「等于重开」，这是从「当场 ≠ 重开」这次坏事反推出来的，不是从目的推的。测试和实现同一条线、同一个提交（`634448a01`）写，尺子是同一实现重开。这三点都违反第 3 条：判据要从目的推，要由不改代码的人在改之前写好（`SKILL.md:22`，main 上）。
3. **方向层**：三轮都在「怎么知道没画出来的样子有多宽」这一个问题上换手段，没人先把「量什么」的几种方法摆在一起比。每轮的修法都只盯上一轮的验收意见。

三条体验铁律：⑫「点了 = 以为的」部分适用。「每个按钮都点得到」是 ⑫ 的前提；副本让引导聚光灯和「去换模型」按 DOM 顺序碰对，一旦顺序变，会指到看不见的那份。⑩「说的 = 摆的」⑪「能选到」不适用：这里没有意图和草稿参数对不上，也没有档案清单缺入口。

## 4. 靶子独立性

- **尺子和被量的是一家**：`composer-bar-yield-history.walk.mjs` 和实现同一提交（`634448a01`）、同一条线写。它的 oracle 是同一实现重开（`:75` `before.level === reopened.level` 等）。「全部拦下」重开也全藏，所以照样相等（验收线 第 2 节）。
- **断言没对准目的**：`wholeCurrent` 是子集判断（`:35-47`），显示「5s」也算对；时长检查读的是 `title`（`:75` `before.full.includes(...)`，而 `title` 永远是全量摘要，见 `InlineParameterBar.tsx:574`），不是屏上显示的字；宽度只有 485–650（`:55`），没有一个「宽到必须是 0 级」的格子。
- **测试的取景框天生看不到副本**：`facts` 只在 `[data-node-composer-footer]` 那一行里取（`:36`），可见控件过滤掉了 `visibility:hidden`；量层是这一行的兄弟节点，所以测试结构上看不到「多出第二份」。
- **修对了反而会红的先例**：transitions 走查有实现相关的前置条件（「574 宽下必须在第 0 级」）。改坏 ② 时它是 throw，不是断言（`mut2-all-hidden-transitions.log`）。字体或外框一变，正确的实现也可能在这里 throw。
- **先修靶子**：第 6 节的目标测试（G1–G5）应由不实现的线在动手前写好；它在「什么都不做」和「全部拦下」两版上都要红，在甲上要被 G4 判红。

**推荐「换一种做法（乙）」**。理由按事实：
① 第二轮唯一被证实的产品问题（副本、+40%）都来自「复制带身份的活组件」，而让级本身算得对（验收线 第 3、4 节：真窗口和三条自找路都对）。乙保留甲「由量到的宽直接算、不存历史」这一半（所以 G1 天然成立），只把量的对象从「整组组件」换成「文字」。
② 什么让「漏一种输入」在结构上写不出来：让级只读两样东西，画出来的节点尺寸和尺子里每段候选文字的尺寸，都挂在 RO 上，而且每次渲染都重算。语言、字体晚到、缩放、换值、积分数变，只要会改变某一级的宽，就必然改变其中某个被观察的尺寸，所以没有一份要人记着补的重算钥匙。尺子在关闭影子根里、只有文字，选择器、`getByText`、读屏都找不到，「第二份」从结构上做不出来。剩下没被结构覆盖的只有一处：① 级的外框常数。它由校准测试自动拦，这一点诚实写明是门岗级。
③ #1549 胶囊变宽以后也成立：胶囊在画布是画着的格（画布圆钮没有 ① 级），宽度变化由 RO 看到；以后若让积分数也进梯子，它的另一种样子只是尺子里多一段文字。甲在 #1549 上会复制胶囊和「去充值」（预测 1）；删掉（断点）不认积分数的位数。

1. **上一份推荐的那条路，第一轮照做了，正好栽在它自己表里的一行**。它推荐「删冻结 + 删手写清单，改为观察每个 `data-yield-item` 自己的尺寸，任一变了从 0 级重量」。它的同形状洞表第 37 行写「切语言，摘要字不变但方式名变宽 → 不会重量」，默认方式名是画着的。可到了「方式只剩图标」那一级，方式名根本不画，观察画着的格看不到它。第一轮 `cfe551ab4` 就是这样被 验收线 抓到的（485 en 4 → zh 仍 4）。本份把类 A 从「画着的格变了没人重量」扩到「**没画出来的样子**没有数据来源」，这是两份最大的差别。
