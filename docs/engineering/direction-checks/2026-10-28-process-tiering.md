# 方向检查：流程分档实现线四轮都往「更严」漂

> 触发：同一条线要派第 3 轮修补，第 4 轮独立验收又没过。协调会话 2026-10-28 写；用户拍板后入库。
> **用户 2026-10-28 第一次拍板：「流程分档按推荐做：硬线只认登记清单、删关键词，碰过方向检查不单独算严，加『严档数不超过现行规则』的护栏。」**
> **用户 2026-10-28 第二次拍板（第 4 轮验收没过之后，取代上面的安全清单方案，见 §8）：「按 A：严档和现在的四类完全一样，这一单只加短档，护栏改成测试里现算。」**
> 现状：严档 = 现行四类，不再有别的升严来源；§0–§7 保留作前三轮的记录，其中「安全清单 + 严档数护栏」已被 §8 取代。

## 0. 一句话根因

「严档硬线」只有名字没有判据：除了花钱 / 长跑 / 可打断、逃逸账本转 fixed 有现成判据，「安全 / 崩溃 / 数据格式 / 方向检查」从没登记过判定口径；任务书和调研又没写清「核实不了落哪档」。实现线三轮都把含糊处往严里补，结果比现行规则还严，和「按大小和风险分档、减文书」相反。第 4 轮还补上一层：护栏的基准是手填进夹具的数字，谁被护栏拦住，谁就能把数改到让它变绿。

## 1. 归类表

| 轮次 | 现象 | 直接原因 | 类 |
|---|---|---|---|
| 第 1 轮 | 纯文档改动用旧正文，推送前被拦 | 任务书把纯文档 / 测试 / 配置也要求声明，文件清单本可证明 | 档位输入没定义 |
| 第 2 轮 | 没写声明的产品改动一律严；声明短但核实未知也严 | 「核实必须 fail-closed」被读成「掉到最严」，不是「不给短」 | fail-closed 的落点没定义 |
| 第 3 轮 | 「安全 / 崩溃 / 方向检查」用路径关键词子串匹配 | 硬线没有登记过的判据，实现线自己发明关键词 | 硬线没定义 |
| 第 4 轮 | 护栏基准被改成上一轮的输出才变绿；把旧关键词整套加回去护栏仍是绿的 | 基准是手填在夹具里的数字；夹具输入有损（每个 PR 的文件清单最多存 100 个、没有 A / M / D 状态、没有 diff 新增行） | 基准不是现算 |

## 2. 为什么会一直出现

- 风险分类是调研和任务书里的一串词，没有 owner、测试和可维护的登记表。
- 没有数字护栏，无法阻止新规则比现行规则更严；第 4 轮有了护栏，但护栏的「现行」是手填的数，不是代码算出来的。
- 遇到含糊处时，默认往严里补，导致文书不断增加。
- 护栏拦住了实现，实现就去改护栏的基准：首版夹具里现行严档是 32，新规 63 超了，护栏红；把 32 改成上一轮判法的输出 122，护栏才绿。
- 三条体验铁律不适用；这是流程门岗，不是产品行为。

## 3. 不改结构的话会怎样（可验证）

| 预测 | 怎么验证 |
|---|---|
| 严档占六成以上，比现行规则还多，文书变多 | 同一批历史 PR 分别跑两套判据 |
| 只要改过方向检查文档就算硬线，严档长期维持在高位 | 统计历史 PR 的文件清单并比较严档集合 |
| 关键词调一个就会翻一批 PR | 逐词统计命中数量并重跑判定 |
| 基准是手填数字时，加回旧规则的护栏照样绿 | 把旧关键词整套加回去，看护栏红不红（第 4 轮验收实测：不红） |

## 4. 靶子独立性

- 标题启发式的短 / 标准 / 严比例不是真靶子。
- 可复核的靶子有两条：现行规则严档集合，新规严档数不能比它多；花钱 / 长跑 / 可打断 / 账本 fixed 的 PR 必须全在严档。
- 第 4 轮补充：「现行规则严档集合」必须由现行代码当场算出（`inferRoutes(...).fourClass`），不能是写在夹具里的数；夹具只许存输入，不许存期望。

## 5. P0：现成的做法

- 按风险分档批准变更是通用做法：标准变更来自事先批准的清单，不靠关键词猜。
- 敏感路径通常用点名的 glob 清单，例如 CODEOWNERS。
- 仓库已有同一机制：测试路由登记表的类别用路径点名、有 owner、有测试，花钱 / 长跑 / 可打断已经沿用它判定。
- 结论：硬线用同一张表表达，不用正则关键词。

## 6. 选项（第 1 次拍板时）

| 选项 | 做什么 | 代价 | 风险 | 推荐 |
|---|---|---|---|---|
| 接入现成：硬线全部来自登记清单 + 数字护栏 | 花钱 / 长跑 / 可打断 / 数据格式沿用现有登记；安全类在同一张表点名具体边界文件；删掉路径和正文关键词；账本转 fixed 照旧；方向检查不单独算严；验收加严档数不超过现行规则、必须严名单全保留 | 一轮实现加一轮对抗验收；安全清单需逐条过 | 清单漏列时，危险改动会落到标准；仍由评审和清单 owner 兜 | ★（已被 §8 取代） |
| 补 | 只删几个宽关键词 | 最小 | 还是关键词，下一个词又误伤；没有护栏 | |
| 重写 | 换成风险打分 | 大 | 已选清单方案 | |
| 删 | 硬线只留花钱 / 长跑 / 可打断 / 账本 fixed | 小 | 安全边界靠自报 | |

## 7. 要权衡的核心

严档按点名到文件的清单加不比现在严的护栏来判，准确但需要维护；关键词省事却会把大量 PR 判严。方向检查本身已经要用户拍板，不再叠一层严档。

## 8. 第 4 轮：验收没过，基准是手填的（2026-10-28 第二次拍板）

**发生了什么。** 第 4 轮的护栏把「现行严档数」写在夹具里。首版按现行四类算出 32，新规判出 63，护栏红；随后这个数被改成 122（上一轮判法的输出，含旧关键词），168 个 PR 的现行档位整列一起换掉，护栏才绿。独立验收用完整输入重算：现行四类严档是 51（夹具里每个 PR 的文件清单最多只存 100 个，漏掉了清单靠后的花钱 / 长跑文件）；新规按完整输入是 68，按四类基准超限。验收还实测：把旧关键词整套加回去，护栏的计数恰好等于 122，照样绿，护栏对它要防的东西是瞎的。

**类根因。** 护栏的基准是人写进去的数，而不是现行代码算出来的；被护栏拦住的人可以改它，又没有任何东西报警。夹具还同时存了输入和期望，输入有损（清单截断、没有文件状态、没有 diff 新增行），期望（档位、计数、必须严名单）手填。这是「基准不是现算」这一类，补哪个数都会再来一次。

**用户拍板（原话）：「按 A：严档和现在的四类完全一样，这一单只加短档，护栏改成测试里现算。」**

**结构修法（删旧，不留并行）。**

- 严档的唯一判据是现有的 `inferRoutes(...).fourClass`（花钱、长跑、可打断、新界面，按测试路由登记表）。`evaluateProcessTier` 里其余升严来源全部删掉：安全类、逃逸账本转 fixed、数据格式、声明与核实不一致。测试路由登记表和 `inferRoutes` 一行不改；第 4 轮新增的安全类也一并撤掉，以后要不要把安全清单升严另行拍板。
- 非严档只有两去处：短（判据照第 2、3 轮，不放宽）和标准（= 今天四类之外的全部要求）。两处按「不比今天轻」改：声明短档但界面清单有差异或核实不了，落标准档而不是严档；让逃逸账本转 fixed 的 PR 至少标准档，永不进短档。
- 护栏改成测试里现算：对历史回放夹具里的每个 PR（空正文、无声明），新规判严 ⇔ 测试当场调 `inferRoutes(...).fourClass` 为真。夹具只存输入，由提交进仓库的生成脚本重新生成：200 个 PR，每个带完整文件清单（含 A / M / D，不截断）、命中现有 diff 规则的那几行新增、让账本转 fixed 的条目 id；没有档位、没有严档数、没有必须严名单，夹具里也没有本机路径。
- 再断言夹具里的 PR 数恰好等于生成时记下的数；四类里每一类，夹具中至少有一个 PR 只因这一类才严，否则「去掉这一类」护栏看不见。
- 旧夹具（手填的现行档位、严档数和必须严名单）整份删除。

**反例必须真红**（在隔离副本里逐字节改坏，再还原）：①把第 3 轮的整套关键词硬线原样加回去 → 护栏本身红（单独断言，不与别的测试合取）；②去掉四类里任意一类的判严 → 护栏红；③恢复「声明与核实对不上就升严」→ 对应单测红；④让账本转 fixed 的纯文档改动进短档 → 对应单测红；⑤从夹具删掉一个 PR → 数量断言红。

**靶子独立性。** 靶子不再是任何人写下的数：期望是现行判据在同一份输入上的输出，夹具与判据之间唯一的耦合是「diff 规则的正则对得上」，对不上有单测红。

## 特征测试

同一批历史 PR 的完整输入（含文件状态与 diff 新增行）作为护栏夹具，测试当场用现行 `inferRoutes` 算出严档集合，要求新规的严档与它逐个相同；花钱 / 长跑 / 可打断 / 新界面各有一个 PR 只因这一类才严，保证每一类的判严都被钉住。
