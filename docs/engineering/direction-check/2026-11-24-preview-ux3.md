# 预览成片画幅与导出回执方向复盘

适用 Phase 1 #6、#16 前半、#21。协调批复见 [#issuecomment-7126279479](https://github.com/aqm857886159/Nomi/issues/1586#issuecomment-7126279479)，目标和门表见 [设计卡](../../plan/2026-11-24-ux-simple-preview-ux3.md)。

`fix-churn.mjs` 命中真实热点。14 天内 `workbenchStore.ts`、`projectRecordSchema.ts`、`projectNormalize.ts` 各已有 2 个 fix，`workbenchProjectContent.ts` 有 3 个。ShellTopBar 本身未达到次数阈值，所属顶栏目录已有 4 个。最终扫描还数到能力读口 `capabilityApplyHandler.ts` 的 2 个已有修复，分别是审片结果的明确三态 `538af1950` 和打开项目不改文件 `952a1cfd6`。能力读口这次只把快照的三个画幅读法接到同一投影。坏项隔离 `773838150`、文件引用与留存 `9feea8bea`、`4a1329146`、`b1f499159` 以及窄窗让位 `18db58a75`、`14d1d609b` 均需保留。画幅、空的导出状态和完成回执在这些旧修复里没有同一根因。

独立只读复盘先看了 Phase 1 报告、提交历史和实际状态链。它找到素材库直接入轨与采纳事务两条写门，指出只改前者会漏镜头和批量采纳，只改 UI 又漏非 UI 导出及重开。它建议用项目内容记录替换临时画幅字段，并且用单一导出提示替换原生 title、把自动揭示移成回执动作。

| 路线 | 结果 |
| --- | --- |
| 局部修改预览组件 | 预览画面可变，项目、Agent 与批量采纳的值仍可能不同 |
| 把画幅归项目内容，提交时由同一函数决定 | 可复用两条写门的事务，显式选择随文件恢复，所有现有出口同读 |
| 删除手选或导出入口 | 现有编辑工作流失去创作者控制 |

采用第二条。画幅记录不装文件地址，沿项目内容的既有写盘和读取路径，与隔离和无损打开合同兼容。导出仍用顶栏的同一按钮与任务状态通路。补齐后的结构由首次入轨与成功回执类测试验证，实窗口证据由设计卡验收。

## §5 整块能力的主人

这一整块：项目成片画幅、时间轴导出资格和已保存成片回执。
归谁：项目的可持久化内容在 `src/workbench/project/workbenchProjectContent.ts:13`，时长在 `src/workbench/timeline/timelineMath.ts:217`，完成后的文件定位由 [Electron shell](https://www.electronjs.org/docs/latest/api/shell/#shellshowiteminfolderfullpath) 负责。
我们哪里绕开了它：画幅原先放在 UI 会话，入轨时缺媒体尺寸，顶栏没有消费时间轴资格，已保存回执径直到文件管理器。此改将选择随项目保存，入轨时间确定格式，回执只在用户点击时请求定位。
