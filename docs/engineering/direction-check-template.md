# 方向检查：类根因复盘模板（RW）

> 什么时候写：`node scripts/fix-churn.mjs <路径>` 命中，或下面「触发」任一条出现。写完一页，结构性结论交用户拍板。
> 提交 fix 时在提交信息里加一行 `Direction-Check: docs/…/你的复盘.md`（git commit-msg 会校验文件存在、在 `docs/` 下、不是空壳）。
> 同一份复盘可以被同一概念的多个 fix 提交引用，不必每个提交写一份。

## 触发（任一即停止派修补，先写这份）

1. 同一文件、同一概念目录、concept-owners 里同一个概念，14 天内第 3 个 fix 提交；或同一条自写登记（评估中 / 待替换 / 通用区里的合理自写）30 天内第 2 个 fix 提交（`fix-churn.mjs` 能算；自写登记命中时，本文档必须写出该登记的 id）。
2. 出现 revert 一个 fix 的提交（`fix-churn.mjs` 能算）。
3. 修复因评测分数下降被回滚（人工判）。
4. 同一条线派第 3 轮及以上修补，交接单 / 任务书里写的「第 N 轮」同样算（人工判）。
5. 要加第三个特例分支（人工判）。

来源是逃逸账本（`tests/ux/full-walk/escapeLedger.json`）的修复：复盘里要写明「结账挂的是哪条类检查」（铁律 ⑩ ⑪ ⑫ / inv:N，或矩阵 / 普查测试路径），`check:escape-ledger` 按这条卡结账；只修现场不算修好。

## 动作

停止派修补 → 先写特征测试钉住现状 → 写下面七节（一页，别写成论文）→ 结构性结论交用户拍板。

### 2. 为什么这一类会一直出现

追到结构 / 表示 / 方向层，不停在「某处没判断」。

#### 三条体验铁律（类根因必须落到其中一条或明确不适用）

| 铁律 | 类根因要回答的问题 | 最小证据 |
|---|---|---|
| ⑩ 说的=摆的 | 意图抽取写下的期望，是否与草稿中的模型 / 比例 / 时长 / 引用等参数逐项一致？ | 意图期望与草稿参数的确定性对比收据；任一字段不一致就失败 |
| ⑪ 能选到 | 模型档案的参数清单是否自动生成，并覆盖 Agent、画布、分镜、批量等每个入口？ | 档案清单生成物 + 各入口可选项对照；缺入口或手抄清单就失败 |
| ⑫ 点了=以为的 | 每个可点目标是否写了用户预期，并记录了点击后的实际结果？ | `tests/ux/full-walk/catalog.mjs` 的 `userExpectation` / `actualObservation` 对照 |

这三条是类根因和硬门的共同语言，不新增产品逻辑或常驻规则；找不到证据时把条目写进 `tests/ux/full-walk/escapeLedger.json`，状态保持 `candidate`，由人工复核后再转正式回归。
