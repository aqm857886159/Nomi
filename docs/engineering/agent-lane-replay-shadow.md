# L2 · 回放影子夜跑（怎么跑 / 报告在哪 / 7 天绿从哪天起算）

> 方案：[`docs/plan/2026-09-07-agent-rebuild-stage3-5-deep-plan.md`](../plan/2026-09-07-agent-rebuild-stage3-5-deep-plan.md) §2.3 第二行 + 「冷重启 200 个回放会话」那一行。
> 代码：`tests/agent-runtime/agent-lane-replay-shadow.mts`（入口）· `replayShadowSources.mts`（读数）· `replayShadowEngine.mts`（回放与比对）。

## 它回答哪个问题

阶段 4 要一刀删掉旧运行时。删之前必须回答一句话：**用户过去真实的对话，换成新通路跑，出来的东西还是不是同一份。**

「同一份」不能靠感觉。所以这套夜跑做的事是：从本机真实资料库里取一条**录下来的助手回复**，把它一个字节不改地当成供应商的输出重放进一条新 lane，然后比新通路的投影和录下来的东西——段的顺序、每段的文字、每个 toolCall 的参数、每条 toolResult 的正文，**逐字**。再关掉、用同一个会话 id 重开，投影必须逐项相等。

L1（`lane-shadow-parity.test.mts`）比的是我们自己写的剧本；L2 比的是**用户真的说过、模型真的回过**的东西。两者都绿才算「够稳可切」。

## 怎么跑

```
pnpm run replay:shadow
```

可选参数（都有默认值，日常不用给）：

| 参数 | 默认 | 用途 |
|---|---|---|
| `--turns=N` | `200` | 最多回放多少个回合（按落盘时间新→旧取） |
| `--out=<file>` | `~/Library/Application Support/nomi/replay-shadow/<本地日期>.json` | 报告落点 |
| `--projects-root=<dir>` | `~/Documents/Nomi Projects` | 真实项目库 |
| `--host-root=<dir>` | `~/Library/Application Support/nomi/project-agent-host` | 宿主分区库 |

退出码 0 = 绿，1 = 红。

**它不在 CI 里，也不该进 CI。** 语料是本机真实资料库；CI 里没有它，造一份假语料跑出来的 100% 只证明「我写的假数据和我写的断言一致」。

## 数据纪律

- **只读。** `replayShadowSources.mts` 全文件只有 `readFile` / `readdir` / `stat`。真实数据不复制进仓库、不出机器；回放全部发生在 `os.tmpdir()` 里的临时项目目录，用完即删。
- **零额度。** 出站闸装在 `globalThis.fetch` 上，非回环地址一律 `OutboundBlocked`。密钥不读、不打印——夹具用的是 `fixture-key` 这个字面量。
- **报告只留本机。** `<本地日期>.json` 里含项目目录名与不一致处的 80 字摘录。**整份别贴进 PR/issue**，PR 只写数字。

## 判据（三条 + 三个阳性对照）

绿 = 下面六条同时成立：

| # | 判据 | 红了说明什么 |
|---|---|---|
| 1 | 逐字一致率 **100%** | 新通路读回来的这一段和录下来的不一样。报告里打印**第一处**：段号 + 期望/实际各前 80 字 |
| 2 | 崩溃 **0** | 回放过程中抛异常 |
| 3 | 冷重启逐项相等 **100%** | 会话落盘/重开丢了或改了什么 |
| 4 | 阳性对照·改字 = `detected` | 把回放文字的第一个字符改掉，探测器必须报红。`missed` = 上面那个 100% 什么都没证明 |
| 5 | 阳性对照·乱序工具对 = `detected` | 把回填里的 toolResult 排到它的 toolCall 前面，必须报红（pi 自己**不**校验成对，探针 §5 P2② 实测「照单全收」——所以这条只能由我们自己拦） |
| 6 | 阳性对照·出站请求 = `detected` | 往 `api.anthropic.com` 发一个请求，出站闸必须拒掉 |

**一致率永远和「比过的段的成分」一起读。** 报告里的 `coverage.segments` 分了文字 / toolCall / toolResult / thinking 四列——只比过文字的 100% 和比过上百个 toolCall 参数的 100% 不是同一句话。

## 这套比对里，哪一半是真端到端的（别把它读大了）

一次回放里有两段路，可信度**不一样**，分开说：

- **真端到端的那一段：被回放的那条助手回复。** 它从录里出来 → 走真 HTTP → `pi-ai` 的 openai-completions 解析器 → transcript → 生产的 `projectLaneSnapshot`。中间没有一处是绕过去的，所以「段顺序 / 文字 / toolCall 参数」这三项的一致率是实打实的。
- **半自证的那一段：`appendMessage` 回填的前文。** 我们把录里的消息转成 pi 消息、写进去、再投影出来，比的是**我们自己那份转换**。它证明「写进去的东西原样读得回来」（这正是方案 §2.1 第一档要押的事），但它证明不了「我们那份转换本身对不对」。前文里的 toolResult 正文属于这一段。

**冷重启那一行没有这个折扣**：它比的是同一条会话关掉前后的两份投影，两边都由 pi 产出，中间隔着一次真实的落盘与重开。

阳性对照就是冲着这个折扣设的：改一个字符、把一对工具消息掉个个儿——探测器不报红，上面那个 100% 就一句话都没证明。

## 语料够不够（2026-09-08 实核）

方案 §2.3 要「最近 ≥200 个真实回合，跨 ≥3 个真实项目」。本机实核的结果与方案的假设**不一致**，如实记在这里：

| 来源 | 方案 §2.1 里的编号 | 本机实际 | 可回放回合 |
|---|---|---|---|
| `<project>/.nomi/agent-thread-context-v1.json`（pi 快照信封） | ① | **0 份**（369 个项目零命中） | 0 |
| `<project>/.nomi/agent-session.json`（旧 agentChatV2 存储，AI SDK CoreMessage 形状） | **不在 §2.1 的三份清单里** | 40 份 / 50 段对话 | 111 |
| `<userData>/project-agent-host/<partition>/snapshot-v1.json` | ② | 17 个分区 / 8 段有内容 | 27 |

也就是说：**方案点名的那一份在真实机器上一份都没有**，而唯一带有序 content 数组 + toolCall 参数的真实语料是 §2.1 没有盘点到的 `agent-session.json`。读数层因此按「来源适配器」写——①出现就自动被读到且排在最前，实际有的那两份现在就能跑。

**补数来源的建议（都不许造数据）**：
1. 用打包版真机跑一批真实任务（R13.3（原 R30）那批 5 任务 × 3 次、MiniMax H3 短片闭环），新通路会落 ① 的信封，语料自然长；
2. 阶段 3 的审批/任务卡走查每跑一次也进语料；
3. 协作者机器上的资料库各自本地跑一次，**只报数字不传数据**，合并计数。

在语料补到 200 之前，判定会显示 `green-short-of-corpus`：三条判据 + 三个对照全过，但覆盖面还没到方案要求的量。**它不等于绿，不能拿它开始数 7 天。**

## 「连续 7 天绿」从哪天起算

- 起算日 = **第一份 `verdict: "green"`（不带 `-short-of-corpus`）报告的本地日期**。报告按本地日历日命名，一天一份。
- 期间 main 上每合一个 Agent 相关 PR，**当天重跑一次**（方案 §2.3 时间维那一行）。重跑红了，计数归零、重新起算。
- 数够 7 天 + L1 全绿 + §2.3 其余四行同时成立，才谈切换（方案 §2.3：「够稳可切 = 六行同时成立，少一行都不切」）。
