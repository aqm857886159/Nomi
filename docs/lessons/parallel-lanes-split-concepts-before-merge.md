# 按目录派工的并行 lane，会在合并之前各自长出同一概念的第二份实现

> 📎 教训 · 首次记录 2026-09-22 · 状态：现行
> **触发场景**：要同时开两条以上 lane、或者接到一份「你负责这几个目录」的任务书时；合并两条并行分支前；看到「两边改的文件一个都不重叠，应该不冲突」这句话时。

**结论**：派工切的是**概念**，不是文件夹。任务书必须带「概念占用表」（碰哪几个概念 / 每个概念的唯一 owner 落到文件+符号 / 允许谁消费），写不出就不派工、不开工；同一时段同一概念只归一条 lane。收货时多问一句「这一刀有没有让任何概念多出第二个 owner」，有就打回——**测试绿不作为放行理由**。规则是 R33，正本登记表是 `docs/engineering/concept-owners/`。

**为什么会踩**：本仓「一个概念一个 owner」的纪律，过去只在**合并点**才起作用。R14.1 查的是「同一语义今天有几份定义」（已经分裂的存量），R1 拦的是「加新必删旧」（同一个人看得见第一份的情况）。两条都假定有人**看得见**另一份。并行 lane 恰恰打掉这个前提：两条 lane 同时动手、谁都看不见对方，各自在自己那片目录里做「完整的一刀」，于是同一个概念长出两份实现，而且两份都自洽、都有测试、都绿。文件不重叠，`git merge` 一声不吭。

2026-09-22 同一轮并行里抓到四个（参数准入 / 供应商落家 / 花钱回滚 / 待决身份，逐条实例见 [`../engineering-rules.md`](../engineering-rules.md) R33 开头那张表）。四个都不是「明知有第一份还硬造第二份」，全是检索失败的并行版本：**分裂在写的时候不报错，只在合并时由人肉眼对账才看得出来**——而人工对账正是四个全部漏网的那一步。

**怎么用**：

- 发工 / 接工前先写「概念占用表」，owner 只写到目录 = 没写；owner 未定的概念也要列，标 `pending` 并写清由哪份任务书收口。
- 接任务前查一次编排者的全局占用表；发现自己要碰的概念已被别人持有 → **停下来协调**，不许先写再合。
- 改动碰到还没登记的概念 → 和改动同一个 commit 登进 `docs/engineering/concept-owners/`（只登记碰到的，不回头补全仓）。
- 「两边改的文件不重叠」**不是**可以并行的理由：这四个实例里文件一个都不重叠。
- 多入口共享同一概念（Agent 面板 / 画布 / 外部 MCP / 批量）→ 做「同一输入 → 各入口出站报文逐字节相同」的对等测试，做成棘轮（新入口必须登记），让分歧在测试里报错。

**出处**：2026-09-22 并行 lane 概念分裂复盘；规则 R33（`../engineering-rules.md`）与编排手册 [§18](../engineering/agent-orchestration-playbook.md)；语义级门岗 `check:concept-owners` 排在发版后第一批（`../roadmap/TODO.md` T-QA-24）。
