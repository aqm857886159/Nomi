# 界面重设计走四步流水线：整件复用优先，禁脑补

> 📎 教训 · 首次记录 2026-09-02 · 状态：现行
> **触发场景**：要设计 / 重做一整块用户可见界面（多个控件形态起步），正准备「凭感觉画一版样张」。

**结论**：新界面别从零脑补。每个 UI 形态逐个过四步流水线：

1. **分类**：这是**通用件**（对话流、工具条、任务行……成熟产品都有）还是**领域独有件**（只有我们这个领域才有的形态）；
2. **找证据**：通用件从成熟组件库**整件复用**（解剖现役页面，抓真实 DOM/样式，不是看截图脑补）；两库覆盖不了的独有件走**竞品还原**（证据 file:line，禁脑补）；自造只留给「库无此概念、竞品无此控件」且能写出理由的形态；
3. **还原解剖**：把库件 / 竞品件的结构拆到可实现（布局骨架、状态、折叠语法、计时器这类细节都记下来）；
4. **套自家设计系统 + 认知负荷审计**：换 token / icon / 尺寸；每屏**数可见选择数**并压到最少——取舍冲突时认知负荷是最高裁决原则，压过「整件复用」本身。

**为什么会踩**：从零画的样张每个形态都是「差不多像那么回事」，拍板后返工率高；而成熟库的现役件已经替你付过交互细节的学费。Agent UI v2 重做 21 个形态全过此流水线，源分布：Beautiful UI 9 件 · AI Elements 6 件 · 竞品还原 2 件 · 自家整件复用 3 件 · 自造 1 件（自造的那件写明了「两库无生产阶段概念、竞品只有流程文字无阶段线控件」的理由才放行）。第 4 步真的会裁掉好东西：BUI 的 follow-up suggestions 整件成熟，仍因「+2 个常驻可见选择」被认知负荷原则否掉——这就是「取舍冲突以负荷裁」的含义。

**怎么用**：
- 动笔前先列形态清单，逐个标分类（通用 / 独有 / 自造候选），自造候选必须写不采购理由。
- 库解剖抓**现役页面**（WebFetch 真 DOM），竞品还原给仓内证据 file:line；样张里每个形态标注「源（复用到的解剖细节）」。
- 认知负荷审计出数字：每屏常驻可点数、卡内选择数，改版前后对比着报。
- 样张交付按 [逐屏逐件走读](mockup-delivery-is-a-per-screen-walkthrough.md) 制。
