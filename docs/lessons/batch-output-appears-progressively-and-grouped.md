# 批量产出要逐步冒出来 + 自动编组

> 📎 已拍板的产品设计事实 · 首次记录 2026-08-20 · 状态：现行
> **触发场景**：设计或实现任何「一个动作产出多个画布节点」的功能时——拆镜头、批量生成、素材导入、切图九宫格、拆解元素等；或看到有人打算把批量产物塞进某个节点的图片堆叠/抽屉里。

> 架构现状以 [`../ARCHITECTURE-NOW.md`](../ARCHITECTURE-NOW.md) 为准，本条记的是**设计意图**与实现时的必踩点。以下代码位置记录于 2026-08-20，动手前请复核。

**结论**：一个动作产出多个画布节点时，**产出摊在画布上、逐个落、落完自动编组、整批一个 Cmd+Z**。不要攒完一次性落，也不要藏进堆叠里。

**为什么这么定**（2026-08-20 用户对「切图九宫格」拍板：「切完直接在画布上摊成 9 个节点，但是要逐步布局，一节可以直接给他编组」）：

- **摊出来 > 藏起来**：之前的实现把切出的 9 张塞进单个节点的图片堆叠里，画布上只看得到左上角那一格。用户点「九宫格」的预期是**看到九张**，看不到就等于「什么都没发生 / 坏了」——一个正确执行的功能被体验成故障。
- **逐步 > 一次性**：一张接一张冒出来，**进度就是画面本身**，不用另加进度条（effect-first：直接给效果优于给状态说明，见 [`d6-proposal-jargon-must-be-explained.md`](d6-proposal-jargon-must-be-explained.md) 里那套偏好）。攒完一次性落地反而像卡住。
- **编组**：9 张是一件东西的九个部分，整组要能一起选 / 拖 / 删 / 生成，否则画布很快被散件淹掉。

**怎么用**（四条按顺序做）：
1. 产出**摊在画布上**，别塞进某个节点的堆叠 / 抽屉；
2. **逐个产出、逐个落地**，别攒批；落点先用**纯函数**算好（紧凑方块）再配 `exactPosition`——否则节点避让逻辑会把成组产物推散；
3. 落完**自动编组**；
4. 整批必须是**一个 Cmd+Z 步**。做法见 `useNodeImageEditing.splitIntoTiles`：只有整批**第一个** store 写入放行 undo barrier，其余用 `withCanvasGestureContext({ suppressUndoBarriers: true })`。注意该包装**只能包同步段**，该模块禁止跨 `await`。

**出处**：2026-08-20 用户拍板；参考实现 `useNodeImageEditing.splitIntoTiles`。
