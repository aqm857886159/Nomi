# 用户说「坏了」多半是「找不到」

> 📎 教训 · 首次记录 2026-08-26 · 状态：现行
> **触发场景**：收到「X 用不了 / 没反应 / 你们忘加了」类反馈时；准备直接照着报障描述去改代码时；排查中扫到了别的真 bug、想据此结案时。

**结论**：报障类反馈**先在真机上把该功能跑一遍再信**。已连续三次是「功能一直在，用户找不到入口」。用户描述的是**症状**（我按了没反应），不是根因；照症状去修，会修一个不存在的 bug，而真正的摩擦原封不动。

**为什么会踩 —— 三次实测记录**：

- **2026-08-18 供应商管理**：反馈「改不了 API URL、没有删除按钮」→ 功能自 v0.16.1 就在，根因是控件被 overflow 裁出视口。详见 [`vendor-manage-is-a-discoverability-problem.md`](vendor-manage-is-a-discoverability-problem.md)。
- **2026-08-19 画布快捷键**：反馈「Ctrl+C 没用 / 所有快捷键都不好使 / Ctrl+Z 撤销不了」，当场有人判「忘加了」→ 实测 Cmd 与 Ctrl 各跑复制 / 粘贴 / 撤销 / 删除后撤销，**10 项全过**。真问题是画布上**没有任何复制入口**：右键节点被写在右键菜单排除名单里（不弹菜单）、节点工具条与多选工具条都没有复制钮，只有键盘一条路且没写在看得见的地方。原话是「copy 键是啥呢」——问的是「键在哪」，不是「键坏了」。
- **2026-08-26 某图像模型「没有图生图」**：→ 真实资料库里三个同系模型的 `image_edit` mapping 齐全且 enabled、`archetypeId` 正确；走查确认「改图」chip 在、参考槽可连、真 key 实发 **HTTP 200 出图，且确实是改图不是重画**，与多渠道同款模型的参考区 DOM 逐字节相同。最弱点是：「改图」是**选中模型后才出现**的小号分段控件，未附图时参考槽只是个无文字标签的虚线 `+`。

**⚠️ 扫到真 bug ≠ 那就是他的 bug**：第三例同一轮**确实**扫出两个真缺陷（原生端点被拼成 `/api/api/v3` 打不中、向导接入把同一家供应商劈成两个）。但它们只影响**向导接入路径**，而反馈者走的是供应商卡片路径——**bug 是真的、修得也对，却不是他遇到的那个**。别拿「我修到 bug 了」当成「我解决了他的问题」。

**为什么旁人的即时判断也不算证据**：群里其他人（包括开发者自己）说「这肯定是忘加了」同样是猜测。唯一算数的是真机跑一遍。

**怎么用**：
1. **先实测功能是否真的失效**：写走查脚本，判据取**副作用**（剪贴板内容、节点数变化、HTTP 状态与产物）不取截图。
2. **若功能正常，改查它有没有可见入口**：右键菜单排除名单、工具条按钮、是否只有键盘一条路、控件是否要「先选中某物」才出现、空态图标有没有文字标签。**修的是入口，不是功能。**
3. **写探针时每步操作前先量状态**（选中数 / 剪贴板 / 焦点）。第一版快捷键探针没量，被上一步的空剪贴板串了因果，误报「一半失效」，差点据此去改守卫逻辑——重测即消失。见 [`walkthrough-assertions-need-a-real-signal.md`](walkthrough-assertions-need-a-real-signal.md)。

**出处**：三次真机走查（2026-08-18 / 08-19 / 08-26）。
