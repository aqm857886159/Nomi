# 照着一次事情写的规则，只对那一次成立

> 📎 教训 · 首次记录 2026-11-02 · 状态：现行
> **触发场景**：用户当场纠正你、你想「把这个写成规则」时；要往 `CLAUDE.md` 或 `docs/engineering/rules.json` 加一句时

**结论**：用户的纠正先落到这一刀的验收里。规则走 `docs/engineering-rules.md`「改规则」五步，写成不带这一次名词的一句话，放回真实案例试跑过再给用户看。

**为什么会踩**：
- 用户纠正一次批量出图的修复：要真实场景复现，生产的三个页面都要测。协调当场把「三个页面」写进设计卡通用格和长期记忆。用户指出规则不能死板，核心是复现得完不完整、准不准确、是不是按用户流程、有没有复现成功。
- 协调几分钟内重写，第二稿带「真模型真钱」，又准备推送。放回 0.24.1 的 14 个修复 PR 一试：10 个用户问题里 5 个跟模型和钱没关系（安装器、保存、画布缺块、项目文件夹、反馈通道），和「三个页面」是同一个错。
- 同一次试跑还查出门岗会误伤评审发现的问题（#1401，没有用户的流程可写）。不试跑发现不了。
- 同类的旧账：10-28 流程分档连改四轮越改越严，放回历史 PR 才算出比现行规则还严（`docs/engineering/direction-checks/2026-10-28-process-tiering.md`）。`CLAUDE.md` 从 10-02 的 6.5KB 涨到 11-01 的 9.4KB，规则只从 26 条变成 27 条，都是往旧规则里加句子，「加一删二」只数新规则号，管不到。
- 没有地方提醒：`.claude/` 不进 git，管改规则的本机技能别的线看不到，也没人会在编辑那一刻想起它。

**怎么用**：
- 写完一句规则，换几个不同的问题读一遍。句子里出现页面名、供应商、「真钱」这类词，先问换个问题还成不成立。
- 试跑要看两头：该管的管到没有，不该管的有没有误伤。门岗能放回历史 PR 跑就真跑。
- 用户定过的字不自己改，改了就拿回去。
- `scripts/edit-time-reminder.mjs` 在改这两个文件时提醒一次，只提醒不拦。还被跳过就升成门岗。

**出处**：`docs/engineering-rules.md`「改规则」；`docs/engineering-rules.md` R13「真实复现和确认」；`scripts/pr-body-criteria.mjs` `checkEscapeContract`。
