# 安全封闭要同时设计人工出口，否则一处坏记录就是永久锁死

> 📎 教训 · 首次记录 2026-10-31 · 状态：现行
> **触发场景**：给花钱、不可逆或按固定路径认领的动作加「读不出来就拒绝」时；身份是从配置算出来的固定路径时；回执里写了 `allowedActions`、`nextAction` 时。

**结论**：「读不出来就不发」只回答了一半。另一半是：这个状态下人怎么往前走。身份是固定路径的，记录一坏，这条路径就永远读不了，用户除了删文件没有别的办法。动手前写清三件事：读不出来时给什么回执；显式往前走时旧记录去哪；回执里给出去的每个动作在每种状态下真走一遍。

**为什么会踩**：试跑防重（#1387）第一版把「连接 + 模型」算成固定路径，`tryModel` 和共享认领都在任何异常处理之前先读旧单。验防重时每格都绿，因为那些格子的记录都是好的。独立验收把记录弄坏才发现：事件缺失时回执给了 `request_new_attempt`，照做却只拿回旧 unknown，`catch` 又把失败盖住，连接和模型从此试不了。全自动档照样被挡，确认卡根本弹不出来。这不是一个 bug，是一类：写到一半崩溃、以后改记录格式，都会走到同一条死路。

**怎么用**：
- 矩阵要有「记录 × 动作」这一维：每种坏法（缺失、截断、乱码、旧形状、丢尾巴）× 每个动作（普通、换参、重启、确认、拒绝、全自动、窗口不在）。只有「好记录 × 各种调用」的矩阵看不见这一类。
- 回执里的动作不能只断言字段，要真走：`allowedActions` 每个值在每个状态下都调一次，走不通就是 bug。
- 判定只留一份。两处各写一个「能不能开单」，反例删掉其中一处时另一处还兜着，矩阵照绿，什么也没证明。
- 要活过挪动的东西（租约、「这里有过单子」的痕迹）不能放在要挪的目录里。
- 崩溃窗口用真杀进程扫，不靠想：这次第一遍扫就发现一个写到一半的锁文件会把查得到的原单变成「不知道扣没扣钱」。
- 锁文件不带业务事实。它坏了换掉就行，不要算成记录坏。
