# 重画界面前先查旧决定和真实代码

> 📎 教训 · 首次记录 2026-11-02 · 状态：现行
> **触发场景**：改一个现有界面、准备删控件或重画样张前

**结论**：先查以前定过什么、删过什么，核对原话现在还算不算数，再读同类组件的真实代码。逐项问它帮创作者做什么、别处有没有；没查清先标未知，不能凭一句注释决定留删。

**为什么会踩**：
- 改一个现有界面前，没查以前定过什么，也没读同类组件的真实代码，只信了一句过期注释，把别处已删的控件画回样张，又说「和画布一样」。
- 用户批注「这个地方很多都是冗余的 我们以前就删过 你没考虑吗」，又说「删掉无效的东西是很重要」。
- 重画时又把用户 2026-09-05 拍过的整片画幅一起删了。从盲目照搬改成盲目删除，依然没有先核对事实和要保住的用户结果。

**怎么用**：
- 先查 `docs/design/`、`git log --grep` 和协调给的已知事实，读原话，再读现有组件真实实现；注释和代码冲突时继续查，不拿注释代替事实。
- 每个按钮和操作都问：它帮创作者做什么、以前定过什么、这件事别处有没有。确认没用或重复的删，有用的合回一个家，没查清的标未知。
- 出图前把旧功能普查摘要放在探索图旁；拍板后转入 `functionCensus`。删之前交代旧数据和剩下入口，不能把已批准的用户结果一起删掉。
