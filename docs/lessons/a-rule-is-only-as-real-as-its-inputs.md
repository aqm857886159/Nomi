# 判据依赖的输入在现实里不存在，判据就是废话

> 📎 教训 · 首次记录 2026-09-26 · 状态：现行
> **触发场景**：评审或设计一条「按某个值决定行为」的规则（按价格决定弹不弹确认、按时长决定走哪条路、按某个字段决定显示什么）；或者样张上某个格子几乎总是写「未知 / 未标价 / —」。

**结论**：评审一条判据，先问一句「它读的那个值，在真实用户的数据里有几成是存在的」，再看判据本身写得对不对。值几乎总是缺，判据就会退化成永远走同一条分支。这时要么删掉判据，要么等那个值真正有了再加。

**为什么会踩**：

- PR #880 的付费确认规则写成「单次 ≥10 点才弹窗；拿不到报价就保守地弹」，↑ 旁边还常驻显示点数。写法、测试、类型都没问题，协调会话也审过。
- 用户一句话点破：Nomi 的模型全部走中转，每家中转的价格口径都不一样，**Nomi 根本不算价格**。于是「≥10 点」永远不触发，「拿不到报价就弹」变成每次都弹，↑ 旁的点数几乎每个节点都显示「未标价」。
- 审的时候只看了规则本身，没去数它依赖的那个值在真实数据里的覆盖率。

**怎么用**：

- 评审涉及阈值或条件分支的规则时，列出它读的每一个输入，一条一条标明「真实数据里有没有、有几成」。拿不准就用真实资料查一遍（比如数模型目录里有多少条带价格）。
- 输入几乎总是缺失的，就不要写成「缺失时走保守分支」：那等于把保守分支变成了默认行为，还带着一条永远不生效的死判据。
- 界面上几乎总显示「未知」的格子，按 R2 删掉（它没有行动价值）。
- 价格相关的现状：官方额度上线之前，价格这一维对用户隐藏；现有的价格逻辑保留，等官方额度上线时再用。见用户 2026-09-26 的拍板。

**出处**：PR #880 的评审往返（2026-09-26）。
