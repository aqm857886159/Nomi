# 分镜表 = 画布节点的表格表示版

> 📎 已拍板的产品设计事实 · 首次记录 2026-09-01 · 状态：现行
> **触发场景**：要做/改分镜表、拆镜头表、"给分镜方案加个表格视图"、"确认后落画布"这类设计时；或看到有人把分镜表当成"落画布前的临时草稿"。

> 架构现状以 [`../ARCHITECTURE-NOW.md`](../ARCHITECTURE-NOW.md) 为准，本条记的是**设计意图**与踩过的**重造风险**。

**结论**：分镜表**不是**落画布前的临时物，它就是**画布上图片节点/视频节点的表格表示版**——同一批节点换个渲染方式，因为表格更好输入。别把它设计成一个独立的"编辑器"再加"确认落画布"按钮。

**为什么这么定**：

- **表是节点的投影，不是第二份真相。** 因此它不会在"确认落画布"时死掉——节点活多久它活多久。这也让它天然通用（不是短剧专用功能），因为任何有图片/视频节点的项目都能切成表看。
- **两半列，两个 derive 来源，别混成一列**（第一版设计就是混了，被纠正）：
  - **左半边 = 提示词维度**（景别 / 运镜 / 动作·承接 / 情绪 / 台词 / 音效）← 由**片种模板** derive。**提示词是这些格子组装出来的输出，不是第二份真相**；用户直接改提示词 → 该行标「手改」，此后格子不再覆盖它。
  - **右半边 = 参考输入槽** ← 由**该行所选模型的 `mode.slots`** derive。可以每行换模型，也可以整体换；换了模型，能接的参考种类就跟着变。
- **首版槽位 = 6 列**。场景 / 参考已经有 anchor chips 承担，画面描述就是 prompt 本身，不重复造列。

**别重新发明它**：
- 右半列的参考槽抽象**已经存在**，见 [`nomi-reference-slots-are-already-declarative.md`](nomi-reference-slots-are-already-declarative.md)——`ArchetypeMode.slots` + `AssetReference.tsx` 已是拍板过的声明式数据与渲染器。做表格前先读那条，别新建一套 slot 抽象。
- 想加「确认落画布 / 草稿态 / 表格独立存储」这类概念前，先回到本条：它们都预设了"表是临时物"，而这个前提已被否定。

**怎么用**：
- 设计分镜表相关功能时，先问「这一列的值从哪 derive」——答不出「片种模板」或「该行模型的 slots」，说明这一列可能是在造第三份真相源。
- 用户手改提示词后的覆盖行为按上面的「手改」标记走，不要让模板重新盖回去。
- 大 UI 量级的表格改动仍走样张拍板（见 [`mockup-approval-gates-only-big-ui.md`](mockup-approval-gates-only-big-ui.md)）。

**出处**：2026-09-01 用户拍板（纠正了「给分镜方案编辑器加个表格视图」那版设计）；6 列首版同日拍板。相关代码位置见 [`nomi-reference-slots-are-already-declarative.md`](nomi-reference-slots-are-already-declarative.md)。
