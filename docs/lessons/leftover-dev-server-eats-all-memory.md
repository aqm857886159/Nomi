# 遗留的开发服务器会漏到几十 GB 内存，拖垮整机上的所有线

> 📎 教训 · 首次记录 2026-10-06 · 状态：现行
> **触发场景**：多条线并行时，别的线的 tsc / esbuild / vite 起不来（spawn UNKNOWN、OOM），或机器提交内存接近上限。

**结论**：子 agent 起的 vite / 开发服务器 / 静态服务器用 `run_in_background` 起并在用完后立刻停，**不许用 `&` 甩到后台不管**；交付前确认自己起的服务器都已停。

**为什么会踩**：2026-10-06 一条线为设计实验室截图用 `&` 起的 vite 一直没停，那条线合入后它还在跑，漏到 64GB 私有内存；另一条线遗留的 vite 也到 11GB。整机提交内存 123/124GB，其它线全部起不来进程。开发服务器的 HMR 长时间挂着会持续涨内存，后台进程没人管，线结束了进程还在。

**怎么用**：
- 线收尾 / 合入后，清理清单里顺带查有没有该 worktree 下还在跑的 node 进程（按命令行里的路径认）。
- 发现可疑大内存进程：先看命令行和起始时间认出是哪条线的、那条线是否还在用，再停；只按 PID 停，不按进程名杀。

**出处**：2026-10-06 内存撑满事故；`docs/engineering/codex/rules.md` “不许 `&` 甩后台”。
