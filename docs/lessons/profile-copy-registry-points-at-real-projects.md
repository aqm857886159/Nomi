# 资料副本里的项目登记会指回用户的真实项目

> 📎 教训 · 首次记录 2026-10-03 · 状态：现行
> **触发场景**：要用用户真实资料目录的副本跑候选版验收 / 真付费 / 升级验收。

**结论**：隔离 userData 只隔离了“新建项目放哪”，副本里**已登记项目的绝对路径照样会被打开**，项目一打开就会被写入（迁移、事件日志、agent 会话）。用副本测试前必须先断开登记。

**为什么会踩**：2026-10-03 候选版验收线在副本上隔离启动，副本里最近项目登记（`recent-workspaces.json`）仍指向用户真实项目目录：1 个项目的 `project.json` 被迁移改写并新增 3 类文件，2 个项目的事件日志被追加。当场用改动前的副本和指纹原样还原（247 个文件 0 处不同），改动过的文件隔离保存。

**怎么用**：
- 任务书写明：先在副本里搜所有指向真实项目目录的引用，删掉或改到副本目录；每次启动前后对用户项目目录做指纹（路径、大小、修改时间）比对，有一处不同就立刻停、不修、上报；开工前先备份应用资料和所有项目的 `.nomi`。
- 要验“打开老项目”，只能用**复制出来**的项目。
- 这应当做成共享的启动帮手，所有真资料测试都经过它，不只靠任务书。

**出处**：2026-10-03 候选版验收事故。相关：[资料副本硬链接共享 leveldb 锁](profile-copy-hardlink-shares-leveldb-lock.md)。
