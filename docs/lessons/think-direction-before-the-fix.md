# 先想方向，再想修法

> 📎 教训 · 首次记录 2026-11-02 · 状态：现行
> **触发场景**：拿出修法之前；同一个问题修了一轮还没好；写「补还是换」或方向检查的时候

**结论**：遇到问题有两大类思路：沿原方向修；换方向，比如换一种做法，或者干脆不要它。第一次拿出修法之前，这几条都要想过，各有依据。不等用户提醒。

**为什么会踩**：一张卡的生成没收尾，节点此后一直被拒。我们修了两轮，都在给这把锁补窗口，验收每次又查出隔壁的窗口。方向检查表里其实有「删」这一行，我写了「一键双扣，否」，这句没查过，也是错的：同一次点击早就按运行记录号去重，和这把锁无关。表里没有「换模式」这一行。用户问了一句「为什么要锁」，我才去算它真实保护过什么、真实代价多大，答案是该删。

表单没拦住，原因有三：派工书的「补还是换」只查有没有写，六个字就能过；方向检查只在连续失败之后才写，写的人正是修了两轮的人，只看得见原方向；风险那一栏不要求证据，想象的风险也能把一条路否掉。

用户的纠正：「在遇到问题的时候 有这么几种可能的思路 1.原有的方向修复 2.换方向 这里有几种 换模式 或者是不是可以删掉 等等 而对于第二个换方向你这里其实没有很好的做 这次是我说出来的思考删掉 你才思考」。

**怎么用**：
- 不要它：先读记录，算它真实保护过什么、真实代价多大。写下的风险要实查。
- 换一种做法：查别人是不是根本没有这个问题，他们怎么做的，带出处。
- 连续没修好时，把症状和代码交给没参与的人重想一遍，不带自己的结论。
