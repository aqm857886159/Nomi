# 探针判不了的不能当失败，同一个决定写在两处时第二处会把第一处撤销

> 📎 教训 · 首次记录 2026-11-01 · 状态：现行
> **触发场景**：给「发之前先试一下」「能用就用现成的、不能用再换」这类决定加探测、缓存或回退时；一个「发链接还是传文件」「走快路还是走慢路」的判断散在好几个函数里、都读同一个时间窗或同一个标志时；探测要出网，而测试里没有现成的假服务时。

**结论**：先问清探针到底能回答什么。「本机现在打得开」不是「对方拉得到」，所以探针只有三个答案：明确活着、明确失效、判断不了；**判断不了就当没探过，原样照发**，不能当失败（超时、断网、5xx、跳转失败、出站策略拒绝，都是「我这边的事」，对方多半仍拉得到）。明确失效的结论要真的落到一个唯一决定点，下面每一步都不许再把它改回去。

**为什么会踩**：参考素材的临时链接发出去前只看一个 48 小时的窗口，那是对别家链接寿命的猜测，接入中转后不成立；模型拉不到之后，没有任何一处记得，重试发的还是同一条链接。第一版方案只在决定点上加试探，漏了 `resolveLocalAsset` 里的第二处捷径：它也读同一个窗，决定点把判死的链接交给上传通道后，这里又把同一条死链接原样还回去，试探白做。做片返工还有第三处：沿用上一次批准冻住的链接表，也不经决定点。三处都读同一个窗，没有人问过链接现在还活不活，这是一类，不是三个 bug。

**怎么用**：
- 动手前数门：这个判断在哪几处被读、被短路；删掉捷径比在每一处补一个「但判死的除外」更便宜、也不会漏。
- 探针的「判断不了」要写成测试行：超时、连接被拒、5xx、跳转到失败、策略拒绝，每一行都断言「发出去的和没有这个功能时逐字相同」。
- 测试里的探针要真的出网到本机假服务，网络闸开着、全局 fetch 换成只放行回环；匿名图床这类兜底通道最容易在测试里悄悄真传，一律拦住并断言没有一个字节出过机器。
- 并发的结论不要量墙钟，量机制：同一时刻有几个在途请求。墙钟断言在忙机器上会假红。
- 记在连接上的事实（模型拒绝过）只写一处、读一处，并让「忘了传目标连接」编译不过；这种粘住的记录要有有效期，判据说错一次不该影响永远。
- 新增的探测也是出站请求：先问它进不进别的账。这里的试探 GET 带查询串，被付费账本记成「可能花钱」，模型接口一连不上，一笔没发也变成「结果未知」。矩阵只测到决定点看不到，要穿过真的提交出口测。
- 判据是给错误卡和记账用的，错认比漏认贵：错认把审核、鉴权的错误引向要花钱的重试。写完拿仓库里所有字符串和手写的相似说法扫一遍，看翻了哪些。
