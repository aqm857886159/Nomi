# 变异校验后别用 git checkout 目录还原，会冲掉所有未提交的工作

> 📎 教训 · 首次记录 2026-09-24 · 状态：现行
> **触发场景**：做“把修复改回旧行为必须红”的变异校验，准备在每次变异后还原。

**结论**：变异前先做一个 WIP 提交（之后可保留为独立提交），或只备份被变异的那一个文件，用备份还原并核对 SHA。只有该文件已提交干净时才可对**单个文件** `git checkout -- <file>`。

**为什么会踩**：一次在私有服务仓库做变异校验，每次变异后用 `git checkout -q -- internal/` 还原，结果把 `internal/` 下**所有未提交的改动**一并还原成 HEAD（新建的未跟踪文件反而留着变异没还原），靠对话里的原始改动逐个重做才恢复。`git checkout -- <目录>` 不区分“我刚变异的那一行”和“这轮所有还没提交的工作”。给门岗做 RED→GREEN 取证时同理：还原被注入违规的文件若用 checkout，会连尚未提交的修复一起冲掉。

**怎么用**：
- 变异脚本对未跟踪文件同样要能还原（checkout 碰不到它们）。
- 验收线做变异：备份单文件 → 变异 → 看红 → 按备份还原 → 核 SHA 与备份一致。模板见 `docs/engineering/codex/templates/independent-acceptance.md`。

**出处**：2026-09-24 一次变异校验事故；独立验收模板第 3 条。
