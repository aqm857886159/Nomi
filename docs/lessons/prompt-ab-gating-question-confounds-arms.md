# A/B 两版提示词：确认关卡会污染两臂

> 📎 教训 · 首次记录 2026-09-02 · 状态：现行
> **触发场景**：你在对比两版系统提示词（中文 vs 英文、旧版 vs 新版），拿到一组差异极大的产出量，正准备据此下结论或回退改动。

**结论**：如果提示词里有「首次启动必须先询问用户确认」这类**关卡**，两臂很可能一个自作主张跳过、一个老老实实停下——于是你量到的是**「模型会不会擅自跳关」，不是你想量的产出质量**。跑 A/B 前先读一遍提示词有没有交互关卡。

**为什么会踩**：

2026-09-02 实测：同一个故事，中文版 assets 提示词**直接按默认做完（8049 字符）**，英文版**停下来问了四个确认问题（589 字符）**。两版启动段是逐句对应的忠实翻译、都写着「必须询问」——**差异纯粹来自模型行为，不来自提示词内容**。

当时那组数据看起来像「英文版废了」（产出量只有 7%），其实什么也没证明。这类假差异长得和真结论一模一样，而且**方向感很强**，非常容易当场下错判断，并据此回退一个正确的改动。

**怎么用**：

- 跑提示词 A/B 前，**先读一遍提示词有没有交互关卡**（要求先提问 / 先确认 / 先复述）。
- 有关卡就把评测设计成**多轮**，两臂喂**逐字相同**的过关答复，再比第二轮产出。
- 同理适用于任何「提示词要求先提问 / 先确认 / 先复述」的评测。
- 看到 A/B 两臂产出量差一个数量级（如 7% vs 100%），**先怀疑是不是一臂停在了关卡上**，再怀疑质量。
