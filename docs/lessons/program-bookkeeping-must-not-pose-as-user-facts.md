# 程序自己的簿记不许冒充「用户留下的事实」

> 📎 教训 · 首次记录 2026-09-26 · 状态：现行
> **触发场景**：一个判断要看「用户有没有做过 X」「内容到没到」（打开时要不要摆全貌、要不要恢复上次的位置、要不要弹引导）；或者一个 bug 表现为「有时生效、有时不生效」，换条路径复现结果就变。

**结论**：判断读的每一个「事实」，先查它的全部写口，确认每个写口写的都真是那件事。程序自己的同步、回声、挂载，只要也往同一个字段里写，判断就取决于谁先写到——这就是「有时生效」的来源。修法是在写口上把簿记挡掉，不是在判断里再加条件。

**为什么会踩**：

- 「打开项目时摆一次全貌」在 main 上三次「有时生效」：先是 350 ms 盲等，再是「React Flow 还没量完节点」（#880 修掉），第三次（2026-09-26）是从项目库重开不摆。
- 第三次的机制：离开项目时 `categoryViewports` 被清空，画布组件却还挂着，停在上个项目的视角上。「store → React Flow」同步看到 store 里没有记忆，就把画布推回 1:1 兜底；React Flow 回了一次没有来源事件的「移动结束」，这一下被 `rememberCategoryViewport` 记成了「用户留下的视角」。重开时判断看到「有记忆、里面也有卡」，按设计保留，于是不摆。
- 冷开第一次画布本来就在 1:1，同步没有东西可推，所以一直绿。只开一次项目的走查全都抓不到。
- 同一个判断的另一个输入 `isReady`（内容已载入）也有过第二个写口：画布挂载时 `markReady()`。挂载先于内容时，判断会看到「ready 了、画布是空的」。
- 我第一次猜的是 `markReady`，改完在自己的走查里绿了，但那条走查离开前点了「重置视图」，同步本来就不用推。换到真正坏的那条路（离开前视角不在 1:1）仍然红，加日志才看到是回声。**先复现再下结论，复现要走原来坏的那条路。**

**怎么用**：

- 判断依赖「用户留下的 X」时，用 `node scripts/door-map.mjs <写入函数>` 数出全部写口，逐个问「这是用户留下的，还是程序自己的簿记（同步、回声、挂载、默认值兜底）？」簿记在写口处挡掉。
- 「默认值兜底」最容易被物化成一条记录：store 里没有 → 用默认 → 默认被同步出去 → 回声把默认写回 store，从此「没有记忆」变成「记忆 = 默认」。
- 走查要覆盖同一动作的第二次（重开、再切回来、第二个项目），而且第二次之前的状态要是用户真实会留下的样子，不要先点复位把状态洗干净。
