# Windows 笔记本的真实可用画布是 1280×720，面板全开时要按这个尺寸验

> 📎 教训 · 首次记录 2026-09-26 · 状态：现行
> **触发场景**：改浮层、浮框、底部停靠物（画面小窗、小地图、时间轴）、右侧面板的位置或尺寸；或者一个控件「在我的屏幕上好好的」。

**结论**：最常见的 Windows 笔记本是 1920×1080 屏、150% 缩放，应用实际拿到的是 **1280×720**。Agent 面板、时间轴、画面小窗、小地图同时打开时，画布舞台只剩一小块。凡是会被停靠物遮挡的控件，都要在 1280×720 和 1280×800 下，用 `elementFromPoint` 验证真的点得到。

**为什么会踩**：

- PR #880 把节点浮框钉在节点正下方，按「被挡就挡」的规则不再避让停靠物。在 1280×800 下，Agent 面板和时间轴都开着时，浮框右下角的生成钮 ↑ 被右下的画面小窗整个盖住，模型选择被左下的小地图盖住，没有一个位置能让两者同时可点。
- 开发机和 CI 的窗口都比这大，截图里看不出来。协调会话看了真实截图才发现。
- 修法（用户 2026-09-26 拍板 B）：画面小窗和小地图默认收起，用户展开后记住。偏好统一由一个 owner 管理。

**怎么用**：

- 布局类改动的走查矩阵固定包含 1280×720 和 1280×800，zh / en 各跑一遍（英文字符串更长，更容易挤出来）。
- 断言「可点」要用 `elementFromPoint` 命中控件本身，不能只断言元素可见。
- 另见 [GitHub Windows runner 把窗口夹到下限](gh-windows-runner-clamps-window-to-minimum.md)：CI 上的 Windows 窗口尺寸本来就不等于用户的尺寸。

**出处**：PR #880 的遮挡截图、画面小窗与小地图默认收起的 PR（2026-09-26）。
