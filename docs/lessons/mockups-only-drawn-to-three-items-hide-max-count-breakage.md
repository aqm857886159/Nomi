# 样张只画到 3 张图，最大数量下的坏排版没人看见

> 📎 教训 · 首次记录 2026-11-12 · 状态：✅ 已固化（设计系统「会被数据撑开的地方」+ 清单门岗 `check:board-parity` 的 `boundarySheet` 规则）
> **触发场景**：出一张会随数据变多、变长、变窄的界面样张时（图片数、名字、文案、列表）；核对验收证据图时。

**结论**：样张和验收都要用「最大值」来画和来核：出图前先从数据里查数量上限、最长文字、最窄宽度，每处画空 / 常见 / 最大 / 最长文字四种，写进清单的 `boundarySheet`；实现线用同一组最大值造数据和截图。

**为什么会踩**：同一行（生成框底部的方式、参考图、模型名那一行）按「最大数量」坏过四次：2026-09-21 方式栏被滚动区切掉一半；2026-09-22 英文底栏里模型名压住比例；2026-10-22 换模型后 30 张参考整行不见；2026-10-23 英文下放 3 张参考图，行尾那句话被挤成三段折行。最后这一次，坏图就在当时交上来的验收证据里，当时只核了别的事，没人看它。三层原因：

- **修了什么**：每次只修眼前那一处排版。
- **哪一步漏了**：出图没问最大值（流程第 1 步有「窄窗」「长文字」，没有「最大数量」）；自查和核对只核画出来的东西，没画的最大值状态不在核对范围；实现侧没有通用的排版判据，样张画到 3 张就实现到 3 张。
- **改了哪一步**：本次四处——设计系统加「会被数据撑开的地方」七条原则；设计流程第 1 步要求先查这一块以前报过的排版问题、出图必带边界表，清单格式加 `boundarySheet`；清单门岗加规则，2026-11-13 起的板没有边界表就红；设计卡 ★4 加半句，要求按最大值、最长文字各列一行。

**怎么用**：
- 出图前先查这一块以前的排版问题（证据图、修复提交、反馈、待办），每个问题对应一张图。
- 核验收证据图时，先看它画的是不是最大值，再看别的；只有常见情况的图不算过。
- 查不到数量上限就按没有上限画。

**出处**：2026-11-12 用户拍板的七条设计原则；`docs/design/nomi-design-system.md`「会被数据撑开的地方」、`docs/engineering/design-pipeline.md`、`scripts/check-board-parity.mjs`。
