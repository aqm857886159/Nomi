# 连带面必须单独成题，不能埋在一句话里

> 📎 教训 · 首次记录 2026-09-11 · 状态：现行
> **触发场景**：出方案 / grill 用户前，某个改动会连带另一个用同一组件、同一实现的面（同一组件多宿主、改 A 会带动 B）——写题目前先查这条

**结论**：一个决策如果会连带另一个使用同一组件/同一实现的地方，那个连带面必须**单独成一道题**（带自己的默认答案），不能塞进主题目的一句话/从句里当附带说明。用户只会针对主题目表态，藏在句子里的连带默认会被当成「已经问过」，但用户根本没看见、没法反对。

**为什么会踩**：2026-09-11，方案 B「逐参数下拉」本该只改付费卡（模型选择卡片），但把「同一组件，画布节点和卡一起变」写成主问题里的一句话，没有单独列成 Q。用户回答「选 b」时只是在回答主问题，没机会对「画布节点也要变」单独表态。结果画布节点被一并改动，超出了用户以为自己批准的范围。根因不是用户没读仔细，是题目设计本身把一个独立决策伪装成了主决策的细节，读者（用户）没有独立的表态入口。

**怎么用**：
- 出 grill 题时，扫一遍每个候选改动：它是不是被别的宿主/页面/节点复用的组件？改了这里，那边是不是也变？
- 只要连带面存在，单独开一道 Q，带自己的默认答案，不许并进主题目的从句/括号里。
- 校验方法：读自己写的题目，如果某个范围变化只能从一个从句/括号里读出来（而不是题干或选项本身独立列出），说明它该拆成独立题。

**出处**：2026-09-11 用户当面指出（方案 B 逐参数下拉：付费卡改动被一句话带出画布节点改动，未单独确认）；本条落地为 `CLAUDE.md` P5「动手前先 grill」的「连带面单独成题」子规则（见 P5 正文与 `scripts/claude-hooks/self-check.sh` 闸①）。
