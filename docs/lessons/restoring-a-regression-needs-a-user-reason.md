# 修一个「回归」之前，先问那个行为有没有人要

> 📎 教训 · 首次记录 2026-09-26 · 状态：现行
> **触发场景**：一条老走查红了，你准备把它当回归修；尤其当这个行为是框架自带的默认功能，或者从没出现在任何用户反馈、拍板、样张里的时候。

**结论**：「以前能用、现在不能用」只能说明行为变了，不能说明这个行为被需要。修之前先用一句话答出「谁要它、在哪次拍板或反馈里」。答不出来，就把它作为一个待拍板的问题交给用户（留下 / 拿掉），不要默认把它恢复。

**为什么会踩**：

- 0.22.1 RC 验收时，老走查 `core-a-storyboard-undo` 里「选中节点按方向键微调」那一步红了：9 月 20 日的一次改动把它弄坏了。
- 协调会话把它当回归开卡去修，随 #871 合了进去，之后还因为它的单测不稳在 #880 上多花了一轮排查。
- 用户问：「这是谁要做的？」查下来，没有任何用户需求。它是 React Flow 的默认行为，只是被一条老走查断言了下来。
- 这条走查真正守的，其实是「框架自己改了节点位置之后，我们的状态要跟上」。这个问题的根治在「画布收成一份」（T-CV-21），不需要靠方向键来测。

**怎么用**：

- 老断言红了，先分清两件事：它断言的是**用户价值**（有拍板或反馈出处），还是**实现细节 / 框架默认**。后者恢复之前要先问用户。
- 如果一条测试借用某个次要行为（这里是方向键）去触发真正要守的不变量，就改成直接触发那个不变量，别让测试反过来成为保留这个次要行为的理由。

**出处**：#871（修复方向键）、#880（该单测变红）、用户 2026-09-26 的追问；本次暂时保留该行为，到 T-CV-21 时再议。
