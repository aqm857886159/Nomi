# 删旧实现里的一道门之前，先问它在保证什么

2026-09-08 立、2026-09-11 **结论反转**改写 · 画布磁吸连线把手。

迁移前的代码里有一道门：磁吸带子只挂在**选中的**图片类卡片上，其余卡片是 28px 小圆点
（`8f9365aeb:src/workbench/generationCanvas/nodes/BaseGenerationNode.tsx:298`）。

第一版判断把它读成「上一版实现的门槛，不是用户要的行为」，于是删掉，热区改成每张卡常驻。
走查、契约测试、性能对照全绿，真机截图也好看。**但 `canvas-card-stack` 稳定红**：两张卡间距小于约 224px 时，
它们之间的连线整条点不到——改生成方式、断开连接都做不了。机制很物理：热区挂在 `.react-flow__node` 下，
React Flow 把边画在其下的 `.react-flow__edges`，连线正是从卡片侧边进出的，两端必然落进带子。

真正的教训不是「对用户行为不对代码」这么一句话，而是它的反面：
**那道门本身就是用户行为合同的一部分，只是没人把它写下来。** 它保证的是
「同一时刻至多一张卡在卡片外侧捕获指针」，而这条保证才是「卡片之间的连线永远点得到」的原因。
把门当成实现细节删掉，等于把一条没写下来的保证删掉，而没写下来的保证不会在评审里喊疼——
它只会在某条走查里以另一副面孔报红（这次是「聚合编组输入线上存在真的点得到的点」）。

怎么做：

1. **删门之前先补一句断言**：把这道门保证的那条性质写成可执行的判据，跑一遍看它在「删门后」的世界里会不会红。
   这次的判据是两条：未选中卡片外侧 56px 处 `elementFromPoint` 必须仍是 `react-flow__pane`；
   两张间距 150px 的卡之间必须点得开连线模式药丸。两条在常驻带子版上都红。
2. **「旧代码不是规格」要带证据**：说某道门是多余的，得说清它在保证什么、为什么那条保证现在不需要了。
   说不出来 = 还没读懂，别删。
3. **一条走查红了先别怪走查**：同机同断言在干净 `origin/main` 上跑一次做对照。这次对照直接指认了责任方。
