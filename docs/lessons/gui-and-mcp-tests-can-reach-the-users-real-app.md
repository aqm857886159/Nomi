# 起界面的测试会打扰用户，还可能连到用户正开着的真实应用

> 📎 教训 · 首次记录 2026-10-04 · 状态：现行
> **触发场景**：派需要起 Electron / 浏览器 / MCP 外部宿主的测试或验收。

**结论**：先问自己能不能无界面验（单测 / 夹具 / HEAD 请求）；必须起界面时，任务书写明“不弹阻塞错误框、跑完立刻关、只停自己起的进程”；MCP / 外部宿主测试必须保证连不到用户真实的 Nomi。

**为什么会踩**：2026-10-04 用户问“为什么一直看到报错”：验收线起的 Electron 弹了标题为“Error”的窗口，MCP 实测线用已安装的程序起了 3 个临时资料目录实例加一堆启动器进程；用户自己的真实 Nomi 同时开着，而 MCP 启动器靠用户目录下的广告文件找实例，可能连到真实实例——弹确认卡、碰真实项目（与[资料副本事故](profile-copy-registry-points-at-real-projects.md)同类风险）。

**怎么用**：
- 隔离广告目录，或等用户真实应用关着再测；做不到就把测量排到用户不用电脑时。
- 开跑前后对用户项目目录做指纹比对。
- 起的 vite / 开发服务器 / 静态服务器用完即停（见[遗留开发服务器吃光内存](leftover-dev-server-eats-all-memory.md)）。

**出处**：2026-10-04 验收线事故；`docs/engineering/codex/rules.md` 的“不起可见窗口”条。
