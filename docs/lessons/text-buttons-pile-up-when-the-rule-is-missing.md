# 一屏堆四颗文字按钮，是「规则缺席」不是「这四颗写错了」

> 📎 教训 · 首次记录 2026-09-10 · 状态：✅ 已固化（判据由 `check:controls` 规则四~六 + `check:icon-semantics` 词典登记接管）
> **触发场景**：新面上要加第二颗文字按钮；给按钮想文案；纠结「这个动作配个什么 icon」；
> 或者用户指着一屏说「这一堆按钮我不知道该点哪个」。

**结论**：一屏上除主动作外的按钮**默认是 icon + hover 名字**；只有「我们自造的、世界上没有对应图形的概念」
才配文字标签，且必须**动词开头、≤4 字、不解释**。想加第二颗文字按钮时，先问的不是「文案写什么」，
而是**「它是不是主按钮的一个状态」**——2026-09-10 那颗「全部生成」的正解是把主按钮从
`生成 ¥1.20` 换成 `生成 4 镜 ¥4.80`，不是在旁边再摆一颗。规则本体在设计系统 §1.8。

**为什么会踩**：
分镜面上并排四颗文字按钮——「不要」「全部生成」「换模型」「返回修改」——没有一颗是主动作。
第一反应会去改这四颗的文案，但**四个人分别写出这四颗，且各自都觉得自己写得挺清楚**，
说明错的不是这四次判断，而是**判断的依据不存在**：
- `docs/design/nomi-design-system.md` §1.5 管控件**住哪一层**（常驻 / 情境 / 收纳）；
- §1.6 管控件**说到做到**（可点即有效）；
- §6 管图标**长什么样**（唯一库 / size / stroke）；
- **没有一节管「这颗控件该说话还是该画图标、说话该说哪几个字」。**

规则缺席的代价是复利的：同一个「取消」在三个面上分别叫「不要」「算了」「取消」，
用户每换一个面就要重新读一遍；实测立项时全仓有 **289 条**控件文案违反这四条判据。

**怎么用**：
- 加按钮前先过 §1.8 规则 2 的那张表：撤销 / 删除 / 关闭 / 复制 / 下载 / 播放 / 放大 / 设置 / 翻页
  这类**全世界一个样**的 → icon，不写字；自造概念 → 先问它该不该单独存在，确实要才用文字，**不硬造 icon**。
- 想加第二颗文字按钮 → 先问「它是不是主按钮的一个状态」。是 → 改主按钮的状态，不加按钮。
- 写文案前查 [`docs/GLOSSARY.md`「动作词」表](../GLOSSARY.md#动作词按钮--菜单文案的规范动词)：
  规范词只有一个，「确定」「知道了」「算了」这类第二种说法门岗会红。
- 新图标先在 §6「语义图标登记」表里找，找不到再登记一行——**往 `icon-semantics-baseline.json` 里加是无声的，
  往 §6 加要写清语义和用处**，那一步才是规则要的那次思考。
- 门岗只拦得住能机器判定的四条。**「一屏是不是只有一个主动作」拦不住**——那是构图判断，
  留在样张阶段人眼看（§1.5.5 三件产物）。

`docs/plan/2026-09-10-button-icon-rule-gate.md`；
