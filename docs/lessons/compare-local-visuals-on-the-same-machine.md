# 本机视觉变化要与同机渲染的源码基准比较

> 教训 · 首次记录 2026-11-17 · 状态：现行
> **触发场景**：没改界面的主分支在开发机报大量像素不符，末尾却说不阻断。

**结论**：本机要回答「这次改动相对主分支变了哪些格」，两端必须在同一台机器用同一浏览器渲染；CI 继续回答「与用户拍板基线是否一致」。不能把异机差异叫成设计改动。

**为什么会踩**：早先不同 Mac 混录基线造成 97 格不符；把录制集中到 CI 后，本机仍拿 CI PNG 比，主分支出现 158 格不符、22 条用例通过，字号描边差异被错误归因为设计。Playwright [官方说明](https://playwright.dev/docs/test-snapshots)明确指出系统版本和硬件等环境会影响渲染。同机重复采样仍可能有个别随机格，不能把它们藏进零变化。

**怎么用**：
- 跑 `pnpm run check:design-lab`，看基准提交、变化格和差异图；核对 `outputs/design-lab/relative.json`，新增、删除和本机不稳定格也逐项看。
- 缓存绑定机器、浏览器、视口及提交，基准在隔离临时工作树渲染两遍；自己的两遍不同的格单列「本机不稳定，没比」。
- 服务器、页面、基准渲染或报告失败就是失败，不得翻译为没变。只接受完整结果；同机大面积不稳停线。
- 不刷新拍板图、不放宽容差；合并以 CI 为准。CI 镜像换代若真实改变字体，仍需看图再走 `design-lab:accept`，本机相对结果不能代替拍板基线。

**现成能力与退出条件（gate-family）**：像素比较继续交给已接入的 Playwright，源码隔离交给 Git worktree，不自写比图或另一套容差。暂留的编排认的是 Nomi 的待拍板登记、每屏容差和实验室状态清单，通用测试框架不能自行推导这些领域契约；这次同提交删掉 advisory，不再给异机绝对比较补例外。2026-11-30 用同机零改动、单格变化、未提交文件保留及六条反例复查，并评估能否把通用生命周期并回 Playwright projects/setup/teardown；能覆盖相同不变量就删掉对应自写编排，达不到本机零变化承诺则重开升档。
