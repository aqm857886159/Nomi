# 只记在长期记忆里的规则，其他 agent 一条都看不见

> 📎 教训 · 首次记录 2026-10-09 · 状态：现行
> **触发场景**：你刚想说“这条已记进长期记忆 / 我记住了”；或者一条规则被反复违反，而你只能在某个人的记忆里找到它。

**结论**：工程和流程规则当天写进仓库，长期记忆只放用户偏好、敏感信息、本机细节，以及一句指向仓库的指针。放哪：有编号的进 `docs/engineering/rules.json`（P2 的一条子句），协调与多会话流程进编排手册，交付 / 验收进 `delivery-and-review.md` 或 codex 模板，踩坑进本目录。

**为什么会踩**：长期记忆只有协调会话读得到，子 agent、Codex、以后的会话都看不见，规则等于没立。2026-10-08 外壳重设计的样张线直接在设计实验室拼组件，用户说“明显很丑，是没用你的 Claude Design 吗”——“视觉稿先走 Claude Design”那条规则当时只在记忆里；2026-10-09 用户纠正：“不能只记入长期记忆，所有有价值的规则都必须放入我们的仓库。”

**怎么用**：
- 想写“记住”之前先问：这条别的 agent 需要知道吗？需要 → 写仓库，记忆里最多留一句“见仓库 xxx”。
- 记忆瘦身与搬迁做成一次普查：每个记忆文件分 A（仓库已有）/ B（缺，搬进来）/ C（敏感，留在仓库外）/ D（本机或会话细节），公开仓库不写本机路径、价格、额度数字、供应商商务、用户个人信息。

**出处**：用户 2026-10-09 原话；rules.json P2 的“沉淀的规则当天进仓库”子句。
