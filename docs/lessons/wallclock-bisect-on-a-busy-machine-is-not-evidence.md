# 在满载机器上用墙钟做一次性 A/B，不算性能证据

> 📎 教训 · 首次记录 2026-09-03 · 状态：现行
> **触发场景**：有人（包括你自己、包括子 agent）说「这个重构让测试从 X 秒变成 Y 秒，所以不能这么拆」；或者你正准备用「跑一遍前、跑一遍后」来判断某个改动有没有让代码变慢。

**结论**：**在本仓这台机器上，墙钟一次性 A/B 得出的性能结论默认不成立**——它量到的大概率是当时的机器负载，不是代码。这台机器常年 20+ worktree 并行跑套件，load average 在 12 到 264 之间摆。要下性能结论必须满足三条：① 量 **CPU 时间**（`process.cpuUsage()` / `time` 的 user+sys），不量墙钟；② **交错 A/B**（base、variant、base、variant…），不是「先跑完一臂再跑另一臂」；③ 先用一个**已知的注入变慢**证明你的尺子量得出回归，否则「没测出回归」什么也证明不了。

**已经栽过的那次（结论被完整推翻）**：2026-09-03 有人拆 `electron/projectAgentHost/projectAgentState.ts` 的 ~450 行逐记录断言层，测得「拆前 9.1s、拆后 47s，零算法改动」，据此判定这个模块**不能拆**，并把「常数因子 CPU 回归没有守卫」写进了根因契约 `docs/fixes/2026-09-03-wallclock-as-unit-test-oracle.root-cause.json` 的 residual_risks。

用带阳性对照的量具重测，**这个回归根本不存在**：

| | 微基准 cpuMs（4 轮交错，中位） | 真实 vitest 套件 user CPU（3 轮交错） |
|---|---|---|
| 未拆分 | 1393 | 10.881 / 10.530 / 10.194 |
| 拆分后 | 1369 | 10.769 / 10.526 / **9.803** |

两臂**完全重叠**，拆分后甚至略快。而同一把尺子对一个**已知 2x** 的注入（让 `assertProjectAgentHostState` 连调两次）分得干干净净：base 上界 1690 < variant 下界 2324，三轮无一例外。

**那 47s 是什么**：就是负载。PR #410 实测过**同一条未改动的测试**：空闲时 9.1s、load 76 时 **29,668ms**。47s 完全落在这条未改动代码自己的漂移区间里。也就是说——那次 bisect 用一把已知会骗人的尺子，去论证「这把尺子测出的问题得留着」。

**同一组数据里墙钟怎么骗人的**（这是最值得记住的一张表）：

| 指标 | base 三轮 | 注入 2x 后三轮 | 分得开吗 |
|---|---|---|---|
| cpuMs | 1389 / 1690 / 1461 | 2637 / 2353 / 2324 | **分得开** |
| wallMs | 1509 / **4222** / 1566 | **3274** / 5159 / 2681 | **分不开**（base 某轮比 variant 某轮还慢） |

同一次运行、同一份代码，`wallMs` 在 1509↔4222 之间摆了 2.8 倍，而 `cpuMs` 稳定在 ~1400。

**为什么 CPU 时间抗得住**：机器忙的时候，你的进程被别人抢占，**墙钟**被拉长；但你自己那份活该烧多少 CPU 周期没变，所以 `user+sys` 基本不动。它抵消不了的是 CPU 型号/频率差异（跨机器、跨 CI runner 比较时无效），那一层再用「同进程内固定对照负载」的比值抵消——这就是 `scripts/bench-agent-host.ts` 里 `ratio` 的用途。

**怎么用**：

- 要判断某个重构有没有拖慢 agent-host 验证热路径，直接跑 `pnpm run bench:agent-host`，按脚本头部注释交错 A/B。看 `cpuMs` 与 `ratio`，**不看 `wallMs`**。
- **两臂区间重叠 = 没有信号**。别拿中位数差几个百分点说事——上面那次 7%/11% 的「差异」再多跑两轮就翻号了。
- 下「我没测出回归」这种否定式结论前，**必须先注入一个已知变慢证明尺子有效**（同 [复现竞态必须有阳性对照](race-repro-needs-positive-control.md)）。没有阳性对照的 null result 不作数。
- 写对照负载时小心 V8 把它整个优化掉：第一版每轮 new 一个临时对象，逃逸分析删了整个循环，300 万次「跑」了 5ms，`ratio` 于是变成纯噪声却毫无报错。`bench-agent-host.ts` 现在带 `controlSane` 自检，低于 2ms CPU 直接 exit 1。
- 反过来也要小心：**别因为这条就以为常数因子回归不可能发生**。它可能发生，而且只有墙钟/CPU 量得出来（计数器看不见）；只是「量出来了」的门槛比大多数人以为的高得多。
