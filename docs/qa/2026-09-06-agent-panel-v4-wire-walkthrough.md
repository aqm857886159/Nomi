## 2. 走查过程中发现并**当场修掉**的问题

### 2.1 🔴 「帮我做一条 20 秒短片」这句话，一次都发不出去（main 上既有的生产 bug）

最严重的一条，而且**与本次接线无关**——是这条真实任务走查撞出来的。

- **现象**：发送后什么都没发生，面板只给一句「发送失败，请检查后重试。」没有出站请求、
  没有 failure item，宿主的回合直接 `failed`。
- **根因**：`layout` 能力的 pi 别名写成了 `layout.read` / `layout.write`——**带点**。
  运行时组装工具表时按 `/^[a-zA-Z_][a-zA-Z0-9_-]*$/` 校验（`runtime/pi/tools.mts`），
  不合法**直接抛**，于是含它的**整个工具档一次请求都发不出去**。
  而 `PRODUCTION_INTENT` 命中「短片 / 成片 / 剧本 / 制作 / N 分钟」——也就是说
  Nomi 最核心的那句话每一次都走进这个档。契约 id 带点是对的（RPC method、
  requiredScope 都按它走），错的是「喂给模型的那个名字」也照抄了 id。
- **修**：pi 别名改成 `layout_read` / `layout_write`（契约 id 不动）。
- **防线**（R28，建在最早能拦住的那层）：`registry.test.ts` 新增一条断言——
  **每一个** pi 别名都要过运行时那条正则，带阳性对照。任何新能力都先过这一关，
  不留给用户在真机上按下发送时才发现。

### 2.2 🔴 有待决工具时，整个工作台崩成「工作台加载失败」

- **现象**：审批卡该浮出来的那一刻，工作台白屏 + 错误边界。
- **根因**：待决登记表的 `listFor()` 每次都返回新数组，而它是 `useSyncExternalStore`
  的数据源——React 用 `Object.is` 比相邻两次快照，「变了」永远成立 → 无限重渲染。
  空态本来就共用一个冻结数组，所以**只有有待决的那一刻**才炸。
- **修**：按 (version, bindingKey) 缓存；单测钉死引用稳定性 + 阳性对照（有改动时必须变）。

### 2.3 🟠 用户点的「不要」被记成「失败」

拒绝时没有带 `denied: true`，运行时记成 `error`，宿主落成 `failed`，
收据行尾写「失败 ⚠」——把用户的决定记成了系统故障。修：带上 `denied`，
配合本轮宿主侧 `denied → declined` 的契约改动，行尾写「已拒绝 ×」。走查里有断言。

### 2.4 🟠 等你确认的时候，它还在说「正在想…」

审批卡浮着，思考行同时写着「正在想…」——那一刻在等的是用户，不是模型。
用户会以为再等等它自己就好了。修：有待决时不渲染思考行。

### 2.5 🟠 思考行丢了秒数

定稿写死「4s · esc 打断」，理由是"转圈没有时间感，秒数才告诉用户没死"。
接线时只印了「esc 打断」，把这一行的**论点**丢了。修：补上真实秒数（只在真有东西跑时走计时器）。

### 2.6 🟠 审批一段文稿改动，却看不见要写什么

槽里只写「1 条内容」。用户在这一刻要判断的是**那句话该不该进文稿**。
修：投影层把要写的内容摘一行（60 字截断）进摘要；长文去对象自己的家看（§1.5.2）。

### 2.7 🟡 运行中时，同一句话在最窄的一列里说了两遍

用户气泡刚说完，下面队列又列一遍同一条，而「立即中断」在 composer 上已经有了
（运行中那颗钮就是停止）。修：只有**真的排了队**（有 running 之外的项）才渲染队列——
和「空队列不渲染」同一条理由：一个只会复述的框比没有框更吵。

### 2.8 🟡 创作面丢了它那一档的方法论提示词

旧面板从 `PROMPT_PRESETS`（随旧菜单删除）取创作模式的 system prompt；
接线时漏了。界面上看不出来，产出会明显变差。修：改从 `getCreationAiMode()` 取（那个模块还在）。

### 2.9 🟡 收起后 composer 一起消失了

定稿 Collapsed 板：收起藏的是**对话流**，不是对话——同一个 composer 掉到画面下沿，
介入槽跟着它。首版只留了 32px 图标条，等于把对话真的中断了。
修：把旧 `ResidentCollapsedDock` 那套「量走带条空当」的定位逻辑搬成 v4 的 `V4CollapsedDock`。

## 3. 记下但**没有**在本轮修的（连同不修的理由）

| 摩擦 | 为什么留着 |
|---|---|
| 待决工具在流里出现一次（收据「待确认」）、在槽里再出现一次（同一个标题） | 定稿要的就是这两件事：收据是**发生在哪一行**的痕迹，槽是**在哪决定**。标题重复读起来冗余，但改法会动已拍板的外观——要改先出样张 |
| `读取画布 · 正在准备可审阅的变更摘要` 这类摘要文案不准（那是只读操作） | 出自 `residentToolDisplay.ts`，是多个面共用的展示层；本轮不动它，避免把一次接线扩成一次文案大修 |
| 空面板是一整列白 | 定稿八积木里没有空态件。旧面板有「从这里开始」。要补得先进设计 |
| `missing_param` / `missing_credential` / `question` 三档介入**全仓没有生产者** | 拍板 ④ 的投影与单测都在，但没有任何工具会产出这三个字段，所以真机走不到。这是「设计先于能力」的欠账，不是接线漏了——见 §4 |

## 4. 诚实交代：这轮**没能**在真机上验到的东西

- **缺参数提问 + 建议 chip（拍板 ④）**：全仓 grep 不到任何 `missingParam` 的生产者，
  `missingCredential` / `question` 同样。投影层与单测覆盖到了，真机走不到——
  要真机验，得先有一个会说「我缺这个参数」的工具。
- **付费介入（`spend`）与任务卡的金额**：loopback 不产生 ProductionRun，
  budget ledger 是空的。金额那一路（`run.budget.actual/reserved`）只有单测覆盖。
- **上下文环的百分比**：夹具目录没写 `contextWindow`，所以真机上环恒为「—」。
  这**正是**「缺字段就不渲染」那条纪律的现场证明，但「有分母时画对百分比」只有单测覆盖。
- **推理 token / 线程花费**：loopback 不报 `reasoning`、也没有价目，两行都不渲染。
  同上，是诚实降级的现场证明，不是这两条被验过。
