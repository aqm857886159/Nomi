真正的根因还在更下面：

### 0.8 根因：我们自己的 SSRF 门岗把所有出片都挡在门外

`tasks.result` 直接报 **`Refusing to fetch private/loopback DNS address`**。

- 这台机器（以及**任何** Clash/Surge TUN + fake-ip 模式的机器，也就是国内绝大多数要访问境外
  API 的用户）DNS 会把**每一个**域名解析进 `198.18.0.0/15`：`api.apimart.ai → 198.18.0.140`。
- `electron/networkHostPolicy.ts` 的黑名单里有 `['198.18.0.0', 15]`，于是 `hardenedFetch` 的
  `resolvePublicAddresses` 判定「私网」，**拒绝**。
- 而**提交**任务那一路走的是 `appFetch`（不过门岗），所以**下单成功、扣款成功、取货被自己拦下**。
  同一个供应商域名，POST 放行、GET 拒绝——这个不对称本身就是问题。

**后果**：在用户自己的机器上，视频生成**当前是走不通的**——钱花了，成片下载不回来，
而且界面只说「生成失败」。

**本次绕过方式（真实用户没有）**：`LAB_ALLOW_LOCALHOST=1` —— 代码里既有的 lab 逃生口
（注释写着「Never set in production」）。开了它之后，10 条全部用**免费**的「重新拉取结果」
一次拉回，`0.34272 USD/条` 的 `cost` 也是这时才读到的。

**为什么没在本轮修**：这是安全边界与架构取舍（把 `198.18/15` 从「私网」里摘掉？还是给
「用户自己配置过的供应商 origin」开例外？还是让两条路走同一套策略？），按 CLAUDE.md 属于
「碰信任 / 架构岔路 → 停下上报」。建议见 §2 F1。

## 2. 记下但**没有**在本轮修的（连同不修的理由）

### F1 🔴 分镜表把「可找回」记成「失败」，并把免费的重新拉取换成了**再扣一次钱**

`storyboardRowStatus.ts:69` 的 `isNodeFailed` 里 `node.status === 'error' || node.status === 'recoverable'`。
画布那层为 `recoverable` 专门做了中性面板 + 免费「重新拉取结果」（`recoverTaskActions.ts`，
注释里明写「query 不是 generate → 不铸付费令牌」），分镜表把它折平成 `failed`，
配一颗会重新生成的「重试」。本次是 10 镜 × $0.34272 = **$3.43 的重复扣费风险**。

**不修的理由**：正解是给 `recoverable` 一个自己的行状态 + 中性外观 + 接到既有的免费拉取动作，
这是**新的用户可见 UI**，按 R8 要先出样张、等拍板；而且我手上已经没有一个真的 `recoverable`
状态可以复验（10 条都已拉回成功）。改一半（只把动作换成免费拉取、标签仍写「生成失败」）
是两个半吊子，不做。

### F1' 🔴 SSRF 门岗把 fake-ip 代理下的**每一个**域名判成私网

见 §0.8。`198.18.0.0/15` 在黑名单里，而它正是 Clash/Surge fake-ip 的默认段。
门岗真正要挡的是 `10/8`、`172.16/12`、`192.168/16`、`127/8`、`169.254/16` 这些**真的能打到内网**
的地址；`198.18/15`（RFC 2544 基准测试段）和 `192.0.2/24`、`198.51.100/24` 一样是文档/保留段，
挡它保护不了什么，却让整个国内代理场景下的出片链路全断。
另外，**同一个供应商域名 POST 放行、GET 拒绝**这个不对称，无论怎么定策略都得先抹平。

**不修的理由**：动 SSRF 分类是安全边界决策，按 CLAUDE.md 属于「碰信任 / 架构岔路 → 停下上报」，
不该由一次验收单方面放宽。

### F6 🔴 `nomi_generation_plan` / `nomi_canvas_plan` 的校验错误对模型不可用

见 §0.4。9 分支 `anyOf` 的失败被平铺成一串无分支归属的短句，`must be equal to constant`
甚至不说是哪个常量。后果是 Nomi **最核心的那句话**（「帮我做一条 N 秒短片」）走不完。
**不修的理由**：正解要么是把联合体拆成按 operation 分的多个工具，要么是在校验失败时按
discriminator 只报选中分支的错误——两条都是工具契约的架构取舍，且 pi 的校验器是第三方库，
不能直接改（P1 不留 fork）。

### F4 🟠 Gemini 系模型在 Nomi 里当 Agent 大脑是**必然失败**的

工具 schema 里 `z.literal()` 编成 `{"const": …}`，Gemini 的 function-declaration 方言不认
（`$schema` / `additionalProperties` 它也不认，但 APIMart 的转换层似乎已经吃掉了那两个）。
**不修的理由**：正解是在 `createHostTools` 这唯一的漏斗里做一次 provider 方言降级
（`const` → 单值 `enum` 等价且各家都认），但要不要按 provider 分方言、降到哪一档，
是新的一层架构，且必须对每家供应商实测过再上，不该顺手塞进验收分支。

### F9 🟠 「先生成参考卡锁住长相」对本次选的模型根本不适用，界面不说

分镜表顶上写着方法论「先生成参考卡锁住长相，再生成镜头」，每一行又写着「此模型不吃参考」——
两句话都对，合起来是死路，而且**没有第三句话**告诉用户该换模型还是换成首帧档。
实测后果：10 镜里人物在第 9 镜换了衣服。**不修的理由**：这是产品建议逻辑（要不要在用户选了
不吃参考的模型时主动提示/改推荐），属于产品取舍，先报。

## 3. 这次验收自己的方法说明（给下一个人）

- 驱动器：`tests/ux/_launchApp.mjs` + 四路隔离，交互式「开一次不关、边看边点」（同 `ui-driver.mjs` 模式），
  外加主进程 `stdout/stderr` 落盘——**「发送失败」那一段唯一的线索本来该在那儿，结果那儿也是空的**，
  这个「空」本身就是证据。
- 记账用供应商自己回报的 `cost`（`GET /v1/tasks/{id}` 的 `data.cost` / `credits_cost`），
  不靠本地估算。注意：`appFetch` 在模块加载时就 bind 了 `globalThis.fetch`，
  **事后包一层 `globalThis.fetch` 是拦不到出站报文的**（本次踩过，ledger 全程为空，
  差点被当成「没有出站请求」）。
- 判「任务是不是真的失败」不要看节点状态，直接查供应商的任务端点：本次 10 条节点全红，
  上游 10 条全绿。
