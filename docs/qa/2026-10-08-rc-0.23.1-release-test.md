### 发现 1 · `check:site` 把这个包判红（**当时 PR 的阻断项**）

PR #1116 的 `Contracts` 已经红了，PR 处于 BLOCKED：

```
check:site 红了（2 项）：marketing site、sitemap
Marketing site output is stale:
- marketing/features.html
- marketing/en/features.html
- marketing/models.html
… （一长串生成的 marketing/*.html）
```

不是内容写错，是**生成物过期**：`marketing/*.html` 是从站点数据 + 模板生成的，merge 回 main 之后没有再生成一遍。

- 在 release 分支 `66d6eafe` 上单独跑 `check:site` 是**全绿 19/19**，所以问题出在「合回 main」这一步，不是 release 分支本身。
- 修法（在主仓对 PR 分支）：`pnpm run build:site`，把重新生成的 `marketing/**` 一起提交。

另外 `check:concept-owners` 有 4 处 advisory 失败（未登记的共享边界，涉及 `workers/nomi-asset-relay`、`assetIngestionRegistry`、`extractVideoFrameToNode`、`handleFocusNode`）——**不阻断**，但按 R33.4 应顺手登记。

### 发现 2 · 打包版命令沙箱证据线在 mac 包上出不来

`packaged-sandbox-active.e2e.mjs` 问三件事，两件没过去：

1. `active:true` —— 起来了 ✅（`packaged sandbox active:true exit:126`）
2. 探针里那条命令 exit=126：`env: /usr/bin/sandbox-exec: Operation not permitted` —— **这是测试执行环境的拦截**：在同一个 shell 直接跑 `/usr/bin/sandbox-exec -p '(version 1)(allow default)' /bin/echo hi` 也是 `operation not permitted`（exit 127）。不是 RC 的问题，需要在**不被宿主 seatbelt 包住的进程**（比如维护者从 Finder 起一个终端）里跑才能拿到这条。
3. `vendor/seccomp/{arm64,x64}/apply-seccomp` 卡在 `app.asar` 里（解包处没有）——**这是真实状态**：
   - `node_modules` 里有这两个二进制，`package.json` 的 `asarUnpack` 也覆盖了 `node_modules/@anthropic-ai/sandbox-runtime/vendor/**`；
   - 但 `Nomi-mac-arm64.zip` 里 `apply-seccomp` 条目数 = **0**，解包目录 `vendor/seccomp/arm64/` 是空的；
   - **已发布的 0.23.0（`/Applications/Nomi.app`）完全同一形状** → 不是本 PR 引入，是既有状态；
   - macOS 的沙箱走 seatbelt（`/usr/bin/sandbox-exec`），**一次都不碰 `vendor/`**（`docs/lessons/sandbox-runtime-not-unpacked-from-asar.md` 有实测结论），所以对 mac 用户无影响；真正会被打到的是 Windows 的 `srt-win.exe` 与三个平台的 Java agent。

**建议**：要么让 `apply-seccomp` 真的进解包处，要么把这条判据按平台收窄（mac 上跳过 Linux-only 资产）——现在这样，§4 要求的 `packaged sandbox active:true …` 那行证据在 mac 包上永远拿不到，等于这道门岗事实上没在跑（RC 工作流里也确实没有它）。

### 发现 3 · 子进程被宿主拦，两个打包测试测不了（环境）

打包 app 的 Chromium 子进程沙箱初始化失败 —— `sandbox initialization failed: Operation not permitted` → GPU / 网络进程崩 → 主进程 `FATAL: GPU process isn't usable. Goodbye.` 退出。**这是测试执行环境的限制（宿主 seatbelt 会传给整个进程树）**，同一台机器上从 Finder 起 Nomi 不受影响。加 `--no-sandbox --disable-gpu` 后窗口能起来、界面正常，但 `mcp-l2` 走的是完整应用启动，仍被这一层拦住。

另外：第一次跑 `model-integration` / `mcp-l2` 都失败了，原因是测试 shell 里**导出了 `ELECTRON_RUN_AS_NODE=1`**，Electron 二进制退化成纯 node（正是 `_launchApp.mjs` 文件头写的那条死法）。清掉这个环境变量后 `model-integration:packaged` 立刻转绿。**这是个可在 CI 之外复现的环境坑，值得记一笔。**

### 顺手复现到的用户现场（0.23.0 上的退出 bug）

测试中被维护者授权终止的那个 Nomi 0.23.0（PID 670）：

1. `osascript -e 'quit app "Nomi"'` 被 Automation 权限挡了（`-10004`），拿不到正常退出路径；
2. `SIGTERM` 后**主进程瞬退，但留下 3 个孤儿的 `mcpNodeLauncher.js` 帮助进程**（PID 15294 / 16411 / 26583）——正是 `FB-20261007-quit-teardown-orphaned-lane` 那条的形状；
3. 这 3 个孤儿要单独 kill 才清干净。

也就是说，0.23.1 想修的三件事（升级不丢项目 / 旧项目能开 / 退出几秒结束），**前两件在这个 RC 上验过了，第三件在 RC 上也不卡**；而 0.23.0 上确实能看到退出残留。
