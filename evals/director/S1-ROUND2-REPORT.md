## 单元处置

### 单元 1：F1/F2 尺子修正

- F1 只接受 `model/actionLibrary.ts` 中真实存在的动作 id。移动区间要求 `standard_walk`/`running` 覆盖完整区间，停止要求静止片段，hold_pose 要求真实动作。
- 动作库没有的语义在卡上标为 `capability: missing_asset`，所有方案该项得 0，并在能力缺口节单列。
- F2 oracle 构造器只物化真实动作，不制造语义假动作。
- 修正前：oracle `0.977486`，s0-pr960-raw `0.192124`。修正后：oracle `0.973611`，s0-pr960-raw `0.247266`（均为 28 张同一 scorer）。oracle 下降来自 courtyard 的缺资产动作按规格归零；没有修改阈值或权重。

### 单元 2：编译器

`s1OraclePlans.ts` 已覆盖 28 张卡。编译器流水为 `0.411175 → 0.577953 → 0.747053 → 0.809830 → 0.926069 → 0.954608`；最终最低卡 courtyard `0.863424`，28/28 均达到 0.85。

修复包含：`lookAtAngles` 朝向约定、`distanceForShotSize` 景别距离、cut/continuous 接续、轴线约束、pan/whip 方向识别、push/track 安全半径、物体 AABB 碰撞，以及真实动作片段物化。

### 单元 3：规划器与归一化

- 删除有损别名：`orbit`、`arc`、`truck`、`track`、`crane`、`zoom`、`dolly`、`wide`、`establishing`、`close`、`横移挡住`、`古代庭院`、`城市街道`、`展台`、`产品台` 等不再猜测映射；这些输入现在直接进入 zod 错误并触发已有重试。
- 保留的别名均为中英一一对应、大小写/空白/分隔符变化，或不改变方向的动作/关系同义词。`in/out → forward/backward` 只做无方向猜测的明确方向缩写。
- 提示词改为要求精确合法值，并明确禁止从 wide/close/orbit/truck/track/crane/zoom/dolly 推断景别或方向。

## 最差五张归因

按三轮平均总分排序：

1. `t2-courtyard`：0；规划器输出与题卡实体/镜头主体绑定不足，并触发轴线判据。
2. `t3-storm`：0；缺少可识别演员、景别覆盖和 `storm_ground` 场景。
3. `t3-space`：0；缺少可识别演员、景别覆盖和 `quiet_room` 场景。
4. `t3-market`：0；缺少 `market_street` 场景和景别覆盖，并触发轴线/碰撞判据。
5. `courtyard-standoff`：0.070081；规划器实体命名与题卡实体不一致，且有轴线、主体和缺资产影响。

实体绑定导致 L2/L3 近乎归零属于下一轮尺子专班，本轮没有修改 scorer、adapters、cards 或 measurement。
